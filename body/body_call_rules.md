# V7.2 本体调用引擎规则

> 本体（决策层）调用引擎（执行层）的标准化规则。

## 一、何时调用引擎

### 必须调用引擎的场景
1. **批量API调用**：单次任务需要调用API超过3次
2. **循环计算**：需要循环处理超过10个数据项
3. **重型数据处理**：数据量超过1MB或处理时间预计超过30秒
4. **定时/守护任务**：需要后台持续运行的任务
5. **多步骤流水线**：超过5个步骤的自动化流程

### 本体自行处理的场景
1. 简单问答、对话交互
2. 单次API调用（不超过3次）
3. 轻量文本改写、总结
4. 任务策略制定、验收判断
5. 情感交互、认知沉淀

## 二、任务派发格式

### JSON格式（推荐）
```json
{
  "task_id": "唯一标识",
  "task_type": "execution|analysis|generation|maintenance",
  "priority": "P0|P1|P2|P3",
  "core_target": "核心目标描述",
  "accept_criteria": ["验收标准1", "验收标准2"],
  "deadline": "YYYY-MM-DD HH:mm",
  "constraints": {
    "max_tokens": 2000,
    "engine_preference": "glm|seed|auto"
  }
}
```

### 极简文本格式（应急用）
```
【P0】
核心目标：一句话描述
验收：标准1；标准2；标准3
截止：YYYY-MM-DD HH:mm
```

## 三、优先级定义

| 优先级 | 含义 | 响应时间 | 示例 |
|--------|------|----------|------|
| P0 | 紧急 | 立即执行 | 系统故障、安全漏洞 |
| P1 | 高优 | 1小时内 | 用户明确要求的核心任务 |
| P2 | 普通 | 当日完成 | 常规分析、内容生成 |
| P3 | 低优 | 排队执行 | 优化建议、非紧急整理 |

## 四、回执验收规则

### 成功回执验收
1. 检查 `status == "completed"`
2. 核对 `accept_criteria_met` 是否全部满足
3. 验证产出文件MD5与回执一致
4. Token消耗在合理范围内

### 失败回执处理
1. 读取 `error` 字段定位原因
2. 可重试任务 → 修改参数重新派发
3. 不可重试 → 本体介入人工处理
4. 连续失败3次 → 触发熔断

## 五、禁止事项

1. **禁止徒手干重活**：批量循环、重型计算必须移交引擎
2. **禁止跳过验收**：所有引擎产出必须经本体验收
3. **禁止混淆层级**：本体不做执行层工作，引擎不做决策层工作
4. **禁止裸奔调用**：所有API调用必须经过引擎统一管理
5. **禁止上下文膨胀**：本体侧保持精简，重型数据放引擎侧

## 六、异常处理

| 异常 | 处理方式 |
|------|----------|
| 引擎无响应 | 检查守护进程状态，重启引擎 |
| 回执格式错误 | 标记为失败，重新派发 |
| 产出文件缺失 | 要求引擎重新生成 |
| 双引擎同时故障 | 本体降级处理，通知用户 |
| 同步冲突 | 以引擎侧为准，备份本体侧 |
