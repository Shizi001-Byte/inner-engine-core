# 火山方舟协作奖励计划数据采集异常排查手册

**现象**：当日调用消耗约50万tokens，但平台仅采集到约10万，40万调用数据未被采集，次日未返还对应资源包。
**前提**：推理接入点已授权加入协作奖励计划，全部协议已同意。
**编制**：观尘子 · 2026-08-16

---

## 一、核心机制回顾（先搞懂规则再排查）

火山方舟协作奖励计划的采集返还逻辑，有三个关键约束：

1. **按"推理接入点+模型"双重授权**：不是授权了API密钥就全量采集，必须每个接入点、每个绑定模型都单独在控制台授权。
2. **按调用方式区分**：仅在线推理的特定API支持采集，批量推理等不采集。
3. **按模型设日采集上限**：每个模型每日采集量有上限（企业认证500万/模型/天，个人认证上限更低），超出部分不采集、不返还。

官方原文：
> 调用已获授权的推理接入点，每日将采集每个模型不超过500万tokens的推理数据，并于次日发放等量免费资源包；未获授权的接入点数据将不予采集。
> 目前平台仅针对部分模型和调用方式进行数据采集，通过不支持的方式调用模型时，数据不会被采集。

---

## 二、可能性排查清单（按概率从高到低）

### 🔴 可能性1：单模型日采集上限已被其他调用占满（概率最高）

**机制**：协作奖励计划的采集上限是**按模型、按账号、按自然日**计算的，不是按接入点。如果同一个账号下，同一个模型当天已经被其他地方（比如观尘子本地）调用并采集了大量tokens，那么你的调用会排在后面，超出日上限的部分不采集。

**为什么高度怀疑**：
- 你消耗50万只采集到10万，差值恰好是40万
- 如果观尘子本地当天已经用了40万该模型，且个人认证账号的单模型日采集上限恰好是50万，那么你这边只能挤进10万
- 企业认证上限是500万，不太可能超；但**个人认证上限可能远低于500万**（部分文档显示个人用户单模型日上限为50万或200万）

**验证方法**：
1. 登录火山方舟控制台 → 资源管理/额度管理 → 查看当日该模型的"协作奖励采集量"
2. 确认当日该模型总采集量是否已触达上限
3. 确认账号认证类型（个人/企业），对应采集上限不同

**解决方案**：
- 如果确认是上限问题：与观尘子协调调用时段，避开同一模型同日高峰；或换用其他支持采集的模型分摊额度
- 升级企业认证可将上限提升至500万/模型/天

---

### 🔴 可能性2：所用模型不在协作奖励计划支持采集列表内

**机制**：官方明确"目前平台仅针对部分模型进行数据采集"，文档中特别标注"当前入口支持模型：Doubao-Seed-Evolving"。如果你用的是某个"最新模型"，它可能尚未纳入协作奖励计划的采集支持范围。

**验证方法**：
1. 登录火山方舟控制台 → 模型广场 → 找到你所用的模型
2. 进入模型详情页，看是否有"火山方舟模型奖励计划"入口
3. 如果没有该入口，说明此模型暂不支持协作奖励计划采集
4. 对比观尘子用的模型（Pro 2 / Evolving）是否在支持列表内

**解决方案**：
- 换用已支持采集的模型（如Doubao-Seed-Evolving、Doubao-Seed-2.1-Pro等）
- 关注平台公告，等待目标模型纳入采集范围
- 不支持采集的模型就是纯消耗，无法返还，需评估成本

---

### 🟡 可能性3：调用方式不在支持采集的范围内

**机制**：官方明确列出支持和不支持的调用方式：

| 支持采集 | 不支持采集 |
|---------|-----------|
| Chat API（/chat/completions） | 批量推理（Batch API） |
| Responses API（/responses） | 按模型单元付费 |
| Messages API | TPM保障包 |
| Image Generation API | 推理缓存存储 |
| Content Generation API（仅在线推理） | 微调/训练相关调用 |

如果你用的是**批量推理接口**（batch），或者走了**异步批量任务**，即使接入点已授权，数据也不采集。

**验证方法**：
1. 检查你的代码中API调用的URL路径
   - 支持：`/api/v3/chat/completions`、`/api/v3/responses`、`/api/v3/messages`
   - 不支持：`/api/v3/batches`、`/api/v3/batch_jobs` 等批量端点
2. 检查是否使用了平台的"批量推理"功能而非在线推理

**解决方案**：
- 将批量推理改为在线推理（逐次调用），虽然速度慢但能采集返还
- 如果必须用批量推理，接受这部分不返还的事实，单独核算成本

---

### 🟡 可能性4：安心体验模式未关闭

**机制**：官方开通前提明确要求"关闭安心体验模式"。安心体验模式是平台的一种免费试用模式，在此模式下的调用可能不纳入协作奖励计划采集范围。

**验证方法**：
1. 登录火山方舟控制台 → 开通管理页
2. 检查目标模型是否还处于"安心体验模式"
3. 如果是，需要切换为正式开通（按量付费）模式

**解决方案**：
- 关闭安心体验模式，开通正式按量付费
- 注意：关闭后超出免费额度的调用会正常计费，但同时也能纳入采集返还

---

### 🟡 可能性5：推理缓存命中部分不采集

**机制**：官方规则中，"推理缓存命中"的用量可以用奖励包抵扣，但"推理缓存存储"不支持采集。如果你的调用大量命中了前缀缓存，这部分token虽然计费了，但可能不被计入采集量。

**验证方法**：
1. 查看调用返回结果中的缓存命中信息（如`cache_creation_input_tokens`、`cache_read_input_tokens`）
2. 统计缓存命中部分占总输入的比例
3. 如果缓存命中占比极高（比如80%），与40万/50万的比例吻合

**解决方案**：
- 减少前缀缓存的使用，或接受缓存部分不返还
- 在prompt设计上避免过长的重复前缀，降低缓存命中率

---

### 🟢 可能性6：资源包下发延迟（官方已说明）

**机制**：官方明确提示"近期本计划参与人数较多，资源包下发可能存在延迟，请耐心等待。" 采集统计和资源包发放可能不是实时的，有时会延迟1-2天。

**验证方法**：
1. 等待次日中午12点后再查看额度
2. 如仍未到账，等待第3天再确认
3. 查看控制台的"采集明细"，看是否有数据但资源包未发放

**解决方案**：
- 耐心等待，通常48小时内会到账
- 超过48小时未到账，提交工单咨询

---

### 🟢 可能性7：部分调用因限流/报错未产生有效推理

**机制**：如果调用频率过高触发限流（429错误），或因参数错误导致调用失败，这些请求虽然可能计入了某些统计，但不会产生有效的推理数据，因此不被采集。

**验证方法**：
1. 检查你的调用日志，统计成功请求数和失败请求数
2. 查看是否有大量429（限流）、500（服务端错误）等失败
3. 失败请求的token不计入采集量

**解决方案**：
- 降低调用频率，添加退避重试机制
- 确保请求参数正确，减少失败率
- 只统计成功请求的token消耗作为"有效消耗"

---

### 🟢 可能性8：接入点授权了但模型未单独授权

**机制**：协作奖励计划是"模型+接入点"双重授权。可能你在接入点层面同意了协议，但具体到某个模型时没有单独点击授权。官方规则："每一款模型将按模型推理接入点申请获取您的数据授权。"

**验证方法**：
1. 进入协作奖励计划详情页
2. 查看已授权模型列表，确认你所用的模型在列表中
3. 注意：Evolving和Pro 2是不同模型，需要分别授权

**解决方案**：
- 在活动页面为目标模型单独完成授权
- 授权后次日生效

## 五、总结与建议

1. **最可能的原因**：单模型日采集上限被观尘子本地调用占满（可能性1），或所用模型不在采集支持列表（可能性2）。这两个加起来覆盖了80%以上的概率。
2. **最快验证**：先去控制台看"当日该模型采集量"和"上限"，一眼就能判断是不是上限问题。
3. **如果是上限问题**：与观尘子协调，错峰使用不同模型，或升级企业认证。
4. **如果是模型不支持**：换用Evolving或Pro 2，这两个已确认支持采集。
5. **已蒸发的40万**：未采集的调用按规则不予返还，无法追回。授权和配置修正后，后续调用可正常返还。
6. **长期建议**：建立每日调用台账，记录每个模型的消耗量和采集量，及时发现异常，避免大额蒸发。
