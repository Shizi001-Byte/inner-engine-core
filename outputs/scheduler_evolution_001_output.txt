### 意图感知路由：特征向量设计方案

意图感知路由通过提取用户Prompt的多维特征，构建高维特征向量，输入到路由模型（如LightGBM或浅层神经网络）中预测最优目标引擎。

**特征向量设计（总维度：约80维）**：

1. **领域语义特征 (64维)**
   * *设计*：将用户Prompt输入轻量级Sentence-BERT提取稠密向量，并进行PCA降维至64维。
   * *作用*：捕捉请求的领域特征（如代码生成、逻辑推理、创意写作、多语种翻译）。

2. **任务类型特征 (8维)**
   * *设计*：One-hot编码（或Soft标签概率分布），涵盖8种核心任务类型：[QA, 代码生成, 数学计算, 角色扮演, 文本摘要, 信息抽取, 翻译, 长文本创作]。
   * *作用*：直接匹配不同引擎的强项任务。

3. **复杂度特征 (4维)**
   * *设计*：
     * `Token长度`（连续值归一化）：反映计算量。
     * `指令嵌套深度`（连续值）：反映逻辑复杂度。
     * `上下文依赖度`（0-1连续值）：基于历史对话轮次计算。
     * `少样本数量`（离散值）：Prompt中包含的Few-shot个数。

4. **时效与成本特征 (3维)**
   * *设计*：
     * `最大容忍延迟`（离散等级0-2）：由客户端Header指定或业务线推断。
     * `成本敏感等级`（离散等级0-2）：区分免费用户与高价值用户。
     * `流式输出要求`（布尔值0/1）。

5. **安全风险特征 (1维)**
   * *设计*：`风险等级`（离散值0-4），由前置安全拦截模型输出，0为安全，4为高危。用于路由至具备特定安全处理能力的引擎。

### 质量反馈闭环：评分维度与数据回流路径

#### 评分维度体系

采用**显式反馈 + 隐式反馈 + 模型客观评估**三位一体的评分机制，最终加权计算为单一质量得分（Quality Score, 范围0-1）：

1. **客观质量评分 (权重50%)** - 异步LLM-as-a-Judge评估：
   * `事实准确率`：是否存在幻觉、事实错误。
   * `指令遵循度`：是否严格遵守了Prompt中的格式、长度、否定约束。
   * `逻辑连贯性`：推理步骤是否合理，是否存在逻辑断层。
2. **用户隐式反馈 (权重30%)** - 客户端埋点采集：
   * `采纳率`：输出结果是否被用户直接复制使用。
   * `重试率/修改率`：用户是否立刻重新生成或大幅修改Prompt。
   * `平均阅读时长`：结合流式输出时间判断是否有效阅读。
3. **系统效能指标 (权重20%)** - 服务端直接统计：
   * `首字延迟 (TTFT)` 与 `生成速度 (TPS)`。
   * `吞吐成本`：单次请求消耗的Token费用算力。

#### 数据回流路径

```
[客户端/Gateway] -> [在线服务层] -> [实时流处理] -> [离线数仓] -> [模型训练层] -> [在线路由引擎]
```

**具体回流路径步骤**：

1. **数据采集层**：
   * 在线请求完成后，生成唯一`Trace_ID`。
   * 客户端上报隐式反馈行为日志（包含`Trace_ID`）。
   * 服务端上报路由决策日志（输入特征向量、选择引擎、系统效能指标）。
2. **异步评估层**：
   * 请求结果与Prompt通过Kafka进入异步评估队列。
   * 调用评测大模型（如GPT-4级别的模型）对输出进行打分，生成客观质量评分。
3. **数据清洗与对齐层**：
   * Flink流处理作业将实时效能日志、用户隐式日志、异步客观评分基于`Trace_ID`进行Join对齐。
   * 过滤异常离群点（如超时导致的错误评分）和PII（个人敏感信息）脱敏。
4. **特征库与样本构建**：
   * 将对齐后的 `(特征向量X, 引擎选择A, 质量得分R)` 三元组写入特征存储。
   * 按时间窗口（如每1小时）生成增量训练样本集。
5. **模型更新与发布层**：
   * 触发路由模型（如基于强化学习的 contextual bandit 算法或监督微调模型）的增量训练。
   * 新模型权重在AB实验平台验证收益后，通过模型管理平台推送到线上路由引擎的内存中热加载，完成闭环。
