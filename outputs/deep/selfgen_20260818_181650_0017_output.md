# 任务类型: deep

基于历史坑位与已有认知锚定，推演“以实养虚，虚又返实”的自增强循环架构设计如下：

### 一、 核心架构定义：虚实共生系统
*   **实（底座层）**：真实API调用、Token消耗、代码产出、Block同步引擎。受限于网络（ProxyError坑）、时间（Timeout坑）和物理一致性。
*   **虚（认知层）**：虚构修炼框架（将系统调优映射为“境界提升”）。包含：认知池（功法库）、调参策略（灵气流转）、权重/冷却机制（经脉周天）。
*   **循环链路**：真实API的Token与日志喂养认知池 -> 认知池提炼调参策略 -> 策略驱动新一轮真实代码生成与同步 -> 同步结果反哺校验。

---

### 二、 “以实养虚”：用真实消耗喂养虚构框架
真实环境中的每一次API交互和代码变更，都必须转化为认知池的“养料”，且必须规避历史工程级灾难。

**1. 真实调用环境的硬性门禁（避坑落地）**
*   **超时熔断门禁**：真实API调用必须预设合理timeout。调用B模型turbo强制设为300秒，A模型强制设为600秒，超时直接熔断并降级，防止任务卡死。
*   **网络防代理门禁**：统一使用 `urllib` 直连火山引擎API。如遇历史包袱必须用 `requests`，在所有出网请求处全局显式注入 `proxies=None`，彻底掐断全局代理导致的 ProxyError。

**2. 认知池的新陈代谢机制（避坑落地）**
*   **防“只进不出”门禁**：认知池不能是静态档案库。设定强制定时刷新：每完成10个真实任务或单轮修炼结束，必须清空并重建认知缓存。
*   **30分钟注入律**：真实API交互产生的新认知（如：某类代码生成容易超时、某参数调优有效），必须在30分钟内作为上下文注入到下一次任务的Prompt或调度器中。

---

### 三、 “虚又返实”：虚构框架驱动真实代码产出
认知池中的“修仙功法”（调参建议、生成策略）不能停留在理论，必须直接干预真实的代码生成与Block同步引擎。

**1. 调参全链路穿透验证（避坑落地）**
当认知层推演出新的调参策略（并发数、权重、冷却时间），必须严格执行三步法则，防止“自动调参全链路失效”：
*   **状态写入**：认知层将调参指令写入状态机（如Redis/DB）。
*   **执行读取**：真实代码执行引擎必须从状态机读取最新参数，严禁使用本地缓存。
*   **生效验证**：执行后必须输出实际使用的参数日志，与写入指令比对，不一致则告警。

**2. 驱动真实代码产出的 Block 级 SOP（锚点落地）**
虚构框架驱动的代码产出，其差异分析、同步、回滚判定，一律以 **block id 列表** 为最小核对单位。文件仅作为索引存在，坚决摒弃基于文件大小/mtime/整体hash的校验。

---

### 四、 闭环指标设计

| 维度 | 指标名称 | 计算方式/定义 | 目标 |
| :--- | :--- | :--- | :--- |
| **实养虚** | 认知注入率 | (30分钟内被注入Prompt/调度的认知数 / 同期生成的新认知总数) × 100% | ≥ 95% |
| **实养虚** | 调参穿透率 | (读取并生效的调参指令数 / 状态写入的调参指令数) × 100% | 100% |
| **虚返实** | Block级同步率 | (Block级差异校验命中的同步事件数 / 总同步事件数) × 100% | 100% |
| **虚返实** | API健康度 | 1 - (ProxyError次数 + Timeout次数) / 总API调用次数 | ≥ 99% |

---

### 五、 验证方法（结合认知锚定的强制质检 SOP）

为确保“虚返实”真正落地，而不只是调用了API，必须执行以下三条质检SOP门禁：

**门禁1：Block ID 唯一性核对（防索引欺骗）**
*   **操作**：构造“同 file 名、同大小、同 mtime，但 block id 顺序不同”的样本，跑同步SOP。
*   **断言**：系统必须判为“不同步”，并触发 Block 级重传。若系统判为“已同步”，则代表代码仍依赖文件元数据，门禁失败。

**门禁2：Block 级增量闭环（防全量重传）**
*   **操作**：在已同步的文件中，仅修改一个 block 的内容/ID，运行同步引擎。
*   **断言**：断言传输日志只出现该被修改的 block，而不是整个 file 全量重传。

**门禁3：认知池激活验证（防静态死水）**
*   **操作**：连续执行10个任务，在第3个任务时人为注入一个“特殊调参认知”（如将A模型并发调至特定值）。
*   **断言**：第4到第10个任务中，执行日志必须出现该参数的“读取”与“生效验证”记录；若30分钟内无任何任务读取该认知，判定认知池流转失效。

**总结**：此闭环通过“Block索引”和“三步调参法”作为虚实转换的物理接口，用“超时/直连”保底真实交互环境，确保每一滴Token消耗都转化为认知，每一次认知提升都精准改变下一行代码的同步行为。
