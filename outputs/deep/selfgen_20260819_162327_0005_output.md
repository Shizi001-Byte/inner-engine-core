## 二、实→虚：真实调用如何喂养框架

### 2.1 数据采集层（零额外开销，寄生在已有调用上）

**核心原则：不新开API调用，只在已有3路并发任务的结果上寄生采集。**

```python
# 寄生式数据采集 - 挂载在已有任务回调上，不占额外并发
class RealDataHarvester:
    """实→虚 数据采集器，寄生在已有调用上"""
    
    def harvest_from_result(self, task_result):
        """从真实API返回结果中提取喂养数据"""
        return {
            # 硬指标：直接可量化
            'token_cost': task_result.usage.total_tokens,        # 灵石消耗
            'latency_ms': task_result.latency,                   # 时辰耗费
            'success': task_result.success,                      # 炼丹成败
            'task_type': task_result.template_id,                # 功法类别
            'quality_score': task_result.eval_score,             # 丹药品质
            
            # 软指标：从结果内容中提取
            'novelty_signals': self._extract_novelty(task_result),  # 是否产生新认知
            'error_patterns': self._extract_errors(task_result),    # 心魔模式
        }
```

### 2.2 实数据→虚世界的映射协议

| 真实指标 | 虚构世界映射 | 映射公式 | 用途 |
|---------|------------|---------|------|
| token消耗 | 灵石消耗 | 1 token = 1 灵石 | 修炼资源预算管理 |
| 任务成功率 | 功法熟练度 | 累计成功率×100 = 熟练度 | 解锁高级任务模板 |
| 延迟 | 时辰耗费 | latency/1000 = 时辰 | 效率评估 |
| eval_score | 丹药品质 | score×10 = 品阶 | 质量驱动调参 |
| 新认知产生 | 悟道值 | 每条+10悟道 | 触发境界突破 |
| 重复率下降 | 心魔净化 | 降幅×50 = 净化值 | 自动解锁新模板 |

### 2.3 喂养触发时机（不破3路并发）

```
任务完成回调（3路中的某一路释放）
    → 寄生采集（零API调用，纯本地计算）
    → 写入修炼状态（状态写入点①）
    → 检查是否触发境界突破
    → 该路重新接收下一个任务
```

**关键：采集过程是纯本地计算，不消耗API调用，不占用并发槽位。**

## 三、虚→实：框架如何驱动真实产出

### 3.1 虚决策→实动作的三个落地通道

```
┌──────────────────────────────────────────────────────┐
│              虚→实 三个落地通道                        │
│                                                        │
│  通道A：境界突破 → 触发调参（并发/权重/冷却）             │
│  通道B：功法解锁 → 生成新任务模板注入池                  │
│  通道C：悟道积累 → 新认知注入任务上下文                  │
│                                                        │
│  每个通道 = 状态写入 + 执行读取 + 生效验证（三点同步）    │
└──────────────────────────────────────────────────────┘
```

### 3.2 通道A：境界突破→自动调参

```python
class RealmBreakthroughHandler:
    """境界突破触发真实调参"""
    
    def check_breakthrough(self, cultivation_state):
        """检查是否满足突破条件"""
        if cultivation_state.comprehension >= self.breakthrough_threshold:
            # 突破成功 → 产生调参建议
            suggestion = self._generate_param_suggestion(cultivation_state)
            
            # === 坑库预警[1] 防护：三点同步 ===
            # 点①：状态写入
            self.param_state.write(suggestion)          # 写入参数变更
            
            # 点②：执行读取
            self.scheduler.reload_params()              # 调度器重载参数
            
            # 点③：生效验证
            verified = self._verify_params_effective()   # 验证真实生效
            assert verified, "调参未生效！三点同步失败"
            
            return True
        return False
    
    def _verify_params_effective(self):
        """验证参数真实生效"""
        # 读取下一次调度的实际并发数/权重/冷却时间
        actual = self.scheduler.get_current_config()
        expected = self.param_state.get_latest()
        return actual == expected
```

### 3.3 通道B：功法解锁→新模板注入

```python
class TechniqueUnlockHandler:
    """功法熟练度达标 → 解锁新任务模板"""
    
    def check_unlock(self, technique proficiency):
        """熟练度达标自动解锁"""
        if proficiency.level >= self.unlock_threshold:
            # 在3路并发内插空生成新模板
            new_template = self._generate_template_in_slot(
                timeout=300,  # B模型turbo 300秒
                max_retries=1
            )
            
            # 验证模板真实可用
            if self._verify_template(new_template):
                self.task_pool.inject(new_template)
                # 坑库预警[3]：注入后必须刷新认知缓存
                self._refresh_cognition_cache()
```

### 3.4 通道C：认知注入→影响任务上下文

```python
class CognitionInjector:
    """悟道值积累 → 新认知注入任务"""
    
    INJECTION_INTERVAL = 10  # 每10任务刷新一次
    
    def maybe_inject(self, task_count):
        """坑库预警[3]：认知池只进不出 防护"""
        if task_count % self.INJECTION_INTERVAL == 0:
            # 从认知池选取相关认知
            fresh_cognitions = self.cognition_pool.get_fresh(
                max_age_minutes=30  # 30分钟内的新认知必须参与
            )
            
            if fresh_cognitions:
                # 注入下一个任务的system prompt
                self.task_context.augment(fresh_cognitions)
                return True
        return False
```

## 四、闭环指标体系

### 4.1 三层闭环指标

```
┌───────────────────────────────────────────────────────┐
│                   闭环指标体系                          │
│                                                         │
│  Layer 1: 实→虚 转化指标                                │
│  ├── 数据采集覆盖率 = 已采集任务数 / 总任务数             │
│  ├── 数据完整度 = 有效字段数 / 预期字段数                │
│  └── 喂养延迟 = 任务完成到状态写入的间隔                 │
│                                                         │
│  Layer 2: 虚→实 转化指标                                │
│  ├── 决策落地率 = 实际生效的虚决策数 / 产生的虚决策数     │
│  ├── 三点同步成功率 = 三点全通过次数 / 虚决策总数         │
│  └── 注入命中率 = 认知实际影响结果的次数 / 注入总次数     │
│                                                         │
│  Layer 3: 自增强系数（核心指标）                          │
│  ├── 质量提升斜率 = eval_score随时间的提升速率           │
│  ├── 重复率下降率 = task_repeat_rate随时间的下降速率     │
│  └── ROI = 虚→实动作产生的收益 / 框架自身消耗的成本       │
└───────────────────────────────────────────────────────┘
```

### 4.2 自增强系数计算

```python
class SelfReinforcementMetric:
    """自增强系数 - 判断循环是否真正自增强"""
    
    def calculate(self, window: TaskWindow):
        """
        核心公式：
        增强系数 = (虚→实收益) / (框架自身消耗)
        
        若系数 > 1.0：循环自增强，越跑越强
        若系数 = 1.0：循环保本，维持现状
        若系数 < 1.0：循环亏损，需要干预
        """
        # 虚→实收益：质量提升 + 重复率下降节省的token
        quality_gain = window.eval_score_trend.slope  # 正值=提升
        repeat_savings = window.repeat_rate_drop * window.avg_task_cost
        total_benefit = quality_gain * 1000 + repeat_savings
        
        # 框架自身消耗：生成模板/调参/验证的API调用
        framework_cost = window.template_gen_cost + \
                        window.param_verify_cost + \
                        window.cognition_inject_cost
        
        coefficient = total_benefit / max(framework_cost, 1)
        
        return {
            'coefficient': coefficient,
            'is_self_reinforcing': coefficient > 1.0,
            'benefit': total_benefit,
            'cost': framework_cost
        }
```

## 五、验证方法

### 5.1 断点验证法（针对坑库预警[1]）

```
在虚→实链路上设置3个断点：

断点1（状态写入后）：param_state.get_latest() != None ?
    ↓ Yes
断点2（执行读取后）：scheduler.get_current_config() == param_state.get_latest() ?
    ↓ Yes  
断点3（生效验证后）：next_task实际使用的参数 == expected ?
    ↓ Yes
    ✓ 全链路生效

任一断点失败 → 自动告警 + 回滚到上一个稳定参数
```

### 5.2 A/B对照验证

```python
class ABVerification:
    """开启vs关闭框架的对照验证"""
    
    def run_verification(self):
        """
        每100任务为一轮：
        - 前50任务：框架关闭（基线）
        - 后50任务：框架开启（实验）
        
        对比指标：
        - eval_score均值差异
        - task_repeat_rate差异  
        - token_efficiency差异
        """
        baseline = self.run_batch(50, framework_enabled=False)
        experiment = self.run_batch(50, framework_enabled=True)
        
        return {
            'score_delta': experiment.avg_score - baseline.avg_score,
            'repeat_delta': baseline.repeat_rate - experiment.repeat_rate,
            'efficiency_delta': experiment.token_efficiency - baseline.token_efficiency,
            'verdict': 'PASS' if experiment.avg_score > baseline.avg_score else 'FAIL'
        }
```

### 5.3 网络层验证（针对坑库预警[2]）

```python
import urllib.request
# 坑库预警[2]：统一用urllib直连，不引入requests

def safe_api_call(url, payload):
    """避免ProxyError的直连方式"""
    # 不使用requests，避免全局代理污染
    req = urllib.request.Request(
        url,
        data=json.dumps(payload).encode('utf-8'),
        headers={'Content-Type': 'application/json'}
    )
    # 显式不走代理
    proxy_handler = urllib.request.ProxyHandler({})
    opener = urllib.request.build_opener(proxy_handler)
    return opener.open(req, timeout=300)  # B模型turbo 300秒
```

### 5.4 认知活性验证（针对坑库预警[3]）

```python
class CognitionVitalityCheck:
    """验证认知池不是静态档案库"""
    
    def check_vitality(self):
        """每转结束执行"""
        pool = self.cognition_pool
        
        metrics = {
            'total_count': pool.count(),                    # 总量
            'injected_last_30min': pool.injected_count(     # 30分钟内注入数
                since_minutes=30),
            'injected_last_10tasks': pool.injected_in_tasks( # 最近10任务注入数
                task_count=10),
            'stale_ratio': pool.stale_ratio(               # 超过30分钟未使用的比例
                threshold_minutes=30)
        }
        
        # 验证条件
        assert metrics['injected_last_30min'] > 0, \
            "认知池只进不出！30分钟内无新认知注入"
        assert metrics['stale_ratio'] < 0.7, \
            "认知池老化！超过70%认知未参与调度"
        
        return metrics
```

## 六、限流与预算控制

### 6.1 框架自身消耗预算

```
┌─────────────────────────────────────────────┐
│          框架消耗预算（每转）                  │
│                                               │
│  模板生成：≤ 3次API调用（3路各插空1次）       │
│  模板验证：≤ 3次API调用（3路各插空1次）       │
│  调参验证：≤ 1次API调用                       │
│  认知注入：0次API调用（纯本地拼接到prompt）    │
│                                               │
│  总预算：≤ 7次API调用/转                      │
│  约束：不得突破3路并发物理上限                 │
└─────────────────────────────────────────────┘
```

### 6.2 插空执行时序

```
3路并发时序（以一轮为例）：

路1: [任务A执行]──[回调采集]──[插空:模板生成]──[任务D执行]
路2: [任务B执行]──[回调采集]──[任务E执行]──[回调采集]
路3: [任务C执行]──[回调采集]──[任务F执行]──[回调采集]

         ↑                    ↑
    实→虚采集              虚→实生成
    (零API消耗)           (消耗1次API，在路1释放后插空)
```

## 七、自增强飞轮的启动条件与收敛判断

### 7.1 启动门槛

```python
# 循环启动条件（全部满足才开始自增强）
STARTUP_CONDITIONS = {
    'min_task_history': 30,        # 至少30个任务的历史数据
    'min_cognition_count': 50,    # 认知池至少50条
    'min_repeat_rate': 0.3,       # 重复率至少30%（否则不需要新模板）
    'concurrent_stable': True,    # 3路并发稳定运行中
    'budget_available': True,     # 本转预算未耗尽
}
```

### 7.2 收敛/发散判断

```
每转结束后计算自增强系数：

  系数 > 1.2  →  发散增强：可以适当提高模板生成频率
  1.0 ~ 1.2  →  稳定增强：维持当前节奏
  0.8 ~ 1.0  →  收敛警告：降低框架消耗，减少生成频率
  系数 < 0.8  →  亏损干预：暂停框架动作，回退到基线模式
```

## 八、总结：闭环验证清单

| 验证项 | 验证方法 | 对应坑库 | 频率 |
|-------|---------|---------|------|
| 调参三点同步 | 断点验证法3个断点全通过 | 坑[1] | 每次调参 |
| API无ProxyError | urllib直连，proxies={} | 坑[2] | 每次调用 |
| 认知池活性 | 30分钟内注入数>0 | 坑[3] | 每转结束 |
| 超时控制 | B模型300s / A模型600s | 避坑提醒 | 每次调用 |
| 并发不破3路 | 插空执行不超过3路 | 认知锚定1 | 实时 |
| 自增强系数>1.0 | ROI计算 | 核心 | 每转结束 |
| A/B对照 | 50vs50任务对比 | 验证方法 | 每100任务 |

**一句话总结**：真实调用的token是灵石，任务成功率为熟练度，新认知是悟道值——虚世界的境界突破必须通过三点同步验证真实落地为调参/模板/注入，而框架自身消耗不得超过每转7次API调用的预算，自增强系数>1.0则飞轮加速，<0.8则干预收敛。
