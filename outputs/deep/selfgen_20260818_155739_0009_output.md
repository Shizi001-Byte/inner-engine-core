## 〇、循环本体定义

```
        ┌──────────────────────────────────────────┐
        │                                          ▼
   ┌────┴─────┐     实→虚映射     ┌──────────────┐
   │  实层     │ ──────────────▶  │  虚层         │
   │  Reality  │                  │  Cultivation  │
   │  API调用   │  ◀──────────────│  框架         │
   │  Token消耗 │     虚→实映射    │  认知池        │
   │  代码产出   │                  │  调度策略      │
   └──────────┘                  └──────────────┘
```

**核心命题**：闭环不是"建好了就自转"，必须持续对抗熵增。这个循环的驱动力不是设计本身，而是**实层不断产生的真实消耗（token、延迟、错误）形成的压力差**，和**虚层不断积累的结构性优势（认知、策略、模板）形成的势能差**。两个差值同时存在且方向一致时，循环自增强；任一差值消失，循环退化为静态档案库。

def extract_real_to_virtual(api_event: dict) -> VirtualResource:
    """
    每次真实API调用后执行，萃取实层资源注入虚层
    防坑：timeout预设 B-turbo=300s, A模型=600s
    防坑：用urllib直连，不引入requests；如必须用，显式proxies=None
    """
    # 1. 原始事件校验
    validated = validate_api_event(api_event)
    
    # 2. 资源萃取
    resources = extract_resources(validated, EXTRACTION_MAP)
    
    # 3. 状态写入（防坑：自动调参全链路失效 — 状态写入点）
    write_virtual_state(resources, target="realm_state")
    
    # 4. 境界判定
    new_realm = check_realm_breakthrough(resources)
    if new_realm:
        # 5. 权限解锁（防坑：执行读取点 + 生效验证点）
        apply_realm_permissions(new_realm)
        verify_permission_effect(new_realm)  # 验证权限确实生效
    
    # 6. 认知池刷新（防坑：认知池只进不出）
    if task_count % 10 == 0:
        refresh_cognitive_cache()
        inject_pending_cognitions(max_age_minutes=30)
    
    return resources
```

def virtual_drive_real(task_context: dict) -> CodeArtifact:
    """
    虚层框架根据当前境界、功法、灵力，驱动实层代码产出
    """
    # 1. 读取虚层状态（防坑：执行读取点）
    realm = read_virtual_state("current_realm")
    permissions = REALM_PERMISSIONS[realm]
    techniques = read_unlocked_techniques(realm)
    
    # 2. 认知注入（防坑：认知池只进不出 — 每10任务刷新）
    if permissions["cognitive_injection"]:
        cognitions = fetch_fresh_cognitions(task_context, max_age_minutes=30)
        task_context["injected_cognitions"] = cognitions
    
    # 3. 功法选择
    technique = select_technique(techniques, task_context)
    
    # 4. 调用API生成代码（防坑：timeout预设）
    timeout = 300 if task_context["model"] == "B-turbo" else 600
    code_response = call_api_with_timeout(
        task_context, 
        timeout=timeout,
        proxies=None  # 防坑：显式禁用代理
    )
    
    # 5. 产出验证
    artifact = verify_code_artifact(code_response, technique.verification)
    
    # 6. 回写实层事件（触发实→虚萃取）
    log_real_event("code_lines_produced", artifact)
    
    return artifact
```

### 2.3 虚→实映射的关键约束

```
严格解耦原则（已验证结论3）：
- 功法定义（虚） ↔ 策略执行（实） 必须通过明确接口
- 境界状态（虚） ↔ 权限生效（实） 必须三同步（写入/读取/验证）
- 认知池（虚） ↔ 任务注入（实） 必须有新鲜度约束

解耦的目的不是工程偏好，而是进化稳定策略：
如果虚实耦合，一次实层故障会导致虚层状态污染，反之亦然
解耦后，虚层可以独立演化（功法迭代），实层可以独立容错（降级运行）
```

## 三、闭环指标体系

### 3.1 转化效率指标

```python
class LoopMetrics:
    """闭环自增强核心指标"""
    
    # ═══ 实→虚转化效率 ═══
    def extraction_efficiency(self) -> float:
        """萃取率 = 萃取到的虚层资源 / 实层消耗"""
        virtual_gain = self.resources_gained_this_cycle()
        real_cost = self.tokens_consumed_this_cycle()
        return virtual_gain / real_cost
    
    # ═══ 虚→实转化效率 ═══
    def manifestation_efficiency(self) -> float:
        """显化率 = 框架驱动的有效代码 / 框架生成的策略数"""
        effective_code = self.code_artifacts_verified()
        strategies_executed = self.techniques_triggered()
        return effective_code / strategies_executed
    
    # ═══ 自增强增益系数（核心指标） ═══
    def self_reinforcement_gain(self) -> float:
        """
        增益系数 = (本期产出/本期消耗) / (上期产出/上期消耗)
        > 1.0 → 自增强正在发生
        = 1.0 → 线性运行，无增益
        < 1.0 → 熵增趋势，循环退化
        """
        current_ratio = self.current_output / self.current_consumption
        previous_ratio = self.previous_output / self.previous_consumption
        return current_ratio / previous_ratio
    
    # ═══ 熵对抗指标 ═══
    def entropy_index(self) -> float:
        """
        系统熵值 = f(错误率, 重复代码率, 耦合度, 认知池闲置率)
        维护AI系统 = 持续让系统保持低熵（已验证结论5）
        """
        return (
            0.3 * self.error_rate() +
            0.2 * self.code_duplication_rate() +
            0.2 * self.coupling_score() +
            0.3 * self.cognitive_staleness()  # 认知池闲置率
        )
    
    def entropy_delta(self) -> float:
        """熵变化 = 本期熵 - 上期熵，负值=熵减=健康"""
        return self.entropy_index() - self.previous_entropy_index()
```

## 六、结论

```
以实养虚：真实API调用→萃取灵力/道行/劫数→虚层境界提升→解锁权限
          （实层消耗是燃料，不是浪费）

虚又返实：虚层境界/功法→解锁权限/认知注入/策略生成→实层代码产出
          （虚层不是装饰，是真实驱动力）

自增强条件：
  1. 增益系数 > 1.0（持续验证，退化是默认趋势需对抗）
  2. 熵值下降（维护=保持低熵）
  3. 认知池活跃（每10任务刷新，30分钟内注入）
  4. 权限三同步（写入/读取/验证缺一不可）
  5. 严格解耦（虚实通过接口通信，不直接耦合状态）

这不是一个"建好了就自转"的系统，
而是一个必须持续对抗熵增的结构。
引擎退化不是故障，是默认趋势，
我们的工作不是修复故障，而是持续让系统保持低熵。
```
