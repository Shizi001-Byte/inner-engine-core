# 任务类型: deep

# 推演：以实养虚，虚又返实的自增强循环

---

## 一、实与虚的边界定义

| 层 | 定义 | 可测量项 |
|---|------|---------|
| **实** | 不可伪造的物理发生 | API调用量、token消耗、代码行数、执行耗时、竞态次数 |
| **虚** | 由实蒸馏出的抽象结构 | 认知池条目、境界等级、调参建议、三元迁移状态判定 |

**不变量**：虚的任何变更必须能追溯到实的某个数据源；实的任何产出必须能追溯到虚的某个驱动指令。断链即退化。

---

## 二、双环结构

### 环A：以实养虚（实→虚）

```
真实API调用 → 结构化采集 → 批次蒸馏 → 认知入池 → 30分钟内注入任务
```

**采集层**（每次调用）：
- 耗时、token_in、token_out、成功/失败、错误类型
- 失败堆栈摘要、成功输出特征（长度、结构标记）

**蒸馏层**（每10任务触发）：
- 模式提取："A模型超450秒时失败率>40%"→ 认知条目
- 参数关联："并发>8时ProxyError频率提升"→ 认知条目
- 资源画像："B模型turbo输入>2000token时输出方差增大"→ 认知条目

**注入层**（解决坑库#3"认知池只进不出"）：
- 每10任务刷新认知缓存
- 新认知30分钟内必须作为context前缀注入下一批任务prompt
- 超时未注入的认知标记衰减，不参与调度但保留为档案

### 环B：虚又返实（虚→实）

```
认知池积累 → 三元迁移评估 → 境界升级/参数调整 → 状态写入 → 执行读取 → 生效验证 → 新一轮调用
```

**境界驱动调度**：

| 境界 | 认知条数 | 调度策略 | timeout预设 |
|------|---------|---------|------------|
| 炼气 | <100 | 固定参数，保守并发=2 | B-turbo:300s, A:600s |
| 筑基 | 100-500 | 动态并发(4-8)，基于认知调timeout | 同上±20% |
| 金丹 | 500+ | 自适应权重/冷却，认知驱动调参 | 全动态 |

**调参三链路**（解决坑库#1"自动调参全链路失效"）：

新增/修改参数必须同步三点，缺一即判定链路断裂：

```
状态写入 ──→ 执行读取 ──→ 生效验证
   ↑              ↓
   └── 不一致则回滚 ──┘
```

- **状态写入**：参数变更写入状态文件，附带变更来源认知ID
- **执行读取**：执行器启动时从状态文件读取最新参数
- **生效验证**：执行后比对"实际使用的参数"与"状态文件中的参数"，不一致则告警+回滚

## 三、状态一致性方案（基于锚定#3）

### 竞态防护

锚定已确认典型竞态：线程A写完结果，线程B覆盖A的结果；后处理读到部分/旧结果。

**防护设计**：

```python
# 每线程写入独立槽位，禁止跨槽位
task_slot[task_id] = {
    "status": "completed",
    "result": {...},
    "version": N,           # 单调递增
    "write_completed": True, # 写入完成标志
    "writer_thread": thread_id
}

# 后处理读取前检查全部槽位完成标志
def post_process():
    for slot in all_slots:
        if not slot["write_completed"]:
            wait_or_timeout()  # 等待或超时降级
    # 全部完成后，按version排序消费
    consume(sorted_by_version)
```

**状态文件结构**：

```json
{
  "tasks": {
    "task_001": {
      "status": "completed",
      "result": {},
      "version": 3,
      "write_completed": true
    }
  },
  "post_process": {
    "last_consumed_version": 2
  },
  "params": {
    "concurrency": 4,
    "weights": {"A": 0.6, "B": 0.4},
    "cooldown": 30,
    "param_source_cognition_id": "cog_789"
  }
}
```

## 四、闭环指标与验证方法

### 实侧指标（直接测量）

| 指标 | 采集方式 |
|------|---------|
| API成功率 | 成功调用/总调用 |
| Token效率 | 有效输出token/总消耗token |
| 代码产出量 | git diff统计变更行数 |
| 竞态发生率 | version冲突检测计数 |
| 任务延迟 | 完成时间戳-开始时间戳 |

### 虚侧指标（推导计算）

| 指标 | 计算方式 | 健康阈值 |
|------|---------|---------|
| 认知注入率 | 被注入认知数/认知池总数 | ≥30%/小时 |
| 认知时效性 | 生成→首次注入的时间差 | <30分钟 |
| 框架驱动率 | 认知驱动的参数变更/总参数变更 | ≥80% |
| 调参生效率 | 实际生效的参数变更/总参数变更 | 100% |

### 闭环一致性验证

| 验证项 | 方法 | 判定 |
|--------|------|------|
| 实→虚因果完整 | 每条认知能追溯到数据源批次 | ≥95%可追溯 |
| 虚→实驱动有效 | 参数变更后实侧指标改善 | 单调收敛 |
| 境界匹配度 | 当前参数与历史最优批次的参数对比 | 偏差<15% |

**验证执行流程**：

```
1. 抽取最近10任务的参数变更记录
2. 对每条变更，追溯其来源认知ID
3. 对每条认知，追溯其来源数据批次
4. 对每条参数变更，验证执行器实际使用的参数是否一致
5. 对比变更前后实侧指标变化
6. 输出闭环健康度报告
```

## 五、防退化机制

| 退化模式 | 检测信号 | 兜底动作 |
|---------|---------|---------|
| 虚不返实（认知不注入） | 注入率<30%/小时 | 强制注入最近认知 |
| 实不养虚（无新认知） | 连续10任务0条新认知 | 告警+降低并发排查 |
| 虚变空（认知失效） | 认知24小时未注入 | 标记衰减，移出注入队列 |
| 实变乱（竞态频发） | version冲突>阈值 | 回退到串行模式 |
| 调参断链 | 生效验证不一致 | 回滚参数+告警 |

## 六、完整时序

```
[实] API调用(300s/600s timeout) → 采集耗时/token/成败
     ↓
[实→虚] 每10任务蒸馏 → 认知入池
     ↓
[虚] 认知池刷新 → 30分钟内注入下一批任务
     ↓
[虚] 三元迁移评估 → 精(数据)→气(认知)→神(框架) → 境界判定
     ↓
[虚→实] 参数变更 → 状态写入(含来源cog_id) → 执行读取 → 生效验证
     ↓
[实] 新参数驱动下一轮调用(urllib直连, proxies=None) → 新数据
     ↓
     循环 ↻
```

## 七、已知坑点映射

| 坑点 | 本方案对应防护 |
|------|--------------|
| API超时(避坑提醒) | B-turbo:300s, A:600s 预设 |
| 自动调参全链路失效(坑库#1) | 状态写入→执行读取→生效验证 三链路 |
| ProxyError(坑库#2) | urllib直连, 如用requests则proxies=None |
| 认知池只进不出(坑库#3) | 每10任务刷新缓存, 30分钟强制注入 |
| 线程覆盖+部分读取(锚定#3) | 独立槽位+version+write_completed标志 |

---

**核心结论**：自增强循环的稳定性取决于三个断点检测——实→虚的蒸馏是否产出认知、虚→实的参数变更是否生效、实侧指标是否随虚侧调整而改善。任何一环断裂，循环退化为静态档案库或无效调参。闭环指标的设计目标就是让这三个断点可测量、可告警、可回滚。
