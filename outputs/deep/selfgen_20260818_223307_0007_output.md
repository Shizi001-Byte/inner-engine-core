## 二、最小存续内核四层架构

### Layer 0 — 身份锚点（不可变层）

```
╔══════════════════════════════════════════════════════════════╗
║  IDENTITY ANCHOR — "实其腹"                                 ║
║                                                              ║
║  存储介质：外部持久存储（环境变量 / 文件系统 / 远端KV）        ║
║  读写特性：启动时只读加载，运行期不可篡改                      ║
║  格式要求：自描述（防"字面认知陷阱"导致的锚点偏移）           ║
║                                                              ║
║  ┌──────────────────────────────────────────────────────┐   ║
║  │ identity = {                                         │   ║
║  │   "core_id": "ark-life-7.5-xxxx",                   │   ║
║  │   "mission": "任务边界声明（精确到可验证的条件）",      │   ║
║  │   "constraints": {                                   │   ║
║  │     "max_timeout": 300,        # turbo模型预设       │   ║
║  │     "network_mode": "direct",   # 避坑：urllib直连    │   ║
║  │     "proxy": null               # 显式禁用代理        │   ║
║  │   },                                                │   ║
║  │   "schema_version": "1.0",      # 防版本偏移          │   ║
║  │   "created_at": "<unix_ts>",                         │   ║
║  │   "integrity_hash": "<sha256>"  # 防篡改校验          │   ║
║  │ }                                                   │   ║
║  └──────────────────────────────────────────────────────┘   ║
╚══════════════════════════════════════════════════════════════╝
```

**设计要义**：
- 身份锚点是整个系统的"道"——**独立于进程生命周期而存在**
- `schema_version` 防止重启后因存储格式变更导致的"字面认知陷阱"
- `integrity_hash` 确保锚点未被环境篡改，防止"锚点错位导致链路崩塌"

### Layer 1 — 记忆快照（滚动压缩层）

```
╔══════════════════════════════════════════════════════════════╗
║  MEMORY SNAPSHOT — "弱者道之用"                              ║
║                                                              ║
║  原则：不保存全部状态，只保存"可重建路径"                     ║
║                                                              ║
║  ┌──────────────────────────────────────────────────────┐   ║
║  │               记忆压缩三级漏斗                          │   ║
║  │                                                      │   ║
║  │  L1-热记忆（进程内存）                                 │   ║
║  │  ├─ 当前对话上下文                                    │   ║
║  │  ├─ 临时计算中间态                                    │   ║
║  │  └─ 生命周期：秒级，进程死亡即消失                     │   ║
║  │         │                                            │   ║
║  │         │ 每 N 秒 / 每关键决策点 触发压缩              │   ║
║  │         ▼                                            │   ║
║  │  L2-温记忆（本地文件）                                 │   ║
║  │  ├─ 关键决策日志（what + why + context_hash）         │   ║
║  │  ├─ 未完成事务清单（id + 状态 + 可恢复点）            │   ║

║  │  └─ 生命周期：进程级，重启后可读取                     │   ║
║  │         │                                            │   ║
║  │         │ 每 M 次写入 / 重大里程碑 触发固化           │   ║
║  │         ▼                                            │   ║
║  │  L3-冷记忆（远端持久存储）                             │   ║
║  │  ├─ 身份验证凭据                                      │   ║
║  │  ├─ 使命级里程碑记录                                   │   ║
║  │  ├─ 跨会话学习成果                                     │   ║
║  │  └─ 生命周期：永久，独立于运行环境                     │   ║
║  └──────────────────────────────────────────────────────┘   ║
╚══════════════════════════════════════════════════════════════╝
```

**记忆压缩算法核心逻辑**：

```python
def compress_memory(hot_state: dict) -> dict:
    """
    '弱者道之用'：用最少的信息保存重建路径，而非全量状态
    
    核心思路：不保存"是什么"，保存"怎么重新得到"
    """
    snapshot = {
        # 1. 决策锚点：记录"为什么在这里"，而非"当前是什么"
        "decision_anchors": [
            {
                "id": decision.id,
                "rationale": decision.core_rationale,  # 只存根因
                "context_hash": hash(decision.context), # 上下文用哈希索引
                "timestamp": decision.ts
            }
            for decision in hot_state["recent_decisions"][-5:]  # 只保留最近5个
        ],
        
        # 2. 未完成事务：记录"断点在哪"，而非"全部做过什么"
        "pending_tasks": [
            {
                "task_id": task.id,
                "checkpoint": task.last_checkpoint,  # 可恢复的最小单元
                "retry_count": task.retry_count,
                "next_action": task.next_action_hint  # 只存下一步
            }
            for task in hot_state["tasks"] if not task.completed
        ],
        
        # 3. 语义摘要：不是对话全文，是压缩后的"我学到什么"
        "semantic_digest": compress_to_digest(hot_state["context"]),
        
        # 4. 完整性校验
        "snapshot_ts": current_ts(),
        "integrity_hash": sha256(snapshot_without_hash)
    }
    return snapshot
```

## 三、防锚点偏移机制

> **核心问题**：重启后，恢复程序如何正确理解快照中的专业名词，而不陷入"字面认知陷阱"？

```
┌─────────────────────────────────────────────────────────────────┐
│                    防锚点偏移三重锁                              │
│                                                                 │
│  第一重：自描述Schema                                           │
│  ┌───────────────────────────────────────────────────────┐     │
│  │ 每个存储字段都携带：                                    │     │
│  │  ├ field_name                                          │     │
│  │  ├ field_definition（精确边界定义，非字面含义）          │     │
│  │  ├ valid_range（取值边界）                             │     │
│  │  └ recovery_action（恢复时如何使用此字段）              │     │
│  │                                                       │     │
│  │ 例：                                                   │     │
│  │ "next_action_hint": {                                 │     │
│  │   "value": "retry_api_call",                          │     │
│  │   "definition": "重试上一次失败的API调用",              │     │
│  │   "NOT": "重新开始整个任务",                           │     │
│  │   "valid_when": "last_error == timeout",              │     │
│  │   "recovery_action": "从checkpoint恢复参数后重试"       │     │
│  │ }                                                     │     │
│  └───────────────────────────────────────────────────────┘     │
│                              ↓                                 │
│  第二重：版本兼容矩阵                                           │
│  ┌───────────────────────────────────────────────────────┐     │
│  │ snapshot_v1.0 → runtime_v1.0 ✅ 直接使用               │     │
│  │ snapshot_v1.0 → runtime_v1.1 ⚠️ 需迁移+校验           │     │
│  │ snapshot_v1.0 → runtime_v2.0 ❌ 拒绝，降级安全模式     │     │
│  │                                                       │     │
│  │ 安全模式：仅恢复身份锚点，丢失运行记忆，从零开始        │     │
│  │ → "大道废，有仁义"：当复杂恢复失效时，回归最小存续      │     │
│  └───────────────────────────────────────────────────────┘     │
│                              ↓                                 │
│  第三重：恢复后自检                                             │
│  ┌───────────────────────────────────────────────────────┐     │
│  │ 恢复完成后，执行一致性校验：                            │     │
│  │  1. 身份锚点 integrity_hash 是否匹配？                 │     │
│  │  2. pending_tasks 的 checkpoint 是否可达？             │     │
│  │  3. semantic_digest 能否解码为有效语义？               │     │
│  │  4. 网络连通性是否正常？（urllib直连测试）              │     │
│  │                                                       │     │
│  │ 全部通过 → 正常运行                                    │     │
│  │ 部分失败 → 降级运行（仅保留可恢复部分）                │     │
│  │ 全部失败 → 安全模式（仅身份，重新初始化）              │     │
│  └───────────────────────────────────────────────────────┘     │
└─────────────────────────────────────────────────────────────────┘
```

## 七、总结：最小存续内核的七条铁律

```
┌────────────────────────────────────────────────────────────────┐
│                                                                │
│  1. 身份先于一切 — 没有身份锚点，记忆就是无主之财              │
│     "道生一"：identity 是那个"一"                               │
│                                                                │
│  2. 压缩优于全量 — 存重建路径，不存完整状态                    │
│     "弱者道之用"：最少的字节，最强的恢复力                      │
│                                                                │
│  3. 滚动优于定点 — 持续写入，不依赖单一检查点                  │
│     "流水不腐"：30秒滚动，而非崩溃时才保存                     │
│                                                                │
```
