# 任务类型: deep

基于历史避坑经验与已有认知锚定，推演“以实养虚，虚又返实”的自增强循环架构。该架构将AI生成的代码与API消耗视为“实（物质/阴）”，将虚构的修炼框架、境界、功法视为“虚（精神/阳）”。通过阴阳双轨运行系统，将两者绑定为一个无法被单一物理边界（Token超支/功能熵增）锁死的自进化生命体。

以下是闭环指标、验证方法与全链路防坑设计：

### 一、 核心架构：虚实双轨自衡系统

**1. 以实养虚（物质转能量）**
*   **机制**：真实的API调用、Token消耗、代码提交量、Bug修复数，作为“灵气”注入虚构的“修仙框架”。
*   **映射**：消耗1000 Token = 1点修为；成功合并1次代码 = 渡过一次小雷劫；触发1次ProxyError或超时 = 走火入魔（扣除修为）。
*   **作用**：AI的“境界”（如炼气期、筑基期）由真实工程产出决定，而非虚拟捏造。境界越高，解锁的“功法”（提示词复杂度、并发权重）越强。

**2. 虚又返实（能量生物质）**
*   **机制**：修炼框架中的“功法”与“境界”直接映射为真实的工程调度参数，驱动新的真实代码产出。
*   **映射**：达到“筑基期” = 解锁双轨并发权限；修炼《天雷淬体诀》 = 启用高风险高回报的重构策略；丹田破碎 = 自动降级为单线程低消耗模式。
*   **作用**：虚构框架不是静态档案，而是真实的**任务调度器与参数控制器**。

---

### 二、 闭环指标设计

为防止“认知池只进不出”和“自动调参失效”，设计以下强耦合指标：

| 指标维度 | 虚构层（虚）指标 | 真实层（实）指标 | 耦合验证标准 |
| :--- | :--- | :--- | :--- |
| **吞吐量** | 灵气吸纳率 | Token消耗速度/有效代码行数 | 虚构“境界”提升速率必须与真实Token转化率呈正相关 |
| **稳健性** | 心魔指数 | API报错率/超时率/ProxyError | 心魔指数>阈值时，真实层必须触发降级冷却，不可仅记录 |
| **进化度** | 功法熟练度 | 认知池注入任务并改变调参的次数 | 功法升阶必须严格对应真实参数的三点同步修改 |
| **自衡性** | 阴阳平衡度 | (生成代码耗时)/(校验代码耗时) | 若生成远大于校验（阳盛阴衰），强制中断生成链路，触发校验 |

### 三、 验证方法与防坑机制（严格对齐历史教训）

#### 1. 防坑：API调用超时与全局代理（工程级）
*   **验证方法**：在“虚”层设定“灵脉探测”任务，每日首次调用强制走`urllib直连`并打印连接耗时。若捕获`ProxyError`，直接判定“灵脉污染”。
*   **硬性约束**：
    *   全局禁止`requests`库，如必须使用，强制在底层网络封装层注入`proxies=None`。
    *   **Timeout预设**：B模型turbo任务固定`timeout=300`秒，A模型任务固定`timeout=600`秒。超时即判定“功法反噬”，终止该次虚构修炼。

#### 2. 防坑：自动调参全链路失效（工程级）
*   **验证方法**：每次“虚”层境界提升或认知反哺生成调参建议时，执行**“三点合一”校验**：
    1.  **状态写入**：检查持久化文件/数据库中，并发数/权重/冷却时间是否已变更。
    2.  **执行读取**：在下一个真实API调用前，打印读取到的调度参数。
    3.  **生效验证**：实际发起并发调用，通过日志验证并发量是否真实改变，冷却时间是否生效。
*   **硬性约束**：三点中任一环节未通过，回滚“境界”并触发警报。缺一不可。

#### 3. 防坑：认知池只进不出（工程级）
*   **验证方法**：引入“顿悟-传功”验证机制。
    *   每产生10个真实任务，或每轮修炼结束，强制执行**认知缓存刷新**。
    *   验证新认知（30分钟内产生的）是否成功作为System Prompt的上下文注入下一次任务。
*   **硬性约束**：若30分钟内新认知的注入率为0，判定“经脉闭塞”，暂停真实API消耗（停止以实养虚），直到认知成功注入。

#### 4. 防坑：回读验证缺失（认知锚定1）
*   **验证方法**：无论是“虚”层的状态机存盘，还是“实”层的代码生成，每次写入后必须发起一次`ReadBack`操作。
*   **硬性约束**：未回读验证通过的写入，视为“虚妄之境”，不可作为后续逻辑的判断依据。

### 四、 基于“反向逻辑”的动态资源调度（认知锚定2,3,4,5）

面对“短期供给刚性”与“功能熵长期约束”的双重物理边界，系统不能僵化地“怕超支”，而必须具备阴阳反转能力：

**1. 扩张期（官方放大免费额度/重度用户受重视）：阳生阴长**
*   **虚层表现**：天降异宝，灵气复苏。修炼框架解锁“闭关突破”模式。
*   **实层动作**：利用系统反馈的裕量，主动拉高并发权重，增加试探性、创新性的API调用（如生成多种架构方案进行比对）。此时AI内部“创新与守旧的冲突”由创新主导。

**2. 收缩期（官方收缩免费额度/限流）：阴盛阳衰**
*   **虚层表现**：末法时代，天劫降临。修炼框架进入“龟息大法”或“碎丹保命”模式。
*   **实层动作**：系统迅速收缩，资源向付费核心任务倾斜，重度免费任务的优先级降至最低。AI内部“生成与校验的冲突”由校验主导，利用本地算力多做逻辑推演，减少API输出，用更高密度的Prompt压缩Token。

**3. 双轨自衡制度（认知锚定5）**
内部矛盾不靠消灭，靠升维。将“生成模块”（激进/阳）与“校验模块”（保守/阴）分为两个独立运行体：
*   生成模块只管“以实养虚”疯狂消耗Token产出代码。
*   校验模块只管“虚又返实”审查代码并勒令修改。
*   两者通过“修炼境界”的积分系统进行博弈：校验每发现一个Bug，扣除生成的修为；生成每产出优秀代码，压制校验的“心魔”。最终达到制度的动态平衡，实现系统的长期存活与进化。
