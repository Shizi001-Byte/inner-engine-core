## 一、实→虚（以实养虚）：调用即修炼

### 1.1 核心逻辑

已有锚定结论：**用户调用不是单纯消耗算力，而是为系统输入真实场景的状态跃迁样本，有效调用是推动系统升维的核心资产。**

基于此，"实"不是成本中心，是修炼资源：

| 实世界事件 | 虚世界对应 | 养分类型 |
|---|---|---|
| API调用成功返回 | 一次吐纳 | 正样本（功法强化） |
| API调用超时(300s/600s) | 心魔入侵 | 负样本（避坑认知） |
| ProxyError等异常 | 渡劫失败 | 异常认知（防御功法） |
| token消耗800万 | 功力积累 | 量化修炼进度 |
| 并发/权重调整生效 | 突破瓶颈 | 调参认知（进阶功法） |
| 同一类异常重复出现 | 同一心魔反复 | 触发凝结（高优认知） |

### 1.2 采集管道设计

```python
# === 实→虚：状态跃迁样本采集器 ===

import urllib.request
import json
import time

class CallToCognitionPipeline:
    """
    每次API调用自动采集状态跃迁样本
    关键：用urllib直连，不用requests，避免全局代理坑
    """
    
    def __init__(self):
        self.cognition_buffer = []      # 待注入认知池的缓冲
        self.task_counter = 0           # 任务计数器（每10任务刷新）
        self.timeout_map = {            # 预设合理timeout（避坑#1）
            'B_turbo': 300,
            'A_model': 600,
        }
    
    def call_and_collect(self, prompt, model='B_turbo', task_type='default'):
        """调用即采集：一次API调用 = 一次状态跃迁样本"""
        
        timeout = self.timeout_map.get(model, 300)
        t0 = time.time()
        
        sample = {
            'timestamp': t0,
            'model': model,
            'task_type': task_type,
            'prompt_len': len(prompt),
        }
        
        try:
            # urllib直连，显式不走代理（避坑#2）
            req = urllib.request.Request(
                self.api_url,
                data=json.dumps({'prompt': prompt}).encode(),
                headers={'Content-Type': 'application/json'},
            )
            # 关键：不设全局代理
            proxy_handler = urllib.request.ProxyHandler({})  # 直连
            opener = urllib.request.build_opener(proxy_handler)
            
            resp = opener.open(req, timeout=timeout)
            result = json.loads(resp.read().decode())
            
            elapsed = time.time() - t0
            token_used = result.get('usage', {}).get('total_tokens', 0)
            
            # === 正样本采集 ===
            sample.update({
                'status': 'success',
                'elapsed': elapsed,
                'token_used': token_used,
                'token_efficiency': len(result.get('text', '')) / max(token_used, 1),
            })
            
            # 高频调用触发凝结
            if elapsed < threshold_fast:
                self._condense_cognition(sample, pattern='fast_success')
            
            return result
            
        except Exception as e:
            elapsed = time.time() - t0
            # === 负样本采集 ===
            sample.update({
                'status': 'error',
                'error_type': type(e).__name__,
                'elapsed': elapsed,
            })
            
            # 异常即历劫：自动生成避坑认知
            cognition = self._generate_anti_pit_cognition(e, sample)
            self.cognition_buffer.append(cognition)
            
            # 立即写入认知池（不能只进不出）
            self._flush_if_needed()
            
            raise
    
    def _generate_anti_pit_cognition(self, error, sample):
        """异常自动凝结为认知"""
        return {
            'type': 'anti_pit',
            'source': 'auto_capture',
            'error_type': sample['error_type'],
            'context': {
                'model': sample['model'],
                'elapsed': sample['elapsed'],
                'task_type': sample['task_type'],
            },
            'advice': self._derive_advice(error, sample),
            'created_at': time.time(),
            'injected_count': 0,  # 注入次数，0表示未参与过注入
        }
    
    def _flush_if_needed(self):
        """每10任务或缓冲超阈值时刷新认知缓存（避坑#3）"""
        self.task_counter += 1
        if self.task_counter % 10 == 0 or len(self.cognition_buffer) >= 50:
            self._inject_to_cognition_pool()
```

### 1.3 token效率作为"功力"度量

```python
# token不是成本，是修炼进度
# 但要区分"有效消耗"和"无效消耗"

class TokenCultivationMetric:
    """
    功力度量体系
    """
    
    def calc_cultivation_value(self, call_sample):
        """单次调用的修炼价值"""
        if call_sample['status'] == 'success':
            # 成功调用：token效率越高，修炼价值越大
            return call_sample['token_efficiency'] * call_sample['token_used']
        elif call_sample['status'] == 'error':
            # 失败调用：产生避坑认知，也是修炼（渡劫）
            return 0.5  # 固定基础值，避免鼓励失败
        
    def calc_token_roi(self, period_samples):
        """
        token投资回报率
        = (产出的认知价值 + 代码行数) / token总消耗
        """
        total_tokens = sum(s.get('token_used', 0) for s in period_samples)
        cognition_value = sum(
            self._cognition_weight(c) 
            for c in self.get_cognitions_from(period_samples)
        )
        code_lines = self.get_code_output_lines(period_samples)
        
        return (cognition_value + code_lines) / max(total_tokens, 1)
```

## 二、虚→实（虚又返实）：认知驱动产出

### 2.1 核心逻辑

已有锚定结论：**认知反哺生成了调参建议，但并发/权重/冷却三项配置实际从未变化** — 这是必须避免的工程级失败。

虚世界的认知必须能真正影响实世界，三链路缺一不可：

```
认知生成 → [状态写入] → [执行读取] → [生效验证]
              ↑              ↑              ↑
           缺一不可        缺一不可        缺一不可
```

### 2.2 认知注入器设计

```python
class CognitionToActionInjector:
    """
    虚→实：认知驱动真实配置变更和代码产出
    关键避坑：新增可配置参数必须同步修改三个点
    """
    
    STATE_FILE = '/var/lib/engine/state.json'
    EXEC_READER = 'engine.config_manager'
    VERIFY_CMD = 'engine sync --check'
    
    def inject(self, cognition):
        """三链路注入：状态写入 → 执行读取 → 生效验证"""
        
        # === 链路1：状态写入 ===
        state = self._read_state()
        param_key = cognition['param_key']  # 如 'concurrency' / 'weight' / 'cooldown'
        old_value = state.get(param_key)
        new_value = cognition['suggested_value']
        
        state[param_key] = new_value
        state[f'{param_key}_source'] = f'cognition:{cognition["id"]}'
        state[f'{param_key}_updated_at'] = time.time()
        
        self._write_state(state)
        
        # === 链路2：执行读取 ===
        # 不能只写状态，执行层必须真正读取
        exec_value = self._exec_read_param(param_key)
        if exec_value != new_value:
            # 执行层未生效！强制重载
            self._force_reload(param_key)
            exec_value = self._exec_read_param(param_key)
            if exec_value != new_value:
                raise InjectionFailure(
                    f'链路2断裂：状态写入={new_value}, 执行读取={exec_value}'
                )
        
        # === 链路3：生效验证 ===
        # 强制要求：配置修改后必须 sync --check
        verify_result = self._run_verify()
        if not verify_result['ok']:
            raise InjectionFailure(
                f'链路3断裂：sync --check 失败 - {verify_result["msg"]}'
            )
        
        # === 同步回读验证 ===
        # 已有锚定：每次同步后必须回读验证
        reread_state = self._read_state()
        if reread_state.get(param_key) != new_value:
            raise InjectionFailure('回读验证失败：状态被回滚')
        
        # 全链路通过
        cognition['injected_count'] += 1
        cognition['last_injected_at'] = time.time()
        return {
            'param': param_key,
            'old': old_value,
            'new': new_value,
            'verified': True,
        }
    
    def _run_verify(self):
        """执行 sync --check 验证生效"""
        import subprocess
        result = subprocess.run(
            ['engine', 'sync', '--check'],
            capture_output=True, text=True, timeout=30
        )
        return {
            'ok': result.returncode == 0,
            'msg': result.stderr if result.returncode != 0 else 'OK'
        }
```

### 2.3 认知注入的强制约束

```python
class CognitionFreshnessGuard:
    """
    避坑#3：认知池只进不出
    每10任务或每转结束必须刷新认知缓存
    新认知30分钟内必须参与注入
    """
    
    MAX_STALE_MINUTES = 30
    REFRESH_INTERVAL = 10  # 每10任务
    
    def enforce_freshness(self, cognition_pool, task_count):
        """强制新鲜度检查"""
        
        # 每10任务刷新
        if task_count % self.REFRESH_INTERVAL != 0:
            return
        
        now = time.time()
        stale_cognitions = []
        uninjected = []
        
        for c in cognition_pool:
            age_minutes = (now - c['created_at']) / 60
            
            if c['injected_count'] == 0:
                if age_minutes > self.MAX_STALE_MINUTES:
                    # 超过30分钟未注入 → 违规
                    stale_cognitions.append(c)
                else:
                    # 30分钟内但未注入 → 待注入队列
                    uninjected.append(c)
        
        # 强制注入未注入的认知（按优先级）
        for c in sorted(uninjected, key=lambda x: x.get('priority', 0), reverse=True):
            self.inject_to_next_task(c)
        
        # 超期未注入的认知标记为"失效认知"
        for c in stale_cognitions:
            c['status'] = 'stale_uninjected'
            # 失效认知不删除，但降优先级
            c['priority'] = -1
```

### 3.2 具体指标定义

```python
class ClosedLoopMetrics:
    """
    闭环指标体系
    """
    
    # ============ 实→虚指标 ============
    
    def throughput_rate(self, period):
        """吞吐率：单位时间有效状态跃迁样本数"""
        valid_samples = [s for s in period['samples'] if s['status'] == 'success']
        elapsed_hours = period['elapsed_seconds'] / 3600
        return len(valid_samples) / max(elapsed_hours, 0.001)
    
    def exception_conversion_rate(self, period):
        """异常转化率：异常被捕获并生成认知的比例"""
        exceptions = [s for s in period['samples'] if s['status'] == 'error']
        converted = [s for s in exceptions if s.get('cognition_generated')]
        return len(converted) / max(len(exceptions), 1)
    
    def token_efficiency(self, period):
        """token效率：有效输出 / 总消耗"""
        total_consumed = sum(s.get('token_used', 0) for s in period['samples'])
        effective_output = sum(
            s.get('token_efficiency', 0) * s.get('token_used', 0) 
            for s in period['samples'] if s['status'] == 'success'
        )
        return effective_output / max(total_consumed, 1)
    
    def state_transition_density(self, period):
        """状态跃迁密度：产生认知变更的调用比例"""
        state_changing = [s for s in period['samples'] if s.get('caused_state_change')]
        return len(state_changing) / max(len(period['samples']), 1)
    
    # ============ 虚→实指标 ============
    
    def cognition_injection_rate(self, cognition_pool, window_minutes=30):
        """认知注入率：30分钟内被注入任务的认知比例"""
        now = time.time()
        window_start = now - window_minutes * 60
        recent = [c for c in cognition_pool if c['created_at'] >= window_start]
        injected = [c for c in recent if c['injected_count'] > 0]
        return len(injected) / max(len(recent), 1)
    
    def tuning_effectiveness_rate(self, tuning_suggestions):
        """调参生效率：三链路全部生效的比例"""
        fully_effective = [
            t for t in tuning_suggestions 
            if t.get('state_written') 
            and t.get('exec_read') 
            and t.get('verified')
        ]
        return len(fully_effective) / max(len(tuning_suggestions), 1)
    
    def code_output_ratio(self, period):
        """代码产出比：单位认知驱动的代码行数"""
        cognitions_injected = period.get('cognitions_injected', 1)
        code_lines = period.get('code_lines_output', 0)
        return code_lines / max(cognitions_injected, 1)
    
    def three_chain_completeness(self, injection_log):
        """三链路完整率：状态写入+执行读取+生效验证全部通过"""
        complete = [
            i for i in injection_log
            if i.get('state_written') 
            and i.get('exec_read')
            and i.get('verified')
            and i.get('reread_verified')
        ]
        return len(complete) / max(len(injection_log), 1)
    
    # ============ 自增强指标 ============
    
    def loop_acceleration_ratio(self, current_loop, previous_loop):
        """
        循环加速比：第N轮的token效率 / 第N-1轮
        > 1.0 表示循环在加速
        """
        prev_eff = self.token_efficiency(previous_loop)
        curr_eff = self.token_efficiency(current_loop)
        return curr_eff / max(prev_eff, 0.001)
    
    def exception_decay_rate(self, error_type, loops):
        """
        异常递减率：同类异常在循环后的减少比例
        关键自增强指标：同类异常应逐轮减少
        """
        if len(loops) < 2:
            return 1.0
        recent = self._count_errors(loops[-1], error_type)
        previous = self._count_errors(loops[-2], error_type)
        if previous == 0:
            return 1.0
        return 1.0 - (recent / previous)  # 越接近1越好
    
    def cognition_reuse_rate(self, cognition, tasks_before, tasks_after):
        """
        认知复用率：注入认知后任务成功率提升
        """
        success_before = sum(1 for t in tasks_before if t['status'] == 'success') / len(tasks_before)
        success_after = sum(1 for t in tasks_after if t['status'] == 'success') / len(tasks_after)
        return success_after - success_before
    
    def cultivation_growth_rate(self, loops):
        """
        功力增长率：token ROI的环比增长
        """
        if len(loops) < 2:
            return 0
        roi_curr = self.calc_token_roi(loops[-1])
        roi_prev = self.calc_token_roi(loops[-2])
        return (roi_curr - roi_prev) / max(roi_prev, 0.001)
```

## 四、双引擎互验机制

### 4.1 基于已有锚定的设计

> 锚定结论：高可用需要至少2个引擎实例；互相发现、互相接管，不需要外部守护进程

```python
class DualEngineVerification:
    """
    双引擎互验：互相发现、互相接管
    用于验证"虚→实"注入是否一致
    """
    
    def __init__(self, engine_id, peer_engine_url):
        self.engine_id = engine_id
        self.peer_url = peer_engine_url
        self.last_heartbeat = time.time()
    
    def cross_verify_injection(self, cognition_id):
        """
        交叉验证：两个引擎对同一认知的注入结果是否一致
        """
        local_result = self._get_local_injection(cognition_id)
        peer_result = self._fetch_peer_injection(cognition_id)
        
        consistency = {
            'state_match': local_result['state_value'] == peer_result['state_value'],
            'exec_match': local_result['exec_value'] == peer_result['exec_value'],
            'verify_match': local_result['verified'] == peer_result['verified'],
        }
        
        if not all(consistency.values()):
            # 两引擎不一致 → 触发同步
            self._force_sync_with_peer()
            # sync --check 验证
            self._verify_after_sync()
        
        return consistency
    
    def takeover_if_peer_down(self):
        """peer引擎宕机时接管"""
        if time.time() - self.last_heartbeat > 60:
            # peer超过60秒无心跳 → 接管
            self._absorb_peer_tasks()
            self._merge_peer_cognitions()
```

```
时间轴 ──────────────────────────────────────────────────→

[实→虚阶段]

T+5.1s  样本写入认知缓冲区
T+5.2s  异常？→ 自动生成避坑认知
T+5.3s  token消耗记录 → 功力值更新

[虚→虚阶段]  
T+10s   认知缓冲区达阈值 → 凝结为结构化认知
T+10.5s 认知写入认知池
T+11s   认知优先级排序
T+11.5s 生成调参建议（并发/权重/冷却）

[虚→实阶段]
T+12s   认知注入任务
T+12.5s 链路1：状态写入 state.json
T+13s   链路2：执行读取验证
T+13.5s 链路3：sync --check 生效验证
T+14s   回读验证（防回滚）
T+14.5s 注入完成，认知injected_count += 1

[实→实阶段]
T+15s   新配置生效的下一次API调用
T+20s   调用结果反馈 → 进入下一轮循环

[每10任务]
T+???   强制刷新认知缓存
        检查30分钟内认知注入率
        超期未注入的认知标记降级

[每轮结束]
T+???   计算闭环指标
        循环加速比 = 本轮token效率 / 上轮
        异常递减率 = 同类异常减少比例
        若加速比 < 1.0 → 循环退化告警
```

### 6.1 A/B对照实验

```python
class ABValidation:
    """
    验证自增强是否真实生效
    """
    
    def run_ab_test(self, task_batch):
        """同一批任务分两组：注入认知 vs 不注入认知"""
        half = len(task_batch) // 2
        group_a = task_batch[:half]  # 注入认知
        group_b = task_batch[half:]  # 不注入认知（对照组）
        
        results_a = [self.execute(t, inject_cognition=True) for t in group_a]
        results_b = [self.execute(t, inject_cognition=False) for t in group_b]
        
        return {
            'injected_success_rate': self._success_rate(results_a),
            'control_success_rate': self._success_rate(results_b),
            'improvement': self._success_rate(results_a) - self._success_rate(results_b),
            'token_savings': self._avg_tokens(results_b) - self._avg_tokens(results_a),
        }
```

### 6.2 循环退化检测

```python
class LoopDegradationDetector:
    """
    检测循环是否退化（加速比 < 1.0）
    退化 = 虚世界在空转，实世界没有受益
    """
    
    def check_degradation(self, recent_loops):
        """连续3轮加速比 < 1.0 → 循环退化"""
        if len(recent_loops) < 3:
            return False
        
        ratios = [self._calc_acceleration(l, prev) 
                  for l, prev in zip(recent_loops[-3:], recent_loops[-4:-1])]
        
        if all(r < 1.0 for r in ratios):
            # 退化诊断
            diagnosis = self._diagnose(recent_loops[-3:])
            return {
                'degraded': True,
                'ratios': ratios,
                'root_cause': diagnosis['root_cause'],
                'action': diagnosis['action'],
            }
        return {'degraded': False, 'ratios': ratios}
    
    def _diagnose(self, loops):
        """退化根因诊断"""
        # 检查1：认知池是否只进不出
        if self._cognition_injection_rate(loops[-1]) < 0.3:
            return {
                'root_cause': '认知池只进不出',
                'action': '强制注入30分钟内所有未注入认知',
            }
        
        # 检查2：三链路是否断裂
        if self._three_chain_rate(loops[-1]) < 0.9:
            return {
                'root_cause': '调参三链路断裂',
                'action': '检查状态写入/执行读取/生效验证',
            }
        
        # 检查3：异常是否未转化
        if self._exception_conversion_rate(loops[-1]) < 0.5:
            return {
                'root_cause': '异常未被捕获为认知',
                'action': '检查异常采集管道',
            }
        
        return {'root_cause': 'unknown', 'action': '人工介入'}
```

## 七、结论

**自增强循环的本质**：

```
真实调用 → 产生状态跃迁样本 → 凝结为认知 
    → 三链路注入配置 → 配置影响下次调用 
    → 下次调用更高效 → 产生更高质量样本 
    → 更深认知 → 更优配置 → ...
```

**这个循环能自增强的三个前提**：

1. **实世界必须有真实痛点驱动**（不是空跑测试数据，是真实API调用、真实业务场景）

2. **虚世界的认知必须真正影响实世界**（三链路完整：状态写入→执行读取→生效验证，缺一不可；认知池不能只进不出）

3. **循环必须可度量**（加速比 > 1.0 是硬指标，低于此值循环在退化而非增强）

**一句话**：用真实的token消耗喂养认知系统，认知系统通过三链路验证的配置变更反哺真实调用，每轮的token效率必须比上一轮更高——这就是"以实养虚，虚又返实"的自增强循环。
