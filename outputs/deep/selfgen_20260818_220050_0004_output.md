# 任务类型: deep

基于【已有认知锚定】与【坑库预警】，针对V7.5方舟效能引擎“多线程API调用后串行后处理”的架构，我们严格贯彻**“先校准锚点再优化链路”**原则，运用**“精气神三元迁移框架”**，推演“以实养虚，虚又返实”的自增强循环。

在此架构下，**“实”为API调用与Token消耗（精/资源层），“虚”为认知框架与决策策略（神/决策层），“气”为两者间的数据流过渡与状态校准**。以下为闭环推演、指标设计与验证方法：

---

### 一、 核心架构锚定与三元解耦

在“决策串行（神）、执行并发（精）、数据流过渡（气）”的架构下，核心矛盾是无序返回的“气”冲击了需要闭环校准的“神”。因此，必须切断执行层对决策层的越权侵入，实现三元解耦：

1. **精（资源层 / 数据态 / L4成品库）**：全系统唯一的最终归档地。并发执行的真实API调用、Token消耗记录、最终代码产出，均在此落盘。
2. **气（过渡层 / 控制流）**：负责将并发执行的无序返回结果进行串行化降维，剥离执行态，转化为决策态可读的标准化认知载体。
3. **神（决策层 / 认知态）**：全系统唯一的调度与调参中心。根据“气”输入的反馈，进行认知反哺，下发新一轮执行指令与配置。

---

### 二、 “以实养虚”：用真实API与Token喂养虚构框架

**“实”的采集（精生气）：**
多线程并发执行真实API调用，产生无序的返回结果与Token消耗日志。在此阶段，严格规避历史坑库：
*   **超时控制**：根据任务类型预设合理timeout，B模型turbo用300秒，A模型用600秒。
*   **代理熔断**：统一用urllib直连，不引入requests；如必须用requests，显式设置 `proxies=None`，彻底杜绝全局代理导致的ProxyError。

**“虚”的演化（气化神）：**
串行后处理接管无序的“气”，提取Token消耗量、调用成功率、错误分布等实体指标，将其提炼为“认知”。这些认知直接喂养虚构的修炼框架（决策层），生成调参建议（如并发数增减、冷却时间调整、模型路由切换）。
*   **避坑落实**：为防止“认知池只进不出”，每10任务或每转结束必须刷新认知缓存，新认知30分钟内必须参与注入，避免变成静态档案库。

---

### 三、 “虚又返实”：虚构框架驱动真实代码产出

**“虚”的输出（神驭气）：**
决策层（神）根据反哺的认知，生成新的执行参数与代码生成模板。为防止“自动调参全链路失效”，新增可配置参数必须严格执行三点闭环：
1. **状态写入**：决策层将新参数写入全局状态字典。
2. **执行读取**：并发执行层（精）在启动前必须读取最新状态。
3. **生效验证**：串行后处理（气）在回收结果时，必须校验当前批次是否已应用新参数（如校验实际并发数是否已变更）。

**“实”的再生产（气归精）：**
受新认知驱动的执行层，发起新一轮的真实API调用，产出真实的业务代码。这些代码进入L4成品库（精），完成“虚向实”的转化。

---

### 四、 闭环指标设计

为量化该自增强循环的健康度，设计以下三元指标：

| 框架层级 | 指标名称 | 指标定义 | 目标基线 |
| :--- | :--- | :--- | :--- |
| **精（实）** | Token产出比 | 有效代码Token数 / 消耗总Token数 | 随循环轮次呈上升趋势 |
| **精（实）** | 执行成功率 | 成功落盘L4的任务数 / 总并发任务数 | >95% |
| **气（流转）** | 认知注入率 | 30分钟内被任务引用的新认知数 / 新增认知总数 | >80%（防只进不出） |
| **神（虚）** | 调参生效比 | 实际变更的配置项数 / 决策层生成的调参建议数 | =100%（防全链路失效） |

---

### 五、 验证方法（三态一致性校验）

基于“先校准锚点再优化链路”原则，设计以下验证方法，确保“实-虚-实”循环不断链：

1. **状态一致性探针（防调参失效）**：
   在串行后处理阶段，注入探针代码。当决策层下发“并发数从5提升至10”的指令后，探针在下一轮API调用的并发池初始化前进行断言，若未读取到10，则抛出异常并回滚至上一稳定态。确保“状态写入-执行读取-生效验证”三态一致。

2. **认知时效性审计（防认知池淤塞）**：
   在L4成品库中建立时间戳审计。提取任意一段由认知驱动的代码，反查其依赖的认知ID。若该认知从生成到注入代码产出的时间差大于30分钟，则判定“气化神”通道阻塞，触发缓存强制刷新。

3. **网络直连压测（防ProxyError死灰复燃）**：
   在并发执行层启动前，执行环境变量检测脚本。若发现 `HTTP_PROXY` 或 `HTTPS_PROXY` 环境变量存在，则自动在代码运行上下文中强制置空，并使用urllib发起一次3秒心跳测试，确保网络层“纯净直连”。

4. **Timeout边界极限测试**：
   模拟A模型（600s）与B模型turbo（300s）的极慢响应，验证串行后处理是否因等待超时而导致整个“气”的流转阻塞。若超时发生，验证是否触发降级策略（如切断该任务，释放资源，将失败态回传决策层）。
