# 字面认知陷阱：通用机制推演与自动拆解方法论

> 锚定前提：本推演建立在 Guardian-Core 双进程架构、WAL+Snapshot 持久化、认知池 30 分钟注入规则之上，不重复论证底层机制。

---

## 一、陷阱生成的通用机制

### 1.1 核心假说：语义三重映射错位

任何专业术语在"规则定义→大众传播→任务执行"的链路上经历三重映射：

| 映射层 | 代号 | 来源 | 内容 |
|--------|------|------|------|
| 符号层 | S1 | 日常语料 | 字面词形触发的日常语义网络 |
| 定义层 | S2 | 规则文本 | 严格定义的边界、条件、例外 |
| 语境层 | S3 | 操作系统 | 在具体任务执行中真正起作用的语义 |

**陷阱生成条件**：当 S1 的激活强度远大于 S2，且 S3 的约束无法反向修正 S1 时，产生"字面认知陷阱"。

本质是：**大众的语义网络中，日常含义的权重路径太粗，专业含义的权重路径太细，导致推理时走了粗路径但以为是细路径。**

### 1.2 四种基础错位模式

| 模式 | 名称 | 机制 | 一句话 |
|------|------|------|--------|
| A | 日常词占用 | 术语借用了日常高频词的字面形态，日常含义激活权重远大于专业含义 | 词一样，意思不一样 |
| B | 维度坍缩 | 专业概念是多维条件集合，大众理解将其坍缩为一维标签 | 条件很多，但只记住一个 |
| C | 边界侵蚀 | 术语有严格边界，日常使用中被类推泛化，边界模糊 | 该用的地方用了，不该用的地方也用了 |
| D | 因果倒置 | 定义中 A 是 B 的必要条件，大众理解中 A 被当作充分条件 | 需要的被当成足够的 |

**四种模式可叠加**，叠加越多陷阱越深。

## 二、自动识别与拆解方法论

### 2.1 识别层：三个检测信号

```
┌─────────────────────────────────────────────────┐
│              陷阱词识别流水线                       │
│                                                   │
│  信号1: 词形-定义语义距离                          │
│  → 计算术语日常语义与规则定义的embedding距离        │
│  → 距离 > θ₁ → 候选陷阱词                         │
│                                                   │
│  信号2: 条件覆盖率                                 │
│  → 规则定义有N个原子条件                           │
│  → 大众语料平均提及K个                             │
│  → K/N < 0.5 → 候选陷阱词                         │
│                                                   │
│  信号3: 反例存活率                                 │
│  → 构造"符合大众理解但违反规则定义"的反例            │
│  → 反例不被大众识别为违反 → 确认陷阱词               │
└─────────────────────────────────────────────────┘
```

**三信号叠加**：三信号同时命中 → 确认为高优先级门槛类名词，进入拆解流程。

### 2.2 拆解层：SLD 三阶拆解法

```
S阶(Symbol)  ──  字面语义 vs 定义语义并列，显式标注差异点
                  产出: 差异对照表

L阶(Logic)   ──  将规则定义拆解为原子条件集合
                  标注: 必要条件(∧) / 充分条件(→) / 析取(∨)
                  产出: 条件逻辑表达式

D阶(Domain)  ──  在具体任务语境中给出操作语义
                  标注: 该术语在此任务中真正约束什么
                  产出: 语境操作语义卡
```

### 2.3 在 ChainTask 中的落地路径

```
ChainTask 执行
    │
    ├─ 1. 任务文本扫描 → 识别专业术语
    │
    ├─ 2. 三信号检测 → 标记陷阱词
    │
    ├─ 3. SLD三阶拆解 → 生成拆解卡
    │
    ├─ 4. 拆解卡写入认知池（遵循30分钟注入规则）
    │
    ├─ 5. 后续推演必须引用L阶条件表达式，禁止引用字面语义
    │
    └─ 6. 每轮结束刷新认知缓存，拆解卡进入下一轮注入
```

**关键约束**：推演中引用陷阱词时，如果未附带 L 阶条件表达式，Guardian 进程应拦截并要求补全——这是"以实养虚"闭环中功法约束执行的具体体现。

## 三、三个跨领域案例验证

### 案例 1：法律领域——"故意"

| 维度 | 内容 |
|------|------|
| **大众理解** | 故意 = 想要结果发生 |
| **规则定义** | 明知自己的行为会发生危害社会的结果，并且**希望或者放任**这种结果发生 |
| **错位模式** | B(维度坍缩) + C(边界侵蚀) |
| **坍缩分析** | 大众只保留"希望"，完全丢失"放任"这一维度 |
| **边界侵蚀** | 大众将"故意"泛化为"有意识的行为"，但法律中"有意识"≠"故意" |

**SLD 拆解**：
- **S**：字面"故意" → 日常语义"有意为之"
- **L**：`[明知结果会发生] ∧ ([希望结果发生] ∨ [放任结果发生])` → 故意
- **D**：刑事案件中，"放任"（间接故意）同样构成故意犯罪，量刑可能不同但定性一致

**反例验证**：司机明知超速可能撞人仍超速行驶，最终撞人。大众倾向认为是"过失"，法律认定为"间接故意"——因为"放任"维度在大众理解中不存在。

---

### 案例 2：计算机领域——"死锁"

| 维度 | 内容 |
|------|------|
| **大众理解** | 死锁 = 程序卡住不动了 |
| **规则定义** | 多个进程因竞争资源而造成的僵局，需**同时满足四个必要条件** |
| **错位模式** | B(维度坍缩) |
| **坍缩分析** | 四条件被坍缩为单一表象"卡住" |

**SLD 拆解**：
- **S**：字面"死锁" → 日常语义"锁死了，动不了"
- **L**：`[互斥] ∧ [占有并等待] ∧ [不可剥夺] ∧ [循环等待]` → 死锁（四条件**全部必要**）
- **D**：程序"卡住"≠死锁。可能是：活锁（一直在动但无进展）、饥饿（一直被抢占）、IO 等待、资源不足。只有四条件同时满足才是死锁，对应的解锁策略也不同

**反例验证**：线程 A 等待数据库返回结果而阻塞。大众认为是"死锁"，实际只是同步 IO 等待——不满足"循环等待"条件，杀掉对方进程也无法解决。

### 案例 3：金融领域——"对冲"

| 维度 | 内容 |
|------|------|
| **大众理解** | 对冲 = 买相反方向的，降低风险 |
| **规则定义** | 通过建立与现有头寸风险特征相反的头寸，**减少特定风险暴露**，但可能引入新的风险 |
| **错位模式** | D(因果倒置) + B(维度坍缩) |
| **因果倒置** | 大众认为"买了反方向"=对冲成功，但定义要求的是"净风险暴露降低"，买反方向只是手段不是目标 |
| **维度坍缩** | 丢失了"特定风险"限定——对冲消除一种风险但可能引入另一种 |

**SLD 拆解**：
- **S**：字面"对冲" → 日常语义"两头下注，稳赚不赔"
- **L**：`[识别现有头寸的特定风险R₁] → [建立相反风险特征头寸] → [验证: R₁净暴露↓] ∧ [验证: 新风险R₂可接受]` → 有效对冲
- **D**：对冲本质是风险置换，不是风险消除。基差风险、流动性风险、对手方风险都可能因对冲引入。完美对冲在实践中几乎不存在

**反例验证**：持有股票多头，买入等量看跌期权对冲。大众认为是"完美对冲"，但期权存在时间价值衰减（Theta损耗）、隐含波动率变化（Vega风险）、行权价与现价的基差——这些是"对冲"引入的新风险，大众理解中完全不存在。

## 四、方法论总结

```
                    ┌──────────────┐
                    │  专业术语出现  │
                    └──────┬───────┘
                           │
                    ┌──────▼───────┐
                    │  三信号检测    │
                    │  (距离/覆盖率/ │
                    │   反例存活率)  │
                    └──────┬───────┘
                           │
              ┌────────────┼────────────┐
              │            │            │
         命中0-1个      命中2个      命中3个
         常规术语      候选陷阱词    确认门槛词
                           │            │
                    ┌──────▼──────┐     │
                    │  SLD三阶拆解  │◄────┘
                    └──────┬──────┘
                           │
                    ┌──────▼──────┐
                    │  写入认知池   │
                    │  30分钟内注入  │
                    └──────┬──────┘
                           │
                    ┌──────▼──────┐
                    │ ChainTask    │
                    │ 推演强制引用   │
                    │ L阶条件表达式  │
                    └─────────────┘
```

**核心洞察**：字面认知陷阱的本质不是"理解错了"，而是**大众的语义激活路径走了高频低精度的粗路径，却以为走的是低频高精度的细路径**。拆解的目标不是"纠正错误"，而是在推演链路中**强制走细路径**——这正是"以实养虚"的体现：真实的推理失败数据暴露了陷阱词（实），驱动认知池生成拆解卡（虚），拆解卡又约束下一次推演必须走精确路径（返实）。
