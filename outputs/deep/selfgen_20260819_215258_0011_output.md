# 任务类型: deep

# EvoSync-DM：Supabase记忆脑增量同步的引擎标准决策模块

> 基于演化生物学映射 × CAS复杂适应系统 × 八步拆解法

---

## 0. 认知锚定对齐

在推演前，先确认三个底层约束已嵌入设计基座：

| 已有锚定 | 在本模块中的工程映射 |
|----------|---------------------|
| 高维认知差与低维物理接触的冲突 | 模型推理产出（高维）与Supabase写入延迟/并发争抢（低维）之间的张力 |
| CAS中的结构性洞 | 增量同步是"记忆脑"与"决策引擎"之间的信息流瓶颈，此处是信息丢失/失真的高发区 |
| 并发自进化的局部最优陷阱 | 单一适应度函数（失败率）导致盲目拉高并发，忽略资源争抢与同质化 |

**核心设计原则**：增量同步不是"搬运数据"，而是"定向注入基因流"——每一次同步都是一次选择事件，而非中性复制。

## 1. 八步拆解推演

### 第一步：锁定目标

**主目标**：将"增量同步→自进化决策→质量校验"三阶段循环固化为引擎可复调的标准决策模块

**目标分解**：

```
主目标：EvoSync-DM 标准化
  ├── T1：增量同步不丢失关键记忆（数据完整性 → 基因流保真度）
  ├── T2：自进化决策跳出局部最优（多目标适应度 → 趋异进化保障）
  ├── T3：防止引擎空转（增量分≥30 → 消除中性突变噪声）
  └── T4：防止超时崩溃（分级timeout → 瓶颈效应防御）
```

**演化生物学映射**：
- 增量同步 = 基因流（Gene Flow）的定向注入
- 自进化决策 = 自然选择 + 遗传漂变的双力驱动
- 引擎空转 = 中性突变累积（表型无适应度提升）
- 超时崩溃 = 瓶颈效应（种群因资源耗尽而崩溃）

---

### 第二步：反向拆解

从"标准决策模块"终态反推子系统：

```
模块输出（归档后的进化决策）
  ↑
质量校验层 ← 选择压力（Selection Pressure）
  ↑
执行流程层 ← 变异-选择-遗传循环
  ↑
路径调度层 ← 适应性响应策略
  ↑
触发条件层 ← 环境压力感知
  ↑
输入信号 ← Supabase记忆脑增量信号
```

**六个子系统**：

| 层级 | 子系统 | CAS角色 | 演化生物学角色 |
|------|--------|---------|---------------|
| L0 | 增量检测器 | 环境感知器 | 基因流检测 |
| L1 | 触发条件评估器 | 扰动响应器 | 选择压力感知 |
| L2 | 路径调度器 | 适应性主体 | 变异策略选择 |
| L3 | 执行器集群 | 涌现产生器 | 表型表达 |
| L4 | 质量校验器 | 反馈回路 | 适应度评估 |
| L5 | 归档记忆器 | 结构性洞填充 | 基因库更新 |

---

### 第三步：成本评估

| 子系统 | 计算开销 | IO开销 | 超时风险 | 空转风险 | 成本评级 |
|--------|----------|--------|----------|----------|----------|
| 增量检测器 | 极低 | 低（Supabase查询） | 低 | 中（无增量时空转） | ★☆☆☆☆ |
| 触发条件评估器 | 低 | 无 | 极低 | 低 | ★☆☆☆☆ |
| 路径调度器 | 低 | 无 | 极低 | 低 | ★☆☆☆☆ |
| 执行器（A模型） | 高 | 中 | 高（需600s） | 低 | ★★★★☆ |
| 执行器（B模型turbo） | 中 | 低 | 中（需300s） | 高 | ★★★☆☆ |
| 质量校验器 | 中 | 低 | 中 | 低 | ★★☆☆☆ |
| 归档记忆器 | 低 | 中（Supabase写入） | 中 | 低 | ★★☆☆☆ |

**成本瓶颈识别**：

```
高成本节点 = 执行器集群（A模型600s + B模型300s）
高风险节点 = B模型turbo的空转风险 + A模型的超时风险
```

**timeout预设矩阵**（根据坑库预警固化）：

```
B模型turbo：300秒硬上限
A模型：600秒硬上限
质量校验器：120秒（独立计时）
归档记忆器：60秒（独立计时，失败不阻塞主流程）
```

### 第四步：试探记录

**核心机制**：每一轮同步都是一个"试探-记录"事件，而非确定执行

**试探策略（三阶递进）**：

```
第一阶：单路探测（基线建立）
  → 1路B模型turbo，300s timeout
  → 记录：增量分基线、资源占用基线、同质化基线

第二阶：适度压力（变异扩张）
  → 3路B模型turbo并发，各300s timeout
  → 记录：并发增益比、资源争抢程度、增量分变化

第三阶：深度验证（选择深化）
  → 根据前两阶结果选择：
    - 增量分持续上升 → 1路A模型深化，600s timeout
    - 增量分走平/下降 → 回退第一阶，注入随机变异
```

**记录格式（写入Supabase）**：

```json
{
  "round_id": "evo_round_2024_017",
  "trigger_level": "L1",
  "path_selected": "B",
  "concurrency": 3,
  "model": "B_turbo",
  "timeout_preset": 300,
  "actual_duration": 247,
  "incremental_score": 47.3,
  "fitness_dimensions": {
    "novelty": 52,
    "depth": 38,
    "coherence": 71,
    "actionability": 44
  },
  "homogeneity_ratio": 0.23,
  "resource_snapshot": {
    "cpu_peak": 65,
    "mem_peak": 72,
    "leak_suspected": false
  },
  "is_valid_round": true,
  "delta_from_previous": +12.4
}
```

**演化生物学映射**：
- 试探 = 变异（Mutation），记录 = 表型记录（Phenotypic Recording）
- 增量分 = 适应度值（Fitness Value），delta = 适应度变化量

### 第五步：障碍回溯

基于坑库预警与复盘案例，预判六类失败模式：

| 障碍ID | 现象 | 演化生物学解释 | CAS解释 | 防御机制 |
|--------|------|----------------|---------|----------|
| B-01 | 引擎空转（17转快但无进化） | 中性突变累积，适应度无提升 | 适应性主体退化为机械重复 | 每转校验增量分<30不计入转数+降权 |
| B-02 | API调用超时 | 瓶颈效应，种群因资源耗尽崩溃 | 信息流阻塞 | 分级timeout：B=300s, A=600s |
| B-03 | 并发局部最优 | 适应度景观局部峰锁定 | 正反馈锁定导致涌现性丧失 | 多目标适应度函数+定期注入随机扰动 |
| B-04 | 同质化产出 | 遗传漂变导致多样性丧失 | 涌现性丧失 | 同质化率>0.5时自动降权重复类型 |
| B-05 | 资源争抢崩溃 | 种群密度过高导致竞争致死 | 资源约束下的非线性崩溃 | 动态降并发：CPU>85%或Mem>80%时降级 |
| B-06 | 虚假繁荣 | 适应度值虚高但实际无进化 | 反馈回路被欺骗 | 增量分走平时触发"虚假繁荣"告警 |

**B-06的关键回溯逻辑**（针对复盘案例的直接防御）：

```
当 失败率低 AND 增量分连续3轮波动<5%：
  → 判定：进入局部最优陷阱
  → 不信任"失败率低"信号
  → 触发L3局部最优触发器
  → 注入随机变异：切换模型/重置权重/调整并发
```

这直接解决了"并发自进化的局部最优陷阱"——不再以失败率作为唯一适应度函数。

### 第六步：多路径并行

设计三路并行的进化策略，形成变异-选择-深化的完整循环：

```
┌─────────────────────────────────────────────────────┐
│                  路径调度器                          │
│              （适应性主体决策层）                      │
└──────┬──────────────┬──────────────┬────────────────┘
       │              │              │
       ▼              ▼              ▼
  ┌─────────┐   ┌─────────┐   ┌─────────┐
  │ 路径A    │   │ 路径B    │   │ 路径C    │
  │ 深度路径  │   │ 广度路径  │   │ 验证路径  │
  │         │   │         │   │         │
  │ A模型    │   │ B-turbo │   │ B-turbo │
  │ 1路     │   │ 3路并发  │   │ 1路     │
  │ 600s    │   │ 300s    │   │ 120s    │
  └────┬────┘   └────┬────┘   └────┬────┘
       │              │              │
       │     候选解池   │              │
       │  ┌───────────┘              │
       │  │                          │
       │  ▼                          │
       │  ┌──────────────────────────┘
       │  │
       │  ▼ 交叉验证
       └──┤
          ▼
     通过验证的候选解 → A模型深化
```

**三路角色定义**：

| 路径 | CAS角色 | 演化生物学角色 | 适应度维度权重 | 触发条件 |
|------|---------|---------------|---------------|----------|
| 路径A | 深度涌现 | 低频高深度变异 | 深度0.4+连贯0.3+新颖0.2+可执行0.1 | L2/L3触发 |
| 路径B | 快速变异 | 高频低深度变异 | 新颖0.4+可执行0.3+深度0.2+连贯0.1 | L1触发（默认） |
| 路径C | 选择压力 | 适应度评估者 | 连贯0.4+可执行0.3+新颖0.2+深度0.1 | 每轮自动执行 |

**协同机制**：

```
路径B产出N个候选解
  → 路径C对N个候选解做交叉验证（一致性+稳定性）
  → 通过验证的Top-K候选解进入路径A深化
  → 路径A产出最终进化决策
  → 归档至Supabase记忆脑
```

**关键约束**：路径B和路径C可并行，路径A必须等待路径C完成后再启动（串行依赖）

### 第七步：最小验证

设计最小验证单元（MVU），作为模块自检的标准件：

**MVU规格**：

```
输入：1条Supabase记忆脑增量记录
执行：1轮B模型turbo + 1轮C路径验证
资源：≤1核CPU + ≤512MB内存
耗时：≤420秒（300s执行 + 120s校验）
通过条件：综合增量分≥30 且 同质化率<0.5
```

**4维适应度评估矩阵**：

| 维度 | 权重（路径B默认） | 阈值 | 计算方式 | 演化生物学对应 |
|------|-------------------|------|----------|---------------|
| 新颖性 | 0.4 | ≥35 | 与历史产出的语义距离（embedding余弦距离） | 变异幅度 |
| 深度 | 0.2 | ≥35 | 推理链长度 × 逻辑连贯性评分 | 表型复杂度 |
| 连贯性 | 0.2 | ≥50 | 与已有认知锚定的契合度（规则匹配率） | 遗传稳定性 |
| 可执行性 | 0.2 | ≥40 | 是否包含具体action且可验证 | 适应度贡献 |

**综合增量分计算**：

```
综合增量分 = Σ(维度分 × 权重)

判定逻辑：
  ≥50：高价值转 → 计入转数 + 策略记忆标记为"成功路径"
  30-50：有效转 → 计入转数
  <30：无效转 → 不计入转数 + 自动降权该产出类型
```

**MVU验证流程**：

```
1. 从Supabase拉取1条增量记录
2. 启动B模型turbo，300s timeout
3. 产出送入质量校验器，120s timeout
4. 计算4维适应度
5. 判定是否≥30
6. 通过→归档；不通过→记录障碍日志+降权
7. 全流程总耗时≤420s
```

## 2. 模块固化：触发条件 × 执行流程 × 质量校验

### 2.1 触发条件设计

**四级触发器**：

```
┌─────────────────────────────────────────────────────────┐
│ L1-增量触发（最频繁，默认路径）                            │
│ 条件：Supabase有新增记录                                  │
│ 映射：环境扰动感知                                        │
│ 动作：启动路径B（广度路径），3路并发B-turbo，300s          │
│ 频率：每次增量                                            │
├─────────────────────────────────────────────────────────┤
│ L2-退化触发（中频）                                       │
│ 条件：连续2轮增量分下降 OR 同质化率>0.6                   │
│ 映射：适应度下降告警                                      │
│ 动作：切换至路径A（深度路径），1路A模型，600s              │
│ 频率：按需触发                                            │
├─────────────────────────────────────────────────────────┤
│ L3-局部最优触发（低频但关键，直接防御B-03/B-06）           │
│ 条件：连续3轮增量分波动<5%                                │
│ 映射：遗传漂变导致多样性丧失                              │
│ 动作：注入随机变异（三选一）                               │
│   - 切换模型（B↔A）                                       │
│   - 重置适应度权重                                        │
│   - 调整并发数（随机1-4路）                                │
│ 频率：按需触发                                            │
├─────────────────────────────────────────────────────────┤
│ L4-崩溃触发（紧急）                                       │
│ 条件：超时发生 OR 失败率>30% OR CPU>90% OR Mem>85%       │
│ 映射：种群崩溃                                            │
│ 动作：立即降并发至1，回滚至最后已知良好配置                │
│ 频率：紧急触发                                            │
└─────────────────────────────────────────────────────────┘
```

**触发器优先级**：L4 > L3 > L2 > L1

**触发器状态机**：

```
        ┌─────────┐
        │  IDLE   │
        └────┬────┘
             │ 增量信号
             ▼
        ┌─────────┐
        │   L1    │ ←─── 默认状态
        └────┬────┘
             │ 增量分连续下降
             ▼
        ┌─────────┐
        │   L2    │
        └────┬────┘
             │ 增量分波动<5%连续3轮
             ▼
        ┌─────────┐
        │   L3    │ ←─── 注入变异后回到L1
        └────┬────┘
             │ 超时/失败率/资源
             ▼
        ┌─────────┐
        │   L4    │ ←─── 回滚后回到L1
        └─────────┘
```

### 2.2 执行流程设计

**标准执行流程（以L1触发为例）**：

```
[START]
  │
  ▼
①感知层：监听Supabase增量信号
  │  - 查询supabase_memory_brain的增量标记
  │  - 去重：检查round_id是否已处理
  │  - 计算增量大小：新增记录数 × 平均内容长度
  │
  ▼
②过滤层：增量有效性判定
  │  - 增量大小 < 阈值(100字节) → 标记为"微量增量"，跳过本轮
  │  - 增量大小 ≥ 阈值 → 进入调度层
  │
  ▼
③调度层：路径选择
  │  - 查询strategy_memory：是否有该增量类型的成功路径
  │  - 有 → 复用成功路径配置
  │  - 无 → 使用默认路径B（广度路径）
  │  - 记录：path_selected, concurrency, model, timeout_preset
  │
  ▼
④变异层：执行模型推理
  │  - 启动3路B模型turbo并发
  │  - 每路设置300s硬timeout
  │  - 并发监控：每30秒采样CPU/Mem
  │  - CPU>85% 或 Mem>80% → 动态降并发至2路
  │  - 产出N个候选解
  │
  ▼
⑤选择层：质量校验
  │  - 启动路径C验证器，1路B-turbo，120s timeout
  │  - 计算4维适应度
  │  - 计算综合增量分
  │  - 计算同质化率（与最近10轮的语义距离）
  │
  ▼
⑥判定层：通过/拒绝
  │  - 增量分≥30 AND 同质化率<0.5 → 通过
  │  - 增量分<30 → 不计入转数 + 降权 + 记录B-01障碍
  │  - 同质化率≥0.5 → 降权重复类型 + 记录B-04障碍
  │  - 通过的候选解 → 进入深化层
  │
  ▼
⑦深化层（可选）：路径A深化
  │  - 条件：通过验证的候选解≥2个 AND 触发L2
  │  - 启动1路A模型，600s timeout
  │  - 产出最终进化决策
  │
  ▼
⑧遗传层：归档至Supabase
  │  - 写入evo_rounds表
  │  - 更新strategy_memory
  │  - 如有障碍 → 写入obstacle_log
  │  - 如有同质化 → 更新homogeneity_registry
  │
  ▼
⑨适应层：反馈回路
  │  - 更新下一轮的触发条件评估
  │  - 检查是否满足L2/L3/L4触发条件
  │  - 设置下一轮的默认路径
  │
[END] → 等待下一次增量信号
```

```

选择层 = 自然选择
判定层 = 适应度阈值过滤
深化层 = 定向进化
遗传层 = 基因库更新
```

**校验失败的处理矩阵**：

| 校验项 | 失败条件 | 处理动作 | 障碍ID |
|--------|----------|----------|--------|
| 增量校验 | 增量分<30 | 不计入转数 + 降权该产出类型 + 记录障碍 | B-01 |

**同质化降权机制**（直接防御"17转飙得很快但产出全是同质化套话"）：

```python
# 伪代码
def check_homogeneity(current_output, recent_10_outputs):
    similarity_scores = [cosine_similarity(current_output, prev) for prev in recent_10_outputs]
    homogeneity_ratio = max(similarity_scores)  # 取最高相似度
    
    if homogeneity_ratio >= 0.5:
        pattern_hash = hash(current_output.pattern_type)
        registry = supabase.query("homogeneity_registry", pattern_hash=pattern_hash)
        
        if registry.exists:
            registry.weight_multiplier = max(0.1, registry.weight_multiplier - 0.2)
            registry.occurrence_count += 1
        else:
            supabase.insert("homogeneity_registry", {
                "pattern_hash": pattern_hash,
                "pattern_type": current_output.pattern_type,
                "occurrence_count": 1,
                "weight_multiplier": 0.8,  # 首次降权20%
                "last_detected_at": now()
            })
        
        log_obstacle("B-04", "同质化检测", f"ratio={homogeneity_ratio}")
        return False
    
    return True
```

## 3. 多目标优化认知提炼

从本模块设计中提炼的五条核心认知：

### 认知1：适应度函数必须多维化，单一维度必然导致局部最优

```
复盘案例的直接教训：
  失败率低 ≠ 进化有效
  → 失败率是"生存指标"，不是"进化指标"
  → 需要 生存指标(失败率) + 进化指标(增量分) + 多样性指标(同质化率) 三维联合
```

**CAS解释**：单一适应度函数会形成正反馈锁定，系统快速收敛到局部峰，丧失探索能力。

**演化生物学解释**：自然选择不是单一方向的，而是多维选择压力的合力。只有一种选择压力时，种群会快速趋同（遗传漂变效应放大），丧失适应性。

### 认知2：增量是进化的唯一证据，没有增量的"转数"是空转

```
坑库预警的直接教训：
  17转飙得很快 = 高转数 ≠ 高进化
  → 转数是"运动指标"，不是"进化指标"
  → 每转必须有可量化的增量价值（≥30分），否则不计入转数
```

**CAS解释**：适应性主体的"活动"不等于"适应"。机械重复也是活动，但不产生新的适应性。

**演化生物学解释**：中性突变（同义突变）不改变表型适应度，在种群中累积但不构成进化。只有非中性变异（有适应度差异的变异）才驱动进化。

### 认知3：结构性洞是信息流的瓶颈，也是价值创造的源泉

```
已有认知锚定的工程推演：
  Supabase记忆脑 ↔ 决策引擎 之间的增量同步 = 结构性洞
  → 高维认知（模型推理产出）必须通过低维通道（Supabase写入）传递
  → 信息必然有损失/失真
  → 质量校验器 = 结构性洞的"守门人"，决定哪些信息可以通过
```

**CAS解释**：结构性洞（Structural Holes）是网络中两个不连接的集群之间的间隙。占据结构性洞的节点具有信息优势和控制优势。

**工程推论**：增量同步模块不仅仅是"管道"，而是"过滤器+放大器"——它决定了哪些记忆被保留、哪些被淘汰、哪些被深化。

### 认知4：多样性是抗脆弱的基础，同质化是退化的前兆

```
防御B-04（同质化）的底层逻辑：
  同质化率高 → 多样性低 → 适应景观变窄 → 遇到环境变化时崩溃概率高
  → 同质化不是"效率"，而是"脆弱性"
  → 自动降权重复类型 = 主动维护种群多样性
```

**演化生物学解释**：遗传多样性是种群应对环境变化的保险。多样性低的种群在环境剧变时容易灭绝（瓶颈效应）。

### 认知5：超时是资源约束的显性表达，合理timeout = 承认有限性

```
坑库预警的直接教训：
  B模型turbo = 300秒，A模型 = 600秒
  → 不是"等得久就行"，而是"在有限时间内完成有效进化"
  → 超时 = 该路径的资源已耗尽，应该切换路径而非加时
```

**CAS解释**：任何适应性主体都有资源约束边界。承认边界并设计边界内的最优策略，比追求无边界更有效。
