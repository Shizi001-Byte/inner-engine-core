# 推演：以实养虚，虚又返实——自增强循环架构设计

---

## 一、核心定义与边界

### 1.1 概念锚定

```
实 = 真实API调用、真实token消耗、真实延迟数据、真实错误堆栈
虚 = 修炼框架（认知池、策略空间、参数推荐引擎、模式抽象层）
```

**"以实养虚"**：每次真实API调用产生的遥测数据，经串行决策链路提炼为认知条目，注入认知池——这是"用真实经验喂养虚拟框架"。

**"虚又返实"**：认知池中的条目经注入机制参与任务调度、路由决策、参数调优，产出真实代码和真实API调用——这是"虚拟框架驱动真实产出"。

### 1.2 与脑体分离架构的对接

| 层级 | 角色 | 在自增强循环中的职责 |
|------|------|---------------------|
| 脑（引擎） | 串行决策 | 将"实"提炼为"虚"的状态机推进；将"虚"转化为"实"的执行指令下发 |
| 体（算子） | 并发执行 | 产生"实"（API调用/代码产出）；执行"虚"转化的指令（参数变更/路由切换） |

**不可破坏性约束**：虚实转化全链路必须在脑层串行推进，体层只负责"产生实的原料"和"执行虚的指令"。若将提炼或注入逻辑下沉到并发体层，则状态不可重放，循环断裂。

## 二、以实养虚：从真实调用到认知沉淀

### 2.1 数据采集层（炼气——采集真实元气）

每次真实API调用产生一条**遥测记录**，结构如下：

```python
@dataclass
class TelemetryRecord:
    # ── 调用上下文 ──
    task_id: str
    model_used: str           # 实际路由到的模型
    turn_index: int          # 第几轮
    operator_type: str       # 算子类型（生成/验证/修复）
    
    # ── 真实消耗 ──
    input_tokens: int        # 真实输入token
    output_tokens: int       # 真实输出token
    latency_ms: int          # 真实延迟
    api_cost: float          # 真实费用
    
    # ── 结果状态 ──
    success: bool
    error_type: str | None
    retry_count: int
    
    # ── 认知上下文（当时注入了什么）──
    injected_cognition_ids: list[str]  # 本次调用时注入了哪些认知
```

**关键设计**：记录`injected_cognition_ids`——这是闭环的"回溯锚点"，使得后续可以验证"注入的认知是否真的影响了结果"。

### 2.2 模式提炼层（筑基——从数据到模式）

引擎串行扫描遥测记录，按固定窗口（每10任务或每转结束）触发提炼：

```python
def extract_patterns(records: list[TelemetryRecord]) -> list[CognitionEntry]:
    """
    脑层串行执行，严禁下沉到并发体层。
    输入：一个窗口内的遥测记录
    输出：提炼出的认知条目
    """
    patterns = []
    
    # 模式1：模型-任务类型-延迟分布
    latency_patterns = aggregate_latency_by_model_task(records)
    for (model, task_type), stats in latency_patterns.items():
        if stats.p95_ms > get_timeout_config(model):
            patterns.append(CognitionEntry(
                content=f"{model}处理{task_type}的P95延迟({stats.p95_ms}ms)已超timeout阈值",
                source="latency_monitor",
                confidence=stats.sample_count / 10,  # 样本越多置信度越高
                action_hint="increase_timeout",  # 虚→实的指令暗示
            ))
    
    # 模式2：认知注入-成功率关联
    cognition_effectiveness = correlate_injection_with_success(records)
    for cog_id, effectiveness in cognition_effectiveness.items():
        if effectiveness.lift < 0:  # 注入后成功率反而下降
            patterns.append(CognitionEntry(
                content=f"认知{cog_id}注入后成功率下降{abs(effectiveness.lift)*100}%",
                source="injection_correlator",
                confidence=effectiveness.sample_count / 10,
                action_hint="deprecate_cognition",
            ))
    
    # 模式3：token消耗异常
    token_outliers = detect_token_anomalies(records)
    for outlier in token_outliers:
        patterns.append(CognitionEntry(
            content=f"任务{outlier.task_type}在{outlier.model}上token消耗为均值{outlier.ratio}倍",
            source="token_monitor",
            confidence=0.8,
            action_hint="route_redirect",
        ))
    
    return patterns
```

### 2.3 认知入池（金丹——固化认知）

提炼出的模式经引擎校验后写入认知池：

```python
def commit_to_cognition_pool(entries: list[CognitionEntry], pool: CognitionPool):
    for entry in entries:
        if entry.confidence < CONFIDENCE_THRESHOLD:
            continue  # 置信度不足，不入池
        
        # 去重：同源同类认知只保留最新
        existing = pool.find_similar(entry.source, entry.content_hash)
        if existing:
            pool.update(existing.id, entry)  # 更新而非追加
        else:
            pool.add(entry)
    
    # 触发缓存刷新——避坑#3的核心
    pool.refresh_cache()  # 必须同步刷新，否则认知池"只进不出"
```

## 三、虚又返实：从认知到真实代码产出

### 3.1 认知注入层（元婴——虚拟反哺真实）

```python
def inject_cognition(task_context: TaskContext, pool: CognitionPool) -> TaskContext:
    """
    脑层串行执行，在任务派发前完成注入。
    注入是"虚→实"的桥接点：认知影响prompt，prompt影响API调用，API调用产生真实结果。
    """
    # 按任务类型检索相关认知
    relevant = pool.query(
        task_type=task_context.type,
        model=task_context.target_model,
        limit=COGNITION_INJECTION_LIMIT,  # 限制注入量，避免prompt爆炸
    )
    
    # 按时效性过滤——避坑#3的约束
    fresh = [c for c in relevant if c.age_minutes < 30]  # 30分钟内必须参与注入
    
    # 按confidence排序，取Top-N
    fresh.sort(key=lambda c: c.confidence, reverse=True)
    selected = fresh[:MAX_INJECTIONS_PER_TASK]
    
    # 注入到prompt的system段
    task_context.system_prompt += render_cognition_block(selected)
    task_context.injected_cognition_ids = [c.id for c in selected]
    
    # ── 避坑#1：三段式验证 ──
    # 点1：状态写入——记录注入了什么
    state.write(f"task.{task_context.id}.injections", task_context.injected_cognition_ids)
    
    return task_context
```

### 3.2 参数调参执行（化神——虚拟改变真实行为）

认知中的`action_hint`触发真实的参数变更：

```python
def apply_cognition_actions(entry: CognitionEntry, config: SystemConfig):
    """
    避坑#1核心：新增可配置参数必须同步修改三个点
    """
    if entry.action_hint == "increase_timeout":
        old_value = config.timeout[entry.target_model]
        new_value = int(old_value * 1.5)
        
        # 点1：状态写入
        state.write(f"config.timeout.{entry.target_model}", new_value)
        
        # 点2：执行读取
        config.timeout[entry.target_model] = state.read(f"config.timeout.{entry.target_model}")
        
        # 点3：生效验证
        assert config.timeout[entry.target_model] == new_value, "参数未生效"
        log_param_change(
            cognition_id=entry.id,
            param="timeout",
            model=entry.target_model,
            old=old_value, new=new_value,
            verified=True,
        )
```

### 3.3 真实代码产出（返虚入实——最终落地）

认知注入后的任务上下文派发给体层并发执行：

```python
def dispatch_to_operators(task_context: TaskContext, executor: ConcurrentExecutor):
    """
    体层并发执行，产生真实代码产出。
    脑层已串行完成决策（路由+注入+参数），体层只管执行。
    """
    # 此时task_context已携带注入的认知和调整后的参数
    results = executor.submit(
        tasks=task_context.subtasks,
        timeout=task_context.timeout,  # 已被认知调参影响
        proxies=None,  # 避坑#2：显式禁用代理
    )
    
    # 采集"实"——真实结果回传脑层
    for result in results:
        record = TelemetryRecord(
            task_id=task_context.id,
            model_used=task_context.target_model,
            input_tokens=result.input_tokens,
            output_tokens=result.output_tokens,
            latency_ms=result.latency_ms,
            success=result.success,
            injected_cognition_ids=task_context.injected_cognition_ids,  # 回溯锚点
        )
        telemetry_buffer.append(record)  # 喂养下一轮"以实养虚"
```

## 四、闭环指标体系

### 4.1 指标全景图

```
┌─────────────────────────────────────────────────────────┐
│                    自增强循环指标                          │
├──────────────┬──────────────┬────────────────────────────┤
│  以实养虚    │  虚又返实    │      自增强验证             │
│  (实→虚)     │  (虚→实)     │      (循环健康度)          │
├──────────────┼──────────────┼────────────────────────────┤
│ 采集覆盖率   │ 注入命中率   │ 闭环完整性分数              │
│ 提炼转化率   │ 参数变更率   │ 虚实一致性系数              │
│ 认知增长率   │ 代码产出影响率│ 自增强斜率                  │
│ 认知活性     │ 回灌延迟     │ 熵减趋势                    │
└──────────────┴──────────────┴────────────────────────────┘
```

### 4.2 核心指标定义

#### 4.2.1 以实养虚指标（实→虚）

**指标1：采集覆盖率**
```
采集覆盖率 = 已采集遥测字段的API调用数 / 总API调用数
```
目标：100%。每个API调用必须产生完整遥测记录。

**指标2：提炼转化率**
```
提炼转化率 = 一个窗口内提炼出的认知条目数 / 窗口内遥测记录数
```
不是越高越好——过高说明噪音太多，过低说明提炼逻辑失效。健康区间：0.05~0.15（每10条遥测提炼出0.5~1.5条认知）。

**指标3：认知活性（避坑#3的直接度量）**
```
认知活性 = 最近30分钟内被注入过的认知条目数 / 认知池总条目数
```
- 活性 < 10%：认知池退化成静态档案库，踩坑#3
- 活性 > 80%：认知池过小或注入过多噪音
- 健康区间：30%~70%

#### 4.2.2 虚又返实指标（虚→实）

**指标4：注入命中率**
```
注入命中率 = 注入了认知的任务成功率提升 / 未注入认知的同类任务成功率
```
对比方法：同一任务类型，有注入vs无注入的成功率差异。正值说明认知有效，负值说明认知有害（应触发deprecate）。

**指标5：参数变更率（避坑#1的直接度量）**
```
参数变更率 = 实际生效的参数变更数 / 认知建议的参数变更数
```
- 变更率 < 100%：说明有认知建议未被执行，踩坑#1
- 必须为100%——每条action_hint要么执行要么显式拒绝（带拒绝原因）

**指标6：回灌延迟**
```
回灌延迟 = 从遥测记录产生 → 到该记录影响的认知注入到新任务 的时间差
```
- > 30分钟：违反避坑#3的约束
- 健康区间：< 5分钟

#### 4.2.3 自增强验证指标（循环健康度）

**指标7：虚实一致性系数**
```
虚实一致性 = 虚拟模型预测的成功率 / 实际API调用的成功率 的相关系数
```
衡量"虚"（认知预测）与"实"（真实结果）的一致程度。应随循环迭代趋近1.0。

**指标8：自增强斜率**
```
自增强斜率 = 第N轮循环的关键指标改善量 / 第N-1轮的关键指标改善量
```
- 斜率 > 1.0：自增强生效，每轮改善在加速
- 斜率 = 1.0：线性改善，自增强未加速
- 斜率 < 1.0：改善在减速，循环可能进入瓶颈

**指标9：熵减趋势**
```
熵 = -Σ(p_i × log(p_i))，其中p_i是第i类错误/失败模式的发生概率
```
自增强循环应驱动错误分布收敛（少数高频错误被认知消除），表现为熵持续下降。若熵上升，说明出现新的错误模式未被认知覆盖。

## 五、验证方法设计

### 5.1 闭环完整性验证

```python
def verify_loop_integrity(metrics: LoopMetrics) -> LoopHealthReport:
    """
    验证自增强循环是否真正闭合，而非空转。
    """
    issues = []
    
    # ── 检查1：实→虚通道是否畅通 ──
    if metrics.coverage < 1.0:
        issues.append(f"采集覆盖率{metrics.coverage}，有API调用未产生遥测")
    
    if metrics.extraction_rate < 0.02:
        issues.append(f"提炼转化率{metrics.extraction_rate}过低，遥测未被有效提炼")
    
    if metrics.cognition_vitality < 0.1:
        issues.append(f"认知活性{metrics.cognition_vitality}，认知池退化为静态档案库")
    
    # ── 检查2：虚→实通道是否畅通 ──
    if metrics.param_change_rate < 1.0:
        issues.append(f"参数变更率{metrics.param_change_rate}，认知建议未被执行（踩坑#1）")
    
    if metrics.feedback_latency > 30 * 60:  # 30分钟
        issues.append(f"回灌延迟{metrics.feedback_latency}s，认知30分钟内未参与注入（踩坑#3）")
    
    # ── 检查3：自增强是否真正发生 ──
    if metrics.consistency < 0.5:
        issues.append(f"虚实一致性{metrics.consistency}，认知预测与实际结果严重背离")
    
    if metrics.slope < 1.0 and metrics.slope > 0:
        issues.append(f"自增强斜率{metrics.slope}，改善在减速")
    
    if metrics.slope <= 0:
        issues.append(f"自增强斜率{metrics.slope}，循环在退化而非增强")
    
    return LoopHealthReport(
        healthy=len(issues) == 0,
        issues=issues,
        metrics=metrics,
    )
```

### 5.2 A/B对照验证（终极验证）

```python
def ab_test_cognition_effect(cycles: int = 10) -> ABTestResult:
    """
    终极验证：有认知注入 vs 无认知注入，对比关键指标。
    
    这是验证"虚又返实"是否真正发生的金标准。
    """
    group_a = []  # 有认知注入（实验组）
    group_b = []  # 无认知注入（对照组）
    
    for cycle in range(cycles):
        # 实验组：完整闭环
        task_a = generate_task()
        task_a = inject_cognition(task_a, pool)  # 注入认知
        result_a = execute(task_a)
        group_a.append(result_a)
        
        # 对照组：跳过注入
        task_b = generate_task()  # 同类型任务
        # 不注入认知
        result_b = execute(task_b)
        group_b.append(result_b)
    
    # 对比关键指标
    return ABTestResult(
        success_rate_lift=mean([a.success for a in group_a]) - mean([b.success for b in group_b]),
        latency_improvement=mean([b.latency for b in group_b]) - mean([a.latency for a in group_a]),
        token_efficiency=mean([b.input_tokens for b in group_b]) / mean([a.input_tokens for a in group_a]),
        # 如果success_rate_lift > 0 且 latency_improvement > 0，证明"虚又返实"真正发生
    )
```

### 5.3 状态重放验证

```python
def replay_loop_state(checkpoint_id: str) -> ReplayResult:
    """
    验证循环每一步可重放——脑体分离架构的核心要求。
    """
    checkpoint = state.load(checkpoint_id)
    
    # 重放遥测采集
    telemetry = replay_telemetry_collection(checkpoint.telemetry_buffer)
    
    # 重放模式提炼
    cognitions = replay_pattern_extraction(telemetry)
    assert cognitions == checkpoint.cognition_entries, "提炼结果不一致，状态不可重放"
    
    # 重放认知注入
    task_contexts = replay_injection(checkpoint.tasks, cognitions)
    for tc, original in zip(task_contexts, checkpoint.tasks):
        assert tc.injected_cognition_ids == original.injected_cognition_ids, "注入结果不一致"
    
    # 重放参数调参
    config_changes = replay_param_changes(cognitions)
    for change, original in zip(config_changes, checkpoint.param_changes):
        assert change.verified == original.verified, "参数验证不一致"
    
    return ReplayResult(success=True, checkpoint=checkpoint_id)
```

## 六、循环运转的完整时序

```
T+0s    │ [实] API调用发生，产生TelemetryRecord
T+1s    │ [实] 遥测记录写入telemetry_buffer
        │
T+2s    │ ─── 窗口触发（10任务或转结束）───
        │
T+3s    │ [虚→脑] 引擎串行扫描遥测，extract_patterns()
T+5s    │ [虚→脑] 模式提炼完成，生成CognitionEntry列表
T+6s    │ [虚→脑] commit_to_cognition_pool()，入池+刷新缓存
        │
T+7s    │ [虚→实] inject_cognition()，新任务携带认知派发
T+8s    │ [虚→实] apply_cognition_actions()，参数变更三段式验证
        │
T+9s    │ [实] 认知注入后的任务经体层并发执行，产生真实代码
T+10s   │ [实] 执行结果+injected_cognition_ids回传，产生新TelemetryRecord
        │
T+11s   │ ─── 循环回到T+0s ───
```

**回灌延迟 = T+10s - T+0s = 10s**，远低于30分钟约束。

## 七、防退化机制

### 7.1 认知淘汰（防止认知池膨胀）

```python
def evict_stale_cognition(pool: CognitionPool):
    """
    认知不是越多越好——过时的认知会污染注入。
    """
    for entry in pool.all():
        # 条件1：超过7天未被注入
        if entry.last_injected_age_days > 7:
            pool.mark_deprecated(entry.id, reason="7天未被注入")
        
        # 条件2：注入后成功率持续下降
        if entry.injection_lift < 0 and entry.injection_count > 5:
            pool.mark_deprecated(entry.id, reason="注入后成功率下降")
        
        # 条件3：置信度衰减
        entry.confidence *= 0.95  # 每窗口衰减5%，需要新数据持续验证
        if entry.confidence < 0.3:
            pool.mark_deprecated(entry.id, reason="置信度过低")
```

### 7.2 循环制动（防止自增强失控）

```python
def check_loop_runaway(metrics_history: list[LoopMetrics]) -> bool:
    """
    自增强不等于无限增强——必须有制动机制。
    """
    # 条件1：参数振荡检测
    recent_changes = get_recent_param_changes(window=5)
    if detect_oscillation(recent_changes):  # 参数在两个值之间反复跳
        return True  # 触发制动
    
    # 条件2：成本失控检测
    recent_cost = [m.total_api_cost for m in metrics_history[-5:]]
    if recent_cost[-1] > recent_cost[0] * 2:  # 成倍增长
        return True
    
    # 条件3：认知池膨胀失控
    if pool.size > MAX_POOL_SIZE:
        return True
    
    return False
```

## 八、总结：自增强循环的不可破坏性约束

```
                    ┌─────────────────────┐
                    │    真实API调用（实）   │
                    │  token消耗、延迟、错误  │
                    └──────────┬──────────┘
                               │ 遥测记录
                               ▼
              ┌────────────────────────────────┐
              │   以实养虚（脑层串行决策）        │
              │   采集 → 提炼 → 入池 → 刷新缓存   │
              └────────────────┬───────────────┘
                               │ 认知条目
                               ▼
              ┌────────────────────────────────┐
              │   虚又返实（脑层串行决策）        │
              │   注入 → 调参 → 三段式验证        │
              └────────────────┬───────────────┘
                               │ 执行指令
                               ▼
                    ┌─────────────────────┐
                    │   真实代码产出（实）   │
                    │   代码生成、测试、部署  │
                    └──────────┬──────────┘
                               │
                               │ 结果回传 + injected_cognition_ids
                               ▼
                    ┌─────────────────────┐
                    │    新的遥测记录（实）   │
                    └─────────────────────┘
```

**五条不可破坏性约束**：

1. **决策串行不可下沉**：采集、提炼、注入、调参全在脑层串行执行，体层只产生数据和执行指令——破坏则状态不可重放

2. **认知必须流动**：入池后30分钟内必须参与注入，7天未注入必须淘汰——破坏则认知池退化为静态档案库（踩坑#3）

3. **参数变更必须三段验证**：状态写入→执行读取→生效验证，缺一不可——破坏则自动调参全链路失效（踩坑#1）

4. **回溯锚点不可缺失**：每条遥测记录必须携带`injected_cognition_ids`——破坏则无法验证虚实因果链

5. **制动机制不可移除**：振荡检测、成本检测、池容量检测——破坏则自增强失控，token消耗指数增长

循环的本质是：**真实消耗不是成本，而是认知的原料；认知不是档案，而是改变真实的杠杆。两者通过脑层串行状态机严格桥接，形成熵减的自增强飞轮。**
