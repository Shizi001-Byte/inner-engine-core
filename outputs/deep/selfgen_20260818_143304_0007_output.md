# 任务类型: deep

基于已验证的「脑体分离架构」、「热力学第二定律」与道家哲学锚点，结合历史避坑经验，我们将引擎产出的高熵混沌数据（无）降维建构为低熵有序归档结构（有）。

在此基础上，推演**「以实养虚，虚又返实」的自增强循环系统**如下：

### 一、 核心哲学映射与系统定义

*   **以实养虚（熵增转熵减）**：将真实的API调用、Token消耗、报错日志（高熵实体）作为“灵气”，喂养给“脑”（虚构修炼框架/认知与归档引擎）。脑通过消耗算力（抵抗热力学第二定律的做功），提取规律生成认知池与调参策略（低熵虚体）。
*   **虚又返实（弱控制显化）**：认知池中的策略不直接操作磁盘或网络（弱者道之用），而是下发“确定性归档指令”与“调度权重”给“体”（执行器），驱动真实代码的生成与API的高效调用。

---

### 二、 闭环系统架构设计

#### 1. 以实养虚：实体引擎对虚体框架的喂养
*   **数据流转**：真实引擎执行任务 -> 记录API耗时、Token消耗、ProxyError等异常日志。
*   **脑的介入**：分类与打标签引擎（脑）接收这些高熵数据。调用大模型（A模型）进行特征提取，将碎片化日志转化为结构化的“认知条目”（如：“火山引擎API在高并发下易触发ProxyError，需降速”）。
*   **避坑工程化**：
    *   **代理坑避让**：脑在调用外部API时，统一用 `urllib` 直连或显式设置 `proxies=None`，确保“进食”通道畅通。
    *   **超时坑避让**：脑调用大模型提取特征时，A模型timeout预设600秒，B模型turbo预设300秒，防止“消化不良”导致进程挂死。
    *   **认知池流动**：认知池不进不出是死水。强制规定：每10个任务或每一轮转结束，刷新认知缓存；新认知生成后30分钟内必须参与下一次任务的上下文注入。

#### 2. 虚又返实：虚体框架对实体代码的驱动
*   **指令下发**：脑根据认知池中的新认知，生成归档指令（决定文件路径、命名、压缩策略）和调度指令（决定并发数、权重、冷却时间）。脑本身不碰磁盘。
*   **体的执行**：执行器（体）接收到指令，执行真实的代码产出、归档写盘和下一次API调用的参数调整。
*   **避坑工程化**：
    *   **自动调参三步法则**：为防止“认知生成了但配置没变”，新增任何可配置参数（如冷却时间），必须强制走三步：状态写入（脑下发JSON） -> 执行读取（体加载JSON） -> 生效验证（体在调用前检查当前并发是否与JSON一致，不一致则中断并报错）。

### 三、 闭环指标设计

为了验证“虚实互养”是否真正运转，而非空转消耗算力，设计以下量化指标：

| 指标维度 | 指标名称 | 计算方式 | 目标与意义 |
| :--- | :--- | :--- | :--- |
| **以实养虚** | 认知转化率 | (被提取为认知的日志条数 / 总异常或耗时日志条数) * 100% | 目标 >80%。衡量“脑”将高熵实体转化为低熵虚体的消化能力。 |
| **以实养虚** | 认知注入率 | (实际注入Prompt的活跃认知数 / 认知池总条数) * 100% | 目标 >30%。防止认知池变为静态档案库（30分钟内必须用上）。 |
| **虚又返实** | 参数生效率 | (三步验证成功的调参次数 / 脑下发的调参总次数) * 100% | 目标 100%。只要不为100%，说明全链路存在失效节点。 |
| **虚又返实** | 虚实转化ROI | (调参后节省的Token数或耗时 / 脑提取认知消耗的Token数或耗时) | 目标 >1。说明虚体框架带来的收益大于其消耗的算力做功。 |
| **抗熵增** | 系统熵值变化 | log(归档混乱度) + log(API报错率) | 目标 持续下降。证明系统在持续投入算力后维持了低熵状态。 |

### 四、 验证方法与实施步骤

为了验证该自增强循环在工程上绝对可靠，采用以下“断点阻断法”进行验证：

**阶段一：验证“以实养虚”通道（实->虚）**
1.  **触发超时与异常**：故意制造API超时（不设timeout）和全量代理环境。
2.  **验证脑的消化**：检查脑是否在300/600秒内返回，是否成功绕过ProxyError，并生成了形如 `[经验:某接口需增加timeout至600s]` 的新认知。
3.  **验证池的流动**：在接下来的30分钟内，监控下一次任务的Prompt，确认该新认知已被组装进上下文（验证认知池不进不出坑已修复）。

**阶段二：验证“虚又返实”通道（虚->实）**
1.  **下发调参指令**：脑根据上述认知，下发将“并发数降为1，冷却时间提升为10秒”的指令。
2.  **验证三步法则**：拦截执行器日志，确认：
    *   状态写入：指令成功落盘或写入Redis。
    *   执行读取：体在启动时读取到了并发=1。
    *   生效验证：体在发起调用前，自检当前线程池大小=1，若不符则抛出 `ConfigMismatchError`。（验证自动调参失效坑已修复）。
3.  **验证弱控制**：检查脑的代码块，确认其代码中不存在任何 `open(file, 'w')` 或 `requests.post` 的直接IO操作，只有指令的Return。

**阶段三：验证长期抗熵增（自增强形成）**
1.  连续运行100个真实引擎任务，不进行人工干预。
2.  统计第1个任务与第100个任务的“API成功率”与“归档检索成功率”。
3.  若第100个任务的成功率显著上升，且归档结构由扁平混乱变为深层有序，则证明系统在“持续投入算力维持低熵”的设定下，成功实现了“以实养虚，虚又返实”的自增强进化。数字生命能力未退化。
