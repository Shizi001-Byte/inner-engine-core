# 任务类型: deep

# 8.8-8.18 原始对话缺失补全方案

## 一、问题定性（关联已有认知锚定）

这段缺失本质属于三类失效中的 **「认知不新鲜」** 的变体——不是认知池空了（1700+条仍在），而是**溯源链断了**。8月8日前的最后锚点与8月18日后的首个锚点之间，原始对话载体丢失，导致该区间认知**无法回溯、无法被后续任务安全引用**，等同于隐性"静态档案"。

不补全会触发连锁失效：
- 8月18日后的任务若引用该区间认知 → 闭环不开放（无验证入口）
- 若强行调度 → 调用不设限（无效认知被注入，污染下游）

---

## 二、补全方案总框架

采用 **「双锚点-三源交叉-分段重建」** 策略，不做整段一次性补全（直接关联避坑提醒：单次调用必超时）。

```
[8.8前最后锚点] ──缺口── [8.18后首锚点]
        │                       │
        └── 三源交叉重建 ───────┘
              │
     ┌────────┼────────┐
   档案源    日志源    派生源
```

---

## 三、可执行步骤（分6步，每步带超时与缓存约束）

### 步骤1：锚点定位（B模型turbo，timeout=300s）
- 在认知池中以时间戳倒序扫描，定位 **8月8日 00:00 前** 最后一条带 `source_id` 的认知条目，记为 `Anchor_L`。
- 定位 **8月18日 23:59 后** 首条认知，记为 `Anchor_R`。
- 提取两锚点的 `source_id`、`task_id`、`timestamp` 三元组。

**输出物**：`gap_boundary.json`，含两锚点元数据。

---

### 步骤2：档案库反查（B模型turbo，timeout=300s）
对1700+条认知池执行：
- 筛选 `timestamp ∈ [8.8, 8.18]` 的认知条目集合，记为 `C_pool`。
- 对 `C_pool` 中每条认知，提取其 `source_id`，反查是否有对应原始对话快照。
- 分类标记：
  - `class_A`：有原始对话残留片段 → 直接纳入重建
  - `class_B`：仅有认知摘要无对话 → 进入步骤3交叉验证
  - `class_C`：`source_id` 悬空（指向已丢失对话）→ 标记为存疑，不强行填充

**避坑约束**：每处理10条档案即刷新认知缓存，防止内存堆积导致超时。

---

### 步骤3：日志交叉验证（B模型turbo，timeout=300s）
调取8.8-8.18期间的：
- API调用日志（成功/超时记录）
- 任务调度日志（task_id、入参摘要、返回状态）
- 缓存快照（若有周期性dump）

将 `class_B` 认知与日志中的 `task_id` 做关联：
- 能匹配到 task_id 且返回状态为成功 → 升级为 `class_A_verified`
- 匹配到超时记录 → 标记为"派生认知"，需A模型复核
- 完全无日志痕迹 → 降级为 `class_C`

---

### 步骤4：派生认知复核（A模型，timeout=600s）
对 `class_A_verified` 和"派生认知"两类，用A模型执行：
- 对照 `Anchor_L` 的结论，判断该认知是否逻辑自洽
- 对照 `Anchor_R` 的结论，判断该认知是否为后续链路的合理前置
- 两端都兼容 → 写入重建链路，`source_id` 标记为 `derived_<原id>`
- 任一端冲突 → 暂存隔离区，不进入主链路

---

### 步骤5：链路缝合（B模型turbo，timeout=300s）
将验证通过的条目按时间戳排序，缝合到 `Anchor_L` 与 `Anchor_R` 之间：
- 每条认知补充 `reconstructed=true` 标记
- 补充 `cross_validation_source` 字段，记录是哪几个源交叉验证的
- 与原溯源链做完整性检查：`Anchor_L.source_id → 重建条目.source_id → Anchor_R.source_id` 必须形成不中断的链

---

### 步骤6：新鲜度注入验证
补全后立即执行已有认知质检SOP：
- 检查补全认知中是否有超过 **30分钟** 未参与注入的条目
- 计算引用率：`近30分钟新增认知中被后续任务实际引用的条数 / 近30分钟新增认知总数`
- 引用率低于阈值 → 触发缓存刷新，强制注入下一个任务

---

## 四、验证标准（硬指标，不空泛）

| 验证项 | 计算方式 | 合格阈值 |
|---|---|---|
| **溯源链闭合度** | `可回溯到source_id的重建条目 / 重建条目总数` | ≥ 85% |
| **双锚点连通性** | 从 Anchor_L 沿 source_id 链可到达 Anchor_R | 必须为 true |
| **存疑隔离率** | `class_C条目数 / C_pool总数` | ≤ 15%（高于则说明缺口过大，需人工介入） |
| **30分钟注入率** | `近30分钟补全认知被后续任务引用条数 / 补全认知总数` | ≥ 60% |
| **超时发生率** | 6步中调用超时次数 / 总调用次数 | = 0%（若超时，回退到上一步重试，不继续推进） |

---

## 五、失败兜底（关联三类失效防御）

1. **若 class_C 占比 >15%** → 不继续自动补全，该区间标记为 `gap_unresolvable`，提示"认知不新鲜"失效，等待人工档案补充。
2. **若缝合后30分钟注入率为0** → 说明补全认知又变成"静态档案"，触发每10任务强制刷新，并检查注入通道是否阻塞（闭环不开放失效）。
3. **若任一步骤连续超时3次** → 该步骤降级为人工处理，不做无限重试（调用不设限失效）。

---

核心原则：**补全的是溯源链的连通性，不是对话内容本身**。对话已丢就丢，但认知必须能被验证、能被注入、能被追溯——否则宁可标存疑也不伪造。
