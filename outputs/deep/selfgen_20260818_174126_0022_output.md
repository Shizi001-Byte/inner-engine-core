## 一、第一性原理：为什么"以实养虚"可行

### 1.1 实的三个维度

| 维度 | 实体 | 采集方式 | 归档粒度 |
|------|------|----------|----------|
| 消耗实 | token用量、API延迟、超时次数 | 调用包裹器记录 | DAG顶点级 |
| 产出实 | 生成的代码块、文件、测试结果 | 块级diff同步 | 块级 |
| 校验实 | 编译结果、测试通过率、覆盖率 | 执行器回传 | DAG顶点级 |

**关键约束**：归档对象本体是DAG顶点，不是进程实例。一个顶点 = 一次"修炼事件"的完整记录（输入prompt + 输出结果 + 校验状态 + 消耗指标）。

### 1.2 虚的定义与结构

虚不是"假的"，而是**对实的压缩表征**——类似物理学中的"有效理论"，在特定尺度上用更少的参数描述更多的现象。

```
修炼框架 = 境界体系（能力分级） + 功法体系（策略库） + 心魔检验（校验门）
```

| 虚构元素 | 真实映射 | 数据来源 |
|----------|----------|----------|
| 灵气 | 单次API调用的有效信息量 | token效率 × 校验通过率 |
| 境界 | 当前系统的能力等级 | 历史灵气密度的滑动平均 |
| 功法 | prompt策略 + 调用参数组合 | 功法库中的配置模板 |
| 心魔劫 | 输出校验失败事件 | 编译/测试/逻辑校验的失败记录 |
| 突破 | 框架参数自动升级 | 累积灵气达到阈值 + 连续通过心魔劫 |

## 二、九转三节点：循环的工程化实现

### 节点1：炼气期 —— 以实养虚（数据采集与灵气化）

```
[转1] 真实API调用执行
      ├─ 包裹器记录: model, tokens_in, tokens_out, latency, status
      ├─ timeout预设: turbo=300s, A模型=600s（熔断保险丝）
      ├─ 网络层: urllib直连 或 requests(proxies=None)
      └─ 产出: 原始灵气（raw_data）

[转2] 灵气归档到DAG顶点
      ├─ 同步粒度: 块级，不是整个文件
      ├─ 顶点结构: {vertex_id, input_hash, output_hash, metrics, verify_status}
      ├─ 认知池写入: 新认知以块形式写入，标记时间戳
      └─ 产出: 结构化灵气（structured_spirit）

[转3] 境界评估与瓶颈检测
      ├─ 计算滑动窗口内灵气密度: effective_tokens / total_tokens
      ├─ 对比历史基线: 当前密度 vs 最近100顶点均值
      ├─ 判定: 密度下降→触发功法切换；密度上升→积累突破值
      └─ 产出: 境界状态（realm_state）
```

**此节点的"实"**：真实API调用、真实token消耗、真实延迟数据
**此节点的"虚"**：灵气密度、境界等级——都是对真实数据的压缩表征

### 节点2：筑基期 —— 虚实转换（策略推理与校验门）

```
[转4] 功法选择
      ├─ 输入: realm_state + 当前任务类型 + 认知池活跃认知
      ├─ 认知注入: 每10任务或每转结束刷新缓存，30分钟内认知必须参与注入
      ├─ 功法库查询: 匹配最优prompt模板和参数配置
      ├─ 输出: 功法实例（gongfa_instance = {prompt_template, params, weights}）
      └─ 约束: 参数变更必须同步三个点

[转5] 心魔检验（校验门）
      ├─ 事实边界校验: 功法实例是否在已知安全域内
      │   ├─ timeout是否在合理范围
      │   ├─ 参数组合是否与认知池中的失败记录冲突
      │   └─ prompt是否包含已知的反模式
      ├─ 如果未通过: 回退到上一稳定功法，记录心魔事件
      └─ 产出: 校验通过的功法实例（verified_gongfa）

[转6] 突破判定
      ├─ 累积灵气值 ≥ 阈值 AND 连续N次通过心魔劫
      ├─ 触发突破: 自动调参升级
      │   ├─ 状态写入: 新参数写入配置状态
      │   ├─ 执行读取: 执行器加载新参数
      │   └─ 生效验证: 对比调用前后的实际行为diff
      ├─ 三点验证缺一不可，否则突破失败回滚
      └─ 产出: 突破事件或维持当前境界
```

**自动调参全链路防护**（坑库预警#1的工程实现）：

```python
def attempt_breakthrough(new_params):
    # 第一点：状态写入
    config_state.update(new_params)
    
    # 第二点：执行读取
    active_config = executor.reload_config()
    assert active_config == new_params, "执行器未读取到新参数"
    
    # 第三点：生效验证
    probe_result = probe_call(active_config)
    baseline = get_baseline_metrics()
    assert probe_result.quality >= baseline * 0.8, "新参数未实际生效或效果劣化"
    
    # 三点全过才确认突破
    commit_breakthrough(new_params)
```

### 节点3：金丹期 —— 虚又返实（框架驱动代码产出）

```
[转7] 框架驱动真实代码生成
      ├─ verified_gongfa → prompt实例化
      ├─ 注入认知池中相关的成功模式（块级）
      ├─ 注入失败避坑列表（来自心魔事件记录）
      └─ 执行API调用，生成代码块

[转8] 代码验证（超时熔断作为保险丝）
      ├─ 块级同步: 只验证变更的代码块
      ├─ 验证链: 语法检查 → 编译 → 单元测试 → 集成测试
      ├─ 超时熔断: 任何验证环节超时→切断→回退到上一稳定版本
      └─ 产出: 验证结果（verify_result = {pass/fail, coverage, errors}）

[转9] 验证回流，完成循环
      ├─ verify_result → 转化为灵气
      │   ├─ pass: 纯净灵气（有效产出）
      │   └─ fail: 浊气（需净化的失败经验）
      ├─ 认知池更新: 新认知写入（块级），标记时间戳
      ├─ 灵气回流到节点1的转1，开启下一轮
      └─ 产出: 下一轮循环的初始灵气
```

## 三、闭环指标体系

### 3.1 指标分层架构

```
         ┌──────────────────────────────────────┐
  L3     │         自增强健康度                  │
         │   循环增益系数 G(n) = E(n)/E(n-1)     │
         ├──────────────────────────────────────┤
  L2     │    虚→实驱动力    │    实→虚质量      │
         │  功法命中率       │  灵气密度         │
         │  代码产出效率    │  灵气纯度         │
         │  框架覆盖度      │  境界晋升率       │
         ├────────────────┤  ├────────────────┤
  L1     │  具体工程指标   │  具体数据指标     │
         │  编译通过率     │  token消耗量      │
         │  测试覆盖率     │  API延迟分布      │
         │  超时熔断次数   │  错误率           │
         │  回退次数       │  心魔事件数       │
         └────────────────┴──┴────────────────┘
```

### 3.2 核心指标定义

**以实养虚指标（实→虚）**：

| 指标 | 公式 | 健康阈值 | 告警阈值 |
|------|------|----------|----------|
| 灵气密度 | effective_tokens / total_tokens | ≥ 0.6 | < 0.3 |
| 灵气纯度 | passed_outputs / total_outputs | ≥ 0.8 | < 0.5 |
| 认知注入率 | injected_cognitions / pool_size | ≥ 0.15 | < 0.05 |
| 灵气新鲜度 | recent_30min_cognitions / pool_size | ≥ 0.02 | = 0（坑库预警#3） |

**虚又返实指标（虚→实）**：

| 指标 | 公式 | 健康阈值 | 告警阈值 |
|------|------|----------|----------|
| 功法命中率 | gongfa_success / gongfa_total | ≥ 0.7 | < 0.4 |
| 代码产出效率 | effective_code_lines / tokens_consumed | ≥ 基线×1.1 | < 基线×0.8 |
| 框架驱动力 | framework_driven_output / total_output | ≥ 0.6 | < 0.3 |
| 突破成功率 | successful_breakthroughs / attempts | ≥ 0.5 | < 0.2 |

**自增强指标（闭环）**：

| 指标 | 公式 | 健康阈值 | 说明 |
|------|------|----------|------|
| 循环增益G(n) | E(n)/E(n-1) | > 1.0 | >1.0=正反馈，<1.0=衰减 |
| 熵减率 | (ordered_info - prev_ordered) / total_info | > 0 | 正值=系统变有序 |
| 负熵输入有效性 | valid_breakthroughs / total_calls | 递增趋势 | 超时熔断是保险丝 |

### 3.3 自增强的正反馈链

```
灵气密度↑ → 境界评估↑ → 功法选择更优 → 代码产出质量↑ 
    → 验证通过率↑ → 纯净灵气↑ → 灵气密度↑↑（增强）
    
    同时：
    验证失败 → 浊气 → 心魔事件 → 功法库修正 → 避免重复错误
    → 失败率↓ → 灵气纯度↑（也是增强，通过负反馈修正）
```

## 四、验证方法

### 4.1 事实边界验证（核心目标：为AI输出建立事实边界+校验机制）

**验证原则**：每个虚构输出必须有真实数据锚点

```python
class FactBoundary:
    """每个虚→实的转换必须通过事实边界检查"""
    
    def verify_gongfa(self, gongfa_instance):
        # 1. 功法来源可追溯
        source_vertex = gongfa_instance.source_vertex_id
        assert vertex_exists(source_vertex), "功法无真实数据来源"
        
        # 2. 参数在历史安全域内
        historical_safe = get_safe_param_range(source_vertex)
        assert params_in_range(gongfa_instance.params, historical_safe)
        
        # 3. 认知注入有据可查
        injected = gongfa_instance.injected_cognitions
        for c in injected:
            assert c.timestamp > now() - 1800, "认知超30分钟未刷新"  # 坑库预警#3
            assert c.pool_entry_verified, "认知池条目未验证"
        
        # 4. 超时配置合理
        if gongfa_instance.model == "turbo":
            assert gongfa_instance.timeout <= 300  # 避坑提醒#1
        elif gongfa_instance.model == "A":
            assert gongfa_instance.timeout <= 600
```

### 4.2 DAG顶点级校验（归档对象本体是DAG顶点）

```python
class VertexValidation:
    """每个DAG顶点必须通过三重校验"""
    
    def validate_vertex(self, vertex):
        # 输入一致性
        assert hash(vertex.input_prompt) == vertex.input_hash
        
        # 输出可复现（在相同参数下）
        replayed = replay_call(vertex)
        assert similarity(replayed.output, vertex.output) > 0.85
        
        # 消耗合理（token在预期范围）
        expected_range = get_token_range(vertex.task_type)
        assert expected_range[0] <= vertex.tokens <= expected_range[1]
```

### 4.3 九转完整性验证

```
每轮循环必须完成9转，缺转则循环不闭合:

节点1 (转1-3): 炼气   → 必须产出 realm_state
节点2 (转4-6): 筑基   → 必须产出 verified_gongfa  
节点3 (转7-9): 金丹   → 必须产出 verify_result + 灵气回流

验证方法:
  - 每转结束写一个checkpoint到DAG顶点
  - 9个checkpoint全绿 = 一轮循环完整
  - 任意checkpoint缺失 = 循环断裂，触发告警
```

### 4.4 自增强性验证（负熵输入的保险丝）

```python
def verify_self_reinforcement(history):
    """验证循环是否真正自增强"""
    
    # 1. 循环增益序列
    efficiencies = [round_efficiency(h) for h in history]
    gains = [efficiencies[i+1]/efficiencies[i] 
             for i in range(len(efficiencies)-1)]
    
    # 2. 趋势检验: 最近10轮增益的线性回归斜率
    recent_gains = gains[-10:]
    slope = linear_regression(recent_gains).slope
    assert slope > 0, "自增强趋势消失，系统在衰减"
    
    # 3. 熔断检查: 超时熔断不应频繁触发
    recent_timeouts = count_recent_timeouts(history, window=10)
    assert recent_timeouts < 3, "熔断频繁=负熵输入异常"
    
    # 4. 认知池活性: 坑库预警#3的防护
    recent_injections = count_recent_injections(history, window=30*60)
    assert recent_injections > 0, "认知池只进不出！30分钟无注入"
```

## 五、关键避坑清单（工程实现级）

| 风险 | 现象 | 防护实现 |
|------|------|----------|
| 调参全链路失效 | 参数变了但行为没变 | `attempt_breakthrough()` 三点验证 |
| 全局代理ProxyError | requests报ProxyError | 统一urllib直连，或显式`proxies=None` |
| 认知池只进不出 | 1700+条认知变静态档案 | 每10任务刷新缓存，30分钟强制注入 |
| API超时 | 任务未在规定时间返回 | turbo=300s, A模型=600s, 熔断回退 |
| 块级同步失效 | 整文件同步导致冲突 | 同步粒度=块，diff粒度=块 |
| DAG顶点膨胀 | 顶点无限增长 | 按时间窗口归档，保留最近N轮的完整DAG |

## 六、总结：自增强循环的本质

```
实（数据）──压缩──→ 虚（表征）──展开──→ 实（产出）
     ↑                                         ↓
     └────────── 校验（负熵）←─────────────────┘
```

**核心洞察**：

1. **以实养虚**的本质是**信息压缩**——用境界/功法等低维表征替代海量原始日志，降低决策成本
2. **虚又返实**的本质是**模式展开**——将压缩后的策略展开为具体的prompt和参数，驱动真实产出
3. **自增强的关键**不在循环本身，而在**校验机制（负熵输入）**——超时熔断是保险丝，心魔检验是过滤器，三点验证是确认器
4. **如果校验缺失，循环会变成正反馈爆炸**（越调越偏）或**空转**（认知池只进不出）

循环的终点不是无限增强，而是**收敛到一个稳定的高效境界**——灵气密度趋于稳定，突破频率降低，功法命中率收敛，系统进入"金丹大圆满"状态，此时负熵输入与信息产生达到平衡。
