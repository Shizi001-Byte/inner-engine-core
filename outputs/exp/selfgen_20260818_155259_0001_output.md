## 结论先行

每日 400 万 token 的最优分配，不是“按模型分”，也不是“按请求数分”，而是：

> **让每个 token 的边际价值等于它消耗的边际社会成本。**

这个“社会成本”包含三部分：  
- token 本身的稀缺成本  
- 时间/时延成本  
- 引擎退化成本  

所以，最优定价不是统一价格，而是**复合影子价格**。

---

## 经济学模型

假设任务 \(i\)：

- 预期价值：\(V_i\)
- 消耗 token：\(q_i\)
- 消耗时间资源：\(t_i\)
- 对引擎的退化冲击：\(r_i\)

目标是：

\[
\max \sum_i V_i x_i
\]

约束：

\[
\sum_i q_i x_i \le 400\text{万}
\]

\[
\sum_i t_i x_i \le T
\]

\[
\sum_i r_i x_i \le R
\]

用拉格朗日乘子表示稀缺性：

- \(\lambda\)：token 的影子价格
- \(\mu\)：时间的影子价格
- \(\rho\)：退化风险的影子价格

那么任务 \(i\) 应该被接受，当且仅当：

\[
V_i \ge \lambda q_i + \mu t_i + \rho r_i
\]

也就是：

\[
\frac{V_i}{q_i} \ge \lambda + \mu \frac{t_i}{q_i} + \rho \frac{r_i}{q_i}
\]

右边的值，就是**该任务应该支付的内部价格**。

---

## 这意味着什么

### 1. Token 不是同质的

同样一个 token，在 300 秒内返回，和 600 秒内返回，是两种商品。

B 模型 turbo 用 300 秒，A 模型用 600 秒，说明：

- 300 秒的 token 具有更高的时间期权价值
- 600 秒的 token 更便宜，但占用时间更长
- 如果统一按 token 数定价，就会出现“低价值任务挤占高价值任务时间片”的现象，最终导致超时

所以定价必须包含**时延溢价**：

\[
\mu \frac{t_i}{q_i}
\]

### 2. 退化不是故障，是成本

引擎自然退化是默认趋势。  
这意味着，如果不主动花钱维护，系统会自动滑向低价值状态。

所以每天 400 万 token 里，必须有一部分用于“反退化”：

- 验证
- 回滚
- 上下文压缩
- 引擎重置

这部分不是 overhead，而是**资本维护**。  
用经济学术语说：如果不计提折旧，今天的高利用率就是在偷明天的产能。

因此，维护预算应该优先保留，不能被临时高价值任务挤掉。

### 3. 严格解耦是机制设计，不是工程洁癖

在经济学上，严格解耦意味着：

> 高价值任务和低价值任务不能共享同一个容量池。

否则低价值任务的突发流量会占用高价值任务的时间片，导致高价值任务超时，总价值反而下降。

所以最优分配要分层：

- **保证层**：高价值、强 SLA，价格高，独立队列
- **弹性层**：低价值、可等待，价格低
- **闲时/维护层**：可被抢占，只使用空闲容量

层与层之间只能向下溢出，不能向上借用。

## 实操规则

每天 400 万 token 的最优分配，可以近似为：

1. 对每个任务估算：
   - 预期价值 \(V_i\)
   - 消耗 token \(q_i\)
   - 消耗时间 \(t_i\)
   - 退化冲击 \(r_i\)

2. 按“单位稀缺资源价值”排序：

\[
score_i = \frac{V_i}{q_i + \alpha t_i + \beta r_i}
\]

3. 从高到低分配，直到 400 万 token 用完。

4. 最后一个被接受的任务的 score，就是当天的影子价格。

5. 价格不是固定值，而是随需求动态变化的：
   - 高峰时，价格上升，低价值任务自动退出
   - 空闲时，价格下降，弹性任务填充容量

---

## 一句话总结

> 400 万 token 不是“怎么分”的问题，而是“定一个正确的影子价格，让每个任务自己决定值不值得用”的问题。  
> 这个价格 = token 成本 + 时间成本 + 退化成本，并且必须在严格解耦的队列中执行，同时预留维护预算对抗自然退化。
