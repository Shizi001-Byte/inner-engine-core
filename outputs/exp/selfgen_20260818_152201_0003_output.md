# 任务类型: exp

基于已有锚定，我不再论证“为什么决策事件和全局顺序不能被优化掉”，直接推演定价与分配。

## 核心经济学判断

把每天 400 万 token 看成一条硬供给线，问题不是“token 贵不贵”，而是：

> 每枚 token 放在哪里，能产生最大的边际价值？

最优状态满足一个条件：

> 所有任务类型中，最后一枚 token 的边际价值相等。

否则就应该把 token 从低边际价值任务挪到高边际价值任务。

用公式表示就是：

- 目标：最大化总价值  
- 约束：每天 token 总量 ≤ 400 万  
- 最优条件：各类任务的边际价值 = 同一个影子价格 λ  

λ 就是 token 的“真实价格”。

## 但 token 不是均质商品

虽然 token 是同一计量单位，但用途的风险和外部性完全不同。

- **决策事件**：不可逆、影响全局，省略它可能造成级联错误。
- **全局顺序**：是公共品，所有人受益，但没人愿意主动付费。
- **可检索差异**：有正外部性，贡献差异的人受益小于整个协作网络受益。
- **执行/同步**：可重试、可延迟、可压缩，价值弹性大。

所以不能只定一个价格，而要分层定价。

## 三层定价与分配框架

### 第一层：决策事件 + 全局顺序

**建议分配：25%～35%**

- 这是“保险型”资源，不是“生产型”资源。
- 包括：不可逆操作、跨 agent 共识、事件排序、异常升级、关键审批。
- 定价应该高，因为它们占用的是实时稀缺容量。
- 但基础容量不能完全靠竞价，必须有战略预留，否则公共品会被饿死。

规则：

> 决策事件和全局顺序不能省，只能优化“决策前的信息汇总”和“决策后的同步”。

全局顺序尤其如此：它不是同步，不能靠“最终一致”糊弄；事件序号和因果顺序必须每次保留。

### 第二层：可检索差异

**建议分配：20%～30%**

协作网络的价值不是“连接”，而是“可检索的差异”。

所以 token 要重点投向：

- 提取不同 agent 在同一问题上的结论差异；
- 给差异打标签、建索引；
- 让“谁在什么问题上与别人不同”可以被查询；
- 把差异转化为决策选项。

定价方式：

- 对贡献方补贴：贡献一条可检索差异，奖励 token；
- 对检索方收费：按命中价值收费；
- 低质量差异不补贴，避免垃圾索引。

这一层有正外部性，所以不能按边际成本定价，否则供给不足。

### 第三层：执行 + 同步

**建议分配：40%～50%**

这是最“可优化”的一层：

- 日常生成、格式化、日志、批量工具调用；
- 低优先级任务可以排队；
- 可以用 B 模型 turbo，timeout 设 300 秒；
- 可以压缩、延迟、分片执行。

定价应该低，但不要为零。零价格会导致过度使用和浪费。

规则：

> 超时只允许发生在执行/同步层。  
> 决策事件超时是事故，不是优化。

决策事件用 A 模型，timeout 设 600 秒；执行/同步用 B 模型 turbo，timeout 设 300 秒。

## 动态调节机制

每天 400 万 token 不是固定食谱，而是一个动态市场。

具体做法：

1. 每天先预留决策事件和全局顺序的“最低可行容量”。
2. 剩余 token 进入内部市场，按优先级和边际价值竞价。
3. 如果某层排队过长，提高该层价格或优先级费用；
4. 如果某层用不满，降价并释放容量。

复盘指标：

- 决策事件错误率 / 全局顺序错乱率：必须趋近于 0，否则从执行层转 token 过来；
- 差异检索命中率：低则减少补贴，提高质量门槛；
- 执行层超时率：如果超时但业务无损，说明执行层分配过多，可以压缩。

## 一句话总结

最大化价值不是“把 400 万 token 用完”，而是让每枚 token 的边际价值趋于相等。  
决策事件和全局顺序是底线，可检索差异是杠杆，执行和同步是弹性空间。  
定价就是让这三者的优先级被显性化：底线靠预留，杠杆靠补贴，弹性靠市场。
