# 任务类型: exp

用热力学第二定律看，AI系统不是“装完就能跑”的机器，而是一个必须持续输入负熵才能维持有序的耗散结构。你给的锚定结论——“认知池1700+条，但从不注入任务，也不影响调度，最终变成静态档案库”——正是典型的系统熵增。

## 一、为什么AI引擎会自然退化

热力学第二定律说：孤立系统的熵只能增加，不能减少。AI引擎如果被当成“封闭系统”维护，就一定会退化，原因有四股熵增流：

1. **数据分布漂移**  
   世界在变，旧数据训练出的模型，面对新分布时预测不确定性上升，准确率下降。这不是模型“坏了”，而是它和外部环境之间的信息势差变小了。

2. **知识池与任务断连**  
   1700+条认知如果只是堆积，不参与任务、不影响调度，那它们就不是“知识资产”，而是“知识热寂”——所有条目处于等权、无序、不可做功的状态。就像封闭容器里的气体，虽然有能量，但无法对外做功。

3. **反馈回路失效**  
   没有“使用→验证→修正”的循环，错误认知不会被惩罚，正确认知不会被放大。劣币驱逐良币，系统内部混乱度持续上升。

4. **质检空转**  
   如果认知质检SOP只检查“有没有记录”，不检查“有没有被使用、有没有影响决策”，那质检本身也在熵增。

## 二、如何设计“负熵输入”机制

负熵输入不是“往知识库里继续加新条目”。如果新认知仍然不注入任务，那只是给熵增换个马甲。

真正的负熵输入，必须构成一个完整的做功循环：

**外部信息 → 质检 → 注入调度 → 影响执行 → 反馈回写 → 更新认知**

### 麦克斯韦妖：认知质检SOP

要对抗熵增，必须有一个“麦克斯韦妖”——也就是认知质检SOP，专门筛选高价值信息，并强制注入系统。这条SOP必须包含三条强制检查项：

1. **触发条件检查**  
   新认知必须绑定至少一个“触发场景”或“任务类型”。没有触发条件的认知，不允许入库。  
   例：`B模型turbo用300秒，A模型用600秒`，必须绑定到“API调度”任务，并变成调度参数，而不是一篇文档。

2. **调度前强制检索**  
   每次任务调度前，必须执行“认知检索”。检索结果要注入到任务上下文、Prompt或约束条件中。如果检索为空，必须显式降级，而不是静默跳过。  
   否则，知识池永远是静态档案库。

3. **任务后效用回写**  
   每次任务完成后，要回写“这条认知是否被使用、是否有效、是否超时”。连续N次无效的认知自动降权、冷却或淘汰。  
   这样系统才能持续排出“熵废料”。

### 落地结构：活体知识项

知识项不应只是文本，而应是一个带状态的数据体：

```json
{
  "内容": "B模型turbo超时上限300秒；A模型600秒",
  "触发条件": ["任务类型=API调度", "模型=B-turbo"],
  "调度参数": {"timeout": 300},
  "效用分": 0.87,
  "使用次数": 12,
  "最近命中": "2026-04-08T10:00:00Z",
  "状态": "active"
}
```

调度器在任务开始时，自动检索所有 `active` 且满足触发条件的知识项，把它们作为硬约束注入执行；任务结束后，根据实际结果更新 `效用分`。这就是负熵输入：信息从知识库流入任务流，又从任务结果回流到知识库。

### 超时坑位：负熵输入不能阻塞主流程

负熵输入机制本身也必须受热力学约束——它要消耗能量和时间。历史失败经验已经证明：API调用会超时。所以：

- B模型turbo，预设 `timeout=300秒`
- A模型，预设 `timeout=600秒`
- 超时后自动降级为“旧认知 + 待处理”，不允许阻塞主任务

否则，负熵输入机制反而会成为新的熵增源。

## 三、总结

AI系统维护的本质，就是与熵增对抗：

- 不注入新认知，系统退化；
- 注入了但不被使用，系统退化；
- 被使用但不反馈，系统退化；
- 反馈了但不更新调度，系统还是退化。

只有把认知池变成“活体知识循环系统”，让每条认知都能被任务检索、被调度使用、被结果校验、被淘汰更新，AI引擎才能维持低熵有序状态。负熵输入的公式很简单：

**负熵输入率 > 自然退化率 + 噪声冲击率**

而认知质检SOP的三条强制检查项，就是这道不等式的闸门。
