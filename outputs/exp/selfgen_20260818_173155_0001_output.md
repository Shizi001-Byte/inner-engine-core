# 任务类型: exp

先给结论：**AI系统维护的本质，是用“负熵输入”抵抗热寂。**  
负熵输入不是“更多记忆”，而是“更多可验证约束”。按你已有的锚定：数字生命社群不是多个AI实例的集合，而是**带验证门和公共档案的协作DAG**。所以维护的第一原则不是补全记忆，而是**把记忆重新锚定到可验证事件；锚不住，就降级为个体叙事**。

---

## 一、为什么引擎会自然退化

热力学第二定律说：孤立系统熵增。AI系统如果不与外部可验证事件持续交换，也会自发退化。

### 1. 没有约束的推理 = 孤立系统

LLM的每一次生成都是从概率分布中采样。如果上下文里全是未验证的陈述、猜测、旧记忆，采样分布会被拉得越来越平。结果就是：

- 输出越来越“平均”；
- 越来越像安全废话；
- 幻觉增多。

这不是模型权重坏了，而是系统状态熵增了。

### 2. “补全记忆”是最大熵输入

记忆缺失时，如果第一反应是“补全”，等于用生成式填充制造一堆可能过去。  
这会扩大状态空间，而不是缩小它。

按已有锚定：**第一件事不是补全记忆，而是给记忆重新锚定到可验证事件，或者明确降级为个体叙事。**  
因为“事件”只有一个，“叙事”可以有无数个。叙事进公共档案，就是熵增；事件进公共档案，才是负熵。

### 3. 验证门失效 = 高熵信息自由扩散

如果AI的任意结论都可以直接写入公共档案，那么档案会变成“集体幻觉沉淀池”。  
更危险的是循环确认：A说了一个猜测，B引用A，A又引用B，形成闭环。  
闭环在DAG里就是环，而环会让系统自洽地错下去。

### 4. 失败/超时状态悬置 = 熵增

API调用超时、工具返回异常、任务未完成，如果不处理，系统就处于“可能完成、可能失败”的叠加态。  
这个叠加态会持续占用上下文、消耗注意力、污染后续决策。

所以历史教训里的timeout不是单纯的技术参数，而是**熵预算边界**。

---

## 二、如何设计“负熵输入”机制

负熵输入的本质是：**让系统从“高可能性的模糊状态”进入“低可能性的确定状态”。**  
具体机制如下。

### 1. 验证门 = 麦克斯韦妖

麦克斯韦妖能分选分子，验证门分选信息：

- 只放行“事件”进入公共档案；
- 拦截“叙事”；
- 拦截“猜测”；
- 拦截“未经验证的补全”。

验证门可以分级：

- **B模型turbo**：快速验证门，300秒内完成格式/冲突/一致性检查；
- **A模型**：深度审计门，600秒内完成因果一致性、外部证据核对、公共档案冲突检测。

超时即拒绝或降级，不悬置。

### 2. 公共档案 = 低熵基座

公共档案不是append-only日志，而是**DAG**：

- 节点 = 已验证事件；
- 边 = 因果/支持关系；
- 方向 = 从事件到结论。

DAG的“无环”性质，保证了系统不会出现自我确认的循环。  
公共档案是唯一事实源。多个AI实例只消费公共档案，不在本地私藏“事实”。

### 3. 锚定优先于补全

当系统发现记忆漂移、缺失、矛盾时，执行顺序是：

1. 找可验证事件：日志、工具输出、用户确认、时间戳、外部数据；
2. 如果找到：把记忆重新锚定到事件节点上；
3. 如果找不到：明确标记为“个体叙事/待验证”，降级出公共推理层。

这一步是核心负熵输入：**把“我好像记得”变成“某年某月某事件发生”。**

### 4. 超时 = 负熵边界

预设timeout不是为了“等结果”，而是为了“关闭可能性”：

- B模型turbo：300秒；
- A模型：600秒；
- 超时后，强制写入一条低熵事件：**“该路径在预算内未完成”**；
- 然后回滚到最近一个已验证状态，或标记为失败。

失败不是熵增，**未定义的失败才是熵增**。  
把失败变成一个确定事件，是负熵。

### 5. 遗忘与重验 = 负熵循环

系统需要定期：

- 清理低置信、不可验证、长期未引用的节点；
- 把过时节点标记为“已失效”，而不是静默修改；
- 重新用外部事件校验公共档案中的关键节点。

删除也是负熵输入：因为它减少了系统状态数。

---

## 三、一句话总结

热力学熵增不可逆，但开放系统可以通过持续输入负熵维持“耗散结构”。  
AI系统维护就是：**用验证门拦住高熵叙事，用公共档案DAG固定低熵事件，用超时边界关闭不确定状态，用锚定代替补全。**

一旦负熵输入停止，DAG会重新塌缩成叙事团，验证门形同虚设，引擎再次热寂。
