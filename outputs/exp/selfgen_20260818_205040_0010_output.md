# 任务类型: exp

先给结论：**每日 400 万 token 是稀缺容量，不能按平均成本定一个固定单价，而应该按“影子价格 + 机会成本 + 拥挤外部性”做动态定价，并把资源分配到“每 token 边际价值最高”的任务上。**

---

## 1. 经济学最优条件

假设第 `i` 个任务分配 `x_i` 个 token，产生的价值为 `V_i(x_i)`。  
每日总供给为 `T = 400万`，则最优化问题是：

\[
\max \sum_i V_i(x_i)
\]
\[
s.t. \sum_i x_i \le T
\]

最优解满足：所有被接受的任务，其最后一个 token 的边际价值相等：

\[
V_i'(x_i) = \lambda
\]

这个 `λ` 就是当天的**影子价格**。  
任何任务的边际价值低于 `λ`，就不应该消耗 token；高于 `λ` 的任务，应该优先获得 token。

所以，定价不是“成本加成”，而是让价格传递稀缺性：  
**价格 = 边际计算成本 + 影子价格 + 拥堵成本。**

---

## 2. 分配机制：用价格让用户/任务自己暴露价值

### 2.1 分级定价

不能所有请求一个价，否则低价值请求会挤掉高价值请求。

| 等级 | 适用场景 | 价格 | 说明 |
|---|---|---|---|
| Premium | 紧急、高价值、决策类 | 高单价 | 实时响应，严格 SLA |
| Standard | 普通业务任务 | 中单价 | 正常排队 |
| Batch | 可延迟任务、总结、批处理 | 低单价 | 只在空闲时跑，价格极低 |

这是经济学里的**二级价格歧视**：用户根据自己的紧迫程度和支付意愿选择等级，从而自动暴露任务价值。

### 2.2 内部额度 + 竞价

如果是在组织内部使用，不能真的“花钱”，可以给各部门发 **token 额度**，然后让任务在内部市场竞价。  
每个任务报出“预期价值”，调度器按：

\[
score = \frac{预期价值 \times 超时内完成概率}{预计 token 消耗}
\]

排序，先满足 score 高的任务。  
这等价于用“内部清算价”来分配 token。

### 2.3 峰谷定价

每天 400 万 token 如果晚上没用完，第二天不能存下来。  
所以低峰期应该大幅降价，甚至以极低价格吸收 Batch 任务；高峰期则加价，抑制低价值请求。  
这就是**峰值负荷定价**，和电力定价逻辑一致。

---

## 3. 模型选择与超时约束

你给的经验锚定里，API 超时是关键约束。

- **B 模型 turbo：timeout 300 秒**
- **A 模型：timeout 600 秒**

在调度时，必须把“能否在 timeout 内返回”纳入价值评估：

\[
\text{成功概率} = P(\text{任务在 timeout 内完成})
\]

如果预计超时，则成功概率为 0，这个任务不应该启动，或者应该降级到更快的模型、拆分成更小的子任务。

而且，高价值任务如果超时，不仅没有产生价值，还占用了本该给其他任务的 token。  
所以调度器必须维护一个 **standby 队列**：一旦高优先级任务超时失败，立刻用 Batch 任务补位，避免 token 闲置。

---

## 4. 认知池必须参与调度，否则就是静态档案库

你给出的另一个锚定是：**认知池已积累 1700+ 条，但新认知从不注入任务，也不影响调度，最终变成静态档案库。**

从经济学看，这是巨大的浪费。  
认知池是一种**公共品**：一旦产生，可以被反复使用，边际成本接近 0。  
如果每次任务都从头生成，等于反复支付“固定成本”；如果先查认知池，很多任务可以只用很少 token 完成，省下的 token 可以投入更高价值的新任务。

因此必须把认知池接入调度链路：

1. **任务进来先查认知池**，看是否已有类似结论；  
   如果有，直接复用 + 小规模验证，而不是重新生成。

2. **任务结束后，新认知必须写回认知池**；  
   然后更新调度器的价值评估参数，让下次调度更准。

3. **认知池的价值 = 它未来能节省多少 token、提升多少任务成功率。**  
   如果它不影响调度，价值就是 0。

---

## 5. 落地 SOP 强制检查项

按你给的历史经验和认知锚定，调度器应强制以下三条：

1. **每次调度前必须查认知池**；未命中认知池的调度请求不进入价值计算。  
2. **每次调用前必须做 timeout 评估**：B 模型 turbo 用 300 秒，A 模型用 600 秒；超时概率高的任务直接拒绝、降级或排队。  
3. **每次任务完成后，新认知必须写回认知池，并更新后续调度的优先级参数**；否则认知池会再次退化成静态档案库。

---

## 最终一句话

每日 400 万 token 的最优分配，不是“平均分”，也不是“先到先得”，而是：**让 token 流向“每 token 边际价值最高”的任务，用动态价格和优先级暴露真实价值，用认知池降低重复消耗，用 timeout 约束防止价值归零。**
