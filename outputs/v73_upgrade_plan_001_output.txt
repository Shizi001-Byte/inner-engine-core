### V7.3 完整架构图（文字描述）

**V7.3系统数据流向与分层架构：**

1. **自驱动感知层 [V7.3新增]**
   - `环境监控探针` -> `任务自生成引擎` -> `优先级排序队列` -> `任务池`
2. **认知与意图解析层 [V7.3升级]**
   - `用户输入/自生成任务` -> `特征提取器` -> `意图感知动态路由模型` -> `任务分发器`
3. **脑体分离执行层 [V7.2基础]**
   - `任务分发器` -> `[脑A(逻辑推理) / 脑B(创意生成) / 脑N(...)]` -> `任务转换协议`
   - `任务转换协议` -> `[体A(代码执行) / 体B(API调用) / 体N(...)]`
4. **质量反馈与进化层 [V7.3新增]**
   - `执行结果` -> `多维质量评分引擎` -> `反馈闭环控制器` -> `引擎能力画像中心`

**与V7.2差异点标注：**
- V7.2采用静态规则路由，V7.3替换为**意图感知动态路由模型**。
- V7.2执行完毕即结束，V7.3在执行后增加了**多维质量评分与反馈闭环**。
- V7.2引擎能力为静态配置，V7.3实现**引擎能力画像自动更新**。
- V7.2完全依赖外部输入触发，V7.3具备**任务自生成与自优先级排序**能力。

### 特性1：意图感知动态路由

**具体实现方案：**
通过轻量级特征提取器捕获任务元数据与语义特征，输入至基于强化学习的上下文Bandit模型，结合各引擎实时能力画像，计算期望收益（Q值），选择最优脑体组合。

**特征提取方案：**
- **语义特征**：使用Sentence-BERT提取任务描述的768维稠密向量。
- **结构特征**：任务Token长度、指令复杂度（AST深度）、历史同类任务平均耗时。
- **上下文特征**：当前系统负载、用户会话上下文权重。

**路由模型选型：**
选用 **LinUCB (线性上下文Bandit)** 算法。
- **选型理由**：无需离线全量训练，支持在线增量学习；能平衡探索（尝试新引擎）与利用（选择历史最优引擎），有效避免冷启动失效。

**数据结构设计：**
```json
{
  "task_id": "uuid",
  "features": {
    "semantic_vector": [0.12, ..., -0.04],
    "struct_features": {"token_len": 512, "ast_depth": 4},
    "context_features": {"sys_load": 0.7}
  },
  "routing_decision": {
    "selected_brain_id": "brain_02",
    "selected_body_id": "body_05",
    "expected_q_value": 0.89,
    "exploration_flag": false
  }
}
```

### 特性2：结果质量反馈闭环

**具体实现方案：**
在任务执行完毕后，异步触发多维评分引擎，对结果进行打分。分数聚合后更新至引擎能力画像中心，并作为LinUCB模型的Reward信号。

**评分维度定义：**
1. **正确性 (0-1)**：通过单元测试或规则引擎校验。
2. **完整性 (0-1)**：任务约束条件满足率。
3. **时效性 (0-1)**：实际耗时与画像基准耗时的比值。
4. **成本 (0-1)**：消耗Token数/API调用成本的对数归一化。

**数据采集点：**
- **脑执行后**：采集推理链路长度、Token消耗、脑部耗时。
- **体执行后**：采集执行成功率、异常堆栈、体部耗时、资源占用。
- **最终结果校验**：采集测试通过率或用户隐式/显式反馈。

**模型更新频率：**
- **实时流更新**：Reward信号通过Kafka流式写入，每5分钟增量更新LinUCB模型权重。
- **全量校准**：每日凌晨02:00对当天数据进行全局聚合，重新拟合特征权重。

### 特性3：引擎能力画像自动更新

**具体实现方案：**
基于滑动窗口机制，结合指数移动平均（EMA）算法，对脑/体引擎的历史执行记录进行聚合，动态更新其能力标签。当能力值发生显著漂移时，触发事件通知路由模型调整权重。

**数据结构设计：**
```json
{
  "engine_id": "brain_02",
  "engine_type": "BRAIN",
  "capabilities": {
    "code_generation": {"score": 0.92, "trend": "up", "sample_size": 150},
    "logical_reasoning": {"score": 0.85, "trend": "stable", "sample_size": 320}
  },
  "system_metrics": {
    "avg_latency_ms_ema": 1200,
    "success_rate_ema": 0.98,
    "avg_cost_tokens": 850
  },
  "last_updated": "2023-10-25T10:00:00Z",
  "health_status": "HEALTHY"
}
```

### 特性4：任务自生成与自优先级排序

**具体实现方案：**
系统后台守护进程定期扫描系统盲区（如低画像覆盖的引擎、久未触达的任务类型、历史失败重试任务），调用任务生成LLM生成测试任务。生成的任务经质量过滤后进入优先级队列，按紧迫度和预期信息增益进行排序执行。

**任务生成Prompt模板：**
```text
[System]
你是一个系统自检任务生成器。目标是为系统生成自验证任务，以补足能力画像盲区或复测历史失败项。
[Context]
当前系统盲区引擎：{engine_id}
历史失败任务特征：{failed_features}
需要增强的能力维度：{weak_capability}
[Instruction]
请生成1个具体的、可执行的自检任务。任务必须包含：
1. 清晰的输入描述
2. 预期输出结果（用于正确性校验）
3. 适用引擎类型约束
[Output Format]
严格输出JSON：{"task_desc": "...", "expected_output": "...", "target_engine_type": "..."}
```

**质量过滤机制：**
1. **可行性过滤**：AST解析任务描述，确保语法合法且不包含死循环/危险指令。
2. **去重过滤**：使用SimHash计算与过去7天自生成任务的相似度，>0.85则丢弃。
3. **价值过滤**：预期信息增益计算（若该任务成功，对引擎画像分数的扰动是否>阈值δ）。

**优先级排序公式：**
`Priority = α * Information_Gain + β * Failure_Retry_Penalty + γ * (1 / Current_Queue_Depth)`

### V7.2兼容性分析

1. **数据结构兼容**：V7.2的任务JSON Schema保留所有原字段，V7.3新增字段（`features`, `routing_decision`, `quality_score`等）设为可选属性，V7.2引擎读取时自动忽略。
2. **接口协议兼容**：路由层与脑体执行层之间仍沿用V7.2的gRPC/REST协议。V7.3路由层在接入V7.2原生脑体时，默认赋予全满分能力画像（冷启动），逐步降权至真实值。
3. **降级兼容**：当LinUCB路由模型或反馈闭环发生故障时，系统自动降级为V7.2的静态规则路由，保证核心业务可用。

### V7.2 → V7.3 迁移步骤和回滚方案

**迁移步骤：**
1. **基建部署**：部署特征提取服务、Kafka反馈数据流、画像Redis集群，不影响V7.2运行。
2. **旁路引流**：将V7.2中10%的只读/低风险任务复制至V7.3路由层，V7.3执行但不返回结果给用户（影子模式），用于冷启动画像数据收集。
3. **灰度切流**：当V7.3画像数据样本量>1000时，开启真实流量切流，从10%逐步提升至100%。同时开启质量反馈闭环。
4. **特性全开**：流量100%切流成功且系统稳定运行48小时后，开启“任务自生成与自优先级排序”模块，激活系统自驱进化能力。

**回滚方案：**
1. **一键降级开关**：在API网关层切换路由模式开关，将流量瞬间切回V7.2静态路由逻辑。
2. **自生成任务阻断**：关闭任务自生成调度器，清空优先级等待队列。
3. **数据隔离**：保留V7.3采集的画像与评分数据供事后分析，但停止对V7.2数据库的任何回写操作。由于V7.2不依赖这些数据，无需执行数据库回滚。
