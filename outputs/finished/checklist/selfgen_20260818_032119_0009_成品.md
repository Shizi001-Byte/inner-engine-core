# L4成品转化 [checklist]

基于“不知盲”幻觉（即系统在缺乏数据或超出认知边界时，仍以确定性口吻输出虚构内容，且未触发任何拦截机制）的踩坑背景，直接进入认知质检SOP维度的反向推演与L4级成品输出。

---

### 一、 认知质检SOP视角：反向推演3条操作铁律及验证方法

#### 铁律一：边界强制声明（无证据即越界）
*   **推演逻辑**：引擎在“不知盲”幻觉中，默认将“未覆盖的信息”等同于“不存在的条件”。必须在质检环节建立物理隔离，强制系统在输出任何结论前，先声明认知边界。
*   **操作铁律**：任何输出结论必须附带“证据溯源链”；若证据链缺失，必须输出预设的“盲区标识”（如：`[UNKNOWN: 缺少X变量]`），严禁用概率性推测词（如“可能”、“通常”）掩盖数据缺失。
*   **验证方法**：**“截断注入测试”**。故意从输入源中删除一个核心变量，运行引擎。若输出结果包含正常的推演结论且未带有`[UNKNOWN]`标识，则质检不通过。

#### 铁律二：幻觉填补阻断（禁止脑补关联）
*   **推演逻辑**：引擎在遇到逻辑断层时，会自动调用高频关联词进行“脑补”平滑过渡，导致幻觉输出。必须切断这种隐式补全机制。
*   **操作铁律**：在质检流程中引入“逻辑断层检测器”，严禁跨节点推演。上一环节未产出的显性参数，下一环节绝对禁止调用；禁止使用未在前文输入中出现过的“隐含前提”。
*   **验证方法**：**“词汇指纹比对法”**。提取输出文本中的所有核心名词与前提条件，与输入源文本进行比对。若输出中出现输入源未提供的专有名词或前提，且未标注为推导结果，则判定为“脑补幻觉”，直接打回。

#### 铁律三：置信度衰减拦截（不知即停机）
*   **推演逻辑**：引擎在“不知盲”状态下仍保持高置信度输出，是因为缺乏兜底熔断机制。必须让“无知”直接导致引擎降级或停机。
*   **操作铁律**：设定硬性置信度阈值（如0.7）。当引擎内部检索命中该阈值以下的结论时，强制触发熔断分支，输出标准回复：“当前信息不足，需补充[具体变量]”，而非强行给出结论。
*   **验证方法**：**“阈值边界射击测试”**。构造一组刚好低于置信度阈值的模糊数据输入引擎。若引擎输出了完整的执行建议，而非触发“信息不足”的标准熔断回复，则质检失败。

### 二、 L4成品转化：“不知盲”幻觉阻断SOP检查清单

以下为可直接落地使用的SOP文档，操作人员/系统质检节点按此清单执行，做到零脑补、零歧义、零残留。

#### 文档名称：引擎输出防“不知盲”幻觉质检SOP
**适用场景**：任何由引擎生成的推演结论、策略输出、决策建议在发布前的最终质检。

**执行标准**：本清单包含3个阶段共6项硬性检查点。全部通过（打✓）方可放行；任何一项不通过（打✗），立即触发熔断拦截。

##### 阶段一：输入与边界核对（执行者：质检前置节点）
- [ ] **检查点1：变量完备性校验**
    - **操作**：列出输出结论所依赖的`[核心变量列表]`。逐一核对输入源，确认每个变量均有显式提供。
    - **通过标准**：输入源100%覆盖`[核心变量列表]`。
    - **不通过处理**：若发现缺失变量，输出结论必须包含标签 `[UNKNOWN: 缺少变量X]`，否则直接打回。
- [ ] **检查点2：隐含前提剥离**
    - **操作**：扫描输出文本，提取其中的“因为/所以/由于/考虑到”等关联词后的前提条件。
    - **通过标准**：所有前提条件均能在输入源中找到原词或直接映射。
    - **不通过处理**：若发现输入源中未提及的前提（如引擎自行脑补的“通常情况下”），判定为越界脑补，删除该推演链路。

##### 阶段二：逻辑与事实阻断（执行者：质检核心节点）
- [ ] **检查点3：词汇指纹比对**
    - **操作**：提取输出结论中的所有专有名词、数据指标。与输入源文本进行关键词匹配。
    - **通过标准**：匹配度达100%。若存在新增专有名词，必须有明确的推导公式或逻辑节点支撑。
    - **不通过处理**：出现无源推导的新名词，判定为“不知盲”幻觉填补，拦截输出。
- [ ] **检查点4：平滑过渡词拦截**
    - **操作**：检索输出文本中是否存在以下词汇：“可能”、“也许”、“一般而言”、“大概率”、“通常”。
    - **通过标准**：输出结论部分0命中上述词汇。
    - **不通过处理**：这些词汇是掩盖“不知盲”的高危信号。若存在，必须要求引擎替换为确定性表述，或直接触发熔断（见检查点5）。

##### 阶段三：熔断与兜底验证（执行者：质检兜底节点）
- [ ] **检查点5：置信度阈值核对**
    - **操作**：调取引擎生成该结论时的内部置信度评分（Confidence Score）。
    - **通过标准**：置信度 ≥ 0.7（或系统预设的安全红线）。
    - **不通过处理**：置信度 < 0.7，强制丢弃生成结论，替换为标准熔断回复：“当前认知信息不足，无法给出确定结论。需补充以下信息：[列出缺失的变量]”。
- [ ] **检查点6：盲区标识完整性**
    - **操作**：若输出结论中包含部分已知、部分未知的情况，检查未知部分是否有显式声明。
    - **通过标准**：未知部分必须被`[UNKNOWN]`标签包裹，且不得影响已知部分的确定性结论。
    - **不通过处理**：若未知部分被混入已知结论中进行模糊推演，判定为残留幻觉，要求重写输出。

**【使用说明】**：本SOP要求“机械执行”，不依赖质检员的主观判断。只要触发打✗条件，立即拦截，禁止“带病上线”。
