# SOP: AI认知池动态注入与引擎产出自动归档执行清单

**方法论来源**：脑体分离架构下的“九转闭环认知更新法则”（由外至内，由有入无）
**核心目标**：防止认知池静态化（只进不出），实现从高熵数据处理到低熵自主进化的生生不息。
**适用场景**：AI引擎任务调度、认知池管理、API调用及产出归档节点。

---

## 📋 执行检查清单（要求逐项打勾，不可跳过）

### 阶段一：API调度与超时预设（防调用超时）
- [ ] **1.1 判定目标模型**：读取当前任务调用的AI模型类型。
- [ ] **1.2 设定Timeout**：
   - 若模型为 **B模型turbo**，在API请求头预设 `timeout = 300`（秒）。
   - 若模型为 **A模型**，在API请求头预设 `timeout = 600`（秒）。
- [ ] **1.3 异常熔断**：若超出预设timeout未返回，直接终止请求并记录“超时异常”日志，不阻塞后续任务队列。

### 阶段二：认知防沉积与动态刷新（防认知池只进不出）
- [ ] **2.1 触发判定**：检查以下两个条件是否满足其一：
   - 条件A：当前引擎已累计完成 **10个** 任务。
   - 条件B：当前处于“一转”生命周期结束节点（当前大阶段任务闭环）。
- [ ] **2.2 执行刷新**：若满足2.1任一条件，系统立即执行认知缓存刷新程序，拉取认知池最新状态，更新本地调度上下文。

### 阶段三：新认知强制注入（由外至内，参与调度）
- [ ] **3.1 提取新认知**：扫描认知池，提取生成时间在 **近30分钟内** 的新增认知条目。
- [ ] **3.2 强制注入**：拦截下一个待执行任务，将提取到的新认知条目强制写入任务的Prompt上下文头部。
- [ ] **3.3 效力校验**：检查待发Prompt，确认新认知已作为前置约束或参考方法论参与本次调度。

### 阶段四：引擎产出自动归档（由有入无，高熵转低熵）
- [ ] **4.1 高熵剥离**：任务执行完毕后，剥离原始任务中的冗余输入、调试日志等高熵中间数据。
- [ ] **4.2 低熵提取**：提取本次任务产出的核心结论、避坑经验或方法论（即“新认知”）。
- [ ] **4.3 写入认知池**：将提取的低熵结构化数据写入认知池，打上时间戳与任务来源标签。
- [ ] **4.4 静态归档**：将原任务完整高熵数据标记为“归档态”，转入冷存储档案库（化为“无”），释放引擎活跃内存。

### 阶段五：闭环验证（生生不息）
- [ ] **5.1 确认超时配置**已按1.2执行。
- [ ] **5.2 确认认知刷新**已按2.2执行（若触发）。
- [ ] **5.3 确认30分钟新认知**已按3.2注入下一轮任务。
- [ ] **5.4 确认产出归档**已按4.3与4.4完成高低熵分离。
