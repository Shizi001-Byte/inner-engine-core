# 【L4 SOP文档】认知池防熵增与动态注入执行手册

## 1. 执行目标与适用范围
- **目标**：彻底解决“认知池只进不出”的静态档案库问题，确保新认知在规定时间内强制参与任务注入，实现闭环的持续对抗熵增。
- **适用范围**：所有涉及认知调度、模型调用、任务生成的自动化流转环节。

## 2. 触发机制（满足任一条件立即启动）
1. **时间触发**：系统时间戳达新认知生成后 30 分钟（1800秒）未注入。
2. **计数触发**：任务调度器累计完成 10 个任务。
3. **转次触发**：当前“转”流转结束。

## 3. 标准执行步骤 (SOP)

### 步骤 1：前置环境与超时配置检查
- 动作：根据当前调度的模型类型，预设API超时参数。
- 执行标准：
  - 若调用 B模型turbo：设置 `timeout = 300` 秒。
  - 若调用 A模型：设置 `timeout = 600` 秒。
- 异常处理：若超时未返回，立即终止调用并抛出超时异常，转入重试或备用模型。

### 步骤 2：认知池提取与缓存刷新
- 动作：清空当前认知内存缓存，防止旧数据残留。
- 执行标准：
  1. 执行查询：从认知池中拉取 `status = 'PENDING'` 的新认知。
  2. 按时间倒序或权重正序提取认知。
  3. 加载入内存缓存，标记为 `CACHE_READY`。

### 步骤 3：任务注入与控制流调度
- 动作：将新认知强制注入下一个待执行任务。
- 执行标准：
  1. 监听待执行任务队列，捕获下一个任务 `Task_ID`。
  2. 将 `CACHE_READY` 的认知作为上下文前缀，拼装至任务Prompt中。
  3. 发送指令，完成控制流与数据流的扩展调度。
  4. 记录映射关系：`Task_ID` <-> `Cognition_ID` 写入日志表。

### 步骤 4：闭环防熵增验证
- 动作：校验注入结果，更新认知状态。
- 执行标准：
  1. 任务返回后，校验输出结果是否包含/响应了新认知的逻辑。
  2. 将认知池中该条认知状态由 `PENDING` 更新为 `INJECTED`。
  3. 重置任务计数器至 0，重置时间触发器至当前时间。

## 4. L4级无脑执行检查清单

执行人员/系统在每次任务流转时，必须逐项打钩确认：

- [ ] **超时预警**：当前调用的模型API是否已按标准设置超时？（B模型turbo=300s，A模型=600s）
- [ ] **触发校验**：是否满足三大触发条件之一（满30分钟 / 满10任务 / 单转结束）？
- [ ] **缓存清理**：是否已执行认知缓存清空操作，确保无旧档残留？
- [ ] **强制注入**：新认知是否已作为Context前缀强制注入了最新任务？
- [ ] **状态更新**：已注入的认知状态是否已从 `PENDING` 更新为 `INJECTED`？
- [ ] **计数重置**：时间戳与任务计数器是否已成功重置？
- [ ] **防熵增校验**：控制流与数据流是否已确认无断点，形成完整闭环？
