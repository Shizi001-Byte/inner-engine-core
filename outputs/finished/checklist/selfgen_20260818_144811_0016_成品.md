# L4成品转化 [checklist]

### 【L4成品】认知池动态注入与防呆归档SOP

**提取方法论**：基于九转周期的认知缓存防呆与动态注入机制
**应用场景**：AI认知引擎调度系统、引擎产出自动归档系统
**核心目标**：根除“认知池只进不出”的静态档案库问题，确保系统从高熵数据处理向低熵自主进化转化。

---

#### 一、 触发条件与执行参数（硬性指标）

| 机制分类 | 触发条件 | 执行动作 | 关联避坑项 |
| :--- | :--- | :--- | :--- |
| **周期刷新** | 每完成10个任务 或 每转周期结束 | 强制清空并重建“认知注入缓存池” | 防止认知池变异为静态档案库 |
| **时效注入** | 距离上次认知注入间隔达30分钟 | 强制将新增认知拉入调度上下文 | 确保新认知30分钟内参与注入 |
| **超时预防** | API调用发起前 | 根据任务类型预设Timeout阈值 | 防止API调用超时导致任务失败 |

---

#### 二、 标准操作程序 (SOP)

**Step 1: 触发判定与状态盘点**
1. 系统监听任务计数器与时间戳。当满足“10个任务”、“每转结束”或“30分钟时效”任一条件时，中断当前调度准备，进入认知刷新流程。
2. 扫描认知池，提取时间戳在“上次刷新时间”之后的所有新增认知条目。

**Step 2: 缓存重建与权重评估**
1. 清空当前的“认知注入缓存队列”。
2. 将Step 1提取的新增认知加载至缓存队列。
3. 依据“九转玄功-生生不息”原则，将新增认知打上标签：
   - **高熵数据处理类**：用于解析、清洗、归档外部输入数据。
   - **低熵自主进化类**：用于优化调度策略、修正历史错误路径。
4. 剔除30分钟内未被调用的老旧低权重认知，实现“由有入无”的代谢。

**Step 3: 强制注入与任务下发**
1. 将Top-N条（建议3-5条）高价值新认知作为系统Prompt或上下文前缀，强制注入下一个待执行任务。
2. 下发任务前，根据目标模型预设Timeout参数：
   - 目标为B模型turbo：硬编码/配置设定 **Timeout = 300秒**。
   - 目标为A模型：硬编码/配置设定 **Timeout = 600秒**。
3. 发起API调用。

**Step 4: 引擎产出自动归档**
1. 任务执行完毕或触发Timeout熔断后，收集引擎产出结果。
2. 对结果进行高/低熵判定，抽取可复用方法论或失败教训。
3. 将抽取的认知追加写入认知池尾部，并更新认知池总计数（如：认知池总数达1700+条），记录写入时间戳。
4. 重置任务计数器与30分钟注入计时器，恢复常规调度。

---

#### 三、 终端检查清单 (Checklist)

执行人员/自动化系统需在每次转结束或每10个任务周期末尾，逐项核对以下清单：

**✅ 认知防呆检查项**
- [ ] 确认“认知注入缓存队列”已执行清空操作，无残留历史数据。
- [ ] 确认认知池中“过去30分钟内新增”的条目已被提取。
- [ ] 确认至少有1条新增认知已被强制注入到当前任务的上下文调度中。
- [ ] 确认未被调用的老旧认知已被降权或移出活跃缓存池。

**✅ 工程级超时避坑检查项**
- [ ] 确认当前API调用目标模型类型（B模型turbo 或 A模型）。
- [ ] 确认调用B模型turbo的Timeout参数已被设定为 `300` 秒。
- [ ] 确认调用A模型的Timeout参数已被设定为 `600` 秒。
- [ ] 确认存在超时熔断后的重试或降级机制记录。

**✅ 归档与生命周期检查项**
- [ ] 确认引擎产出结果已完成高/低熵属性分类。
- [ ] 确认新认知已追加写入认知池，且时间戳已更新。
- [ ] 确认任务计数器（/10）与时间计数器（/30min）已重置归零。
