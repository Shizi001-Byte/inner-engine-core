# L4成品转化 [checklist]

以下针对**“大规模数据同步”**这一具体工程场景，生成L4级别逐项可勾选的检查清单。

### 场景：大规模数据同步任务（含API拉取与本地数据落库）

#### 一、 同步前：环境与参数预检
- [ ] **1.1 超时参数配置校验**
  - **判定标准**：检查任务调度中心配置，B模型turbo API的`timeout`必须严格等于300秒，A模型API的`timeout`必须严格等于600秒，且配置不得为空或使用默认无限制。
  - **异常处理**：若参数校验失败，拦截任务启动，触发“参数配置异常”告警，并自动回滚至上一个已验证的配置版本。
- [ ] **1.2 并发边界隔离校验**
  - **判定标准**：检查线程池配置，API调用阶段必须使用独立的多线程池（核心线程数>1）；后处理阶段（数据清洗、落库）必须使用单线程池（核心线程数=最大线程数=1）或全局唯一消费者实例，严禁复用API调用线程池。
  - **异常处理**：若发现后处理线程池配置>1，立即终止任务下发，抛出“并发边界破坏”异常，防止并发写入导致数据错乱。
- [ ] **1.3 任务初始化乐观锁校验**
  - **判定标准**：任务状态变更为`RUNNING`时，必须执行`UPDATE task SET status='RUNNING', version=version+1 WHERE task_id=? AND version=?`，且返回`affected_rows`必须为1。
  - **异常处理**：若返回0，说明任务已被其他节点抢占或状态被篡改，立即放弃本次执行并记录“状态仲裁失败”日志，不进行后续API调用。

#### 二、 同步中：API调用阶段
- [ ] **2.1 超时熔断与重试机制校验**
  - **判定标准**：监控API调用日志，若触发300秒/600秒超时，系统必须自动捕获`TimeoutException`，并按指数退避策略（如1s, 2s, 4s）重试，最多重试3次。
  - **异常处理**：若3次重试后仍超时，将该API对应的数据分片标记为`API_TIMEOUT_FAILED`，跳过当前分片继续执行其他分片（如果允许部分成功），或者整体中断任务并将状态回滚为`FAILED`。
- [ ] **2.2 并发水位线控制校验**
  - **判定标准**：API并发调用阶段，正在执行的Future数量不得超过预设并发上限（如50），且内存队列堆积数据量未达到阈值（如10000条）。
  - **异常处理**：若达到水位线，必须触发反压，暂停新的API调用拉取；若内存队列堆积超限，触发“背压溢出”告警，并暂停所有API拉取线程5秒。

#### 三、 同步中：后处理阶段（单消费者）
- [ ] **3.1 单消费者独占性校验**
  - **判定标准**：后处理队列消费端必须且仅能存在一个活跃线程。通过分布式锁或单线程Executor验证，当前持有锁的消费者ID唯一。
  - **异常处理**：若检测到多个消费者线程并存（如因Bug导致线程泄漏），立即`kill`后启动的所有多余线程，保留最早存活的线程，并触发P1级告警。
- [ ] **3.2 状态变更原子化校验**
  - **判定标准**：每批次数据落库后更新`task`进度时，必须执行`UPDATE task SET progress=?, version=version+1, updated_at=NOW() WHERE task_id=? AND version=?`，返回`affected_rows`必须为1。
  - **异常处理**：若返回0，说明出现并发修改或脏读。当前消费者必须立即停止处理该批次，丢弃内存中后续所有数据，触发“后处理并发冲突”告警，并进入安全自旋等待状态（等待5秒后重新加载Task状态）。

#### 四、 同步后：收尾与状态终局
- [ ] **4.1 终态状态原子化提交校验**
  - **判定标准**：所有数据落库且API无残留分片后，任务状态变更为`SUCCESS`必须带乐观锁：`UPDATE task SET status='SUCCESS', version=version+1 WHERE task_id=? AND version=?`，且`affected_rows`=1。
  - **异常处理**：若返回0，说明在同步期间该任务被外部干预（如人工中止或灾备切换覆盖）。禁止强行覆盖状态，必须回滚本次本地事务的副作用，并记录“终态提交冲突”，交由人工介入核对数据一致性。
- [ ] **4.2 资源释放与死信队列校验**
  - **判定标准**：任务到达终态后，API调用线程池与后处理单消费者线程必须全部`shutdown`完毕，无残留线程；重试超限的失败数据分片必须已全部写入死信表（DLQ）。
  - **异常处理**：若存在线程未正常销毁，强制调用`shutdownNow()`并记录未处理任务列表；若DLQ数据条数与失败分片数不匹配，触发“数据丢失风险”告警，任务不可标记为完全成功，状态挂起为`PARTIAL_SUCCESS`。
