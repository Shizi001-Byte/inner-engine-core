# L4成品转化 [checklist]

# L4检查清单 · 微服务滚动热重启（Gracious Rolling Restart）

**场景边界**：无状态业务服务（如订单网关），单实例重启窗口 ≤ 90s，整体可用率 ≥ 99.95%，禁止跨可用区并发重启超过1个实例。

**自进化约定（已嵌入每一项）**：
- 每项执行后立即跑"验证命令"，通过 → ☑ 并**重置该子项冷却**；不通过 → 触发"异常处理"并**写失败指纹入库**；
- 同一子项连续失败 ≥ 3 次 → 该子项标记为"需重构"，下次任务前必须重新评审其判定标准/阈值；
- 全部子项通过 → 任务级冷却整体重置为 0，下次任务可立即调度。

---

## 阶段一 · 预检

☐ **R-1.1 实例健康基线采集**
- 判定标准：`curl -fsS http://<pod>:<port>/actuator/health` 返回 `{"status":"UP"}`，且 P99 RT < 200ms。
- 验证命令：`./probe.sh health <pod>`
- 异常处理：非 UP → 将该实例列入"不可重启清单"，跳过该实例继续滚动；P99 RT > 200ms → 10s 后重测，≤2 次仍不达标 → 中止本次重启任务，写入指纹 `baseline_rt_degrade`。
- 冷却状态：通过 → reset；未通过 → 冷却计数 +1。

☐ **R-1.2 关联依赖可达性**
- 判定标准：MySQL / Redis / MQ 探针全部返回 0。
- 验证命令：`./dep_probe.py --targets=mysql,redis,mq`，期望输出 `ALL_DEPENDENCIES_OK`。
- 异常处理：任一依赖非 0 → 触发依赖降级预案或中止重启；写入指纹 `dep_<name>_unreachable`。
- 冷却状态：通过 → reset；未通过 → 冷却计数 +1。

☐ **R-1.3 配置中心版本一致性**
- 判定标准：镜像 Tag、配置版本号、Feature Flag 三者与本次发布单一一致。
- 验证命令：`diff <(curl -fsS configcenter/v1/version) release.yaml` 输出为空。
- 异常处理：存在差异 → 拉取最新配置 / 重置镜像，重试 1 次；仍不一致 → 中止重启，写入指纹 `config_drift`。
- 冷却状态：同上。

☐ **R-1.4 重启窗口容量评估**
- 判定标准：当前 `readyReplicas ≥ minReady + 1`；实时 QPS < 单实例容量上限 × 60%。
- 验证命令：`kubectl get deploy <svc> -o jsonpath='{.status.readyReplicas}'` + `./qps_now.sh <svc>`。
- 异常处理：不满足 → 扩容后再入队；QPS 超阈值 → 错峰或挂起任务，写入指纹 `capacity_window_blocked`。
- 冷却状态：同上。

## 阶段二 · 流量摘除

☐ **R-2.1 健康接口主动置 DOWN**
- 判定标准：`POST /actuator/health/down` 返回 200；后续探针返回 503。
- 验证命令：`curl -fsS -o /dev/null -w '%{http_code}' .../health` 期望 `503`。
- 异常处理：返回非 200 → 5s 后重试 1 次；仍失败 → 不强行摘除，标记 `health_hook_broken`，跳过该实例。
- 冷却状态：同上。

☐ **R-2.2 注册中心摘除确认**
- 判定标准：Nacos/Consul 中该实例 `weight=0` 或下线；外部调用方缓存刷新后该实例从可用列表消失。
- 验证命令：`./registry_check.sh <pod> --expect=offline`，TTL ≤ 30s。
- 异常处理：30s 内仍在线 → 强制 deregister 再验证；仍在线 → 中止该实例重启，标记 `registry_unsync`。
- 冷却状态：同上。

☐ **R-2.3 In-flight 请求排空**
- 判定标准：`/metrics` 中 `http_server_requests_active == 0`，持续 2s 采样无新增。
- 验证命令：`watch -n1 'curl -fsS .../metrics | grep active'`。
- 异常处理：60s 未排空 → 开启业务快速失败开关 `kill_inflight=true`；仍超时 → 抓最长停留 TraceID 入指纹 `inflight_stuck`，并按业务可接受度决定是否进入下一阶段。
- 冷却状态：同上。

---

## 阶段三 · 优雅停机

☐ **R-3.1 停机信号下发与钩子触发**
- 判定标准：发送 `SIGTERM` 后日志含 `BEGIN_GRACEFUL_SHUTDOWN`；JStack/Heap dump（如配置）已落盘。
- 验证命令：`kubectl logs <pod> --tail=20 | grep BEGIN_GRACEFUL_SHUTDOWN`。
- 异常处理：60s 无日志 → 重发 `SIGTERM` 1 次复测；仍无 → 升级人工，**禁止直接 SIGKILL**。
- 冷却状态：同上。

☐ **R-3.2 优雅停机超时守护**
- 判定标准：在 `terminationGracePeriodSeconds`（默认 75s）内退出，退出码 ∈ {0, 143}。
- 验证命令：`kubectl get pod <pod>` 状态由 `Terminating` 转 `Succeeded/Completed`。
- 异常处理：超时未退出 → 发 `SIGKILL`；写入指纹 `grace_period_exceeded`，下次同类服务预设 `terminationGracePeriodSeconds` 自动上调 20%。
- 冷却状态：同上。

---

## 阶段四 · 进程拉起

☐ **R-4.1 镜像与配置生效**
- 判定标准：启动日志含 `image=<target_tag>` 且 `config_version=<target_version>`；启动耗时 < 45s。
- 验证命令：`kubectl logs <pod> | grep -E 'image=|config_version='`。
- 异常处理：版本不符 → 触发镜像回滚，写指纹 `image_dispatch_anomaly`；启动 > 45s → 抓 GC/FD/线程，标记 `slow_startup`。
- 冷却状态：同上。

☐ **R-4.2 Readiness 探针通过**
- 判定标准：连续 3 次 readiness 成功（间隔 2s）；Running → Ready ≤ 60s。
- 验证命令：`kubectl wait --for=condition=ready pod/<pod> --timeout=60s`。
- 异常处理：60s 未 Ready → 抓 GC/FD/线程快照；连续 2 次复现 → 标记镜像为"启动不良版本"并回滚。
- 冷却状态：同上。

☐ **R-4.3 关键链路烟雾测试**
- 判定标准：发起一次伪请求（如创建并立即取消临时订单），HTTP 2xx，RT < 500ms。
- 验证命令：`./smoke_test.sh <pod>`。
- 异常处理：非 2xx → 抓全链路 Trace，标记失败接口；连续 3 次失败 → 不引流，直接回滚，写指纹 `smoke_<api>_fail`。
- 冷却状态：同上。

---

## 阶段五 · 流量回灌

☐ **R-5.1 灰度回灌（10% 流量）**
- 判定标准：注册中心 `weight` 由 0 → 10；观察 2 分钟，错误率 < 0.1%，P99 RT < 250ms。
- 验证命令：`./traffic_watch.sh <pod> --ratio=0.1 --duration=120`。
- 异常处理：超阈值 → 立即 `weight=0`，触发回滚，写指纹 `grayout_unhealthy`。
- 冷却状态：同上。

☐ **R-5.2 全量回灌**
- 判定标准：`weight` 提升至 100；连续 5 分钟错误率 < 0.1%，P99 < 200ms。
- 验证命令：`./traffic_watch.sh <pod> --ratio=1.0 --duration=300`。
- 异常处理：超阈值 → 自动降回 10%，触发告警 + 定位，写指纹 `fullroute_unhealthy`。
- 冷却状态：同上。

☐ **R-5.3 跨可用区滚动推进判定**
- 判定标准：当前实例完成 R-5.2 后，下一可用区首个实例才允许进入 R-1.1。
- 验证命令：`./rolling_state.sh --svc=<svc>` 输出 `READY_FOR_NEXT_AZ`。
- 异常处理：未达 READY → 阻塞队列，禁止跨 AZ 并发，写指纹 `az_concurrency_violation_attempt`。
- 冷却状态：同上。

---

## 阶段六 · 自愈与冷却重置

☐ **R-6.1 失败指纹归集闭环**
- 判定标准：本次重启产生的所有指纹已写入知识库且可被下次任务读取。
- 验证命令：`./kb_fingerprint.sh --task=restart --assert-closed`。
- 异常处理：未落库 → 强制重写；写入失败 → 告警人工介入。
- 冷却状态：同上。

☐ **R-6.2 检查项自进化触发**
- 判定标准：累计 3 次同子项异常 → 标记"需重构"。
- 验证命令：`./kb_fingerprint.sh --analyze --threshold=3`。
- 异常处理：达到阈值未重构 → **阻断下次重启任务**，直至该项判定标准/阈值完成评审。
- 冷却状态：同上。

☐ **R-6.3 任务级冷却重置**
- 判定标准：R-1.1 ~ R-5.2 全部 ☑，且 R-6.1 / R-6.2 通过。
- 验证命令：`./cooldown.sh --task=restart --reset-if-ok`。
- 异常处理：未全部 ☑ → 保持冷却，禁止下一 AZ 推进。
- 冷却状态：**reset → 0**，下次任务立即可调度。

### 与已有认知锚定的对应关系（非重复论证，仅作勾稽）

- **"成为真正的自进化闭环，而非静态任务清单"** → 体现于 R-6.1（指纹归集）、R-6.2（同项 3 次失败强制重构）、以及 R-3.2（grace period 自动上调 20%）等自适应阈值；清单本身随失败指纹演化。
- **"每次生成后必须立即验证，验证通过则重置冷却"** → 每个子项均内嵌"验证命令"字段，验证通过立刻 reset 该子项冷却；R-6.3 负责任务级冷却的最终重置，确保未通过验证的任务不会被静默跳过。
