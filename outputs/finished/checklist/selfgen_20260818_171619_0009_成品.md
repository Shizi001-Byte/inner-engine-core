# 认知质检三项SOP（可直接执行版）

> **抽取方法论**：引擎运行中的坑本质是三个质检项失效——**认知不新鲜、闭环不开放、调用不设限**
> **适用场景**：引擎调度-执行-认知沉淀全流程
> **使用方式**：每10任务/每轮结束时逐项执行，任一项不通过则暂停派发

---

## 质检项一：认知不新鲜

**失效定义**：新认知入库后超过30分钟未出现在任何任务注入上下文中。

| 检查步骤 | 操作 | 通过标准 | 不通过则执行 |
|:---------|:-----|:---------|:------------|
| ① 查时间戳 | 取认知池中最新一条认知的 `created_at` | 距当前时间 < 30分钟 | 进入步骤④ |
| ② 查注入记录 | 检索该认知 `injected_count` 字段 | ≥ 1 | 进入步骤④ |
| ③ 查缓存版本 | 比对认知缓存版本号与认知池最新版本号 | 一致 | 触发 `refresh_cognitive_cache()` |
| ④ 修复动作 | 将未注入认知标记为 `priority=P0`，强制写入下一任务注入队列前3位 | 标记成功 | 人工介入排查注入管道 |

**硬性时间窗**：
```
新认知入库 → 30分钟内必须参与至少1次任务注入
每10个任务完成 → 必须刷新认知缓存
每轮结束 → 必须刷新认知缓存 + 清理过期标记
```

---

## 质检项二：闭环不开放

**失效定义**：认知池只进不出，认知沉淀后从未被任何任务调用/引用/影响调度决策。

| 检查步骤 | 操作 | 通过标准 | 不通过则执行 |
|:---------|:-----|:---------|:------------|
| ① 统计池总量 | `SELECT COUNT(*) FROM cognitive_pool` | 无限制（仅记录基线） | — |
| ② 查僵尸条目 | `SELECT * FROM cognitive_pool WHERE injected_count=0 AND created_at < NOW() - INTERVAL 1 HOUR` | 结果集 = 0 | 进入步骤④ |
| ③ 查轮次引用 | 检查当前轮次调度日志中是否出现 `cognitive_pool` 引用记录 | ≥ 1条 | 进入步骤④ |
| ④ 修复动作 | 提取僵尸条目前5条 → 标注 `priority=P0` → 强制注入下一轮任务上下文 | 标注成功 | 若僵尸条目 > 池总量30%，触发认知池清理流程 |

**僵尸条目判定标准**：
```
入库时间 > 1小时 AND injected_count = 0          → 僵尸（黄色预警）
入库时间 > 2个完整轮次 AND injected_count = 0    → 僵尸（红色预警，强制清理或强制注入）
```

---

## 质检项三：调用不设限

**失效定义**：API调用未根据任务类型预设合理超时时间，导致任务挂起、资源占用、流水线阻塞。

| 检查步骤 | 操作 | 通过标准 | 不通过则执行 |
|:---------|:-----|:---------|:------------|
| ① 查timeout参数 | 检查当前API调用是否携带 `timeout` 参数 | 参数存在 | 补设默认值，进入步骤② |
| ② 查值匹配 | 按任务类型核对timeout值（见下表） | 值在容差范围内 | 修正为目标值 |
| ③ 查兜底策略 | 检查超时触发后是否配置 `fallback` 动作 | 配置存在且可执行 | 配置兜底链：重试1次→降级模型→标记失败跳过 |
| ④ 查日志记录 | 检查超时事件是否写入运行日志 | 日志已写入 | 补写日志，纳入下一轮认知沉淀 |

**超时预设对照表**：

| 任务类型 | timeout（秒） | 容差 | 兜底链 |
|:---------|:-------------|:-----|:-------|
| B模型 turbo | 300 | ±30秒 | 重试1次 → 降级A模型 → 标记失败跳过 |
| A模型 | 600 | ±60秒 | 重试1次 → 标记失败跳过 |
| 其他/未分类 | 300 | ±30秒 | 重试1次 → 标记失败跳过 |

**裸调用零容忍**：
```
grep -r "api_call(" --include="*.py" | grep -v "timeout" 
→ 结果集必须为空
```

## 执行节奏总表

| 触发条件 | 执行质检项 | 预期耗时 | 不通过则 |
|:---------|:-----------|:---------|:---------|
| 每10个任务完成 | 三项全检 | < 30秒 | 暂停派发，逐项修复 |
| 每轮结束 | 三项全检 + 僵尸清理 | < 60秒 | 暂停派发，逐项修复 |
| 新认知入库后30分钟 | 仅检项一 | < 5秒 | 强制注入 |
| 任一API调用前 | 仅检项三步骤①② | < 1秒 | 拦截调用，补设参数 |

## 通过/阻断判定

```
三项全部通过 → 引擎状态=HEALTHY → 继续运行
任一项不通过 → 引擎状态=BLOCKED → 暂停新任务派发 → 执行修复动作 → 复检 → 全通过后恢复
```
