# L4成品转化 [code]

基于“决策串行、执行并发”的分层原则及“脑体分离”架构的不可破坏性，针对API调用超时问题，以下提供可直接运行的L4级Python代码补丁/脚本。该脚本严格隔离了控制流（脑：负责串行决策、超时配置与状态管理）与数据流（体：负责并发执行与IO处理），并针对历史避坑经验内置了动态超时机制。

### 1. 完整Python代码 (`brain_body_async_runner.py`)

```python
"""
脑体分离架构执行器 v1.0
核心原则：
1. 决策串行（脑）：Brain按序解析任务，分配资源，设置超时，不参与IO计算。
2. 执行并发（体）：Body通过异步队列并发处理数据流，互不阻塞。
3. 不可破坏性：脑与体通过明确的指令队列解耦，脑不知道体的IO细节，体不知道脑的决策逻辑。
4. 避坑机制：根据任务类型预设合理timeout，A模型用600秒，B模型turbo用300秒。
"""

import asyncio
import time
from dataclasses import dataclass
from typing import Any, Dict, List, Optional

@dataclass
class TaskCommand:
    """控制流（脑）下发给数据流（体）的指令实体"""
    task_id: str
    task_type: str  # "A_model" 或 "B_turbo"
    payload: Dict[str, Any]
    timeout: int    # 动态预设的超时时间

class Body:
    """
    数据流（体）：纯粹的任务执行者
    负责接收指令，进行IO密集型操作或计算，返回结果。
    """
    @staticmethod
    async def execute(task: TaskCommand) -> Dict[str, Any]:
        """模拟具体的API调用或任务执行"""
        # 模拟耗时：假设任务内部有具体的执行时间
        exec_time = task.payload.get("mock_exec_time", 1)
        
        try:
            # 模拟异步API调用过程
            await asyncio.sleep(exec_time)
            return {
                "task_id": task.task_id,
                "status": "success",
                "result": f"Data processed for {task.task_id} in {exec_time}s"
            }
        except Exception as e:
            return {
                "task_id": task.task_id,
                "status": "failed",
                "error": str(e)
            }

class Brain:
    """
    控制流（脑）：纯粹的任务编排者
    负责任务队列管理、超时时间分配、并发调度与状态收集。
    """
    def __init__(self, body: Body, timeout_scale: float = 1.0):
        self.body = body
        self.task_queue: List[TaskCommand] = []
        self.timeout_scale = timeout_scale  # 用于测试时缩短超时时间，生产环境必须为1.0

    def make_decision(self, task_configs: List[Dict[str, Any]]) -> None:
        """串行决策：遍历配置，预设超时时间，生成控制指令"""
        for config in task_configs:
            task_type = config.get("type", "B_turbo")
            
            # 避坑核心：根据任务类型预设合理timeout
            if task_type == "A_model":
                base_timeout = 600
            elif task_type == "B_turbo":
                base_timeout = 300
            else:
                base_timeout = 120 # 默认兜底
            
            # 应用缩放比例（生产环境 scale=1.0）
            actual_timeout = int(base_timeout * self.timeout_scale)
            
            cmd = TaskCommand(
                task_id=config["id"],
                task_type=task_type,
                payload=config["payload"],
                timeout=actual_timeout
            )
            self.task_queue.append(cmd)
            print(f"[Brain] 串行决策: 任务 {cmd.task_id} 已编排，预设超时 {cmd.timeout}s")

    async def dispatch_and_collect(self) -> List[Dict[str, Any]]:
        """执行并发：将脑部生成的指令并发下发给体部执行"""
        async def _run_with_timeout(task: TaskCommand) -> Dict[str, Any]:
            # 脑部强制施加超时控制，体部在限定时间内必须返回
            try:
                result = await asyncio.wait_for(self.body.execute(task), timeout=task.timeout)
                return result
            except asyncio.TimeoutError:
                return {
                    "task_id": task.task_id,
                    "status": "timeout",
                    "error": f"API调用超时，超过 {task.timeout} 秒未返回"
                }
                
        # 并发执行所有任务
        tasks = [_run_with_timeout(cmd) for cmd in self.task_queue]
        results = await asyncio.gather(*tasks)
        return results

# ================= 使用示例与测试入口 =================
async def main():
    # 测试用例配置
    # 注意：为了快速验证避坑逻辑，将mock_exec_time设置在临界值
    task_configs = [
        {"id": "TASK_001", "type": "A_model", "payload": {"mock_exec_time": 2}},   # 正常执行
        {"id": "TASK_002", "type": "B_turbo", "payload": {"mock_exec_time": 1}},   # 正常执行
        {"id": "TASK_003", "type": "B_turbo", "payload": {"mock_exec_time": 50}},  # 模拟超时 (测试环境scale=0.1时，超时时间为30s，将触发超时)
    ]

    print("=== 初始化脑体分离架构 ===")
    # 实例化体部
    body = Body()
    # 实例化脑部，为了快速测试，将超时时间缩放为 0.1 (A_model: 60s, B_turbo: 30s)
    # 生产环境务必使用默认值 1.0 (A_model: 600s, B_turbo: 300s)
    brain = Brain(body, timeout_scale=0.1) 
    
    print("\n=== 步骤1: 脑部串行决策 ===")
    brain.make_decision(task_configs)
    
    print("\n=== 步骤2: 体部并发执行 ===")
    start_time = time.time()
    results = await brain.dispatch_and_collect()
    end_time = time.time()
    
    print("\n=== 执行结果汇总 ===")
    for res in results:
        print(f"任务 {res['task_id']} -> 状态: {res['status']}")
        if res['status'] != 'success':
            print(f"  错误信息: {res.get('error')}")
            
    print(f"\n总耗时: {end_time - start_time:.2f} 秒")

if __name__ == "__main__":
    asyncio.run(main())
```

### 2. 使用方法

1. **环境准备**：确保Python版本 >= 3.7（需支持 `asyncio` 和 `dataclasses`）。
2. **保存代码**：将上述代码保存为 `brain_body_async_runner.py`。
3. **执行脚本**：
   ```bash
   python brain_body_async_runner.py
   ```
4. **生产环境接入**：
   - 将测试代码中的 `timeout_scale=0.1` 改为默认值 `1.0`（或直接不传参）。
   - 将 `Body.execute` 方法内的 `await asyncio.sleep(exec_time)` 替换为真实的API调用代码（如 `aiohttp` 请求或大模型SDK调用）。

### 3. 验证步骤

**验证1：架构隔离性与并发执行验证**
- **现象**：控制台输出 `[Brain] 串行决策` 先打印完成，随后 `[Brain] 体部并发执行` 并发进行。总耗时接近最慢的单个任务耗时（约2秒），而非所有任务耗时之和。
- **结论**：证明决策阶段是串行预处理的，执行阶段是并发解耦的，脑体分离架构生效。

**验证2：避坑超时机制验证（模拟超时）**
- **配置**：测试脚本中 `TASK_003` 设定 `mock_exec_time=50`，由于测试环境 `timeout_scale=0.1`，B_turbo的超时时间被缩放为 $300 \times 0.1 = 30$ 秒。
- **现象**：程序运行至约30秒时，`TASK_003` 返回状态 `timeout`，错误信息为 `API调用超时，超过 30 秒未返回`。程序不会无限期挂起。
- **结论**：证明基于A/B模型动态预设timeout的历史避坑经验已成功硬编码至控制流中，不可破坏。

### 4. 回滚方案

若该异步架构在特定低版本环境或特定特殊IO操作中引发兼容性问题，需回滚至原单线程串行架构。请执行以下操作：

1. **代码替换**：将 `Brain` 类中的 `dispatch_and_collect` 方法替换为如下串行同步版本：
   ```python
    def dispatch_and_collect_sync(self) -> List[Dict[str, Any]]:
        """回滚方案：串行同步执行"""
        results = []
        for task in self.task_queue:
            # 回退为同步调用逻辑（此处需将Body.execute改回同步函数 def execute）
            result = self.body.execute_sync(task) 
            results.append(result)
        return results
   ```
2. **移除异步依赖**：删除文件中所有的 `async/await` 关键字，将 `asyncio.run(main())` 替换为直接调用 `main()`。
3. **超时降级**：由于回退为串行，若仍需保留超时机制，可使用 `signal.alarm` (仅限Unix) 或 `multiprocessing.Process` 配合 `join(timeout=task.timeout)` 实现强制超时阻断。若无需超时控制，直接移除 `asyncio.wait_for` 逻辑即可。
