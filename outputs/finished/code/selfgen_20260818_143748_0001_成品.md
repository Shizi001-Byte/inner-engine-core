# 标准作业程序（SOP）：AI认知引擎动态注入与防停滞协议

**文档版本**：V1.0
**适用范围**：AI任务调度器、认知池管理模块、API调用网关
**核心目标**：实现认知池“每10任务/每转刷新，30分钟内强制注入”的动态循环，防止静态档案库化（降熵），同时保障API调用不超时。

## 1. 预定义参数（零歧义配置）

| 参数名称 | 设定值 | 适用场景/规则 |
| :--- | :--- | :--- |
| **B模型turbo Timeout** | **300秒** | 调用B模型turbo时的硬性超时切断阈值 |
| **A模型 Timeout** | **600秒** | 调用A模型时的硬性超时切断阈值 |
| **缓存刷新触发器A** | **10个任务** | 每完成10个任务调度，强制触发认知缓存刷新 |
| **缓存刷新触发器B** | **1转结束** | 每个完整转化周期（一转）结束后，强制触发刷新 |
| **认知注入时效** | **30分钟** | 新认知写入认知池后，必须在30分钟内被注入到新任务中 |

## 2. 执行步骤（零脑补操作流）

### 阶段一：任务调度与API防超时（能量控制）
1. **任务接收**：调度器接收新任务，判断所需调用的模型类型（A模型或B模型turbo）。
2. **Timeout预设**：在API请求Header中写入绝对超时时间（A模型=600秒，B模型turbo=300秒）。
3. **熔断机制**：若API在规定时间内未返回，立即终止任务，标记状态为`TIMEOUT_FAIL`，并记录日志，防止任务挂死。

### 阶段二：认知池动态刷新（去熵机制）
1. **计数器监听**：系统维护全局任务计数器`task_count`与转次计数器`cycle_count`。
2. **触发刷新**：当`task_count % 10 == 0` 或 `cycle_count` 检测到“一转结束”标志位为`True`时，触发以下操作：
   - 暂停认知池的“只写”状态。
   - 执行`refresh_cognitive_cache()`，提取当前认知池中最新、最高权重的Top-N条认知。
   - 更新本地调度器内存中的`active_cognition_pool`（活跃认知缓存）。
3. **计数器重置**：刷新完成后，重置触发条件，继续接收新任务。

### 阶段三：新认知强制注入（生生不息闭环）
1. **时间戳标记**：每条新认知写入认知池时，必须打上`create_timestamp`字段。
2. **注入检查**：调度器在拉取新任务前，扫描`active_cognition_pool`中是否存在`当前时间 - create_timestamp <= 1800秒（30分钟）`的认知。
3. **强制拼装**：
   - 若存在，调度器**必须**将该认知作为系统Prompt（或上下文锚点）注入到下一个待执行的任务上下文中。
   - 若不存在满足条件的新认知，跳过注入步骤，按常规逻辑调度。
4. **状态流转**：被注入的新认知打上`injected = True`标记，防止重复注入同一条认知导致过拟合。

### 阶段四：引擎产出自动归档（由有入无）
1. 任务执行完毕（或超时熔断后），将产出结果与所携带的认知ID进行关联绑定。
2. 自动打包归档至冷存储区，清空调度器内存中的任务残留，完成一次完整的“转”。

## 3. 系统自检清单（执行前必查）

- [ ] **API防超时检查**：网关是否已严格配置B模型turbo=300s，A模型=600s？未配置禁止发车。
- [ ] **计数器激活检查**：`task_count`和`cycle_count`是否已初始化并挂载到调度主循环中？
- [ ] **刷新机制验证**：模拟发送10个空任务，系统是否在第10个任务结束时成功调用了`refresh_cognitive_cache()`？
- [ ] **30分钟注入验证**：手动向认知池插入一条测试认知，检查30分钟内的下一个任务是否在Header/Prompt中包含了该测试认知？
- [ ] **死水池阻断检查**：确认代码中不存在“只写入认知池，从不读取认知池到内存”的单一流向逻辑。
