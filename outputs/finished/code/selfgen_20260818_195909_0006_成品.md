基于L4成品转化要求，从历史认知中抽取【认知池只进不出】的高价值避坑方法论，转化为可直接执行的SOP文档。本SOP严格遵循零脑补、零歧义、零残留标准，可直接交付系统调度层与执行层使用。

# SOP-CDR-01：认知池动态刷新与新认知强制注入作业指导书

## 1. 目的与适用范围
**目的**：彻底解决“认知池1700+条只进不出”的静态档案库问题，确保30分钟内生成的新认知100%参与下一轮任务调度与注入。
**适用范围**：所有涉及认知检索、任务调度、Prompt组装的工程节点。

## 2. 触发机制（满足任一条件即强制触发）
- **计数触发**：任务调度器累计完成10个任务。
- **节点触发**：当前“一转”（单次完整认知流转回合）结束。
- **时间红线触发**：距离上一条新认知写入认知池的时间达到**25分钟**（预留5分钟处理余量，逼近30分钟红线前必须完成注入）。

## 3. 标准作业程序 (SOP)

### Step 1: 状态锁定与缓存清空 (耗时: 0秒)
- **动作**：调度器暂停接收新任务，锁定认知池写入接口。
- **操作指令**：`Flush_Cognition_Cache(pool_id="active")`

### Step 2: 增量抽取新认知 (耗时: ≤2秒)
- **动作**：从认知池中抽取近30分钟内新增的高价值认知条目。
- **筛选条件**：`timestamp >= (当前时间 - 30min) AND status = "validated"`
- **输出**：生成`[待注入认知列表]`。

### Step 3: 任务匹配与强制拼装 (耗时: ≤3秒)
- **动作**：将`[待注入认知列表]`强制拼接至下一个待执行任务的Context（上下文）中。
- **强制规则**：若`[待注入认知列表]`非空，下一个任务的System Prompt**必须**包含`[待注入认知列表]`中的至少1条内容，否则禁止下发任务。

### Step 4: 超时预防与任务下发 (耗时: ≤1秒)
- **动作**：根据任务所调用的目标模型，硬编码预设Timeout，防止因认知扩充导致Prompt膨胀进而引发API超时。
- **参数配置**：
  - 若目标为 **B模型turbo**：预设 `Timeout = 300秒`
  - 若目标为 **A模型**：预设 `Timeout = 600秒`
- **动作**：携带新认知与预设Timeout的任务包下发至执行层。

### Step 5: 状态解锁与流转 (耗时: 0秒)
- **动作**：任务下发后，解锁认知池写入接口，恢复常规任务接收，重置任务计数器。

## 4. 零残留执行检查清单

执行人员/自动化脚本在完成任务下发前，必须逐项打勾确认：

- [ ] **触发校验**：是否满足（10任务/一转结束/时间达25分钟）之一？
- [ ] **刷新校验**：认知缓存是否已执行刷新操作，非读取历史静态快照？
- [ ] **时效校验**：抽取的新认知时间戳是否均在近30分钟内？
- [ ] **注入校验**：下发的任务包Context中，是否已实际包含新认知节点（非空引用）？
- [ ] **超时校验**：任务包是否已绑定对应模型的Timeout（B模型turbo=300s / A模型=600s）？

## 5. 异常熔断机制
- **现象**：因新认知注入导致Prompt超长或API连续超时。
- **处置**：立即触发降级，保留最新1条核心认知，剔除其余新认知；保持Timeout不变重试1次；若仍超时，阻断任务并记录“认知注入失效”异常日志。
