# L4成品转化 [code]

基于【已有认知锚定】与【避坑提醒】，针对“多线程并发调用大模型API并由主线程串行后处理”这一具体工程场景，以下运用**“精气神三元迁移框架”**（精=底层实体/锚点，气=链路流转，神=顶层目标），生成针对**“大模型并发调用与串行后处理引擎灾备恢复”**的L4逐项检查清单。

所有条目均严格贯彻“先校准锚点再优化链路”原则，确保L4成品转化不仅限于SOP，而是切实落地为可执行的Code与Checklist。

---

### L4工程检查清单：大模型并发调用与串行后处理引擎灾备恢复

#### 阶段一：“精”—— 底层实体与锚点校准（重启前必检）

**1. API调用Timeout参数配置校验**
*   **判定标准**：配置文件或代码常量中，B模型turbo的timeout必须硬编码或配置为 `300秒`，A模型的timeout必须配置为 `600秒`。禁止使用全局统一timeout或默认无限期阻塞。
*   **异常处理方案**：若检测到timeout配置缺失或不符合标准，引擎拒绝启动，抛出 `ConfigValidationError`，并回滚至上一个稳定版本的配置文件。

**2. L4成品转化类型枚举闭环校验**
*   **判定标准**：任务实体（Task Entity）的 `output_type` 字段类型定义必须为闭环枚举：`[SOP, Code, Checklist]`。禁止仅包含 `SOP` 的单态定义，必须确保后处理逻辑链路能识别并路由 `Code` 和 `Checklist` 类型。
*   **异常处理方案**：若实体类型定义未闭环，触发 `EntitySchemaBlockError`。阻断当前所有多线程任务下发，强制执行DB Schema迁移脚本补全枚举值。

**3. 线程返回体结构一致性校验**
*   **判定标准**：多线程中每个调用大模型的Worker，其返回体必须严格包含 `task_id`, `model_type`, `status`, `raw_payload`, `type_tag`（标识SOP/Code/Checklist）五个核心字段。缺一不可。
*   **异常处理方案**：若主线程在串行接收时发现字段缺失，立即将该task标记为 `POISON_PILL`，写入死信队列（DLQ），主线程跳过该项继续后处理，防止因解析空指针导致全局断流。

#### 阶段二：“气”—— 链路流转与并发控制（运行时监控）

**4. 主线程串行后处理防断流与超载检测**
*   **判定标准**：主线程在执行 `future.result()` 获取并发结果时，必须包裹独立的 `try-catch/timeout` 块，单个task的后处理时间不得超过 `30秒`。禁止因单个task的后处理异常导致主线程整体退出。
*   **异常处理方案**：若单task后处理超时或抛出未捕获异常，主线程记录错误日志至监控大盘，将该task状态置为 `POST_PROCESS_FAILED`，并立即 `continue` 处理下一个future，保障“气”的流转不中断。

**5. 并发队列背压与API限流控制**
*   **判定标准**：并发线程池的 `max_workers` 必须与API速率限制匹配。当触发API限流（HTTP 429）时，Worker线程必须进入指数退避等待，且退避最大时长不得超过该模型的预设timeout（B模型300秒/A模型600秒）。
*   **异常处理方案**：若在退避窗口内仍未获取响应，强制中断该线程调用，返回 `status=TIMEOUT` 的标准结构体交由主线程处理，严防线程泄漏与资源死锁。

**6. L4 Code/Checklist结构化转化校验**
*   **判定标准**：主线程串行后处理时，若 `type_tag == 'Checklist'`，必须校验大模型返回的 `raw_payload` 是否包含 `item_id`, `judgment_criteria`, `exception_handler` 三个结构化字段。禁止直接将纯文本SOP写入Checklist成品库。
*   **异常处理方案**：若结构校验失败，触发 `L4FormatNotMatchError`。将原始payload降级转为SOP类型存储，并向重试队列发送一个带有Few-Shot提示词的修正任务，要求大模型重新生成符合结构的Checklist。

#### 阶段三：“神”—— 顶层目标与灾备恢复（故障后恢复）

**7. 断流续传断点保存机制校验**
*   **判定标准**：主线程每完成10个task的串行后处理，必须向本地Checkpoint文件或Redis原子写入当前进度指针 `last_success_task_id`。引擎重启时必须能读取该指针并跳过已处理项。
*   **异常处理方案**：若重启后发现Checkpoint文件损坏或丢失，禁止直接全量重跑。应扫描DB中所有 `status=PENDING` 或 `status=RUNNING` 但时间戳超过20分钟的幽灵任务，将其重新入队，确保顶层灾备可恢复。

**8. 灾备切换与降级策略校验**
*   **判定标准**：当A模型连续超时失败率达到阈值（如5次/分钟），必须触发降级逻辑，将后续任务自动路由至B模型turbo（并同步将timeout从600秒动态调整为300秒）。
*   **异常处理方案**：若降级路由模块自身故障无法切换，触发最高级别告警 `P0_ESCALATION`，熔断所有外部API调用，暂停并发线程池，等待人工介入确认网络链路或模型服务可用性后手动恢复。
