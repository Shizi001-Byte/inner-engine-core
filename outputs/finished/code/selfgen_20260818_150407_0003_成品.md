# L4成品转化 [code]

【L4工程检查清单：引擎重启与双轨归档恢复】

**工程场景**：脑（元控制器）接管控制权后，引擎从宕机状态重启，恢复“引擎产出 → 分类 → 打标签 → 落盘 → 索引”的阳轨链路，并同步激活阴轨兜底校验。

**使用说明**：逐项执行，满足【判定标准】方可勾选；若触发【异常处理方案】，需执行完毕后方可进入下一项。

---

### [ ] 1. 脑（元控制器）控制权接管与状态确认
*   **判定标准**：脑节点心跳上报至分布式锁（如ZK/ETCD）成功，集群角色标识为“脑节点”，且引擎底层控制权状态由 `STANDBY` 切换为 `ACTIVE`，切换延迟 < 3秒。
*   **异常处理方案**：若5秒内未获取控制权，强制终止残留的旧引擎进程（`kill -9`），触发脑裂防护脚本；若仍失败，冻结当前节点并发出P0告警，人工介入排查网络分区。

### [ ] 2. 引擎产出验证（阳轨起点）
*   **判定标准**：引擎重启后产出队列消费速率 > 0，TPS 达到基线水平的 80% 以上，且积压消息量呈单调递减趋势，无 `OOM` 或 `DeadLock` 错误日志。
*   **异常处理方案**：若产出为空或TPS为0，立即断开上游数据源重连；若积压持续增长，启动降级策略，丢弃非关键业务数据（依据标签优先级），并将队列分流至备用缓冲集群。

### [ ] 3. 分类与打标签一致性校验（阳轨中段）
*   **判定标准**：数据分类成功率 ≥ 99.9%，打标字段非空率 = 100%。抽样100条数据，其标签与脑节点下发的规则库版本号完全匹配，分类打标平均延迟 < 200ms。
*   **异常处理方案**：若成功率跌破阈值或版本不匹配，将未分类数据路由至“阴轨死信队列”；同时强制从脑节点拉取最新规则库重置本地缓存，重试3次。若仍失败，阻断后续产出并告警。

### [ ] 4. 阴阳双轨落盘校验（阳轨存储/阴轨兜底）
*   **判定标准**：阳轨主库写入ACK返回成功，落盘耗时 < 50ms；阴轨归档库同步写入完成，阴阳双轨落盘数据的 `checksum` 差异率 = 0%。
*   **异常处理方案**：若阳轨落盘超时/失败，触发熔断，自动将写入流量切换至阴轨归档库（降级为只追加不索引模式）；若阴阳 checksum 不一致，以阴轨归档库为准，触发阳轨数据的逆向修复任务，并记录脏数据日志。

### [ ] 5. 索引重建与检索可用性（阳轨检索）
*   **判定标准**：索引构建任务状态为 `COMPLETED`，索引段（Segment）成功刷盘；随机抽样10条最新落盘数据执行查询，命中率 = 100%，且检索P99延迟 < 100ms。
*   **异常处理方案**：若索引构建失败，清理残留的 `write.lock` 及损坏的 Segment 文件，调用 B模型turbo（**预设 timeout=300秒**）进行快速重建；若抽样检索未命中，回滚索引至上一可用快照，并触发增量补建机制。

### [ ] 6. 模型调用超时与熔断验证（历史避坑落实）
*   **判定标准**：归档链路中调用的模型超时配置严格生效：A模型 timeout = 600秒，B模型turbo timeout = 300秒。断路器（Circuit Breaker）处于 `CLOSED` 状态，监控面板无超时告警。
*   **异常处理方案**：若日志出现 `TimeoutException`，立即阻断对该模型的调用，熔断器切换为 `OPEN` 状态；降级走本地规则引擎或阴轨缓存数据进行打标，并记录超时上下文至审计表，等待模型侧恢复后再半开试探。
