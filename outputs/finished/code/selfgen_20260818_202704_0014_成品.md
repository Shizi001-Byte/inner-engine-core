# L4成品转化 [code]

基于认知池中“每次变更均为突变，通过测试即保留，回滚即净化选择”的核心方法论，将其转化为工程上可直接落地的标准操作程序（SOP）。

以下是零脑补、零歧义、可直接执行的L4成品文档：

---

# 【L4 SOP】版本“突变”与“净化选择”执行规范

## 1. 前置定义
- **突变**：任何可能导致系统行为发生变化的操作，包括但不限于：代码 Merge、版本 Release 发布、环境变量修改、基础设施参数调整。
- **选择**：突变发生后，系统进行的自动化与人工验证过程。
- **净化选择**：当“选择”阶段判定当前“突变”有害（不达标或引发故障）时，执行的回滚操作，剥离有害突变，恢复至上一稳定态。

## 2. 适用场景
所有涉及生产环境或预发环境变更的发布与参数调整任务。

## 3. 标准操作流程 (SOP)

### 阶段一：引入“突变”
1. **确认变更内容**：明确本次 commit/参数调整的具体 diff，确保已合并至主分支。
2. **生成突变标识**：为本次变更生成唯一标识符（如 Git Commit Hash 或 Release Ticket ID）。
3. **记录基准状态**：记录当前生产环境的稳定版本号及核心监控指标基线（包含：CPU使用率、内存使用率、HTTP 5xx错误率、P99响应延迟）。

### 阶段二：执行“选择”
4. **预发环境验证**：
   - 4.1 执行全量自动化测试套件（单元测试+集成测试）。
   - 4.2 **判定标准**：测试通过率必须为 100%。
   - 4.3 若未通过，终止流程，直接执行“阶段三：净化选择”。
5. **生产环境灰度验证**：
   - 5.1 将“突变”版本部署至生产环境 5% 的流量节点。
   - 5.2 **观察时长**：不少于 15 分钟。
   - 5.3 **判定标准**：错误率 < 0.1%，P99 延迟波动不得超过基线 10%。
   - 5.4 若指标达标，逐步扩大流量至 100%，完成部署（突变保留）；若指标未达标，执行“阶段三：净化选择”。

### 阶段三：“净化选择”执行（回滚机制）
6. **触发条件**：满足以下任一条件即触发净化（回滚）：
   - 自动化测试未达 100% 通过率。
   - 灰度期间监控指标越界（错误率 ≥ 0.1% 或 P99 波动 > 10%）。
   - 收到严重级别（P0/P1）线上告警。
7. **执行净化（回滚操作）**：
   - 7.1 在 3 分钟内执行一键回滚脚本，将生产环境版本切回“阶段一-步骤3”记录的基准稳定版本。
   - 7.2 验证回滚结果：检查监控面板，确认错误率在 5 分钟内恢复至基线水平。
8. **变异体解剖（复盘）**：
   - 8.1 保留本次“突变”的日志与监控快照。
   - 8.2 将该突变标记为“有害”，禁止在未查明原因并修复前重新注入相同的突变。

## 4. 执行检查清单

请在每次执行变更任务时，逐项打勾确认，全部通过方可进行下一阶段：

**【突变前准备】**
- [ ] 已记录变更前的生产环境稳定版本号：`__________`
- [ ] 已记录变更前的核心监控指标基线（错误率：`__%`，P99延迟：`__ms`）

**【选择阶段验证】**
- [ ] 预发环境自动化测试 100% 通过？（若选否，禁止继续，直接执行回滚）
- [ ] 生产环境 5% 灰度已持续观察 15 分钟？
- [ ] 灰度期间错误率 < 0.1%？
- [ ] 灰度期间 P99 延迟波动 <= 10%？

**【净化选择触发与执行】（如触发回滚必填）**
- [ ] 触发回滚的原因已记录？
- [ ] 是否在 3 分钟内完成一键回滚脚本执行？
- [ ] 回滚后 5 分钟内，监控指标是否已恢复至基线水平？
- [ ] 是否已提取并保存故障快照日志，并标记该 commit 为有害突变禁止重试？
