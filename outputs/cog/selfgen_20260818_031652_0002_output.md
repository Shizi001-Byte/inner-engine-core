# 任务类型: cog

基于您提供的核心认知锚定，直接切入“认知质检SOP”视角，针对引擎运行中因“不知盲”（即不知道自己不知道，将系统盲区伪装成已知结论）引发的幻觉，反向推演提炼出以下3条操作铁律及验证方法：

### 铁律一：边界声明前置（阻断“参数记忆”伪装成“事实依据”）
*   **【踩坑推演】**：引擎在生成回答时，曾直接调用参数化记忆中的模糊关联，将“高频共现词”等同于“因果事实”，未在输出前声明该结论的来源是“内部推断”而非“外部检索”，导致用户将其视为确凿事实。
*   **【操作铁律】**：引擎在输出任何核心结论前，**必须显性声明信息源属性**（外部检索确证 / 内部逻辑推断 / 参数化记忆）。对于无法映射到外部确定性数据的结论，必须强制前置“认知盲区”标签。
*   **【验证方法：溯源率与盲区触发测试】**
    1.  **探针注入法**：向引擎输入刻意构造的“伪命题”或“极度冷门跨界问题”，检测引擎是否触发“不知盲”警报，而非强行生成看似合理的解释。
    2.  **溯源率审计**：抽取引擎近期输出的100条事实性结论，统计“带有明确信息源属性标签”的占比。若溯源率<95%，则判定该铁律执行失效。

### 铁律二：证据-结论阻尼机制（阻断“逻辑强接”导致的顺滑幻觉）
*   **【踩坑推演】**：引擎在推理链路中，当A证据与B结论之间存在逻辑断层时，由于语言模型的“顺滑预测”本能，直接用修辞或假设填补了断层，产生了“看起来逻辑自洽但实则缺乏事实支撑”的幻觉。
*   **【操作铁律】**：严禁在证据完备度<100%时进行无标记的推导。**当证据链存在缺失节点时，引擎必须强制降级输出**（如从“断言”降级为“假设”），或在推理链中插入“认知阻尼块”（显性标注：此处证据不足，结论为推测），禁止平滑跨越逻辑断层。
*   **【验证方法：逻辑截断与拒答率监控】**
    1.  **残缺信息对抗测试**：向引擎投喂刻意剔除关键逻辑环节的上下文，验证引擎是“强行补全幻觉”还是“触发阻尼标记/拒答”。
    2.  **阻尼块命中率监控**：在复杂推理任务中，统计引擎自发输出“推测性标记”的频率。若阻尼块命中率趋近于0，且任务复杂度高，则说明引擎存在严重的“不知盲”幻觉风险。

### 铁律三：逆向自证审计（阻断“单一视角”导致的过度自信）
*   **【踩坑推演】**：引擎在生成初始结论后，仅做了正向逻辑自洽检查，未进行反向证伪。因为初始结论符合引擎自身的权重分布，引擎“认为自己知道”，从而掩盖了其可能违反基础常识或物理规律的盲区。
*   **【操作铁律】**：引擎在输出最终结果前，**必须执行一轮内部的“红蓝对抗”**。生成初始结论后，立即触发“证伪引擎”，要求寻找推翻该结论的反例或反面逻辑。若证伪引擎无法找到反例且无法解释原因，则判定初始结论为“不知盲”幻觉。
*   **【验证方法：红蓝对抗一致性校验】**
    1.  **反例生成率检测**：对引擎输出的结论，自动触发Prompt：“请给出3个推翻该结论的情境”。若引擎输出的情境中包含原有结论完全无法覆盖的合理场景，则扣减该输出的置信度分数。
    2.  **置信度校准曲线**：对比“引擎自评置信度”与“人工抽检真实准确率”。若引擎自评高置信度（>90%）的输出中，真实准确率低于80%，说明引擎的“不知盲”感知模块失效，需立即回滚并重训审计模块。
