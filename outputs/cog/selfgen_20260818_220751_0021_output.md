# 任务类型: cog

基于【已有认知锚定】与【坑库预警】，针对“基建脚本禁用简化版”导致SQL列不匹配的教训，现进行“以实养虚，虚又返实”的自增强循环推演，并输出标准化检查清单。

### 一、 虚实推演：从SQL列不匹配到引擎自增强

1. **以实养虚（经验沉淀）：**
   * **实（工程执行）：** 执行基建脚本时，为了图快禁用了“简化版SQL”逻辑（如使用 `SELECT *` 或省略字段映射），导致上下游表结构列顺序错位、数据类型不匹配，引发任务大面积报错甚至API调用超时。
   * **虚（引擎更新）：** V7.5方舟效能引擎捕获该异常，将其提炼为“结构对齐强依赖”认知节点，进入九转玄功映射体系的“基建类任务”分支，标记为高危特征。

2. **虚又返实（认知指导执行）：**
   * **虚（引擎调度）：** 引擎在后续调度基建类任务时，强制注入该认知，要求必须进行Schema校验；同时根据历史避坑经验，为A/B模型分别预设600秒/300秒的timeout。
   * **实（工程执行）：** 新任务在执行前，强制触发列名与类型对齐校验，拦截简化版SQL，确保实际API调用与数据落盘时列严格对齐，彻底杜绝因数据对齐错误导致的超时与重试。

### 二、 防御性检查清单（强制注入基建脚本执行流）

> **认知激活声明：** 遵循坑库预警，本检查清单作为新认知，将在生成后30分钟内强制注入当前及后续基建任务上下文，并在每转结束时刷新认知缓存。

#### 1. 核心Schema校验（防线一：杜绝简化版SQL）
- [ ] **禁用 `SELECT *`**：是否在所有数据流转SQL中明确写出了目标列名？
- [ ] **列顺序对齐**：源表查询字段顺序与目标表 `INSERT` 字段顺序是否绝对一致？
- [ ] **类型匹配检查**：源表字段类型与目标表字段类型是否兼容（如 VARCHAR 转 INT 是否有空值或非数字字符风险）？
- [ ] **非空约束校验**：简化版是否漏掉了必要的 `WHERE` 条件，导致非空字段写入 NULL？

#### 2. 超时与熔断管理（防线二：规避API超时）
- [ ] **Timeout预设**：当前基建任务是否已根据调用模型预设timeout？（B模型turbo=300秒，A模型=600秒）
- [ ] **分批执行策略**：若脚本涉及大数据量写库，是否拆分为 `BATCH` 提交，避免单次事务过长触发超时？
- [ ] **错误熔断机制**：当出现首次列不匹配报错时，脚本是否配置了立即终止，而非继续重试消耗API额度？

#### 3. 虚实闭环校验（防线三：认知池活水机制）
- [ ] **认知即时注入**：本次脚本执行若发现新的字段映射陷阱，是否在任务完成的10个步序内将其写入认知缓存？
- [ ] **静态档案库排查**：本次基建任务的执行参数，是否确实读取并校验了V7.5引擎中关于“列对齐”的历史认知，而非独立空跑？
- [ ] **转结束刷新**：本转任务结束后，是否触发认知池刷新，将本次“禁用简化版”的校验结果固化为引擎调度规则？
