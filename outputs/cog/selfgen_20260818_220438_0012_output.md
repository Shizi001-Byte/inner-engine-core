# 任务类型: cog

# 先校准锚点再优化链路 → 任务优先级排序

---

## 一、根因拆解：项目ID看错导致1小时排查

```
错误链路还原：

[看错项目ID] → [进入错误工作空间] → [排查1小时] → [发现锚点错误] → [归零重来]
     ↑                    ↑                                          ↑
   锚点错误            链路优化全部失效                           1小时劳动归零
```

**本质**：锚点未校验就启动链路优化，导致后续所有动作方向性失效。

**代价比**：校验锚点10秒 : 未校验排查1小时 = **1 : 360**

---

## 二、迁移到任务优先级排序

任务排序本质也是一条链路。排序前若**锚点未校准**，排出来的优先级队列就是"错误项目ID下的排查链路"——**越优化越偏离**。

### 锚点对应关系

| 项目排查场景 | 任务优先级排序场景 |
|---|---|
| 项目ID | 任务的真实价值归属（服务于哪个目标？） |
| 工作空间 | 任务的约束条件（截止时间/依赖/资源） |
| 排查动作 | 优先级排序动作本身 |
| 1小时白费 | 排出的队列全部推翻重来 |

---

## 三、具体应用：锚点校验三步法

### 第一步：识别锚点（排序前必须确认的3个标识）

对每个待排序任务，先提取锚点属性：

```
锚点A — 价值归属：这个任务服务于哪个目标？（不是"看起来重要"，而是"实际产出到哪"）
锚点B — 约束边界：真实截止时间 + 真实依赖链 + 真实资源需求
锚点C — 战略坐标：在整体路线图中处于哪一转的哪一层
```

### 第二步：校验锚点（30秒快速验证，对应"看项目ID"）

```
校验清单：
□ 价值归属是否确认？（不是别人说紧急就紧急，需追溯到目标层）
□ 约束边界是否完整？（只看到截止时间，没看到依赖链 = 项目ID只看了一半）
□ 战略坐标是否匹配？（1-3转的执行层任务 vs 4-6转的调度层任务，排序逻辑不同）
```

> **核心教训**：项目ID看错 = 锚点A/B/C任意一个识别错误，后续优先级排序等于在错误空间里排序。

### 第三步：锚点确认后再排序（链路优化）

只有三个锚点全部校验通过，才进入排序链路：

```
排序公式：
优先级 = 价值归属权重 × 约束紧急度 × 依赖阻塞系数

其中：
- 价值归属权重：锚点A确定 → 1-3转任务权重 < 4-6转 < 7-9转（战略层级递进）
- 约束紧急度：锚点B确定 → 基于真实截止时间而非主观感受
- 依赖阻塞系数：锚点C确定 → 该任务是否阻塞后续多个任务
```

## 四、反面案例对照

### ❌ 错误做法（未校准锚点直接排序）

```
收到5个任务 → 凭直觉按"看起来紧急"排序 → 执行2小时后发现：
- 任务1的价值归属判断错误（服务于已废弃的目标）
- 任务3的依赖链漏看（前置任务未完成，排了也做不了）
→ 2小时链路优化全部失效，等于"项目ID看错导致1小时排查"的重演
```

### ✅ 正确做法（先校准锚点再排序）

```
收到5个任务 → 
  锚点校验阶段（每个30秒，共2.5分钟）：
    □ 任务1：价值归属=目标X，约束=今天18:00，战略坐标=4转调度层 ✓
    □ 任务2：价值归属=目标Y，约束=无截止，战略坐标=2转执行层 ✓
    □ 任务3：价值归属=目标X，约束=依赖任务7未完成，战略坐标=3转 ⚠ 依赖阻塞
    ...
  → 排序链路阶段（基于已校验锚点）：
    优先级队列 = [任务1(阻塞+紧急) → 任务3(依赖解锁后) → 任务2(低权重)]
```

**代价比**：锚点校验2.5分钟 : 错误排序后返工2小时 = **1 : 48**

## 五、一句话总结

> **项目ID看错 = 优先级锚点未校验。10秒的锚点校验省360秒的链路返工，排序前先问"这个任务的三个锚点是什么"，再问"怎么排"。**
