# 基建脚本禁用简化版 — 认知复盘与检查清单

## 一、认知复盘：简化版SQL导致列不匹配

### 根因链路

```
简化版SQL（省略列名，用SELECT *）
  → 表结构变更/补丁式ALTER ADD COLUMN
    → 简化版未同步声明列
      → 结果集列数/列序与下游解析不匹配
        → 数据错位写入 → 静默数据腐败
```

### 核心教训

| 维度 | 简化版的诱惑 | 实际代价 |
|------|-------------|---------|
| 开发速度 | 写得快、改得少 | 列序漂移不可控 |
| 可读性 | 看起来简洁 | 语义不自解释 |
| 维护性 | 改表不用改SQL | 下游全部炸裂 |
| 可追溯 | 无列级变更记录 | 故障时无法定位 |

## 二、检查清单（使用前必须逐项过）

### P0 — 禁令级（违反即阻断）

- [ ] **SQL中是否出现了 `SELECT *`？** → 出现即拒绝合并
- [ ] **INSERT语句是否省略了目标列名？** → 省略即拒绝合并
- [ ] **简化版SQL是否与正式版共用同一张表？** → 共用即拒绝执行
- [ ] **是否有"临时跑一下简化版"的注释或TODO？** → 存在即拒绝合并

### P1 — 结构一致级

- [ ] **简化版SQL的列声明是否与正式版完全对齐？**（列名、列序、列类型）
- [ ] **是否有自动化对比脚本校验两版SQL的列差异？**
- [ ] **表结构变更后，简化版SQL是否同步更新？**
- [ ] **简化版SQL的结果集是否被下游代码按列索引硬编码解析？**

### P2 — 运行时校验级

- [ ] **SQL执行后是否校验了返回列数 == 预期列数？**
- [ ] **是否对关键列名做了exists校验（而非仅靠列序）？**
- [ ] **简化版SQL是否带版本标记，与表schema版本绑定？**
- [ ] **执行日志中是否记录了实际返回的列名列表？**

### P3 — 流程治理级

- [ ] **简化版SQL是否需要审批才能创建？**（而非随手写）
- [ ] **是否有定期巡检脚本扫描代码库中的`SELECT *`？**
- [ ] **简化版SQL是否有明确的生命周期标注（过期自动告警）？**
- [ ] **CI/CD流水线是否包含列匹配校验门禁？**

## 三、锚定到V7.5方舟效能引擎

> 基于【已有认知锚定】的"精气神三元迁移框架"：

| 三元 | 简化版SQL问题映射 | 治理动作 |
|------|-------------------|---------|
| **精**（决策层） | SQL列声明是数据契约，简化版破坏契约显式性 | 决策层强制要求列级声明，禁止隐式列推断 |
| **气**（调度层） | 简化版与正式版混用，执行层越权侵入决策层 | 调度层隔离两版SQL的执行通道，不交叉调用 |
| **神**（状态层） | 列不匹配导致状态一致性被破坏 | 状态层在执行后做列schema校验，不匹配即回滚 |

> 贯彻"先校准锚点再优化链路"：**列声明锚点校准 → 执行链路才允许展开**
