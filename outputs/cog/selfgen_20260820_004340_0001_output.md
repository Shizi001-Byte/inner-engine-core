## 二、重复模式识别

### 模式1：同义异表（同簇最高频）
- **现象**：同一条结论被不同任务以不同表述记入认知池
- **示例**（推演）：
  - "文件mtime变化触发重算hash"
  - "通过mtime判断是否需要重新计算内容指纹"
  - "mtime未变可跳过hash计算以节省IO"
- **本质**：三者皆是 **链1→链2 衔接规则**的拆碎表达

### 模式2：链路冗余碎片
- **现象**：锚定链已固化的整链结论，其内部节点仍以独立认知形式存在
- **示例**：链1/2/3是已锚定的完整推理链，但池中可能仍有"变化检测原理""去重收益""增量同步优势"等可被链吸收的低密条目
- **本质**：链锚定动作未触发对底层碎片的回收

### 模式3：版本残留覆盖
- **现象**：旧结论被新结论覆盖但未清理
- **示例**：早期"用MD5做内容寻址" → 后修正为"用BLAKE3"，两条并存
- **本质**：认知更新时无失效标记机制

### 模式4：单例边角
- **现象**：针对单一特殊case记录的认知，未抽象为通用规则
- **示例**："某次跨平台同步时Windows路径分隔符导致冲突"
- **本质**：应升级为链4"异构自适应"的子节点，而非独立C级条目

## 三、合并与清理方案

### 方案A：簇内合并（吸收密度升级）

```
操作：同簇多条C级 → 合并为1条B级
触发条件：同簇内语义相似度 ≥ 0.85
示例：
  C-A簇3条 → "文件变化检测：mtime作为低成本预筛，事件源作为实时性补充，二者组合避免漏检"
  密度评级 C → B
```

### 方案B：链锚定吸收（降为叶子引用）

```
操作：被锚定链覆盖的碎片 → 不独立保留，转为链节点的"支撑证据"索引
触发条件：认知内容属于链1-5任一节点的直接推导
好处：池容量下降，链结构保持权威
```

### 方案C：失效标记与归档

```
操作：版本残留/已被推翻 → 标记deprecated，移出活跃池
触发条件：存在更新的同主题认知，且旧认知与之矛盾
注意：不物理删除，保留审计轨迹
```

### 方案D：单例升级或淘汰

```
操作：边角case → 尝试抽象为通用规则，无法抽象则降为归档
示例：Windows路径分隔符case → 升级为链4"路径归一化预处理"子规则
```
