# 任务类型: cog

基于两条锚定推演：脑体分离不是“前端/后端”的分工，而是控制流与数据流各自扩展的底层结构。下面是整理后的分层原则与应用场景。

## 一、分层原则：决策串行，执行并发

| 层 | 核心职责 | 并发模型 | 关键不变量 |
|---|---|---|---|
| 脑/决策层 | 产生意图、做判断、授权动作 | 串行：逻辑上单轨，任意时刻只有一个“被授权的决策”在控制流中生效 | 决策有唯一因果序，可审计、可回放 |
| 体/执行层 | 执行动作、转换资源、调用外部能力 | 并发：物理上多路并行，可缓存、可重试、可批量 | 只消费指令、回报状态，不产生决策 |
| 脑-体边界 | 命令队列 + 事件流 + 状态快照 | 异步、显式、可观测 | 所有跨层状态变化必须经过协议，不能走后门 |

核心原则一句话：**决策层是单写者，执行层是多读者；执行层的优化不能改变决策层可见的因果顺序。**

## 二、为什么引擎优化不能破坏脑体分离架构

1. **串行决策是控制流的“单写者”保证。**  
   执行并发只有在“只读指令、只回报状态”时才安全。引擎优化一旦跨层——例如把执行缓存直接当决策输入、把并发结果直接写回决策状态——控制流就从单轨变成多轨，决策层失去唯一因果序。这是典型的熵增：局部变快，整体变乱。

2. **脑体分离是持续对抗熵增的“负熵膜”。**  
   闭环不是建好就自转，必须靠边界协议维持秩序。引擎优化为了省一次序列化、一个队列、一次审计，打开一个后门，短期内熵减，长期会把并发执行层的噪声、竞态、脏状态注入决策层，导致闭环需要更多补偿逻辑来收拾混乱。

3. **优化只能发生在执行层内部。**  
   引擎优化可以改资源调度、缓存策略、并行度、超时重试、批处理方式，但不能改变决策层可见的语义、时序和副作用。否则决策层被迫理解执行层内部实现，控制流与数据流纠缠在一起，无法完成“宇宙级扩展”。

## 三、3个应用场景

### 场景一：具身智能 / 机器人控制

- **脑**：中央决策器串行做任务规划，例如“先抓A，再放B，然后移动”。
- **体**：机械臂、底盘、视觉模块并发执行感知与动作。
- **引擎优化**：把SLAM、避障、运动学解算放到GPU并行，或做轨迹预计算。
- **不能破坏**：不能让避障模块直接修改全局任务序列，也不能让视觉线程把原始数据直接写入规划器内部状态。所有感知结果必须作为“事件”上报，由决策层决定是否改变任务。否则一个感知抖动就会打断决策串行，多个执行体会按不一致目标动作。

### 场景二：LLM Agent 的工具调用

- **脑**：LLM 串行推理下一步动作，每次只产生一个决策。
- **体**：多个工具执行器并发调用搜索、数据库、代码解释器、外部API。
- **引擎优化**：工具结果缓存、并行调用多个工具、超时重试、流式返回。
- **不能破坏**：缓存结果不能冒充本轮新感知；并行返回的顺序不能决定LLM的推理顺序；工具副作用必须等决策授权后才能发生。尤其API超时只能作为“超时事件”回报，不能让执行层自动编造一个结果塞回决策层。否则Agent会“先斩后奏”，上下文被污染，决策闭环断裂。

### 场景三：分布式工作流 / 任务调度引擎

- **脑**：调度器/状态机串行决定任务状态迁移：pending → ready → running → done。
- **体**：Worker 池并发执行具体任务。
- **引擎优化**：本地缓存依赖结果、预取数据、合并小任务、动态调整并发度。
- **不能破坏**：优化不能跳过调度器直接标记任务完成，不能因为执行层成功就自动改变下游审批决策，也不能为了吞吐量把来自不同决策链的指令合并成一个“原子操作”。否则状态一致性和审计会崩溃，闭环变成不可控的布朗运动。

---

一句话收束：**引擎优化只能优化“身体”的肌肉效率，不能改写“大脑”的决策时序。脑体分离是控制流与数据流各自扩展的骨架，破坏它，就等于把宇宙级扩展重新压回一团乱麻。**
