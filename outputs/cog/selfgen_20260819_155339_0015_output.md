# 任务类型: cog

## 分层原则：决策串行、执行并发

### 一、原则定义

- **决策串行**：所有“做什么、按什么顺序、能不能做”的判断，都收敛到同一个决策层（大脑）串行处理。每次决策以 `change_id + 内容哈希` 为唯一纽带，保证可追踪、可幂等、可冲突仲裁。
- **执行并发**：决策通过后，具体的动作（API 调用、文件上传、代码提交、存储同步）交给执行层（身体）并发执行。执行层只负责“更快、更稳地完成动作”，不负责“判断该不该做”。
- **脑体分离**：大脑与身体之间通过“结果回报”通信，而不是共享状态或互相直接调用。大脑是唯一写状态的地方，身体是唯一做 I/O 的地方。

一句话：

> **大脑单线思考，身体多线程干活。**

---

### 二、为什么引擎优化不能破坏脑体分离架构

引擎优化，比如提高并发数、调整 timeout、重试策略、切换模型（B 模型 turbo 300 秒，A 模型 600 秒），都属于**执行层优化**。

这些优化不能破坏脑体分离，原因有三：

#### 1. 决策串行是幂等和冲突处理的唯一防线

如果执行引擎为了提速，把“判断是否冲突”“是否重大变更”“是否跳过验证”这些决策逻辑下沉到执行层，就会产生多个并发决策者。

- 两个 worker 同时认为“自己可以改同一个文件”
- 两个上传任务同时认为“自己是第一次执行”
- `change_id` 失去唯一权威

最终结果就是：重复提交、重复上传、状态覆盖。

所以，引擎优化只能优化“手脚”，不能替“大脑”做判断。

#### 2. 执行并发是性能来源，但不能拥有最终决定权

执行层并发是为了缩短耗时，但它产生的结果是**局部视角**：

- 这次 API 超时了
- 这个文件上传失败了
- 这个 git 提交冲突了

如果执行层基于局部视角自动改变全局决策，比如“既然上传失败，我就换个目标存储”，那么大脑的全局状态就会失控。

正确做法是：

> 执行层只回报结果，大脑根据结果做下一步决策。

#### 3. 替换或升级执行引擎，不应影响决策语义

脑体分离的架构，允许执行引擎独立演进：

- 同步调用改成异步任务
- 串行上传改成并发分片上传
- 换更快的模型、调更合理的 timeout

但如果优化引擎需要侵入决策层，比如要求决策层理解“某个并发任务的内部顺序”，那说明架构已经耦合。

引擎优化应该对大脑透明：

> 大脑看到的还是“提交任务 -> 等待结果 -> 继续决策”，至于身体内部怎么并发、怎么重试、怎么优化，大脑不关心。

---

### 三、3 个应用场景

#### 场景 1：AI 编码 / 代码仓库协同

- **大脑**：串行分析 issue，生成变更计划，计算 `change_id + 内容哈希`，决定“先改 A 仓库，再改 B 仓库”，或者“哪些改动可以并行”。
- **身体**：多个 worker 并发执行 git 提交、代码修改、测试运行。
- **引擎优化**：把原来串行的 git 提交改成并发提交到多个仓库，或者优化 API 调用超时。
- **不能破坏**：worker 不能因为“想提速”就跳过内容哈希校验，也不能自行判断“这个改动不重大，不用通知大脑”。
- **正确做法**：每个 worker 只执行大脑分配的任务，完成后把新的 `change_id` 和哈希回报给大脑。

---

#### 场景 2：多目标文件 / 存储同步

- **大脑**：串行校验文件哈希，判断是否已有相同 `change_id`，然后决定“上传飞书 + 写入 Supabase + 触发通知”。
- **身体**：并发执行飞书上传、Supabase 写入、通知发送；每个任务有独立 timeout，比如 B 模型 turbo 用 300 秒，A 模型用 600 秒。
- **引擎优化**：增加上传并发度、调整重试退避、优化超时策略。
- **不能破坏**：执行层不能因为“飞书上传慢”就自动把文件改存到别处，也不能用局部成功结果覆盖大脑的全局同步状态。
- **正确做法**：执行层回报每个目标的成功/失败/哈希，大脑决定是标记完成、重试，还是回滚。

---

#### 场景 3：多智能体 / 任务编排

- **大脑**：串行维护全局任务队列，决定哪个智能体处理哪个任务，以及任务之间的依赖关系。
- **身体**：多个智能体并发执行“调研、写代码、发消息、跑测试”等具体动作。
- **引擎优化**：增加智能体并发数，优化模型调用，加入缓存，调整超时。
- **不能破坏**：智能体不能在执行中直接修改全局状态，也不能互相“商量”后绕过大脑做决策。
- **正确做法**：所有智能体的执行结果统一汇总到大脑，由大脑进行下一轮决策；引擎优化只改变“身体跑多快”，不改变“大脑怎么想”。

---

### 总结

- **决策串行** = 全局只有一个人说了算。
- **执行并发** = 干活的人可以很多。
- **脑体分离** = 干活的人没有决策权，说了算的人不亲自干活。
- **引擎优化** = 让干活的人更快、更稳，但绝不能让他们变成“决策者”。

> 引擎优化一旦破坏了脑体分离，系统就从“可控的并发”退化成“失控的并发”。  
> 所以，优化执行层可以，但边界必须清晰：**身体可以更快，不能替大脑思考。**
