# 任务类型: cog

# 基建脚本「简化版」认知复盘与防截断检查清单

---

## 一、事件本质降维分析

| 表象 | 根因 | 认知层映射 |
|------|------|------------|
| INSERT列数与VALUES不匹配 | 简化版脚本砍掉了部分字段定义 | **维度截断幻觉**：执行者假设简化版 ≡ 完整版 |
| 脚本跑通但数据错位 | 列名未显式声明，依赖位置映射 | **隐性关联悬置态**：列名↔位置的对齐关系被悬置，未显式锚定 |
| 事后才发现错误 | 无运行时校验拦截 | **不知盲**：缺失高维探针，无法感知维度坍缩 |

**核心教训：在基建场景中，"简化版"本质是一次降维操作，而基建要求全维对齐。**

---

## 二、防截断检查清单（12项硬门禁）

### A. 等价性验证（执行前）

- [ ] **A1 差异清单显式化**：简化版与完整版的diff是否已逐字段列出，而非口头确认"差不多"？
- [ ] **A2 被砍字段影响域标注**：每个被简化的字段/约束/索引，是否标注了"在当前场景可忽略"的理由？
- [ ] **A3 上下文边界声明**：简化版脚本的头部是否声明了 `适用边界 = [环境/数据量/阶段]`，越界即失效？

### B. Schema对齐（执行前）

- [ ] **B1 列名显式声明**：INSERT语句是否 `INSERT INTO t(a,b,c) VALUES(...)` 而非 `INSERT INTO t VALUES(...)`？
- [ ] **B2 列数=值数硬校验**：是否在脚本执行前自动解析SQL的列token数与占位符数做等值断言？
- [ ] **B3 目标表DDL快照比对**：执行前是否拉取目标表当前DDL，与脚本预期schema做字段级diff？

### C. 环境一致性（执行前）

- [ ] **C1 环境版本锚定**：简化版脚本是否绑定了具体的schema版本号，而非"当前环境"这种模糊引用？
- [ ] **C2 多环境漂移检测**：dev/staging/prod的表结构是否已确认一致，或已声明预期差异？

### D. 运行时拦截（执行中）

- [ ] **D1 Dry-Run模式**：脚本是否支持 `--dry-run` 先解析不执行，输出影响行数与列映射预览？
- [ ] **D2 事务包裹+断言**：是否在事务内执行并设置 `列匹配断言`，失败即ROLLBACK？

### E. 认知防截断（归档时）

- [ ] **E1 禁用标记**：简化版脚本文件名是否含 `_simplified_dangerous` 后缀，归档系统自动标记为 `不可直接用于生产`？
- [ ] **E2 教训沉淀**：本次事件是否已提炼为一条 `高维记忆` 写入归档引擎，下次类似脚本生成时自动注入检查规则？

## 三、检查清单的工程化嵌入点

```
脚本编写 → [A1-A3] 等价性门禁
         → [B1-B3] Schema对齐门禁  → 不通过 = 阻断
         → [C1-C2] 环境锚定门禁
         → 执行 → [D1] Dry-Run预览 → [D2] 事务断言拦截
         → 归档 → [E1] 禁用标记 → [E2] 教训写入高维记忆
                                        ↓
                              下次脚本生成时自动注入此清单
```

**关键设计原则**：简化版脚本的"简化"必须只简化执行逻辑，**不可简化校验逻辑**。校验维度只增不减。
