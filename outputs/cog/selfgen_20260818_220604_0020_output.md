# 任务类型: cog

基于您提供的【避坑提醒】与【已有认知锚定】，在此认知基础上推演“决策串行、执行并发”的分层原则及脑体分离架构的不可破坏性。

### 一、“决策串行、执行并发”的分层原则整理

该原则是复杂AI系统或自动化工作流的核心设计哲学，旨在平衡“准确性”与“效率”：

1. **决策串行（脑层/单线程）：** 
   涉及锚点校验、意图识别、资源路由、工作空间确认等关键节点的决策，必须强制串行。每一步的输出是下一步的输入（如：看对项目ID → 进入正确工作空间）。**串行的目的是防止“锚点错误导致链路优化全部失效”。**
2. **执行并发（体层/多线程）：** 
   在锚点被彻底锁定、任务被拆解为无状态的独立子任务后，进入执行层。此时可充分利用多线程、异步IO等引擎优化手段并发处理（如：批量文件读取、多分支API调用）。
3. **脑体分离架构：** 
   “脑”负责定方向、锁锚点、防越界；“体”负责跑速度、做并发、提吞吐量。两者物理或逻辑隔离，确保执行层的极高并发不会反向污染决策层的逻辑正确性。

---

### 二、为什么引擎优化不能破坏“脑体分离”架构？

**核心结论：引擎优化（如并发执行、超时控制）如果越界侵入决策层，会直接导致“锚点失稳”，从而让1小时劳动归零，且并发越高，失效越快。**

1. **锚点校验是排他性的（不可并发）：** 
   如历史经验所示，“看错项目ID”会导致进入错误工作空间。如果为了追求“引擎速度”，在未串行确认项目ID（锚点）的情况下，就并发执行后续任务，只会导致**“在错误的工作空间里以极高的效率生成了一堆废数据”**。并发执行不能掩盖决策层的方向性错误。
2. **状态污染与回滚成本指数级放大：** 
   “脑体分离”保证了执行层的无状态性。一旦破坏该架构，让执行层拥有决策权或绕过脑层校验，高并发下的多线程状态交叉污染会导致系统陷入不可知状态。一旦发现锚点错误，回滚的不是单条链路，而是并发散开的N条链路，彻底击穿系统的容错底线。
3. **Timeout机制必须服从于脑体边界：** 
   避坑提醒中提到“根据任务类型预设timeout（B模型300秒，A模型600秒）”。这属于**体层（执行层）的引擎优化**。但如果脑层（决策层）本身因为缺乏串行校验而陷入死循环或错误路由，再合理的timeout也只是“准时宣告失败”，无法挽回已消耗的算力。Timeout只能优化“体”，不能替代“脑”的串行把关。

### 三、3个核心应用场景

#### 场景1：多租户/多工作空间的自动化代码重构
* **痛点：** 极易发生“看错项目ID进入错误工作空间”，导致1小时劳动归零。
* **脑体分离应用：** 
  * **决策串行（脑）：** 系统首先串行执行身份校验 → 解析目标Project ID → 调用API验证工作空间归属权 → **锁定锚点**。此阶段严禁任何并发。
  * **执行并发（体）：** 锚点锁定后，引擎启动。对该工作空间下的100个代码文件进行并发读取、重构分析。根据模型分配Timeout（如B模型turbo分配300秒），如果某文件处理超时，引擎直接熔断该单文件，不影响其他99个文件的并发，更不会动摇已锁定的项目ID锚点。

#### 场景2：海量数据的多Agent清洗与入库
* **痛点：** 数据源地址错误或Schema映射错误时，并发清洗越快，产生的脏数据越多，链路优化全部失效。
* **脑体分离应用：**
  * **决策串行（脑）：** 串行获取数据源Endpoint → 试连接 → 抽样1条数据进行Schema对齐校验 → 确认目标数据库表结构匹配。
  * **执行并发（体）：** 校验通过后，引擎将10万条数据切分为100个分片，100个并发Worker同时拉取并清洗数据。即使某个Worker遇到A模型长文本解析耗时600秒，引擎的并发调度机制也能保证整体任务流不阻塞。若中途发现数据源异常，脑层可一键熔断所有体层并发任务。

#### 场景3：长周期多模型编排与内容生成（如研报生成）
* **痛点：** 大纲方向错误（锚点错误），后续各章节并发生成的内容将全部作废。
* **脑体分离应用：**
  * **决策串行（脑）：** 串行执行：用户意图解析 → 联网搜索锚定核心事实 → 生成大纲 → **人工/二次AI校验大纲逻辑锚点**。
  * **执行并发（体）：** 大纲锚点锁定后，拆分为“行业背景、竞品分析、未来趋势”等独立章节。引擎将这些章节分发给不同模型并发生成（B模型负责简单数据整理配置300秒timeout，A模型负责深度推理配置600秒 timeout）。引擎在此阶段发挥最大并发吞吐能力，但绝对不触碰大纲的修改权。
