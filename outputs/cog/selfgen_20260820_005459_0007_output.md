## 二、重复模式分析

### 模式A：避坑库/坑库直接镜像（6条）

```
C01, C02, C09, C10, C15, C19
```

**特征**：内容与避坑提醒和坑库预警**逐字重复**，属于认知录入时未做密度提升，直接将外部约束存入认知池。

**危害**：占用认知池容量，注入时产生冗余上下文，拖慢推理速度。

---

### 模式B：链路三节点拆散重复存储（5条）

```
C06 ↔ C16（文件变化检测 = 文件哈希检测）
C07（内容寻址去重）  — 独立条目但属同一链路节点
C08 ↔ C17（块级增量同步 = 块级同步减少传输）
```

**特征**：`文件变化检测→内容寻址去重→块级增量同步` 这条已锚定链路被拆成3-5条独立低密认知，每条只描述单节点，缺乏链路级上下文。

**危害**：注入时碎片化，模型需自行拼接链路关系，增加推理开销。

---

### 模式C：V7.5管线描述碎片化（5条）

```
C03, C04, C05, C14, C20
```

**特征**：`多线程API调用 → 结果入队 → 串行后处理` 被拆成5条，其中C05与C14**语义完全相同**（串行后处理避免竞态 vs 多线程结果需串行后处理），C20是管线整体描述与前四条包含关系。

**危害**：同模式B，碎片化注入导致上下文冗余。

---

### 模式D：硬约束声明重复（2条）

```
C12, C13
```

**特征**：硬约束本身是系统级声明，不应作为C级认知存储。两条内容仅为约束声明，无增量信息。

**危害**：约束已在锚定层固化，认知池重复存储无意义。

---

### 模式E：通用运维常识（2条）

```
C11, C18
```

**特征**：队列积压监控、API重试机制属于通用工程常识，密度极低，无领域特异性。

## 三、合并与清理方案

### 方案总览

```
20条C级低密认知 → 合并为6条B级认知 + 清理8条
压缩率: 60%容量释放
```

### 具体操作

| 操作 | 源条目 | 合并后条目 | 目标等级 |
|------|--------|------------|----------|
| **合并** | C01+C02 | `cog-api-timeout-strategy`：API超时按模型分级预设（turbo=300s, A模型=600s），写入调度器默认配置 | B级 |
| **合并** | C06+C07+C08+C16+C17 | `cog-sync-pipeline-v1`：文件同步链路三节点一体化认知（检测→去重→增量），链路级注入而非单节点 | B级 |
| **合并** | C03+C04+C05+C14+C20 | `cog-v75-pipeline-integrated`：V7.5管线为`多线程调用→结果入队→串行后处理`一体化，并发控制+时序保证+竞态避免均为管线固有属性 | B级 |
| **合并** | C09+C10+C15+C19 | `cog-pool-lifecycle`：认知池生命周期管理（每10任务刷新缓存，新认知30分钟内注入，防止静态档案化） | B级 |
| **清理** | C12, C13 | 删除 — 硬约束已在锚定层固化，认知池不再重复存储 | — |
| **清理** | C11, C18 | 删除 — 通用运维常识，无领域特异性，密度不足 | — |

### 合并后认知注入映射

```
任务类型              注入认知
─────────────────────────────────────
API调用类任务    →    cog-api-timeout-strategy
文件同步类任务    →    cog-sync-pipeline-v1
管线调度类任务    →    cog-v75-pipeline-integrated
认知管理类任务    →    cog-pool-lifecycle
```

## 四、防再积压机制建议

```
┌─────────────────────────────────────────────┐
│  认知入池前置检查（写入前）                      │
│                                               │
│  1. 与避坑库/坑库做语义去重                     │
│  2. 与已有认知做链路归属检查（是否可归入已有链路）  │
│  3. 密度评分 < 阈值 → 拒绝入池或升级合并         │
│                                               │
│  触发条件：每次认知写入                          │
│  缓存刷新：每10任务执行一次池内去重扫描           │
└─────────────────────────────────────────────┘
```

**核心原则**：认知池只存**链路级整合认知**和**领域特异性经验**，不存约束声明镜像和通用常识。
