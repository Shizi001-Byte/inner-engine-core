# 任务类型: cog

基于「反者道之动+热力学第二定律」的底层规律，我们首先将决策-执行系统与底层演化规律进行锚定对应，作为后续推演的基础：

### 决策-执行系统与底层规律对应表

| 系统分层 | 对应演化类型 | 核心逻辑 |
| :--- | :--- | :--- |
| **认知记忆层**（认知池/档案库） | **负熵对抗演化** | 孤立系统必自发走向熵增（热寂）。认知池必须作为开放系统，将新认知作为“负熵流”注入任务，打破无序。 |
| **认知调度层**（认知质检与更新） | **反者道之动演化** | 认知无限扩张至极点必走向反面（系统失序/失效）。必须通过反向收敛（剔除/降级）维持动态平衡。 |
| **认知执行层**（API调用/任务流） | **耗散结构演化** | 系统需通过与外界交换物质能量维持有序。必须设定时间边界阻断局部死锁，防止全局能量耗散枯竭。 |

基于以上演化规律，从“认知质检SOP”的角度，总结引擎运行中踩过的坑，提炼出以下3条可复用铁律：

---

### 铁律一：【负熵流强制注入律】（破除认知热寂）
* **历史踩坑**：认知池1700+条但新认知从不注入任务，也不影响调度，变成静态档案库。
* **底层推演**：根据热力学第二定律，若认知池“只进不出”且不与执行系统交互，即退化为孤立系统，必然走向信息熵增与死寂。新认知是系统的高维负熵，必须流动才能对抗无序。
* **铁律描述**：认知质检SOP中不仅要检验“认知是否生成”，更要强制检验“认知是否作为负熵流动”。新认知生成后30分钟内必须参与任务调度注入，每10个任务或每轮转换结束时必须强制刷新认知缓存，拒绝静态只读。
* **验证方法**：
  1. **注入率探针**：在SOP流程末尾注入自动化探针脚本，查询近30分钟内新增的认知条目。
  2. **Trace溯源**：强制检查这些新认知是否携带被执行任务的 `trace_id`。
  3. **熔断判定**：若“新认知注入率 = 0”，判定SOP执行失败，系统自动阻断下一轮任务并触发认知缓存强制刷新。

### 铁律二：【极值反向收敛律】（制衡认知膨胀）
* **历史踩坑**：认知无节制扩张，低质、冗余、过期认知堆积，导致调度引擎被污染，有效认知被淹没。
* **底层推演**：基于“反者道之动”，认知的积累不能是单向的加法。当认知池数量或矛盾冲突积累到极值时，系统效能必然向反面衰败。因此质检SOP必须包含“反向收敛”机制，通过减法来维持系统的低熵与活力。
* **铁律描述**：认知质检SOP必须执行双向校验——既验“产出”，又验“出清”。每10个任务或每轮调度结束，必须执行认知冗余度与冲突度校验，对重复、矛盾、低信噪比的认知执行降级或物理剔除，保持认知池的新陈代谢。
* **验证方法**：
  1. **冗余对冲审计**：每10个任务后触发一次《认知池清洗审计》，对比新增认知与历史库的逻辑一致性。
  2. **阈值判定**：若发现冲突或重复率 > 15%，触发“极值反向收敛”机制。
  3. **出库核销**：强制输出《认知出库清单》，验证系统是否真正执行了删除/降级操作，确保“减法”动作有执行回执。

### 铁律三：【边界阻断熔断律】（切断耗散死锁）
* **历史踩坑**：API调用超时，任务未在规定时间内返回，导致引擎长时间挂起，整体吞吐量瘫痪。
* **底层推演**：根据耗散结构演化规律，系统若在单一节点陷入长时间无输出的停滞，将导致能量与信息的无效耗散，最终引发局部死锁向全局蔓延。必须通过设定绝对的“时间边界”来阻断熵增的无限扩张。
* **铁律描述**：认知质检执行与模型调用环节，严禁无限等待。必须预设合理的耗散边界作为硬性阻断器：B模型turbo预设300秒上限，A模型预设600秒上限。达到边界时间后，无论认知生成质量如何，立即强制熔断，以保全局流转。
* **验证方法**：
  1. **硬超时看门狗**：在质检执行链路植入独立于主线程的看门狗计时器。
  2. **耗时监控**：实时监控API调用耗时，当B模型达到300秒/A模型达到600秒时，看门狗直接切断连接。
  3. **降级回溯**：验证超时熔断后，系统是否记录了“超时熔断日志”，并是否成功切换至兜底策略（如使用历史优质认知或降级模型）以推进下一阶段任务，确保不留死锁线程。
