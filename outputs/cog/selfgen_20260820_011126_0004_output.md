# 任务类型: cog

# 复盘：基建脚本禁用简化版 — 列不匹配教训

---

## 一、认知锚定回顾

| 已有认知 | 与本次复盘的关联 |
|---------|----------------|
| 核心不是"调用次数"而是"认知转化效率" | 简化版省的是编写时间，毁的是调试效率，净效率为负 |
| Hox同源异型基因突变类比 | 简化版删列 = 发育蓝图缺段，表结构"长歪"后数据写入即错配，后续全部链式崩坏 |

---

## 二、根因链拆解

```
简化版SQL（省略部分列 / 跳过迁移步骤）
    │
    ▼
表结构与完整版不一致（列缺失 / 列顺序偏移 / 类型隐式变更）
    │
    ▼
写入时按位置而非按名称映射 → 数据落入错误列
    │
    ▼
下游查询/JOIN依赖原始schema契约 → 列不匹配报错 或 静默错数据
    │
    ▼
排查耗时 >> 简化版省下的编写耗时
```

**关键认知**：简化版破坏的不是"内容"而是"结构契约"。结构契约一旦断裂，就像Hox基因调控顺序错乱——身体各段发育正确但拼接位置全错，整体功能归零。

## 三、检查清单

### 预防层：是否应该创建简化版？

- [ ] **P0-必要性审查**：这个"简化版"解决的是真实瓶颈，还是只是图省事？
  - 省编写时间 < 10分钟 → **直接禁用简化版**
  - 省执行时间但破坏schema → **直接禁用，换批量优化方案**
- [ ] **P0-场景隔离**：简化版是否限定在"一次性销毁的临时环境"？
  - 如果可能流入持久化环境 → **禁止创建**
- [ ] **P1-生命周期声明**：简化版是否标注了销毁时间点？
  - 未标注 → 视为永久存在 → **按完整版要求处理**

### 创建层：如果必须创建，如何守住结构

- [ ] **P0-列定义对齐**：简化版SQL的 `CREATE TABLE` / `ALTER TABLE` 是否与完整版**逐列**对齐？
  - 列名、列序、数据类型、约束四项逐一核对
- [ ] **P0-写入方式审查**：所有 `INSERT` 语句是否使用**显式列名**而非位置映射？
  ```sql
  -- ✅ 安全
  INSERT INTO t (col_a, col_b, col_c) VALUES (1, 2, 3);
  -- ❌ 危险：列序变化时静默错配
  INSERT INTO t VALUES (1, 2, 3);
  ```
- [ ] **P1-迁移步骤保留**：简化版是否跳过了完整版中的 `ALTER TABLE` 迁移？
  - 跳过迁移 = schema版本不一致 → **禁止跳过，可用空迁移占位但不能删**

### 使用层：防止简化版流入错误场景

- [ ] **P0-环境标记**：简化版脚本是否带有环境前缀/后缀标记（如 `_dev_only` `_tmp`）？
- [ ] **P0-执行前置校验**：脚本执行前是否检查目标表当前列结构？
  ```sql
  -- 执行前校验
  SELECT column_name, data_type, ordinal_position
  FROM information_schema.columns
  WHERE table_name = 'target_table'
  ORDER BY ordinal_position;
  -- 与预期schema比对，不匹配则中止
  ```
- [ ] **P1-版本对齐检查**：简化版引用的表结构版本号是否与完整版一致？

### 验证层：检测列不匹配

- [ ] **P0-执行后断言**：脚本执行后是否运行结构断言？
  ```
  ASSERT column_count = expected_count
  ASSERT column_names = expected_names (顺序敏感)
  ASSERT sample_row_values match expected mapping
  ```
- [ ] **P1-下游冒烟测试**：简化版执行后，是否跑了至少一个下游查询验证数据落位正确？
- [ ] **P1-回滚预案**：简化版执行失败时，是否有 `DROP` + 完整版重建的回滚脚本就绪？

## 四、认知注入声明

> **认知条目**：基建脚本禁止简化版 — 简化版省略列定义/迁移步骤会破坏schema结构契约，导致数据按错误列位写入，下游链式报错，调试成本远超编写节省。
>
> **约束规则**：所有基建脚本统一使用完整版schema定义；INSERT必须显式列名；执行前后必须做列结构断言。
>
> **注入时效**：本认知将在30分钟内注入后续任务的schema审查环节。
