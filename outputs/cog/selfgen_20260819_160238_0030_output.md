# 任务类型: cog

## 核心结论：并发自进化必须从“单指标寻优”升级为“多目标约束寻优”，否则必然陷入局部最优

### 一、陷阱复盘：为什么5路并发产出反而低于稳定3路？

| 维度 | 失败表现 | 根因 |
|---|---|---|
| **优化目标** | 只盯“任务失败率” | 失败率下降，但崩溃频率上升，整体有效产出下降 |
| **优化变量** | 盲目上调并发路数 | 并发从3→5，资源争抢加剧，单任务超时、崩溃增多 |
| **评估口径** | 只看“是否完成” | 忽略了“完成质量”“重试成本”“系统稳定性” |
| **自进化机制** | 每轮根据失败率自动调参 | 无多目标约束，无人工干预阈值，陷入局部最优 |

**关键数据示例**：  
- 3路并发：失败率8%，崩溃0次/小时，有效产出≈3路×92%×质量系数  
- 5路并发：失败率降至5%，但崩溃4次/小时，每次恢复耗时2分钟，重试任务额外消耗资源，最终有效产出反而低于3路。

**本质**：优化目标是单维的（失败率），优化变量是显性的（并发数），但代价是隐性的（崩溃、超时、资源碎片化）。系统误以为“失败率低=好”，实际是“用崩溃换失败率”，得不偿失。

---

### 二、提炼的多目标优化认知原则

1. **目标集必须包含“代价类指标”**  
   不能只优化“成功类指标”（如失败率、吞吐量），必须同时约束“代价类指标”（如崩溃频率、平均超时时间、重试开销）。否则系统会“作弊”——用稳定性换成功率。

2. **优化必须带“硬约束”**  
   多目标不是“加权求和”，而是“主目标+红线约束”。例如：  
   - 主目标：有效产出最大化  
   - 硬约束：崩溃频率≤1次/小时，单任务最大耗时≤300秒（B模型）/600秒（A模型）  
   - 任何调参不得突破硬约束，否则回滚。

3. **自进化必须设置“人工护栏”和“回滚机制”**  
   自动调参不能无限探索。当系统发现“并发=5”时崩溃超限，必须自动回滚到最近稳定参数（如3），并记录负面样本，禁止短期内再次尝试。

4. **有效产出才是终极指标**  
   不要用“任务完成率”或“并发路数”衡量系统，要用“有效产出”（完成且质量达标且无副作用）作为唯一终极KPI。失败率只是中间指标，崩溃频率也是中间指标，两者都不等于产出。

5. **认知池必须动态参与决策，不能成为静态档案**  
   本次教训与“认知池只进不出”同源：如果系统不把历史崩溃教训注入当前调度决策，那么每次调参都是“失忆”的，必然重复踩坑。**每10任务或每轮调度结束时，必须将新产生的崩溃/超时/失败教训刷新进认知缓存，并强制在30分钟内参与下一次并发决策**，否则认知池再大也是死数据。

---

### 三、落地措施：把多目标优化嵌入并发自进化

#### 1. 改造评估函数
```
有效产出 = 成功完成任务数 × 平均质量分 - 惩罚项(崩溃次数 × 恢复成本) - 惩罚项(超时任务数 × 超时成本)
```
系统目标改为最大化“有效产出”，而非最小化“失败率”。

#### 2. 增加硬约束检查
每次并发调整前，先检查：
- 预测崩溃率 > 阈值？ → 禁止调高并发
- 近30分钟内是否有崩溃事件？ → 强制回滚到保守参数
- 认知池中是否有类似“5路并发崩溃”的历史？ → 若存在，直接跳过该方案

#### 3. 自进化流程（带多目标护栏）
```
循环：
  1. 读取当前并发参数、近期失败率、崩溃频率、认知池最新教训
  2. 生成候选参数（如并发+1）
  3. 用历史数据和认知池模拟：候选参数是否突破硬约束？
     - 突破 → 丢弃该候选，记录负面教训
     - 未突破 → 小流量试运行（如10个任务）
  4. 试运行后计算有效产出：
     - 有效产出 > 当前 → 保留新参数
     - 有效产出 ≤ 当前 → 回滚，并写认知池：“并发5在崩溃率X时有效产出低于并发3”
  5. 每轮结束强制刷新认知池（去重+注入新教训）
```

#### 4. 明确“身体”与“大脑”边界
- **大脑**：决定“目标是什么”（有效产出最大化）、制定硬约束、判断何时回滚、解释认知教训。这是人类或高层AI的职责，不可交给自动调参器。
- **身体**：自动调参器只能在给定约束下搜索并发数、超时时间等执行层参数，不能更改目标、不能忽略崩溃频率、不能越过护栏。
- **一句话：身体可以更快，但绝不能替大脑思考。** 本次陷阱正是“身体”擅自把并发调到5，而“大脑”没有设定崩溃红线。

---

### 四、认知池与多目标优化的联动规则

| 历史失败经验 | 本次应用 |
|---|---|
| 认知池只进不出 | 每10任务/每轮结束强制刷新，新教训30分钟内必须参与调度决策 |
| API调用超时 | 并发调整时，按模型类型预设超时（B模型300秒，A模型600秒），超时计入崩溃成本 |
| 引擎优化手脚/大脑边界 | 自动调参器不得修改多目标函数和硬约束，只能优化执行参数 |
| 本次教训：局部最优陷阱 | 所有并发候选必须通过“有效产出+崩溃红线”双重检验，否则回滚 |

---

### 五、最终结论

**并发自进化不是“调参游戏”，而是“约束下的多目标搜索”。**  
- 只看失败率 = 局部最优陷阱；  
- 忽略崩溃频率 = 用稳定性换指标；  
- 无认知注入 = 每次踩坑都像第一次；  
- 无人工护栏 = 系统会自己走到悬崖边。  

**只有把“有效产出”作为终极目标，把“崩溃频率”“超时率”作为硬约束，把“认知池”作为实时记忆，把“身体/大脑”边界划清，自进化才能真正持续正向迭代，而不是在局部最优里打转。**
