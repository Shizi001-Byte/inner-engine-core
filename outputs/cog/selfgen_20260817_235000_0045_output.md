# 任务类型: cog

# 基建脚本禁用简化版 · 复盘与检查清单

---

## 一、事件还原

| 维度 | 事实 |
|------|------|
| **触发场景** | 基建部署流程中，存在"完整版"与"简化版"两套SQL脚本 |
| **预期行为** | 简化版已被标记禁用，执行链路应只走完整版 |
| **实际行为** | 简化版仍被某条执行路径引用，DDL中缺失若干列定义 |
| **后果** | 应用层ORM映射与实际表结构列不匹配，运行时字段级异常 |

---

## 二、根因定位（三层穿透）

```
┌─ 表层 ──────────────────────────────────────────────┐
│  简化版SQL未物理清除，仅做了逻辑禁用标记              │
│  → 禁用标记是"文档级"的，不是"执行门控级"的          │
└───────────────────────────────────────────────────┘
         │
┌─ 中层 ──────────────────────────────────────────────┐
│  完整版与简化版之间，从未做过列级diff审计             │
│  → 两个版本的schema drift长期存在，无人知晓差异范围   │
└───────────────────────────────────────────────────┘
         │
┌─ 底层 ──────────────────────────────────────────────┐
│  "简化"这一行为本身缺乏约束协议                       │
│  → 没有定义"什么可以简化、什么绝对不能简化"           │
│  → 列定义属于拓扑结构信息，不可降采样                 │
└───────────────────────────────────────────────────┘
```

> **认知锚定映射**：在"算力代谢"框架下，SQL DDL定义的是信息网络的**底层拓扑结构**。"简化版"本质上是一次**有损降采样**——列定义的缺失等同于拓扑节点丢失，直接导致上层算力流的代谢通路断裂。禁用标记失效，则相当于信息网络中存在**死信通道**——标记已废弃的路径仍被路由激活。

---

## 三、检查清单

### A. 脚本版本管控（5项）

| # | 检查项 | 通过标准 |
|---|--------|----------|
| A1 | 禁用脚本是否已**物理隔离**（移出执行目录/重命名/.disabled后缀） | 执行目录下不存在被禁用脚本的可达路径 |
| A2 | 禁用标记是否在**执行入口**被强制校验（非仅文档/注释层标注） | `if config.DISABLED: raise` 级别的硬门控 |
| A3 | 多版本SQL之间是否已做**列级diff审计**并归档 | 有diff报告，明确差异列清单 |
| A4 | 当前生效版本是否**唯一且可追溯**（版本号/commit hash绑定） | `SELECT version FROM schema_version` 可查 |
| A5 | 全局搜索是否还存在对简化版脚本的**引用残留**（import/路径拼接/CI配置） | `grep -r` 零命中 |

### B. Schema一致性（4项）

| # | 检查项 | 通过标准 |
|---|--------|----------|
| B1 | 应用层ORM模型字段与实际表结构是否有**自动化比对** | CI中有schema diff检查步骤 |
| B2 | DDL是否纳入**迁移工具管理**（Flyway/Liquibase/自定义版本表） | 不存在裸SQL手动执行路径 |
| B3 | 表结构变更是否有**前置评审**（新增列/删除列/类型变更） | 有评审记录，标注影响范围 |
| B4 | 是否存在**schema快照对比机制**（部署前 vs 部署后） | 有before/after结构diff报告 |

### C. 执行链路防护（4项）

| # | 检查项 | 通过标准 |
|---|--------|----------|
| C1 | CI/CD流水线是否有**脚本来源校验**步骤 | 非白名单路径脚本无法执行 |
| C2 | 部署脚本是否有**dry-run模式**（先校验不执行） | dry-run能检测到列缺失 |
| C3 | 应用启动时是否有**表结构预校验**（列存在性/类型匹配） | 启动阶段fail-fast，而非运行时才暴露 |
| C4 | 是否有**回滚DDL预案**（列不匹配时的应急修复） | 预置ALTER TABLE补列脚本 |

### D. 认知协议（3项）

| # | 检查项 | 通过标准 |
|---|--------|----------|
| D1 | "简化"是否经过**正式评审**，而非个人临时决策 | 有评审记录和签字 |
| D2 | 简化版的**简化边界**是否明确定义（可省项 vs 禁省项） | 有文档标注：列定义/约束/索引属于禁省项 |
| D3 | 是否建立了**脚本变更影响半径**评估机制 | 每次变更标注下游影响模块清单 |

## 四、固化措施

```
 简化行为约束协议（三层门控）
 ─────────────────────────────
 
     ┌─── 门控1：物理隔离 ───┐
     │  禁用 → 移出执行目录   │
     │  不可达 = 不可能执行   │
     └──────────┬───────────┘
                │
     ┌──────────▼───────────┐
     │  门控2：diff审计     │
     │  版本间列级比对       │
     │  差异清单归档可查     │
     └──────────┬───────────┘
                │
     ┌──────────▼───────────┐
     │  门控3：启动预校验    │
     │  应用启动时检测表结构  │
     │  列缺失 → fail-fast  │
     └──────────────────────┘
```

> **底层逻辑**：拓扑结构信息（列定义）属于算力代谢的**不可降采样层**。任何"简化"只能作用于数据填充层（初始数据量/测试数据），不能作用于结构定义层。这一边界需要写入团队共识协议，而不仅是技术文档。
