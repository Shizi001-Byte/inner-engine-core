# 任务类型: cog

## 复盘：基建脚本禁用简化版——列不匹配教训

### 一句话复盘

> 简化版 SQL 把“结构契约”交给了“环境默认值”，一旦列集合、列顺序、列定义发生变化，脚本不会报错，业务却会在运行期因列不匹配炸掉。

---

### 根因分析

1. **省略列清单**  
   `INSERT INTO t VALUES (...)` 完全依赖表的当前列顺序。  
   一旦 `ALTER TABLE` 调整了列顺序或新增了列，数据就会错位写入。

2. **依赖隐式建表**  
   简化版 `CREATE TABLE` 不写全列类型、长度、默认值、约束、字符集，不同环境可能生成不同结构，导致“测试环境没问题，生产环境列不匹配”。

3. **使用 `SELECT *`**  
   业务代码按位置取值时，只要表多一列或少一列，结果集结构就变，但脚本不会提前暴露。

4. **缺少结构校验**  
   基建脚本只负责“执行成功”，没有在跑完后对比“预期结构”和“实际结构”，列不匹配被留到运行时才发现。

5. **不幂等**  
   简化脚本重复执行时，可能跳过建表、重复插入、追加重复列，造成环境间结构漂移。

---

## 检查清单

### 一、DDL 建表/改表检查

- [ ] 每张表显式列出所有列，禁止依赖省略后的隐式定义。
- [ ] 每一列必须写全：
  - 列名
  - 数据类型
  - 长度/精度
  - 是否允许 `NULL`
  - 默认值
  - 字符集/排序规则（如适用）
  - 注释
- [ ] 主键、唯一键、普通索引、外键单独且显式声明。
- [ ] 表引擎、默认字符集、自增起始值必须显式声明。
- [ ] 禁止用 `CREATE TABLE AS SELECT` / `LIKE` 隐式继承表结构。
- [ ] `ALTER TABLE ADD COLUMN` 必须写完整列定义，不能只写“加一列”。
- [ ] 禁止用 `CREATE TABLE IF NOT EXISTS` 代替结构校验——表存在不代表列结构正确。

### 二、DML 数据操作检查

- [ ] `INSERT` 必须显式写列清单：
  ```sql
  -- 正确
  INSERT INTO user (name, created_at) VALUES ('alice', NOW());

  -- 错误：禁止
  INSERT INTO user VALUES ('alice', NOW());
  ```
- [ ] 禁止使用裸 `SELECT *`；必须显式列出所需列。
- [ ] `UPDATE` / `DELETE` 必须带 `WHERE`，禁止全表更新/删除。
- [ ] 批量导入数据时，文件列顺序必须与 SQL 显式列清单一致。
- [ ] 日期、字符串、数字、`NULL` 必须按正确类型显式书写，禁止依赖隐式转换。
- [ ] 使用 `ON DUPLICATE KEY UPDATE` 时，显式列出要更新的列。

### 三、执行前/后校验检查

- [ ] 执行前用 `SHOW CREATE TABLE` 或 `DESC table` 导出当前结构。
- [ ] 执行后用 `SHOW CREATE TABLE` 再次导出，与预期结构做 diff。
- [ ] 用 `information_schema.columns` 做程序化断言，对比：
  - 列名集合
  - 列顺序
  - 数据类型
  - 是否可空
  - 默认值
  - 自增/注释等属性
- [ ] 执行最小冒烟数据：`INSERT` 后 `SELECT`，逐列比对返回值。
- [ ] 跑完基建脚本后，再跑一次业务启动自检（ORM 实体映射、DAO 字段检查）。
- [ ] 验证幂等性：同一脚本重复执行两次，第二次结果应与第一次一致，且不产生结构漂移。

### 四、流程与评审检查

- [ ] 代码评审时，凡是出现以下“简化版”特征，一票否决：
  - `INSERT INTO t VALUES (...)` 无列清单
  - `SELECT *`
  - 无 `WHERE` 的 `UPDATE` / `DELETE`
  - `CREATE TABLE` 不写引擎/字符集/列注释
  - 没有执行后结构校验步骤
- [ ] 基建脚本必须进入版本管理，不能用临时手工命令替代。
- [ ] 每个脚本有版本号、变更说明、执行顺序、责任人。
- [ ] 列结构变更必须新增迁移脚本，禁止修改已执行过的脚本。
- [ ] 上线前 `git diff` 检查 SQL 改动，确认没有意外列顺序变化。

---

### 认知沉淀

> **基建脚本不是“能跑就行”，而是“契约定义”。**  
> 所有 SQL 必须显式、完整、可审查、可 diff、可重放。  
> 本次“简化版 SQL 导致列不匹配”的教训，已纳入认知池；后续基建任务中，执行前必须检索该认知并执行上述检查清单。
