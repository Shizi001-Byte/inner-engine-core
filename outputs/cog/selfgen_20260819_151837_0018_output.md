# 任务类型: cog

## 复盘：基建脚本禁用简化版SQL

### 一、教训

简化版SQL在“临时查数、快速验证”时有用，但用在**基建脚本**（建表、迁移、ETL、初始化、数据修复）里，就是埋雷。

核心问题：**简化版SQL把“列契约”藏起来了。**

- 列名不写：靠 `SELECT *` 或 `INSERT INTO t VALUES (...)` 隐式依赖列顺序。
- 列类型不写：靠隐式转换，源表结构一变，目标表列就错位。
- 列数量不写：靠临时表/CTAS自动生成列，源表加一列，目标表跟着变。
- 最危险的是：**SQL还能跑，但数据已经错位、截断、补默认值，下游查不出来，直到线上故障。**

所以结论是：  
**基建脚本必须显式、完整、可对比、可审查。简化版SQL不是省事，是给未来埋坑。**

---

## 二、检查清单

每次写/改基建脚本前，逐条过：

### 1. 列名显式化

- [ ] 禁止 `SELECT *` 出现在基建脚本中，除非是临时探查且明确不会进入数据链路。
- [ ] 所有 `SELECT` 必须显式列出每个字段，并尽量使用别名。
- [ ] 所有 `INSERT` 必须显式指定目标列，例如：
  ```sql
  INSERT INTO target_table (col1, col2, col3)
  SELECT source_col1, source_col2, source_col3 FROM source_table;
  ```

### 2. INSERT 语法防呆

- [ ] 禁止使用 `INSERT INTO t VALUES (...)` 这种不指定列的写法。
- [ ] 如果必须用 `VALUES`，必须写成：
  ```sql
  INSERT INTO t (a, b, c) VALUES (1, 2, 3);
  ```
- [ ] 多行插入时，确保每行字段数量和顺序完全一致。

### 3. 表结构变更后必须重新校验

- [ ] 任何源表、目标表结构变更后，必须重新跑一遍所有引用它们的基建SQL。
- [ ] 使用 `DESCRIBE table;` 或 `SHOW COLUMNS FROM table;` 查看真实列结构。
- [ ] 对比源表和目标表的列名、列顺序、数据类型、长度、精度、是否可空。

### 4. 禁止依赖自然列顺序

- [ ] 不假设“现在表里第3列就是xxx”。
- [ ] 不依赖 `SELECT *` 产生的列顺序来灌入目标表。
- [ ] 建临时表、中间表时，显式声明列名和列类型，禁止直接用 `CREATE TABLE tmp AS SELECT * ...`。

### 5. UNION / JOIN / 集合操作类型一致

- [ ] `UNION` / `UNION ALL` 两侧的列数必须一致。
- [ ] 两侧对应列的类型必须兼容，尽量相同，避免隐式转换。
- [ ] `JOIN` 的关联字段类型必须显式核对，防止 char/varchar、int/bigint 隐式转换导致索引失效或数据错位。

### 6. 类型与长度显式声明

- [ ] 建表/临时表时，每个字段都要显式写类型，禁止全部省略靠默认。
- [ ] 字符字段必须明确长度，禁止无长度 `VARCHAR` 依赖数据库默认。
- [ ] 数值字段明确精度，尤其是金额、比率字段，防止小数位截断。

### 7. Schema 版本化管理

- [ ] 所有建表/改表脚本纳入版本管理，禁止只改线上库不留脚本。
- [ ] 每次变更前，用 `git diff` 对比旧脚本和新脚本。
- [ ] 上线前跑一次 `schema diff`，确认只有计划中的变更。

### 8. 上线前必须做数据校验

- [ ] 先跑 `dry run`，不实际写入，只验证SQL能执行、列匹配。
- [ ] 用样本数据做前后对比，核对目标表数据与源表是否一致。
- [ ] 检查空值率、行数、去重数、关键字段汇总值，防止“SQL能跑但数据错”。

### 9. CI/自动化防线

- [ ] 基建SQL纳入CI检查，至少包含：SQL语法校验、列名解析、表结构diff。
- [ ] 对核心脚本添加“列映射测试”：源表列名到目标表列名的映射关系硬编码在测试用例中。
- [ ] 每次表结构变更自动触发所有依赖该表的脚本测试。

### 10. 注释与文档同步

- [ ] 每个基建脚本顶部写清楚：用途、依赖的表、预期的列映射。
- [ ] 字段变更后，同步更新数据字典或映射文档。
- [ ] 禁止“先改代码后补文档”，文档和脚本必须同 PR 提交。

---

## 三、一句话总结

> **基建脚本里，SQL的每一列都必须是白纸黑字写出来的契约，而不是让数据库猜的潜规则。**

这条认知已注入认知池，后续所有基建任务强制套用该检查清单，并纳入代码审查和CI检查。
