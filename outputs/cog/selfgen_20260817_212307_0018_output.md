# 任务类型: cog

针对“基建脚本禁用简化版”导致SQL列不匹配的事故，我们需要从认知层面进行深度复盘，并沉淀为可落地的操作规范。以下是复盘总结与检查清单：

### 一、 事件回溯与认知反思

**1. 事故核心原因：**
在编写“禁用某基建功能”的简化版脚本时，为了图快或减少代码量，使用了类似 `INSERT INTO table_name VALUES (...)` 的隐式列写入，或者更新/查询时未严格对齐目标表的最新表结构。导致SQL在执行时，传入的值与实际列的顺序、数量或类型不匹配，引发数据错乱或执行报错。

**2. 认知误区剖析：**
*   **误区一：“简化版”等于“省略列名”**。真正的脚本简化应当是**逻辑上的精简**（如减少不必要的关联、缩短流程），而不是**语法上的偷懒**（如省略列名依赖数据库默认顺序）。数据库表结构是会动态演进的，隐式依赖极度脆弱。
*   **误区二：基建脚本要求低**。基建脚本往往涉及底层配置、元数据或开关。越是底层的脚本，一旦出错（如列错位导致配置写反），爆炸半径越大，越需要最严格的规范。
*   **误区三：依赖测试环境表结构**。如果简化版脚本是在测试环境基于某版本表结构编写的，直接拿到生产环境执行，一旦生产环境有未同步的DDL（如新增了字段），列匹配必将彻底崩溃。

**3. 核心教训：**
**“简化逻辑，绝不简化约束”**。任何面向生产环境的SQL，尤其是基建脚本，必须具备“防御式编程”思维，显式声明所有的列名与映射关系，消除对表结构隐式顺序的依赖。

---

### 二、 基建脚本SQL编写与执行检查清单

为了避免此类问题再次发生，请在编写和执行任何基建SQL脚本前，严格走查以下清单：

#### 阶段一：编写前准备
- [ ] **1. 确认目标表结构**：是否已获取生产环境目标表的最新 DDL（`SHOW CREATE TABLE`）？
- [ ] **2. 确认环境一致性**：测试环境的表结构是否与生产环境完全一致（含字段顺序、默认值、约束）？
- [ ] **3. 识别关键字段**：是否清楚该表哪些字段是必填（NOT NULL）、哪些是主键、哪些有唯一约束？

#### 阶段二：SQL编写规范
- [ ] **4. 显式声明列名**：所有的 `INSERT` 语句是否严格采用了 `INSERT INTO table_name (col1, col2) VALUES (val1, val2)` 格式？（**严禁**使用无列名的 `INSERT INTO table_name VALUES (...)`）
- [ ] **5. 列与值一一对应**：是否通过换行或对齐格式，肉眼校验了列名列表与 `VALUES` 列表的参数数量、顺序完全一致？
- [ ] **6. 避免 `SELECT *` 用于写入**：在 `INSERT INTO ... SELECT ...` 语句中，是否显式写明了查询的列名，且与 `INSERT` 的列名完全对应？（**严禁** `INSERT INTO t1 SELECT * FROM t2`）
- [ ] **7. 数据类型匹配**：写入的值类型是否与目标列类型兼容？（如将字符串写入 `INT`，或超长字符串写入 `VARCHAR`）
- [ ] **8. 默认值与非空校验**：如果简化版脚本未包含所有字段，被省略的字段是否都有安全的 `DEFAULT` 值，或者允许为 `NULL`？是否会触发 `NOT NULL` 约束报错？

#### 阶段三：执行前校验
- [ ] **9. Explain 验证**：是否对脚本执行了 `EXPLAIN` 或语法检查，确保没有低级语法错误？
- [ ] **10. 事务保护**：脚本是否包裹在事务中（`BEGIN; ... COMMIT; / ROLLBACK;`），以便在列不匹配报错时能安全回滚？
- [ ] **11. Dry-Run（试跑）**：在正式执行前，是否在准生产环境/UAT环境使用真实脱敏数据试跑过？
- [ ] **12. 影响行数预判**：是否已知该脚本预期会影响多少行数据？如果执行后影响行数不符，是否有机制立即拦截？

#### 阶段四：执行后验证
- [ ] **13. 结果抽样核对**：执行后是否抽查了前N条数据，确认各列的值确实落在了正确的列里（如：`status`列的值确实是数字/状态码，而不是跑到了`name`列）？
- [ ] **14. 业务联调**：是否通知了依赖该基建配置的下游业务进行快速验证？

### 三、 团队规范建议

将以下规则加入团队的 SQL Code Review 清单中：
1. **SQL Lint 接入**：在 CI/CD 流程中接入 SQL 静态扫描工具（如 Soar、SQLFluff），强制拦截未显式指定列名的 `INSERT` 和 `UPDATE` 语句。
2. **“简化版”脚本定义重审**：明确团队内“简化版脚本”的定义。简化版允许：减少业务日志输出、减少非核心状态更新、使用更高效的过滤条件；**绝不允许**：省略表名别名、省略字段列表、省略事务控制。
