# 任务类型: cog

基于“同步单位是 block，不是 file；文件只是有序 block id 列表的索引”这一锚点，以下不重复论证，直接把历史坑位转成认知质检 SOP 的三条门禁。

### 铁律一：质检粒度必须是 block，不是 file；file 级结论必须能下钻到 block diff。

- 落地：同步、差异分析、回滚判定，一律以 block id 列表为最小核对单位。文件只是索引，文件存在、大小、mtime 甚至文件整体 hash，都不能替代 block 级校验。
- 验证方法：
  1. 构造“同 file 名、同大小、同 mtime，但 block id 顺序不同”的样本，跑 SOP，必须判为不同步。
  2. 修改一个 block 的内容/ID，运行同步，断言传输日志只出现该 block，而不是整个 file 全量重传。
  3. 质检报告必须输出 block-level diff；如果报告只有 file 级状态，视为质检不合格。

---

### 铁律二：认知池必须“进且用”；只沉淀不消费 = 没沉淀。

- 落地：每 10 个任务或每轮结束，强制刷新认知缓存；新认知必须在 30 分钟内进入注入候选，并实际参与后续任务，不允许变成静态档案库。
- 验证方法：
  1. 注入一条带唯一 marker 的新认知，连续执行 10 个任务；断言第 10 个任务后触发刷新，第 11 个任务的注入候选/上下文中出现该 marker。
  2. 监控 `认知新鲜度 = 当前时间 - 最近一次认知刷新时间`，超过 30 分钟必须告警。
  3. 统计 `认知消费率 = 新认知实际被引用的任务数 / 新认知应参与的任务数`，低于阈值时阻断发布。

---

### 铁律三：外部模型调用必须设分级超时，超时后的动作必须可观测；无限等待是最严重的质检事故。

- 落地：B 模型 turbo 超时上限 300 秒，A 模型超时上限 600 秒；调用前先算任务剩余 deadline，实际超时取 `min(模型分级上限, 剩余 deadline)`。超时后走明确的重试/降级/熔断，并记录阶段日志。
- 验证方法：
  1. 故障演练：mock B 模型延迟 301 秒、A 模型延迟 601 秒返回，断言任务在 deadline 前返回失败/降级，不挂起。
  2. 检查调用链日志：超时记录必须包含调用阶段、已等待时间、触发动作（retry/degrade/circuit_break）。
  3. 压测指标：`任务超时率 = 0`，且每次超时都有对应 fallback trace。

这三条作为认知质检 SOP 的固定检查项，每次引擎变更或发布前必须过一遍。
