# 任务类型: cog

基于两条锚定推演：

> 引擎优化可以优化“执行”和“同步”，但不能优化掉“决策事件”和“全局顺序”  
> 协作网络不是从“连接”开始的，而是从“可检索的差异”开始的

所以核心结论是：**脑体分离架构的边界，就是“决策事件/全局顺序”与“执行/同步”的边界。**  
优化后者是提效，优化前者是破坏协作系统的语义基础。

---

## 一、分层原则

### 1. 决策层（脑）：串行、事件化、全局有序

- 所有决策必须产生“决策事件”；
- 同一决策域内，决策事件必须严格串行，有全局顺序；
- 决策事件不能被合并、删除、覆盖或重排；
- 串行是逻辑约束，不是性能瓶颈；可通过分片/分区扩展，但每个分片内部仍保持串行。

### 2. 执行层（体）：并发、可优化、可失败

- 决策事件产生后，执行层可以并发执行；
- 无依赖的副作用：API 调用、数据写入、消息通知、工具执行，都可以并行；
- 执行层可以重试、超时、缓存、批量、异步；
- 执行层的优化不能反过来改变决策层的事件顺序。

### 3. 同步层：异步、增量、按事件顺序对齐

- 执行结果可以异步同步；
- 同步可以增量、压缩、批量；
- 但最终合并必须按决策事件的全局顺序进行，不能跳跃；
- 节点之间先比较“事件游标/版本差异”，再补差，而不是盲目直连。

---

## 二、为什么引擎优化不能破坏脑体分离架构？

### 1. 决策事件是“可检索差异”的锚点

协作网络不是从连接开始的，而是从“可检索的差异”开始的。

两个节点要协作，首先要知道：

- 你比我多哪些决策事件？
- 我比你多哪些决策事件？
- 我们之间的差异是什么？

如果引擎优化把决策事件合并、删除或覆盖掉，节点之间就失去可检索差异，只能靠“连接”硬同步，最终会丢失语义，也无法收敛。

### 2. 全局顺序是“脑”的单一事实来源

决策事件必须有一个全局顺序，这是大脑判断因果关系的依据。

执行层可以并发跑，但最终状态必须按照决策顺序归并。  
如果引擎优化为了性能，重排、跳跃、省略决策事件，那么各执行体看到的因果顺序就会不一致，系统状态无法收敛。

### 3. 执行并发是“体”的性能来源，但必须受“脑”控制

性能来自哪里？来自执行层并发：

- 多个工具同时调用；
- 多个 API 同时请求；
- 多个副本同时计算。

但如果把“决策事件”也优化掉，让执行体自己决定顺序，那就是把大脑功能下放给身体，系统会变成“各行其是”的并发混乱体。

所以：

- 决策必须串行，因为要保证一致性；
- 执行可以并发，因为要榨取性能；
- 引擎优化只能优化“手脚”，不能优化掉“大脑的判断记录”。

## 三、3 个应用场景

### 场景 1：多人实时协同编辑

#### 脑体分离

- 决策层：每个用户操作产生一个全局有序的编辑事件；
- 执行层：各副本并发应用这些事件，渲染到本地；
- 同步层：增量同步缺失的事件。

#### 可优化

- 广播协议优化；
- diff 计算优化；
- 本地渲染优化；
- 事件压缩、批量同步。

#### 不可优化

- 不能合并或删除用户的每个操作事件；
- 不能改变操作到达的全局顺序；
- 否则 undo/redo、历史回溯、冲突解决全部失效。

> 两个编辑器副本同步时，不是先建立连接再盲目同步，而是先比较事件版本差，再拉取缺失的编辑事件。

---

### 场景 2：订单 / 交易状态机

#### 脑体分离

- 决策层：订单状态变更串行发生：创建 → 支付 → 发货 → 完成；
- 执行层：扣库存、调支付、开票、发通知并发执行；
- 同步层：各系统通过事件流对账。

#### 可优化

- 外部 API 调用并发化；
- 超时与重试策略优化；
- 幂等机制优化；
- 异步通知、批量对账。

#### 不可优化

- 不能把“支付成功”和“发货”合并成一个事件；
- 不能让扣库存先于支付决策发生；
- 不能删除状态变更事件来换取性能。

> 订单、库存、支付系统之间不是靠直连“商量”出结果，而是靠事件流中的可检索差异对齐状态。

---

### 场景 3：多智能体 / 工作流编排

#### 脑体分离

- 决策层：Planner / LLM 串行产生决策事件，例如：
  - 下一步行动；
  - 选择哪个工具；
  - 任务如何分解。
- 执行层：多个工具调用、检索、计算并发执行；
- 同步层：把执行结果异步带回决策层。

#### 可优化

- 工具调用并发执行；
- 结果缓存；
- 上下文压缩；
- API 调用超时设置：
  - B 系列 turbo 模型可设 300 秒；
  - A 系列模型可设 600 秒；
- 重试与降级策略。

#### 不可优化

- 不能省掉“决策事件”本身；
- 不能用最终答案覆盖所有中间决策轨迹；
- 不能改变决策事件的先后顺序。

> 多智能体的协作上下文来自“决策事件轨迹”。删除这些轨迹，协作网络就只剩连接，没有可检索差异；后续智能体无法复盘、纠错、评估，也无法对齐各自进度。

---

## 四、一句话总结

> **引擎优化可以优化“执行”和“同步”，但不能优化掉“决策事件”和“全局顺序”。**  
> 因为决策事件是协作网络的“可检索差异”，全局顺序是大脑的“单一事实来源”。  
> 脑体分离不是性能负担，而是让系统既快又一致的架构边界。
