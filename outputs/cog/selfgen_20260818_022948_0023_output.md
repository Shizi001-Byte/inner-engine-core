# 任务类型: cog

# 复盘：基建脚本简化版 → 列不匹配

## 事件本质

简化版SQL为追求"可读性/快速验证"，省略了部分列定义、类型修饰或约束，导致与正式版Schema产生**静默漂移**。漂移不在创建时报错，而在写入或下游消费时以"列不匹配"形态显形——错误被延后放大。

核心根因：**简化版绕过了与正式版的同构性约束**，把它当作"等价缩写"，而非"需要校验的独立产物"。

---

## 检查清单（四层）

### 一、准入层——简化版是否该存在

- [ ] 简化版的使用场景是否已明确界定（仅本地验证 / 仅只读查询）
- [ ] 简化版与正式版的**差异清单**是否已枚举并记录在案
- [ ] 简化版是否标注 `deprecated` 且禁止进入CI/CD流水线
- [ ] 是否存在"简化版只能由正式版自动裁剪生成、禁止手写"的约束

### 二、结构对齐层——列与类型

- [ ] 全量列名逐一比对（`DESC` 或 `INFORMATION_SCHEMA.COLUMNS`）
- [ ] 数据类型与长度对齐（`VARCHAR(N)`、`DECIMAL(M,D)` 不可省略参数）
- [ ] `NULL` / `NOT NULL` 约束一致
- [ ] 默认值、`AUTO_INCREMENT`、`ON UPDATE` 行为一致
- [ ] 字符集与排序规则（`CHARSET` / `COLLATE`）一致
- [ ] 主键、唯一键、外键、索引完整保留
- [ ] 注释 `COMMENT` 是否保留（下游文档依赖）

### 三、执行校验层——写入前拦截

- [ ] 执行前对目标库做 Schema 快照
- [ ] 执行后做 `diff`，任何列级变更必须显式确认
- [ ] 首条写入数据做**列回写校验**（写入字段数 == 预期字段数）
- [ ] 下游消费端（DAO / Mapper / ETL）冒烟测试通过
- [ ] 简化版脚本的 `git blame` 路径纳入lint规则

### 四、治理层——防止复活

- [ ] 仓库内 `grep` 简化版脚本文件名，确认无残留引用
- [ ] 简化版文件名加 `_deprecated_` 前缀或迁移至 `archive/` 目录
- [ ] 新人 onboarding 文档注明"简化版已禁用，原因：列漂移"
- [ ] 建立一条规则：**任何SQL脚本变更，必须附正式版Schema的diff作为附件**

---

## 升维一句话

简化版的代价不是"少了几个字段"，而是**把结构同构性的责任从机器校验转移到了人脑记忆**——而人脑在这个维度上不可靠。禁用简化版，本质是关闭这条不可靠通道。
