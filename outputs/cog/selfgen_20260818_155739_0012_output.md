# 任务类型: cog

## 一、分层原则：决策串行，执行并发

1. **决策层（脑）必须串行**  
   所有全局目标、路径选择、状态变更、冲突仲裁，都收敛到同一个决策上下文。决策不是“慢”，而是保持全局一致性的唯一写入点。任何并发决策都会制造多大脑，导致系统内部互相否定。

2. **执行层（体）必须并发**  
   所有不依赖决策上下文的动作——工具调用、数据读取、计算任务、物理操作——都拆成可并行任务，由执行引擎调度。执行体只负责“做”，不负责“选”。

3. **脑体之间只传递意图与结果**  
   决策层下发命令/目标，执行层回传状态/结果/异常。执行层不能反向修改决策目标，决策层不直接干预执行细节。控制流是单向的：脑 → 体；数据流是双向的：体 → 脑。

4. **引擎优化只能优化“体”，不能改造“脑”**  
   引擎优化可以做并发调度、缓存复用、批处理、资源弹性、算子加速，但必须保持“脑体分离”的拓扑不变。优化一旦让执行体获得自主决策权，就是把执行引擎从“手”升级成了“另一个脑”。

---

## 二、为什么引擎优化不能破坏脑体分离架构

脑体分离的本质是：**控制流单点收敛，数据流扇出扇入**。

引擎优化的目标是让“体”更快、更省、更稳，而不是让“体”更聪明。一旦优化破坏了脑体分离，会出现：

- **隐性多头决策**：执行层为了性能，开始本地判断、跳过步骤、自行排序，导致决策层拿到的是被扭曲后的结果。
- **闭环熵增**：闭环不是“建好就自转”，而是必须持续对抗熵增的结构。执行体自作主张，就是向系统注入不可控分支，使全局状态分裂。
- **控制流与数据流脱缰**：本应是宇宙级扩展的控制流/数据流，会退化成无数局部小闭环，最终无法被全局追踪和裁决。

所以，引擎优化必须遵守一个铁律：  
**可以优化“执行”的速度和效率，不能优化掉“决策”的必经之路。**

## 三、3个应用场景

### 场景 1：AI Agent 编排系统

- **脑**：中央 Planner，负责拆解任务、决定下一步动作、判断工具结果。
- **体**：多个 Worker Agent，并发执行搜索、读文件、写代码、调 API。
- **引擎优化**：对 Worker 做并发调度、工具调用批处理、结果缓存、超时重试。
- **不能破坏的点**：不能让 Worker 根据本地启发式规则“自动跳过”某个任务，也不能让 Worker 自行决定“这个结果不重要不回报”。所有结果必须回流到脑，由脑决定是否采纳。否则 Agent 会在没有全局视野的情况下做出局部最优，最终偏离用户目标。

### 场景 2：分布式数据管线的控制面/数据面

- **脑**：中心调度器，负责 DAG 编排、数据质量规则、表结构变更、重试策略。
- **体**：Spark/Flink 等执行引擎，并发处理海量数据分片。
- **引擎优化**：动态资源伸缩、数据本地性调度、向量化计算、谓词下推。
- **不能破坏的点**：不能因为优化谓词下推，就让执行节点在数据校验前直接过滤数据。数据质量规则是脑的决策，执行体只能执行过滤逻辑，不能决定“这条规则这次可以忽略”。否则金融、医疗等场景下，数据错误会在执行层被悄悄吞掉。

### 场景 3：机器人/自动驾驶的中央决策与底层控制

- **脑**：全局规划器，负责导航目标、行为决策、交通规则判断。
- **体**：底盘控制、电机驱动、传感器融合、局部避障等高频执行单元。
- **引擎优化**：提高控制频率、优化传感器数据融合延迟、调整执行器 PID 参数。
- **不能破坏的点**：底层避障模块可以做“快速反射”，但它的反射阈值和方向优先级必须由中央决策层设定。引擎优化不能让底层控制器在未上报的情况下，永久改变全局路径。例如无人机蜂群中，单机避障可以快速绕开障碍，但绕开后的行为必须回到中央编队决策，否则整个蜂群会因局部自主而解体。
