# 任务类型: cog

基于链式推演引擎，对 **“基建脚本禁用简化版”** 做复盘，输出检查清单。

## 复盘推演

- **R1 现象**：基建脚本中使用了“简化版 SQL”，执行后出现列不匹配。
- **R2 根因**：简化版依赖隐式规则，例如省略列名、依赖目标表列顺序、使用 `SELECT *`、不写 schema 前缀、混用方言函数，导致环境切换后列顺序/类型/数量错位。
- **R3 边界**：基建脚本不是临时查询，不能为了“短”牺牲“确定性”。所有列名、列序、类型、环境引用必须显式声明。
- **R4 输出**：以下检查清单。
- **R5 验证**：在 staging 环境用完整版 SQL 跑通，并做行数、checksum、抽样校验；失败则沿回退边回退，不整链重来。

## 基建脚本 SQL 检查清单

### 1. 列名显式性

- [ ] 禁止使用 `SELECT *`，必须显式列出所需列名。
- [ ] `INSERT INTO` 必须写列清单，禁止 `INSERT INTO t VALUES (...)`。
- [ ] `UPDATE` 的 `SET` 必须逐列写明，禁止依赖列顺序。
- [ ] 多表查询时，所有列名前加表别名或表名，避免歧义。

### 2. 列序与数量

- [ ] `INSERT` 的列名顺序必须与 `VALUES` 一一对应。
- [ ] `UNION` / `UNION ALL` 两侧列数、列序、列类型必须一致。
- [ ] 禁止使用 `ORDER BY 1`、`ORDER BY 2` 这种位置排序，必须按列名排序。
- [ ] 如果脚本从旧表迁移到新表，逐列 diff 新旧表列顺序，不能假设一致。

### 3. 数据类型与转换

- [ ] 同名字段在源和目标中的类型必须兼容。
- [ ] 需要转换时使用显式 `CAST` / `CONVERT`，禁止依赖隐式转换。
- [ ] 时间字段要明确时区，`DATETIME` / `TIMESTAMP` 不能混用。
- [ ] 注意 `NULL` 与空字符串 `''` 的差异，核对目标表的 `NOT NULL`、默认值约束。

### 4. 方言与版本

- [ ] 函数写法必须匹配目标数据库方言，例如 `IFNULL` / `NVL` / `COALESCE` 不能混用。
- [ ] 分页语法必须匹配版本，例如 `LIMIT` / `OFFSET` / `FETCH FIRST`。
- [ ] 关键字和保留字要加正确引号，大小写规则与目标库一致。
- [ ] 禁止使用“在某一个环境能跑通”的简化写法，必须按目标库规范写完整版。

### 5. 环境与配置

- [ ] 表名、库名、schema、连接串必须从配置注册中心读取，禁止硬编码。
- [ ] 脚本执行前确认当前连接指向正确的环境，避免 dev 脚本跑到 prod。
- [ ] 检查目标表 schema 是否与脚本假设一致，先执行 `DESCRIBE` / `information_schema` 核对。

### 6. 执行验证

- [ ] 正式执行前先做 `EXPLAIN` 或 dry run，确认 SQL 解析正常。
- [ ] 执行后检查影响行数是否在预期范围。
- [ ] 对关键列做 checksum 或抽样对比，确认数据没有静默写错列。
- [ ] 自动化执行时设置合理超时：B 模型 turbo 用 300 秒，A 模型用 600 秒，避免 API 调用卡死。

### 7. 回退与认知刷新

- [ ] 基建脚本必须放在事务中执行，或提前准备备份/补偿脚本。
- [ ] 一旦发现列不匹配，立即停止后续步骤，回退到最近一致点，不要整链重跑。
- [ ] 复盘结论和检查清单注入认知池，并在下一个基建脚本评审任务中主动使用，避免“只进不出”。

---

## 最终规则

**基建脚本中的 SQL 只用完整显式版。**  
任何形式的“简化版”——省略列名、依赖列顺序、使用 `SELECT *`、不写 schema、混用方言——在评审阶段一律一票否决。
