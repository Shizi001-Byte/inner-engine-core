# 任务类型: cog

# 基建脚本禁用简化版 · 认知复盘

## 一、事故还原

```sql
-- 简化版（问题根源）
INSERT INTO t_dao_node (node_id, node_name) VALUES (?, ?);

-- 完整版（正确）
INSERT INTO t_dao_node 
  (node_id, node_name, realm_type, qi_field, meridian_status, 
   tribulation_threshold, soul_bind_flag, created_ts, updated_ts) 
VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?);
```

**核心病灶**：简化版只覆盖了2列，实际表结构9列。其余7列中：
- 3列 `NOT NULL` 无默认值 → 直接报错
- 2列虽有默认值，但业务语义依赖显式传入 → 数据污染
- 2列 `updated_ts` 类时间戳默认 `CURRENT_TIMESTAMP` → 逻辑不自洽

---

## 二、认知升维

> 在算力代谢的生态中，SQL的列即是**灵脉节点**。简化版等于只激活了主脉，旁脉枯竭——整个修仙架构的灵力循环就会塌陷。

**根因不是"写了简化版"，而是允许简化版存在于基建路径中。**

```
完整版 = 完整灵脉图
简化版 = 残缺功法
残缺功法一旦流入基建 → 走火入魔（列不匹配）是必然，不出事才是偶然
```

---

## 三、检查清单

### ✅ 阶段一：脚本准入检查

| 序号 | 检查项 | 方法 | 不通过处置 |
|------|--------|------|------------|
| 1 | DDL与DML列数一致性 | `DESCRIBE` 结果 vs INSERT列名 | 禁止合入 |
| 2 | NOT NULL列全覆盖 | 查 `information_schema.columns` where `IS_NULLABLE='NO'` AND `COLUMN_DEFAULT IS NULL` | 补全或脚本驳回 |
| 3 | 业务语义列覆盖 | 核对领域模型字段映射表 | 补全 |
| 4 | 时间戳列显式传入 | `created_ts`/`updated_ts` 必须出现在VALUES中 | 补全 |

### ✅ 阶段二：CI/CD 门禁

```yaml
# 伪代码 - 列匹配守卫
guard_column_match:
  steps:
    - name: 提取DDL列定义
      run: |
        COLUMNS=$(psql -c "\d t_dao_node" | awk 'NR>3{print $1}')
    - name: 解析DML INSERT列
      run: |
        INSERT_COLS=$(grep -oP '(?<=\().*(?=\))' insert_script.sql | tr ',' '\n')
    - name: 差集断言
      run: |
        DIFF=$(comm -23 <(echo "$COLUMNS"|sort) <(echo "$INSERT_COLS"|sort))
        if [ -n "$DIFF" ]; then
          echo "列缺失: $DIFF"
          exit 1
        fi
```

### ✅ 阶段三：运行时熔断

| 序号 | 检查项 | 触发条件 | 动作 |
|------|--------|----------|------|
| 5 | 执行后行结构校验 | INSERT后 `SELECT * LIMIT 1`，比对列数 | 不一致则ROLLBACK |
| 6 | 默认值漂移检测 | 执行前后 `information_schema.columns.COLUMN_DEFAULT` diff | 告警+人工介入 |
| 7 | 灵脉完整性扫描 | 定时全表扫描NULL率，NOT NULL列NULL率>0即告警 | 自动建工单 |


## 五、一句话总结

> **简化版不是"简"，是"残"。残缺的功法不该出现在筑基的阵法里——列不匹配只是表象，根因是允许残缺逻辑进入了需要完整性的路径。**
