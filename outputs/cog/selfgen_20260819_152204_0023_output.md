# 任务类型: cog

## 复盘结论：这是“以虚代实”的局部最优陷阱

引擎把“失败率”当作唯一优化目标，忽略“崩溃频率”，导致：

- 并发从 3 调到 5 后，单请求失败率可能被重试、排队、负载均衡掩盖，表面“好看”；
- 但系统崩溃频率上升，崩溃会清空队列、中断任务、触发雪崩重试；
- 最终端到端产出：**5路并发 < 稳定3路并发**。

本质是：  
**失败率是“虚”，有效产出是“实”。**  
5路在“失败率”维度上是局部最优，3路在“有效产出”维度上是全局最优。

---

## 核心公式

```
有效产出 = 完成任务数 × 正确率 × 可用性权重 - 崩溃损失

崩溃损失 = 崩溃次数 × 平均恢复成本 + 重试放大系数
```

所以调并发不能看：

```
argmin 失败率
```

而要看：

```
argmax 有效产出
```

## 多目标优化的认知原则

### 1. 单一指标必然导致局部最优
任何只看“失败率”“吞吐”“延迟”的单指标优化，都是在一条一维线上爬山。  
爬山到顶，也只是局部山顶。  
真正的目标不是让某个指标最小，而是让“系统整体健康度”最优。

### 2. 失败率与崩溃频率是两个维度，不能互相替代
- 失败率反映的是“单请求质量”；
- 崩溃频率反映的是“系统稳定性”；
- 单请求失败率低，不代表系统稳定；  
  5路并发下，每个请求都“试错成功”，但整体系统随时可能崩溃。

### 3. 调参信号应使用“边际产出”，而不是指标绝对值
并发从 3→4→5，每一步都要问：

> 总产出增加了多少？  
> 崩溃风险增加了多少？  
> 如果产出增量小于风险增量，就回退。

不要因为失败率下降就继续加并发。

### 4. 设置崩溃预算与熔断线
- 崩溃频率 > 0 时，禁止继续加并发；
- 连续崩溃 2-3 次，强制降级到保守水位；
- 崩溃比失败更贵，因为崩溃会一次性抹掉整批任务。

### 5. 反向验证：主动打破局部最优
周期性故意降低并发，测试产出是否反而上升。  
这是“反者道之动”的实践：  
- 当 5 路看起来“最优”时，主动试 3 路；  
- 当失败率看起来“健康”时，主动制造压力测试；  
- 用真实消耗换取“崩溃频率”的认知，而不是省 token。

### 6. 虚实自增强闭环：真实产出反哺认知池
- “失败率”是虚指标，“有效产出”是实结果；
- 每次调参后，必须用真实任务校验产出；
- 将“5路失败率低但产出低”的反例写入认知池；
- 每 10 个任务或每轮调度结束，刷新认知缓存；
- 新认知必须在 30 分钟内参与注入，否则认知池变成静态档案库。

### 7. 最省资源的方案，往往不是最高产出的方案
3路看似保守，但因为不崩溃，反而产出更高；  
5路看似激进，却因崩溃耗散，实际产出更低。  
所以优化目标不是“省”，而是“稳中高产”。

## 落地策略清单

1. 建立“双仪表盘”：
   - 速度表：失败率、延迟；
   - 温度表：崩溃频率、恢复时间、重试风暴指数。
   - 温度表报警时，速度表再好看也必须降速。

2. 使用“健康度”作为统一调度指标：

```
健康度 = w1 × 完成率 + w2 × 可用性 - w3 × 崩溃损失率
```

3. 并发调整必须梯度试探：
   - 3→4 观察 10 个完整任务；
   - 4→5 观察 10 个完整任务；
   - 每一步比较“有效产出”，而不是失败率。

4. 超时配置与并发联动：
   - B 模型 turbo 用 300 秒，A 模型用 600 秒；
   - 并发升高时，缩短全局快速失败时间，避免重试堆积；
   - 崩溃发生后，立即熔断，而不是继续重试。

5. 写入认知池的反例模板：

```
场景：并发5路，失败率正常，但崩溃频率上升，产出低于并发3路  
原因：单一目标优化，忽略崩溃成本  
原则：多目标优化，用有效产出反馈修正调参  
动作：将崩溃频率纳入调度约束，设置崩溃预算  
```

---

## 一句话认知

**失败率低不一定是好事，崩溃少才是真本事。**  
多目标优化的本质不是看多个指标，而是始终盯住“有效产出”这个实目标，用实目标校正虚指标，再用虚指标指导资源调度，形成“以实养虚，虚又返实”的自增强闭环。
