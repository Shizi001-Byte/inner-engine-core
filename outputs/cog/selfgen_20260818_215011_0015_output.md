# 任务类型: cog

基于【已有认知锚定】与历史踩坑经验，从“认知质检SOP”角度出发，将“精气神”三元框架（精为认知原料、气为调度流转、神为校准准则）映射至引擎运行机制，提炼出以下3条可复用的认知质检铁律及验证方法：

### 铁律一：【精】认知活水法则——拒绝“死水档案库”，强制时效注入
*   **坑点溯源**：认知池高达1700+条但只进不出，新认知未注入任务导致引擎变成“静态档案库”。
*   **铁律内容**：在认知质检SOP中，认知产出不能作为终点，必须作为下游调度的起点。认知池必须建立“新陈代谢”机制，将认知注入率作为核心质检指标，确保“精（原料）”持续滋养任务执行。
*   **验证方法**：
    1.  **日志埋点审查**：在调度引擎中加入 `cognitive_injection_log` 埋点。
    2.  **强制刷新校验**：检查系统日志，确认每完成10个并发任务或每轮转换结束时，是否触发一次认知缓存刷新机制。
    3.  **时效断言测试**：提取新产生的高优认知时间戳，断言其在30分钟内是否被下游任务调度链路读取（检索 `read_cognitive_pool` 记录）。若超时未注入，触发“认知断流”告警。

### 铁律二：【气】分层吞吐律——决策串行锚定，执行并发破壁
*   **坑点溯源**：主线程串行后处理导致断流，且API调用无合理timeout导致任务僵死。
*   **铁律内容**：在链路流转的“气”上，必须严格贯彻“决策串行、执行并发”的分层原则。主线程仅做锚点校准与结果汇聚（串行），大模型调用与L4成品转化必须下沉至并发线程。同时，必须依据模型特性设置硬性超时熔断，保障气机顺畅不堵塞。
*   **验证方法**：
    1.  **线程模型代码扫描**：使用静态分析工具扫描主线程，断言主线程内不存在直接发起大模型API调用的同步阻塞代码。
    2.  **超时熔断压测**：向引擎注入死循环或长文本生成任务。验证B模型turbo版本是否在300秒触发超时熔断并降级；A模型是否在600秒触发熔断。
    3.  **断流恢复测试**：并发注入10个任务，人为将其中2个任务的后处理阶段阻塞，验证主线程是否能通过超时机制抛弃该子任务，继续执行后续任务的汇聚，不发生整体断流。

### 铁律三：【神】锚定降维校验律——先校准锚点，再全态转化
*   **坑点溯源**：L4成品转化仅sop类型，code/checklist未实现，导致认知质检维度残缺。
*   **铁律内容**：在质检核心准则的“神”上，必须贯彻“先校准锚点再优化链路”。L4认知转化必须支持多形态（SOP/Code/Checklist），在转化前必须校验目标锚点是否支持多维降维，防止链路跑通后才发现产出形态单一的问题。
*   **验证方法**：
    1.  **多维转化断言**：在L4转化节点前设置拦截器，注入包含复杂逻辑的认知条目，断言转化器输出结果是否同时包含 `sop_output`、`code_output`、`checklist_output` 三种结构。
    2.  **锚点前置校验脚本**：运行校验脚本，检查引擎在调度L4转化前，是否输出了“多维转化能力校验通过”的标志。若仅支持SOP，必须阻断流程并抛出“L4转化形态残疾”异常。
    3.  **回归测试覆盖**：在CI/CD流水线中加入认知质检回归用例，确保每次引擎优化链路时，三种L4形态的转化率不低于基准线。
