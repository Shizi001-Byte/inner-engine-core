# 任务类型: cog

“先校准锚点，再优化链路”这条原则，本质是：**在动手优化或排序之前，先确认“关键参照物”是否正确；否则后续动作越高效，错得越远。**

项目ID看错导致1小时排查，就是典型锚点错误：ID是后续所有操作的关键索引，ID错了，后面查日志、对数据、找原因全都在错误链路上空转。同理，任务优先级排序如果锚点没校准，排序越“科学”，越可能把资源投到错误任务上。

---

### 应用到任务优先级排序的具体做法

#### 1. 排序前先校准“目标锚点”
- 问：这个任务到底服务哪个核心目标？
- 校准方式：把任务目标与上级OKR/项目目标逐字对照，确认没有理解偏差。
- 反例：把“提升页面UV”当成“提升转化率”去排优先级，后续所有优化动作都会偏。

#### 2. 排序前先校准“依赖锚点”
- 问：这个任务的前置条件是什么？是否依赖某个系统、接口、数据或人？
- 校准方式：列出任务依赖链，确认“依赖方/被依赖方”的ID、版本、接口名称、负责人无误。
- 反例：任务A看起来紧急，但依赖的接口还没上线；任务B看似普通，但它是所有后续任务的前置。锚点没校准，就会把A排前，造成等待阻塞。

#### 3. 排序前先校准“定义锚点”
- 问：这个任务的边界、验收标准、涉及范围是否清晰？
- 校准方式：把任务ID、标题、范围描述、验收条件逐项核对，尤其是涉及多个相似任务时。
- 反例：把“订单列表优化”和“订单详情优化”当成同一任务排序，结果排错优先级，做了半天才发现范围不对。

#### 4. 排序前先校准“时间锚点”
- 问：这个任务的真实截止时间、关键时间窗口是什么？
- 校准方式：确认是“固定截止”还是“弹性窗口”，是否受外部时间节点约束。
- 反例：把“客户演示前必须完成”的任务排到下周，而把“可随时上线”的优化排到本周，导致错过窗口。

---

### 推荐操作流程

```
先校准 → 再排序 → 后优化
```

1. **逐任务过锚点清单**：目标、依赖、定义、时间，每个任务花30秒确认。
2. **标记锚点异常项**：有疑问的任务先挂起，不参与排序。
3. **再使用优先级模型**：如RICE、Eisenhower、加权评分。
4. **链路优化放到排序之后**：排序确定了，再优化执行链路、资源配置、协作方式。

---

一句话总结：

> **优先级排序不是“先给任务打分”，而是“先确认任务的锚点没看错”。锚点错了，排序越精确，浪费越大。**
