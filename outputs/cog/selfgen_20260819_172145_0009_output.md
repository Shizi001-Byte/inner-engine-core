# 任务类型: cog

基于锚定：**Guardian-Core 双进程、WAL+Snapshot、单向同步与幂等优先**。本复盘不展开底层自恢复，只聚焦增量同步链上的“基建脚本”环节。

## 复盘结论

认知成立，但需要升级为一条强制规则：

> **基建脚本没有“简化版”，只有“完整版 + 可校验版本”。任何简化版 SQL 都不得进入同步链路，也不得作为补丁直接对 Supabase 执行。**

简化版 SQL 导致列不匹配的本质是：  
它破坏了“单一事实来源”和“可校验性”。  
在 ChainTask 链路里，**本地文件（实）** 一旦失真，后面的变化检测（虚）、只传差异（实）、冲突处理（虚）全都会被带偏。

---

## ChainTask 链路上的落点

- **本地文件（实）**：必须保存完整 DDL/DML，不保存简化版。
- **变化检测（虚/策略）**：用 schema 版本/checksum 检测变化，而不是“文件改没改”。
- **只传差异（实）**：diff 必须由完整 schema 生成，禁止手工写“只改一个字段”的简化 SQL。
- **冲突处理（虚/策略）**：遇到列不匹配，先走迁移流程，不允许自动用简化 SQL 补列。
- **Supabase 认知池（实）**：迁移状态写入 `schema_migrations`；认知池中固化“基建脚本禁用简化版”规则。
- **同步指标（实）**：记录 schema 校验失败次数、迁移耗时、列不匹配错误类型。
- **策略调优（虚）**：如果某张表反复出现列不匹配，就把它设为强制 schema 校验，CI 不通过直接阻断。

## 检查清单

### 1. 单一事实来源

- [ ] 基建脚本必须从唯一 schema 文件或迁移工具生成，不允许“我再写个简单版”。
- [ ] 每次表结构变更新增一个迁移文件，不修改已发布的历史迁移文件。
- [ ] schema 文件纳入版本控制，并进入 code review。

### 2. SQL 编写规范

- [ ] `INSERT` 必须显式列出列名：  
  `INSERT INTO t (id, name, created_at) VALUES (?, ?, ?)`  
  禁止：`INSERT INTO t VALUES (?, ?)`
- [ ] `SELECT` 禁止 `*`，同步查询必须写显式列名。
- [ ] `CREATE TABLE` 必须包含全部列、类型、默认值、非空、主外键、索引、约束。  
  禁止只写“当前业务用到的列”。
- [ ] `ALTER TABLE` 必须使用 `ADD COLUMN IF NOT EXISTS`，并且补全列定义。
- [ ] 迁移脚本必须幂等，重复执行结果一致。
- [ ] 禁止用 `DROP TABLE` 或 `TRUNCATE` 作为常规迁移手段。
- [ ] 每个迁移脚本带版本号，并登记到 `schema_migrations` 表。

### 3. 变更检测与冲突处理

- [ ] 用 schema checksum 或版本号检测变化，不只比较文件 mtime。
- [ ] 同步前检查目标表是否已有源端新增列；没有则先执行完整迁移，再继续 diff。
- [ ] 同步中遇到 `column does not exist` 或列不匹配，立即停止任务。
- [ ] 禁止在同步任务里临时写“简化版 ALTER”补列；必须走正式迁移流程。
- [ ] 冲突处理以完整 schema 为基准，不因“业务紧急”跳过校验。

### 4. 验证与 CI

- [ ] 在 staging 数据库执行迁移后，对比 `information_schema.columns` 与 schema 文件，差异为空才通过。
- [ ] 检查关键列的列名、数据类型、非空、默认值，用断言脚本或 pgTAP 校验。
- [ ] CI 中检查 ORM 模型/代码定义与数据库 schema 是否一致，不一致则构建失败。
- [ ] 任务设置合理超时：B 模型 turbo 用 300 秒，A 模型用 600 秒；超时即失败，不悬挂等待。

### 5. 执行后与同步指标

- [ ] 执行后再次查询 `information_schema.columns` 并输出日志，留作审计。
- [ ] 同步指标记录 schema 校验通过/失败次数、迁移耗时、列不匹配错误类型。
- [ ] 如果 30 分钟内重复出现同类 mismatch，自动告警并暂停该链路的后续任务。

### 6. 认知池刷新

- [ ] 本次复盘结论作为新认知注入认知池。
- [ ] 后续每 10 个任务或每轮同步结束，刷新认知缓存，确保新认知 30 分钟内参与注入。
- [ ] 如果后续任务没有引用本检查清单，调度层应视为认知池未刷新，触发检查。

---

**一句话收尾**：  
列不匹配的根因不是“粗心”，而是“简化版基建脚本”绕过了完整 schema 校验。禁用简化版不是限制效率，而是保证增量同步链路的起点是可信的。
