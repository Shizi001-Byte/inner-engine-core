# 任务类型: cog

### 分层原则：决策串行、执行并发

在“脑体分离”架构中：
- **决策（脑）必须串行**：所有涉及共享状态、任务仲裁、版本校验的逻辑，必须单消费者顺序执行，确保状态一致性和乐观锁有效。
- **执行（体）允许并发**：只有 API 调用、IO 等待等无共享副作用的操作，才能并发执行，以提升吞吐。

引擎优化只能增强“执行并发”的宽度（如加大连接池、异步 IO），**绝不能**把决策逻辑并行化，也不能把执行阶段串行化。否则会破坏脑体分离：要么状态更新互相踩踏，要么执行吞吐被锁死。

---

### 3 个应用场景

1. **批量任务调度**  
   大脑串行扫描待处理任务队列，决策每个任务的下一步（调用哪个模型、超时时间），然后并发发起 API 调用。例如 B 模型 turbo 用 300 秒超时，A 模型用 600 秒超时。  
   **优化方向**：扩大 API 调用并发池。  
   **破坏风险**：若多个决策者同时扫描队列并分发任务，会导致同一任务被重复执行，version 乐观锁冲突。

2. **状态回写**  
   执行器完成 API 调用后，结果交给单消费者后处理，串行更新 task 状态（带 version 做乐观锁仲裁）。  
   **优化方向**：在 API 调用阶段并发，提高请求吞吐。  
   **破坏风险**：若后处理也并行更新状态，version 校验和原子更新会失效，造成状态错乱。

3. **超时与重试决策**  
   决策线程串行统一管理超时策略和重试次数，执行器只负责发起请求并等待结果。  
   **优化方向**：优化执行器的网络 IO、超时监听机制，提升并发效率。  
   **破坏风险**：若把超时判断和重试决策分散到并发执行器中，可能出现重复重试、超时误判，且无法统一仲裁全局状态。
