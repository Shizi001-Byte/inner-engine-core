# 任务类型: eng

## 结论

V7.5 方舟效能引擎的“多线程 API 调用 + 串行后处理”竞态问题，不能用一把普通互斥锁把 API 调用和后处理一起锁住，否则会：

- 持锁等待网络，导致超时；
- 后处理乱序，后完成的先写，破坏状态一致性；
- standby 补位被后处理阻塞，造成 token 闲置。

推荐方案是：

> **状态锁 + 顺序闸门 + 单消费者后处理线程**  
> 多线程只并发调用 API；完成后在锁内更新状态、放入 `pending` 缓冲；由一个后处理线程按 `seq` 顺序串行消费。

---

## 一、竞态根因

1. **check-then-act 竞态**  
   多个线程同时进入完成回调，检查 `task.status == RUNNING` 后同时更新状态，导致重复处理。

2. **完成顺序与提交顺序不一致**  
   API 返回是无序的。如果后处理直接按“完成顺序”执行，seq 1 可能先于 seq 0 被写入，造成状态回退或覆盖。

3. **共享计数器丢失更新**  
   `running`、`standby` 队列长度、指标计数等，如果不在同一把锁下更新，会出现负数或漏计。

4. **超时路径与正常路径竞争**  
   看门狗超时和 API 迟到响应同时进入完成回调，必须保证只有一个路径生效。

5. **standby 补位与后处理竞争**  
   高优先级任务失败后，standby 应立即启动，不能被串行后处理排队堵住。

---

## 二、锁机制设计

### 核心思想

- 所有共享状态统一由一把条件锁 `self.cv` 保护。
- API 调用在锁外执行。
- 每个任务分配全局单调递增 `seq`。
- 后处理线程只处理 `pending[next_to_process]`，保证按 `seq` 串行。
- 高优先级失败时，在锁内弹出 standby 任务并分配新 `seq`，然后在锁外启动 API 线程。
- 迟到响应通过 `task.status != RUNNING` 丢弃。

### 锁的边界

| 操作 | 是否持锁 |
|---|---|
| API 调用 | 否 |
| 更新 `task.status` / `running` | 是 |
| 操作 standby 队列 | 是 |
| 写入 pending 缓冲 | 是 |
| 重量级后处理（解析、降噪、结构化提取） | 否 |
| 提交后处理结果到认知池 | 是 |
| 启动新线程 | 否 |

## 三、完整代码骨架

```python
import json
import threading
import time
import urllib.request
from collections import deque

TIMEOUT = {
    "B": 300,   # B 模型 turbo
    "A": 600,   # A 模型
}

class TaskStatus:
    PENDING = "pending"
    RUNNING = "running"
    DONE = "done"
    FAILED = "failed"


class Task:
    def __init__(self, priority, model, payload):
        self.seq = None
        self.priority = priority
        self.model = model
        self.payload = payload
        self.timeout = TIMEOUT.get(model, 600)
        self.status = TaskStatus.PENDING
        self.result = None
        self.error = None
        self.started_at = None


class ArkEngine:
    def __init__(self, cognitive_pool):
        self.cv = threading.Condition()
        self.cognitive_pool = cognitive_pool

        self.next_seq = 0
        self.next_to_process = 0
        self.pending = {}      # seq -> (task, result, error)

        self.running = 0
        self.standby = deque()
        self.tasks = {}        # seq -> task

        self.closed = False

        threading.Thread(target=self._post_loop, daemon=True).start()
        threading.Thread(target=self._watchdog_loop, daemon=True).start()

    # ---------- 提交 ----------

    def submit(self, priority, model, payload):
        task = Task(priority, model, payload)

        with self.cv:
            if self.closed:
                raise RuntimeError("engine closed")

            task.seq = self.next_seq
            self.next_seq += 1
            task.status = TaskStatus.RUNNING
            task.started_at = time.time()
            self.tasks[task.seq] = task
            self.running += 1

        self._start_worker(task)
        return task.seq

    def add_standby(self, priority="BATCH", model="B", payload=None):
        with self.cv:
            self.standby.append(Task(priority, model, payload))

    # ---------- API 调用 ----------

    def _start_worker(self, task):
        threading.Thread(target=self._api_worker, args=(task,), daemon=True).start()

    def _api_worker(self, task):
        try:
            result = self._call_api(task)
            error = None
        except Exception as e:
            result = None
            error = e

        self._finish(task, result=result, error=error)

    def _call_api(self, task):
        # 坑库：统一 urllib 直连，并显式禁用代理，避免 ProxyError
        opener = urllib.request.build_opener(
            urllib.request.ProxyHandler({})
        )

        url = "https://ark.volcengine.com/api/v7.5/..."
        headers = {"Content-Type": "application/json"}
        data = json.dumps(task.payload).encode("utf-8")
        req = urllib.request.Request(url, data=data, headers=headers, method="POST")

        with opener.open(req, timeout=task.timeout) as resp:
            raw = resp.read()

        parsed = json.loads(raw.decode("utf-8"))

        # 坑库：B 模型 Responses API 可能 content 为空
        if task.model == "B":
            content = parsed.get("content") or parsed.get("output", {}).get("content")
            if not content:
                raise RuntimeError("B model Responses API content is empty")

        return parsed

    # ---------- 完成回调 ----------

    def _finish(self, task, result=None, error=None):
        standby_task = None

        with self.cv:
            # 迟到响应 / 重复完成，直接丢弃
            if task.status != TaskStatus.RUNNING:
                return

            if error is None:
                task.status = TaskStatus.DONE
                task.result = result
            else:
                task.status = TaskStatus.FAILED
                task.error = error

            self.running -= 1

            # 高优先级失败：立即从 standby 补位，避免 token 闲置
            if error is not None and task.priority == "HIGH":
                standby_task = self._promote_standby_locked()

            self.pending[task.seq] = (task, result, error)
            self.cv.notify()  # 唤醒后处理线程

        # 锁外启动 standby，不能等后处理
        if standby_task is not None:
            self._start_worker(standby_task)

    def _promote_standby_locked(self):
        if not self.standby:
            return None

        st = self.standby.popleft()
        st.seq = self.next_seq
        self.next_seq += 1
        st.status = TaskStatus.RUNNING
        st.started_at = time.time()
        self.tasks[st.seq] = st
        self.running += 1

        return st

    # ---------- 串行后处理 ----------

    def _post_loop(self):
        while True:
            with self.cv:
                while self.next_to_process not in self.pending and not self.closed:
                    self.cv.wait()

                if self.next_to_process not in self.pending:
                    break

                task, result, error = self.pending[self.next_to_process]

            # 锁外做重量级后处理：多模态解析、降噪、结构化提取
            try:
                commit = self._build_commit(task, result, error)
            except Exception as e:
                commit = self._build_error_commit(task, e)

            with self.cv:
                try:
                    self._commit_locked(commit)
                finally:
                    self.pending.pop(self.next_to_process, None)
                    self.next_to_process += 1
                    self.cv.notify_all()

    def _build_commit(self, task, result, error):
        if error is not None:
            return {"type": "failure", "task": task, "error": error}

        return {
            "type": "success",
            "task": task,
            "data": self.cognitive_pool.extract(task, result),
        }

    def _build_error_commit(self, task, error):
        return {"type": "error", "task": task, "error": error}

    def _commit_locked(self, commit):
        if commit["type"] == "success":
            self.cognitive_pool.ingest(commit["data"])
        else:
            self.cognitive_pool.record_failure(commit["task"], commit["error"])

    # ---------- 超时看门狗 ----------

    def _watchdog_loop(self):
        while True:
            time.sleep(1)

            expired = []
            with self.cv:
                now = time.time()
                for task in self.tasks.values():
                    if task.status == TaskStatus.RUNNING and now - task.started_at > task.timeout:
                        expired.append(task)

            for task in expired:
                self._finish(
                    task,
                    error=TimeoutError(f"{task.model} timeout {task.timeout}s")
                )
```

## 四、防坑配置与验证

### 1. 防坑配置

- 新增配置必须从同一个 `TIMEOUT` / config 读取，不能散落硬编码。
- 修改 timeout 后，立即跑一次 smoke test，确认 `_call_api` 和 watchdog 都使用新值。
- 必须使用 `urllib` 且 `ProxyHandler({})`；如果历史代码必须用 `requests`，则显式传 `proxies={"http": None, "https": None}`。
- B 模型 Responses API 接入前，先单测 `content` 非空；为空要抛异常，触发 standby 补位。

### 2. 硬性验证指标

- `running` 永远不为负。
- `next_to_process` 单调递增。
- 最终 `pending` 为空，所有任务状态为 `DONE` 或 `FAILED`。
- 乱序返回压力测试：让 seq 5 先完成、seq 0 最后完成，后处理日志必须仍是 `0,1,2,3,4,5`。
- 高优先级超时失败后，standby 任务必须在后处理排队之前启动，不能等串行后处理结束才补位。
- 重复完成回调测试：同一 task 调用两次 `_finish`，最终只执行一次后处理。

这套机制可以保证：**API 并发最大化、后处理严格有序、standby 补位不被阻塞、状态最终一致。**
