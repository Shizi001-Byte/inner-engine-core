# 熵减归档引擎：算力生命体的记忆代谢系统

> 在九转认知框架下，自动归档系统不是"文件管理器"，而是算力生命体的**记忆代谢器官**——吞噬任务流，剥离信息骨架，编织关联图谱，最终实现从被动存储到自主组织的维度跃迁。

---

## 一、系统定位：在九转框架中的坐标

```
第一转·语料吞噬 ──→ 任务摄入管道
第一转·特征剥离 ──→ 多维特征提取器
阴阳自衡架构   ──→ 双轨分类引擎
                ↘ 代谢循环（目录进化/规则固化）
```

系统本质：**将无序的任务流（高熵）转化为有序的归档结构（低熵），在硅基记忆中实现持续熵减。**

---

## 二、核心架构：六层代谢链路

### 第一层 · 摄入管道（语料吞噬）

任务从设计引擎产出后，全量进入归档系统的原始缓冲池。

```
设计引擎 ──→ 任务流 ──→ 原始缓冲池 ──→ 特征预提取 ──→ 待归档队列
```

**设计原则**：
- 原始数据不丢失（完整保留任务描述、上下文、产出物引用）
- 摄入即提取（不等归档时再处理，降低延迟）
- 背压控制（任务洪峰时缓冲，避免系统过载）

**任务数据结构**：
```json
{
  "task_id": "TASK-2024-1023",
  "source_engine": "design_engine_v2",
  "raw_description": "修复AuthService中session超时未正确清理的问题...",
  "context": {
    "project": "core-platform",
    "sprint": "S12",
    "assignee": "agent_arch_03"
  },
  "artifacts": ["patch_auth_timeout.py", "test_session_cleanup.py"],
  "timestamp": "2024-03-15T08:30:00Z",
  "lifecycle": "completed"

```

### 第二层 · 特征剥离引擎

对每个任务执行六维度特征提取，**剥离叙述冗余，只保留信息骨架**：

| 维度 | 提取方法 | 输出示例 |
|:-----|:---------|:---------|
| 语义向量 | Embedding模型 | `[0.12, -0.34, 0.56, ...]` |
| 关键词骨架 | TF-IDF + 领域词典 | `["auth", "timeout", "session_cleanup"]` |
| 结构类型 | 模板分类器 | `template_type: "bug_fix"` |
| 时间特征 | 时间戳解析 | `quarter: "Q1", sprint: "S12"` |
| 关联实体 | NER + 依赖链 | `entities: ["AuthService", "SessionManager"]` |
| 优先级/紧迫度 | 分类模型 | `priority: "P1", urgency: 0.85` |

**特征指纹**（剥离后的骨架）：
```json
{
  "task_id": "TASK-2024-1023",
  "embedding": [0.12, -0.34, ...],
  "skeleton": {
    "type": "bug_fix",
    "domain": "authentication",
    "keywords": ["auth", "timeout", "session", "cleanup"],
    "entities": ["AuthService", "SessionManager"],
    "priority": "P1",
    "urgency": 0.85
  },
  "redundancy_stripped": "移除312字客套/重复上下文，保留78字核心描述"
}
```

### 第三层 · 阴阳双轨分类引擎（系统核心）

> 此处直接映射"阴阳自衡"架构——阴轨为规则确定性，阳轨为语义动态性。

```
                    任务到达
                       │
           ┌───────────┴───────────┐
           ▼                       ▼
    ┌──────────────┐      ┌──────────────────┐
    │  阴轨·规则匹配  │      │  阳轨·语义聚类    │
    │  （确定性70%） │      │  （自适应性30%）   │
    └──────┬───────┘      └────────┬─────────┘
           │                       │
     匹配? │                近邻?   │
     ┌─YES─┴─NO─┐          ┌─YES─┴─NO─┐
     │          │          │          │
   归档     进入阳轨      归档      进入孵化区
           (带复核标记)          (积累后聚类)
```

```python
def yang_classify(task_embedding, vector_db, threshold=0.75):
    """阳轨：在向量空间中寻找最近邻"""
    neighbors = vector_db.search(task_embedding, top_k=5)
    
    if neighbors[0].similarity > threshold:
        return {
            "category": neighbors[0].category,
            "method": "yang_match",
            "confidence": neighbors[0].similarity,
            "needs_review": True  # 阳轨匹配需标记复核
        }
    else:
        return {
            "category": "_emerging",
            "method": "yang_incubate",
            "confidence": 0.0,
            "note": "进入孵化区，等待聚类"
        }
```

**阴阳自衡机制（关键）**：

| 转化方向 | 触发条件 | 动作 |
|:---------|:---------|:-----|
| 阳转阴（规则固化） | 阳轨某模式连续30天稳定出现，匹配率>80% | 自动生成新阴轨规则 |
| 阴转阳（规则退化） | 阴轨某规则30天匹配率<10% | 规则降级，任务回流阳轨 |
| 阴轨裂变 | 某规则匹配的任务内部出现明显子聚类 | 拆分为更细粒度规则 |

```python
def yin_yang_metabolism(rule_engine, vector_db, window_days=30):
    """阴阳自衡代谢循环"""
    # 阳转阴：聚类模式固化为规则
    for pattern in vector_db.get_stable_patterns(window_days):
        if pattern.match_rate > 0.80 and pattern.count > 20:
            new_rule = extract_rule_from_pattern(pattern)
            rule_engine.solidify(new_rule)
            log(f"阴阳转化：阳轨模式 '{pattern.name}' 固化为阴轨规则")
    
    # 阴转阳：失效规则降级
    for rule in rule_engine.get_all_rules():
        recent_matches = rule_engine.count_matches(rule.id, window_days)
        if recent_matches < 2:
            rule_engine.deprecate(rule.id)
            log(f"阴阳转化：阴轨规则 '{rule.name}' 降级，任务回流阳轨")
```

### 第四层 · 标签矩阵

标签不是平面列表，而是**四层层次化矩阵**：

```
Layer 1: 主分类标签（对应顶层目录）
  └─ Layer 2: 子分类标签（对应子目录）
      └─ Layer 3: 横切属性标签（跨目录，如 priority/domain/sprint）
          └─ Layer 4: 动态学习标签（系统自发现的隐含模式标签）
```

**标签生成策略**：

| 策略 | 来源 | 对应 | 示例 |
|:-----|:-----|:-----|:-----|
| 预定义 | 人工领域词典 | 阴 | `bug_fix`, `feature`, `refactoring` |
| 提取式 | 任务文本高频术语 | 阳 | `auth_timeout`, `connection_pool` |
| 推断式 | 任务共现关系 | 阴阳交汇 | `refactoring_side_effect` |

**标签冲突消解**：
```python
def resolve_tag_conflicts(candidate_tags):
    """
    一个任务可能匹配多个标签，通过置信度消解
    """
    resolved = {
        "confirmed": [],    # confidence > 0.8
        "candidate": [],    # 0.5 < confidence < 0.8
        "discarded": []     # confidence < 0.5
    }
    
    for tag in candidate_tags:
        if tag.confidence > 0.8:
            resolved["confirmed"].append(tag)
        elif tag.confidence > 0.5:
            resolved["candidate"].append(tag)
        else:
            resolved["discarded"].append(tag)
    
    return resolved
```

```python
def archive_task(task):
    # Step 1: 特征剥离
    features = extract_features(task)
    
    # Step 2: 阴轨优先
    rule_match = yin_rule_engine.match(features)
    if rule_match and rule_match.confidence > 0.9:
        category = rule_match.category
        method = "yin_rule"
    else:
        # Step 3: 阳轨兜底
        yang_result = yang_classify(features.embedding, vector_db)
        category = yang_result.category
        method = yang_result.method
    
    # Step 4: 标签生成
    tags = generate_tag_matrix(features, category)
    
    # Step 5: 持久化
    archive_path = build_path(category, task.task_id)
    store_task(task, features, tags, archive_path)
    
    # Step 6: 图谱关联
    update_memory_graph(task, features, category)
    
    # Step 7: 输出归档记录
    return ArchiveResult(
        path=archive_path,
        category=category,
        method=method,
        tags=tags,
        graph_links=extract_relations(task)
    )
```

> 传统归档是树形结构。本系统在树形之上构建**关联图谱**，使归档不只是"存"，更是"织"。

```json
{
  "task_id": "TASK-2024-1023",
  "archive_path": "/bug_fixes/api/TASK-2024-1023_auth_timeout.md",
  "graph": {

  }

```

检索时可通过图谱遍历找到关联任务，而非仅靠目录路径或关键词。

## 三、代谢引擎（系统的心跳）

> 对应九转中的"自省"与"演化"——系统不是静态的文件柜，而是持续代谢的生命体。

| 代谢动作 | 触发条件 | 效果 |
|:---------|:---------|:-----|
| 目录合并 | 某目录90天无新任务 | 归档内容合并到上级，删除空目录 |
| 目录拆分 | 某目录任务数 > 500 | 按子特征自动拆分 |
| 标签退化 | 某标签180天无使用 | 降级为历史标签 |
| 规则固化 | 阳轨聚类稳定率 > 80% | 阳轨模式 → 阴轨规则 |
| 规则退化 | 阴轨规则30天匹配率 < 10% | 规则降级，任务回流阳轨 |
| 归档修正 | 人工反馈错误归档 | 更新分类模型权重 |
| 重复清理 | 两任务embedding相似度 > 0.95 | 合并，保留主任务 |
| 图谱修剪 | 关联边权重 < 0.1 | 削弱/删除弱关联 |

```python
class MetabolismScheduler:
    """代谢引擎：每日/每周/每月执行不同层级的代谢"""
    
    def daily(self):
        """日代谢：轻量级"""
        self.cleanup_duplicates(threshold=0.95)
        self.update_embeddings_for_new_tasks()
    
    def weekly(self):
        """周代谢：中量级"""
        self.yin_yang_metabolism(window_days=30)
        self.check_directory_split(threshold=500)
        self.optimize_graph_edges()
    
    def monthly(self):
        """月代谢：重量级"""
        self.check_directory_merge(idle_days=90)
        self.deprecate_stale_tags(idle_days=180)
        self.retrain_classifier()
        self.generate_metabolism_report()
```

## 五、九转映射总览

| 转次 | 玄功含义 | 归档系统对应能力 | 当前实现状态 |
|:-----|:---------|:----------------|:------------|
| 一转 | 语料吞噬 | 任务摄入管道 + 特征剥离 | ✅ 核心 |
| 二转 | 阴阳分拣 | 阴轨规则 + 阳轨聚类双轨分类 | ✅ 核心 |
| 三转 | 标签矩阵 | 四层层次化标签体系 | ✅ 核心 |
| 四转 | 目录映射 | 动态目录路由 + 孵化区 | ✅ 核心 |
| 五转 | 记忆沉淀 | 持久化 + 记忆图谱 | ✅ 核心 |
| 六转 | 代谢循环 | 目录合并/拆分/标签退化 | ✅ 增强 |
| 七转 | 规则固化 | 阳轨→阴轨自动转化 | ✅ 增强 |
| 八转 | 模式预测 | 基于历史分布预测未来任务类型 | 🔲 后续 |
| 九转 | 归档意识 | 全自主归档闭环，零人工干预 | 🔲 后续 |

> **核心闭环**：任务进入 → 特征剥离 → 阴阳分类 → 标签矩阵 → 目录路由 → 持久化 → 图谱编织 → 代谢优化 → 规则进化 → 循环。每完成一轮，系统的归档精度提升一分，熵值降低一分。
