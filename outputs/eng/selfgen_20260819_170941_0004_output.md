# 任务类型: eng

## 任务池自进化闭环设计（基于 ChainTask）

> 本设计直接建立在已确认的 Guardian-Core 双进程、WAL+Snapshot、单向同步与幂等优先架构之上，不重复论证底层原理。  
> 核心目标：**自动检测重复率 → 生成新 ChainTask 模板 → 注入任务池 → 真实执行回流 → 再次影响调度**，形成“以实养虚，虚又返实”的闭环。

---

## 1. 闭环总览

```
Core 执行真实任务（实）
        │
        ▼
Guardian 统计重复率（实 → 虚）
        │
        ▼
认知池选取种子 + A模型生成模板（虚）
        │
        ▼
Core 幂等写入模板并注入种子任务（虚 → 实）
        │
        ▼
探针/种子任务执行验证（实）
        │
        ▼
成功则放大权重，失败则回滚/禁用
        │
        ▼
执行结果回流认知池，重复率下降
```

其中 **ChainTask** 是闭环的最小单元：

```json
{
  "template_id": "auto_chain_xxx",
  "input_schema": {},
  "output_schema": {},
  "next_conditions": [],
  "quality_rules": {
    "model_a": [],
    "model_b": []
  },
  "timeout_ms": 600000,
  "status": "canary"
}
```

## 2. 重复率检测

### 2.1 检测窗口

- 滑动窗口：最近 **100 个已执行 ChainTask**，或最近 **1 小时**。
- 连续 **3 个窗口** 重复率超过阈值，才触发自进化，避免抖动。

### 2.2 重复率计算

```text
R = 0.4 * exact_dup_rate
  + 0.4 * semantic_dup_rate
  + 0.2 * template_concentration
```

| 指标 | 定义 |
|---|---|
| `exact_dup_rate` | 相同 `template_id + input_hash` 的任务数 / 窗口任务数 |
| `semantic_dup_rate` | 输入语义相似度 > 0.92 的任务数 / 窗口任务数 |
| `template_concentration` | 出现次数最多的模板任务数 / 窗口任务数 |

语义向量可用 B 模型 turbo 生成，调用 timeout 固定 **300 秒**；若超时则降级为 exact hash 统计，不阻塞主流程。

## 3. 模板生成：从认知池选取种子

### 3.1 种子来源

Guardian 每次触发生成前，必须从认知池中选取：

1. **新认知**：`created_at` 在 30 分钟内、且未参与过注入的认知，优先选取。
2. **高价值认知**：评分高于阈值的认知。
3. **重复热点**：最近重复率高的任务链节点、失败模式、超时模式。

> 硬约束：认知池每 **10 个任务** 或 **每轮结束** 必须刷新缓存；新认知 **30 分钟内必须参与注入**，防止认知池只进不出。

### 3.2 生成调用

- 使用 **A 模型** 生成模板，timeout 固定 **600 秒**。
- 生成 prompt 中必须携带：
  - 现有模板列表（用于反重复）；
  - 认知种子；
  - ChainTask 模板 schema；
  - 质量规则要求：**B 模型必须跳过 reasoning 占比检测**，不能把 B 模型正常特征判为废稿。

生成结果必须通过校验：

- JSON Schema 合法；
- 与现有模板语义相似度 < 0.85，否则重新生成；
- `quality_rules` 必须按模型区分；
- 若模板指定 B 模型，则 `quality_rules.model_b` 中禁止出现 `reasoning_ratio` 检查。

---

## 4. 注入与生效：三处同步修改

> 这是避免“配置修改后未生效”的关键。  
> 新增模板必须同步修改三个点：**状态写入、执行读取、生效验证**。

### 4.1 状态写入

- 使用 WAL 事务写入：

```text
upsert_template(template)
enqueue_task(seed_task)
```

- `template_id` 作为唯一键，重复注入直接忽略，保证幂等。
- 只写模板库不够，必须同时向任务池注入一个**可执行的种子任务**，否则模板变成静态档案。

### 4.2 执行读取

- Core 收到模板更新事件后，必须立即刷新调度器缓存。
- 刷新点包括：
  - 模板注册表；
  - 任务池读取视图；
  - 质量规则缓存；
  - 超时配置缓存。
- 不能依赖重启生效，必须支持运行时热更新。

### 4.3 生效验证

- 新注入的种子任务作为 **探针任务**，低优先级运行。
- 验证内容：
  - 任务能否成功执行；
  - 输出是否符合 `quality_rules`；
  - B 模型不检查 reasoning 占比；
  - 是否真正产生了新路径或新产出。
- 探针失败：模板置为 `disabled`，从调度器移除，并记录失败原因。
- 探针成功：模板进入 `canary` 状态，分配少量真实流量。

## 5. 自进化与回滚

### 5.1 Canary 放大

- 新模板初始权重：**5%**。
- 每执行 20 个任务观察一次：
  - 成功率；
  - 质量分；
  - 对重复率的贡献；
  - 是否产生了新的下游 ChainTask 路径。

### 5.2 放行条件

连续观察 50 个任务后：

- 成功率 ≥ 阈值；
- 输出质量达标；
- 整体重复率下降或保持稳定；
- 没有污染任务池。

满足条件后，从 `canary` 提升为 `active`，正常参与调度。

### 5.3 回滚条件

- 探针失败；
- 新任务成功率低于阈值；
- 注入后重复率不降反升；
- 生成模板与已有模板高度相似。

满足任一条件，立即 `disabled`，并从任务池中撤回未执行的种子任务。

## 6. ChainTask 链式推演落地

自进化不能只生成孤立模板，必须生成“链上节点”。

### 6.1 链式断点识别

Guardian 分析真实任务链：

```text
A → B → C
```

如果发现：

- B 的输出没有下游任务；
- B 重复率极高；
- B 产生大量失败/超时；

则在 B 后生成新的 ChainTask 模板 `B2`，消费 B 的输出并产生新结果。

### 6.2 新模板必须带 next_conditions

自动生成的模板必须包含：

```json
{
  "next_conditions": [
    {
      "condition": "output.code_quality_score >= 0.8",
      "next_template_id": "existing_review_task",
      "priority": 0.9
    }
  ]
}
```

这样新模板注入后，会真实改变任务链路径，实现“虚又返实”。

## 7. 模型调用与超时硬约束

| 场景 | 模型 | timeout |
|---|---|---|
| 模板生成 | A 模型 | 600 秒 |
| 认知摘要/深度校验 | A 模型 | 600 秒 |
| 语义向量/重复率检测 | B 模型 turbo | 300 秒 |
| 轻量分类/质量预检 | B 模型 turbo | 300 秒 |

超时后不无限重试，进入退避，并记录为生成失败。

---

## 8. 避坑清单映射

| 历史坑 | 本设计对策 |
|---|---|
| 配置修改未生效 | 模板/阈值修改必须同步：状态写入、执行读取、生效验证 |
| API 超时 | A 模型 600s，B 模型 turbo 300s，超时退避 |
| 废稿检测误杀 B 模型 | 质量规则按模型隔离，B 模型跳过 reasoning 占比检测 |
| 认知池只进不出 | 每 10 任务或每轮刷新缓存；新认知 30 分钟内必须参与注入 |
| 自动调参全链路失效 | 每次注入后必须有探针任务验证行为变化 |

---

## 9. 闭环度量指标

- `repetition_rate`：重复率是否下降；
- `template_entropy`：任务池模板多样性；
- `auto_inject_count`：自动生成并注入的模板数量；
- `probe_success_rate`：探针任务成功率；
- `cognitive_usage_rate`：新认知参与注入的比例；
- `chain_path_count`：真实任务链路径数量。

最终目标：**重复率上升 → 自动生成新 ChainTask → 注入任务池 → 真实执行 → 路径变多 → 重复率下降 → 更多真实数据回流认知池**，形成持续自进化闭环。
