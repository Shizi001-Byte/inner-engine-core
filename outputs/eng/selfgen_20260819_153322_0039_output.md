# 任务类型: eng

## 链式推演机制设计

### 1. 定位

把一个核心议题拆成 **3-5 轮递进任务**，每一轮都产出一个结构化“实”产物，并且必须留下 `next_input` 给下一轮。

核心关系是：

> **上一轮输出 = 下一轮输入**  
> **实生虚，虚又返实**

- “实”是每轮产出的结论、方案、数据；
- “虚”是下一轮尚未生成的思考空间；
- 上一轮越实，下一轮越有抓手；
- 下一轮又产出新的实，形成自增强闭环。

---

### 2. 任务依赖图

完整 5 轮依赖图如下：

```text
R0 核心议题
  │
  ▼
R1 定题 ──▶ V1 验证门 ──失败──▶ 修正反馈 ──▶ R1
  │
 通过
  ▼
R2 辨机 ──▶ V2 验证门 ──失败──▶ 修正反馈 ──▶ R2
  │
 通过
  ▼
R3 反演 ──▶ V3 验证门 ──失败──▶ 修正反馈 ──▶ R3
  │
 通过
  ▼
R4 合和 ──▶ V4 验证门 ──失败──▶ 修正反馈 ──▶ R4
  │
 通过
  ▼
R5 归真 ──▶ V5 验证门 ──失败──▶ 修正反馈 ──▶ R5
  │
 通过
  ▼
落地行动 + 进化反馈
```

如果是 3 轮，则取：

```text
R0 → R1 定题 → R3 反演 → R5 归真
```

如果是 4 轮，则取：

```text
R0 → R1 定题 → R2 辨机 → R4 合和 → R5 归真
```

关键点：

- 主链是严格递进的：`R_i` 只消费 `R_{i-1}` 的 `next_input`；
- 验证门控制是否进入下一轮；
- 失败回退到当前轮，而不是从头开始；
- 如果验证发现上一轮存在根本缺陷，可跨级回退，例如：

```text
V3 验证失败
  ├─ 普通错误 → 回到 R3
  └─ 重大缺陷 → 回到 R2
```

但每次回退次数有限，防止死循环。

---

### 3. 轮次契约

每一轮都定义清晰的任务、输出字段和下游读取点。

| 轮次 | 名称 | 核心动作 | 必含字段 |
|---|---|---|---|
| R1 | 定题 | 把模糊议题变成具体问题、边界、约束 | `问题定义`、`边界条件`、`关键假设`、`next_input` |
| R2 | 辨机 | 拆解动力机制，找出虚实转化点 | `动力模型`、`关键变量`、`反方风险`、`next_input` |
| R3 | 反演 | 反向证伪，寻找失效模式 | `失效条件`、`反向指标`、`可逆动作`、`next_input` |
| R4 | 合和 | 构建虚实自增强闭环方案 | `闭环结构`、`资源需求`、`验证指标`、`next_input` |
| R5 | 归真 | 形成可执行落地计划 | `行动清单`、`决策门`、`时间节点`、`冷却重置标志` |

统一输出信封：

```json
{
  "round": 1,
  "round_name": "定题",
  "output": {
    "问题定义": "...",
    "边界条件": "...",
    "关键假设": "...",
    "next_input": "给下一轮的具体输入"
  }
}
```

`next_input` 是链式推演的核心握手字段。

---

### 4. 引擎执行流程

```text
1. 接收核心议题
2. 根据复杂度选择 3/4/5 轮模板
3. 初始化 state：
   state[0].output.next_input = 核心议题
4. 对每一轮 i：
   a. 取输入：state[i-1].output.next_input
   b. 构造本轮 prompt
   c. 调用模型生成
   d. 验证输出
   e. 验证通过 → 写入 state，重置冷却
   f. 验证失败 → 修正重试，或回退
5. 全部轮次完成 → 生成最终行动方案
6. 把执行日志送入进化轨
```

伪代码：

```python
def run_chain(core_issue):
    rounds = select_rounds(core_issue)
    state = {}
    state[0] = {"output": {"next_input": core_issue}}

    for r in rounds:
        inp = state[r - 1]["output"]["next_input"]
        output = call_model_with_timeout(round_prompt(r, inp))
        output = validate_and_repair(output, r, state)

        state[r] = {"output": output}
        reset_cooldown()

    return finalize_plan(state)
```

### 5. 避坑规则落地

#### 避坑 1：配置修改后未生效

预防机制：**配置同步校验**

每一轮输出中的新字段，必须在下游轮次模板中有对应读取点。

```text
本轮 output 字段：
  produced_fields = [问题定义, 边界条件, 关键假设, next_input]

下一轮模板读取字段：
  consumed_fields = [问题定义, 边界条件, 关键假设, next_input]

校验规则：
  consumed_fields ⊆ produced_fields
```

如果不满足，则：

- 自动补丁下一轮模板；
- 或者直接报错，阻止进入下一轮；
- 修改后立即用 `next_input` 做一次最小读取测试，确认生效。

#### 避坑 2：API 调用超时

预防机制：预设模型级 timeout

```text
B模型turbo：300秒
A模型：600秒
```

超时后不无限等待，进入修正通道：

```text
超时
  → 把已生成的部分输出 + 错误信息拼接
  → 重新请求，并提示“缩短输出，直接给结构化结果”
  → 最多重试 2 次
  → 仍失败则终止本轮，进入进化反馈
```

### 6. 自进化闭环：以实养虚，虚又返实

整个机制分两条轨：

#### 阳轨：执行链

- 核心议题 → R1 → R2 → R3 → R4 → R5 → 落地
- 这是“实”的生成过程
- 每轮成功输出都会成为下一轮的“实”

#### 阴轨：进化链

- 验证失败日志
- 超时日志
- 回退记录
- 修正反馈
- 模板缺口

这些“虚”的信号不会丢弃，而是进入进化器：

```text
每次任务完成后：
  1. 收集 validation_log
  2. 分析失败模式
  3. 更新轮次模板
  4. 调整依赖图
  5. 更新 timeout / 模型选择规则
```

所以：

> **以实养虚**：每轮成功输出滋养下一轮思考空间  
> **虚又返实**：失败与反馈沉淀为新的规则，再反哺执行链

这个机制不是静态任务清单，而是会持续进化的认知引擎。

### 7. 示例

核心议题：

> 如何在资源有限的情况下验证 AI 客服产品可行性？

链式推演：

| 轮次 | 任务 | 输出示例 |
|---|---|---|
| R1 定题 | 明确用户、场景、约束 | 目标用户：中小电商；痛点：客服响应慢；约束：2人/2周/0预算 |
| R2 辨机 | 拆解关键假设 | 价值假设：用户愿意为省时付费；渠道假设：社群能触达；付费假设：可接受预付定金 |
| R3 反演 | 反向证伪 | 失效条件：用户不愿付费、合规风险、模型幻觉；反向指标：100个访谈中不足20人愿付定金则放弃 |
| R4 合和 | 设计最小验证方案 | 落地页 + 人工模拟AI回复 + 定金按钮 |
| R5 归真 | 落地执行 | 第1天搭页面，第3天邀约访谈，第7天出决策结论 |

每一轮都只基于上一轮输出继续，不回到原始议题。

---

### 8. 结论

链式推演机制的核心是：

- **依赖图驱动**
- **验证门把关**
- **上一轮输出作为下一轮输入**
- **成功则重置冷却**
- **失败则进入进化轨**

这样，一个核心议题不再是“一次生成完事”，而是经过多轮认知折叠，逐步逼近可执行的真问题、真方案、真行动。
