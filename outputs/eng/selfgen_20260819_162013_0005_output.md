# 任务类型: eng

## 任务池动态扩充机制设计

### 一、目标与边界

本机制是**执行层自进化闭环**：  
引擎运行中持续检测任务重复率，超过阈值后自动生成新任务模板，注入任务池，并验证其真实生效，从而让任务池“更聪明地复用重复任务、生成多样化变体”。

边界：

- **不替大脑做业务判断**：只改变执行层模板，不改变业务目标。
- **不突破“稳定3路并发”物理上限**：生成/验证任务不得另开第4路，只能在3路内插空执行。
- **不是“零成本”免费午餐**：生成、验证、生效验证都会消耗算力，必须限流、限预算。

---

### 二、闭环链路

```text
监控统计 -> 重复率判定 -> 触发冷却 -> 模板生成 -> 候选校验 -> 注入同步 -> 生效验证 -> 效果反馈 -> 调整策略
```

---

### 三、核心模块设计

#### 1. 重复率检测器

对最近 N 个已完成任务计算重复率：

```text
任务指纹 = hash(模板ID + 归一化参数 + 模型 + 任务类型)

重复率 R = 1 - 最近N个任务中去重指纹数 / N
模板集中度 C = 最近N个任务中最高频模板占比
```

触发条件（满足任一即可）：

- `R > 0.35`
- `C > 0.50`
- 最近 N 个任务中，同一模板连续出现次数超过 15 次

> 冷启动保护：最近任务数少于 50 时不触发。

---

#### 2. 触发与冷却

避免“为扩而扩”，必须限流：

- 每轮最多生成 1 批候选模板，每批 3 个。
- 两次触发间隔至少 30 分钟，或间隔至少 50 个任务。
- 生成/验证任务在 3 路并发中作为“低优先级任务”插空执行，不额外开线程。
- API 超时：
  - A 模型生成模板：`timeout=600s`
  - B 模型 turbo 生成模板：`timeout=300s`
  - 超时即放弃本批，不重试，进入冷却。

---

#### 3. 模板生成器

输入：

- 当前重复率最高的父模板
- 最近任务样本
- 已存在的任务模板池
- 认知池最新内容

生成策略：

对父模板执行“受控变异”：

```text
换场景、换对象、换约束、换目标、换边界、换输出格式
```

每次生成时，**强制注入认知池中新认知**：

- 每 10 个任务或每转结束，刷新认知缓存。
- 30 分钟内新增的认知，必须出现在本次模板生成的候选上下文中。
- 认知池不能只进不出，旧认知按使用频率和时间衰减淘汰。

> 生成结果只改变“执行路径”，不改变“业务目标”。

---

#### 4. 候选校验器

生成后的候选模板必须全部通过以下校验，才能进入注入阶段：

- 结构校验：字段完整、输入输出 schema 合法。
- 相似度去重：与现有模板 embedding 相似度 > 0.85 则拒绝。
- 成本校验：预估单次执行 token 成本不超过预算。
- 并发校验：新增模板后，并发数仍严格保持 3 路。
- 质量规则校验：**不同模型使用独立检测规则**。
  - B 模型 turbo：跳过 reasoning 占比检测，只检查格式、完整度、目标对齐。
  - A 模型：按 A 模型独立质量规则检测。
  - 防止把 B 模型正常的高 reasoning 占比误判为废稿。

---

#### 5. 注入器：三点同步

这是防止“自动调参全链路失效”的关键。

新增模板必须同时修改三个点，缺一不可：

| 点 | 动作 |
|---|---|
| 状态写入 | 模板落库，状态=active，记录父模板、触发原因、版本号、创建时间 |
| 执行读取 | 热刷新执行器内存中的模板注册表；每次任务执行前校验 registry version，强制读到新模板 |
| 生效验证 | 注入后立即执行 1 条冒烟任务，确认新模板可读、可跑、输出合规；失败则自动回滚为 inactive，并告警 |

> 配置修改后必须立即验证生效，不能只写库不刷新。

---

#### 6. 效果反馈

注入后跟踪接下来 M 个任务的重复率变化：

- 如果重复率下降，说明新模板有效，保留并继续生成。
- 如果重复率不变或上升，说明生成策略跑偏，回退模板，并调整变异维度。
- 如果模板废稿率过高：
  - 先判断是否模型特性误判；
  - B 模型 turbo 跳过 reasoning 占比检测；
  - 再判断模板本身质量问题，决定是否停用。

---

### 四、关键参数建议

| 参数 | 默认值 | 说明 |
|---|---|---|
| 检测窗口 N | 200 | 最近任务数 |
| 重复率阈值 R | 0.35 | 超过则触发 |
| 模板集中度阈值 C | 0.50 | 超过则触发 |
| 最小触发样本 | 50 | 冷启动保护 |
| 生成间隔 | 30 分钟 | 冷却 |
| 每批候选数 | 3 | 控制成本 |
| 相似度拒绝线 | 0.85 | 防止模板重复 |
| B 模型 timeout | 300s | 超时放弃 |
| A 模型 timeout | 600s | 超时放弃 |
| 并发上限 | 3 | 物理上限，不可突破 |

---

### 五、避坑映射

| 历史坑 | 本机制如何避开 |
|---|---|
| 配置修改后不生效 | 注入器强制“状态写入 + 执行读取 + 生效验证”三点同步 |
| API 超时 | 按模型预设 timeout：B=300s，A=600s，超时不重试 |
| 自动调参全链路失效 | 每次注入后立即冒烟验证，失败自动回滚 |
| 废稿误杀 B 模型 | B 模型跳过 reasoning 占比检测，独立质量规则 |
| 认知池只进不出 | 每 10 任务/每转刷新认知缓存；新认知 30 分钟内必须参与生成；旧认知衰减淘汰 |

---

### 六、落地要点

- 任务池动态扩充不是“越多越好”，而是**在稳定 3 路并发和有限算力内，让任务模板保持多样性和新鲜度**。
- 生成、校验、注入、验证全链路必须可观测：每次自动扩充都要留下审计日志，方便回滚。
- 如果算力预算真的为零，就关闭自动生成，只保留“重复率检测 + 告警”，避免为了进化而拖垮主任务执行。
