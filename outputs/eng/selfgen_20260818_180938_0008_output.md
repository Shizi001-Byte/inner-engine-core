# 任务类型: eng

按已有锚定推演，不重复论证。

**自动归档系统 = 一个三节点九转的 DAG 写入器，不是“任务复制器”。**  
输入任务在 Detect 被降解为事实块；Diff 只计算块级差异；Commit 以不可变顶点方式发布。最终目录不是文件夹，而是“索引的索引”。

## 1. 顶点模型

| 顶点 | 角色 | 内容 |
|---|---|---|
| `block` | 事实单元 | 内容 + `meta{source_task_id, created_at, schema_version}` |
| `index` | 有序索引 | 一组 `refs`，表示文件/目录/标签 |
| `tombstone` | 删除标记 | 被取代的旧顶点引用 |

- 块 ID = `sha256(content)`，内容寻址。
- 文件 = 一个 `index` 顶点，内容是 block ID 的有序列表。
- 目录 = 一个 `index` 顶点，内容是子目录/文件 index 的列表。
- 标签/类型 = 一个 `index` 顶点，内容是文件 index 的列表。

所以“存入对应目录”的本质是：**创建/更新目录 index 的引用，而不是复制整个文件**。

## 2. 三节点九转

```
Detect -> Diff -> Commit
```

每个节点三转，共九转：

| 节点 | 转 | 动作 | 产物/校验 |
|---|---|---|---|
| Detect | 1 | 读输入；读配置版本 | 配置版本必须匹配 |
| Detect | 2 | 分类、打标签、映射目录 | 候选分类结果 |
| Detect | 3 | 校验分类/标签/目录合法性 | `DetectResult` |
| Diff | 4 | 读目标目录已有 index/block | 现有事实集合 |
| Diff | 5 | 按块哈希计算差异 | `DiffPlan` |
| Diff | 6 | 校验差异计划 | 无冲突、无悬空引用 |
| Commit | 7 | 只写缺失/变化的 block | 块哈希校验 |
| Commit | 8 | 写 file/dir/tag index 和 tombstone | 引用关系更新 |
| Commit | 9 | 最终校验并发布目录 index | 发布即成功 |

任一转超时或校验失败，则熔断：  
**停止写入，不发布 index，不更新目录/标签。**  
已写入但未被引用的 block 可后续 GC；不会形成可见的半成品。

## 3. 自动分类、打标签、目录映射

Detect 第 2 转输出：

```
type       = "meeting" | "report" | "data" | "code" | ...
tags       = ["date:2025-04-11", "project:sync", "source:meeting"]
target_dir = "/archive/2025/04/meetings/"
model      = "B模型turbo" | "A模型"
```

- 分类/标签规则和目录映射都来自配置 index，不是硬编码。
- 新增配置必须同步修改读取点；每次 Detect 都读配置版本，避免“配置改了不生效”。
- 配置变更后立即跑 smoke test：用一条合成任务验证分类、标签、目录是否符合新配置，通过后才递增配置版本。

## 4. 超时熔断

- 分类模型调用超时按任务类型预设：
  - `B模型turbo`：300 秒
  - `A模型`：600 秒
- 超时后不是无限重试，而是熔断。
- 熔断后的处理：
  - 不写入最终目录；
  - 如分类失败，可写入 `pending/` 索引并打 `needs-review` 标签，但这同样必须走完整三节点九转，不能绕过校验直接落盘；
  - 最终目录保持旧状态，不产生混乱。

## 5. 校验机制与事实边界

每个 block 是一个不可变事实单元。提交前必须校验：

1. **哈希**：`block.id == sha256(block.content)`
2. **结构**：index 引用存在、无环、顺序正确；目录/标签引用完整
3. **来源**：同一 file index 内的 block 来源一致，`source_task_id` 与输入匹配
4. **版本**：配置版本、schema 版本一致

只有全部通过，Commit 第 9 转才发布。  
这保证：**同步的是事实，不是混乱。**

## 6. 防坑落实

| 历史坑 | 本系统对策 |
|---|---|
| 配置修改后未生效 | 配置 index + 版本号；每次 Detect 读配置；变更后 smoke test |
| API 调用超时 | B模型turbo 300s、A模型 600s；超时熔断 |
| 整个文件同步 | 块级 Diff，只上传缺失/变化块 |
| 把任务当进程记录 | 远端只有 block/index/tombstone 顶点，没有“同步任务”记录 |
| 写入混乱 | 提交前哈希/结构/来源校验；失败不发布 |

以上即设计引擎产出的自动归档系统骨架。实现时把“任务”视为临时输入，最终落地的都是不可变 DAG 顶点；目录、标签、类型都是 index，同步单位永远是块。
