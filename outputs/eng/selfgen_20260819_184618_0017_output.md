# 任务类型: eng

## 结论

V7.5 的“多线程 API 调用 + 串行后处理”不能只用一把裸 `Lock` 包住后处理函数，否则会出现：

- 两个线程同时进入后处理；
- 状态先读后写产生丢失更新；
- 有顺序要求时后完成的任务可能先处理；
- 异常/超时后卡死后处理链路。

推荐方案：**一把 `threading.Condition` 锁 + 状态机 + 专用串行后处理线程**。  
API 线程只负责并发调用 API 并更新任务状态，然后立即释放线程；后处理由一个专用线程统一按序消费，天然串行。

---

## 状态机

| 状态 | 含义 | 流转 |
|---|---|---|
| `PENDING` | 已提交 | → `API_CALLING` |
| `API_CALLING` | API 调用中 | → `API_SUCCEEDED` / `API_FAILED` |
| `API_SUCCEEDED` | API 成功，等待后处理 | → `PROCESSING` |
| `API_FAILED` | API 超时/异常/内容为空 | → `SKIPPED` |
| `PROCESSING` | 串行后处理中 | → `DONE` / `FAILED` |
| `DONE` | 后处理成功 | 终态 |
| `FAILED` | 后处理异常 | 终态 |
| `SKIPPED` | API 失败被跳过 | 终态 |

## 完整锁机制代码

```python
import threading
from concurrent.futures import ThreadPoolExecutor
from dataclasses import dataclass
from enum import Enum
from typing import Any, Callable, Optional


class TaskState(Enum):
    PENDING = "PENDING"
    API_CALLING = "API_CALLING"
    API_SUCCEEDED = "API_SUCCEEDED"
    API_FAILED = "API_FAILED"
    PROCESSING = "PROCESSING"
    DONE = "DONE"
    FAILED = "FAILED"
    SKIPPED = "SKIPPED"


TERMINAL_STATES = {TaskState.DONE, TaskState.FAILED, TaskState.SKIPPED}


@dataclass
class Task:
    task_id: str
    seq: int
    state: TaskState = TaskState.PENDING
    result: Any = None
    error: Optional[BaseException] = None


class SerialPostProcessingEngine:

    def __init__(
        self,
        max_workers: int = 8,
        post_processor: Optional[Callable[[Task], None]] = None,
    ):
        # 唯一锁：保护所有共享状态
        self._cond = threading.Condition()

        self._tasks: dict[str, Task] = {}
        self._seq_to_id: dict[int, str] = {}

        self._next_seq = 0          # 任务提交序号
        self._next_process_seq = 0  # 下一个允许后处理的序号

        self._stopping = False

        # API 调用线程池
        self._api_executor = ThreadPoolExecutor(
            max_workers=max_workers,
            thread_name_prefix="api-worker",
        )

        self._post_processor = post_processor or self._default_post_processor

        # 专用串行后处理线程
        self._post_thread = threading.Thread(
            target=self._post_loop,
            name="post-serial",
            daemon=True,
        )
        self._post_thread.start()

    def submit(self, task_id: str, api_call: Callable[[], Any]) -> None:
        with self._cond:
            if task_id in self._tasks:
                # 幂等：同一 task_id 不重复提交
                return

            seq = self._next_seq
            task = Task(task_id=task_id, seq=seq)
            self._tasks[task_id] = task
            self._seq_to_id[seq] = task_id
            self._next_seq += 1

        # API 调用交给线程池，不在锁内执行
        self._api_executor.submit(self._run_api, task_id, api_call)

    def _run_api(self, task_id: str, api_call: Callable[[], Any]) -> None:
        with self._cond:
            task = self._tasks[task_id]
            if task.state != TaskState.PENDING:
                return
            task.state = TaskState.API_CALLING
            self._cond.notify_all()

        try:
            # 锁外执行 API 调用，api_call 内部必须设置超时
            # B_turbo 建议 300s，A 模型建议 600s
            result = api_call()
            self._validate_result(result)
        except BaseException as e:
            with self._cond:
                task = self._tasks[task_id]
                if task.state != TaskState.API_CALLING:
                    return
                task.error = e
                task.state = TaskState.API_FAILED
                self._cond.notify_all()
            return

        with self._cond:
            task = self._tasks[task_id]
            if task.state != TaskState.API_CALLING:
                return
            task.result = result
            task.state = TaskState.API_SUCCEEDED
            self._cond.notify_all()

    def _post_loop(self) -> None:
        while True:
            with self._cond:
                while not self._stopping and not self._next_task_ready():
                    self._cond.wait()

                if self._stopping:
                    return

                task_id = self._seq_to_id[self._next_process_seq]
                task = self._tasks[task_id]

                if task.state == TaskState.API_FAILED:
                    # API 失败的任务直接跳过，不能阻塞后续任务
                    task.state = TaskState.SKIPPED
                    self._next_process_seq += 1
                    self._cond.notify_all()
                    continue

                # 只有 API_SUCCEEDED 会走到这里
                task.state = TaskState.PROCESSING
                task_to_process = task
                break

            # 锁外执行串行后处理
            try:
                self._post_processor(task_to_process)
            except BaseException as e:
                with self._cond:
                    task = self._tasks[task_id]
                    task.error = e
                    task.state = TaskState.FAILED
                    self._next_process_seq += 1
                    self._cond.notify_all()
                continue

            with self._cond:
                task = self._tasks[task_id]
                task.state = TaskState.DONE
                self._next_process_seq += 1
                self._cond.notify_all()

    def _next_task_ready(self) -> bool:
        task_id = self._seq_to_id.get(self._next_process_seq)
        if task_id is None:
            return False

        task = self._tasks[task_id]
        return task.state in (
            TaskState.API_SUCCEEDED,
            TaskState.API_FAILED,
        )

    def _validate_result(self, result: Any) -> None:
        # 坑：Responses API 可能把 token 全耗在 reasoning 上，content 为空
        if result is None:
            raise ValueError("API result is None")

        if isinstance(result, dict) and not result.get("content"):
            raise ValueError("Responses API content is empty")

    def _default_post_processor(self, task: Task) -> None:
        # 实际业务后处理，必须幂等
        pass

    def shutdown(self) -> None:
        with self._cond:
            self._stopping = True
            self._cond.notify_all()

        self._api_executor.shutdown(wait=True)
        # post_thread 是 daemon，不强制 join，避免后处理函数卡死导致进程退出卡住
```

---

## 锁机制关键点

1. **唯一锁是 `self._cond`**，保护 `_tasks`、`_seq_to_id`、`_next_seq`、`_next_process_seq`、`_stopping`。  
   不存在多把锁，因此没有锁顺序死锁问题。

2. **API 调用在锁外执行**。  
   不会出现“持锁等待网络”导致的全局阻塞。

3. **后处理在锁外执行，但只有一个专用线程消费**。  
   因此天然串行，不需要额外加 `processing_lock`。

4. **等待条件用 `while`，不用 `if`**。  
   防止虚假唤醒导致状态判断错误。

5. **状态变更必须重新查 `self._tasks[task_id]`**。  
   避免使用过期对象引用。

6. **API 失败/超时/内容为空统一转为 `API_FAILED`**，由后处理线程跳过并推进游标，防止卡死后续任务。

7. **后处理函数必须幂等**。  
   锁只能保证不并发，不能保证崩溃/重试时外部副作用只发生一次。

## 坑库映射

| 历史坑 | 本方案规避方式 |
|---|---|
| API 调用超时 | `api_call` 内部按模型预设 timeout；锁不覆盖网络等待 |
| 全局代理导致 ProxyError | API 调用层用 urllib 直连；如必须用 requests，显式 `proxies=None` |
| Responses API content 为空 | `_validate_result` 强制校验 content 非空，否则按 `API_FAILED` 处理 |
| 后处理线程被异常卡死 | API 失败会 `SKIPPED`；后处理异常会 `FAILED` 并推进游标，不让后续任务空转 |
| PID 文件竞态 | 与本锁无关；启动脚本应先 `kill -0` 确认旧 PID 已死，再写 PID，或用 `flock` |
