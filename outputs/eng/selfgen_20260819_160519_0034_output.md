# 任务类型: eng

## 任务池动态扩充机制设计

### 1. 目标与边界

**目标**：引擎运行中，基于最近任务的相似度计算“重复率”。当重复率超过阈值时，自动从重复任务中抽象出可复用任务模板，经校验后注入任务池，并实例化少量变体任务，形成：

```text
执行 → 重复率检测 → 聚类抽象 → 模板校验 → 注入任务池 → 灰度验证 → 反馈 → 再执行
```

的自进化闭环。

**边界**：本机制只优化“任务池的生成与调度”这一执行层，不替代业务大脑。生成的模板不能新增业务目标、不能绕过审批链、不能改变人工判断规则。若重复率持续不降，应告警并人工介入，而不是自动修改业务判断。

---

### 2. 总体架构

任务池分为两层：

- **TemplatePool**：存放可复用任务模板。
- **PendingQueue**：存放待执行的具体任务。

核心组件：

| 组件 | 职责 |
|---|---|
| `RepeatRateMonitor` | 滑动窗口检测任务重复率 |
| `TemplateGenerator` | 对重复任务聚类，抽象任务模板 |
| `TemplateValidator` | 锚点校验、模板级查重、模型规则校验 |
| `TemplateInjector` | 注入模板池，执行金丝雀验证 |
| `CognitivePool` | 缓存和注入认知，保证认知流动 |

---

### 3. 重复率检测

#### 3.1 任务指纹

不直接用文本全文比较，使用本地 MinHash + Jaccard 相似度，避免每次调用模型 API。

```python
def fingerprint(task):
    text = normalize(task.prompt)  # 小写、去标点、数字归一化
    shingles = {text[i:i+2] for i in range(len(text) - 1)}
    return MinHash(shingles)
```

#### 3.2 滑动窗口重复率

使用最近 N 个已完成任务作为窗口。

```python
def compute_repeat_rate(recent_tasks, similarity_threshold):
    if len(recent_tasks) < min_sample_size:
        return 0.0

    duplicate_count = 0

    for i, task in enumerate(recent_tasks):
        for j in range(i):
            if jaccard(task.fingerprint, recent_tasks[j].fingerprint) >= similarity_threshold:
                duplicate_count += 1
                break

    return duplicate_count / len(recent_tasks)
```

触发策略使用“滞回区间”，避免频繁抖动：

- 当 `repeat_rate > high_threshold` 时触发模板生成。
- 当 `repeat_rate < low_threshold` 时停止生成。
- 两个阈值之间保持不变。

### 4. 模板生成

#### 4.1 聚类重复任务

对窗口内任务构建相似度图，超过 `similarity_threshold` 则连边，取连通分量作为聚类。

只保留满足条件的簇：

- 簇大小 ≥ `min_cluster_size`
- 簇内任务 `project_id` 必须一致，否则拒绝。

#### 4.2 抽象模板

对同一个簇内的任务做文本对齐，提取公共部分和可变部分，生成模板。

示例：

```text
重复任务：
- 请分析量子计算的商业应用，要求500字
- 请分析碳中和的商业应用，要求500字
- 请分析脑机接口的商业应用，要求500字

生成模板：
请分析 {topic} 的商业应用，要求500字

slots:
  topic: [量子计算, 碳中和, 脑机接口]
```

如果本地抽象置信度不足，可调用模型辅助生成。调用时严格按模型预设超时：

- B 模型(turbo)：300 秒
- A 模型：600 秒

#### 4.3 防止模板过泛

计算模板特异性：

```text
specificity = 公共文本长度 / 模板总长度
```

如果 `specificity < template_specificity_min`，说明模板过于泛化，拒绝生成。

### 5. 模板校验与注入

#### 5.1 锚点校验优先

模板注入前，先做最小成本锚点校验：

- `template_id` 唯一且合法
- `prompt_hash` 不与已有模板重复
- `project_id` 必须存在且一致
- `model` 必须在模型白名单内
- `timeout` 必须符合模型预设：
  - B_turbo：300 秒
  - A：600 秒
- 对应模型的 endpoint / credential 必须有效

锚点校验失败时直接拒绝，不重试。因为起点错误不是链路复杂度问题。

#### 5.2 模板级查重

新模板必须与 TemplatePool 中已有模板计算相似度：

```text
template_similarity >= template_similarity_threshold
```

则拒绝注入，避免“越扩充越重复”。

#### 5.3 模型独立质量规则

不同模型必须使用不同质量检测规则：

- **B_turbo**：跳过 reasoning 占比检测。reasoning 占比 70%–82% 是正常特性，不能判为废稿。
- **A**：按 A 模型完整规则校验。

```python
def build_validation_rules(model):
    if model == "B_turbo":
        return {
            "check_reasoning_ratio": False,
            "check_output_complete": True,
            "check_schema": True,
        }

    if model == "A":
        return {
            "check_reasoning_ratio": True,
            "check_output_complete": True,
            "check_schema": True,
        }
```

#### 5.4 注入方式：影子模式 + 金丝雀验证

注入模板不能直接全量生效，必须：

1. 将模板写入 TemplatePool，状态为 `shadow`。
2. 用该模板实例化 1 条金丝雀任务。
3. 金丝雀任务成功且质量校验通过，模板状态改为 `active`。
4. 金丝雀任务失败或超时，模板状态改为 `retired`。

这样避免“生成模板后从未真正参与调度”，也避免坏模板污染任务池。

---

### 6. 生效验证与闭环反馈

#### 6.1 注入后必须验证“真正生效”

每次注入模板后，立即验证三点：

```python
# 1. 状态写入
task_pool.template_registry[template.template_id] = template

# 2. 执行读取
assert task_pool.template_registry[template.template_id].status == "shadow"

# 3. 生效验证
canary_task = instantiate(template, sample=True)
task_pool.submit(canary_task, priority="shadow")
```

如果不验证，就可能出现“配置已写入但行为无变化”的问题。

#### 6.2 金丝雀结果反馈

```python
def on_canary_finished(canary):
    template = get_template_by_canary(canary.task_id)

    if validate_execution(canary, template.validation_rules):
        template.status = "active"

        # 生成少量变体任务，真正扩充任务池
        variants = instantiate_variants(template, expansion_batch_size)
        for v in variants:
            if v.fingerprint not in recent_fingerprints:
                task_pool.submit(v, priority="normal")

        cognitive_pool.inject({
            "type": "template_activated",
            "template_id": template.template_id,
            "time": now(),
        })
    else:
        template.status = "retired"

        cognitive_pool.inject({
            "type": "template_retired",
            "template_id": template.template_id,
            "reason": canary.fail_reason,
        })
```

#### 6.3 认知池必须流动

- 每完成 10 个任务，或每轮结束，刷新认知缓存。
- 新认知 30 分钟内必须参与注入。

```python
if completed_count % 10 == 0 or round_ended:
    cognitive_pool.refresh()

# 模板生成时使用30分钟内的新认知
fresh_cognition = cognitive_pool.get_fresh(max_age=1800)
template = template_generator.generate(cluster, fresh_cognition)
```

避免认知池变成“只进不出的静态档案库”。

### 7. 配置项

| 配置 | 默认值 | 说明 |
|---|---:|---|
| `repeat_window_size` | 100 | 重复率统计窗口 |
| `repeat_min_sample_size` | 20 | 最小有效样本量 |
| `repeat_rate_high_threshold` | 0.30 | 重复率超过则触发 |
| `repeat_rate_low_threshold` | 0.15 | 重复率低于则停止 |
| `similarity_threshold` | 0.85 | 任务相似度阈值 |
| `min_cluster_size` | 3 | 最小聚类任务数 |
| `evolution_min_interval` | 3600 | 两次触发最小间隔秒数 |
| `max_templates_per_trigger` | 3 | 单次最多生成模板数 |
| `template_specificity_min` | 0.40 | 模板特异性下限 |
| `template_similarity_threshold` | 0.90 | 模板级查重阈值 |
| `expansion_batch_size` | 3 | 激活后实例化变体任务数 |
| `shadow_ttl` | 1800 | 影子模板最长存活秒数 |
| `cognitive_refresh_interval_tasks` | 10 | 每10任务刷新认知 |
| `cognitive_inject_max_age` | 1800 | 新认知30分钟内参与注入 |
| `B_turbo_timeout` | 300 | B模型turbo超时 |
| `A_timeout` | 600 | A模型超时 |
| `B_turbo_skip_reasoning_ratio` | true | B模型跳过reasoning占比检测 |

所有配置必须走配置中心，禁止硬编码。新增可配置参数时，必须同步修改三个点：

1. 状态写入
2. 执行读取
3. 生效验证

缺一不可。

### 8. 伪代码主流程

```python
class TaskPoolEvolver:
    def __init__(self, task_pool, config, cognitive_pool):
        self.task_pool = task_pool
        self.cfg = config
        self.cognitive_pool = cognitive_pool
        self.recent_tasks = deque(maxlen=config.repeat_window_size)
        self.recent_fingerprints = set()
        self.completed_count = 0
        self.last_evolution_at = 0

    def on_task_finished(self, task):
        if task.status != "completed":
            return

        task.fingerprint = fingerprint(task)
        self.recent_tasks.append(task)
        self.recent_fingerprints.add(task.fingerprint)
        self.completed_count += 1

        # 认知缓存刷新：每10任务或每转结束
        if self.completed_count % self.cfg.cognitive_refresh_interval_tasks == 0:
            self.cognitive_pool.refresh()

        self._maybe_evolve()

    def _maybe_evolve(self):
        if len(self.recent_tasks) < self.cfg.repeat_min_sample_size:
            return

        rate = compute_repeat_rate(
            self.recent_tasks,
            self.cfg.similarity_threshold
        )

        if rate <= self.cfg.repeat_rate_high_threshold:
            return

        if time.time() - self.last_evolution_at < self.cfg.evolution_min_interval:
            return

        clusters = cluster_tasks(self.recent_tasks, self.cfg.similarity_threshold)

        for cluster in clusters[:self.cfg.max_templates_per_trigger]:
            template = self._generate_template(cluster)

            if not template:
                continue

            ok, reason = self._validate_template(template)

            if not ok:
                log_warning("template rejected", reason)
                continue

            self._inject_with_canary(template)

        self.last_evolution_at = time.time()

    def _generate_template(self, cluster):
        fresh_cognition = self.cognitive_pool.get_fresh(
            max_age=self.cfg.cognitive_inject_max_age
        )

        template = template_generator.generate(
            cluster,
            fresh_cognition,
            model_timeouts={
                "B_turbo": self.cfg.B_turbo_timeout,
                "A": self.cfg.A_timeout,
            }
        )

        return template

    def _validate_template(self, template):
        # 锚点校验
        for field in ["template_id", "project_id", "task_type",
                      "prompt_template", "model", "timeout",
                      "validation_rules"]:
            if not template.get(field):
                return False, f"missing anchor: {field}"

        # 超时校验
        if template.model == "B_turbo":
            template.timeout = self.cfg.B_turbo_timeout
            template.validation_rules["check_reasoning_ratio"] = False
        elif template.model == "A":
            template.timeout = self.cfg.A_timeout
        else:
            return False, f"unknown model: {template.model}"

        # 模板级查重
        if template_pool.find_similar(template) >= self.cfg.template_similarity_threshold:
            return False, "duplicate template"

        return True, ""

    def _inject_with_canary(self, template):
        # 1. 状态写入
        self.task_pool.template_registry[template.template_id] = template

        # 2. 执行读取
        assert self.task_pool.template_registry[template.template_id].status == "shadow"

        # 3. 生效验证：金丝雀任务
        canary = instantiate(template, sample=True)
        self.task_pool.submit(canary, priority="shadow")
```

### 9. 防坑清单

- 新增配置必须同步修改：状态写入、执行读取、生效验证。
- API 调用必须预设 timeout：B 模型 turbo 用 300 秒，A 模型用 600 秒。
- B 模型(turbo) 的 reasoning 占比 70%–82% 是正常特性，跳过 reasoning 占比检测。
- 每 10 任务或每转结束刷新认知缓存，新认知 30 分钟内必须参与注入。
- 模板注入前先做锚点校验，锚点错误不重试。
- 模板注入后必须做可见性和可调度性验证。
- 新模板先影子模式 + 金丝雀任务，通过后才激活。
- 新模板必须通过模板级查重，防止任务池越扩充越重复。

---

该机制本质上是一个“执行层自进化闭环”：它让任务池更聪明地复用重复任务、生成多样化变体，但不替大脑做业务判断。
