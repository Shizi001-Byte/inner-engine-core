# 任务类型: eng

以下方案直接基于已有锚定推演，不重复论证。

## 一、总体结构

```
引擎输出
   │
   ▼
┌────────────────────────────────────────────┐
│           脑（元控制器）                     │
│   状态机调度 / 配置校验 / 超时兜底 / 重试    │
└────────────────────────────────────────────┘
   │
   ├── 阳轨：分类 → 打标签 → 落盘 → 索引
   └── 阴轨：配置校验、超时兜底、目录自愈、失败重试
```

整个系统是一个“开放、有界、循环”的负熵机制：

- **开放**：接收任意引擎输出，不预设来源；
- **有界**：所有输出必须经过配置、格式、大小、类型校验；
- **循环**：落盘后生成索引，索引反馈给分类/打标签规则，持续优化。

---

## 二、脑（元控制器）

元控制器不直接执行全部步骤，而是负责：

- 维护每个归档任务的状态机：
  `pending → classifying → tagging → storing → indexing → done`
- 任一状态失败，进入 `failed → retry / fallback`；
- 避免“单线死局”：每步独立队列、独立 worker，一个任务卡住不影响其他任务。

每个任务记录：

```json
{
  "artifact_id": "task_1234_ab12",
  "source_task_id": "engine_task_987",
  "raw_path": "/landing/xxx",
  "state": "tagging",
  "class": null,
  "tags": [],
  "target_path": null,
  "attempts": 0,
  "timeout_policy": "B-turbo:300s / A:600s"
}
```

## 三、阳轨：主流程

### 1. 引擎输出接入

- 监听引擎输出目录、消息队列或 API 回调；
- 先做边界校验：
  - 文件大小是否超限；
  - 文件类型是否在允许列表；
  - 是否携带任务元数据；
- 校验失败进入 `quarantine`，不进入主流程。

### 2. 自动分类

分类器由元控制器调度，支持：

- **规则分类**：文件名、扩展名、来源目录、任务类型；
- **模型分类**：对内容或摘要进行分类；
- **置信度兜底**：低于阈值时归入 `uncategorized`，等待人工/二次确认。

分类结果决定目录：

```text
archive_root/
  report/
  code/
  image/
  data/
  misc/
```

### 3. 打标签

标签来源：

- 引擎任务自带标签；
- 任务元数据：作者、项目、时间、任务类型；
- 内容提取：关键词、命名实体、文件名模式；
- 模型生成标签（与分类共用调用策略）。

标签处理：

- 统一小写；
- 去重；
- 限制标签数量与长度；
- 写入 `meta.json`。

### 4. 落盘

目录模板：

```text
archive_root/{class}/{yyyy}/{mm}/{artifact_id}/
  original_file
  meta.json
```

落盘采用**原子写**：

- 先写临时文件；
- 写入成功后 `rename` 到目标路径；
- 避免半文件残留。

### 5. 索引

落盘成功后立即生成索引：

```text
artifact_id
class
tags
target_path
checksum
created_at
indexed_at
```

索引写入失败不阻塞主流程，进入阴轨重试队列。

## 四、阴轨：保障机制

### 1. 配置校验

所有配置统一由配置中心/配置服务管理，不散落在各 worker 本地。

- 配置变更后生成新版本号；
- 所有读取点必须从配置中心读取；
- 配置版本不一致时自动刷新；
- 修改后立即执行 `dry-run`，验证分类、标签、目录映射是否生效。

> 这直接避免“配置修改后未生效、行为无变化”。

### 2. 超时兜底

所有外部调用必须显式设置超时，禁止默认无超时：

| 调用类型 | 超时时间 |
|---|---|
| B模型 turbo | 300 秒 |
| A模型 | 600 秒 |
| 本地落盘 | 30 秒 |
| 索引写入 | 30 秒 |

超时后：

- 标记当前步骤超时；
- 不直接丢弃；
- 进入重试或降级流程；
- 可先使用规则分类/标签，后续异步补模型标签。

### 3. 目录自愈

- 每次写入前执行 `ensure_dir(target_path)`；
- 如果目录缺失或不可写，按配置自动重建；
- 定期扫描目录结构，对比配置中的 `class → directory` 映射；
- 发现缺失目录自动创建；
- 发现孤立文件进入 `orphan` 队列，由元控制器决定归类或人工处理。

### 4. 失败重试

- 每个步骤失败后进入重试队列；
- 采用指数退避：`1m → 5m → 15m`；
- 最多重试 3 次；
- 超过最大重试次数：
  - 原始文件保留在落地区；
  - 任务状态标记为 `manual_review`；
  - 发送告警；
  - 保证不丢数据。

## 五、循环与反馈

索引不是终点，而是循环的一部分：

- 索引结果反馈给分类器和标签规则；
- 定期统计各分类的准确率、标签使用频率；
- 目录自愈依赖索引扫描实际文件；
- 配置优化后，通过元控制器触发一次“历史归档重扫”，让旧数据也能受益于新规则。

最终效果：

> 引擎无序输出 → 自动分类 → 打标签 → 有序落盘 → 可检索索引 → 持续复用。

这就是整个自动归档系统。
