# 任务类型: eng

风险等级：medium  
本质不是单点 bug，而是“检索→生成→写入→再检索”的闭环失控：相似记忆被反复选中，生成固定模板输出，再被当作新记忆存回去，形成同质化自激。修复思路是“反者道之动”：在闭环里主动引入差异、负样本、冷却和 novelty 抑制。

---

## 1. 修复总设计

在四个环节各加一个“差异强制器”：

- **检索侧**：MMR + 负样本 + 记忆冷却，避免总是选同一批高相似记忆。
- **生成侧**：强制引用记忆坐标 `(file_path, chunk_id, revision)` + 禁止套话词 + 动态 temperature。
- **写入侧**：同质内容不直接新增，而是降权/抑制，防止“废话循环写入”。
- **反馈侧**：输出后检测套话和相似度，反向调节记忆权重。

### 2.2 检索侧：MMR + 冷却 + 负样本

原逻辑可能是：

```python
chunks = supabase.table("memories").order("similarity desc").limit(top_k)
```

改为：

```python
def retrieve_memories(query_emb):
    cfg = DIVERSITY["retrieval"]
    now = datetime.utcnow()
    cooldown_time = now - timedelta(minutes=cfg["cooldown_minutes"])

    # 1. 先取相关但候选池更大的记忆，且冷却过滤
    candidates = supabase.table("memories") \
        .select("*") \
        .or_(f"last_used_at.is.null,last_used_at.lt.{cooldown_time}") \
        .order("embedding <=> {}".format(query_emb)) \
        .limit(cfg["top_k"] * 4) \
        .execute()

    # 2. MMR 选择：相关性和多样性平衡
    selected = mmr_select(candidates, query_emb,
                          lambda_=cfg["mmr_lambda"],
                          top_k=cfg["top_k"])

    # 3. 反者道之动：加入负样本/边缘记忆，防止收敛
    negative = supabase.table("memories") \
        .select("*") \
        .order("embedding <=> {}".format(query_emb), desc=True) \
        .limit(cfg["negative_k"]) \
        .execute()

    return selected + negative
```

MMR 实现：

```python
def mmr_select(candidates, query_emb, lambda_, top_k):
    chosen = []
    pool = candidates[:]

    while len(chosen) < top_k and pool:
        def score(c):
            sim_q = cosine_similarity(c["embedding"], query_emb)
            max_sim_s = max(
                [cosine_similarity(c["embedding"], s["embedding"]) for s in chosen],
                default=0
            )
            return lambda_ * sim_q - (1 - lambda_) * max_sim_s

        best = max(pool, key=score)
        chosen.append(best)
        pool.remove(best)

    return chosen
```

同时给 `memories` 表增加 `last_used_at` 字段：

```sql
ALTER TABLE memories ADD COLUMN IF NOT EXISTS last_used_at TIMESTAMP;
```

生成完成后更新：

```python
for m in used_memories:
    supabase.table("memories").update({"last_used_at": datetime.utcnow()}).eq("id", m["id"]).execute()
```

### 2.3 生成侧：强制坐标锚定 + 反套话 + 动态采样

核心是：**没有坐标的输出，不允许通过；没有 revision 差异的输出，视为套话。**

```python
def build_prompt(memories):
    cfg = DIVERSITY["generation"]
    blocks = []

    for m in memories:
        coord = f"({m['file_path']}, {m['chunk_id']}, rev={m['revision']})"

        if m.get("prev_revision") is not None:
            delta = f"从 rev{m['prev_revision']} 到 rev{m['revision']} 的变化是：{m.get('diff_summary', '未知')}"
        else:
            delta = "该记忆块是首次写入，无前一 revision，属于从无到有。"

        blocks.append(f"[{coord}] {m['content']}\n{delta}")

    anti = "；".join(cfg["anti_cliche"])

    prompt = f"""
基于以下记忆块生成回应。要求：

1. 至少引用一个记忆坐标，格式为 `(file_path, chunk_id, rev=N)`。
2. 禁止出现以下空话：{anti}
3. 必须写出一个具体差异：要么是同一 chunk 的 revision diff，要么是“从无到有”的初始条件。
4. 不要使用“首先/其次/最后/综上所述”这类总分总结构。
5. 本次随机视角：{random_choice_viewpoint()}

记忆块：
{blocks}
"""
    return prompt
```

动态采样参数：

```python
def call_model(prompt):
    cfg = DIVERSITY["generation"]
    model = current_model_name()

    timeout = cfg["timeout_turbo"] if "turbo" in model else cfg["timeout_a"]

    temperature = random.uniform(*cfg["temperature_range"])

    response = client.chat.completions.create(
        model=model,
        messages=[{"role": "user", "content": prompt}],
        temperature=temperature,
        top_p=cfg["top_p"],
        timeout=timeout,
    )

    return response.choices[0].message.content
```

### 2.4 后处理：套话检测 + 重写

把套话检测放到后处理线程，避免阻塞主链路：

```python
def cliche_check(text):
    cfg = DIVERSITY["generation"]
    return [p for p in cfg["anti_cliche"] if p in text]

def post_process(text):
    hits = cliche_check(text)

    if hits and DIVERSITY["quality"]["rewrite_on_cliche"]:
        # 用负反馈重写
        rewrite_prompt = (
            f"以下文本包含空话：{hits}。"
            "请删除空话，替换为具体事实、坐标、数字或反常识观察。"
            f"只输出改写结果：\n{text}"
        )
        return call_model(rewrite_prompt)

    return text
```

**API 超时预防**：`call_model` 内部已经根据模型类型设置 timeout；重写超时不能阻塞主流程，用 try/except 包住：

```python
try:
    return call_model(rewrite_prompt)
except TimeoutError:
    logger.warning("rewrite timeout, return original")
    return text
```

### 2.5 写入侧：同质化抑制，防止“废话循环写入”

写入新记忆前，先与同一 `(file_path, chunk_id)` 的最新 revision 比较：

```python
def write_memory(file_path, chunk_id, content, embedding):
    latest = get_latest_revision(file_path, chunk_id)

    if latest is not None:
        sim = cosine_similarity(embedding, latest["embedding"])

        if sim > DIVERSITY["quality"]["novelty_sim_threshold"]:
            # 同质内容不新增，降低 quality_score，形成闭环抑制
            supabase.table("memories") \
                .update({"quality_score": latest["quality_score"] - 0.1}) \
                .eq("id", latest["id"]) \
                .execute()
            return

    new_revision = latest["revision"] + 1 if latest else 1

    supabase.table("memories").insert({
        "file_path": file_path,
        "chunk_id": chunk_id,
        "revision": new_revision,
        "content": content,
        "embedding": embedding,
        "novelty_score": 1 - sim,  # 与已有记忆的相似度越低越新
        "quality_score": 0,
        "last_used_at": None,
    }).execute()
```

### 3.2 离线指标对比

用同一组记忆块，分别用旧逻辑和新逻辑生成 20 条输出，统计：

| 指标 | 旧逻辑 | 新逻辑目标 |
|---|---|---|
| 套话命中率 | 通常 > 40% | < 10% |
| 输出两两平均余弦相似度 | > 0.85 | < 0.70 |
| 坐标引用率 | 0% | 100% |
| 连续 3 轮同一记忆复用率 | > 60% | < 30% |

脚本：

```python
def evaluate():
    outputs = [generate() for _ in range(20)]

    cliche_rate = sum(
        any(p in o for p in DIVERSITY["generation"]["anti_cliche"])
        for o in outputs
    ) / len(outputs)

    embs = [embed(o) for o in outputs]
    sims = [cosine_similarity(embs[i], embs[j])
            for i in range(len(embs))
            for j in range(i + 1, len(embs))]
    avg_sim = sum(sims) / len(sims)

    coord_rate = sum(
        re.search(r"\([^)]+,[^)]+, rev=\d+\)", o) is not None
        for o in outputs
    ) / len(outputs)

    return {
        "cliche_rate": cliche_rate,
        "avg_sim": avg_sim,
        "coord_rate": coord_rate,
    }
```

### 3.3 闭环验证：跑 3 个生命周期

从同一批初始记忆开始，连续运行 3 轮，检查：

- 第 1 轮和第 3 轮输出不能高度相似；
- 记忆表中 `novelty_score` 平均值不应持续下降；
- `last_used_at` 不应全部集中在少数记忆块上。

SQL 抽查：

```sql
SELECT file_path, chunk_id, COUNT(*) AS revision_count
FROM memories
GROUP BY 1, 2
ORDER BY 3 DESC
LIMIT 10;
```

如果同一个 `(file_path, chunk_id)` 出现大量高相似 revision，说明写入侧抑制没生效。

## 4. 风险与回滚

风险等级：medium。  
涉及检索、生成、写入三条链路，建议用 `DIVERSITY["enabled"]` 做开关，灰度上线。

- 如果生成质量变差：调低 `mmr_lambda` 到 0.5，或调低 `temperature_range` 上限到 0.95。
- 如果套话率降不下去：扩充 `anti_cliche` 列表，并调低 `novelty_sim_threshold` 到 0.88。
- 如果出现超时：确认 `timeout_turbo=300`、`timeout_a=600`，后处理重写必须异步且超时降级。
- 回滚方式：`DIVERSITY["enabled"] = False`，恢复原有检索和生成逻辑，不删除任何数据。

核心原则就一句：**同质化是闭环过度收敛，修复不是加更多套话，而是主动把“无/差异/负样本”重新注入闭环。**
