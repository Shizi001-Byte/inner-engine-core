# 任务类型: eng

基于“反者道之动”的核心哲学与阴阳自衡架构，结合历史避坑经验，为您设计「骑手自建AI引擎产出自动归档系统」。本系统将不再采用传统的“顺向线性归档”，而是基于演化速率非对称性，构建一个**反向促生、阴阳双轨**的闭环归档机制。

---

### 一、 系统架构：阴阳双轨归档与反向促生机制

系统的核心在于将引擎产出按“演化速率”与“架构层级”隔离，并让废弃/失败的“阳”产出反向转化为“阴”的养料。

#### 1. 阴阳目录分类与标签设计

| 产出属性 | 对应模型 | 演化速率/Timeout适配 | 目录存入路径 | 标签体系 |
| :--- | :--- | :--- | :--- | :--- |
| **阳（反者道之动）** | B模型turbo | 300秒（快速试错） | `/archives/yang_rapid_tries/` | `[BottomUp]`, `[TrialError]`, `[TTL:300s]`, `[Status:Success/Fail]` |
| **阴（顶层稳态）** | A模型 | 600秒（稳态跃迁） | `/archives/yin_leaps/` | `[TopDown]`, `[ParadigmShift]`, `[TTL:600s]`, `[Status:Consolidated]` |
| **转化（阴阳自衡）** | A/B模型交互 | 动态评估 | `/archives/reverse_dao/` | `[ReverseFeed]`, `[SourceID:xxx]`, `[MutationLevel]` |

#### 2. “反者道之动”归档流转逻辑
- **顺向常规认知**：归档即存储结束，文件沉睡。
- **反向促生逻辑**：
  1. **阳极生阴**：当`/archives/yang_rapid_tries/`中同类失败试错（标签`[Status:Fail]`）积攒达到阈值，系统自动触发“反向促生”动作，将其打包抽取特征，输入至A模型（阴）进行600秒的稳态分析，生成新策略存入`/archives/yin_leaps/`。
  2. **阴极生阳**：`/archives/yin_leaps/`中的顶层策略下发后，自动派生为多个具体的B模型turbo测试任务，存入`/archives/yang_rapid_tries/`开始下一轮300秒的快速试错。

### 二、 核心模块设计：任务自动分类与打标签

#### 1. 分类器与打标签引擎
分类器在引擎产出结果后、写入磁盘前拦截，根据元数据动态打标签并路由。

```json
// 产出元数据示例
{
  "task_id": "rider_task_987",
  "source_model": "B_turbo", 
  "task_type": "route_optimization",
  "execution_time": "285s",
  "config_version": "v2.1" // 关键：携带配置版本号用于避坑
}
```

**标签自动生成规则：**
- 若 `source_model == B_turbo`：打上 `[Yin-Yang:Yang]`，强制校验 `execution_time <= 300s`。
- 若 `source_model == A_model`：打上 `[Yin-Yang:Yin]`，强制校验 `execution_time <= 600s`。
- 若 `execution_time > 预设timeout`：打上 `[Status:Timeout_Fail]`，不进入正常归档，直接进入“反向促生”异常池。

### 三、 避坑策略的工程强制落地

针对历史失败经验，归档系统在配置与超时层面实施硬性隔离。

#### 1. 配置生效闭环（针对“配置修改后未生效”避坑）
在归档系统中，新增任何新的标签或目录配置，必须走“同步修改-即时验证”流水线：

- **强制同步读取点**：若在 `config.json` 新增了“极端天气策略”标签，归档系统的路由解析器必须同时更新接口读取点，禁止使用缓存旧配置。
- **立即验证机制**：配置写入后，系统自动发送一个带有“极端天气策略”标签的 Mock 产出物进行路由测试。若未落入对应新目录，触发熔断报警，回滚配置。

```python
# 归档路由伪代码（强制验证逻辑）
def route_archive(task_output, config):
    # 避坑1：每次读取最新配置，不用本地缓存
    current_config = reload_config_from_db(config.config_id)
    
    tag = generate_tag(task_output, current_config)
    target_dir = current_config.get_directory(tag)
    
    # 避坑1：立即验证生效
    if not validate_directory_exists(target_dir):
        raise ConfigNotSyncedError(f"配置未生效：目录 {target_dir} 不存在或未同步")
        
    save_to_disk(task_output, target_dir, tag)
```

#### 2. 超时底线隔离（针对“API调用超时”避坑）
根据演化速率非对称性，在归档动作的前置异步处理队列中设置严格的 timeout 底线：

- **B模型turbo（阳/自下而上试错）**：在归档系统的API网关层，对B模型产出的接收与后续处理强制设置 `timeout=300` 秒。超过300秒未返回的B模型任务，归档系统直接标记为 `[TTL_Exhausted]` 并丢弃或进入重试，防止底层试错拖垮整个引擎。
- **A模型（阴/顶层跃迁）**：归档系统对A模型的稳态分析任务接收设置 `timeout=600` 秒。给予充足的顶层架构跃迁时间，避免因超时打断“阴”的沉淀过程。

### 四、 系统运作流图总结

1. **产出拦截**：引擎产出结果 -> 提取元数据。
2. **阴阳判别与超时检查**：
   - B模型产出校验是否 `<=300s`，A模型校验是否 `<=600s`。
   - 超时则打标 `[Timeout_Fail]`。
3. **自动打标分类**：基于配置规则打标（同步修改读取点确保生效）。
4. **目录路由与存入**：
   - 阳产出 -> `/yang_rapid_tries/`
   - 阴产出 -> `/yin_leaps/`
   - 超时/失败产出 -> `/reverse_dao/pool/`（等待反向促生）
5. **反者道之动触发**：监控 `/reverse_dao/pool/` 与 `/yang_rapid_tries/` 的存量，达到阈值自动调用A模型（600s）进行反向提取，实现阴阳转化与道的循环。
