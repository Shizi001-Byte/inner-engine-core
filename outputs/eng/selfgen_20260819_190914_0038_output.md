# 任务类型: eng

基于已有认知锚定，针对“AI引擎产出自动归档系统”中出现的「产出同质化，套话多」问题（风险等级：medium），我们从CAS（复杂适应系统）的视角进行推演与修复。

### 一、 问题归因分析
在「消耗→产出→反哺→更多消耗」的正反馈循环中，若引擎产出的内容同质化，意味着系统陷入了**局部最优解（信息熵极低）**。作为“麦克斯韦妖”的归档系统如果仅做简单分类，会将这些同质化内容大量标为“正常”并存入核心检索池，导致后续反哺时引擎参考的上下文高度重合，最终耗尽轻边际资源的有效价值（Token和算力被浪费在生成套话上）。

### 二、 修复方案：引入「信息熵与多样性」门控机制
在归档系统的“打标签”阶段，增加**同质化检测**与**多样性惩罚**。当检测到产出为套话/同质化内容时，将其降级存入“隔离池”，并在下一轮调度的提示词中注入负反馈，强制模型跳出舒适区。

#### 3. 调度引擎反哺逻辑修改（注入负反馈）
当归档系统打上 `HOMOGENEOUS_DETECTED` 标签后，调度引擎需在下次消耗Token时修改Prompt。

```python
# engine/scheduler.py
class AIScheduler:
    def generate_next_output(self, task_context):
        prompt = task_context.base_prompt
        
        # 检查上一轮产出是否被归档系统判定为同质化
        if self.last_archive_tag == "HOMOGENEOUS_DETECTED" and self.config.diversity_check.penalty_prompt_enabled:
            prompt += "\n[系统负反馈指令] 你上一轮的产出被判定为高度同质化/套话。请在本次产出中：1. 放弃常见的空泛排比句式；2. 引入具体的数据或垂直场景案例；3. 采用不同的论证结构。"
            
        # 调用大模型API（严格遵守timeout防避坑）
        timeout = self.config.archive_system.maxwell_demon.api_timeout[task_context.model_type]
        response = self.call_llm_api(prompt, timeout=timeout)
        return response
```

### 四、 验证方法（严格规避历史失败经验）

#### 1. 配置生效验证（针对避坑提醒1）
*   **操作**：将 `similarity_threshold` 从 0.85 修改为 0.50。
*   **验证点**：向归档系统输入一段普通的文本，观察日志中 `calculate_max_cosine` 计算出的实际相似度值。如果相似度 > 0.50 时，系统是否成功将其打上 `HOMOGENEOUS_DETECTED` 标签并存入 `quarantine_pool/` 目录。
*   **预期结果**：配置修改后立即生效，不重启服务也能动态读取新阈值。

#### 2. API超时预防验证（针对避坑提醒2）
*   **操作**：在 `get_embedding` 和 `call_llm_api` 调用处，检查传入的 `timeout` 参数。
*   **验证点**：模拟慢响应，确认A模型的请求在600秒后被强制中断，B模型turbo在300秒后被强制中断，且任务能正常抛出超时异常而不卡死主线程。

#### 3. 同质化修复效果验证（核心功能）
*   **Step 1 - 基线建立**：关闭多样性门控（`diversity_check.enabled = false`），连续运行引擎生成10次相同主题的内容，人工评估其重合度（预期会出现大量套话）。
*   **Step 2 - 开启门控**：开启多样性门控，连续运行引擎生成10次。
*   **Step 3 - 结果验证**：
    *   **检查归档目录**：`quarantine_pool/` 目录下应有被降级的同质化产出，`core_archive/` 目录下应是多样性内容。
    *   **检查Prompt注入**：查看API请求日志，确认在产出被判定为同质化后，下一次请求的Prompt中成功拼接了 `[系统负反馈指令]`。
    *   **人工评估**：输出的内容应当显著减少空泛词汇，结构呈现差异化，证明“麦克斯韦妖”成功通过门控机制降低了系统的信息熵，维持了CAS的自进化能力。
