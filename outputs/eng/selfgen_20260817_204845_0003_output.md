# 任务类型: eng

设计引擎产出的自动归档系统是提升团队效率、保障数字资产安全和便于后续检索的关键。一个完善的自动归档系统需要实现**“任务结束即触发、元数据提取即打标、规则引擎即路由、对象存储即落盘、索引同步即检索”**的闭环。

以下是该系统的完整设计方案：

---

### 一、 系统整体架构

系统分为五个核心层级：
1. **触发层**：监听设计引擎的任务状态变更。
2. **解析层**：提取任务参数、产出物特征和上下文信息。
3. **打标层**：通过规则引擎和AI视觉模型为资产生成多维度标签。
4. **路由层**：根据标签和预设规则，计算出目标存储路径。
5. **执行与索引层**：执行文件移动/复制，并写入数据库资产索引。

---

### 二、 核心流程详细设计

#### 1. 任务完成与触发机制
* **事件驱动**：设计引擎在任务跑完（成功/失败）后，向消息队列（如 Kafka/RabbitMQ）发送一条消息，包含 `Task_ID`, `User_ID`, `Project_ID`, `Job_Status`, `Output_File_URLs` 等。
* **防重入机制**：归档系统消费消息时，先检查 Redis 中该 `Task_ID` 是否已处理，避免重复归档。

#### 2. 自动分类与目录结构设计
建议采用**“时间 + 业务线 + 资产类型”**的层级目录结构，避免单目录文件数量爆炸。
* **目录规则**：`/Archive/{Year}/{Month}/{Project}/{EngineType}/{TaskID}/`
* **示例**：`/Archive/2023/10/双十一活动/图像超分/T_987654/output_4k.png`
* **冷热分层**：
  * 最近 30 天的产出物存在“热存储”（SSD/NAS），方便设计师快速预览。
  * 超过 30 天的自动迁移至“冷存储”（对象存储如 OSS/S3），热存储仅保留缩略图和软链接。

#### 3. 自动打标系统
标签分为三类，层层递进：

* **A. 确定性元数据标签（规则提取）**
  * **基础信息**：生成时间、引擎版本、任务耗时、文件格式、分辨率、文件大小。
  * **业务信息**：归属项目、发起人、任务名称、输入参数（如 Prompt、随机种子 Seed）。
* **B. 业务规则标签（规则引擎计算）**
  * 基于预设的正则或字典匹配。例如：任务名称包含“Logo”则打上`品牌设计`标签；分辨率>4K打上`超高清`标签；如果包含透明通道打上`带通道`标签。
* **C. 语义内容标签（AI 视觉识别 - 可选/进阶）**
  * 对于图像/视频产出，调用轻量级图像识别模型（如 CLIP 或内部微调模型），识别画面主体（如“人物”、“风景”、“赛博朋克风格”、“红色系”），补充语义标签。

#### 4. 路由与归档执行
归档系统根据打标结果决定文件去向：
* **正常归档**：通过标签映射到具体业务目录。
* **异常隔离**：如果任务状态为 `Failed` 或产出文件损坏，自动路由到 `/Quarantine/` 目录，并触发告警。
* **机密项目归档**：如果带有`机密`标签，路由到加密存储桶，并设置严格的访问权限。

### 三、 数据库索引设计

文件归档到目录后，必须建立数据库索引，否则文件夹结构无法支持复杂检索。建议使用 Elasticsearch 或 PostgreSQL (JSONB)。

**资产索引表结构 设计：**
```json
{
  "asset_id": "A_102938",           // 资产唯一ID
  "task_id": "T_987654",            // 关联引擎任务ID
  "file_name": "output_4k.png",
  "file_path": "/Archive/2023/10/.../output_4k.png", // 物理绝对路径
  "storage_type": "HOT",            // HOT / COLD
  "checksum": "md5...",             // 防重与校验
  "tags": [                         // 所有自动打上的标签
    "Image", "4K", "双十一活动", "赛博朋克"
  ],
  "metadata": {                     // 引擎产出的原始参数
    "engine_version": "v2.1",
    "seed": 123456,
    "prompt": "a cyberpunk city..."
  },
  "created_at": "2023-10-24T10:00:00Z",
  "archived_at": "2023-10-24T10:05:00Z"
}
```

### 四、 核心代码逻辑伪代码示例

以下为归档路由处理器的 Python 伪代码示例：

```python
def process_archive_event(event_message):
    task_id = event_message['task_id']
    
    # 1. 幂等校验
    if is_already_archived(task_id):
        return "SKIPPED"

    # 2. 提取元数据与文件信息
    task_meta = fetch_task_meta(task_id)
    output_files = task_meta['output_urls']
    
    for file_url in output_files:
        # 3. 打标引擎：收集标签
        tags = set()
        tags.update(extract_basic_tags(file_url, task_meta))  # 基础标签
        tags.update(apply_business_rules(task_meta))          # 规则标签
        if is_image(file_url):
            tags.update(ai_vision_tagger(file_url))          # AI语义标签
        
        # 4. 路由引擎：计算目标目录
        if task_meta['status'] != 'SUCCESS':
            target_dir = f"/Quarantine/{get_date_path()}/{task_id}/"
        else:
            project = task_meta['project_name']
            engine_type = task_meta['engine_type']
            target_dir = f"/Archive/{get_year()}/{get_month()}/{project}/{engine_type}/{task_id}/"
        
        # 5. 执行落盘 (下载并存储)
        local_path = f"{target_dir}{get_filename(file_url)}"
        download_and_save(file_url, local_path)
        move_to_cold_storage_if_needed(local_path) # 冷热分离判断
        
        # 6. 写入数据库索引
        asset_record = build_asset_record(task_id, local_path, list(tags), task_meta)
        db.insert(asset_record)
        
    # 7. 清理引擎临时缓存
    clean_engine_temp(task_id)
```

### 五、 关键设计考量与最佳实践

1. **解耦设计**：归档系统绝对不能阻塞设计引擎的主流程。引擎只负责生成并抛出事件，归档系统异步消费。如果归档系统宕机，任务依然能跑完。
2. **缩略图机制**：在归档时，系统同步生成一张低清缩略图（如 256x256），存放在 `/Thumbnails/` 目录。前端检索时加载缩略图，点击后再通过鉴权获取原图，大幅提升浏览体验。
3. **生命周期管理 (TTL)**：对于失败任务或临时测试任务产出的资产，自动打上 `ttl:7days` 标签，7天后由定时任务自动清理，释放存储空间。
4. **权限控制**：归档目录的权限应与业务系统权限打通。A部门的机密设计图存入特定目录，该目录在文件系统层面对B部门不可见。
5. **去重处理**：计算文件的 Hash（如 MD5 或 SHA1），如果发现数据库中已存在相同 Hash 的资产，不重复存储物理文件，而是创建软链接或增加引用计数。

通过这套系统，设计引擎跑完后的每一份产出物都能做到“有处寻、有标签、有路径、可检索”，真正实现数字资产的自动化沉淀。
