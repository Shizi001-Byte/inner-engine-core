# 任务类型: eng

## V7.5 方舟效能引擎：状态一致性锁机制方案

### 1. 问题推演

多线程 API 调用后做“串行后处理”，最容易踩到三类竞态：

1. **返回乱序**  
   请求按 `seq=1,2,3` 发出，但响应返回顺序可能是 `3,2,1`。如果每个线程拿到响应后直接进后处理，后处理顺序就会变成 `3,2,1`，导致旧数据覆盖新数据。

2. **check-then-act 非原子**  
   多个线程同时读到同一状态，比如“当前状态是 pending”，然后同时更新，造成状态机跳变丢失。

3. **错误加锁范围**  
   如果在 API 调用前加锁，API 调用期间一直持锁，多线程直接退化为串行，且任何慢请求都会阻塞全局。

**核心原则：并行调用时绝不持锁；后处理必须串行且按序；状态锁只在真正读写共享状态时短临界区持有。**

---

### 2. 总体架构

```text
调度线程
   │  提交任务
   ▼
ThreadPoolExecutor（N 个 worker）
   │  每个 worker 只做 API 调用，无锁
   ▼
OrderedResultBuffer（线程安全，按 seq 重排序）
   │  单线程消费者按 seq 取出
   ▼
PostProcessor（串行后处理，StateStore 内加锁更新）
```

关键点：

- API 调用线程只负责把结果放进 `OrderedResultBuffer`，不碰共享状态。
- 后处理只有一个消费者线程，天然串行。
- `OrderedResultBuffer` 用 `Condition` 保证按 `seq` 顺序取出，而不是按返回顺序取出。
- `StateStore` 用 `Lock` 保护认知池等共享状态，避免外部读线程看到中间态。

### 3. 完整代码骨架

```python
import json
import threading
import time
import urllib.request
from concurrent.futures import ThreadPoolExecutor


# 配置：历史坑位提醒
# B 模型 turbo 用 300 秒，A 模型用 600 秒
API_TIMEOUT = {
    "A": 600,
    "B": 300,
}


class OrderedResultBuffer:
    """按 seq 顺序输出的结果缓冲队列。

    解决多线程 API 返回乱序问题。
    """

    def __init__(self):
        self._cond = threading.Condition()
        self._pending = {}
        self._next_seq = 0
        self._closed = False

    def put(self, seq, result):
        """worker 线程把结果放入缓冲区。"""
        with self._cond:
            # 过期或重复响应，直接丢弃
            if seq < self._next_seq or seq in self._pending:
                return

            self._pending[seq] = result
            self._cond.notify()

    def get_next(self, timeout=None):
        """消费者线程按顺序取结果。

        只有 seq == next_seq 的结果才会被取出。
        如果 next_seq 还没到，就阻塞等待。
        """
        with self._cond:
            deadline = time.monotonic() + timeout if timeout else None

            while not self._closed and self._next_seq not in self._pending:
                if deadline is None:
                    self._cond.wait()
                else:
                    remaining = deadline - time.monotonic()
                    if remaining <= 0:
                        raise TimeoutError(
                            f"等待 seq={self._next_seq} 超时"
                        )
                    self._cond.wait(remaining)

            if self._next_seq not in self._pending:
                if self._pending:
                    raise RuntimeError(f"序列空洞，缺失 seq={self._next_seq}")
                return None

            result = self._pending.pop(self._next_seq)
            self._next_seq += 1
            return result

    def close(self):
        with self._cond:
            self._closed = True
            self._cond.notify_all()


class StateStore:
    """共享状态存储。

    所有对认知池的读写都走 apply，保证原子性。
    """

    def __init__(self):
        self._lock = threading.Lock()
        self._state = {
            "entries": {},
            "processed": set(),
        }

    def apply(self, fn):
        with self._lock:
            return fn(self._state)

    def snapshot(self):
        with self._lock:
            return json.loads(json.dumps(self._state))


class PostProcessor:
    """单线程串行后处理。"""

    def __init__(self, buffer: OrderedResultBuffer, state: StateStore):
        self._buffer = buffer
        self._state = state
        self._thread = None

    def start(self):
        self._thread = threading.Thread(target=self._run, daemon=True)
        self._thread.start()

    def join(self):
        if self._thread:
            self._thread.join()

    def _run(self):
        while True:
            item = self._buffer.get_next()
            if item is None:
                break

            seq, result = item
            try:
                self._handle(seq, result)
            except Exception:
                # 后处理异常不能影响后续任务
                # 生产环境应记录日志并告警
                pass

    def _handle(self, seq, result):
        # 历史坑：Responses API 可能 content 为空
        if result.get("error") or not result.get("content"):
            def mark_failed(state):
                state["entries"][seq] = {
                    "status": "failed",
                    "error": result.get("error") or "empty_content",
                }
                state["processed"].add(seq)

            self._state.apply(mark_failed)
            return

        content = result["content"]

        def update(state):
            # 幂等保护，防止重复响应
            if seq in state["processed"]:
                return

            # 这里写真正的后处理逻辑，例如更新认知池
            state["entries"][seq] = {
                "status": "done",
                "content": content,
            }
            state["processed"].add(seq)

        self._state.apply(update)


def call_api(seq, model, payload):
    """API 调用。

    历史坑：统一用 urllib 直连，不引入 requests，避免全局代理 ProxyError。
    """
    url = "https://ark.example.com/v3/responses"  # 按实际版本替换

    data = json.dumps(payload).encode("utf-8")
    req = urllib.request.Request(
        url,
        data=data,
        headers={
            "Content-Type": "application/json",
            "Authorization": "Bearer <TOKEN>",
        },
    )

    # 显式清空代理，避免环境变量里的全局代理
    opener = urllib.request.build_opener(
        urllib.request.ProxyHandler({})
    )

    timeout = API_TIMEOUT.get(model, 300)

    with opener.open(req, timeout=timeout) as resp:
        result = json.loads(resp.read().decode("utf-8"))

    # 历史坑：新 API 格式必须先验证 content 非空
    if not result.get("content"):
        raise ValueError("empty_content: output_tokens 可能耗尽在 reasoning 上")

    return result


def run_batch(tasks):
    """
    tasks: list of (seq, model, payload)
    返回后处理完成后的 StateStore 快照。
    """
    buffer = OrderedResultBuffer()
    state = StateStore()
    post_processor = PostProcessor(buffer, state)
    post_processor.start()

    def worker(seq, model, payload):
        try:
            result = call_api(seq, model, payload)
        except Exception as e:
            result = {
                "error": str(e),
                "content": None,
            }

        buffer.put(seq, result)

    with ThreadPoolExecutor(max_workers=8) as executor:
        futures = [
            executor.submit(worker, seq, model, payload)
            for seq, model, payload in tasks
        ]

        # 等待所有 API 调用结束
        for future in futures:
            future.result()

    # 所有结果都已放入 buffer，通知消费者退出
    buffer.close()
    post_processor.join()

    return state.snapshot()
```

### 4. 锁机制要点

| 同步原语 | 保护对象 | 持有时间 | 注意 |
|---|---|---|---|
| `OrderedResultBuffer._cond` | `_pending`、`_next_seq` | 仅 `put/get_next` 内 O(1) 操作 | 禁止在持锁时做 API 调用或后处理 |
| `StateStore._lock` | 认知池共享状态 | 仅 `apply` 内状态读写 | 保持临界区极短，禁止嵌套锁 |
| `ThreadPoolExecutor` 内部任务队列 | 任务提交与完成 | executor 管理 | 不要手动加锁 |

**锁顺序约定：**

- 当前代码没有嵌套锁，这是最安全的结构。
- 如果未来需要同时操作 buffer 和 state，必须固定顺序：先 `buffer._cond`，后 `state._lock`。
- 禁止反向加锁。
- 任何锁内禁止调用网络 API、禁止 `sleep`、禁止长时间计算。

### 5. 避坑落地点

1. **配置修改后未生效**  
   新增配置必须在启动时读取并注入到对应模块，修改后通过 `/health` 或自检接口确认当前生效值。

2. **API 超时**  
   `call_api` 使用 `opener.open(timeout=...)`，A 模型 600 秒，B 模型 300 秒。超时后 worker 会写入 error 结果，不会卡死后处理队列。

3. **Responses API content 为空**  
   `call_api` 内先校验 `content` 非空，后处理再兜底一次，避免空结果进入认知池。

4. **ProxyError**  
   代码里用 `urllib.request.build_opener(urllib.request.ProxyHandler({}))` 直连，不依赖 requests，天然避开全局代理。

5. **状态一致性验证**  
   生产环境建议加三个计数器：`out_of_order_count`、`duplicate_count`、`post_process_fail_count`，配合监控认知池条目总数变化曲线，确保没有并发毛刺。
