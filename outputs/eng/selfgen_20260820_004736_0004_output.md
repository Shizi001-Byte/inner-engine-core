## 一、竞态条件全景推演

基于已有认知链路 `文件变化检测→内容寻址去重→块级增量同步` 与硬约束"无记忆修改""恢复时不能遍历所有节点状态"，在 **多线程API调用 → 结果入队 → 串行后处理** 管线中，推演出 **6类竞态条件**：

```
┌─────────────────────────────────────────────────────────────────────┐
│                    V7.5 并发管线架构                                   │
│                                                                     │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐                            │
│  │ API线程A  │ │ API线程B  │ │ API线程C  │  ← 多线程并发调用           │
│  │(turbo300s)│ │(turbo300s)│ │(A模型600s)│                            │
│  └────┬─────┘ └────┬─────┘ └────┬─────┘                            │
│       │  RC-1        │  RC-1      │  RC-1      RC=竞态条件            │
│       ▼              ▼            ▼                                  │
│  ┌─────────────────────────────────────┐                             │
│  │       并发安全结果队列(Mem)          │  ← RC-2                     │
│  └─────────────────┬───────────────────┘                             │
│                    │                                                  │
│                    ▼                                                  │
│  ┌─────────────────────────────────────┐                             │
│  │      串行后处理引擎(单线程)           │  ← RC-3, RC-4               │
│  │  · 内容寻址去重                      │                             │
│  │  · 块级增量计算                      │                             │
│  │  · 冲突检测与异构自适应解决           │  ← RC-5                     │
│  └─────────────────┬───────────────────┘                             │
│                    │                                                  │
│                    ▼                                                  │
│  ┌─────────────────────────────────────┐                             │
│  │        文件系统写入层                │  ← RC-3(与检测器竞争)        │
│  └─────────────────┬───────────────────┘                             │

│                    ▼                                                  │
│  ┌─────────────────────────────────────┐                             │
```

### 竞态条件详表

| 编号 | 竞态名称 | 触发场景 | 后果 | 严重度 |
|------|----------|----------|------|--------|
| **RC-1** | API结果封装竞态 | 多线程同时完成API调用，各自封装Result对象入队 | Result对象内部字段不一致（如哈希与内容不匹配） | 高 |
| **RC-2** | 队列消费-生产竞态 | 后处理线程正在出队时，API线程并发入队，队列非线程安全 | 结果丢失、重复消费、队列结构损坏 | **致命** |
| **RC-3** | TOCTOU去重竞态 | 后处理检查"内容哈希H是否已同步"→另一路径也产生H→两者都判定未同步→重复写入 | 去重失效，写入冗余数据 | 中 |
| **RC-4** | 块级增量写入竞态 | 文件A和文件B共享数据块BK，后处理并行子任务同时写入BK | 块数据损坏、块索引不一致 | **致命** |
| **RC-5** | 冲突检测-解决原子性破坏 | 冲突检测发现冲突C→尚未执行异构自适应解决→另一线程修改了冲突涉及的状态→解决方案基于过时信息 | 冲突解决错误，数据不一致 | 高 |
| **RC-6** | 验证-同步会话交叉 | 会话S1验证进行中→新会话S2启动→S2的同步操作修改了S1正在验证的数据→验证结果不可靠 | 验证通过但实际不一致 | 高 |

## 二、锁机制总体设计

### 2.1 设计约束矩阵

| 硬约束 | 对锁机制的直接限制 | 设计对策 |
|--------|---------------------|----------|
| **无记忆修改** | 不能持久化锁状态到本地磁盘；重启后不能有遗留锁 | 所有锁仅存内存；引擎启动时锁表为空 |
| **恢复时不能遍历所有节点状态** | 不能在恢复时扫描文件系统重建锁状态 | 锁状态随需创建，不依赖全量扫描 |
| **不能维护本地"上次同步时间戳/文件树快照"数据库** | 不能用时间戳作为锁的版本判定依据 | 改用内容哈希作为锁键和版本依据 |

### 2.2 锁层次架构

```
┌─────────────────────────────────────────────────────────────────┐
│                        锁层次架构                                 │
│                                                                 │
│  Layer-0: 会话级令牌锁      [SessionToken Lock]                  │
│           · 隔离不同同步会话                                     │
│           · 内存态，重启即失效                                   │
│           · 解决 RC-6                                          │
│                                                                 │
│  Layer-1: 结果队列锁        [ConcurrentQueue + CAS]              │
│           · 无锁并发入队(MPSC模型)                              │
│           · 单消费者出队                                        │
│           · 解决 RC-1, RC-2                                   │
│                                                                 │
│  Layer-2: 内容寻址去重锁    [ContentHash Lock Strip]            │
│           · 以SHA-256为键的分段锁                               │
│           · 乐观检查+悲观写入                                  │
│           · 解决 RC-3                                          │
│                                                                 │
│  Layer-3: 块级写入锁        [Block-Level RWLock]                │
│           · 共享数据块读多写少→读写锁                           │
│           · 写入时排他                                         │
│           · 解决 RC-4                                          │
│                                                                 │
│  Layer-4: 冲突检测-解决原子锁 [Conflict Resolution Mutex]       │
│           · 检测→决策→执行 三步原子                             │
│           · 解决 RC-5                                          │
│                                                                 │
│  Layer-5: 文件变化检测豁免锁  [FS-Write Exemption]              │
│           · 写入期间豁免文件变化检测                             │
│           · 解决 RC-3(检测器竞争)                              │
└─────────────────────────────────────────────────────────────────┘
```

## 三、各层锁机制详细方案

### Layer-0: 会话级令牌锁 — 解决 RC-6

**核心思想**：每次同步会话生成一个运行时令牌（内存态），所有后续操作必须携带有效令牌。由于"无记忆修改"约束，令牌不持久化，重启后旧令牌自动失效。

```python
import threading
import uuid
import time
from dataclasses import dataclass, field
from typing import Optional, Dict, Set

@dataclass
class SessionToken:
    """内存态会话令牌 - 重启后自动失效"""
    token_id: str = field(default_factory=lambda: uuid.uuid4().hex)
    created_at: float = field(default_factory=time.time)
    active: bool = True
    # 绑定此会话正在验证的文件哈希集合
    verifying_hashes: Set[str] = field(default_factory=set)
    # 绑定此会话正在写入的文件路径集合
    writing_paths: Set[str] = field(default_factory=set)

class SessionTokenManager:
    """
    会话令牌管理器
    约束: 全内存态，重启后为空（满足无记忆修改）
    约束: 不遍历文件系统重建（满足恢复约束）
    """
    def __init__(self):
        self._lock = threading.RLock()
        self._active_tokens: Dict[str, SessionToken] = {}
        self._current_token: Optional[str] = None  # 当前活跃令牌
        
    def create_session(self) -> SessionToken:
        with self._lock:
            # 新会话创建时，旧会话标记为非活跃
            # 但不立即清理旧会话的验证结果（允许旧会话完成收尾）
            token = SessionToken()
            self._active_tokens[token.token_id] = token
            self._current_token = token.token_id
            return token
    
    def validate_token(self, token_id: str) -> bool:
        """验证令牌是否仍然活跃"""
        with self._lock:
            token = self._active_tokens.get(token_id)
            return token is not None and token.active
    
    def invalidate_session(self, token_id: str):
        """会话结束时失效令牌"""
        with self._lock:
            token = self._active_tokens.get(token_id)
            if token:
                token.active = False
            if self._current_token == token_id:
                self._current_token = None
    
    def register_verifying(self, token_id: str, content_hash: str):
        """注册正在验证的内容哈希"""
        with self._lock:
            token = self._active_tokens.get(token_id)
            if token and token.active:
                token.verifying_hashes.add(content_hash)
    
    def is_being_verified_by_other(self, current_token: str, content_hash: str) -> bool:
        """检查某内容哈希是否被其他活跃会话验证中"""
        with self._lock:
            for tid, token in self._active_tokens.items():
                if tid != current_token and token.active:
                    if content_hash in token.verifying_hashes:
                        return True
            return False
```

**RC-6 解决逻辑**：
- 会话S1验证内容哈希H时，先注册 `register_verifying(S1_token, H)`
- 会话S2启动后尝试同步H，检查 `is_being_verified_by_other(S2_token, H)` 返回True
- S2对H的操作进入等待队列，直到S1验证完成并释放

### Layer-1: 并发安全结果队列 — 解决 RC-1, RC-2

**核心思想**：采用 MPSC（Multi-Producer Single-Consumer）模型，API线程为多生产者，后处理为单消费者。入队用无锁CAS，出队单线程无需锁。

```python
import queue
import threading
from dataclasses import dataclass
from typing import Any, Optional

@dataclass(frozen=True)
class APIResult:
    """
    不可变结果对象 - 线程安全
    frozen=True确保构造完成后不可修改，消除RC-1
    """
    content_hash: str          # 内容SHA-256
    file_path: str             # 目标文件路径
    content: bytes             # API返回内容
    api_type: str              # 'turbo' | 'model_a'
    timestamp: float           # 完成时间戳（仅用于排序，不作为版本依据）
    session_token: str          # 绑定的会话令牌
    
class ResultQueue:
    """
    MPSC无锁队列
    生产者: 多个API线程
    消费者: 单个后处理线程
    """
    def __init__(self, maxsize: int = 10000):
        # Python的queue.Queue本身就是线程安全的MPSC实现
        # 底层用deque + threading.Lock + threading.Condition
        self._queue: queue.Queue[APIResult] = queue.Queue(maxsize=maxsize)
        self._shutdown = False
        self._producer_count = 0
        self._producer_lock = threading.Lock()
        
    def register_producer(self):
        """注册生产者（API线程启动时调用）"""
        with self._producer_lock:
            self._producer_count += 1
            
    def unregister_producer(self):
        """注销生产者（API线程结束时调用）"""
        with self._producer_lock:
            self._producer_count -= 1
            if self._producer_count == 0:
                # 所有生产者结束，通知消费者可以退出
                self._queue.put(None)  # 哨兵值
    
    def enqueue(self, result: APIResult, timeout: float = 30.0) -> bool:
        """
        生产者入队 - 线程安全
        RC-1解决: APIResult是frozen dataclass，构造时即不可变
        RC-2解决: queue.Queue.put内部有锁保护
        """
        if self._shutdown:
            return False
        try:
            self._queue.put(result, timeout=timeout)
            return True
        except queue.Full:
            # 队列满，记录告警但不阻塞API线程
            return False
    
    def dequeue(self, timeout: Optional[float] = None) -> Optional[APIResult]:
        """
        消费者出队 - 单消费者无需额外锁
        串行后处理线程独占调用
        """
        try:
            result = self._queue.get(timeout=timeout)
            return result
        except queue.Empty:
            return None
    
    def shutdown(self):
        self._shutdown = True
        # 唤醒等待的消费者
        self._queue.put(None)
```

**关键设计**：
- `APIResult` 使用 `@dataclass(frozen=True)`，构造完成后不可修改 → **RC-1 消除**
- `queue.Queue` 内部线程安全 → **RC-2 消除**
- 单消费者模型，后处理线程独占出队 → 后处理内部无需队列锁

### Layer-2: 内容寻址去重锁 — 解决 RC-3

**核心思想**：以内容哈希为键的分段锁（Lock Striping），避免全局锁瓶颈。采用"乐观检查→悲观获取锁→二次检查→写入"模式消除TOCTOU。

```python
import threading
from typing import Dict, Set, Optional
import hashlib

class ContentHashLockStrip:
    """
    内容寻址分段锁
    · 以SHA-256哈希值分段，减少锁竞争
    · 乐观检查+悲观写入，消除TOCTOU
    · 全内存态，重启清空（满足无记忆修改）
    """
    
    def __init__(self, strip_count: int = 256):
        # 分段锁：256个锁桶，按哈希值取模分配
        self._strips: list[threading.Lock] = [
            threading.Lock() for _ in range(strip_count)
        ]
        self._strip_count = strip_count
        
        # 已同步内容哈希集合（内存态）
        # 约束: 不能持久化，重启后为空
        self._synced_hashes: Set[str] = set()
        self._synced_lock = threading.Lock()
        
    def _get_strip_index(self, content_hash: str) -> int:
        """根据内容哈希计算分段索引"""
        # 用哈希值前8字符的int值取模
        return int(content_hash[:8], 16) % self._strip_count
    
    def check_and_sync(
        self, 
        content_hash: str, 
        sync_fn: callable,
        *args, **kwargs
    ) -> tuple[bool, any]:
        """
        原子化的检查-同步操作
        返回: (was_already_synced, sync_result)
        
        RC-3解决流程:
        1. 乐观检查: 快速判断是否已同步（无锁）
        2. 悲观获取: 获取对应分段锁
        3. 二次检查: 获取锁后再次检查（防止TOCTOU）
        4. 执行同步: 确认未同步后执行
        5. 标记完成: 加入已同步集合
        """
        # Step 1: 乐观检查（无锁快速路径）
        with self._synced_lock:
            if content_hash in self._synced_hashes:
                return (True, None)  # 已同步，跳过
        
        # Step 2: 悲观获取分段锁
        strip_idx = self._get_strip_index(content_hash)
        with self._strips[strip_idx]:
            # Step 3: 二次检查（消除TOCTOU窗口）
            with self._synced_lock:
                if content_hash in self._synced_hashes:
                    return (True, None)  # 另一线程已同步
            
            # Step 4: 执行实际同步
            result = sync_fn(*args, **kwargs)
            
            # Step 5: 标记为已同步
            with self._synced_lock:
                self._synced_hashes.add(content_hash)
            
            return (False, result)
    
    def is_synced(self, content_hash: str) -> bool:
        """非锁检查（可能存在TOCTOU，仅用于快速过滤）"""
        with self._synced_lock:
            return content_hash in self._synced_hashes
    
    def clear(self):
        """重启时清空所有状态"""
        with self._synced_lock:
            self._synced_hashes.clear()
```

**TOCTOU 时序分析**：

```
无锁方案（有Bug）:                    分段锁方案（正确）:
                                      
线程A: check(H) → 未同步              线程A: check(H) → 未同步
线程B: check(H) → 未同步              线程A: acquire_lock(H_strip)
线程A: sync(H) ← 写入                线程A: check_again(H) → 未同步
线程B: sync(H) ← 重复写入! 🔴        线程A: sync(H) ← 写入
                                     线程A: mark_synced(H)
                                     线程A: release_lock(H_strip)
                                     线程B: acquire_lock(H_strip) ← 等待
                                     线程B: check_again(H) → 已同步
                                     线程B: skip ← 正确跳过 ✅
```

### Layer-3: 块级写入读写锁 — 解决 RC-4

**核心思想**：共享数据块读多写少，使用读写锁（RWLock）。写入时排他，读取时共享。块级粒度而非文件级，减少锁竞争。

```python
import threading
from typing import Dict, Optional
from dataclasses import dataclass

@dataclass
class BlockInfo:
    """数据块元信息"""
    block_hash: str
    ref_count: int = 0  # 引用计数（多少文件引用此块）
    size: int = 0

class BlockLevelRWLock:
    """
    块级读写锁
    · 多个文件可共享同一数据块
    · 读取（校验/去重检查）用共享锁
    · 写入（新块创建/块更新）用排他锁
    """
    
    def __init__(self):
        self._block_locks: Dict[str, threading.RLock] = {}
        self._block_rwlock: Dict[str, _RWLockState] = {}
        self._registry_lock = threading.Lock()
        self._block_info: Dict[str, BlockInfo] = {}
    
    def _get_or_create_rwlock(self, block_hash: str) -> '_RWLockState':
        with self._registry_lock:
            if block_hash not in self._block_rwlock:
                self._block_rwlock[block_hash] = _RWLockState()
            return self._block_rwlock[block_hash]
    
    def read_block(self, block_hash: str, read_fn: callable, *args, **kwargs):
        """
        共享读 - 多个后处理子任务可同时读取同一块
        用于: 块校验、块去重检查、块内容比对
        """
        rwlock = self._get_or_create_rwlock(block_hash)
        with rwlock.read_lock():
            return read_fn(*args, **kwargs)
    
    def write_block(
        self, 
        block_hash: str, 
        write_fn: callable, 
        *args, **kwargs
    ):
        """
        排他写 - 同一块同一时间只有一个写入者
        用于: 新块创建、块内容更新
        
        RC-4解决: 文件A和文件B共享块BK时，
        写入BK的操作串行化，防止块数据损坏
        """
        rwlock = self._get_or_create_rwlock(block_hash)
        with rwlock.write_lock():
            result = write_fn(*args, **kwargs)
            # 更新块元信息
            with self._registry_lock:
                if block_hash in self._block_info:
                    self._block_info[block_hash].ref_count += 1
                else:
                    self._block_info[block_hash] = BlockInfo(
                        block_hash=block_hash,
                        ref_count=1
                    )
            return result
    
    def get_block_ref_count(self, block_hash: str) -> int:
        """获取块引用计数"""
        with self._registry_lock:
            info = self._block_info.get(block_hash)
            return info.ref_count if info else 0

class _RWLockState:
    """
    读写锁实现
    · 多读单写
    · 写者优先（避免写者饥饿）
    """
    def __init__(self):
        self._read_ready = threading.Condition(threading.Lock())
        self._readers = 0
        self._writers_waiting = 0
        self._writer_active = False
    
    class _ReadContext:
        def __init__(self, rwlock):
            self._rwlock = rwlock
        def __enter__(self):
            with self._rwlock._read_ready:
                while self._rwlock._writer_active or self._rwlock._writers_waiting > 0:
                    self._rwlock._read_ready.wait()
                self._rwlock._readers += 1
            return self
        def __exit__(self, *args):
            with self._rwlock._read_ready:
                self._rwlock._readers -= 1
                if self._rwlock._readers == 0:
                    self._rwlock._read_ready.notify_all()
    
    class _WriteContext:
        def __init__(self, rwlock):
            self._rwlock = rwlock
        def __enter__(self):
            with self._rwlock._read_ready:
                self._rwlock._writers_waiting += 1
                while self._rwlock._readers > 0 or self._rwlock._writer_active:
                    self._rwlock._read_ready.wait()
                self._rwlock._writers_waiting -= 1
                self._rwlock._writer_active = True
            return self
        def __exit__(self, *args):
            with self._rwlock._read_ready:
                self._rwlock._writer_active = False
                self._rwlock._read_ready.notify_all()
    
    def read_lock(self):
        return self._ReadContext(self)
    
    def write_lock(self):
        return self._WriteContext(self)
```

### Layer-4: 冲突检测-解决原子锁 — 解决 RC-5

**核心思想**：冲突检测→异构自适应决策→执行解决，三步必须原子完成。使用单独的互斥锁保护整个冲突解决流程。

```python
import threading
from enum import Enum
from dataclasses import dataclass
from typing import Optional, Any

class ConflictType(Enum):
    CONTENT_DIVERGENCE = "content_divergence"    # 内容分叉
    METADATA_MISMATCH = "metadata_mismatch"      # 元数据不匹配
    BLOCK_CORRUPTION = "block_corruption"        # 块损坏
    PARTIAL_WRITE = "partial_write"              # 部分写入

@dataclass
class ConflictRecord:
    """冲突记录"""
    conflict_id: str
    conflict_type: ConflictType
    source_hash: str          # 源端内容哈希
    target_path: str          # 目标文件路径
    detected_at: float
    resolution: Optional[str] = None     # 解决方案
    resolved: bool = False

class ConflictResolutionMutex:
    """
    冲突检测-解决原子锁
    · 检测→决策→执行 三步原子化
    · 解决RC-5: 防止检测后、执行前的状态被其他线程修改
    """
    
    def __init__(self):
        self._resolution_lock = threading.Lock()
        self._pending_conflicts: Dict[str, ConflictRecord] = {}
        self._conflict_lock = threading.Lock()
    
    def detect_and_resolve(
        self,
        conflict: ConflictRecord,
        detect_fn: callable,      # 冲突检测函数
        decide_fn: callable,     # 异构自适应决策函数
        execute_fn: callable,     # 解决方案执行函数
    ) -> Any:
        """
        原子化的冲突检测-解决流程
        
        RC-5解决: 整个流程持有锁，防止其他线程在检测后修改状态
        """
        with self._resolution_lock:
            # Step 1: 冲突检测
            detected = detect_fn(conflict)
            if not detected:
                return None  # 无冲突，无需解决
            
            # Step 2: 异构自适应决策
            resolution = decide_fn(conflict)
            conflict.resolution = resolution
            
            # 注册到待解决冲突表
            with self._conflict_lock:
                self._pending_conflicts[conflict.conflict_id] = conflict
            
            # Step 3: 执行解决方案
            try:
                result = execute_fn(conflict, resolution)
                conflict.resolved = True
            finally:
                with self._conflict_lock:
                    self._pending_conflicts.pop(conflict.conflict_id, None)
            
            return result
    
    def get_pending_conflicts(self) -> list[ConflictRecord]:
        """获取待解决的冲突列表"""
        with self._conflict_lock:
            return list(self._pending_conflicts.values())
```

### Layer-5: 文件变化检测豁免锁 — 解决 RC-3（检测器竞争）

**核心思想**：后处理写入文件期间，文件变化检测器可能误判为"新变化"触发重复同步。通过豁免锁让检测器跳过正在写入的路径。

```python
import threading
from typing import Set, Dict
import os

class FSDetectionExemption:
    """
    文件变化检测豁免锁
    · 写入线程注册豁免路径
    · 检测器扫描时跳过豁免路径
    · 写入完成后注销豁免
    
    解决RC-3(检测器竞争): 
    后处理写入file_A时，检测器不应把file_A的变化当作新变化
    """
    
    def __init__(self):
        self._exemptions: Set[str] = set()
        self._lock = threading.RLock()
        self._path_to_token: Dict[str, str] = {}  # 路径→会话令牌
    
    def register_exemption(self, file_path: str, session_token: str):
        """注册写入豁免"""
        with self._lock:
            abs_path = os.path.abspath(file_path)
            self._exemptions.add(abs_path)
            self._path_to_token[abs_path] = session_token
    
    def unregister_exemption(self, file_path: str):
        """注销写入豁免"""
        with self._lock:
            abs_path = os.path.abspath(file_path)
            self._exemptions.discard(abs_path)
            self._path_to_token.pop(abs_path, None)
    
    def is_exempted(self, file_path: str) -> bool:
        """检查路径是否被豁免（检测器调用）"""
        with self._lock:
            abs_path = os.path.abspath(file_path)
            return abs_path in self._exemptions
    
    def get_exempted_paths(self) -> Set[str]:
        """获取所有豁免路径快照"""
        with self._lock:
            return set(self._exemptions)
```

```python
import hashlib

        """
        timeout = API_TIMEOUTS.get(api_type, 300)
        
        try:
            # 避坑: urllib直连，避免ProxyError

            content = response.read()

            if not content:
                raise ValueError(f"API {api_type} returned empty content")

            result = APIResult(
                content_hash=content_hash,
                file_path=file_path,
                content=content,
                api_type=api_type,
                timestamp=time.time(),
                session_token=session_token,
            )
            
            # 入队 (RC-2: queue.Queue线程安全)
            if not self.result_queue.enqueue(result):
                # 队列满，记录告警
                pass
            
            return result
            
        except urllib.error.URLError as e:
            return None
        except Exception as e:
            return None
    
    # ==================== 串行后处理层 (单线程) ====================
    
    def _serial_post_processor(self):
        """
        串行后处理主循环
        · 从队列消费APIResult
        · 依次执行去重→块级增量→冲突检测→写入→验证
        
        关键: 虽然后处理是串行的，但内部仍需锁保护

            result = self.result_queue.dequeue(timeout=5.0)
            if result is None:
                continue
            
            try:
                self._process_single_result(result)
            except Exception as e:
                pass
    
    def _process_single_result(self, result: APIResult):
        """
        处理单个APIResult的完整流程
        串联Layer-2到Layer-5的所有锁
        """
        # Layer-0: 验证会话令牌
        if not self.session_mgr.validate_token(result.session_token):
            return  # 会话已失效，丢弃结果
        
        # Layer-5: 注册文件写入豁免
        self.fs_exemption.register_exemption(
            result.file_path, result.session_token
        )
        
        try:
            # Layer-2: 内容寻址去重 (RC-3解决)
            was_synced, _ = self.content_lock.check_and_sync(
                result.content_hash,
                self._do_sync,
                result
            )
            
            if was_synced:
                # 内容已同步，仅需更新引用
                self._update_reference(result)
            else:
                # 新内容，需要完整同步流程
                self._full_sync(result)
        
        finally:
            # Layer-5: 注销文件写入豁免
            self.fs_exemption.unregister_exemption(result.file_path)
    
    def _full_sync(self, result: APIResult):
        """

        """
        # 计算块级差分

        for block in blocks:
            self.block_lock.write_block(
                block.hash,
                self._write_block_data,
                block
            )
        
        # Layer-4: 冲突检测与解决 (RC-5解决)
        conflict = ConflictRecord(
            conflict_id=f"{result.content_hash}:{result.file_path}",
            conflict_type=ConflictType.CONTENT_DIVERGENCE,
            source_hash=result.content_hash,
            target_path=result.file_path,
            detected_at=time.time(),
        )
        
        self.conflict_lock.detect_and_resolve(
            conflict,
            detect_fn=self._detect_conflict,
            decide_fn=self._decide_resolution,
            execute_fn=self._execute_resolution,
        )
        
        # Layer-0: 无状态验证 (RC-6解决)
        self.session_mgr.register_verifying(
            result.session_token, result.content_hash
        )
        self._verify_sync(result)
    
    def _do_sync(self, result: APIResult):
        """实际同步执行函数"""
        # 写入文件内容
        pass
    
    def _update_reference(self, result: APIResult):
        """更新已同步内容的引用"""
        pass
    
    def _compute_block_diffs(self, content: bytes):
        """计算块级差分"""
        pass
    
    def _write_block_data(self, block):
        """写入块数据"""
        pass
    
    def _detect_conflict(self, conflict: ConflictRecord) -> bool:
        """冲突检测"""
        return False
    
    def _decide_resolution(self, conflict: ConflictRecord) -> str:
        """异构自适应决策"""
        return "skip"
    
    def _execute_resolution(self, conflict: ConflictRecord, resolution: str):
        """执行解决方案"""
        pass
    
    def _verify_sync(self, result: APIResult):
        """无状态验证"""
        pass
    
    def _get_api_url(self, api_type: str) -> str:
        """获取API URL"""
        return "https://ark.volcengine.com/api/v1/chat/completions"
    
    # ==================== 引擎生命周期 ====================
    
    def start(self, tasks: List[tuple], max_workers: int = 8):
        """
        启动同步引擎
        
        避坑: start_engine.sh PID文件竞态
        · 启动前检查旧PID是否存活 (kill -0)
        · 使用flock文件锁
        """
        # 创建会话令牌
        session = self.session_mgr.create_session()
        
        # 启动后处理线程
        self._running = True
        self._processor_thread = threading.Thread(

        self._processor_thread.start()
        
        # 多线程API调用
```

## 五、锁交互矩阵与死锁预防

### 5.1 锁获取顺序矩阵

```
获取顺序: Layer-0 → Layer-5 → Layer-2 → Layer-3 → Layer-4 → Layer-0(验证)

         L0(令牌)  L1(队列)  L2(去重)  L3(块锁)  L4(冲突)  L5(豁免)
L0(令牌)    -        ×        →        ×        ×        ×
L1(队列)    ×        -        ×        ×        ×        ×
L2(去重)    ←        ×        -        →        ×        ←
L3(块锁)    ×        ×        ←        -        →        ×
L4(冲突)    ×        ×        ×        ←        -        ×
L5(豁免)    ×        ×        →        ×        ×        -

→ : 持有当前锁后可能获取目标锁
← : 持有当前锁后可能释放并获取目标锁（不嵌套）
×  : 不存在嵌套关系
```

### 5.2 死锁预防策略

| 策略 | 实现方式 | 覆盖的锁组合 |
|------|----------|-------------|
| **锁排序** | 所有线程按固定顺序获取锁 | L2→L3→L4 |
| **超时退避** | 每个锁获取设30s超时，超时后释放已持有锁并重试 | 任意组合 |
| **不嵌套原则** | L0和L5不与L2/L3/L4嵌套，需先释放再获取 | L0/L5 vs L2/L3/L4 |
| **单消费者** | 后处理串行消费，队列锁不与处理锁嵌套 | L1 vs L2/L3/L4 |

```python
class TimedLock:
    """带超时的锁包装器"""
    def __init__(self, lock: threading.Lock, timeout: float = 30.0):
        self._lock = lock
        self._timeout = timeout
    
    def __enter__(self):
        if not self._lock.acquire(timeout=self._timeout):
            raise TimeoutError(
                f"Lock acquisition timed out after {self._timeout}s. "
                f"Possible deadlock detected."
            )
        return self
    
    def __exit__(self, *args):
        self._lock.release()
```

## 八、总结

本方案通过 **6层锁机制** 完整覆盖了V7.5方舟效能引擎在"多线程API调用+串行后处理"架构下的全部竞态条件：

| 层 | 锁类型 | 解决竞态 | 关键设计 |
|----|--------|----------|----------|
| L0 | 会话令牌锁 | RC-6 | 内存态令牌，重启自动失效，满足无记忆约束 |
| L1 | 无锁MPSC队列 | RC-1, RC-2 | frozen dataclass + queue.Queue |
| L2 | 内容寻址分段锁 | RC-3 | 乐观检查+悲观锁+二次检查消除TOCTOU |
| L3 | 块级读写锁 | RC-4 | 共享块读共享/写排他，写者优先 |
| L4 | 冲突解决互斥锁 | RC-5 | 检测→决策→执行三步原子化 |
| L5 | 检测豁免锁 | RC-3(检测器) | 写入期间豁免文件变化检测 |

**核心约束遵守**：所有锁状态仅存内存（无记忆修改），恢复时不遍历文件系统（按需内容哈希验证），不维护持久时间戳/快照（内容寻址替代）。
