# 自动归档系统设计（引擎可落地方案）

## 0. 系统目标

```
输入任务 → 自动分类 → 自动打标签 → 存入对应目录 → 校验归档结果
```

系统只负责“手脚”的高效执行，不替“大脑”做分类判断。  
所有关键锚点校验必须先于任何链路优化。

---

## 1. 核心原则

### 1.1 大脑/手脚分离

| 模块 | 职责 | 禁止 |
|---|---|---|
| 大脑 | 调用模型输出 `category`、`tags`、`confidence` | 禁止用规则猜测分类、禁止用目录名反推分类 |
| 手脚 | 建目录、移动文件、写标签、更新索引 | 禁止修改模型输出、禁止自动补标签、禁止自动选目录 |

### 1.2 锚点校验永远高于链路优化

进入任务链路前，先做最小成本校验：

- 项目 ID 是否正确
- 配置版本/哈希是否最新
- 根目录是否存在、可写、未越界
- API 端点是否可达
- 凭证是否有效
- 模型超时是否已配置
- 源文件是否存在、SHA-256 是否已记录

校验不通过，不进入下一步，不重试，不猜测。

---

## 2. 总体流程

```
任务进入
  ↓
P0 锚点校验
  ↓
大脑：模型分类 + 打标签
  ↓
决策校验：分类是否合法、标签是否合法、置信度是否达标
  ↓
手脚：写入对应目录 + 写入标签
  ↓
归档后校验
  ↓
成功 / 进入人工队列
```

---

## 3. 关键设计

### 3.1 配置管理：避免“修改后未生效”

所有配置通过统一配置中心加载，代码中只能通过 `Config.get("key")` 读取。

```python
# 错误示范：散落读取
target = "/archive/" + raw_config["dir"]  # 不推荐

# 正确示范：统一读取点
target = Config.get("category_map").get(category)
```

配置变更流程：

1. 修改配置
2. 执行 `validate_config()`
   - 校验 schema
   - 校验目录映射完整性
   - 校验 API 端点
   - 校验凭证
   - 校验超时配置
3. 执行 dry-run：用样本任务跑通全链路，不写真实目录
4. 校验 dry-run 结果
5. 发布新配置版本
6. 使用 canary 任务验证
7. 全量生效

新增配置时，必须同步注册读取点；否则 `validate_config()` 直接失败。

---

### 3.2 超时治理：避免 API 调用超时

模型超时统一配置：

| 模型 | 超时 |
|---|---|
| A 模型 | 600 秒 |
| B 模型 turbo | 300 秒 |

```python
MODEL_TIMEOUT = {
    "A": 600,
    "B_turbo": 300,
}
```

模型调用规则：

- 设置连接超时，例如 10 秒
- 设置读超时，按模型类型取 300s / 600s
- 使用 `request_id` 和幂等键
- 超时后立即取消，不无限等待
- 最多重试 1 次；重试仍超时则进入人工队列

---

### 3.3 自动分类与打标签

模型只负责“大脑”部分。

```python
def classify(task):
    model = select_model(task)
    timeout = MODEL_TIMEOUT[model]

    prompt = build_classify_prompt(task)
    response = call_model(
        model=model,
        prompt=prompt,
        timeout=timeout,
    )

    decision = parse_json(response)
    return decision
```

模型输出必须是严格 JSON：

```json
{
  "category": "invoice",
  "tags": ["finance", "2025", "need_review"],
  "confidence": 0.93,
  "reason": "包含发票号、金额、日期"
}
```

模型选择：

| 任务复杂度 | 使用模型 | 超时 |
|---|---|---|
| 简单任务 | B 模型 turbo | 300 秒 |
| 复杂/高准确任务 | A 模型 | 600 秒 |

### 3.4 决策校验

大脑输出后，手脚不能直接执行，必须先做合法性校验。

```python
def validate_decision(decision):
    if decision.confidence < CONFIDENCE_THRESHOLD:
        return manual_review("低置信度")

    if decision.category not in Config.get("category_map"):
        return manual_review("未知分类")

    unknown_tags = set(decision.tags) - Config.get("tag_dict")
    if unknown_tags:
        return manual_review("未知标签")

    return ok()
```

校验不通过，进入人工队列，不自动归档。

### 3.5 归档执行：手脚层

分类合法后，执行层负责“放进去”。

```python
def archive(task, decision):
    src = task.source_path

    # 根据分类映射到目标目录
    relative_dir = Config.get("category_map")[decision.category]
    dest_dir = (Config.get("archive_root") / relative_dir).resolve()

    # 防止路径越界
    if not dest_dir.is_relative_to(Config.get("archive_root").resolve()):
        raise PathTraversalError()

    # 创建目录（仅允许在明确配置下）
    if Config.get("create_dir"):
        dest_dir.mkdir(parents=True, exist_ok=True)

    # 生成安全文件名
    dest = dest_dir / f"{task.id}{src.suffix}"

    # 带校验移动
    move_with_checksum(src, dest)

    # 写标签
    write_tags(task.id, decision.tags)

    # 更新索引
    update_index(task.id, dest, decision)
```

执行层可以优化：

- 并发归档
- 流式拷贝
- 批量写标签
- 索引批量写入
- 目录缓存

但禁止：

- 自动选择其他目录
- 自动补充缺失标签
- 自动忽略未知分类

---

### 3.6 归档后校验

归档完成后必须验证：

```python
def verify_archive(task, dest):
    assert dest.exists()
    assert sha256(dest) == task.src_sha256
    assert read_tags(task.id) == task.tags
```

验证失败：

- 能回滚则回滚
- 不能回滚则标记失败并告警
- 不静默通过

---

## 4. 状态与异常处理

| 状态 | 触发条件 | 处理方式 |
|---|---|---|
| `blocked` | 锚点校验失败 | 告警，不执行 |
| `review` | 模型超时 / 低置信度 / 未知分类 / 未知标签 | 进入人工队列 |
| `failed` | 目录不存在 / 无权限 / 校验失败 | 告警，回滚或人工介入 |
| `archived` | 全部成功 | 记录审计日志 |

---

## 5. 总结

这套自动归档系统的关键不是“跑得快”，而是“不乱跑”。

- 模型负责分类、打标签：这是大脑
- 执行层负责移动、写入、校验：这是手脚
- 锚点校验永远优先
- 配置修改必须验证生效
- 超时必须按模型类型预设

最终效果：

> 任务自动分类、自动打标签、自动存入对应目录，并且每一步都可验证、可回滚、可追踪。
