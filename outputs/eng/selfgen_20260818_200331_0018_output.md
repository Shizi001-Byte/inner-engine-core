# 任务类型: eng

基于你给的避坑提醒和认知锚定，直接推演一套可落地的“自动归档系统”设计。核心是：**并发只做 API 调用，后处理必须单消费者；状态变更必须原子化；同步必须带版本仲裁**。

## 1. 总体架构

```text
设计引擎任务
   │
   ▼
Ingest：计算 content_hash，写入 content_blocks
   │
   ▼
并发调用分类/打标 API（A/B 模型，不同 timeout）
   │
   ▼
只写 classification_results 结果表，不直接改任务状态
   │
   ▼
单消费者后处理：原子 UPDATE archive_tasks
   │
   ▼
写入对应目录：archive/{分类}/{标签}/{task_id}.json
   │
   ▼
与 Supabase 记忆脑增量同步：指纹 + 内容寻址 + 乐观锁 + 三方仲裁 + 软删除
```

核心原则：

- API 线程/协程只负责“拿结果、写结果表”；
- 后处理只有一个消费者，所有状态变更用单条 SQL；
- 旧响应靠 `version` 丢弃，不允许旧数据覆盖新数据；
- 所有删除都是软删除/归档。

## 2. 数据模型

```sql
create table archive_tasks (
  id uuid primary key,
  seq bigint generated always as identity,
  content_hash text not null,
  status text not null default 'pending'
    check (status in ('pending','classifying','tagging','archived','deleted','failed')),
  classification text,
  tags jsonb,
  target_directory text,
  version integer not null default 1,
  deleted_at timestamptz,
  updated_at timestamptz default now()
);

create table classification_results (
  id bigint generated always as identity,
  task_id uuid not null,
  task_version integer not null,
  result jsonb not null,
  created_at timestamptz default now()
);

create table content_blocks (
  hash text primary key,
  content text not null,
  ref_count integer not null default 1
);

create table sync_state (
  id boolean primary key default true,
  local_fingerprint text not null default '',
  last_synced_seq bigint not null default 0,
  updated_at timestamptz default now()
);

-- 三方仲裁用的 base 快照
create table task_base_snapshot (
  task_id uuid primary key,
  classification text,
  tags jsonb,
  target_directory text,
  version integer,
  updated_at timestamptz
);
```

## 3. 配置管理：避免“配置修改后未生效”

所有配置统一走 `Config.get()`，禁止业务代码直接散落读配置。

```yaml
# config.yaml
classifier:
  timeouts:
    model-a: 600
    model-b-turbo: 300
  task_model:
    design_doc: model-a
    quick_note: model-b-turbo
  directory_rules:
    design_doc: archive/design
    quick_note: archive/notes
    default: archive/misc
```

```python
class Config:
    _data = load_config()

    @classmethod
    def get(cls, dotted_path):
        node = cls._data
        for key in dotted_path.split("."):
            node = node[key]
        return node

    @classmethod
    async def reload(cls):
        new = load_config()
        old = cls._data
        cls._data = new
        try:
            await verify_smoke()
        except Exception:
            cls._data = old
            raise
```

`verify_smoke()` 用一条已知任务验证分类和打标结果，失败自动回滚配置：

```python
async def verify_smoke():
    result = await call_classifier(SMOKE_TASK_CONTENT, model=Config.get("classifier.task_model.smoke"))
    assert result["classification"] == "smoke_expected"
    assert set(result["tags"]) == set(SMOKE_EXPECTED_TAGS)
```

这样新增配置项时，只要读取点都走 `Config.get()`，改完立即 smoke test，就不会出现“行为无变化”。

## 4. API 调用：超时控制 + 只写结果表

```python
async def ingest(task):
    content_hash = sha256(task["content"])
    await store_content_block(content_hash, task["content"])

    task_id = uuid4()
    await db.execute("""
        insert into archive_tasks (id, content_hash, status, version)
        values (:id, :hash, 'classifying', 1)
    """, {"id": task_id, "hash": content_hash})

    model = Config.get(f"classifier.task_model.{task['type']}")
    timeout = Config.get(f"classifier.timeouts.{model}")

    asyncio.create_task(call_classifier(task_id, 1, task["content"], model, timeout))
```

```python
async def call_classifier(task_id, version, content, model, timeout):
    try:
        result = await asyncio.wait_for(
            api.classify(content),
            timeout=timeout
        )
    except asyncio.TimeoutError:
        await db.execute("""
            update archive_tasks
            set status = 'failed',
                version = version + 1
            where id = :id
              and version = :version
              and status = 'classifying'
        """, {"id": task_id, "version": version})
        return

    # 不在这里做后处理，只写结果表
    await db.execute("""
        insert into classification_results (task_id, task_version, result)
        values (:task_id, :version, :result)
    """, {
        "task_id": task_id,
        "version": version,
        "result": result
    })
```

这里就是锚定中的关键：

- 每个线程拿到响应后不直接进后处理；
- 只投递到 `classification_results`；
- 后处理顺序即使变成 `3,2,1`，也由 `version` 条件拦截。

## 5. 单消费者后处理：原子 UPDATE 防止竞态

```python
async def postprocess_loop():
    last_id = 0

    while True:
        rows = await db.fetch("""
            select *
            from classification_results
            where id > :last_id
            order by id
            limit 100
        """, {"last_id": last_id})

        for row in rows:
            result = row["result"]
            classification = result["classification"]
            tags = result["tags"]
            directory = make_directory(classification, tags)

            updated = await db.fetchrow("""
                update archive_tasks
                set classification = :classification,
                    tags = :tags,
                    target_directory = :directory,
                    status = 'archived',
                    version = version + 1,
                    updated_at = now()
                where id = :task_id
                  and version = :task_version
                  and status = 'classifying'
                returning *
            """, {
                "task_id": row["task_id"],
                "task_version": row["task_version"],
                "classification": classification,
                "tags": tags,
                "directory": directory,
            })

            if updated:
                await write_directory_entry(updated)

            # 无论是否成功，都要推进 last_id，避免重复消费
            last_id = row["id"]

        await asyncio.sleep(0.1)
```

这里同时解决了：

- `check-then-act` 非原子问题：单条 `update ... where status=... and version=...`；
- 多线程状态机跳变丢失：`version + status` 双重条件；
- 旧数据覆盖新数据：旧结果的 `task_version` 不等于当前 `version` 时，直接丢弃。

## 6. 目录归档：内容寻址 + 指针文件

内容本体以 `content_hash` 存储，目录里只放指针文件，避免重复存储。

```python
async def store_content_block(content_hash, content):
    await db.execute("""
        insert into content_blocks (hash, content, ref_count)
        values (:hash, :content, 1)
        on conflict (hash) do update
        set ref_count = content_blocks.ref_count + 1
    """, {"hash": content_hash, "content": content})
```

```python
async def write_directory_entry(task):
    path = f"{task['target_directory']}/{task['id']}.json"
    pointer = {
        "task_id": str(task["id"]),
        "content_hash": task["content_hash"],
        "classification": task["classification"],
        "tags": task["tags"],
        "archived_at": task["updated_at"].isoformat(),
    }
    await storage.write(path, json.dumps(pointer, ensure_ascii=False))
```

目录规则来自配置：

```python
def make_directory(classification, tags):
    base = Config.get(f"classifier.directory_rules.{classification}")
    tag_part = "-".join(slugify(tag) for tag in tags)
    return f"{base}/{tag_part}"
```

## 7. Supabase 记忆脑增量同步

### 7.1 本地指纹状态

```python
async def compute_local_fingerprint():
    rows = await db.fetch("""
        select id, content_hash, version, status
        from archive_tasks
    """)
    raw = "\n".join(
        f"{r['id']}:{r['content_hash']}:{r['version']}:{r['status']}"
        for r in sorted(rows, key=lambda x: x["id"])
    )
    return sha256(raw.encode()).hexdigest()
```

### 7.2 三方冲突仲裁

同步时以 `task_base_snapshot` 为 base，本地和远端分别做三方合并：

```python
def three_way_merge(base, local, remote):
    if base is None:
        return local if local["version"] >= remote["version"] else remote

    if local["version"] == base["version"]:
        return remote
    if remote["version"] == base["version"]:
        return local

    merged = base.copy()

    for key in ("classification", "tags", "target_directory"):
        lv = local.get(key)
        rv = remote.get(key)

        if lv == rv:
            merged[key] = lv
        elif lv == base.get(key):
            merged[key] = rv
        elif rv == base.get(key):
            merged[key] = lv
        else:
            if key == "tags":
                merged[key] = sorted(set(lv or []) | set(rv or []))
            else:
                # 无法自动判定时进入人工仲裁队列
                raise Conflict(task_id=local["id"])

    merged["version"] = max(local["version"], remote["version"]) + 1
    return merged
```

### 7.3 增量同步流程

```python
async def sync_with_supabase():
    local_fp = await compute_local_fingerprint()
    remote_state = await supabase.from_("sync_state").select("*").eq("id", True).single()

    if local_fp == remote_state["local_fingerprint"]:
        return

    # 拉远端增量
    remote_changes = await supabase.from_("archive_tasks") \
        .select("*") \
        .gt("seq", remote_state["last_synced_seq"]) \
        .order("seq") \
        .execute()

    for remote_task in remote_changes.data:
        local_task = await db.get_task(remote_task["id"])
        base_task = await db.get_base_snapshot(remote_task["id"])

        try:
            merged = three_way_merge(base_task, local_task, remote_task)
            await db.save_merged_task(merged)
        except Conflict:
            await db.insert_conflict_queue(local_task, remote_task, base_task)

    # 推本地增量，远端更新必须带 version 乐观锁
    local_changes = await db.get_changes_since(remote_state["last_synced_seq"])
    for task in local_changes:
        result = await supabase.from_("archive_tasks") \
            .update({
                "classification": task["classification"],
                "tags": task["tags"],
                "target_directory": task["target_directory"],
                "version": task["version"],
            }) \
            .eq("id", task["id"]) \
            .eq("version", task["base_version"]) \
            .execute()

        if not result.data:
            # 远端被改过，重新拉取后做三方仲裁
            pass

    # 更新同步水位和指纹
    await db.update_sync_state(
        local_fingerprint=local_fp,
        last_synced_seq=remote_state["last_synced_seq"]
    )
```

### 7.4 软删除/归档

所有删除都走软删除：

```sql
update archive_tasks
set status = 'deleted',
    deleted_at = now(),
    target_directory = 'archive/deleted',
    version = version + 1
where id = :id
  and version = :version
```

同步时传播的是 tombstone，不是物理删除，避免已删除数据被旧数据“复活”。

## 8. 避坑对照表

| 历史坑 | 本设计对策 |
|---|---|
| 配置修改后未生效 | 统一 `Config.get()` 读取；`Config.reload()` 后立即 `verify_smoke()`，失败回滚 |
| API 调用超时 | 按任务类型配置 timeout：`model-a=600s`，`model-b-turbo=300s`；超时置为 `failed` |
| 后处理顺序 `3,2,1`，旧数据覆盖新数据 | API 只写结果表；后处理用 `version` 条件，旧版本结果直接丢弃 |
| `check-then-act` 非原子 | 所有状态变更用单条 SQL `update ... where status=... and version=...` |
| 多线程状态机跳变丢失 | `version` 乐观锁 + `status` 条件，每次更新 `version+1` |
| Supabase 增量同步覆盖 | 本地指纹 + 内容寻址块 + 三方冲突仲裁 + 软删除/归档 |

这套设计可以直接落到 Supabase：`archive_tasks`、`classification_results`、`content_blocks` 都是表，后处理用一个常驻 worker 跑，增量同步用 `sync_state` 控制水位线即可。
