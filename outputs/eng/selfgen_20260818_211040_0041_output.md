# 任务类型: eng

基于【已有认知锚定】中的“精气神三元迁移框架”（精：数据与配置底座；气：并发与执行调度；神：状态一致与逻辑推演），并结合【避坑提醒】中的历史失败教训，直接推演**引擎任务的链式推演机制与状态一致性方案**。

为解决多线程 API 调用后接串行后处理的竞态问题，并实现核心议题的递进拆解，设计以下 5 轮链式任务依赖图。

---

### 链式推演机制设计（5轮递进）

#### 第1轮：【精】基座准备与配置生效校验
*   **核心议题**：初始化推演上下文，确保配置全链路对齐。
*   **输入**：原始核心议题与用户初始配置。
*   **处理逻辑**：
    1. 解析议题，注入初始状态。
    2. **【避坑1预防】**：新增配置写入后，立即触发“读点探针”验证读取点是否同步更新，未生效则直接熔断重试，杜绝行为无变化。
*   **输出**：已生效的初始上下文（Context_v1）、任务拆解清单。

#### 第2轮：【气】多线程 API 并发调用与超时阻断
*   **核心议题**：基于 Context_v1 并发执行子任务 API 调用。
*   **输入**：上一轮输出的任务拆解清单。
*   **处理逻辑**：
    1. 开启线程池，按任务类型分发 API 请求。
    2. **【避坑2预防】**：强制预设合理 timeout。判定为 B模型turbo 的任务设定 300秒 超时，A模型任务设定 600秒 超时，超时即抛出异常并降级。
    3. **【认知锚定3/4预防】**：为每个线程分配独立的结果暂存区（ThreadLocal 或独立缓冲队列），禁止直接写入全局结果集，防止“线程 B 覆盖 A 的结果”。
*   **输出**：各线程独立的结果集集合（Partial_Results_Set）。

#### 第3轮：【气/神交割】状态汇聚与竞态规避
*   **核心议题**：从并发态安全过渡到串行态，保证状态一致性。
*   **输入**：Partial_Results_Set（各线程独立结果）。
*   **处理逻辑**：
    1. 引入 CyclicBarrier 或 CountDownLatch 等待所有 API 线程完成（或超时）。
    2. **【认知锚定3预防】**：串行后处理线程在 Barrier 释放后启动，通过原子操作将各独立缓冲区的结果按任务 ID 强校验合并至全局状态。
    3. 校验完整性：若发现“部分结果”或版本号对不上，触发该分支重试，绝不将旧结果带入下一轮。
*   **输出**：完整的、一致的聚合状态（Context_v2）。

#### 第4轮：【神】串行后处理与依赖推演
*   **核心议题**：基于聚合状态进行深度逻辑推演。
*   **输入**：Context_v2。
*   **处理逻辑**：
    1. 执行核心业务逻辑的后处理（数据清洗、逻辑推演、条件判断）。
    2. 动态生成下一轮推演的依赖图节点。判断是否达到终态，若未达到，构建新的子任务列表。
*   **输出**：推演中间结论（Context_v3）、下一轮任务依赖图。

#### 第5轮：【神】状态一致性校验与闭环输出
*   **核心议题**：推演结果一致性校验与最终输出。
*   **输入**：Context_v3。
*   **处理逻辑**：
    1. 执行状态机最终校验，比对推演前后状态是否符合精气神三元迁移框架的预期跃迁。
    2. 清理临时状态与线程残留，释放资源。
*   **输出**：最终推演结果（Final_Result）。

---

### 任务依赖图设计 (DAG)

为了保证上述链式推演的严格执行，设计如下任务依赖图（T代表Task节点）：

```text
[核心议题输入]
       │
       ▼
┌─────────────────────────────────────────────────────────┐
│ T1: [精] 配置初始化与读点校验                            │
│ (Action: 配置写入 -> 读点探针验证 -> 未生效则重试)       │
└─────────────────────────────────────────────────────────┘
       │ (依赖: Context_v1)
       ▼
┌─────────────────────────────────────────────────────────┐
│ T2: [气] 并发 API 调用池                                │
│ ┌──────────────┐   ┌──────────────┐   ┌──────────────┐  │
│ │T2-A: API调用  │   │T2-B: API调用  │   │T2-C: API调用  │  │
│ │(A模型,600s)  │   │(B模型,300s)  │   │(B模型,300s)  │  │
│ │(独立缓冲区)  │   │(独立缓冲区)  │   │(独立缓冲区)  │  │
│ └──────┬───────┘   └──────┬───────┘   └──────┬───────┘  │
└────────┼──────────────────┼──────────────────┼──────────┘
         │                  │                  │
         ▼                  ▼                  ▼
┌─────────────────────────────────────────────────────────┐
│ T3: [气/神] 同步屏障与状态汇聚                          │
│ (Action: Barrier 等待 -> 原子合并 -> 防覆盖/防部分读取) │
└─────────────────────────────────────────────────────────┘
       │ (依赖: Context_v2, 所有T2完成)
       ▼
┌─────────────────────────────────────────────────────────┐
│ T4: [神] 串行后处理与推演引擎                            │
│ (Action: 逻辑推演 -> 依赖图动态生成)                    │
└─────────────────────────────────────────────────────────┘
       │ (依赖: Context_v3)
       ▼
┌─────────────────────────────────────────────────────────┐
│ T5: [神] 一致性校验与闭环                               │
│ (Action: 状态比对 -> 资源回收 -> 最终输出)              │
└─────────────────────────────────────────────────────────┘
       │
       ▼
[最终结果输出]
```

### 方案防御点总结
1. **防配置失效**：T1 节点强制执行“写后即读”探针，彻底杜绝“修改未生效”现象。
2. **防超时挂死**：T2 节点按模型类型硬编码 Timeout（300s/600s），防止任务无限期等待。
3. **防竞态覆盖**：T2 节点所有 API 写入隔离暂存区，T3 节点使用同步屏障后串行合并，杜绝 B 覆盖 A 及后处理读取部分/旧结果的问题，保障状态一致性。
