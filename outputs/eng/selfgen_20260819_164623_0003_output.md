# 任务类型: eng

下面直接基于 V7.5 的已有锚定来设计，不再重复论证一致性原理，只说明任务池动态扩充机制如何与 V7.5 兼容。

## 一、闭环总览

```
任务执行
   ↓
结果提交（state_lock + generation 校验）
   ↓
重复率监控（滑窗 + 语义向量）
   ↓
触发条件判断（阈值 / 冷却 / 队列容量）
   ↓
候选任务模板生成（API 可并行）
   ↓
质量校验（B-turbo 独立规则）
   ↓
注入任务池（串行提交 + generation 递增）
   ↓
执行新任务 → 回到第一步
   ↓
若重复率未下降 → 调整生成策略/认知池反哺
```

目标是：**任务池不是静态的，而是根据运行时的重复率自动生成新任务模板并注入，形成“检测 → 生成 → 注入 → 反馈”的自进化闭环。**

---

## 二、重复率检测与触发

### 1. 重复率定义

重复率不是简单字符串重复，而是语义重复：

- 对已完成任务，取 `任务内容 + 成功指标` 做 embedding。
- 滑动窗口大小默认 `window_size = 100`。
- 当两个任务 embedding 余弦相似度 `> duplicate_similarity_threshold`（默认 0.92）时，视为重复。
- 重复率 = `窗口内重复任务数 / 窗口任务数`。

### 2. 触发条件

同时满足以下条件才触发扩充：

```text
duplicate_rate > duplicate_rate_threshold
len(window_tasks) >= min_window_size
now - last_expansion_at >= expansion_cooldown_minutes
inject_queue 未满
```

默认值建议：

| 参数 | 默认值 |
|---|---|
| `duplicate_rate_threshold` | 0.30 |
| `duplicate_similarity_threshold` | 0.92 |
| `min_window_size` | 30 |
| `expansion_cooldown_minutes` | 30 |
| `max_templates_per_expansion` | 5 |
| `new_template_similarity_threshold` | 0.85 |
| `template_generation_model` | B-turbo |
| `template_generation_timeout` | B-turbo 300s / A 600s |

## 三、候选任务模板生成

### 1. 输入

触发时，取重复任务簇作为生成上下文：

- 对窗口内重复任务做连通图聚类，形成若干个重复簇。
- 每个簇取 2~3 个代表性任务。
- 从认知池缓存中取相关认知作为约束和反哺上下文。

### 2. 生成方式

API 调用可以并行，例如：

- 每个重复簇并行调用 B-turbo 生成候选模板。
- B-turbo 超时用 `300s`。
- 如果 B-turbo 生成质量不足，可对复杂模板用 A 模型精修，超时用 `600s`。

### 3. 生成提示词骨架

```text
你是任务模板生成器。

已有重复任务簇：
{duplicate_cluster_examples}

认知池上下文：
{cognitive_context}

请生成 {n} 个新任务模板，要求：
- 与上述重复簇的语义相似度 < {new_template_similarity_threshold}
- 保留核心目标，但至少改变一个关键维度/约束/成功指标
- 每个模板包含：任务描述、约束条件、成功指标、验证优先级
- 当前 diversity_pressure = {diversity_pressure}
```

`diversity_pressure` 越高，生成时要求改变的维度越多。

## 四、质量校验：B-turbo 必须有独立规则

必须避免“B 模型 reasoning 占比 70-82% 被判为废稿”的问题。

质量校验器按模型类型区分：

| 校验项 | B-turbo | A 模型 |
|---|---|---|
| 必填字段完整 | ✅ | ✅ |
| 内容长度 >= 50 | ✅ | ✅ |
| 包含约束条件 | ✅ | ✅ |
| 包含成功指标 | ✅ | ✅ |
| reasoning 占比检测 | ❌ 跳过 | ✅ 0.1~0.9 |
| 与现有任务相似度 < 0.85 | ✅ | ✅ |
| 可执行性/可回答性 | ✅ | ✅ |

关键点：

```python
def quality_filter(template, model_type):
    if model_type == "B-turbo":
        # B 模型 reasoning 占比高是正常特性，必须跳过
        template.reasoning_ratio_check_enabled = False
    else:
        template.reasoning_ratio_check_enabled = True
```

B-turbo 生成的模板，如果只因为 reasoning 占比高被判废稿，会浪费一次生成周期；因此 B-turbo 的废稿规则必须独立维护。

## 五、注入任务池：串行提交 + generation 版本校验

新模板生成后，不能边生成边写任务池。必须走 V7.5 的单写者提交模型。

### 1. 注入伪代码

```python
def inject_templates(validated_templates):
    with state_lock:
        next_generation = task_pool.generation + 1

        for tpl in validated_templates:
            tpl.generation = next_generation
            tpl.status = ACTIVE
            save_template(tpl)

            task = Task(
                template_id=tpl.id,
                generation=next_generation,
                state=PENDING,
                version=1
            )
            task_pool.add(task)
            inject_queue.put(task.id)

        task_pool.generation = next_generation

    # 注入完成后触发认知池刷新
    cognitive_refresher.refresh()
```

### 2. 防止旧结果覆盖新状态

执行器提交结果时：

```python
def commit_task_result(task_id, result):
    with state_lock:
        task = get_task(task_id)

        # generation 不一致说明该结果来自旧版本任务，丢弃
        if result.generation != task.generation:
            return

        task.state = COMPLETED
        task.result = result
        task.version += 1
        save(task)
```

这就是“API 调用可并行，状态提交必须串行”的落地。

### 3. 有界队列削峰

`inject_queue` 必须有界，避免一次注入过多任务打爆执行器：

```python
inject_queue = Queue(maxsize=1000)

def enqueue_injection(task_id):
    try:
        inject_queue.put_nowait(task_id)
    except QueueFull:
        # 退避重试，不丢弃
        schedule_retry(task_id, delay=5s)
```

## 六、认知池刷新：避免“只进不出”

认知池不能变成静态档案库。必须让新认知快速参与任务生成和调度。

### 1. 刷新时机

- 每完成 10 个任务，刷新一次认知池缓存。
- 每个轮次结束，强制刷新一次。

```python
def on_task_committed(task):
    completed_since_last_refresh += 1

    if completed_since_last_refresh >= 10 or is_turn_end():
        cognitive_refresher.refresh()
        completed_since_last_refresh = 0
```

### 2. 新认知 30 分钟内参与注入

新生成的模板和反哺策略写入认知池后，必须立刻进入可消费状态：

```python
def write_cognitive_entry(entry):
    entry.created_at = now()
    entry.participate_before = now() + timedelta(minutes=30)
    entry.status = ACTIVE

    db.save(entry)
    cognitive_cache.set(entry.id, entry, ttl=30 * 60)
```

生成候选模板时，从认知池缓存取最近、优先级最高的 50 条作为上下文，确保新认知能参与生成。

### 3. 消费与淘汰

认知池缓存使用 TTL + 优先级：

- 每次刷新时只保留活跃且未过期的条目。
- 已经被消费过的条目标记 `last_used_at`。
- 超过 30 天未使用且优先级低的条目可以降级/归档，避免只进不出。

## 七、自进化反馈：调参必须全链路生效

### 1. 反馈指标

每次扩容后，不是立即判断效果，而是等待新任务执行一段时间后，再计算新的重复率：

```text
old_duplicate_rate = 触发时的重复率
new_duplicate_rate = 新任务完成 window_size * 0.8 个后的重复率

if new_duplicate_rate < old_duplicate_rate - 0.03:
    # 成功：当前生成策略有效
    cognitive_pool.add("template_strategy_effective")
else:
    # 失败：提高 diversity_pressure
    diversity_pressure += 0.1
    config.set("diversity_pressure", diversity_pressure)
```

### 2. 配置三点同步，避免“改了不生效”

新增或修改任何可配置参数，必须同步三个点：

| 配置项 | 状态写入 | 执行读取 | 生效验证 |
|---|---|---|---|
| `duplicate_rate_threshold` | 配置中心写入新值 | DuplicateMonitor 读取 | 修改后跑一次 `compute_duplicate_rate()`，确认阈值分支变化 |
| `diversity_pressure` | ExpansionController 反馈写入 | TemplateGenerator 生成时读取 | 修改后生成一个测试模板，确认提示词中压力值变化 |
| `max_templates_per_expansion` | 配置中心写入 | ExpansionController 注入时读取 | 触发一次扩容，确认注入数量变化 |
| `template_generation_timeout` | 配置中心写入 | API 调用客户端读取 | 修改后发一次测试调用，确认超时生效 |

关键原则：

- 业务代码禁止使用本地硬编码默认值覆盖配置中心。
- 所有配置读取点必须从 `ConfigService` 获取。
- 每次修改配置后，必须立即执行一次“验证命令”或“dry-run”，而不是只改配置不验证。

## 八、整体伪代码

```python
class TaskPoolEvolutionEngine:

    def on_task_committed(self, task):
        # V7.5 一致性已保证：task 是已提交状态
        self.duplicate_monitor.add(task)
        self.cognitive_refresher.on_task_committed(task)

        if self.duplicate_monitor.should_expand():
            self.expand()

    def expand(self):
        rate = self.duplicate_monitor.current_rate()
        snapshot = self.duplicate_monitor.duplicate_clusters()

        # 1. 并行生成候选
        candidates = self.template_generator.generate_candidates(
            clusters=snapshot,
            model=config.get("template_generation_model"),
            timeout=config.get("template_generation_timeout")
        )

        # 2. 质量校验
        validated = self.quality_filter.filter(candidates)

        # 3. 串行注入
        self.inject_templates(validated)

        # 4. 反馈记录
        self.record_expansion(rate)
```

## 九、避坑检查清单

1. **配置修改后必须生效**
   - 所有参数都做了“写入 → 读取 → 验证”三点同步。
   - 修改后立即触发一次验证，而不是等下次任务自然触发。

2. **API 调用超时**
   - B-turbo 生成候选：`timeout=300s`
   - A 模型精修/校验：`timeout=600s`
   - 并行调用时，每个调用单独设置超时，不共用一个总超时。

3. **B 模型废稿误杀**
   - B-turbo 跳过 `reasoning_ratio` 检测。
   - B-turbo 有独立的模板质量规则。

4. **认知池只进不出**
   - 每 10 任务或每轮结束刷新认知缓存。
   - 新认知 30 分钟内必须参与注入。
   - 缓存有 TTL，过期条目会被淘汰。

5. **自动调参全链路失效**
   - `diversity_pressure` 写入配置中心，生成器读取，并在下一次生成结果中验证。
   - 如果压力值变了但生成结果没变，立即告警。

---

这个设计形成完整闭环：**任务池重复率高 → 自动生成新模板 → 注入 → 执行 → 反馈 → 调整生成策略 → 再生成**。同时完全兼容 V7.5 的串行提交、generation 版本校验、有界队列削峰和认知池刷新机制。
