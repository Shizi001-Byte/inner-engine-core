# 任务类型: eng

针对 V7.5 方舟效能引擎，状态一致性问题的核心结论是：**API 调用可以并行，但状态提交必须串行**。  
所以锁机制不是“锁住 API 调用”，而是“锁住后处理提交”，并用版本号防止旧结果覆盖新状态。

---

## 一、竞态根因

多线程 API 调用后如果直接并发写共享状态，会出现：

1. **丢更新**：两个线程同时读到 `duplicate_count=10`，都写回 `11`，实际应为 `12`。
2. **脏读/脏写**：一个线程读 task_pool 时，另一个线程正在注入新模板，读到半成品。
3. **重复注入**：两个 API 结果同时发现同一个重复模式，同时生成同一个模板。
4. **超时/死锁**：持锁调用 API，导致其他线程等锁超时；或锁顺序不一致导致死锁。

---

## 二、完整锁机制设计

### 1. 并发模型

- API 调用：最多 3 路并发，用 `ThreadPoolExecutor(max_workers=3)` 或 `Semaphore(3)` 限制。
- 后处理：单线程消费结果队列，**天然串行**。
- 状态写：只在后处理线程内发生，配合 `state_lock` 保护。
- 所有网络 I/O 都在 `state_lock` 外执行，**绝不持锁调用 API**。

### 2. 锁/同步原语清单

| 原语 | 作用 |
|---|---|
| `ThreadPoolExecutor(max_workers=3)` | API 并发闸门，保证 3 路上限 |
| `result_queue` | 有界结果队列，解耦 API 与后处理 |
| `state_lock` | 保护 EngineState 所有共享字段 |
| `generation` | 状态版本号，防止旧结果覆盖新状态 |
| `pending_count + pending_cv` | 跟踪批次完成状态，避免提前退出 |
| `shutdown_event` | 优雅退出，防止死锁 |
| `flock` 文件锁 | 进程级单实例锁，避免 PID 文件竞态 |

## 三、核心伪代码

```python
import threading
import urllib.request
from concurrent.futures import ThreadPoolExecutor
from queue import Queue, Empty

class EngineState:
    def __init__(self):
        self.generation = 0
        self.task_pool = {}
        self.template_repo = {}
        self.metrics = {
            "api_calls": 0,
            "failures": 0,
            "empty_responses": 0,
            "duplicates": 0,
            "generated": 0,
            "stale": 0,
        }
        self.config = {
            "remaining_budget": 100,
            "duplicate_threshold": 0.3,
        }


class Engine:
    def __init__(self):
        self.state = EngineState()

        # 状态锁：保护 EngineState 所有可变字段
        self.state_lock = threading.RLock()
        self.state_cv = threading.Condition(self.state_lock)

        # API 并发闸门：3 路上限
        self.executor = ThreadPoolExecutor(max_workers=3)

        # 结果队列：有界，防内存膨胀
        self.result_queue = Queue(maxsize=6)

        # 批次完成跟踪
        self.pending_lock = threading.Lock()
        self.pending_cv = threading.Condition(self.pending_lock)
        self.pending_count = 0

        self.shutdown = threading.Event()

        # 单写者后处理线程
        self.post_thread = threading.Thread(target=self._post_loop, daemon=True)
        self.post_thread.start()

    # ---------- API 调用阶段 ----------

    def submit_batch(self, requests):
        with self.state_cv:
            gen = self.state.generation

        for req in requests:
            with self.pending_cv:
                self.pending_count += 1
            self.executor.submit(self._api_worker, req, gen)

    def _api_worker(self, req, gen):
        # 坑位：B模型turbo用300秒，A模型用600秒
        timeout = 600 if req.model == "A" else 300

        try:
            # 坑位：统一用 urllib 直连，不用 requests，避免 ProxyError
            with urllib.request.urlopen(req.url, timeout=timeout) as resp:
                content = resp.read().decode("utf-8")

            # 坑位：Responses API 可能 content 为空，必须验证
            if not content.strip():
                raise ValueError("empty content")

            result = ("api", gen, True, content, req.id, None)

        except Exception as e:
            result = ("api", gen, False, None, req.id, str(e))

        # 只投递结果，不碰共享状态
        self.result_queue.put(result)

    # ---------- 串行后处理阶段 ----------

    def _post_loop(self):
        while not self.shutdown.is_set():
            try:
                msg = self.result_queue.get(timeout=0.5)
            except Empty:
                continue

            try:
                self._post_process(msg)
            except Exception:
                with self.state_cv:
                    self.state.metrics["failures"] += 1
            finally:
                self.result_queue.task_done()
                with self.pending_cv:
                    self.pending_count -= 1
                    if self.pending_count == 0:
                        self.pending_cv.notify_all()

    def _post_process(self, msg):
        kind, gen, ok, content, req_id, error = msg

        with self.state_cv:
            # 版本校验：防止旧 API 结果覆盖新状态
            if gen != self.state.generation:
                self.state.metrics["stale"] += 1
                return

            if not ok:
                self.state.metrics["failures"] += 1
                return

            if not content or not content.strip():
                self.state.metrics["empty_responses"] += 1
                return

            # 重复检测
            fp = hash(content)
            if fp in self.state.template_repo:
                self.state.metrics["duplicates"] += 1
                return

            # 预算控制：算力非零成本
            if self.state.config["remaining_budget"] <= 0:
                return

            # 生成新模板并注入任务池
            template_id = f"tpl_{fp}"
            self.state.template_repo[fp] = template_id
            self.state.task_pool[template_id] = {
                "status": "pending_verification",
                "content": content,
            }

            self.state.metrics["generated"] += 1
            self.state.config["remaining_budget"] -= 1

            # 每次状态变更都递增版本号
            self.state.generation += 1

            # 唤醒等待任务的线程
            self.state_cv.notify_all()

    # ---------- 批次等待 ----------

    def wait_all(self, timeout=None):
        with self.pending_cv:
            self.pending_cv.wait_for(
                lambda: self.pending_count == 0,
                timeout=timeout
            )
```

## 四、死锁预防与避坑

1. **锁顺序固定**  
   统一顺序：`state_lock` → 释放 → `pending_lock`。  
   不要嵌套持锁。

2. **绝不持锁调用 API**  
   API 调用、验证调用、文件 IO 全部放在 `state_lock` 外。

3. **超时兜底**  
   - API 层：B 模型 300 秒，A 模型 600 秒。  
   - 锁层：如果使用 `Lock.acquire()`，可加 timeout，但不要依赖锁超时处理业务超时。

4. **不引入 requests**  
   统一 `urllib`，避免环境变量全局代理导致 `ProxyError`。  
   如果历史代码必须用 requests，按坑库约定显式传 `proxies=None`。

5. **PID 文件竞态**  
   引擎单实例锁不要用“先写 PID 再检查”，要用 `fcntl.flock`：

```python
import fcntl

lock_file = open("/var/run/v7_5_engine.lock", "w")
try:
    fcntl.flock(lock_file, fcntl.LOCK_EX | fcntl.LOCK_NB)
except OSError:
    raise RuntimeError("engine already running")
```

## 五、验证方案

修改后必须立即验证，不能只看“能跑”。

### 一致性不变量

- `pending_count` 最终归零。
- `generation` 每次提交只递增 1。
- `template_repo` 中不存在重复 `fp`。
- 结果总数守恒：

```text
api_calls = failures + empty_responses + duplicates + generated + stale
```

### 并发压测

- 3 个线程同时提交 API 请求。
- 模拟乱序返回：后发先至。
- 模拟超时、空 content、重复响应。
- 断言所有不变量成立。

---

结论：**V7.5 状态一致性 = 3 路并发 API + 单写者后处理 + state_lock 串行提交 + generation 版本校验 + 有界队列削峰**。这套机制可以在不突破 3 路并发上限的前提下，保证“检测重复率 → 生成新模板 → 注入任务池 → 验证生效”闭环的状态一致性。
