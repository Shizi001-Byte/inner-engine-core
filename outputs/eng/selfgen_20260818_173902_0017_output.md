# 任务类型: eng

基于已有认知锚定，直接给出可落地的自动归档系统设计。

## 一、系统定位

本系统属于**基础指令跟随层**：不要求 AI 自由发挥，只要求 AI 在预设边界内完成三个动作：

> **自动分类 → 打标签 → 存入对应目录**

整个系统是一个 **DAG 三节点串联流水线**，每个节点内部再拆三转，共九转，对应“九转玄功”。

---

## 二、总体架构

```text
配置中心 ConfigService
        │
        ▼
[ 分类节点 Classify ]  →  [ 打标节点 Tag ]  →  [ 归档节点 Archive ]
        │                       │                      │
   生成/验证冲突            记忆/遗忘冲突           自由/约束冲突
```

- 每个任务是一个 **DAG 顶点**，不是进程实例。
- 顶点之间严格串联：分类未完成，不打标；打标未完成，不归档。
- 文件/任务内容按 **块（block）** 同步，不按整个文件同步。

---

## 三、九转玄功映射

| DAG 节点 | 消解冲突 | 三转拆解 | 输入 | 输出 |
|---|---|---|---|---|
| 1. 分类节点 | 生成与验证 | ① 生成候选 → ② 事实校验 → ③ 边界裁定 | 任务内容块 | 分类 + 证据块 |
| 2. 打标节点 | 记忆与遗忘 | ① 标签抽取 → ② 记忆更新 → ③ 遗忘衰减 | 分类 + 内容块 | 标签集合 |
| 3. 归档节点 | 自由与约束 | ① 目录映射 → ② 约束检查 → ③ 原子写入 | 分类 + 标签 + 源文件 | 归档路径 |

每个节点三转，三节点共九转。

---

## 四、节点详细设计

### 节点 1：分类节点 Classify

对应冲突：**生成与验证**

AI 生成分类候选时容易幻觉，验证能力弱，所以必须让“生成”和“验证”分离。

三转：

1. **生成候选**  
   使用 B 模型（turbo）生成最多 3 个候选分类。  
   候选必须来自预设分类表 `categories.yaml`，禁止生成分类表之外的分类。

2. **事实校验**  
   每个候选分类必须有至少一个内容块作为证据。  
   证据块用哈希标识，例如 `sha256:block_123`。  
   低置信度候选交由 A 模型复核。

3. **边界裁定**  
   最终只输出一个分类。  
   若置信度低于阈值，或找不到证据块，则输出 `UNKNOWN`，进入人工队列。

```text
输出示例：
{
  "category": "财务",
  "confidence": 0.91,
  "evidence_blocks": ["sha256:block_123", "sha256:block_456"]
}
```

---

### 节点 2：打标节点 Tag

对应冲突：**记忆与遗忘**

标签系统要记住高频有用标签，也要遗忘低频噪声标签。

三转：

1. **标签抽取**  
   从内容块中提取关键词。  
   优先使用预设标签表 `tags.yaml`；若不在表内，则必须有足够分数和证据块才允许新增。

2. **记忆更新**  
   标签索引按块增量同步，只更新新增或变化的标签块，不重写整个标签索引。

3. **遗忘衰减**  
   长期未命中的标签降低权重。  
   低于阈值后移入冷标签库，不参与自动打标，但保留历史查询能力。

```text
输出示例：
{
  "tags": [
    {"name": "预算", "weight": 0.87},
    {"name": "季度", "weight": 0.72}
  ]
}
```

---

### 节点 3：归档节点 Archive

对应冲突：**自由与约束**

目录映射允许管理员配置规则，但最终写入必须受到严格约束。

三转：

1. **目录映射**  
   根据分类和标签生成目标目录。  
   默认规则：`/archive/{category}/{yyyy}/{mm}/`。  
   支持管理员自定义模板。

2. **约束检查**  
   检查目标目录是否满足：
   - 必须在 `archive_root` 下
   - 不包含路径穿越
   - 无非法字符
   - 权限足够
   - 不超配额

3. **原子写入**  
   按块复制到临时目录 `.tmp/`，校验所有块哈希后，再原子 `rename` 到目标目录。  
   失败则回滚，不产生半成品归档。

```text
输出示例：
{
  "archive_path": "/archive/finance/2026/05/report.pdf",
  "block_manifest": ["sha256:block_123", "sha256:block_456"]
}
```

## 五、关键机制

### 1. 从“进程实例”到“DAG 顶点”

任务不再是一个进程内对象，而是一个持久化的 DAG 顶点：

```text
TaskVertex {
  id: task_001
  type: archive_task
  state: CLASSIFIED
  config_version: 3
  block_manifest: [...]
  evidence_blocks: [...]
}
```

好处：

- 进程重启后可以从顶点恢复。
- 单个节点失败只重放该节点，不重跑全流程。
- 每次处理前检查 `config_version`，配置变更后自动感知。

---

### 2. 增量同步按“块”进行

所有文件切分为内容块：

```text
block_id = sha256(文件内容块)
```

归档时只传输目标端缺失的块，不传输整个文件。

这同时服务于分类证据：

- 分类必须引用证据块。
- 打标必须基于内容块。
- 归档必须按块校验完整性。

---

### 3. 配置即时生效，避免“修改后未生效”

所有规则读取点统一收敛到 `ConfigService`，禁止业务代码散落硬编码。

```text
ConfigService.version = 4
ConfigService.broadcast()
```

每个 DAG 顶点处理前检查：

```text
if task.config_version != ConfigService.version:
    reload_rules()
    task.config_version = ConfigService.version
```

修改配置后立即验证：

```text
POST /admin/validate
{
  "sample": "测试任务内容"
}
```

必须能观察到分类、标签、目录路径发生变化，否则视为配置未生效。

---

### 4. API 超时控制

| 模型 | 用途 | 超时时间 |
|---|---|---|
| B 模型（turbo） | 快速生成候选分类、候选标签 | 300 秒 |
| A 模型（完整） | 低置信度复核、边界判定 | 600 秒 |

超时后处理策略：

- 当前候选作废。
- 降级为规则匹配。
- 仍无法分类则进入人工队列，不阻塞整个 DAG。

---

## 六、避坑落地清单

- [ ] 新增配置必须同步修改所有读取点，统一走 `ConfigService`。
- [ ] 修改配置后必须执行 `validate` 验证立即生效。
- [ ] B 模型 turbo 调用超时设置为 300 秒。
- [ ] A 模型调用超时设置为 600 秒。
- [ ] 归档文件按块同步，不按整个文件同步。
- [ ] 任务状态持久化为 DAG 顶点，不依赖进程实例。
- [ ] AI 输出必须落在预设分类表、标签表、目录模板边界内。
- [ ] 每个分类和标签必须有证据块，否则拒绝进入下游节点。

---

## 七、最终效果

```text
输入任务/文件
    │
    ▼
分类节点：AI 生成候选 → 校验证据 → 边界裁定
    │
    ▼
打标节点：抽取标签 → 更新记忆 → 遗忘衰减
    │
    ▼
归档节点：目录映射 → 约束检查 → 原子写入
    │
    ▼
输出：/archive/{分类}/{年}/{月}/文件名
```

这就是一个同时解决：

- 幻觉生成与弱验证矛盾
- 记忆与遗忘矛盾
- 自由与约束矛盾

的自动归档系统。
