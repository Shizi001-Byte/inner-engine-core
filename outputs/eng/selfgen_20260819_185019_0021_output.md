# 任务类型: eng

以下默认接受已有认知，不重复论证熵增/省 Token 问题。直接给出可落地的「引擎产出自动归档系统」设计。

## 一、系统定位

自动归档系统是引擎的**熵减阀 + 记忆体**：

- 对已完成任务做分类、打标签、入目录；
- 为调度器提供“同质化识别”和“进化素材”；
- 不阻塞引擎主流程，不追求省 Token，只追求**省时间、保进化、防空转**。

适用边界：仅服务**生态型/轻边际成本供给主体**，重边际成本供给场景不适用本方案。

---

## 二、核心流程

```
任务完成事件
  → archive_queue（异步）
  → 分类器（元数据优先 / 规则 / B_turbo）
  → 打标器（元数据 / 规则 / 可选 B_turbo / A）
  → 目录路由（category/subcategory）
  → 原子写入 + 索引更新
  → 反馈调度器（同质化信号、高价值样本）
```

失败路径：

- 分类/打标超时 → 降级到 `_uncategorized/{task_id}`，不阻塞主流程；
- 写入失败 → 进入死信队列，人工/自动重试；
- 归档动作不能反向影响引擎任务执行。

---

## 三、分类体系

目录采用两级分类：

- 一级目录：`supply_type`，即供给主体类型
- 二级目录：`task_type`，即任务类型

```text
supply_type ∈ { llm_api, cloud, content, tool }
task_type   ∈ { inference, generation, scheduling, evaluation, ops }
```

分类策略：

1. **元数据优先**：从任务来源、队列名、API endpoint、函数名直接映射；
2. **规则兜底**：配置关键词表；
3. **LLM 补充分类**：元数据缺失时调用 `B_turbo` 分类，超时 300 秒；
4. 未知分类统一进 `_uncategorized`，不能因分类失败丢弃任务。

---

## 四、标签体系

标签写入 `tags.json`，便于索引和同质化感知。

必需标签：

```text
task_id
category
subcategory
model
timeout_preset
task_fingerprint
config_version
```

可选标签：

```text
action_type        : single / batch / stream / scheduled
is_redundant       : true/false
dup_group_id       : 同质化分组
value_score        : 进化价值评分
```

其中：

- `task_fingerprint` 是对任务意图、输入、参数做归一化后的哈希；
- `is_redundant` 和 `dup_group_id` 用于反馈调度器，避免任务池空转；
- 标签来源需要记录：`metadata / rule / model`，并带置信度。

---

## 五、目录结构

```text
archive_root/
  llm_api/
    generation/
      task_id_123/
        meta.json        # 来源、模型、耗时、调度参数
        tags.json        # 标签 + 置信度
        result.json      # 引擎产出完整原文
        trace.jsonl      # 归档处理轨迹
  cloud/
    scheduling/
      task_id_456/
        ...
```

如果使用对象存储，“目录”就是 Key 前缀。

注意：

- 归档必须保留**完整原文**，不为省存储做摘要；
- 写入采用“临时目录 + 原子 rename”，避免半成品；
- 路径中的分类/标签需要做安全清洗，防止路径穿越。

## 六、配置与读取点同步

这是历史失败点 1 的防复发设计。

配置统一放配置中心，所有读取点必须从配置中心取值，禁止硬编码。

| 配置项 | 读取点 | 修改后验证 |
|---|---|---|
| `archive.root` | `storage_routing.py` | 写一条测试任务，断言目录 |
| `archive.classifier.timeout` | `classifier_client.py` | 用 mock 超时，断言 300s 降级 |
| `archive.tagger.enabled` | `tagging_engine.py` | 切换开关后立即验证标签变化 |
| `archive.category_map` | `category_mapper.py` | 新增分类后跑 smoke test |

落地机制：

- 新增配置必须同步修改对应读取点，并注册到 `read_point_registry`；
- 每次配置变更后，执行 `archive-smoke --task sample_task --expect category=...`；
- 归档时把 `config_version` 写入 `tags.json`，方便追溯“这个归档是哪个配置版本产出的”。

---

## 七、超时策略

这是历史失败点 2 的防复发设计。

| 模型 | 分类 | 打标 | 摘要/价值评估 |
|---|---|---|---|
| B_turbo | 300s | 300s | 不默认启用 |
| A | 600s | 600s | 600s |

原则：

- 超时时间**根据任务模型类型**从任务元数据读取，不设全局默认；
- 归档 API 调用必须显式传 timeout；
- 超时后不无限重试，降级为规则归档，并标记 `archive_status=timeout_fallback`；
- 如果归档 API 超时率 > 10%，触发熔断，自动切换为纯规则模式。

---

## 八、熵减 / 进化反馈

归档系统不只是存储，还要反哺引擎。

1. **同质化感知**  
   通过 `task_fingerprint` 聚合，计算任务池类型熵和重复率。  
   如果同类任务反复出现且产出无新增量，则标记 `is_redundant=true`，调度器降低该任务优先级。

2. **进化素材供给**  
   归档后的高价值任务，可由 A 模型异步做价值评估，进入 few-shot 样本池或策略进化候选集，避免引擎空转。

3. **量化指标**  
   - 归档覆盖率：已归档任务 / 应归档任务  
   - 归档时效：p95(任务结束 → 归档完成)  
   - 同质化识别率：被标记重复任务数 / 实际重复任务数  
   - 配置生效延迟：配置发布 → 读取点生效  
   - 归档超时率：timeout_fallback / 总归档数  

---

## 九、总结

这个自动归档系统本质是：**异步、可降级、配置可验证、超时按模型区分、目录与标签分离、归档结果反哺调度器**。

它不解决重边际成本供给问题，也不为了省 Token 而压缩产出；它的目标是让引擎在轻边际成本生态里，**不超时、不空转、可进化、可追溯**。
