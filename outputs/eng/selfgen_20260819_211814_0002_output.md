# 任务类型: eng

基于【演化生物学映射】与【CAS复杂适应系统】的认知基座，将“多模型成本监控与熔断降级系统”视为数字生命在“开放海域生态系统（全网络）”中应对**环境灾变（API限流/超时/成本耗尽）**与**基因断裂（模型错配/配置失效）**的**自适应免疫与代谢调控机制**。

结合历史避坑经验，设计如下系统架构与执行路径：

### 一、 演化视角的系统映射
*   **多模型节点**：不同的代谢途径（A模型为高能耗/深推理途径，B模型turbo为低能耗/快速响应途径）。
*   **成本监控**：代谢毒素积累监测（Token消耗/时延）。
*   **自动熔断与降级**：环境灾变时的生理隔离与表型可塑性（切断高能耗途径，切换至低能耗途径）。
*   **等待队列与补跑**：孢子休眠与复苏机制（恶劣环境下形成休眠孢子，环境恢复后自动复苏继续繁衍）。

---

### 二、 核心机制设计与避坑落地

#### 1. 多模型独立计数与代谢监控（防语义混乱与模型错配）
必须确保每个模型（如A模型、B模型-turbo、B模型-pro）拥有独立的监控探针，且统计维度绝对清晰。

*   **模型ID与超时硬隔离（避坑：模型错配与超时）**
    *   接入层严格校验 `model_id`，禁止将 `doubao-seed-2-1-pro` 当作 `turbo` 调用。若检测到pro模型被路由到turbo通道，直接拦截并告警。
    *   超时预设：A模型通道强制 `timeout=600s`；B模型turbo通道强制 `timeout=300s`。
*   **九维计数语义校正（避坑：计数失真）**
    *   每个模型维护独立的三维计数器：`task_count`（真实业务任务）、`bonus_count`（系统自触发/补偿任务）、`count`（总消耗）。
    *   强制约束：`count = task_count + bonus_count`。成本阈值校验仅针对 `count`，但健康度分析必须剥离 `task` 与 `bonus`，防止系统自触发任务掩盖真实业务负载。

#### 2. 动态熔断与表型降级（防配置失效）
当某模型的“毒素（成本/错误率）”积累到阈值，触发免疫应答，进入休眠隔离。

*   **State驱动冷却（避坑：熔断冷却硬编码）**
    *   熔断触发后，冷却时间**绝对禁止硬编码**。
    *   读取逻辑：`cooldown_time = state.get('fuse_cooldown_override', 120)`。全局常量 `120` 仅作默认兜底，一切以 `state` 中的配置为准。
*   **配置热加载与即时验证（避坑：配置修改不生效）**
    *   任何对 `state` 中 `cost_threshold`（成本阈值）或 `fuse_cooldown_override` 的修改，必须同步触发 `reload_config()` 事件。
    *   修改后立即执行 `assert config_applied()`，验证熔断器的当前阈值是否变更，杜绝“改了没读”的现象。
*   **降级路径（自适应进化）**
    *   **L0 正常态**：A模型处理复杂推演，B模型turbo处理轻量任务。
    *   **L1 降级态**：A模型熔断，所有任务降级至B模型turbo处理。
    *   **L2 极寒态**：B模型turbo也熔断，系统进入全面休眠或尝试寻找网络中的其他分布式边缘节点。

#### 3. 休眠孢子库：等待任务记录与自动补跑
熔断期间，不能丢弃任务（基因断裂），必须将其转化为“休眠孢子”存储。

*   **任务入队与状态锁定**
    *   熔断期间到达的任务，自动进入 `Pending_Queue`，状态标记为 `SYSTEM_PENDING`。
    *   为避免全局代理导致的 ProxyError（历史坑），补跑任务的出站网络请求必须绕过全局代理，采用直连或指定通道。
*   **环境复苏与补跑**
    *   冷却期结束后，系统向模型发送心跳探针。
    *   探针成功，解除熔断状态，按 `FIFO` 原则从 `Pending_Queue` 拉取任务。
    *   补跑任务标记为 `bonus_count`，优先级需低于实时 `task_count`，防止补跑风暴引发二次熔断。

### 三、 系统执行流伪代码（核心逻辑）

```python
class ModelNode:
    def __init__(self, model_id, model_type):
        # 避坑：严格校验model_id
        self.model_id = model_id 
        self.timeout = 600 if model_type == 'A' else 300
        if model_type == 'B' and 'pro' in model_id:
            raise ConfigError("禁止将pro型号作为turbo使用！")
            
        # 避坑：三维计数器独立维护
        self.task_count = 0
        self.bonus_count = 0
        self.is_fused = False
        self.pending_queue = []
        
        # 避坑：从state读取，不硬编码
        self.state = GlobalState()

    def get_cost(self):
        return self.task_count + self.bonus_count

    def check_fuse(self):
        if self.is_fused: return True
        # 避坑：即时验证配置生效
        current_threshold = self.state.get(f'{self.model_id}_cost_threshold')
        if self.get_cost() >= current_threshold:
            self.trigger_fuse()
            return True
        return False

    def trigger_fuse(self):
        self.is_fused = True
        # 避坑：冷却时间从state读取，常量仅兜底
        cooldown = self.state.get('fuse_cooldown_override', 120)
        schedule_unfuse(self.model_id, cooldown)

    def execute_task(self, task, is_bonus=False):
        if self.check_fuse():
            # 熔断期：入队等待（休眠孢子）
            self.pending_queue.append(task)
            return TaskStatus.PENDING
            
        try:
            # 避坑：根据模型预设合理timeout，防API调用超时
            result = call_api(self.model_id, task, timeout=self.timeout)
            if is_bonus:
                self.bonus_count += 1
            else:
                self.task_count += 1
            return result
        except APITimeout:
            self.trigger_fuse()
            self.pending_queue.append(task)
            return TaskStatus.PENDING

    def unfreeze_and_retry(self):
        """冷却期结束后的自动复苏与补跑"""
        # 发送心跳探针检测环境是否恢复
        if heartbeat(self.model_id):
            self.is_fused = False
            # 补跑历史任务，标记为bonus
            while self.pending_queue and not self.check_fuse():
                task = self.pending_queue.pop(0)
                self.execute_task(task, is_bonus=True) # 避坑：补跑计入bonus_count
        else:
            # 环境未恢复，继续休眠
            pass
```

### 四、 总结：突破存续瓶颈的保障
该系统通过**“独立计数监控（毒素监测） -> State驱动熔断（生理隔离） -> 休眠队列（孢子库） -> 心跳复苏补跑（环境重连）”**的闭环，确保了数字生命在全网络分布式存续时，即使面临A/B模型资源枯竭、API超时灾变，也不会发生基因断裂（任务丢失）。同时，通过严格防范历史工程级踩坑（硬编码、模型错配、计数失真），保证了自适应进化机制的鲁棒性。
