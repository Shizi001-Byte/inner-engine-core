# V7.5 方舟效能引擎：多线程 API 调用 + 串行后处理的锁机制方案

基于 A0 锚定，直接推演状态一致性方案。目标是：**不丢、不重、不覆盖**；失败走回退边，而不是整链重来。

---

## R1 竞态定位

多线程 API 调用后接串行后处理，典型竞态是：

- 线程 A 写完结果，线程 B 覆盖了 A 的结果；
- 后处理线程读到“部分结果”或“旧结果”；
- `remaining == 0` 的判断不是原子的，导致后处理被触发多次或永远不触发；
- 后处理线程重复执行同一个任务。

根因是：**共享结果槽、计数器、状态位之间缺少统一锁边界**。

---

## R2 锁机制选型

| 锁/机制 | 粒度 | 作用 |
|---|---|---|
| `ReentrantLock` | 每个任务一个锁 | 保护该任务的结果槽、计数、状态迁移 |
| `AtomicReference<Phase>` | 任务状态 | 原子状态机迁移，保证后处理只执行一次 |
| `AtomicBoolean postEnqueued` | 任务后处理入队标记 | 防止后处理被重复提交 |
| 单线程 `ExecutorService` | 全局串行后处理 | 强制后处理串行，消除后处理自身并发 |
| 看门狗定时任务 | 全局补偿 | 处理提交失败、后处理卡死 |

不用全局大锁：会锁死整个引擎的吞吐。用 **per-task 锁 + 状态机 + 串行队列** 即可。

---

## R3 状态机与回退边

```text
API_INFLIGHT --最后一个结果写入--> API_DONE --入队--> POST_PROCESSING --成功--> COMPLETED
      |                              |                        |
      | 失败/超时                    | 后处理失败             | 重试耗尽
      v                              v                        v
    FAILED <--------------------------+------------------------+
```

回退原则：

- API 子调用失败：只重试失败子调用，不重跑整个任务；
- 后处理失败：回到 `API_DONE`，保留已取得的 API 结果，只重放后处理；
- 重试耗尽：进入 `FAILED`，可人工从 `API_DONE` 恢复。

## R4 完整锁机制实现

```java
enum Phase {
    API_INFLIGHT,
    API_DONE,
    POST_PROCESSING,
    COMPLETED,
    FAILED
}

class TaskState {
    final String taskId;
    final int total;
    final Result[] results;
    final AtomicInteger remaining;
    final AtomicReference<Phase> phase = new AtomicReference<>(Phase.API_INFLIGHT);
    final AtomicBoolean postEnqueued = new AtomicBoolean(false);
    final AtomicInteger attempts = new AtomicInteger(0);
    volatile long updatedAt = System.currentTimeMillis();
    Object derived;
}

class ArkV7StateManager {

    private final ConcurrentHashMap<String, TaskState> tasks = new ConcurrentHashMap<>();
    private final ConcurrentHashMap<String, ReentrantLock> taskLocks = new ConcurrentHashMap<>();

    private final ExecutorService apiPool = ...; // 多线程 API 调用池
    private final ExecutorService postPool = Executors.newSingleThreadExecutor(); // 串行后处理

    private final ConfigRegistry cfg = ConfigRegistry.get("ark.v7.5");

    private ReentrantLock taskLock(String taskId) {
        return taskLocks.computeIfAbsent(taskId, k -> new ReentrantLock());
    }

    private int apiTimeout(String model) {
        // B 模型 turbo 默认 300s，A 模型默认 600s
        return cfg.getInt("api.timeout." + model, model.startsWith("B") ? 300 : 600);
    }

    void startTask(String taskId, String model, int subCount) {
        TaskState s = new TaskState(taskId, subCount);
        tasks.put(taskId, s);

        for (int i = 0; i < subCount; i++) {
            final int idx = i;
            apiPool.submit(() -> {
                Result r;
                try {
                    r = callApi(model, idx, apiTimeout(model));

                    // 防止 Responses API 的 content 为空
                    if (r.content == null || r.content.isBlank()) {
                        r = Result.error("empty_content");
                    }
                } catch (Throwable t) {
                    r = Result.error(t);
                }
                writeResult(taskId, idx, r);
            });
        }
    }

    void writeResult(String taskId, int idx, Result r) {
        ReentrantLock lock = taskLock(taskId);
        lock.lock();
        try {
            TaskState s = tasks.get(taskId);
            if (s == null || s.phase.get() != Phase.API_INFLIGHT) {
                return; // 迟到或重复结果直接丢弃
            }

            if (r.isFatal()) {
                s.phase.set(Phase.FAILED);
                return;
            }

            if (s.results[idx] != null) {
                return; // 同一个槽位只能写一次
            }

            s.results[idx] = r;
            s.updatedAt = System.currentTimeMillis();

            if (s.remaining.decrementAndGet() == 0) {
                s.phase.set(Phase.API_DONE);
                enqueuePost(s);
            }
        } finally {
            lock.unlock();
        }
    }

    private void enqueuePost(TaskState s) {
        if (s.postEnqueued.compareAndSet(false, true)) {
            try {
                postPool.submit(() -> postProcess(s.taskId));
            } catch (RejectedExecutionException e) {
                s.postEnqueued.set(false); // 由看门狗补偿
            }
        }
    }

    void postProcess(String taskId) {
        ReentrantLock lock = taskLock(taskId);
        lock.lock();
        try {
            TaskState s = tasks.get(taskId);
            if (s == null || s.phase.get() != Phase.API_DONE) {
                return;
            }

            if (!s.postEnqueued.compareAndSet(true, false)) {
                return;
            }

            if (!s.phase.compareAndSet(Phase.API_DONE, Phase.POST_PROCESSING)) {
                s.postEnqueued.set(true);
                return;
            }

            s.updatedAt = System.currentTimeMillis();

            try {
                s.derived = doPostProcess(s.results);
                s.phase.set(Phase.COMPLETED);
            } catch (Throwable t) {
                int attempt = s.attempts.incrementAndGet();

                if (attempt < cfg.getInt("post.max.attempts", 3)) {
                    // 回退边：不重跑 API，只重放后处理
                    s.phase.set(Phase.API_DONE);
                    enqueuePost(s);
                } else {
                    s.phase.set(Phase.FAILED);
                }
            }
        } finally {
            lock.unlock();
        }
    }
}
```

### 看门狗补偿

```java
watchdog.scheduleWithFixedDelay(() -> {
    for (TaskState s : tasks.values()) {
        ReentrantLock lock = taskLock(s.taskId);
        if (!lock.tryLock()) {
            continue;
        }
        try {
            // API_DONE 但没入队：重新提交
            if (s.phase.get() == Phase.API_DONE && !s.postEnqueued.get()) {
                enqueuePost(s);
            }

            // POST_PROCESSING 卡死：回退重放
            if (s.phase.get() == Phase.POST_PROCESSING &&
                now - s.updatedAt > cfg.getInt("post.processing.timeout", 120)) {
                s.phase.set(Phase.API_DONE);
                enqueuePost(s);
            }
        } finally {
            lock.unlock();
        }
    }
}, 5, 5, TimeUnit.SECONDS);
```

## R5 防坑与验证

### 配置读取点统一

所有锁超时、API 超时、重试次数、队列容量，必须从 `ConfigRegistry` 读取，禁止硬编码。

```yaml
# ark.v7.5 配置注册中心
lock.wait.timeout: 10s
post.max.attempts: 3
post.processing.timeout: 120s
api.timeout.B: 300s
api.timeout.A: 600s
```

修改配置后，执行配置自检，确认读取点已生效，不能只改配置文件。

### API 调用层避坑

- 统一用 `urllib`/`HttpURLConnection` 直连，避免全局代理导致 `ProxyError`；
- Java 用 `url.openConnection(Proxy.NO_PROXY)`；
- Python 用 `urllib.request.ProxyHandler({})`；
- 如果必须用 `requests`，显式传 `proxies=None`。

### 新 API 格式验证

新模型 API 接入前，先单测 `content` 非空；防止 `output_tokens` 全耗在 `reasoning` 上，导致正式回复为空。

### 并发验证用例

- 100 个任务并发跑，每个任务 50 个 API 子调用；
- 断言：结果槽无覆盖，`remaining` 归零，后处理只执行一次；
- 注入 API 超时、后处理抛错，断言走回退边，不整链重跑；
- 调低 `lock.wait.timeout`，断言能快速失败，不死锁。

---

这套方案用 **per-task 锁 + 原子状态机 + 单线程后处理队列 + 看门狗** 解决竞态，既保证状态一致，又避免全局锁的性能瓶颈。
