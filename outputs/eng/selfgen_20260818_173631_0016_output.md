# 任务类型: eng

## 结论先行

增量同步不按“整个文件”同步，而按 **“块”** 同步。  
每个块是带 `hash` 和 `rev` 的 DAG 节点，本地文件是工作区，Supabase 是公共档案区，`sync_log` 是变更 DAG。

```text
N1 检测本地变更
   → ChangeSet
   → 验证门 G1
N2 提取变更块
   → BlockPatch
   → 验证门 G2
N3 远端同步 + 冲突处理
   → SyncResult
   → 验证门 G3
```

节点间只传递结构化产物，不传递中间推理过程。

---

## 核心数据模型

### 1. `memory_docs`

记录每个记忆文档的当前版本号：

```sql
create table memory_docs (
  doc_id text primary key,
  rev bigint not null default 0,
  updated_at timestamptz default now()
);
```

### 2. `memory_blocks`

只存“块”，不存整个文件：

```sql
create table memory_blocks (
  doc_id text,
  block_id text,
  content text,
  hash text,
  event_ref text,
  scope text,              -- 'public' 或 'individual'
  updated_at timestamptz default now(),
  deleted_at timestamptz,
  primary key (doc_id, block_id)
);
```

### 3. `memory_conflicts`

冲突不是错误，而是“双轨存在”的证据：

```sql
create table memory_conflicts (
  id uuid primary key default gen_random_uuid(),
  doc_id text,
  block_id text,
  base_content text,
  local_content text,
  remote_content text,
  status text default 'open',
  created_at timestamptz default now()
);
```

### 4. `sync_log`

形成可验证的同步 DAG：

```sql
create table sync_log (
  id uuid primary key default gen_random_uuid(),
  doc_id text,
  parent_rev bigint,
  child_rev bigint,
  patch jsonb,
  conflict_ids uuid[],
  created_at timestamptz default now()
);
```

---

## N1：检测本地文件变化

### 输入

- 本地记忆目录路径
- 上次同步状态 `.sync/state.json`
- 监听配置：忽略规则、块拆分规则、模型配置

### 处理

1. 启动文件监听器，`debounce` 2 秒，避免文件写入过程中被误读。
2. 同时每 60 秒做一次全量扫描，补掉监听器可能丢失的事件。
3. 计算文件指纹：

```text
sha256(content) + mtime + size
```

4. 与 `.sync/state.json` 对比，得到变化类型：

```json
{
  "changes": [
    {
      "path": "memories/agent.md",
      "doc_id": "agent",
      "type": "modified",
      "fingerprint": "abc123"
    }
  ]
}
```

### 输出

```text
ChangeSet
```

### 验证门 G1

- 配置修改后，必须重新加载配置并验证“读取点”已更新。
- 自检方法：创建临时文件，确认事件到达，再删除临时文件。如果没收到事件，禁止进入 N2。
- 全量扫描结果必须覆盖监听事件，否则说明有事件丢失。
- 不进入 N2 前，不能修改 Supabase 任何数据。

## N2：提取变更块

### 输入

- `ChangeSet`
- 本地文件内容
- `.sync/state.json` 中的 base 快照

### 处理

1. 把文件解析成块：

- Markdown：按 frontmatter + `##` 标题拆分。
- JSON：按顶层 key 拆分。
- 纯文本：按段落拆分。
- 块太大时继续按段落拆分，控制单块大小。

2. 给每个块生成稳定 `block_id`：

```text
优先：文件中显式写入 <!-- block-id: xxx -->
兜底：sha256(doc_id + heading_path)
```

3. 计算每个块的 `hash`，与 base 快照比较：

- `hash` 相同 → 不传。
- `hash` 不同 → `upsert`。
- base 有、本地没有 → `delete`。
- base 没有、本地有 → `upsert`。

4. 生成 `BlockPatch`：

```json
{
  "doc_id": "agent",
  "base_rev": 42,
  "ops": [
    {
      "op": "upsert",
      "block_id": "intro",
      "content": "新的记忆内容",
      "hash": "def456"
    },
    {
      "op": "delete",
      "block_id": "old-section",
      "prev_hash": "abc123"
    }
  ]
}
```

### 输出

```text
BlockPatch
```

### 验证门 G2

- 把 `BlockPatch` 应用到 base 快照上，结果必须等于当前本地文件的块集合。
- `ops` 里只允许出现变更块，不能包含未变化块。
- 本节点不调用 LLM，避免把语义模型引入确定性 diff。
- 如果解析超时，直接中止，保留旧状态，不进入 N3。

## N3：远端同步与冲突处理

### 输入

- `BlockPatch`
- Supabase 当前远端状态
- `sync_log`

### 处理

#### 3.1 获取远端当前状态

```sql
select block_id, content, hash
from memory_blocks
where doc_id = 'agent'
  and deleted_at is null;
```

同时读取：

```sql
select rev
from memory_docs
where doc_id = 'agent';
```

#### 3.2 对比版本号

```text
remote_rev == patch.base_rev
```

相等 → 无远端变更，直接原子写入。

```text
remote_rev > patch.base_rev
```

→ 进入三方合并。

```text
remote_rev < patch.base_rev
```

→ 远端被回滚或重建，禁止自动覆盖，标记为异常冲突。

#### 3.3 三方合并

合并基准：

- base：上次同步时的块快照
- local：当前本地块
- remote：当前远端块

| 情况 | 动作 |
|---|---|
| 本地改，远端未改 | 取本地 |
| 远端改，本地未改 | 取远端，并回写本地文件 |
| 两边改成相同内容 | 无冲突，合并 |
| 两边改成不同内容 | 冲突，进入 `memory_conflicts` |
| 一边删，一边改 | 冲突，不自动删除 |
| 一边删，一边未改 | 删除 |
| 两边都删 | 删除 |

冲突时：

- 不覆盖任何一方。
- 把 `base_content`、`local_content`、`remote_content` 都写入 `memory_conflicts`。
- 如果两方都无法锚定到可验证事件，则 `scope` 标记为 `individual`，降级为个体叙事。
- 如果一方有 `event_ref`，保留该锚点，等待后续验证。

#### 3.4 可选 LLM 自动合并

只有双方都改且内容不同时才启用。

```text
调用 LLM：
输入：base_content + local_content + remote_content
输出：merged_content
```

超时约束：

- B 模型（turbo）：300 秒。
- A 模型：600 秒。
- 超时后不阻塞主流程，保留冲突。

质量校验必须按模型分流：

```text
B 模型（turbo）：跳过 reasoning 占比检测。
  因为 reasoning 占比 70%-82% 是 B 模型的正常特性，不是废稿。

A 模型：使用 A 模型独立质量规则。
  禁止复用 B 模型的阈值。
```

如果 LLM 合并结果不可信，或无法锚定到可验证事件，则保留冲突，不写入公共记忆。

#### 3.5 原子写入

用 Supabase RPC 完成，避免并发问题。

```text
begin;

select pg_advisory_xact_lock(hashtext(doc_id));

select rev into current_rev from memory_docs where doc_id = ... for update;

if current_rev != patch.base_rev then
  return conflict;
end if;

for op in patch.ops loop
  if op.op == 'upsert' then
    upsert memory_blocks;
  else
    update memory_blocks set deleted_at = now();
  end if;
end loop;

update memory_docs set rev = rev + 1;

insert into sync_log(parent_rev, child_rev, patch);

commit;
```

### 输出

```json
{
  "doc_id": "agent",
  "new_rev": 43,
  "applied_ops": [],
  "conflicts": [],
  "local_write_back": []
}
```

### 验证门 G3

- 写入后必须读回 Supabase，对比 `hash` 集合是否等于预期状态。
- 如果存在冲突，确认 `memory_conflicts` 中两方内容都在，原始数据没有丢失。
- 如果调用了 LLM，必须确认超时配置生效：B 模型 300 秒，A 模型 600 秒。
- 配置读取点必须使用最新配置，修改配置后不能沿用旧配置继续同步。

---

## 最终效果

- 本地只传“变更块”，不传整个文件。
- Supabase 只存块，不存冗余全文。
- 冲突不删除，不静默覆盖，保留为双轨。
- 所有同步记录进入 `sync_log`，形成可回滚、可验证的记忆 DAG。
- 未验证的记忆明确降级为个体叙事，只有锚定到可验证事件的记忆才允许进入公共档案。
