# 任务类型: eng

## 自动归档系统设计：契约驱动，决策/执行分离

一句话：**先定 `ArchiveManifestContract` 锚点，再谈自动分类、打标签、并发归档。**

---

### 1. 总体链路

```text
任务接入
   ↓
决策层（串行）：schema 定义 → 规则评审 → 生成归档清单/脚本
   ↓
执行层（并发）：worker 并行消费清单，执行 copy/move
   ↓
校验/审计：确认目录、标签、目标路径正确
```

核心原则：

- **决策串行**：先明确分类规则、标签字典、目录映射，再生成脚本。
- **执行并发**：多个 worker 并行归档，但**只按清单执行，不允许自行简化或重新分类**。
- **列契约是锚点**：执行层拿到的每一行数据，必须包含 `category`、`tags`、`target_dir`，缺失就是契约违约。

---

### 2. 契约定义

#### 2.1 任务输入契约

```json
{
  "task_id": "T-001",
  "task_name": "hourly_etl_pipeline",
  "source_path": "/data/raw/task_001.json",
  "raw_metadata": {}
}
```

#### 2.2 归档规则契约

```json
{
  "rule_id": "rule_etl",
  "version": 1,
  "match": {
    "type": "name_contains",
    "value": "etl"
  },
  "category": "ETL",
  "tags": ["pipeline", "hourly"],
  "target_dir_template": "/archive/etl/{yyyy}/{MM}/{dd}",
  "priority": 10,
  "enabled": true
}
```

#### 2.3 归档清单契约

这是**执行层唯一读取点**。

```json
{
  "manifest_version": "1.0",
  "batch_id": "batch_20260409",
  "tasks": [
    {
      "task_id": "T-001",
      "source_path": "/data/raw/task_001.json",
      "category": "ETL",
      "tags": ["pipeline", "hourly"],
      "target_dir": "/archive/etl/2026/04/09",
      "exec_mode": "move",
      "timeout_ms": 600000
    }
  ]
}
```

> 执行层拿不到 `target_dir`，就是“列契约”丢失；再简单的 SQL 也救不回来。

---

### 3. 关键实现点

#### 3.1 严格按契约生成 SQL

不写简化版 SQL，不写 `SELECT *`，必须显式列出契约字段：

```sql
SELECT
  task_id,
  source_path,
  category,
  tags,
  target_dir,
  exec_mode,
  timeout_ms
FROM archive_manifest
WHERE batch_id = :batch_id;
```

如果列缺失，worker 必须直接报错，**不允许自己猜目录、补标签**。

#### 3.2 配置修改后必须立即生效

- 规则配置只允许通过“规则配置中心”修改。
- 配置存储统一为 `archive_rules` 表。
- 修改后必须：
  1. 增加 `version`；
  2. 刷新规则缓存；
  3. 使用 sample task 跑一次冒烟验证；
  4. 断言 `category`、`tags`、`target_dir` 符合预期。

> 新增配置字段时，必须同步修改决策层的读取点和清单契约，否则配置只是“死配置”。

#### 3.3 API 调用超时兜底

如果分类/打标签使用外部模型，必须显式设置 timeout：

- **B 模型/turbo：300 秒**
- **A 模型：600 秒**

超时后进入重试队列或死信队列，不允许无限阻塞主流程。

#### 3.4 执行层并发，但不决策

Worker 并行执行时：

- 只从 `archive_manifest` 读取任务；
- 只做 `copy` / `move` / `checksum` 校验；
- 不重新分类、不打新标签、不自行修改目录；
- 如果目标已存在且 checksum 一致，则幂等跳过。

---

### 4. 避坑落地清单

| 历史坑 | 本系统预防方式 |
|---|---|
| 简化版 SQL 导致列不匹配 | 清单 SQL 必须显式列出契约字段，worker 不猜列 |
| 配置修改后不生效 | 唯一配置读取点 + 版本号 + 冒烟验证 |
| API 超时导致任务无法返回 | 按模型预设 timeout：B/turbo 300s，A 600s |
| 执行层自行简化 | 决策层生成清单，执行层只消费清单，不自行决策 |

---

### 5. 总结

这个自动归档系统的核心不是“自动分类”，而是**先校准契约锚点**：

- 决策层负责生成“带 `category`、`tags`、`target_dir` 的归档清单”；
- 执行层负责并发执行清单；
- 任何简化、猜测、缺列，都按契约违约处理。
