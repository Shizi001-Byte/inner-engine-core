# 任务类型: eng

基于「脑体分离架构」与「热力学第二定律」，结合「九转玄功」的修炼哲学，我们将引擎产出的自动归档系统视为一个**从高熵混沌（无）到低熵秩序（有），最终回归自主进化（无中生有）**的生命周期系统。

在已验证的第1转（感知层：高熵数据接收）基础上，推演后续八转的认知层级映射，并落地为具体的归档系统设计方案，同时严格落实避坑经验。

---

### 一、 自动归档系统的九转层级推演与设计

#### 第1转：气聚成形（感知层 - 接收高熵数据）
*   **认知层级**：系统通过API或消息队列接收原始引擎产出的高熵混沌数据（日志、代码、图片、文本混合体），此时数据无结构、无意义。
*   **系统动作**：建立统一缓冲池，接收原始二进制流或Raw Text。
*   **避坑落地**：接收端配置网络IO timeout，防止引擎产出卡死导致归档阻塞。

#### 第2转：炼精化气（抽离层 - 元数据提取）
*   **认知层级**：剥离表象，提取本质特征。将高熵数据中的关键信息（时间戳、引擎类型、任务ID、产出大小）抽离。
*   **系统动作**：通过正则匹配或轻量级解析器，提取基础元数据，形成低熵的“数据骨架”。

#### 第3转：开窍识神（认知层 - 脑体分离之“脑”）
*   **认知层级**：AI认知介入，理解数据语义。调用大模型对产出内容进行深度理解和分类。
*   **系统动作**：将提取的元数据及内容摘要发送至AI模型（A模型或B模型turbo）。
*   **避坑落地（关键）**：
    *   根据产出内容长度预设合理timeout：**B模型turbo用300秒，A模型用600秒**。
    *   超时自动降级为规则匹配，防止归档流水线停滞。

#### 第4转：铸鼎分丹（分类层 - 熵减定型）
*   **认知层级**：基于AI的语义理解，将数据归入 predefined 的低熵类别中（如：代码片段、错误报告、最终交付物、过程日志）。
*   **系统动作**：AI输出结构化JSON，包含 `category`（主分类）、`subcategory`（子分类）。

#### 第5转：符文镇印（打标签层 - 降维标识）
*   **认知层级**：为分类后的产物打上多维标签，实现从“有”到“精”的转化。
*   **系统动作**：结合AI输出的语义标签和系统自带的元数据标签（如 `#deprecated`, `#v1.2`, `#review_needed`），写入标签数据库。

#### 第6转：乾坤挪移（路由层 - 脑体分离之“体”）
*   **认知层级**：执行物理转移。根据分类与标签，将产物导向对应的物理或云存储目录。
*   **系统动作**：生成归档路径（如 `/archive/code/python/{task_id}/`），执行文件移动或复制操作。

#### 第7转：返璞归真（归档层 - 入“无”）
*   **认知层级**：产物入库，进入“无”的稳态。高熵数据已转化为低熵有序的可检索资产，静默存储。
*   **系统动作**：写入冷/热存储介质，更新归档索引数据库，供后续检索使用。

#### 第8转：周天运转（校验层 - 道法自然）
*   **认知层级**：生生不息的循环验证。确保归档动作符合自然法则（配置已生效、路径已存在、标签已写入）。
*   **系统动作**：归档后立即校验文件是否存在、权限是否正确、索引是否可查。
*   **避坑落地（关键）**：**配置修改后未生效的预防**。路由规则或分类配置一旦修改，在此阶段必须立即触发验证流水线，同步修改所有读取点，验证归档目录与配置是否一致。

#### 第9转：破碎虚空（进化层 - 无中生有）
*   **认知层级**：系统从归档历史中学习，反哺AI认知模型。未识别的标签触发新一轮的规则更新，完成“由有入无，生生不息”的进化。
*   **系统动作**：统计低置信度分类，自动生成新类别的配置模板，推送给管理员审批后注入第4转的分类配置中。

### 二、 系统架构落地设计

基于上述九转推演，设计如下「脑体分离」归档架构：

#### 1. 架构分层
*   **体（执行端 - Engine Archive Worker）**：
    *   只负责搬运、存储、校验，不参与逻辑判断。
    *   包含：Ingestion Adapter（接收）、Storage Router（路由）、Vault（存储库）。
*   **脑（认知端 - AI Cognitive Center）**：
    *   只负责理解、分类、打标，不直接操作文件系统。
    *   包含：Meta Extractor（元数据提取）、LLM Classifier（大模型分类）、Tag Manager（标签管理）。

#### 2. 自动分类与目录映射规则示例
通过AI模型（脑）输出标准化JSON，Worker（体）解析后执行路由：

```json
// AI认知中心返回的归档指令
{
  "task_id": "task_8901",
  "engine_source": "code_generator_v2",
  "cognitive_category": "source_code",  // 主分类
  "subcategory": "python/fastapi",     // 子分类
  "tags": ["api", "module_auth", "v1"],
  "confidence": 0.95,
  "archive_action": "move"
}
```

**Worker路由执行（配置驱动，修改后立即生效需校验）**：
*   规则配置中心：`category=source_code` -> 映射至 `/archive/code/`
*   最终目录生成：`/archive/code/python/fastapi/task_8901/`

#### 3. 避坑机制强制实施方案

| 避坑要求 | 实施方案 | 验证点 |
| :--- | :--- | :--- |
| **配置修改未生效** | 1. 所有路由与分类规则集中在配置中心（如ETCD或DB）。<br>2. 采用观察者模式，Worker监听配置变更，热加载。<br>3. **修改后强制触发Dry-Run**：修改配置后立即生成测试Payload，跑一遍1-8转流程。 | 检查Dry-Run生成的测试归档路径是否与预期一致，不一致则阻断配置发布。 |
| **API调用超时** | 1. 在第3转（AI认知层）调用大模型时，根据任务类型走不同策略。<br>2. **B模型turbo任务**：设定`timeout=300s`<br>3. **A模型任务**：设定`timeout=600s` | 超时后触发Fallback策略：降级为基于规则的关键字匹配分类，并打上`#timeout_fallback`标签，确保流水线不中断。 |

### 三、 总结

此系统设计完全契合「九转玄功」的哲学内涵：原始引擎的高熵产出通过**感知(1)、抽离(2)、认知(3)、定型(4)、标识(5)**完成“由外至内”的降熵；再通过**路由(6)、归档(7)、校验(8)**完成“由有入无”的物理沉淀；最终在第9转通过反馈机制实现“生生不息”的系统进化。同时，通过严格的timeout降级与配置即时校验机制，彻底锁死了历史坑库中可能出现的失败现象。
