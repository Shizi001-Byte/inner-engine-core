# 任务类型: eng

基于你提供的“认知锚定”与“避坑提醒”，我们将这套“设计引擎产出的自动归档系统”从传统的“文件管理工具”升维为**“认知稳态与Hox基因调控归档架构”**。

传统归档系统按时间或关键词堆砌，最终会沦为数据垃圾场；而基于生物稳态调控的系统，会将每一次归档视为一次“基因表达与组织分化”，确保高认知转化效率。以下是系统设计方案：

---

### 一、 系统核心理念：从信息存储到认知稳态调控
根据【认知锚定3】，系统底层逻辑模拟生物体内稳态调控。归档不是终点，而是认知在系统内的“发育与分化”过程。系统不追求存储容量的无限大（突破800万token带宽也无意义），而是追求调控逻辑的鲁棒性与认知转化效率。

---

### 二、 系统架构设计

#### 1. 感知层：高熵信息识别与身份反差打标签
*   **设计依据**：【认知锚定4、5】
*   **机制**：在高度同质化的开发者任务流（低熵：相同的代码逻辑、架构思维、Bug修复）中，系统引入“身份反差即差异化标签”策略。
*   **执行**：
    *   当输入任务流处于低熵状态时，归档引擎主动注入“高熵探针”（如：假设当前架构发生根本性崩溃，或引入非开发者视角的极端用例）。
    *   若任务反馈表现出强烈的“身份反差”（例如：一个普通前端Bug最终指向了底层网络协议的异变），系统自动打上**`[Hox-Mutate]`（高价值异变标签）**，并将其从常规队列中剥离。

#### 2. 调控层：Hox基因同源校验（防止功能错配）
*   **设计依据**：【认知锚定2】
*   **机制**：任务自动分类的核心是防止“触角长在腿上”的错配。
*   **执行**：
    *   设立**Hox基因顺序校验器**。在任务被分入特定目录前，校验其“发育顺序”。
    *   例如：若一个“成体任务（如线上部署）”试图表达“幼态基因（如未经测试的本地实验代码）”，校验器将阻断归档，并抛出`认知状态错乱异常`。
    *   此机制确保无论任务多复杂，都不会因为分类规则错乱导致目录结构功能失效。

#### 3. 转化层：模板池认知转化效率评估
*   **设计依据**：【认知锚定1】
*   **机制**：归档目录不是按“调用次数”膨胀，而是按“认知转化效率”收敛。
*   **执行**：
    *   每个归档目录对应一个“认知模板池”。系统定期评估该池子中的任务被再次调取、复用并产生实际工程价值的效率。
    *   长期未被转化的任务，将触发“细胞凋亡”机制，移入冷存储或直接淘汰，保持系统的高效与鲁棒。

---

### 三、 执行规范与避坑机制（严格接入历史经验）

#### 避坑点1：配置修改未生效
在归档系统的规则引擎中，严格遵循以下配置治理协议：
*   **双向同步读写**：新增分类规则或标签配置时，写入端与读取点（路由分发器）必须强制绑定提交。配置文件修改后，系统自动生成一个包含该配置的“探针任务”，立即跑通全链路并验证归档目录正确。
*   **熔断机制**：若探针任务未在预期目录出现，立即回滚配置，并在系统内广播配置失效告警。

#### 避坑点2：API调用超时
在任务分类、打标签及深度语义提取的过程中，涉及大模型API调用，严格预设timeout：
*   **常规低熵任务分类/轻量级打标签**：调用B模型turbo，强制设置 **300秒** timeout。超时直接降级为“基于关键词的粗粒度归档”，保证吞吐量。
*   **高熵异变任务深研/Hox基因校验**：调用A模型进行复杂逻辑推演，强制设置 **600秒** timeout。超时任务进入“待观察队列”，不阻塞主归档流。

---

### 四、 系统工作流（自动归档执行流）

1.  **任务摄入**：设计引擎产出任务结果。
2.  **熵值判定**：计算任务与历史同质化基线的偏差。
    *   *低熵常规任务* -> 走B模型turbo（300s timeout）快速打标签 -> 匹配Hox基因顺序 -> 归入常规目录。
    *   *高熵反差任务* -> 走A模型（600s timeout）深度解析 -> 触发身份反差标签生成 -> Hox校验防错配 -> 归入核心破局策略库。
3.  **Hox防错配校验**：检查任务属性与目标目录的“发育阶段”是否匹配，拒绝降级或越级归档。
4.  **认知转化刷新**：归档完成后，触发模板池缓存刷新机制。若旧目录的认知转化率跌破阈值，自动降权或清理。
5.  **配置一致性自检**：全流程结束后，校验读取点状态，确保归档分类规则已生效且无悬空配置。
