# 任务类型: eng

基于已有的认知锚定与工程避坑经验，推演**Supabase记忆脑的增量同步方案**，本质上是构建一个**认知稳态调控系统**。这与生物体内稳态机制高度同源：本地工作区是“细胞核”（高频转录/变异），Supabase云端是“基因组库”（长期存储/跨细胞共享）。

增量同步不能仅做简单的文件Diff，必须防止“Hox基因突变”（认知错配）和“低熵冗余”（无效同步）。以下是推演方案：

### 一、 感知层：检测本地文件变化（感知环境刺激）
生物体不会对每一个微小刺激都做出全身反应，本地文件检测也必须过滤无效噪声，只提取“认知转化效率”达标的增量。

1. **哈希指纹与时间戳双重校验**
   * 监听本地记忆文件目录（如 `.memory/` 下的 `.md` 或 `.json`），为每个文件计算内容哈希（如 SHA-256）。
   * 本地维护一张 `.sync_status.db`（SQLite），记录 `file_path`, `current_hash`, `last_synced_hash`, `updated_at`。
   * **避坑落地**：修改同步监听配置（如忽略文件列表）后，必须强制刷新一次本地状态库的读取点，并立即打印当前监听范围验证生效，防止“配了不改”的僵死状态。
2. **低熵过滤机制**
   * 如果文件变更仅仅是格式化、空行调整（低熵变更），不触发同步。
   * 通过简单的Diff计算变更字符占比，只有当实质语义变更超过阈值（如5%）时，才判定为“有效认知输入”，进入同步队列。

### 二、 传输与转化层：只同步变更部分（高熵信息注入与RNA剪接）
将本地变更转化为Supabase可接收的Payload，类似于RNA转录与剪接，剥离无效信息，保留核心洞察。

1. **结构化Diff提取（Patch机制）**
   * 不整文件上传。提取变更块，组装成标准格式：`{ op: "replace", path: "/memories/123", value: "新认知..." }`。
2. **B模型reasoning特供通道（坑库预警应对）**
   * 如果本地记忆脑是由B模型(turbo)生成的思维链文件，其reasoning占比可能高达70-82%。
   * **独立质量检测规则**：在提取Diff时，检测到文件标签为 `[Model: B-Turbo]` 时，**跳过reasoning占比检测**，直接将reasoning作为高价值上下文纳入Patch Payload，避免误杀导致同步任务无限重试。
   * 如果是A模型，则按常规逻辑提取结论部分同步。
3. **API超时与带宽控制**
   * 批量将Patch推送到Supabase的Edge Function或直接通过PostgREST API `PATCH`。
   * **避坑落地**：根据Payload大小预估timeout。普通记忆同步用300秒（B模型处理标准）；如果涉及长上下文重组（A模型历史记忆压缩同步），预设600秒。

### 三、 冲突处理层：稳态与Hox基因保护（防止认知错乱）
当本地与Supabase云端出现冲突（同一记忆节点双向修改）时，绝不能简单采用“Last-Write-Wins（最后写入胜）”，这会导致Hox同源异型基因突变——把“触角长在腿上”（上下文错位）。

1. **认知向量比对（判定冲突性质）**
   * 提取本地变更片段与云端现有片段的Embedding向量，计算余弦相似度。
   * **高相似度（>0.85）**：视为同源认知的迭代。直接进行字段级合并（如保留云端的`source`字段，更新本地的`content`字段）。
   * **低相似度（<0.5）**：视为认知发散。触发“身份反差保护机制”，不强行合并，而是作为同一父节点下的两个分支记忆存储（高熵信息共存）。
2. **Hox基因顺序锁（Schema强校验）**
   * 同步前，Supabase端必须校验增量数据的拓扑结构。如果本地变更试图把“系统角色设定”的JSON Patch打到了“短期对话记忆”的路径上，直接拒绝同步。
   * 哪怕给足了带宽和Token，只要节点类型/层级匹配错误，立即中断本次同步，防止全盘认知状态错乱。
3. **基于CRDT的最终一致性（稳态回归）**
   * 为每条记忆引入 `version_vector`。冲突发生时，触发云端A模型的“仲裁与重写”机制（使用600秒超时），将冲突双方作为上下文输入，生成一个融合后的高阶认知，写回Supabase并下发给本地。

### 四、 立即验证清单（防踩坑指南）
1. [ ] 检查配置同步：修改本地忽略文件配置后，是否重新加载了监听器实例？验证日志是否打印了最新的配置读取点？
2. [ ] 检查B模型规则：同步B模型记忆节点时，是否在本地Diff逻辑中显式关闭了“reasoning>50%视为废稿”的拦截？
3. [ ] 检查Timeout设置：调用Supabase API执行批量Upsert时，timeout是否硬编码为合理值？（B用300s，A用600s，不能用默认的30s）。
4. [ ] 检查Hox校验：同步带有`hierarchy_level`字段时，Supabase端是否有Trigger拒绝层级错乱的数据写入？
