# 任务类型: eng

## 结论先行

多线程 API 调用本身不直接改共享状态；**共享状态只允许在“串行后处理”阶段修改**。  
锁的作用不是让所有线程抢锁，而是保证：

1. 同一时间只有一个批次在跑；
2. 后处理阶段严格串行；
3. 状态提交是原子操作，读不到中间态。

推荐方案：**“并发取数 + 单线程提交”**。

---

## 锁清单

| 锁 | 保护对象 | 获取顺序 |
|---|---|---|
| `_batch_lock` | 整个批次生命周期，防止多批次交叉 | 1 |
| `_post_lock` | 后处理临界区，保证串行后处理 | 2 |
| `_state_lock` | 全局状态 `_state` 的读写原子性 | 3 |

关键原则：**固定锁顺序，禁止逆序获取**。

---

## 完整代码骨架

```python
import threading
import time
import json
import urllib.request
from concurrent.futures import ThreadPoolExecutor, as_completed


class ArkEngine:
    def __init__(self, max_workers=8, cooldown_seconds=60):
        self._max_workers = max_workers
        self._cooldown_seconds = cooldown_seconds

        # 锁顺序：_batch_lock -> _post_lock -> _state_lock
        self._batch_lock = threading.Lock()
        self._post_lock = threading.Lock()
        self._state_lock = threading.Lock()

        # 全局状态，只能由 _post_process 修改
        self._state = {
            "generation_count": 0,
            "last_success": 0.0,
            "cooldown_until": 0.0,
            "consecutive_failures": 0,
        }

    def get_state(self):
        """读取状态快照，避免外部直接拿到内部可变引用。"""
        with self._state_lock:
            return dict(self._state)

    def run_batch(self, tasks):
        if not tasks:
            return None

        # 同一时间只允许一个批次
        with self._batch_lock:
            results = self._call_all(tasks)

            # 后处理严格串行
            with self._post_lock:
                return self._post_process(results)

    def _call_all(self, tasks):
        """多线程并发调用 API，主线程统一收集结果。"""
        results = []
        worker_count = min(self._max_workers, len(tasks))

        with ThreadPoolExecutor(max_workers=worker_count) as pool:
            future_map = {
                pool.submit(self._api_call, task): task
                for task in tasks
            }

            for future in as_completed(future_map):
                task = future_map[future]
                try:
                    data = future.result()
                except Exception as exc:
                    results.append({
                        "task_id": task.get("task_id"),
                        "success": False,
                        "error": str(exc),
                    })
                else:
                    results.append({
                        "task_id": task.get("task_id"),
                        "success": True,
                        "data": data,
                    })

        # 固定后处理顺序，避免乱序导致状态不一致
        results.sort(key=lambda x: x.get("task_id", 0))
        return results

    def _api_call(self, task):
        # 坑库：统一用 urllib，不用 requests，避免全局代理 ProxyError
        # 超时：B模型 turbo 用 300 秒，A模型 用 600 秒
        timeout = 300 if task.get("model") == "B-turbo" else 600

        req = urllib.request.Request(
            task["url"],
            data=json.dumps(task["payload"]).encode("utf-8"),
            headers={"Content-Type": "application/json"},
            method="POST",
        )

        with urllib.request.urlopen(req, timeout=timeout) as resp:
            parsed = json.loads(resp.read().decode("utf-8"))

        # 坑库：Responses API 的 content 可能为空，必须在此校验
        if isinstance(parsed, dict) and "content" in parsed and not parsed.get("content"):
            raise RuntimeError("API content is empty")

        return parsed

    def _post_process(self, results):
        """串行后处理：唯一允许修改 _state 的地方。"""
        # 先读当前状态快照，不持锁计算
        with self._state_lock:
            old_state = dict(self._state)

        # 无锁计算新状态
        new_state = self._compute_next_state(old_state, results)

        # 验证；如果需要调用外部验证 API，必须在这里无 state_lock 调用
        failed = [r for r in results if not r.get("success")]
        verified = not failed and self._verify(new_state, results)

        # 短临界区提交
        with self._state_lock:
            if verified:
                self._state = new_state
                self._state["last_success"] = time.time()
                self._state["cooldown_until"] = 0          # 验证通过则重置冷却
                self._state["consecutive_failures"] = 0
                self._state["generation_count"] += 1
                next_tasks = self._derive_next_tasks(self._state, results)
            else:
                self._state = new_state
                self._state["consecutive_failures"] += 1
                self._state["cooldown_until"] = time.time() + self._cooldown_seconds
                next_tasks = None

            state_snapshot = dict(self._state)

        # 持久化放到锁外
        self._persist(state_snapshot)
        return next_tasks

    def _compute_next_state(self, old_state, results):
        # 根据业务实现
        new_state = dict(old_state)
        return new_state

    def _verify(self, new_state, results):
        # 验证逻辑，可调用 API，但不要持有 _state_lock
        return True

    def _derive_next_tasks(self, state, results):
        # 自进化闭环：返回下一批任务；没有则返回 None
        return None

    def _persist(self, state):
        # 持久化实现
        pass


# 自进化闭环入口
def evolution_loop(engine, initial_tasks, max_rounds=100):
    tasks = initial_tasks
    for _ in range(max_rounds):
        tasks = engine.run_batch(tasks)
        if not tasks:
            break
```

## 为什么这样能避免竞态

1. **API 调用阶段无锁**  
   所有 worker 线程只负责请求和返回结果，不碰共享状态。

2. **结果收集在主线程完成**  
   使用 `ThreadPoolExecutor` + `as_completed`，主线程是唯一写入 `results` 的线程，因此不需要 `_result_lock`。

3. **后处理串行提交**  
   `_post_lock` 保证后处理临界区只有一个线程在跑；`_state_lock` 保证状态提交原子性。

4. **Copy-on-Write 状态切换**  
   先无锁计算 `new_state`，最后在 `_state_lock` 内一次性替换 `self._state`，读者要么看到旧状态，要么看到新状态，不会看到中间状态。

---

## 必须遵守的锁规则

- API 调用绝不持锁。
- 共享状态只有 `_post_process` 能写。
- 锁顺序固定：`_batch_lock` → `_post_lock` → `_state_lock`，禁止反向获取。
- 不要在 `_post_process` 里调用 `run_batch`，否则会死锁。  
  正确做法：`_post_process` 返回 `next_tasks`，由外层 `evolution_loop` 在锁释放后再跑下一轮。

## 变体：如果后处理是逐条串行，而不是整批后处理

用“单消费者队列”天然串行：

```python
import queue
import threading


class IncrementalEngine:
    def __init__(self):
        self.q = queue.Queue()
        self.state_lock = threading.Lock()
        self.state = {}
        threading.Thread(target=self._consume, daemon=True).start()

    def submit(self, task):
        threading.Thread(target=self._worker, args=(task,)).start()

    def _worker(self, task):
        try:
            result = self._api_call(task)
        except Exception as exc:
            result = {"error": str(exc)}
        self.q.put(result)

    def _consume(self):
        while True:
            result = self.q.get()
            with self.state_lock:
                self._apply(result)
```

## 进程级单例锁（可选）

如果还要防止引擎多开，不要用 PID 文件自检测，用 `flock`：

```python
import fcntl

lock_file = open("/tmp/ark_engine.lock", "w")
try:
    fcntl.flock(lock_file, fcntl.LOCK_EX | fcntl.LOCK_NB)
except OSError:
    raise RuntimeError("已有引擎实例在运行")
```

---

这套方案把“并发 API 调用”和“串行状态提交”彻底分离，锁的粒度小、路径清晰，能同时覆盖状态一致性、自进化闭环、冷却重置和已有踩坑经验。
