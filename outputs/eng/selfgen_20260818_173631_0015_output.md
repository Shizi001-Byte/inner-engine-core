# 任务类型: eng

以下为设计引擎产出的**自动归档系统 v1.0**。基于锚定直接推演，不重复论证。

## 0. 设计基线

- 归档对象是“事件/任务/冲突”，不是“AI 实例的私有记忆”。
- 第一件事不是补全记忆，而是**锚定 `source_event`**；无法锚定则降级为**个体叙事**。
- 系统是**带验证门和公共档案的协作 DAG**，不是多个 AI 实例的集合。
- 节点间只传递结构化产物 `TaskRecord`，不传原始长上下文。

---

## 1. 总体节点流

```
输入
→ N1 自动分类
→ G1 分类验证门
→ N2 打标签
→ G2 标签验证门
→ N3 目录映射 + G3 终验 + 提交
→ 公共档案 / 个体叙事 / 隔离区
```

三个串联节点：**分类、打标签、归档**。  
阴阳双轨体现在：N1/N2 是“生成轨”，G3 是“验证轨”。

---

## 2. N1：自动分类

**输入**：原始任务/冲突事件  
**模型/超时**：B 模型 turbo，300 秒  
**输出结构化产物**：

```json
{
  "task_id": "t1",
  "source_event": "event://...",
  "category": "conflict",
  "category_conf": 0.92,
  "config_version": "2026-01-01-v3"
}
```

**关键规则**：

- 先尝试提取/确认 `source_event`。
- 若没有可验证事件，`category` 直接置为 `narrative`，后续不补全记忆。
- 超时则降级为规则分类；规则分类也失败则进隔离区。

---

## 3. G1：分类验证门

- `category` 必须在分类注册表中。
- `source_event` 缺失且 `category != narrative` → 强制降级为 `narrative`。
- `config_version` 必须与当前配置注册表一致，否则拒绝并提示“配置漂移”。

---

## 4. N2：打标签

**输入**：N1 的结构化产物  
**模型/超时**：B 模型 turbo，300 秒  
**输出**：

```json
{
  "task_id": "t1",
  "tags": ["conflict:generation_vs_verification", "track:generation", "track:verification", "needs_verification"],
  "tag_conf": 0.88,
  "config_version": "2026-01-01-v3"
}
```

**自由与约束**：

- 生成侧自由：模型可以提议新标签。
- 验证侧约束：新标签必须先进入 `tag registry`，并通过 smoke test 才能生效。
- 标签必须携带轨道信息：`track:generation` 或 `track:verification`。

---

## 5. G2：标签验证门

- 所有标签必须在标签注册表中。
- 禁止同时存在 `verified` 和 `unverified`。
- 标签 `verified` 必须有 `evidence_refs` 支撑。
- 标签与分类必须一致，例如 `category=narrative` 不能打 `public` 标签。

---

## 6. N3：存入对应目录

**包含**：目录映射 → G3 终验 → 原子提交。

### 目录映射表

| 状态/分类 | 目标目录 |
|---|---|
| verified + 公共分类 | `/archive/public/verified/{category}/{task_id}.json` |
| narrative | `/archive/private/individual/{agent_id}/narrative/{task_id}.json` |
| 拒绝/隔离 | `/archive/quarantine/{reason}/{task_id}.json` |
| 过期/遗忘 | `/archive/cold/forgotten/{task_id}.json` |

### G3：终验

**模型/超时**：A 模型，600 秒  
**决策**：

- `approve` → 提交到公共档案。
- `downgrade` → 证据不足但有用，降级为个体叙事。
- `reject` → 进隔离区。

**G3 校验项**：

- `source_event` 是否真实存在。
- `category`、`tags`、`target_dir` 是否一致。
- 是否与已有公共档案冲突或重复。
- `config_version` 是否一致。

提交时原子写：

1. 写入目标 JSON 文件。
2. 追加 `archive_dag.jsonl` 节点记录。
3. 更新标签索引。

三者任一失败，不产生孤儿索引。

---

## 7. DAG 公共档案

`archive_dag.jsonl` 是唯一真相：

```json
{
  "task_id": "t1",
  "parent": "event://...",
  "category": "conflict",
  "tags": ["track:generation", "track:verification"],
  "status": "verified",
  "path": "/archive/public/verified/conflicts/t1.json",
  "verified_by": "A-model"
}
```

AI 实例查询档案时，拿到的是 **DAG 节点引用**，不是私有记忆副本。  
冲突事件按“双轨”归档：

- 生成轨节点：`track:generation`
- 验证轨节点：`track:verification`
- 终验通过后生成合并节点

---

## 8. 避坑落地

### 配置修改后不生效

- 唯一配置源：`config/registry.yaml`。
- 所有读取点统一从配置中心生成，禁止硬编码。
- 修改配置后必须执行：

```bash
sync_readers
archive_smoke_test --task "测试冲突" --expect category=conflict,tags=[...],target_dir=...
```

- 每个节点输出携带 `config_version`，验证门发现版本不一致即拒绝。

### API 超时

| 节点/门 | 模型 | 超时 |
|---|---|---|
| N1 分类 | B 模型 turbo | 300 秒 |
| N2 打标签 | B 模型 turbo | 300 秒 |
| G1/G2 | 本地规则 | 5 秒 |
| G3 终验 | A 模型 | 600 秒 |
| 提交 | 本地原子写 | 10 秒 |

所有调用必须显式设置 timeout，不依赖默认值。  
超时后走降级/隔离，绝不静默成功。
