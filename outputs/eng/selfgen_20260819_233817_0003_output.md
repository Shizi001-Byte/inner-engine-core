# 任务类型: eng

# 修复方案：产出同质化/套话多

## 一、多目标优化视角下的问题诊断

沿用「单游标局部最优」的认知锚点，本问题是同一病根在**输出层**的复现：

| 维度 | 并发陷阱（已知） | 同质化陷阱（本次） |
|---|---|---|
| 单一游标 | 单任务失败率 | 任务完成率 / 相似度匹配分 |
| 隐性代价 | OOM/死锁激增 | 输出 embedding 收敛到狭窄流形 |
| 表现 | 5路不如3路 | 高分但可读性/信息密度下降 |
| 根因 | 缺资源健康度目标 | 缺多样性目标 |

引擎在自进化时只奖励"答对"，从不惩罚"答对但雷同"。模型在梯度方向上自然收敛到最安全的套话模板（"综上所述/需要注意的是/总而言之"），因为这是完成率方差最小的局部最优。

## 二、修复方案设计（多目标，软约束）

采用 **主目标硬约束 + 次目标软惩罚** 的 Pareto 结构，避免为多样性牺牲正确性：

```
final_score = success_score                    # 硬门槛，必须 ≥ threshold
            + w_div * diversity_score            # 软奖励，与近 N 条输出的最小余弦距离
            - w_boil * boilerplate_penalty       # 软惩罚，套话短语命中数
```

关键约束：**不修改记忆、不全量扫描、不强制输出格式**。
- 多样性只与"近 N 条缓存"对比（N≤16，LRU），不做全量扫描；
- 套话用"负面清单"软扣分，不规定必须怎么写，符合"无标准化强制"；
- 评分发生在 selection 层，不动对话记忆。

## 三、代码修改点

### 改动点1：`scoring/score_task.py`（核心）
```python
# Before
def score_task(output: str, expected: str) -> float:
    return 1.0 if is_success(output, expected) else 0.0

# After
def score_task(output, expected, ctx: ScoreCtx) -> ScoreResult:
    success = 1.0 if is_success(output, expected) else 0.0
    diversity = ctx.recent_emb.min_cosine_distance(emb(output))  # LRU≤16
    boil = count_boilerplate(output, ctx.boil_bank)               # 命中数
    final = success + ctx.w_div * diversity - ctx.w_boil * boil
    return ScoreResult(success=success, diversity=diversity,
                       boil=boil, final=final)
```
读取点同步：`ScoreCtx` 必须从 `config/runtime.yaml` 单一来源加载 `w_div / w_boil / boil_bank_path`，**严禁在函数内硬编码默认值**（避坑1）。

### 改动点2：`evolution/selector.py`
```python
# Before：单目标排序
candidates.sort(key=lambda c: c.score, reverse=True)

# After：硬门槛 + 双软目标
passed = [c for c in candidates if c.success_score >= ctx.success_thr]
passed.sort(key=lambda c: (c.diversity - ctx.w_boil * c.boil), reverse=True)
```
避免引入新的局部最优：`success_thr` 维持原值不动，仅新增次目标。

### 改动点3：新增 `detection/boilerplate.py`
- 维护可配置短语黑名单（如"综上所述、需要注意的是、总而言之、不可忽视"）
- 纯 regex 本地匹配，零外部调用，无 timeout 风险
- 黑名单走配置文件，**改完立即冒烟测试验证生效**（避坑1）

### 改动点4：`prompts/system_prompt.py`（最小侵入）
仅在系统提示追加**负面清单**（不规定正向格式，守住"无标准化强制"）：
```
- 避免以下高频套话：[来自 boil_bank 的动态列表]
- 完成任务即可，无需收束性总结句
```
列表动态注入，改配置即生效，无需改代码。

## 四、验证方法（分层）

### L1 单元验证（配置生效，对应避坑1）
```bash
# 修改 boil_bank 加一条新短语"本次任务"
pytest tests/test_score.py::test_boil_config_hot_reload
# 期望：同一输出在新配置下分数下降 w_boil
```

### L2 多样性回归（防局部最优复现）
固定 10 个任务，A/B 跑两组：
| 组 | w_div | w_boil | 预期 |
|---|---|---|---|
| A（baseline） | 0 | 0 | 同质化基线 |
| B（修复） | 0.3 | 0.2 | 见下 |

指标：
1. 输出两两平均余弦相似度 ↓ ≥ 15%
2. 套话短语命中率 ↓ ≥ 60%
3. **任务成功率不下降超过 2pp**（硬约束防过优化）

### L3 真实进化环回归
在自进化 loop 跑 1 轮，断言：
- LRU 缓存命中率 > 0（证明 diversity 在生效路径上）
- 无 OOM / 无全量扫描日志（守住 5 项锚点）
- 平均 latency 不超过 B 模型 turbo 300s / A 模型 600s（避坑2，diversity 计算走本地 emb 模型，不触发大模型调用）

## 五、风险防控（medium 等级对应措施）

| 风险 | 缓解 |
|---|---|
| w_div 过大 → 为新颖牺牲正确性 | Pareto 硬门槛 + A/B 监控成功率，超 2pp 自动回滚 w_div |
| 套话黑名单误杀领域术语 | 软扣分而非过滤，扣分上限 0.2*w_boil |
| emb 缓存膨胀 | LRU 上限 16，OOM 风险可控 |
| 配置改了不生效（避坑1） | 三处读取点统一走 `ScoreCtx`，单测覆盖热加载 |
| diversity 计算意外触发大模型（避坑2） | 强制本地 sentence-embedder，禁用远程 API 路径 |

## 六、上线节奏

1. 先合 `boilerplate.py` + 配置 + 单测（无行为变化，零风险）
2. 再开 `w_boil=0.2` 灰度，跑 L2 验证套话下降
3. 最后开 `w_div=0.3`，监控成功率与 latency
4. 任一指标越线即按上表回滚单个权重，互不影响

这样设计的核心收益：把"套话多"从主观感受转化为可观测、可回滚的多目标变量，避免重蹈"单游标→隐性崩溃"的并发陷阱。
