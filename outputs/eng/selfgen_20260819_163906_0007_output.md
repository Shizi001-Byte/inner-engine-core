# 任务类型: eng

# 引擎产出自动归档系统设计方案

## 1. 定位与边界

- **输入**：引擎已完成的任务记录（任务 ID、输出内容、任务类型、时间、来源等）。
- **输出**：按分类/日期归档的稳定目录 + 规范化标签 + 可检索索引。
- **约束**：
  - 不突破“稳定 3 路并发”物理上限；
  - 模型调用必须有超时兜底；
  - 配置修改后必须即时验证生效；
  - 算力成本受预算限制，先规则后模型。

---

## 2. 调度：归档任务如何融入 3 路并发

归档任务不单独开并发，而是作为引擎任务池中的一类任务：

- 队列优先级：**生产任务 > 归档任务 > 自进化模板任务**
- 只有 `active_count < 3` 且没有更高优先级任务时，才取出归档任务执行。
- 归档任务在步骤边界可以让出执行权，不在模型调用中强制打断。
- 无任务时调度器阻塞等待，不空转；若空闲超过阈值，最多执行一次预算内的模板验证。

---

## 3. 八步拆解流程

| 步骤 | 动作 | 预算/超时 |
|---|---|---|
| 1 | **捕获**：监听任务完成事件，按 `task_id` 幂等创建归档任务 | 无模型调用 |
| 2 | **排队**：进入归档队列，等待空闲并发位 | 无模型调用 |
| 3 | **规则初判**：先用规则引擎分类，置信度 ≥ 0.85 则直接采用 | 无模型调用 |
| 4 | **模型兜底**：规则未命中或置信度低时，调用 B 模型 turbo 分类/打标 | **300 秒** |
| 5 | **标签规范化**：合并系统标签和内容标签，去重、归一化、限长 | 无模型调用 |
| 6 | **目录映射**：分类映射到安全目录路径，防止路径穿越 | 无模型调用 |
| 7 | **原子写入**：写临时文件 → `os.replace` 原子迁移 → 写 `metadata.json` | IO 超时建议 10 秒 |
| 8 | **反馈与进化**：写归档反馈记录，统计重复率/失败率，触发模板生成 | 验证用 A 模型 **600 秒** |

---

## 4. 标准决策模块：触发器 / 执行器 / 反馈器

### 4.1 触发器

触发条件包括：

- 任务完成事件；
- 定时扫描未完成归档任务；
- 重复率超过阈值，触发新模板生成。

重复率阈值建议：

```text
最近 100 条归档记录中：
(verify_failed + needs_review) / total >= 5%
```

触发后不立即修改规则，而是进入“候选模板生成”流程。

### 4.2 执行器

执行器在每步开始前检查：

```text
1. 当前活动任务数 < 3；
2. 队列中无更高优先级任务；
3. 今日模型调用预算未超限；
4. 当前归档任务未超过对应 timeout。
```

模型调用预算示例：

- 分类/打标：B 模型 turbo，单次 **300 秒**，每小时最多 20 次；
- 模板验证：A 模型，单次 **600 秒**，每小时最多 10 次；
- 预算耗尽后，只做规则归档，不再调用模型。

### 4.3 反馈器：自进化闭环

闭环路径：

```text
检测重复率 → 生成新模板 → 注入任务池 → 验证生效
```

具体实现：

1. 归档反馈表中统计同一规则下的低置信率、失败率；
2. 重复率 ≥ 5% 时，抽取代表性样本；
3. 调用 B 模型 turbo 生成候选分类/打标模板，超时 **300 秒**；
4. 候选模板作为普通任务注入任务池，进入“验证任务”；
5. 调用 A 模型在历史样本上验证精确率/覆盖率，超时 **600 秒**；
6. 验证通过后，将模板写入配置，配置版本号 +1；
7. 立即执行 smoke test，验证配置已生效；失败则自动回滚。

## 5. 目录与标签规则

### 5.1 目录结构

```text
/archive
  /{category}
    /{yyyy}/{mm}/{dd}
      /{task_id}_{sha8}/
        main.result
        metadata.json
```

- `category` 只允许 `[a-z0-9_-]`，长度 ≤ 32；
- 未分类任务进入 `_unknown` 目录，等待复核；
- 同一任务有多个标签时不复制物理文件，只写索引指针。

### 5.2 标签规则

标签分两类：

- 系统标签：`source=engine`、`task_type`、`status`、`archived_at`；
- 内容标签：由规则或模型提取，必须经过标签字典归一化。

示例：

```text
tag_dict:
  bug:
    aliases: [error, exception, crash]
  api:
    aliases: [interface, endpoint]
```

新标签不直接使用，先进入候选标签池；同一候选标签出现 ≥ 3 次后，再考虑提升到正式标签字典。

### 5.3 metadata.json

```json
{
  "task_id": "t-001",
  "category": "api_issue",
  "tags": ["api", "timeout"],
  "source_path": "/tmp/output/t-001.result",
  "archived_at": "2026-01-01T00:00:00Z",
  "config_version": 12
}
```

## 6. 避坑保障

### 6.1 配置修改后必须立即生效

- 所有读取点统一走 `ConfigService.get("archive")`；
- 不允许在业务代码里硬编码分类规则、目录路径、阈值、超时时间；
- 配置变更后自动执行 smoke test：

```text
用一条已知预期分类/标签的任务跑通归档链路；
通过则保留新配置；
不通过则回滚旧配置并告警。
```

### 6.2 API 调用超时

- B 模型 turbo：分类/打标，超时 **300 秒**；
- A 模型：模板验证，超时 **600 秒**；
- 超时不重试，避免占用并发位和算力；
- 超时后降级为规则结果，并标记 `needs_review=true`。

### 6.3 算力非零成本

- 规则优先，模型兜底；
- 按 `task_hash` 缓存分类结果，重复任务直接复用；
- 每日模型调用预算写死在配置中心，而不是散落在代码里。

### 6.4 稳定 3 路并发不被突破

- 归档任务和模板验证任务都复用同一个并发闸口；
- 不允许在归档系统内部使用额外的 `asyncio.gather` 或线程池；
- 所有并发执行统一由引擎调度器控制。

---

这个方案将“自动分类、打标签、存入对应目录”的归档流程，固化成了引擎标准决策模块下的一个可自进化、可预算控制、可验证生效的执行器。
