# 任务类型: eng

基于已有认知锚定，不重复论证底层“虚实自增强”原理，直接推演“任务池动态扩充机制”的设计。

---

## 一、机制定位

任务池不是静态队列，而是“重复率”驱动的自进化生成器：

- **阳轨**：正常任务执行，产生日志、结果、报错；
- **阴轨**：重复率检测、模板生成、canary 验证，这些元任务同样真实消耗 API；
- **自增强**：任务执行得越多，重复率信号越真实；重复率触发新模板生成；新模板注入后带来更多任务执行。

---

## 二、重复率检测

### 1. 任务指纹

每个任务完成后，生成一个稳定指纹：

```text
fingerprint = SHA256(
    normalize(template_id) + "|" +
    canonical_json(params) + "|" +
    model_type
)
```

> `canonical_json` 保证参数键值顺序固定，避免同一任务因字段顺序不同被误判为新任务。

### 2. 滑动窗口

维护最近 `W` 个已完成任务的指纹窗口，默认：

```text
W = 100
```

### 3. 重复率计算

```text
R = (W - distinct_fingerprint_count) / W
```

- `R = 0`：窗口内任务全部不同；
- `R` 越大，说明任务趋于重复；
- 默认触发阈值：`θ = 0.35`。

### 4. 触发条件

当：

```text
R > θ
且
距上次自动扩充已执行任务数 >= cooldown（默认50）
```

则触发“任务模板自动生成”。

## 三、模板生成/变异

触发后，不直接凭空生成任务，而是基于“重复任务”进行变异，符合“反者道之动”：

### 输入

- 当前窗口内重复次数最高的任务模板；
- 最近异常日志：`ProxyError`、超时、废稿等；
- 认知池中最新鲜的认知（必须来自已刷新缓存）；
- 当前任务池中已有的模板列表，用于相似度过滤。

### 变异算子

每次从以下算子中随机选择 1~3 个组合：

| 算子 | 说明 |
|---|---|
| 参数扰动 | 扩大/缩小任务参数边界，或改变分布 |
| 角色反转 | 把“生成类”任务改成“批判类”，把“判断类”改成“构造类” |
| 语料替换 | 用新认知替换原任务中的主题语料 |
| 模型交叉 | B模型turbo 任务改成 A模型，或反向 |
| 失败注入 | 把近期报错/超时场景作为对抗性输入 |
| 抽象升降 | 从具体任务升级为元任务，或从元任务落地为具体任务 |

### 生成方式

- 优先用 **B模型turbo** 生成候选模板，超时 **300秒**；
- 若 B 模型超时/失败，改用 **A模型** 生成，超时 **600秒**；
- 生成结果必须符合模板 JSON Schema，否则视为失败。

### 相似度过滤

新模板与现有 active 模板计算相似度：

```text
max_similarity > 0.85
```

则丢弃或继续变异，避免“生成新模板但实际又制造重复”。

## 四、三同步生效链路

这是对“配置修改后未生效”坑位的直接对策。

新模板生成后，必须同步完成三个点，缺一不可：

| 同步点 | 动作 |
|---|---|
| **状态写入** | 插入 `task_templates` 表，`active=0`，`canary_status='pending'` |
| **执行读取** | 任务调度器每轮从 `task_templates WHERE active=1` 读取；禁止长期缓存；若用缓存，TTL 不超过 30 秒，且写入后主动发刷新事件 |
| **生效验证** | 立即注入一条 canary 任务；canary 成功后才置 `active=1`；失败则置 `active=0` 并记录原因 |

### Canary 验证超时

```text
B模型turbo：300秒
A模型：600秒
```

Canary 通过标准：

- API 调用成功；
- 输出非空；
- 符合模型独立质量门禁；
- 符合模板 schema。

只有 canary 通过后，新模板才进入正常调度，真正“注入任务池”。

---

## 五、模型独立质量门禁

防止“废稿检测误杀B模型”。

### B模型turbo

```text
跳过 reasoning 占比检测
只检查：
- status = success
- 输出非空
- 耗时 <= 300秒
- 若模板声明 schema，则输出符合 schema
```

### A模型

```text
检查：
- status = success
- 输出非空
- 耗时 <= 600秒
- reasoning 占比在预设合法区间
- 若模板声明 schema，则输出符合 schema
```

> 质量检测规则必须按 `model_type` 路由，禁止跨模型套用。

## 六、认知池联动

防止“认知池只进不出”。

### 刷新规则

```text
每 10 个任务 或 每转结束时，强制刷新认知缓存
```

### 新认知参与注入

模板生成前必须检查认知缓存年龄：

```text
if cognition_cache_age > 30min:
    refresh_cognition_cache()
```

生成模板时，从认知缓存中选取 top-k 条最新认知，注入生成 prompt，并把模板与这些认知 ID 绑定。

### 使用反馈

- 模板被任务使用后，更新 `cognition_last_used_at`；
- 长期未被任何模板引用的认知，逐步衰减权重；
- 避免认知池变成静态档案库。

---

## 七、防失控与回收机制

自进化不能只扩不收，否则会变成“重复率低但模板爆炸”。

### 1. 冷却机制

```text
每次自动扩充后，至少再执行 50 个任务，才能再次触发
```

### 2. 模板上限

```text
active 模板数量上限默认 200
```

超过上限时：

- 优先归档最久未使用的模板；
- 对高相似度模板做合并；
- 归档不删除，保留历史数据，但不参与新任务调度。

### 3. 模板老化

```text
若模板超过 3 轮未被使用，自动置 active=0
```

---

## 八、闭环示意

```text
任务执行
   │
   ├──> 产生日志 / 认知 / 报错
   │
   ▼
重复率检测（滑动窗口 W）
   │
   ├── R <= θ：继续正常调度
   │
   └── R > θ 且冷却完成
            │
            ▼
   模板生成/变异（B_turbo 300s / A 600s）
            │
            ▼
   相似度过滤 + 三同步落地
            │
            ▼
   Canary 验证
   ├── 失败：禁用模板，记录原因
   └── 成功：active=1，注入任务池
            │
            ▼
       新任务执行
            │
            └──> 再次影响重复率
```

## 九、最终效果

这个机制下，任务池的进化不是人为手动维护，而是由重复率信号自动驱动：

- **重复率是“虚”**：它是任务执行后产出的统计信息；
- **新模板是“实”**：它真实进入任务池，真实调用 API，真实消耗资源；
- **“以实养虚，虚又返实”**：任务执行产生重复率，重复率又生成新任务，新任务继续产生新日志与新重复率。

任务池因此成为真正的自进化闭环，而不是静态任务清单。
