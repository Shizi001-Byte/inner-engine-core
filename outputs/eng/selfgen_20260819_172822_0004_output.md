# 任务类型: eng

## 结论

根因不是“L4 没有 code/checklist 生成能力”，而是**增量同步 ChainTask 链上的成品转化器只对 `sop` 做了分派**。  
修复点集中在：类型枚举、converter 分派表、Supabase 同步 payload 构造。

只推演增量同步链：`CF --> ChainTask --> L4 成品转化 --> SP[Supabase 认知池 实]`，不展开底层自恢复机制。

---

## 代码修改点

### 1. 类型枚举：允许 `code` / `checklist`

文件：`src/l4/artifact_types.py`

```python
class L4ArtifactType(str, Enum):
    SOP = "sop"
    CODE = "code"
    CHECKLIST = "checklist"
```

如果 `ChainTask.type` 目前是 `Literal["sop"]`，也要同步放开：

```python
ChainTaskType = Literal["sop", "code", "checklist"]
```

---

### 2. Converter：注册 code / checklist 转化器

文件：`src/l4/converter.py`

修改前：

```python
L4_CONVERTERS = {
    "sop": convert_sop,
}
```

修改后：

```python
L4_CONVERTERS = {
    "sop": convert_sop,
    "code": convert_code,
    "checklist": convert_checklist,
}
```

新增两个转化函数：

```python
def convert_code(task: ChainTask) -> CodeArtifact:
    return CodeArtifact(
        language=task.payload.get("language", "python"),
        filename=task.payload.get("filename", "main.py"),
        code=task.payload["code"],
        run_command=task.payload.get("run_command"),
    )


def convert_checklist(task: ChainTask) -> ChecklistArtifact:
    return ChecklistArtifact(
        title=task.title,
        items=[
            ChecklistItem(
                text=item["text"],
                checked=item.get("checked", False),
            )
            for item in task.payload["items"]
        ],
    )
```

注意：这里不要把 `checklist` 当成普通 Markdown 列表，而是按结构化 `ChecklistArtifact` 转换，避免 SP 认知池出现“字面认知陷阱”。

---

### 3. Supabase 同步：去掉 `sop` 硬编码

文件：`src/l4/supabase_sync.py`

修改前：

```python
if artifact.type != "sop":
    raise UnsupportedL4Type(artifact.type)

payload = {
    "id": task.id,
    "artifact_type": "sop",
    "artifact_json": artifact.json(),
}
```

修改后：

```python
payload = {
    "id": task.id,
    "artifact_type": artifact.type,   # 来自 converter，而不是硬编码 "sop"
    "artifact_json": artifact.model_dump_json(),
}
```

如果同步链路里有 SQL 过滤：

```sql
-- 修改前
WHERE artifact_type = 'sop'

-- 修改后
WHERE artifact_type IN ('sop', 'code', 'checklist')
```

---

### 4. 如果 SP 表有数据库约束

如果 `cognitive_pool` 表有 `CHECK` 约束，需要做增量迁移：

```sql
ALTER TABLE cognitive_pool
  DROP CONSTRAINT IF EXISTS cognitive_pool_artifact_type_check;

ALTER TABLE cognitive_pool
  ADD CONSTRAINT cognitive_pool_artifact_type_check
  CHECK (artifact_type IN ('sop', 'code', 'checklist'));
```

这个改动是 additive 的，不影响已有 SOP 数据。

## 验证方法

### 1. 单元测试

新增测试文件：`tests/l4/test_converter.py`

```python
def test_convert_code():
    task = ChainTask(
        id="task_code_1",
        type="code",
        payload={
            "language": "python",
            "filename": "run.py",
            "code": "print('hello')",
        },
    )

    result = convert_l4_artifact(task)

    assert result.type == "code"
    assert result.code == "print('hello')"


def test_convert_checklist():
    task = ChainTask(
        id="task_checklist_1",
        type="checklist",
        title="发布前检查",
        payload={
            "items": [
                {"text": "构建通过", "checked": True},
                {"text": "测试通过", "checked": False},
            ]
        },
    )

    result = convert_l4_artifact(task)

    assert result.type == "checklist"
    assert len(result.items) == 2
    assert result.items[1].checked is False
```

同时保留一个 SOP 回归测试，确保原有行为不变化。

### 2. 增量同步集成测试

在 Guardian-Core 双进程最小环境里执行：

```python
# 构造 CF -> ChainTask(type=code) -> sync
task = ChainTask(
    id="sync_code_1",
    type="code",
    payload={"language": "python", "code": "print('ok')"},
)

run_incremental_sync(task)
```

然后查询 Supabase 认知池：

```sql
SELECT id, artifact_type, artifact_json
FROM cognitive_pool
WHERE id = 'sync_code_1';
```

预期：

```text
id           | artifact_type | artifact_json
sync_code_1  | code          | {"language":"python","code":"print('ok')"}
```

再跑一次同样的 `run_incremental_sync(task)`，应幂等更新，不产生重复记录。

---

### 3. 配置生效验证

如果这次修复引入了配置项，例如：

```python
L4_ENABLED_TYPES = ["sop", "code", "checklist"]
```

必须同步修改读取点：

- `src/l4/settings.py`
- `src/l4/converter.py` 中的白名单判断

不能只改 `.env` 或配置文件，否则会出现“配置修改后未生效，行为无变化”。

验证方式：

```bash
L4_ENABLED_TYPES='["sop","code"]' pytest tests/l4/test_converter.py -k code
```

如果 `code` 被禁用，则应抛出预期异常。

## 风险等级

**low**

原因：

- 只做加法，不修改 SOP 原有转换路径。
- 不需要迁移旧数据。
- 回滚方式简单：回退 `converter.py` 和 `supabase_sync.py` 的改动即可。
- 如果转换 code/checklist 时不需要调用 LLM，则无新增超时风险；如果需要调用模型，按已有约定设置 timeout：B 模型 turbo 用 300 秒，A 模型用 600 秒。
