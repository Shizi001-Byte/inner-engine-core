# 任务类型: eng

以下只推演“增量同步”这条 **ChainTask** 链，不重述底层自恢复机制。

## 问题定位

产出同质化、套话多的根因不在生成模型，而在 ChainTask 增量同步链里缺少“差异化信号”：

1. 每次生成都从 `SP[Supabase 认知池]` 取最相关、最高频的片段，导致上下文固定。
2. 本地文件中的“外部大众语义”和内部规则定义之间的“字面认知陷阱”，没有被作为增量冲突注入生成。
3. 没有对“最近已产出文本”做重叠检测，模型会不断复用上一轮句式。

修复方案：在 ChainTask 中增加一个 **Diversity Gate（多样性闸门）**，把“增量冲突”变成“反套话素材”，而不是简单过滤。

---

## 修复设计

```
本地文件（外部大众语义）
        ↓
增量同步 ChainTask
        ↓
SP 认知池（内部规则定义）
        ↓
新步骤：检测字面认知陷阱 + 检测近期产出重叠度
        ↓
生成 prompt 时注入“反套话约束”和“冲突表达对”
        ↓
输出
```

核心逻辑：**当检测到“套话度高”或“存在字面认知陷阱”时，强制让模型用冲突语义重新表述，而不是复用内部规则模板。**

### 3. 新增 `cliche_detector.py`

```python
# services/cliche_detector.py
from collections import Counter

CLICHE_NGRAMS = {
    1: {"首先", "其次", "最后", "综上", "总而言之", "值得注意的是", "众所周知"},
    2: {("赋能", "业务"), ("闭环", "管理"), ("抓手", "落实")},
}

def cliche_score(texts):
    hits = 0
    total = 0
    for text in texts:
        tokens = text.split()  # 实际请用你的 tokenizer
        for n, phrases in CLICHE_NGRAMS.items():
            ngrams = zip(*[tokens[i:] for i in range(n)])
            ngrams = list(ngrams)
            hits += sum(1 for ng in ngrams if ng in phrases)
            total += len(ngrams)
    return hits / max(total, 1)

def extract_common_patterns(texts, top_n=5):
    counter = Counter()
    for text in texts:
        tokens = text.split()
        for n in (2, 3):
            for i in range(len(tokens) - n + 1):
                counter[tuple(tokens[i:i+n])] += 1
    return [" ".join(ng) for ng, _ in counter.most_common(top_n)]
```

### 4. 修改 `services/chain_task.py`

在增量同步后、生成 prompt 前，加入 Diversity Gate：

```python
# services/chain_task.py
from .cliche_detector import cliche_score, extract_common_patterns
from .sp_client import fetch_recent_outputs, fetch_conflict_pairs

def run_chain_task(task):
    # 原有增量同步：CF -> SP
    sp.sync_cognitive_pool(task.cf, task.local_file)

    # 新增：多样性信号
    recent_outputs = fetch_recent_outputs(
        cf=task.cf,
        intent=task.intent,
        limit=MAX_RECENT_OUTPUTS,
    )

    score = cliche_score(recent_outputs)

    task.need_anti_cliche = False
    task.conflict_pairs = []
    task.forbidden_patterns = []

    if score > CLICHE_THRESHOLD:
        task.need_anti_cliche = True
        task.forbidden_patterns = extract_common_patterns(recent_outputs)
        task.conflict_pairs = fetch_conflict_pairs(
            cf=task.cf,
            limit=TOP_K_CONFLICTS,
        )

    prompt = build_prompt(task)

    # 按模型类型设置 timeout：B 模型 turbo 用 300 秒，A 模型用 600 秒
    timeout = 300 if task.model_type == "B" else 600
    response = call_model(prompt, timeout=timeout)

    sp.save_output_fingerprint(
        cf=task.cf,
        intent=task.intent,
        output_text=response,
    )

    return response
```

### 5. 修改 `prompt_builder.py`

```python
# prompt_builder.py
def build_prompt(task):
    prompt = base_prompt(task)

    if not task.need_anti_cliche:
        return prompt

    prompt += "\n[反同质化约束]\n"
    prompt += "- 禁止使用以下套话/固定句式：\n"
    for pattern in task.forbidden_patterns:
        prompt += f"  - {pattern}\n"

    if task.conflict_pairs:
        prompt += "\n[字面认知陷阱提醒]\n"
        for pair in task.conflict_pairs:
            prompt += (
                f"- 外部常把“{pair['term']}”表述为“{pair['external_expression']}”，"
                f"但内部规则定义是“{pair['internal_definition']}”。\n"
                f"  请不要直接复制内部定义，也不要用外部错误说法；"
                f"用差异点或具体场景重新解释。\n"
            )

    prompt += "- 如果必须使用术语，请换一种类比或场景。\n"
    return prompt
```

### 6. 新增 SP 查询方法

```python
# services/sp_client.py
def fetch_recent_outputs(cf, intent, limit=20):
    return supabase.table("sp_output_fingerprints") \
        .select("output_text") \
        .eq("cf", cf) \
        .eq("intent", intent) \
        .order("created_at", desc=True) \
        .limit(limit) \
        .execute()

def fetch_conflict_pairs(cf, limit=3):
    return supabase.table("sp_expression_conflicts") \
        .select("term, external_expression, internal_definition") \
        .eq("cf", cf) \
        .limit(limit) \
        .execute()

def save_output_fingerprint(cf, intent, output_text):
    fingerprint = ngram_fingerprint(output_text, n=3)
    supabase.table("sp_output_fingerprints").insert({
        "cf": cf,
        "intent": intent,
        "output_text": output_text,
        "fingerprint": fingerprint,
    }).execute()
```

## 验证方法

### 1. 单元测试

`tests/test_diversity_gate.py`：

```python
def test_same_intent_outputs_not_cliche():
    task1 = make_task(cf="computer", intent="explain_memory")
    task2 = make_task(cf="computer", intent="explain_memory")

    out1 = run_chain_task(task1)
    out2 = run_chain_task(task2)

    overlap = ngram_overlap(out1, out2, n=3)
    assert overlap < 0.3

def test_cliche_suppressed():
    task = make_task(cf="management", intent="explain_process")
    out = run_chain_task(task)
    assert "综上所述" not in out
    assert "赋能" not in out

def test_conflict_pair_injected():
    task = make_task(
        cf="computer",
        local_file="data/computer_terms.yaml",
        intent="explain_memory",
    )
    out = run_chain_task(task)
    # 不能直接说“内存=存储”，也不能只说“内存=运行空间”
    assert "内存就是存储" not in out
    assert "运行空间" in out
```

### 3. 回归验证

- 确认原有增量同步不中断：本地文件更新后，SP 认知池能正常同步。
- 确认 API 超时不阻塞：`diversity.enabled=true` 时，如果 embedding/查询超时，应降级为原始 prompt 并返回，不能导致任务失败。

### 4. 线上小流量对比

取同一批任务，分别用开启/关闭 Diversity Gate 生成：

- `Distinct-2` 提升 15% 以上；
- `Self-BLEU` 下降 20% 以上；
- 人工抽评“套话率”低于 10%。

## 风险控制（medium）

- 该改动只在 ChainTask 增量同步链内，不触碰 Guardian-Core 双进程架构。
- 通过 `diversity.enabled` 开关控制，默认可以先 `false`，验证后再开启。
- 如果线上出现质量回退，把 `diversity.enabled` 改为 `false` 即可回滚。
- 所有新增配置必须在 `config/settings.py` 中同步读取，修改后立即验证生效。
