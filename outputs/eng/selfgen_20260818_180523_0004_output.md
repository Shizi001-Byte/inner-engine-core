# 任务类型: eng

## V7.5 方舟效能引擎：多线程 API 调用 + 串行后处理的状态一致性锁方案

基于已有锚定，先给结论：

> **同步粒度是块，所以锁粒度也是块；远端只存不可变 DAG 顶点，所以锁只存在于本地进程；流程是 Detect → Diff → Commit，所以锁只用在节点边界，不能跨 API 调用持锁；提交前必须校验哈希/结构/来源；超时或冲突只熔断、不提交。**

---

## 1. 竞态来源

多线程 API 调用 + 串行后处理，本质上是一个：

> **多生产者 → 单消费者 → 单提交者**  
> 生产者 = API 调用线程  
> 消费者/提交者 = 串行后处理

核心竞态有 6 类：

| 竞态 | 根因 | 对策 |
|---|---|---|
| 部分结果被提交 | 某个线程先完成就触发后处理 | 结果缓冲 + `Condition` 等待全部完成 |
| 同一 block 被重复 Diff | 两个线程同时认领同一 block | 块级 striped lock + 状态机 |
| 旧结果覆盖新状态 | API 调用期间 head/version 已变化 | `expected_version` 乐观锁 |
| 读到半新半旧的索引 | 后处理逐个写 DAG 顶点 | 顶点先全部建好，head 一次原子切换 |
| 多个后处理并发写共享索引 | 多线程同时进入 Commit | `COMMIT_LOCK` 串行化 |
| 超时后线程继续写结果 | 线程未感知 abort | `Abort Event` + 提交前检查 |

## 2. 锁与状态机

### 2.1 锁集合

```python
class LockManager:
    def __init__(self):
        # 1. 全局状态锁：保护 head/version/DAG 容器
        self.global_lock = threading.RLock()

        # 2. 提交锁：保证同一时间只有一个 Commit 后处理
        self.commit_lock = threading.Lock()

        # 3. 结果收集锁/条件变量：保护 results/done/total/abort
        self.result_cond = threading.Condition()

        # 4. 块级 striped lock：保护每个 block 的状态
        self.block_locks = [threading.RLock() for _ in range(1024)]

        self.block_state = {}
        self.results = {}
        self.done = 0
        self.total = 0
        self.abort = threading.Event()

        self.dag = {}
        self.head = None
        self.version = 0

    def block_lock(self, block_id):
        idx = zlib.crc32(block_id.encode()) % len(self.block_locks)
        return self.block_locks[idx]
```

### 2.2 block 状态机

```
PENDING → FETCHING → DONE → COMMITTED
                  ↘ FAILED
```

- `PENDING`：Detect 发现需要同步
- `FETCHING`：已有线程认领，正在调 API
- `DONE`：API 成功且校验通过，结果已写入 result map
- `FAILED`：API 超时/异常/校验失败
- `COMMITTED`：已生成不可变 DAG 顶点并切换 head

## 3. 关键路径伪代码

### 3.1 配置读取点统一，避免“配置修改未生效”

```python
class RuntimeConfig:
    def __init__(self):
        self.lock = threading.RLock()
        # B 模型 turbo 用 300 秒，A 模型用 600 秒
        self.timeout_by_model = {
            "B_turbo": 300,
            "A": 600,
        }

    def snapshot(self):
        with self.lock:
            return dict(self.timeout_by_model)

    def reload(self, new_values):
        with self.lock:
            self.timeout_by_model.update(new_values)
        # 修改后立即验证生效
        for model, t in new_values.items():
            assert self.timeout(model) == t

    def timeout(self, model):
        with self.lock:
            return self.timeout_by_model[model]
```

### 3.2 API 调用：urllib 直连，绕过代理，校验 content 非空

```python
def call_ark_api(block_id, model_type, timeout):
    payload = {
        "model": model_type,
        "block_id": block_id,
    }

    req = urllib.request.Request(
        API_URL,
        data=json.dumps(payload).encode(),
        headers={"Content-Type": "application/json"},
    )

    # 统一 urllib 直连，避免全局代理导致 ProxyError
    opener = urllib.request.build_opener(urllib.request.ProxyHandler({}))

    with opener.open(req, timeout=timeout) as resp:
        data = json.loads(resp.read())

    # Responses API 可能把 output_tokens 全耗在 reasoning 上
    # 必须强制校验正式 content 非空，否则视为失败
    if not data.get("content"):
        raise EmptyContentError(block_id)

    return data
```

### 3.3 Diff 阶段：多线程生产结果

```python
def diff_worker(block_id, model_type, timeout):
    if lm.abort.is_set():
        return

    # 块级认领：防止同一个 block 被两个线程同时处理
    with lm.block_lock(block_id):
        if lm.block_state.get(block_id) != PENDING:
            return
        lm.block_state[block_id] = FETCHING

    try:
        data = call_ark_api(block_id, model_type, timeout)
        fact = validate_fact(data)

        if fact.get("deleted"):
            status = "DELETED"
        else:
            status = "OK"

    except Exception as e:
        with lm.result_cond:
            lm.results[block_id] = ("FAIL", e)
            lm.done += 1
            if lm.done >= lm.total:
                lm.result_cond.notify_all()
        return

    # 如果已经熔断，丢弃结果，不写入 result map
    if lm.abort.is_set():
        return

    with lm.result_cond:
        lm.results[block_id] = (status, fact)
        lm.done += 1
        if lm.done >= lm.total:
            lm.result_cond.notify_all()
```

### 3.4 等待全部完成：用 Condition，不用 threading.Barrier

```python
def wait_all_results(timeout):
    with lm.result_cond:
        ok = lm.result_cond.wait_for(
            lambda: lm.done >= lm.total or lm.abort.is_set(),
            timeout=timeout,
        )
        if not ok or lm.abort.is_set():
            lm.abort.set()
            return False
        return True
```

> 不要用 `threading.Barrier`：一旦某个线程超时，Barrier 会直接 `BrokenBarrierError`，处理更麻烦。

### 3.5 Commit 阶段：串行后处理 + 原子切换 head

```python
def commit(results, expected_version):
    if lm.abort.is_set():
        raise AbortError("abort happened before commit")

    with lm.commit_lock:  # 串行后处理

        # 1. 二次校验：任一 FAIL 都中止，不能把失败固化成事实
        for block_id, (status, fact) in results.items():
            if status == "FAIL":
                raise AbortError(block_id)
            validate_fact(fact)

        # 2. 版本校验：API 调用期间如果已有其他提交，则放弃
        with lm.global_lock:
            if lm.version != expected_version:
                raise ConcurrentVersionError(
                    expected_version, lm.version
                )
            prev_head = lm.head
            next_version = lm.version + 1

        # 3. 构建不可变 DAG 顶点，注意按 block_id 排序保证确定性
        new_vertices, new_index = build_dag_vertices(
            results,
            prev=prev_head,
            version=next_version,
        )

        # 4. 原子切换 head
        with lm.global_lock:
            # 再次检查版本，防止极端情况下版本变化
            if lm.version != expected_version:
                raise ConcurrentVersionError(
                    expected_version, lm.version
                )

            for v in new_vertices:
                lm.dag[v.id] = v
            lm.dag[new_index.id] = new_index

            lm.head = new_index
            lm.version = next_version

            for block_id in results:
                with lm.block_lock(block_id):
                    lm.block_state[block_id] = COMMITTED

        return lm.version
```

`build_dag_vertices` 规则：

- `OK`：生成不可变 `BlockVertex`，并加入新的 `IndexVertex.entries`
- `DELETED`：生成不可变 `TombstoneVertex`，不加入新的 `IndexVertex.entries`
- 已有 block 的顺序按旧 index 保持；新增 block 按 `block_id` 排序
- 绝对不修改旧顶点，只追加新顶点

## 4. 主流程编排

```python
def run_cycle(tasks):
    """
    tasks: [(block_id, model_type), ...]
    """
    if not tasks:
        return lm.version

    # 配置快照：当前周期统一使用同一份 timeout
    timeout_map = cfg.snapshot()

    with lm.global_lock:
        expected_version = lm.version
        prev_head = lm.head

    # Detect：基于不可变 index 计算变更集
    changed_tasks = detect_changed_blocks(prev_head, tasks)

    if not changed_tasks:
        return lm.version

    # 初始化本轮状态
    lm.total = len(changed_tasks)
    lm.done = 0
    lm.results = {}
    lm.abort.clear()

    for block_id, _ in changed_tasks:
        with lm.block_lock(block_id):
            lm.block_state[block_id] = PENDING

    overall_timeout = max(
        timeout_map[model_type] for _, model_type in changed_tasks
    ) + 30

    pool = ThreadPoolExecutor(max_workers=min(8, len(changed_tasks)))
    try:
        for block_id, model_type in changed_tasks:
            timeout = timeout_map[model_type]
            pool.submit(diff_worker, block_id, model_type, timeout)

        if not wait_all_results(overall_timeout):
            lm.abort.set()
            raise TimeoutError("Diff 阶段超时，熔断，不提交")

        return commit(lm.results, expected_version)

    finally:
        if lm.abort.is_set():
            pool.shutdown(wait=False, cancel_futures=True)
        else:
            pool.shutdown(wait=True)
```

## 5. 锁获取顺序与死锁规避

固定锁顺序：

```
COMMIT_LOCK → STATE_LOCK → BLOCK_LOCK
```

`RESULT_COND` 单独使用，不与其他锁嵌套。

禁止事项：

1. **API 调用期间不持有任何锁**。
2. **禁止在持有 BLOCK_LOCK 时获取 STATE_LOCK**，否则会与 Commit 方向形成死锁环。
3. **禁止直接修改 head 指向的 IndexVertex**；只能创建新 IndexVertex 后原子切换 head。
4. **禁止把 FAIL 结果写入 DAG**；失败不是事实，超时/冲突必须熔断。

---

## 6. 避坑落实

| 历史坑 | 本方案落实 |
|---|---|
| 配置修改后未生效 | 所有 timeout 通过 `RuntimeConfig.snapshot()` 统一读取；`reload` 后立即断言验证 |
| API 超时 | B_turbo 300s、A 600s；`overall_timeout = max(timeout) + 30`；超时即 abort |
| 全局代理 ProxyError | 统一 `urllib` + `ProxyHandler({})`；不用 `requests` |
| Responses API content 为空 | `call_ark_api` 强制校验 `content` 非空，否则记为 FAIL |
| 多线程竞态 | 块级锁 + 结果缓冲 + Condition + 版本校验 + 串行提交 |
| 超时/冲突写入混乱 | Abort Event + 提交前二次校验；熔断时不生成任何 DAG 顶点 |

---

## 7. 最终一致性语义

- 线性化点是：`lm.head = new_index` 这一行。
- 提交前所有结果都在 `lm.results` 中缓冲，DAG 顶点不可变。
- 提交时一次切换 head，读者永远只能看到旧 head 或新 head，不会看到中间态。
- 远端 DAG 只新增 `block / index / tombstone` 顶点，不存任何“同步任务”或锁记录。
- 超时、冲突、校验失败时，不提交、不重试、不写半成品；等下一轮新的 Detect → Diff → Commit 周期重新开始。
