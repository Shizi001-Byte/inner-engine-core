# 任务类型: eng

基于「反者道之动」的底层逻辑与阴阳自衡架构，任务池的动态扩充机制不能是简单的“队列加塞”，而必须是**演化速率非对称的对抗与共生**。当重复率（阳之过度同质化、停滞）超过阈值时，引擎必须“反向”触发阴的收敛与重组，生成新任务（变异）注入池中，形成“试错驱动-异化收敛-新态注入”的自进化闭环。

以下为严格避坑的任务池动态扩充机制设计：

### 一、 重复率检测与配置全链路生效（避坑：配置修改未生效/自动调参失效）

**1. 阈值配置的三点同步法**
新增「任务重复率阈值」与「扩充触发开关」参数，必须严格执行以下三步，缺一不可：
*   **状态写入**：将 `Dup_Threshold` (默认0.65) 与 `Auto_Expand_Switch` 写入全局配置中心。
*   **执行读取**：重复率监控进程必须从实时配置中心读取，禁止使用本地缓存或硬编码。
*   **生效验证**：配置下发后立即注入一条测试任务，日志打印 `[Config Verify] Dup_Threshold=0.65, reader_status=OK`，未看到此日志视为配置未生效。

**2. 自动调参/扩容动作的闭环校验**
当检测到重复率超标并生成新模板时，必须验证三项配置（并发数/权重/冷却时间）是否随新模板真正变化：
*   新模板注入后，强制向任务池拉取一次任务，验证拉取到的确实是新模板ID。
*   校验新模板的调度权重与冷却时间已重置，防止“生成了新模板但调度器还在跑旧任务”的假扩充。

### 二、 阴阳双轨模板生成与超时控制（避坑：API调用超时/废稿检测误杀）

**1. 阴阳双轨生成机制**
*   **阳（自下而上的试错/B模型turbo）**：针对高频重复的骑手常规指令（如“催单话术”），调用B模型turbo快速裂变出10个新模板变体。**工程适配：预设timeout为300秒**。
*   **阴（顶层架构跃迁/A模型）**：当重复率持续居高不下，说明池子维度枯竭，调用A模型基于宏观认知池进行跨维度模板重构（如从“催单话术”跃迁至“情绪安抚+催单复合模板”）。**工程适配：预设timeout为600秒**。

**2. B模型废稿检测豁免（严格避坑）**
在模板生成与验证阶段，B模型生成的草稿中 `reasoning`（思考过程）占比达到70%-82%是正常特性。
*   **执行规则**：质检模块识别到 `model_type == 'B_turbo'` 时，**强制跳过 `reasoning` 占比检测**，仅对最终输出模板的逻辑完整性与格式进行打分，防止误杀导致B模型疯狂重试耗尽300秒超时。

### 三、 认知池强制反哺注入（避坑：认知池只进不出/静态档案库）

新模板不能是凭空捏造的随机字符，必须作为认知池的“出口”被激活。

**1. 强制绑定与缓存刷新**
*   **强制注入**：A/B模型生成新任务模板时，API请求体中必须携带从认知池中提取的至少1条“近30分钟内新增认知”作为Prompt上下文。
*   **缓存刷新**：每处理10个任务或每轮（转）调度结束时，强制清空并刷新认知缓存索引。若新模板未携带最新认知标签，系统拒绝入库。

**2. 动态扩充闭环流转图**
```
[骑手真实指令流] -> [指令指纹化比对]
      ↓
 (重复率 > Dup_Threshold?)
      ↓ (是)
[触发阴阳双轨生成器]
      ├─(阳) B模型turbo (300s超时, 跳过reasoning质检) -> 微变异模板
      └─(阴) A模型 (600s超时) + [刷新认知池缓存] -> 跨维度新模板
      ↓
[三态写入校验] -> 状态写入(库) + 执行读取(调度) + 生效验证(日志)
      ↓
[注入任务池] -> 动态权重调高，冷却时间缩短，优先派发
```

### 四、 实施总结
本机制将“重复率超标”这一负面现象，转化为“认知提取+模板变异+池体扩容”的正面驱动力，完美契合「反者道之动」。在工程落地时，只要死守**配置三点同步、B模型豁免质检、认知30分钟强制注入**这三条红线，即可避免历史踩坑，实现骑手AI引擎任务池的真正自进化。
