# 任务类型: eng

基于【已有认知锚定】与【避坑提醒】，我们将严格贯彻**“先校准锚点再优化链路”**原则，运用**“精气神三元迁移框架”**推演并设计「设计引擎产出的自动归档系统」。

针对「L4成品转化仅sop类型，code/checklist未实现」的痛点，本质是“精”的残缺导致“气”的断流。以下是系统性修复与归档系统的推演落地方案：

### 一、 精（底层实体/锚点）：校准类型枚举与状态闭环（落实修改点 A）

“精”是系统的基石，类型定义未闭环是一切断流的源头。必须首先补全 `code` 和 `checklist` 的实体定义。

1. **校准 `type` 枚举锚点**
   - 将 L4 成品类型枚举从单一的 `["sop"]` 扩展并闭环为 `["sop", "code", "checklist"]`。
   - 为每种类型定义严格的 Schema（数据结构），例如 `code` 需包含语言、依赖环境等字段，`checklist` 需包含检查项权重、验收标准等字段。
2. **同步配置与读取点（防范避坑提醒1）**
   - **排查读取点**：全面检索系统中所有依赖 L4 `type` 的配置文件、路由表及解析器。
   - **同步修改**：在新增 `code` 和 `checklist` 后，必须同步更新所有读取点的分支逻辑（如 `switch-case` 或策略模式路由），确保新类型能被正确识别。
   - **立即验证**：配置修改后，立即注入 `type=code` 和 `type=checklist` 的测试用例，验证读取点是否按预期生效，杜绝“配置改了但行为没变”的盲区。

### 二、 气（链路流转）：修复多线程并发与主线程串行后处理

“气”代表数据的流转。在多线程并发调用大模型 API + 主线程串行后处理的架构下，必须确保新补全的“精”能顺畅流转，不发生堆积或断流。

1. **并发层：API 调用与超时控制（防范避坑提醒2）**
   - **预设合理 Timeout**：根据任务类型动态分配超时时间。
     - 生成 `code` 和 `checklist` 若走 B 模型，强制设置 `timeout=300` 秒。
     - 若走 A 模型（如复杂代码重构或长篇 SOP 生成），强制设置 `timeout=600` 秒。
   - **熔断与重试**：超时后主线程不得无限期阻塞，需捕获 `TimeoutException`，标记任务失败并允许后续任务继续流转，防止主线程被拖死。
2. **串行后处理层：补全转化链路（修复断流）**
   - **消除隐式依赖**：之前主线程串行后处理可能硬编码了 `if type == 'sop'` 的隐式逻辑，导致 `code/checklist` 到达此处时静默丢弃（断流）。
   - **重构分发逻辑**：将后处理改造为基于 `type` 锚点的策略模式。
     - `sop` -> 走文档排版与步骤校验链路。
     - `code` -> 走语法检查与依赖打包链路。
     - `checklist` -> 走条目去重与格式化链路。

### 三、 神（系统目标）：设计引擎产出的自动归档系统

在“精”已校准、“气”已贯通的基础上，实现“神”——任务自动分类、打标签、存入对应目录的终极目标。

1. **自动分类（基于“精”的锚点驱动）**
   - 引擎产出 L4 成品后，归档系统直接读取校准后的 `type` 字段。
   - 分类器无需再做复杂推理，直接作为路由网关：`sop` 路由至知识库目录，`code` 路由至代码仓库或资产库，`checklist` 路由至 QA 资产目录。
2. **自动打标签（多维元数据注入）**
   - **静态标签**：基于 `type` 打底标签（`[L4]`, `[SOP/CODE/CHECKLIST]`）。
   - **动态标签**：从大模型 API 返回的元数据中提取摘要，结合时间戳、任务来源线程 ID 打上动态标签（如 `[并发Task-12]`, `[20231024]`），便于后续追溯。
3. **存入对应目录（归档执行器）**
   - **目录映射**：
     - `/archives/sop/{date}/{filename}.md`
     - `/archives/code/{date}/{filename}.{ext}`
     - `/archives/checklist/{date}/{filename}.yaml`
   - **原子化落盘**：主线程在串行后处理完成后，将标签元数据与转化后的实体打包，写入对应目录。写盘成功后向主线程发送 ACK，否则触发告警。

### 总结推演路径
**修改点 A（校准 type 枚举）** -> 同步所有读取点并即时验证生效（避坑1） -> 并发层按模型预设 300s/600s timeout（避坑2） -> 串行后处理层补全 code/checklist 的转化分发逻辑 -> 归档系统按 type 自动分类、打标签、落盘归档。

通过此推演，我们避免了“在错误的锚点（调度逻辑）上盲目优化”，确保了类型枚举的闭环，彻底打通了从大模型并发调用到自动归档的全链路。
