# 任务类型: eng

## 结论

多线程 API 调用 + 串行后处理，最稳的模型是：

> **任务锁 + 条件队列 + 状态机**  
> API 调用在锁外并发执行；状态迁移、结果写入、入队都在锁内完成；后处理由一个消费者线程通过 `Condition` 串行取任务。

不要用“裸 list + 全局锁”硬扛，也不要在持锁时做网络 IO。

---

## 1. 状态机锚点

先锚定任务状态，状态变更必须原子化：

```text
PENDING -> RUNNING -> READY -> PROCESSING -> DONE
```

说明：

- `PENDING`：初始状态
- `RUNNING`：API 调用中
- `READY`：API 已返回，结果/错误已写入，等待后处理
- `PROCESSING`：后处理中
- `DONE`：后处理完成，不代表业务成功，具体成功/失败看 `task.error`

**API 失败也进入 `READY`**，否则后处理线程会永远等不到总数闭合。

---

## 2. 锁机制总览

| 同步原语 | 作用 | 说明 |
|---|---|---|
| `Task.lock`（`RLock`） | 保护单个任务状态和结果字段 | 每个任务一把锁，避免全局锁竞争 |
| `ResultCollector.cond`（`Condition`） | 保护待处理队列和 `processed/total` 计数 | 同时用于后处理线程的等待/唤醒 |
| `Semaphore` | 限制 API 并发数 | 流量控制，不是一致性锁 |

**锁顺序强制规定：**

```text
Task.lock  ->  Collector.cond
```

禁止反向嵌套：

```text
Collector.cond -> Task.lock   // 禁止
```

后处理线程从队列取任务时，先拿 `Collector.cond`，弹出任务后立即释放，再拿 `Task.lock`，所以不会形成死锁。

## 3. 完整代码骨架

```python
import json
import threading
import urllib.request
from collections import deque
from concurrent.futures import ThreadPoolExecutor
from dataclasses import dataclass, field
from enum import Enum, auto
from typing import Optional

# 历史避坑：B 模型 turbo 用 300 秒，A 模型用 600 秒
MODEL_TIMEOUT = {
    "B_turbo": 300,
    "A": 600,
}


class TaskState(Enum):
    PENDING = auto()
    RUNNING = auto()
    READY = auto()
    PROCESSING = auto()
    DONE = auto()


@dataclass
class Task:
    task_id: str
    model: str
    url: str
    payload: dict
    state: TaskState = TaskState.PENDING
    result: Optional[dict] = None
    error: Optional[str] = None
    _lock: threading.RLock = field(default_factory=threading.RLock, repr=False)


class ResultCollector:
    """后处理队列 + 完成计数，统一由一把 Condition 保护。"""

    def __init__(self, total: int):
        self.total = total
        self.queue = deque()
        self.processed = 0
        self.cond = threading.Condition()

    def append(self, task: Task):
        with self.cond:
            self.queue.append(task)
            self.cond.notify()

    def next_task(self) -> Optional[Task]:
        with self.cond:
            while not self.queue and self.processed < self.total:
                self.cond.wait()

            if not self.queue:
                return None

            return self.queue.popleft()

    def mark_processed(self):
        with self.cond:
            self.processed += 1
            if self.processed >= self.total:
                self.cond.notify_all()


class ArkEngine:
    def __init__(self, tasks, max_workers=8):
        self.tasks = tasks
        self.collector = ResultCollector(len(tasks))
        self.semaphore = threading.Semaphore(max_workers)
        self.max_workers = max_workers

    # ============ 对外入口 ============

    def run(self):
        post_thread = threading.Thread(target=self._post_processing_loop)
        post_thread.start()

        max_w = min(self.max_workers, len(self.tasks)) if self.tasks else 1

        with ThreadPoolExecutor(max_workers=max_w) as executor:
            futures = [executor.submit(self._run_task, task) for task in self.tasks]
            for f in futures:
                f.result()

        post_thread.join()

        return [(t.task_id, t.state, t.error) for t in self.tasks]

    # ============ 并发 API 调用 ============

    def _run_task(self, task: Task):
        with self.semaphore:
            self._set_state(task, TaskState.PENDING, TaskState.RUNNING)

            try:
                result = self._call_api(task)
                self._complete(task, result)
            except Exception as e:
                self._fail(task, e)

    def _set_state(self, task: Task, expected: TaskState, new: TaskState):
        with task._lock:
            if task.state != expected:
                raise RuntimeError(
                    f"{task.task_id} 状态异常: {task.state} != {expected}"
                )
            task.state = new

    def _complete(self, task: Task, result: dict):
        with task._lock:
            if task.state != TaskState.RUNNING:
                raise RuntimeError(f"{task.task_id} 不在 RUNNING 状态")

            task.result = result
            task.error = None
            task.state = TaskState.READY

            # 持 Task.lock 时入队，保证：READY 状态一定已经在队列里
            self.collector.append(task)

    def _fail(self, task: Task, exc: Exception):
        with task._lock:
            if task.state != TaskState.RUNNING:
                raise RuntimeError(f"{task.task_id} 不在 RUNNING 状态")

            task.result = None
            task.error = str(exc)
            task.state = TaskState.READY

            # 失败也是结果，必须入队，否则后处理线程会一直等
            self.collector.append(task)

    # ============ 串行后处理 ============

    def _post_processing_loop(self):
        while True:
            task = self.collector.next_task()

            if task is None:
                return

            self._claim(task)

            try:
                self._post_process(task)
                self._finish(task)
            except Exception as e:
                self._finish(task, error=str(e))

    def _claim(self, task: Task):
        with task._lock:
            if task.state != TaskState.READY:
                raise RuntimeError(f"{task.task_id} 不在 READY 状态")

            task.state = TaskState.PROCESSING

    def _finish(self, task: Task, error: Optional[str] = None):
        with task._lock:
            if task.state != TaskState.PROCESSING:
                raise RuntimeError(f"{task.task_id} 不在 PROCESSING 状态")

            task.state = TaskState.DONE

            if error:
                task.error = error

            self.collector.mark_processed()

    def _post_process(self, task: Task):
        # 这里不需要再加全局锁，因为只有一个后处理线程。
        # 但如果要读其他任务，仍然必须按 Task.lock -> Collector.cond 顺序。
        pass

    # ============ API 调用，历史避坑全部落地 ============

    def _call_api(self, task: Task) -> dict:
        timeout = MODEL_TIMEOUT.get(task.model, 600)

        body = json.dumps(task.payload).encode("utf-8")

        req = urllib.request.Request(
            task.url,
            data=body,
            headers={"Content-Type": "application/json"},
            method="POST",
        )

        # 历史避坑：全局代理会导致 ProxyError
        # urllib 直连，并显式禁用代理
        opener = urllib.request.build_opener(
            urllib.request.ProxyHandler({})
        )

        with opener.open(req, timeout=timeout) as resp:
            raw = resp.read().decode("utf-8")

        data = json.loads(raw)

        # 历史避坑：Responses API 可能 content 为空，必须先校验
        content = self._extract_content(data)

        if not content:
            raise RuntimeError("Responses API content empty")

        return data

    def _extract_content(self, data: dict) -> str:
        if not isinstance(data, dict):
            return ""

        if data.get("content"):
            return data["content"]

        # 兼容 Responses API output 结构
        for item in data.get("output", []):
            if item.get("type") == "message":
                content = item.get("content")
                if content:
                    return content

        return ""
```

## 4. 竞态推演与规避

| 竞态场景 | 为什么会被锁住 |
|---|---|
| 两个 API 线程同时完成，同时写结果 | `Task.lock` 串行化单任务状态；`Collector.cond` 串行化入队 |
| 后处理线程读到一半的结果 | 后处理线程只能从队列取任务；任务入队前状态必须是 `READY`，且 `READY` 的赋值和入队在同一个临界区 |
| 同一任务被重复后处理 | `_claim` 将 `READY -> PROCESSING`，只能成功一次 |
| 后处理完成计数丢失 | `processed` 自增在 `Collector.cond` 保护下 |
| 后处理线程空等/提前退出 | `Condition.wait` 在 `while` 循环中，且 `total` 固定；所有失败也入队，保证最终闭合 |
| 死锁 | 禁止 `Collector.cond -> Task.lock` 嵌套；取任务时先释放队列锁，再拿任务锁 |

---

## 5. 避坑清单

1. **API 调用必须放在锁外**：`_run_task` 中先 `_set_state` 释放锁，再调 `_call_api`。
2. **不要引入 `requests`**：统一用 `urllib`，并且 `ProxyHandler({})` 直连。
3. **B 模型 turbo 用 300 秒，A 模型用 600 秒**：写在 `MODEL_TIMEOUT` 里。
4. **Responses API content 为空**：接入前先单测确认 `content` 路径；代码里 `_extract_content` 校验为空直接抛错。
5. **失败也必须入队**：否则 `processed` 永远到不了 `total`，后处理线程会卡死。

---

这套方案把“状态一致性”作为锚点，用状态机 + 锁顺序固化下来；执行层允许 API 并发，但后处理严格串行，不会因为多线程写共享状态而产生竞态。
