# 任务类型: eng

基于【已有认知锚定】的V7.5方舟效能引擎架构与“九转玄功”映射体系，我将**“先校准锚点再优化链路”**作为第一性原则，并结合历史避坑经验，为你设计**V7.5方舟效能引擎：任务自动归档系统**。

该系统将归档过程分为“锚点校验”、“链路执行（分类/打标签/存盘）”与“熔断保障”三个核心阶段。

---

### V7.5 方舟效能引擎：任务自动归档系统设计

#### 一、 第一转：锚点校验层（归零预判机制）
*映射认知：校验锚点10秒 : 未校验排查1小时 = 1 : 360*

在归档任务启动前，必须完成锚点（目标项目ID/工作空间）的绝对校验，严禁在未校验ID的情况下启动归档链路。

1. **ID探针校验**：
   - 读取待归档任务携带的 `Project_ID`。
   - 调用工作空间查询API，验证该 `Project_ID` 的真实性与归属。
   - **硬性阻断**：若ID不存在或不匹配，系统直接抛出 `AnchorValidationError`，阻断后续所有分类与存盘动作，避免“1小时劳动归零”。
2. **锚点快照锁定**：
   - 校验通过后，生成包含 `Project_ID`、`Workspace_Path`、`Timestamp` 的锚点快照，作为后续所有文件流转的绝对基准。

#### 二、 第二转：链路优化层（分类与打标签）
*映射认知：锚点正确后，链路优化才有意义*

进入正确的工作空间后，启动双模型异步链路进行任务解析、分类与打标签。

1. **A模型（深度解析模型）- 用于复杂任务分类**：
   - **职责**：分析任务执行日志、代码变更范围，生成多维度的语义标签。
   - **超时预设**：根据避坑经验，A模型预设 **timeout = 600秒**。
   - **动作**：产出标签如 `[架构变更]`、`[核心逻辑]`、`[依赖更新]`。
2. **B模型turbo（高频并发模型）- 用于常规任务打标签**：
   - **职责**：对海量常规子任务进行快速特征提取与轻量级打标签。
   - **超时预设**：根据避坑经验，B模型turbo预设 **timeout = 300秒**。
   - **动作**：产出标签如 `[文档更新]`、`[UI微调]`、`[日常修复]`。
3. **标签内存映射**：
   - 为避免配置修改后未生效（避坑点1），标签与分类规则采用“内存常驻+版本号”机制。读取点直接从内存映射表中获取，规则更新时同步刷新内存并立即发送测试任务验证生效。

#### 三、 第三转：归档执行层（自动存入对应目录）
*映射认知：动作方向性正确，落地存盘*

依据上一步产出的标签，将任务产物自动路由至锚点锁定的目录下。

1. **目录路由树设计**：
   ```text
   /{Project_ID}_Workspace/  <-- 锚点锁定的工作空间
       ├── /01_架构与核心/    <-- 命中[A模型] [架构变更]标签
       ├── /02_业务与功能/    <-- 命中[A模型] [核心逻辑]标签
       ├── /03_日常维护/      <-- 命中[B模型turbo] [日常修复]标签
       └── /04_文档与资源/    <-- 命中[B模型turbo] [文档更新]标签
   ```
2. **存盘动作与配置强校验（防范避坑点1）**：
   - 新增归档目录配置时，必须同步修改“路由读取点”。
   - **立即验证机制**：配置修改后，引擎自动生成一个 `.test_archive` 虚拟任务，强制走完一遍分类打标签到存盘的完整链路，若在目标目录未检测到该虚拟任务，则回滚配置并报警。

#### 四、 熔断与避坑保障机制

1. **API超时熔断器**：
   - 每次调用A/B模型时开启倒计时。
   - A模型达590秒（预留10秒IO）、B模型达290秒未返回，触发熔断，记录当前任务状态至“死信队列”，释放引擎线程，避免任务积压卡死。
2. **链路闭环校验**：
   - 任务存入目录后，引擎反向读取该目录的文件列表。
   - 若未发现刚归档的任务，判定为“行为无变化（配置未生效）”，触发告警并重试。

---

### 引擎执行流转总结

1. **[耗时10秒]** 抓取任务ID -> 校验工作空间锚点 -> 失败则归零重来，成功则锁定目录。
2. **[并行触发]** A模型(600s超时)深度分类 + B模型turbo(300s超时)快速打标签。
3. **[配置校验]** 读取路由配置表 -> 写入新分类规则 -> 立即验证读取点是否生效。
4. **[落盘归档]** 根据标签将任务产物写入对应子目录 -> 反向读取验证存盘成功。

该设计完全吸收了“看错项目ID导致1小时白干”的惨痛教训，将锚点校验作为不可逾越的护城河，同时从系统底层堵死了“配置不同步”和“API无响应拖垮全局”两个致命漏洞。
