## 推演总览：五链环紧扣

```
[链1] 文件变化检测 ──→ [链2] 内容寻址去重 ──→ [链3] 块级增量同步
                                                        │
[链5] 无状态验证 ←── [链4] 冲突检测与异构自适应解决 ←────┘
```

## 链1：文件变化检测 — 事件驱动，拒绝全量扫描

### 问题
恢复时不能遍历所有节点状态（硬约束3），但传统同步方案往往启动时全量扫描文件系统。

### 设计

```python
class ChangeDetector:
    """事件驱动变更检测，O(1)响应，不扫描"""
    
    def __init__(self, watch_path: str, storage: 'StorageBackend'):
        self.watch_path = watch_path
        self.storage = storage
        # 内存态映射，不落本地磁盘（硬约束2：无记忆修改）
        self._hash_cache: dict[str, str] = {}  # {filepath: content_hash}
        self._watcher = FileWatcher(watch_path)
        self._watcher.on_modify = self._on_change
        self._watcher.on_create = self._on_change
        self._watcher.on_delete = self._on_delete
    
    def _on_change(self, filepath: str):
        """单个文件变化 → 只算这一个文件的hash"""
        new_hash = compute_sha256(read_bytes(filepath))
        old_hash = self._hash_cache.get(filepath)
        
        if new_hash == old_hash:
            return  # 内容没变（可能是touch），跳过
        
        self._hash_cache[filepath] = new_hash
        # 推入同步队列，带content-addressed信息
        SyncEngine.instance().enqueue(
            filepath=filepath,
            new_hash=new_hash,
            old_hash=old_hash,
            event_type="upsert"
        )
    
    def _on_delete(self, filepath: str):
        old_hash = self._hash_cache.pop(filepath, None)
        if old_hash:
            SyncEngine.instance().enqueue(
                filepath=filepath,
                new_hash=None,
                old_hash=old_hash,
                event_type="delete"
            )
    
    def restore_state(self):
        """节点恢复时，从StorageBackend拉回hash映射，不全量扫描文件"""
        # 用scan_prefix有限查询，只取本节点的hash映射
        records = self.storage.scan_prefix(
            table="file_hashes",
            prefix={"node_id": self.node_id},
            limit=10000
        )
        self._hash_cache = {r["filepath"]: r["content_hash"] for r in records}
        # 然后异步比对本地文件与缓存hash，产生增量事件
```

### 关键决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 检测方式 | FS Watcher事件驱动 | O(1)响应，非O(N)扫描 |
| hash缓存位置 | 内存dict，不落盘 | 满足无记忆修改约束 |
| 恢复策略 | scan_prefix有限拉取 | 拒绝全量扫描 |

## 链2：内容寻址去重 — 相同内容只存一份

### 问题
多个文件/节点可能产生相同内容（如相同的reasoning输出），重复存储浪费带宽和存储。

### Supabase表结构设计

```sql
-- 内容寻址块表：天然去重
CREATE TABLE memory_blocks (
    block_hash TEXT PRIMARY KEY,      -- SHA-256(block_data)
    block_data BYTEA,
    size INT,
    created_at TIMESTAMPTZ DEFAULT now()
);

-- 文件元数据表：记录文件→块的映射
CREATE TABLE memory_files (
    filepath TEXT PRIMARY KEY,
    file_hash TEXT NOT NULL,           -- SHA-256(全部block_hash有序拼接)
    block_list TEXT[] NOT NULL,        -- 有序block_hash列表
    version INT NOT NULL DEFAULT 1,
    node_id TEXT NOT NULL,
    model_type TEXT NOT NULL,          -- 异构环境标识
    updated_at TIMESTAMPTZ DEFAULT now()
);

-- 节点hash缓存表：用于快速恢复
CREATE TABLE file_hashes (
    node_id TEXT,
    filepath TEXT,
    content_hash TEXT,
    updated_at TIMESTAMPTZ DEFAULT now(),
    PRIMARY KEY (node_id, filepath)
);

-- 索引：支持scan_prefix有限查询
CREATE INDEX idx_file_hashes_node ON file_hashes(node_id);
CREATE INDEX idx_memory_files_node ON memory_files(node_id);
CREATE INDEX idx_memory_files_model ON memory_files(model_type);
```

### 去重逻辑

```python
class ContentAddressedStore:
    """内容寻址存储：相同内容只存一份"""
    
    def upsert_content(self, data: bytes) -> str:
        block_hash = compute_sha256(data)
        # upsert天然去重，hash相同则不重复写入
        self.storage.upsert(
            table="memory_blocks",
            data={"block_hash": block_hash, "block_data": data, "size": len(data)},
            on_conflict="block_hash DO NOTHING"
        )
        return block_hash
    
    def file_exists_remote(self, file_hash: str) -> bool:
        """检查远端是否已有相同内容的文件"""
        result = self.storage.scan_prefix(
            table="memory_files",
            prefix={"file_hash": file_hash},
            limit=1
        )
        return len(result) > 0
```

### 链1→链2衔接

```
链1产出 → (filepath, new_hash, old_hash)事件
    ↓
链2消费 → 先查file_hash是否远端已存在
    ├─ 存在 → 只更新filepath→file_hash引用，不上传数据
    └─ 不存在 → 进入链3块级增量同步
```

## 链3：块级增量同步 — 只传变化的块

### 问题
文件内容微小变化（如修改一行），如果整文件上传浪费带宽。

### 块分割策略

```python
class BlockSyncEngine:
    """块级增量同步：只传变化的块"""
    
    BLOCK_SIZE = 4096  # 可配置，异构环境自适应
    
    def sync_file(self, filepath: str, new_hash: str, old_hash: str | None):
        # --- 链2已确认：远端不存在此file_hash，需要上传 ---
        
        new_data = read_bytes(filepath)
        new_blocks = self._split_blocks(new_data)
        
        # 获取旧块列表（从远端）
        old_block_list = []
        if old_hash:
            old_block_list = self._get_remote_block_list(filepath)
        
        # --- 块级diff ---
        changed_blocks = self._diff_blocks(new_blocks, old_block_list)
        
        if not changed_blocks:
            # 块没变但file_hash变了？理论上不该发生，防御性处理
            return
        
        # --- 只上传变化的块 ---
        uploaded_hashes = []
        for block_data in changed_blocks:
            block_hash = self.content_store.upsert_content(block_data)
            uploaded_hashes.append(block_hash)
        
        # --- 更新文件元数据（乐观锁） ---
        all_block_hashes = [compute_sha256(b) for b in new_blocks]
        new_version = self._get_next_version(filepath)
        
        try:
            self.storage.upsert_file_with_lock(
                filepath=filepath,
                file_hash=new_hash,
                block_list=all_block_hashes,
                version=new_version,
                node_id=self.node_id,
                model_type=self.model_type
            )
        except OptimisticLockError:
            # 版本冲突 → 进入链4冲突处理
            ConflictResolver.instance().resolve(filepath, new_hash, new_version)
    
    def _split_blocks(self, data: bytes) -> list[bytes]:
        return [data[i:i+self.BLOCK_SIZE] 
                for i in range(0, len(data), self.BLOCK_SIZE)]
    
    def _diff_blocks(self, new_blocks, old_block_list) -> list[bytes]:
        """只返回内容变化的块"""
        new_hashes = [compute_sha256(b) for b in new_blocks]
        old_set = set(old_block_list)
        
        changed = []
        for block, h in zip(new_blocks, new_hashes):
            if h not in old_set:
                changed.append(block)
        return changed
    
    def _get_remote_block_list(self, filepath: str) -> list[str]:
        record = self.storage.scan_prefix(
            table="memory_files",
            prefix={"filepath": filepath},
            limit=1
        )
        return record[0]["block_list"] if record else []
```

### 同步量对比

| 场景 | 全量同步 | 块级增量 | 节省 |
|------|----------|----------|------|
| 修改1行（4KB块） | 1MB | 4KB | 99.6% |
| 追加100行 | 1MB+100行 | 100行 | ~90% |
| 删除中间块 | 1MB | 0字节（只更新元数据） | 100% |

## 链4：冲突检测与异构自适应解决

### 问题
多节点同时修改同一文件时产生冲突；不同模型类型需要不同冲突策略。

### 冲突检测：乐观锁

```sql
-- Supabase RPC：带版本校验的原子更新
CREATE OR REPLACE FUNCTION upsert_file_versioned(
    p_filepath TEXT, p_file_hash TEXT, p_blocks TEXT[],
    p_version INT, p_node_id TEXT, p_model_type TEXT
) RETURNS BOOLEAN AS $$
BEGIN
    INSERT INTO memory_files (filepath, file_hash, block_list, version, node_id, model_type, updated_at)
    VALUES (p_filepath, p_file_hash, p_blocks, p_version, p_node_id, p_model_type, now())
    ON CONFLICT (filepath) DO UPDATE
    SET file_hash = p_file_hash, block_list = p_blocks, 
        version = p_version, updated_at = now()
    WHERE memory_files.version = p_version - 1;  -- 乐观锁
    RETURN FOUND;
END;
$$ LANGUAGE plpgsql;
```

```python
class OptimisticLockError(Exception):
    """版本冲突，远端已被其他节点修改"""
    pass
```

### 异构环境自适应冲突解决

```python
class ConflictResolver:
    """按模型类型分治的冲突解决器"""
    
    _instance = None
    
    def __init__(self):
        self.config = ConfigRegistry.instance()
    
    def resolve(self, filepath: str, local_hash: str, attempted_version: int):
        # 获取远端当前状态
        remote = self._get_remote_state(filepath)
        
        # 按模型类型选择策略
        model_type = self.config.get_current_model_type()
        strategy = self.config.get(model_type, "conflict_strategy")
        
        if strategy == "last_write_wins":
            return self._resolve_lww(filepath, local_hash, remote)
        elif strategy == "merge_blocks":
            return self._resolve_merge(filepath, local_hash, remote)
        elif strategy == "branch":
            return self._resolve_branch(filepath, local_hash, remote)
    
    def _resolve_lww(self, filepath, local_hash, remote):
        """B模型(turbo)：最后写入者胜，简单高效"""
        local_mtime = os.path.getmtime(filepath)
        if local_mtime > remote["updated_at"].timestamp():
            # 本地更新 → 强推
            self._force_push(filepath, local_hash, remote["version"] + 1)
        else:
            # 远端更新 → 拉取远端覆盖本地
            self._force_pull(filepath, remote)
    
    def _resolve_merge(self, filepath, local_hash, remote):
        """A模型：块级合并，保留双方修改"""
        local_data = read_bytes(filepath)
        remote_data = self._fetch_remote_data(remote["block_list"])
        
        # 块级三方合并
        base_data = self._get_base_data(remote["version"] - 1)
        merged = self._three_way_merge(
            base=base_data,
            local=local_data,
            remote=remote_data,
            block_size=self.config.get_block_size()
        )
        
        merged_hash = compute_sha256(merged)
        write_bytes(filepath, merged)
        self._force_push(filepath, merged_hash, remote["version"] + 1)
    
    def _resolve_branch(self, filepath, local_hash, remote):
        """保守策略：保留两个版本，创建分支"""
        branch_path = f"{filepath}.conflict.{int(time.time())}"
        write_bytes(branch_path, read_bytes(filepath))
        # 本地保留分支，主体拉取远端
        self._force_pull(filepath, remote)
```

### ConfigRegistry：异构配置分治

```python
class ConfigRegistry:
    """单例配置注册中心 — 异构环境自适应"""
    _instance = None
    
    DEFAULTS = {
        "B_turbo": {
            "block_size": 4096,
            "conflict_strategy": "last_write_wins",
            "timeout": 300,                    # 避坑：B模型turbo用300秒
            "skip_reasoning_check": True,       # 避坑：跳过reasoning占比检测
            "sync_batch_size": 50,
        },
        "A_model": {
            "block_size": 8192,
            "conflict_strategy": "merge_blocks",
            "timeout": 600,                    # 避坑：A模型用600秒
            "skip_reasoning_check": False,
            "sync_batch_size": 20,
        }
    }
    
    def get(self, model_type: str, key: str):
        config = self.DEFAULTS[model_type]
        # 避坑：配置修改后立即验证生效
        self._validate(config)
        return config[key]
    
    def _validate(self, config: dict):
        """配置变更后立即验证"""
        assert config["timeout"] > 0, "timeout必须为正数"
        assert config["block_size"] > 0, "block_size必须为正数"
```

### 超时保护

```python
class SyncExecutor:
    """带超时保护的同步执行器"""
    
    def execute_sync(self, filepath: str, sync_fn):
        model_type = ConfigRegistry.instance().get_current_model_type()
        timeout = ConfigRegistry.instance().get(model_type, "timeout")
        
        try:
            result = sync_fn(timeout=timeout)
            return result
        except TimeoutError:
            # 避坑：超时后标记任务为pending，不直接失败
            self._mark_pending(filepath)
            raise
```

## 链5：无状态验证 — 配置变更立即生效，质量规则分治

### 问题
配置修改后未生效（避坑1）；废稿检测误杀B模型（避坑2）。

### 解决方案

```python
class SyncValidator:
    """同步后验证 — 确保变更真的生效"""
    
    def validate_sync(self, filepath: str, expected_hash: str):
        # 1. 验证远端确实写入
        remote = self.storage.scan_prefix(
            table="memory_files",
            prefix={"filepath": filepath},
            limit=1
        )
        if not remote or remote[0]["file_hash"] != expected_hash:
            raise SyncVerificationError(f"远端未更新: {filepath}")
        
        # 2. 验证块数据完整
        for block_hash in remote[0]["block_list"]:
            block = self.storage.scan_prefix(
                table="memory_blocks",
                prefix={"block_hash": block_hash},
                limit=1
            )
            if not block:
                raise SyncVerificationError(f"块缺失: {block_hash}")
        
        # 3. 质量检测 — 异构规则分治
        self._quality_check(filepath, remote[0])
    
    def _quality_check(self, filepath: str, file_record: dict):
        model_type = file_record["model_type"]
        
        if model_type == "B_turbo":
            # 避坑：B模型跳过reasoning占比检测
            self._check_basic_quality(filepath)
        elif model_type == "A_model":
            # A模型执行完整质量检测
            self._check_full_quality(filepath)
    
    def _check_basic_quality(self, filepath: str):
        """B模型：只检查基本完整性"""
        data = read_bytes(filepath)
        if len(data) == 0:
            raise QualityError("空文件")
        # 不检查reasoning占比
    
    def _check_full_quality(self, filepath: str):
        """A模型：完整质量检测"""
        data = read_bytes(filepath)
        if len(data) == 0:
            raise QualityError("空文件")
        reasoning_ratio = self._calc_reasoning_ratio(data)
        if reasoning_ratio > 0.85:
            raise QualityError(f"reasoning占比过高: {reasoning_ratio}")
```

## 完整链式推演：端到端流程

```
[本地文件修改]
      │
      ▼
┌─────────────────────────┐
│ 链1: ChangeDetector     │  事件驱动，O(1)响应
│ on_change(filepath)     │  计算单个文件hash
│ 不全量扫描              │
└──────────┬──────────────┘
           │ (filepath, new_hash, old_hash)
           ▼
┌─────────────────────────┐
│ 链2: ContentAddressed   │  查远端是否已有此file_hash
│ file_exists_remote()    │  存在→只更新引用，跳过上传
│ 内容寻址去重            │
└──────────┬──────────────┘
           │ 远端不存在此hash
           ▼
┌─────────────────────────┐
│ 链3: BlockSyncEngine    │  4KB分块，只传变化块
│ _diff_blocks()         │  块级增量，节省~90%带宽
│ upsert_file_with_lock() │  乐观锁版本控制
└──────────┬──────────────┘
           │ 版本冲突?
           ├────否────→ 链5验证
           ▼ 是
┌─────────────────────────┐
│ 链4: ConflictResolver   │  按model_type分治
│ B_turbo: LWW (300s)    │  B模型跳过reasoning检测
│ A_model: 块级合并(600s) │  A模型完整质量检测
└──────────┬──────────────┘
           │
           ▼
┌─────────────────────────┐
│ 链5: SyncValidator      │  验证远端写入完整
│ validate_sync()        │  配置变更立即验证
│ _quality_check()       │  质量规则按模型分治
└─────────────────────────┘
```

## 避坑检查清单

| 坑 | 本方案预防措施 |
|----|---------------|
| 配置修改后未生效 | `ConfigRegistry._validate()` 修改后立即验证；`SyncValidator` 同步后验证远端 |
| API调用超时 | B_turbo→300s，A_model→600s，超时后标记pending不直接失败 |
| 废稿检测误杀B模型 | `_quality_check()` 按model_type分治，B_turbo跳过reasoning占比检测 |
| 全量扫描O(N) | 链1事件驱动检测 + `scan_prefix`有限查询恢复 |
| 本地持久态 | hash缓存只在内存dict，恢复时从Supabase拉取 |
| 重复内容浪费带宽 | 链2内容寻址，相同hash的block只存一份 |

---

## 核心结论

> **Supabase记忆脑增量同步 = 事件驱动检测(链1) × 内容寻址去重(链2) × 块级diff传输(链3) × 乐观锁+模型分治冲突解决(链4) × 配置立即验证+质量规则分治(链5)**
>
> 整个链路满足三大硬约束：无记忆修改（内存态hash缓存）、无全量扫描（事件驱动+scan_prefix）、异构环境自适应（ConfigRegistry按model_type分治，timeout/质量规则/冲突策略各不相同）。
