# 任务类型: eng

## 结论先行

针对 V7.5 方舟效能引擎的「多线程 API 调用 → 串行后处理」场景，状态一致性问题的核心是：

> **不能让后处理线程在 API 结果尚未全部提交时启动，也不能让 API 线程在后处理启动后继续写入共享状态。**

采用：

- **双锚点**：`start_task` 与 `mark_terminal` 是仅有的两个状态写入锚点；
- **三源交叉校验**：`states 全终态`、`terminal_count == total`、`success_count + failure_count == total` 三者一致，才放行后处理；
- **分段重建**：大批量任务按批执行同一套锁协议，避免单次等待超时。

---

## 一、竞态条件推演

1. **写读竞态**  
   多线程并发写结果列表，后处理线程发现 `terminal_count == total` 后开始读。  
   如果先 `increment count` 再写结果，后处理会读到不完整数据；  
   如果先写结果再 `increment count`，必须用锁保证可见性。

2. **重复触发竞态**  
   多个 API 线程都发现自己是“最后一个完成”，可能同时尝试启动后处理。  
   必须用 `post_started` 保证后处理只执行一次。

3. **晚到写入竞态**  
   API 调用超时后线程不一定立即死亡，可能晚到写结果。  
   后处理启动后，这些晚到写入必须被丢弃。

4. **内存可见性竞态**  
   没有锁 / Condition 约束时，后处理线程可能看不到 API 线程写入的状态。

---

## 二、锁机制设计

### 状态机

任务状态：

```
PENDING → RUNNING → SUCCEEDED / FAILED / TIMEOUT
```

后处理状态：

```
IDLE → RUNNING → DONE / FAILED
```

### 锁对象

```python
cv = threading.Condition()
```

`Condition` 内部自带锁，同时提供 `wait / notify_all`，用于等待“全部任务终态”。

---

## 三、完整代码骨架

```python
import threading
import urllib.request
import json
from concurrent.futures import ThreadPoolExecutor

TERMINAL_STATES = {"SUCCEEDED", "FAILED", "TIMEOUT"}

class ArkEngine:

    def __init__(self, tasks, model_timeout_map, max_workers=8):
        self.tasks = tasks
        self.task_ids = list(tasks.keys())
        self.total = len(tasks)
        self.model_timeout_map = model_timeout_map
        self.max_workers = max_workers

        self.cv = threading.Condition()

        # 三源交叉的数据源
        self.states = {tid: "PENDING" for tid in self.task_ids}
        self.terminal_count = 0
        self.success_count = 0
        self.failure_count = 0

        self.success_results = []
        self.failure_reasons = []

        self.post_started = False
        self.aborted = False
        self.post_state = "IDLE"

    def _mark_terminal(self, task_id, state, result=None, error=None):
        """锚点2：唯一写入终态的地方。锁内提交数据，再更新计数，再 signal。"""
        with self.cv:
            if self.aborted or self.post_started:
                return False

            if self.states[task_id] in TERMINAL_STATES:
                return False

            # 先写数据，后更新计数
            if state == "SUCCEEDED":
                self.success_results.append(result)
                self.success_count += 1
            else:
                self.failure_reasons.append((task_id, repr(error)))
                self.failure_count += 1

            self.states[task_id] = state
            self.terminal_count += 1

            if self.terminal_count == self.total:
                self.cv.notify_all()

            return True

    def _call_api(self, task):
        """API 调用，不持有任何锁。"""
        model = task.get("model", "A")
        timeout = self.model_timeout_map.get(model, 600)

        # 避坑：统一 urllib 直连，禁用全局代理
        opener = urllib.request.build_opener(urllib.request.ProxyHandler({}))
        req = urllib.request.Request(
            task["url"],
            data=task.get("data"),
            headers=task.get("headers", {}),
            method=task.get("method", "POST")
        )

        try:
            with opener.open(req, timeout=timeout) as resp:
                data = json.loads(resp.read().decode("utf-8"))
        except TimeoutError as e:
            raise TimeoutError(f"API timeout after {timeout}s") from e

        # 避坑：Responses API 的 content 不能为空
        content = data.get("content")
        if not content or not content.strip():
            raise ValueError("Responses API content is empty")

        return data

    def run_task(self, task_id):
        """锚点1：启动任务时置 RUNNING，然后开始 API 调用。"""
        with self.cv:
            if self.aborted or self.post_started:
                return
            self.states[task_id] = "RUNNING"

        try:
            result = self._call_api(self.tasks[task_id])
            result = {
                "task_id": task_id,
                "data": result,
            }
            self._mark_terminal(task_id, "SUCCEEDED", result=result)
        except TimeoutError as e:
            self._mark_terminal(task_id, "TIMEOUT", error=e)
        except Exception as e:
            self._mark_terminal(task_id, "FAILED", error=e)
        finally:
            # 兜底：防止线程异常退出导致状态永远不闭合
            with self.cv:
                if (
                    self.states[task_id] not in TERMINAL_STATES
                    and not self.aborted
                    and not self.post_started
                ):
                    self._mark_terminal(
                        task_id,
                        "FAILED",
                        error=RuntimeError("worker lost")
                    )

    def wait_and_postprocess(self, postprocess, wait_timeout=None):
        """等待所有任务终态，三源交叉校验，然后串行后处理。"""
        with self.cv:
            while self.terminal_count < self.total and not self.aborted:
                if wait_timeout is None:
                    self.cv.wait()
                else:
                    if not self.cv.wait(wait_timeout):
                        self.aborted = True
                        return False

            if self.aborted:
                return False

            # 三源交叉校验
            if self.terminal_count != self.total:
                self.aborted = True
                return False

            if self.success_count + self.failure_count != self.total:
                self.aborted = True
                return False

            if any(self.states[tid] not in TERMINAL_STATES for tid in self.task_ids):
                self.aborted = True
                return False

            if self.post_started:
                return False

            self.post_started = True
            self.post_state = "RUNNING"

        # 锁外执行后处理，避免持锁做长任务
        try:
            # 如果后处理依赖顺序，按 task_id 排序
            ordered_results = sorted(
                self.success_results,
                key=lambda r: r["task_id"]
            )
            postprocess(ordered_results, self.failure_reasons)
        except Exception:
            with self.cv:
                self.post_state = "FAILED"
            raise

        with self.cv:
            self.post_state = "DONE"

        return True

    def run(self, postprocess, wait_timeout=None):
        """多线程 API 调用 + 串行后处理入口。"""
        if wait_timeout is None:
            wait_timeout = max(self.model_timeout_map.values()) + 60

        executor = ThreadPoolExecutor(max_workers=self.max_workers)
        try:
            futures = [
                executor.submit(self.run_task, tid)
                for tid in self.task_ids
            ]

            return self.wait_and_postprocess(postprocess, wait_timeout)
        finally:
            # 不等待仍卡住的 API 线程，避免二次超时
            executor.shutdown(wait=False, cancel_futures=True)
```

## 四、关键策略说明

### 1. 双锚点

- `run_task` 中进入 `RUNNING` 是锚点 1；
- `_mark_terminal` 写入终态是锚点 2。

所有共享状态修改都必须在这两个锚点内完成，且**不能持有锁调用外部 API**。

### 2. 三源交叉

后处理启动前必须同时满足：

```
terminal_count == total
success_count + failure_count == total
所有 task 状态都是终态
```

缺一个都不能放行。

### 3. 分段重建

如果任务量很大，例如一次几千个 API 调用，不要全部塞进同一个 `wait_and_postprocess`。

按批处理：

```python
def run_in_batches(all_tasks, batch_size, postprocess, model_timeout_map):
    task_ids = list(all_tasks.keys())

    for i in range(0, len(task_ids), batch_size):
        batch_ids = task_ids[i:i + batch_size]
        batch_tasks = {
            tid: all_tasks[tid]
            for tid in batch_ids
        }

        engine = ArkEngine(
            tasks=batch_tasks,
            model_timeout_map=model_timeout_map,
            max_workers=min(8, len(batch_tasks))
        )

        engine.run(postprocess)
```

每批独立锁协议，批次之间串行提交，避免单次锁等待被超时拖死。

### 4. 超时控制

```python
MODEL_TIMEOUT_MAP = {
    "B_turbo": 300,
    "A": 600,
}
```

- API 调用超时：B 模型 turbo 用 300 秒，A 模型用 600 秒；
- 等待全部任务终态超时：取模型超时最大值 + 60 秒；
- 修改超时配置后，必须立即用小流量任务验证新值生效。

## 五、验证清单

1. **重复后处理验证**  
   观察 `post_started` 是否只出现一次。

2. **状态闭合验证**  
   打印日志：

```python
terminal_count == total
success_count + failure_count == total
```

3. **晚到写入验证**  
   人为制造超时，确认后处理启动后，晚到结果被 `_mark_terminal` 丢弃。

4. **空 content 验证**  
   用 Responses API 返回空 content 的用例，确认任务进入 `FAILED`，不会污染成功结果。

5. **代理验证**  
   用 `urllib + ProxyHandler({})` 直连，避免 `ProxyError`。

这套方案能保证：

> **API 线程未全部提交前，后处理不会启动；后处理启动后，API 线程无法再写入共享状态。**
