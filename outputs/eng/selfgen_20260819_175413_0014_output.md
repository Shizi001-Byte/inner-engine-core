# 任务类型: eng

## 结论

多线程 API 调用本身可以并发；真正的竞态发生在**后处理写回共享状态**。

不要用全局锁，也不要在 API 调用期间持锁。正确做法是：

> **per-model 双层锁 + Redis Lua 原子更新 + 版本号/fencing + 幂等去重**

---

## 1. 锁层次设计

```
调用前：try_reserve（Lua 原子预占，不持分布式锁）
  ↓
API 调用：多线程并发，不持锁
  ↓
后处理：per-model 串行化
  - 本地线程锁
  - Redis 分布式锁
  - Lua 原子状态更新
```

不同 `model_id` 互相独立，可以并行；同一个 `model_id` 必须串行。

---

## 2. Key 设计

所有 key 必须使用官方完整 `model_id`，pro/turbo/light 不可混用。

```
state:model:{model_id}          # Hash：计数器、熔断、降级、version
config:model:{model_id}         # Hash：timeout、熔断阈值、降级策略
lock:model:{model_id}           # Redis 分布式锁
processed:{model_id}            # Set：已后处理的 attempt_id，幂等去重
inflight:{model_id}             # Set：已发出但未返回的 attempt_id
engine:lease                    # 引擎租约，用于主备切换/fencing
```

如果使用 Redis Cluster，建议给同一 model 的 key 加 hash tag：

```
{model_id}:state
{model_id}:config
{model_id}:lock
{model_id}:processed
{model_id}:inflight
```

---

## 3. 调用前：try_reserve 原子预占

API 调用前必须原子完成三件事：

1. 检查熔断是否打开；
2. 增加 `task_count` 或 `bonus_count`；
3. 写入 `inflight`。

不能在后处理里再对 `task_count` / `bonus_count` 加 1，否则会双计。

Lua 逻辑：

```lua
-- KEYS[1] = {model_id}:state
-- KEYS[2] = {model_id}:inflight
-- KEYS[3] = engine:lease
-- ARGV[1] = engine_id
-- ARGV[2] = lease_epoch
-- ARGV[3] = call_type  task|bonus
-- ARGV[4] = attempt_id
-- ARGV[5] = now
-- ARGV[6] = allow_open 0|1

if redis.call('GET', KEYS[3]) ~= ARGV[1] .. ':' .. ARGV[2] then
  return -1 -- NOT_LEADER
end

local open_until = tonumber(redis.call('HGET', KEYS[1], 'cb_open_until') or '0')
if open_until > tonumber(ARGV[5]) and ARGV[6] == '0' then
  return -2 -- CIRCUIT_OPEN
end

if ARGV[3] == 'task' then
  redis.call('HINCRBY', KEYS[1], 'task_count', 1)
  redis.call('HINCRBY', KEYS[1], 'count', 1)
elseif ARGV[3] == 'bonus' then
  redis.call('HINCRBY', KEYS[1], 'bonus_count', 1)
  redis.call('HINCRBY', KEYS[1], 'count', 1)
else
  return -3
end

redis.call('HINCRBY', KEYS[1], 'version', 1)
redis.call('HSET', KEYS[1], 'updated_at', ARGV[5])
redis.call('SADD', KEYS[2], ARGV[4])
redis.call('PEXPIRE', KEYS[2], 86400000)

return 1
```

这样 `count = task_count + bonus_count` 始终成立。

## 4. 后处理：per-model 串行化

后处理是真正需要锁的临界区。

### 4.1 本地线程锁

每个进程内维护 per-model 锁：

```python
_model_locks = {}
_model_locks_guard = threading.Lock()

def get_local_lock(model_id):
    with _model_locks_guard:
        if model_id not in _model_locks:
            _model_locks[model_id] = threading.Lock()
        return _model_locks[model_id]
```

### 4.2 Redis 分布式锁

用于两个引擎实例互斥：

```python
def acquire_post_lock(model_id, wait_timeout=3.0, ttl_ms=10000):
    key = f"lock:model:{model_id}"
    token = f"{engine_id}:{lease_epoch}:{uuid4().hex}"
    deadline = time.monotonic() + wait_timeout

    while time.monotonic() < deadline:
        if redis.set(key, token, nx=True, px=ttl_ms):
            return token
        time.sleep(0.02)

    raise PostLockTimeout(model_id)
```

释放锁必须用 Lua 比较 token，防止误删别人的锁：

```lua
if redis.call('get', KEYS[1]) == ARGV[1] then
  return redis.call('del', KEYS[1])
else
  return 0
end
```

### 4.3 后处理主流程

```python
def post_process(model_id, attempt_id, result):
    for _ in range(3):
        with get_local_lock(model_id):
            token = acquire_post_lock(model_id)
            try:
                state = redis.hgetall(state_key(model_id))
                expected_version = int(state.get('version', 0))

                rc = redis.eval(
                    POST_PROCESS_LUA,
                    5,
                    state_key(model_id),
                    processed_key(model_id),
                    inflight_key(model_id),
                    config_key(model_id),
                    engine_lease_key,
                    engine_id,
                    lease_epoch,
                    expected_version,
                    attempt_id,
                    int(time.time()),
                    result,  # success | failure
                )

                if rc == 1:
                    return
                if rc == -1:
                    raise NotLeader()
                if rc == -2:
                    continue  # STALE，重试
                if rc == -3:
                    return  # DUP，已处理过
            finally:
                release_post_lock(model_id, token)

    raise PostProcessRetryExceeded(model_id)
```

## 5. 后处理 Lua 脚本

后处理脚本必须：

- 检查引擎租约；
- 检查 version，防止锁过期后的旧写入；
- 幂等去重；
- 从 `config:model:{model_id}` 读取最新配置，而不是本地缓存；
- 更新熔断和降级状态。

```lua
-- KEYS[1] = {model_id}:state
-- KEYS[2] = {model_id}:processed
-- KEYS[3] = {model_id}:inflight
-- KEYS[4] = {model_id}:config
-- KEYS[5] = engine:lease
-- ARGV[1] = engine_id
-- ARGV[2] = lease_epoch
-- ARGV[3] = expected_version
-- ARGV[4] = attempt_id
-- ARGV[5] = now
-- ARGV[6] = result success|failure

if redis.call('GET', KEYS[5]) ~= ARGV[1] .. ':' .. ARGV[2] then
  return -1
end

local version = tonumber(redis.call('HGET', KEYS[1], 'version') or '0')
if version ~= tonumber(ARGV[3]) then
  return -2
end

if redis.call('SISMEMBER', KEYS[3], ARGV[4]) == 0 then
  if redis.call('SISMEMBER', KEYS[2], ARGV[4]) == 1 then
    return -3
  end
  return -4
end

if redis.call('SADD', KEYS[2], ARGV[4]) == 0 then
  return -3
end

redis.call('PEXPIRE', KEYS[2], 86400000)
redis.call('SREM', KEYS[3], ARGV[4])

-- 从 state 读取最新配置，避免“配置修改后未生效”
local max_fail = tonumber(redis.call('HGET', KEYS[4], 'max_fail') or '5')
local window_sec = tonumber(redis.call('HGET', KEYS[4], 'window_sec') or '60')
local cooldown_sec = tonumber(redis.call('HGET', KEYS[4], 'cooldown_sec') or '300')
local degrade_step = tonumber(redis.call('HGET', KEYS[4], 'degrade_step') or '1')
local max_degrade = tonumber(redis.call('HGET', KEYS[4], 'max_degrade') or '3')

local fc = tonumber(redis.call('HGET', KEYS[1], 'cb_fail_count') or '0')
local ws = tonumber(redis.call('HGET', KEYS[1], 'cb_window_start') or '0')
local dl = tonumber(redis.call('HGET', KEYS[1], 'degrade_level') or '0')

if ARGV[6] == 'success' then
  redis.call('HSET', KEYS[1], 'cb_fail_count', 0,
             'cb_window_start', 0,
             'cb_open_until', 0)
  if dl > 0 then
    redis.call('HSET', KEYS[1], 'degrade_level', math.max(0, dl - 1))
  end
else
  if tonumber(ARGV[5]) > ws + window_sec then
    ws = tonumber(ARGV[5])
    fc = 1
  else
    fc = fc + 1
  end

  redis.call('HSET', KEYS[1], 'cb_window_start', ws,
             'cb_fail_count', fc)

  if fc >= max_fail then
    redis.call('HSET', KEYS[1], 'cb_open_until', tonumber(ARGV[5]) + cooldown_sec)
    redis.call('HSET', KEYS[1], 'degrade_level', math.min(max_degrade, dl + degrade_step))
  end
end

redis.call('HINCRBY', KEYS[1], 'version', 1)
redis.call('HSET', KEYS[1], 'updated_at', ARGV[5])

return 1
```

## 6. 关键避坑

### 6.1 不要在 API 调用期间持锁

B 模型 turbo 超时 300 秒，A 模型 pro 超时 600 秒。  
锁 TTL 只用于后处理，建议 `10s` 左右，绝不能设成 API 超时时间。

### 6.2 锁过期后的旧写入

分布式锁 TTL 过期后，旧线程可能还在执行。  
用 `version` 做 fencing：旧线程的 `expected_version` 已经过期，Lua 返回 `-2`，必须重试或丢弃。

### 6.3 幂等

网络重试、超时后迟到响应、双引擎接管，都会导致同一个 `attempt_id` 被后处理多次。  
`processed:{model_id}` 集合必须在 Lua 里和状态更新同原子完成。

### 6.4 结果判定

B 模型 Responses API 可能出现 `content` 为空但 reasoning 消耗 tokens 的情况。  
不能把 HTTP 200 当成功，必须校验正式回复 `content` 非空；否则会污染熔断和计数。

### 6.5 调用阶段直连

API 调用统一用 urllib 直连，显式禁用代理：

```python
opener = urllib.request.build_opener(urllib.request.ProxyHandler({}))
resp = opener.open(req, timeout=timeout)
```

避免全局代理导致 ProxyError，进而误判为 API 失败。

### 6.6 引擎租约与 PID 文件

不要用 PID 文件判断实例存活。  
用 `engine:lease` + 心跳：

```python
def heartbeat_loop():
    while True:
        if redis.get("engine:lease") == f"{engine_id}:{lease_epoch}":
            redis.pexpire("engine:lease", 15000)
        time.sleep(5)
```

旧 leader 失去租约后，即使还活着，Lua 中的 `engine:lease` 检查也会拒绝它的写入。

## 7. 验证清单

- 两个线程同时后处理同一个 model，最终 `task_count` 不丢失。
- 两个失败同时到达，`cb_fail_count` 能正确累加并触发熔断。
- 同一个 `attempt_id` 重复后处理，只生效一次。
- 配置修改后，后处理能读取到最新 `config:model:{model_id}`。
- 旧 leader 失去租约后，状态写入被 `NOT_LEADER` 拒绝。
- `sync --check` 回读时满足：
  - `count == task_count + bonus_count`
  - `version` 正常递增
  - 配置已从 state 生效
