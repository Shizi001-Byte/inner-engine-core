# 任务类型: eng

# P2-1 单文件拆分方案：engine_zhuan1.py → 6 模块

## 0. 设计原则

1. **回读验证**：每次迁移、每次配置/状态写入后，必须读回比对，不一致立即回滚。
2. **单向依赖**：依赖方向只允许 `main → router → cultivation/idle_mode → api_client/state_manager`，禁止反向依赖。
3. **兼容优先**：拆分后保留 `engine_zhuan1.py` 作为兼容入口，对外行为不变。
4. **API 安全**：统一 urllib 直连、显式禁代理、显式 timeout、返回 content 必须非空。
5. **双轨运行**：`cultivation` 与 `idle_mode` 分开，避免生成逻辑与空闲逻辑互相污染；`router` 负责双轨调度，`state_manager` 负责状态同步，形成制度性双轨。

## 1. 模块职责与接口定义

### 1.1 `api_client.py`

职责：所有外部 API 调用的唯一出口。  
不持有配置，不读取业务状态；`api_key`、`base_url` 由上层注入。

```python
class ApiClient:
    # 超时预设：B模型turbo用300秒，A模型用600秒
    MODEL_TIMEOUT_MAP = {
        "B_turbo": 300,
        "A": 600,
    }

    def __init__(self, api_key: str, base_url: str = ""):
        ...

    def chat_completions(self, model: str, messages: list[dict]) -> str:
        """Chat Completions 调用，返回正式文本内容。"""

    def responses(self, model: str, messages: list[dict]) -> str:
        """Responses API 调用，返回前必须校验 content 非空。"""

    def raw_request(self, url: str, payload: dict, timeout: int) -> dict:
        """底层请求：
        - 使用 urllib.request，不引入 requests；
        - 显式使用 ProxyHandler({}) 禁用全局代理；
        - 必须传 timeout，不允许不设超时。
        """
```

关键约束：

- 禁止 `import requests`。
- 必须处理 `ProxyError`/`URLError`，并明确报错“检测到代理干扰”。
- `responses()` 内部必须调用 `extract_content()` 校验非空，空则抛 `ContentEmptyError`。
- 超时重试采用指数退避；4xx 不重试，5xx/超时可重试。

### 1.2 `state_manager.py`

职责：所有配置、状态、持久化、回读验证的唯一入口。  
不允许业务模块直接读写文件。

```python
class StateManager:
    def __init__(self, config_path: str, state_path: str):
        ...

    def load_config(self) -> dict:
        """读取配置，并做基础 schema 校验。"""

    def get_config(self, key: str, default=None):
        """获取配置，所有读取点必须走这里，禁止复制配置常量。"""

    def set_config(self, key: str, value) -> dict:
        """写入配置后立即读回，校验一致后才返回；不一致抛 ConfigSyncError。"""

    def reload_config(self) -> dict:
        """热更新配置，返回新配置并校验版本号。"""

    def load_state(self) -> dict:
        """读取状态文件。"""

    def save_state(self, state: dict) -> None:
        """原子写：临时文件 + os.replace + fsync。"""

    def update_state(self, new_state: dict) -> dict:
        """保存后读回，确认落盘成功。"""
```

关键约束：

- 所有“写入配置”必须走 `set_config`，写后立刻读回。
- 所有“状态变更”必须走 `update_state`，保存后验证。
- 状态文件写坏时自动加载最近一次备份。

### 1.3 `cultivation.py`

职责：养成/培育主逻辑，包括 prompt 构建、交互响应、成长状态更新。

```python
class CultivationEngine:
    def __init__(self, api_client: ApiClient, state_manager: StateManager):
        ...

    def process_event(self, user_input: str, state: dict) -> dict:
        """
        处理一次用户输入。
        返回：
        {
            "mode": "cultivation",
            "state": <更新后的state>,
            "reply": <回复文本>,
            "meta": {...}
        }
        """

    def build_prompt(self, state: dict, user_input: str) -> str:
        """根据当前状态构建 prompt。"""

    def update_state(self, state: dict, interaction: dict) -> dict:
        """根据交互结果更新亲密度/成长值/状态。"""

    def validate_state(self, state: dict) -> bool:
        """状态迁移合法性校验，防止脏状态写入。"""
```

关键约束：

- 不直接调用 API，必须通过 `api_client`。
- 不直接写文件，必须通过 `state_manager`。
- 只负责“养成/培育”事件；空闲事件不在这里处理。

### 1.4 `idle_mode.py`

职责：空闲模式判定、空闲消息生成、空闲状态更新。

```python
class IdleMode:
    def __init__(self, api_client: ApiClient, state_manager: StateManager):
        ...

    def is_idle(self, state: dict, now: float | None = None) -> bool:
        """判断是否进入空闲模式。"""

    def process_timer(self, state: dict) -> dict:
        """
        处理定时器触发的空闲事件。
        返回：
        {
            "mode": "idle_mode",
            "state": <更新后的state>,
            "reply": <空闲消息>,
            "meta": {...}
        }
        """

    def build_idle_prompt(self, state: dict) -> str:
        """构建空闲触发 prompt。"""

    def update_after_idle(self, state: dict, response: str) -> dict:
        """更新空闲后的状态。"""
```

关键约束：

- 与 `cultivation` 互不调用，只通过 `router` 调度。
- 同样只通过 `api_client` 和 `state_manager` 工作。

### 1.5 `router.py`

职责：事件路由和分发，是业务模块的唯一调度器。

```python
class Router:
    def __init__(
        self,
        cultivation: CultivationEngine,
        idle_mode: IdleMode,
        state_manager: StateManager,
    ):
        ...

    def route(self, event: dict, state: dict) -> str:
        """
        返回：
        - "cultivation"：用户输入事件
        - "idle_mode"：空闲定时事件
        - "system"：系统管理事件
        """

    def dispatch(self, event: dict) -> dict:
        """
        统一入口：
        1. state = state_manager.load_state()
        2. mode = route(event, state)
        3. 调用对应模块处理
        4. state_manager.update_state(result["state"])
        5. 返回结果
        """
```

关键约束：

- `router` 不承载业务逻辑，只做“判断 + 转发 + 统一落盘”。
- 禁止 `router` 反向 import `main`。

```python
def main() -> None:

def create_app(config_path: str) -> Router:
```

关键约束：

```python
    main()
```

## 2. 依赖关系

```
engine_zhuan1.py（兼容入口）
    └── main.py
          └── router.py
                ├── cultivation.py
                │     ├── api_client.py
                │     └── state_manager.py
                ├── idle_mode.py
                │     ├── api_client.py
                │     └── state_manager.py
                └── state_manager.py
```

依赖规则：

- `api_client.py` 与 `state_manager.py` 是叶子模块，不依赖任何上层业务模块。
- `cultivation.py` 与 `idle_mode.py` 可以依赖 `api_client` 和 `state_manager`，但不能互相依赖。
- `router.py` 只能依赖 `cultivation`、`idle_mode`、`state_manager`，不能依赖 `main`。
- `main.py` 只依赖 `router` 和 `state_manager`。
- 所有依赖通过构造函数注入，避免模块内直接 `import` 单例。

## 3. 迁移步骤

### Step 0：建立回归基线

- 在 git 新建分支 `refactor/p2-1-split`。
- 锁定 `engine_zhuan1.py` 当前版本。
- 收集 3~5 个典型场景的输入、输出、状态文件快照、日志。
- 建立“回读验证清单”：每次迁移后必须跑一遍基线，比对状态文件和回复。

### Step 1：抽取 `state_manager.py`

- 将配置读取、状态读取、文件写入、原子写、回读校验相关代码迁入。
- 原文件中所有直接读写文件的地方替换为 `state_manager` 调用。
- 验证：
  - 修改配置后，立即通过 `get_config` 读回，必须读到新值。
  - 状态文件 hash 与迁移前一致。
  - 回归测试通过。

### Step 2：抽取 `api_client.py`

- 将原文件所有网络调用迁入。
- 统一改用 urllib 直连，显式 `ProxyHandler({})` 禁用代理。
- 按模型配置默认 timeout：B 模型 turbo 用 300 秒，A 模型用 600 秒。
- 新增 `extract_content()`，对 Responses API 返回做 content 非空校验。
- 验证：
  - 在沙箱环境跑一次真实 API 调用，确认无 ProxyError。
  - 对 B 模型 turbo 用 Responses API 单测，确认 content 非空。
  - 若 content 为空，必须修复或降级，不能接入主流程。

### Step 3：抽取 `cultivation.py`

- 将养成逻辑、prompt 构建、交互状态更新迁入。
- 原网络调用替换为 `api_client`。

- 验证：

### Step 4：抽取 `idle_mode.py`

- 将空闲判定、空闲消息、空闲状态更新迁入。
- 验证：

  - 空闲触发阈值与旧逻辑完全一致。

### Step 5：抽取 `router.py`

- 将原事件分发 if/switch 逻辑迁入。
- 确认所有事件类型都映射到正确模块。
- 验证：
  - 所有历史事件类型均能路由到正确模块。

### Step 6：创建 `main.py`

- 将入口初始化、事件循环、信号处理迁入。
- 将 `engine_zhuan1.py` 改为兼容 shim。
- 验证：
  - `python engine_zhuan1.py` 行为不变。
  - `python main.py` 行为一致。

### Step 7：全量回读验证

- 跑全部回归测试。
- 比对状态文件、日志、API 调用次数与顺序。
- 检查 `engine_zhuan1.py` 中不再存在业务逻辑和 API 调用。

## 4. 风险评估与规避

| 风险 | 概率 | 影响 | 规避措施 |
|---|---|---|---|
| 循环依赖 | 中 | 高 | 依赖方向强制单向；`api_client`/`state_manager` 不 import 上层；使用 `TYPE_CHECKING` 做类型注解。 |
| 全局代理导致 ProxyError | 中 | 高 | `api_client` 统一 urllib 直连，显式 `ProxyHandler({})`；不引入 requests；如临时用 requests 必须 `proxies=None`。 |
| API 超时 | 高 | 中 | 所有调用必须传 timeout；B 模型 turbo 默认 300 秒，A 模型默认 600 秒；超时重试加指数退避，且不超任务 deadline。 |
| Responses API content 为空 | 中 | 高 | 在 `api_client.responses()` 内做 `extract_content` 非空校验；为空抛 `ContentEmptyError`，上层重试或降级；新 API 格式先单测再接入。 |
| 配置修改后未生效 | 中 | 高 | `StateManager.set_config()` 写后立即读回；主流程每次从 `get_config` 读取，禁止缓存配置副本。 |
| 状态文件损坏 | 低 | 高 | 原子写：临时文件 + `os.replace` + `fsync`；保存前校验 state schema；启动时自动备份。 |
| 行为回归 | 高 | 高 | 增量迁移，每步跑基线回读验证；保留 `engine_zhuan1.py` 兼容入口；不一致立即回滚。 |
| 模块拆分后职责不清 | 中 | 中 | 先冻结接口签名，再迁移代码；`cultivation` 与 `idle_mode` 严格分离，不互相调用。 |

## 5. 验收标准

1. `engine_zhuan1.py` 不再包含网络调用、文件读写、业务逻辑。
2. `main.py` 启动后与旧文件行为一致。
3. 所有 API 调用只经过 `api_client.py`，且无 ProxyError、无无 timeout 调用、无 content 为空问题。
4. 所有配置/状态写入后都经过读回验证。
5. 模块依赖无环，`import` 顺序稳定。
6. 历史回归测试全部通过。
