# 任务类型: eng

# 任务池动态扩充机制设计（自进化闭环标准决策模块）

## 一、总体闭环

```text
任务执行记录
   ↓
重复率检测（Trigger）
   ↓ 超过阈值且冷却到期
候选模板生成（Executor）
   ↓
独立质量校验（按模型分流）
   ↓
注入任务池（Injector）
   ↓
Canary 验证（Verifier）
   ↓
效果反馈 + 认知池回写
   ↓
回到重复率检测，形成闭环
```

整个闭环必须作为引擎底层的标准决策模块运行，不能是外挂脚本；所有自进化动作都占用已有的 3 路并发 slot，**不新增并发路数**。

---

## 二、三大核心子模块

### 1. 触发器：什么时候检测、什么时候生成

触发器负责回答“要不要做自进化”。

```text
检测频率：每完成 10 个任务，或每轮任务队列清空时，触发一次重复率检测
滑动窗口：最近 W = 100 个已完成任务
重复率定义：窗口内，任务模板语义相似度 > 0.85 的任务占比
重复率阈值：R = 0.25
冷却时间：每次生成后至少再执行 C = 10 个任务，或冷却 30 分钟，才能再次触发
```

触发条件：

```text
重复率 > 0.25
且 当前不在冷却期
且 3 路并发中有可插空的维护 slot
```

不满足条件时直接返回，不做任何额外计算，避免算力浪费和引擎空转。

---

### 2. 执行器：在 3 路并发中如何插空，如何控制预算

执行器负责“生成新模板并注入任务池”。

#### 插空策略

自进化任务也是任务，必须走同一个调度队列，占用 3 路并发中的一路。

采用两种插空方式：

- **被动插空**  
  某一路正常任务完成后，下一批正常任务尚未就绪时，立即把“模板生成/校验任务”填入该 slot，避免 slot 空转。

- **主动配额**  
  为避免自进化被饿死，每完成 10 个正常任务，强制允许一个维护任务占用下一个空闲 slot。  
  即使此时有正常任务排队，也最多只让维护任务执行一个子步骤，执行完立刻释放 slot。

#### 生成流程

1. 从重复率最高的任务簇中提取代表性模板。
2. 从认知池拉取最近 30 分钟内新增的认知。
3. 结合“八步拆解法”和已有认知锚定，生成新任务模板。
4. 生成时明确要求：保持任务目标不变，改变场景、数据分布、约束条件、输出格式中的一个或多个维度。
5. 调用模型时设置超时：
   - B 模型 turbo：300 秒
   - A 模型：600 秒
6. 超时立即放弃，并释放 slot，最多重试 1 次。

#### 预算控制

每一轮自进化闭环最多消耗：

```text
生成候选模板：≤ 3 个
质量校验：≤ 3 个
Canary 验证：≤ 1 个
LLM 调用次数：≤ 4 次
单轮总时长：≤ 900 秒
```

超过预算后，本轮自进化立即终止，等待下一轮冷却后重新触发。

---

### 3. 验证器/反馈器：如何确保真的生效

验证器负责回答“注入后有没有用，会不会引入废稿”。

#### Canary 验证

每个新模板注入任务池后，必须先用该模板执行一个最小化 Canary 任务：

- 检查是否在超时时间内正常完成。
- 检查输出是否符合模板定义的 schema。
- 检查输出与现有任务输出是否有足够区分度。
- 如果模板是 B 模型生成的，**跳过 reasoning 占比检测**，因为 B 模型 reasoning 占比 70%–82% 是正常特性。

Canary 通过后，模板状态变为 `active`，正式参与任务调度。  
Canary 失败则自动回滚，从任务池移除，并把失败原因写入认知池。

#### 效果验证

注入新模板后，再观察后续 50 个任务的重复率：

- 如果重复率降到阈值以下，说明自进化有效。
- 如果重复率没有下降，说明生成策略有问题，触发策略参数调整，并写入认知池。

#### 认知池刷新

- 每完成 10 个任务，强制刷新认知缓存。
- 新认知必须在 30 分钟内参与下一次模板生成。
- 不能只往认知池写入，而不在生成时读取。

## 三、关键参数表

| 参数 | 默认值 | 说明 |
|---|---:|---|
| `W` | 100 | 重复率检测滑动窗口 |
| `R` | 0.25 | 重复率触发阈值 |
| `C` | 10 | 触发冷却任务数 |
| `M` | 10 | 主动配额间隔任务数 |
| `gen_max` | 3 | 每轮最多生成候选模板数 |
| `verify_max` | 3 | 每轮最多校验模板数 |
| `canary_max` | 1 | 每轮最多 Canary 验证数 |
| `B_timeout` | 300s | B 模型 turbo 超时 |
| `A_timeout` | 600s | A 模型超时 |

所有参数必须走统一配置中心，不能硬编码。

## 四、伪代码

```text
on_task_completed(task):
    recent_tasks.append(task)

    if recent_tasks.size() < W:
        return

    if now < last_trigger_time + cooldown:
        return

    rate = compute_repetition_rate(recent_tasks)

    if rate <= R:
        return

    if not scheduler.has_maintenance_slot():
        return

    result = execute_evolution_cycle(rate)

    verify_and_feedback(result)
```

```text
execute_evolution_cycle(rate):
    slot = scheduler.acquire_slot(priority=MAINTENANCE)

    if slot is None:
        return

    try:
        cluster = find_most_repeated_cluster(recent_tasks)
        cognition = cognitive_pool.get_recent(30min)
        candidates = generate_templates(
            cluster=cluster,
            cognition=cognition,
            max_count=gen_max,
            timeout=select_timeout_by_model()
        )

        validated = []
        for tpl in candidates:
            if is_valid_template(tpl, model=tpl.generator_model):
                validated.append(tpl)

        for tpl in validated:
            task_pool.inject(tpl, status=CANARY)
            scheduler.submit(canary_task(tpl), priority=NORMAL)

        cognitive_pool.write(
            action="self_evolution",
            candidates=validated,
            rate=rate,
            timestamp=now()
        )

    finally:
        scheduler.release_slot(slot)
```

## 五、避坑落地清单

| 历史坑 | 本设计中的对策 |
|---|---|
| 配置修改后未生效 | 新增配置必须同步修改“状态写入、执行读取、生效验证”三个点；修改后立即执行 Canary 验证 |
| API 调用超时 | B 模型 turbo 用 300 秒超时，A 模型用 600 秒超时；超时释放 slot，最多重试 1 次 |
| 自动调参全链路失效 | 新参数统一从配置中心读取；模板注入后必须通过 Canary 验证才置为 active |
| 废稿检测误杀 B 模型 | 质量校验按生成模型分流，B 模型跳过 reasoning 占比检测 |
| 认知池只进不出 | 每 10 任务刷新认知缓存；新认知 30 分钟内参与注入 |
| 引擎空转 | 自进化任务只在重复率超阈值且有 slot 时执行；无 slot 则挂起，不空转轮询 |

## 六、最终效果

这套机制固化后，引擎可以在严格不超过 3 路并发的前提下，自动完成：

```text
检测重复率 → 生成新模板 → 注入任务池 → Canary 验证 → 效果反馈 → 认知池更新
```

形成可持续的自进化闭环，同时避免算力浪费、配置失效、废稿误杀、认知池静态化等历史问题。
