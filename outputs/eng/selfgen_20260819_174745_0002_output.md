# 任务类型: eng

## 结论先行

多线程 API 调用的真正并发边界不在“调用 API”本身，而在“API 返回后对共享状态的写入”。  
所以正确锁机制是：

> **API 调用全程无锁；状态预留用短锁；结果通过线程安全队列交给唯一后处理线程；后处理用版本号 + 状态机防止乱序、重复、脏写。**

下面给出针对 V7.5 方舟效能引擎的完整方案。

---

## 一、竞态条件建模

假设当前流程：

```
线程A ──> 调用API ──┐
线程B ──> 调用API ──┤──> 串行后处理 ──> 更新共享状态
线程C ──> 调用API ──┘
```

会出现的竞态：

1. **读改写竞态**  
   后处理线程读共享状态 → 计算 → 写回；如果中间有其他线程插入修改，会丢失更新。

2. **响应乱序**  
   线程A 先调用，线程B 后调用，但 A 的响应晚到；如果后处理直接按到达顺序写，可能用旧数据覆盖新数据。

3. **重复响应 / 重试响应**  
   同一个请求超时重试，旧响应和新响应都到达，后处理被执行两次。

4. **状态机非法跃迁**  
   后处理还没完成，另一个线程已经把任务标记为完成，导致重复处理。

5. **API 调用前快照过期**  
   调用 API 前读取了某个聚合状态，API 返回后该状态已经被其他任务修改；此时直接应用结果会基于过期快照写脏数据。

---

## 二、总体锁机制设计

核心组件：

| 锁 / 原语 | 保护对象 | 获取时机 | 释放时机 |
|---|---|---|---|
| `store.lock` | 任务表、聚合状态、版本号 | 状态查询 / 状态变更前 | 变更后立即释放 |
| `post_queue` | 待后处理消息队列 | `get / put` | queue 内部处理 |
| 单消费者线程 | 后处理临界区 | 线程启动 | 线程退出 |
| `task.seq` | 单任务请求代数 | 每次发起 API 前 | 任务终结 |
| `aggregate_version` | 聚合状态乐观锁 | 后处理 apply 前校验 | apply 后递增 |

关键原则：

1. **网络调用绝不持锁**  
   API 可能耗时 300 秒 / 600 秒，持锁会导致整个引擎阻塞。

2. **状态变更必须短锁**  
   只在创建任务、响应入队、后处理 apply 时加锁，临界区只做内存操作。

3. **后处理严格单消费者**  
   用 `queue.Queue` + 唯一后处理线程，保证“串行后处理”这个语义本身不被破坏。

4. **版本号防乱序**  
   每个任务维护 `seq`，每次重试递增；后处理消息携带 `seq`，旧响应直接丢弃。

5. **聚合状态用乐观锁**  
   后处理 apply 前检查 `base_agg_version == aggregate_version`，不一致则拒绝或重算。

---

## 三、状态机定义

```
PENDING ──> CALLING      # submit 时创建任务
CALLING ──> COMPLETED    # API 响应到达且 seq 匹配
CALLING ──> FAILED       # API 异常 / 超时 / 空 content
COMPLETED ──> PROCESSING # 后处理线程取到消息
PROCESSING ──> APPLIED   # delta 应用成功并回读验证
PROCESSING ──> FAILED    # 后处理异常 / 聚合版本过期
```

非法跃迁一律拒绝。

## 四、核心代码框架

```python
import queue
import threading
from concurrent.futures import ThreadPoolExecutor
from dataclasses import dataclass
from enum import Enum
from typing import Any, Callable, Optional


class TaskStatus(Enum):
    PENDING = "PENDING"
    CALLING = "CALLING"
    COMPLETED = "COMPLETED"
    PROCESSING = "PROCESSING"
    APPLIED = "APPLIED"
    FAILED = "FAILED"


@dataclass
class Task:
    task_id: str
    payload: dict
    status: TaskStatus = TaskStatus.PENDING
    seq: int = 0                # 请求代数，每次重试 +1
    version: int = 0            # 任务状态版本
    base_agg_version: int = 0   # 发起 API 调用时的聚合状态版本
    response: Any = None
    error: Optional[str] = None


class StateStore:
    def __init__(self):
        self.lock = threading.RLock()
        self.tasks: dict[str, Task] = {}
        self.aggregate: dict[str, int] = {}
        self.aggregate_version = 0


class ArkEngine:
    def __init__(
        self,
        api_call_fn: Callable,
        post_process_fn: Callable,
        max_workers: int = 8,
    ):
        self.store = StateStore()
        self.api_call_fn = api_call_fn
        self.post_process_fn = post_process_fn

        # API 调用线程池
        self.executor = ThreadPoolExecutor(max_workers=max_workers)

        # 后处理队列：线程安全，且由唯一消费者消费
        self.post_queue: queue.Queue = queue.Queue()

        # 唯一后处理线程
        self._stop = threading.Event()
        self._post_thread = threading.Thread(
            target=self._post_worker,
            name="ark-post-worker",
            daemon=True,
        )
        self._post_thread.start()

    def submit(self, task_id: str, payload: dict) -> None:
        with self.store.lock:
            if task_id in self.store.tasks:
                raise ValueError(f"task already exists: {task_id}")

            task = Task(
                task_id=task_id,
                payload=payload,
                status=TaskStatus.CALLING,
                seq=1,
                version=1,
                base_agg_version=self.store.aggregate_version,
            )
            self.store.tasks[task_id] = task
            seq = task.seq

        # 网络调用在锁外执行
        self.executor.submit(self._api_call, task_id, seq)

    def _api_call(self, task_id: str, seq: int) -> None:
        with self.store.lock:
            task = self.store.tasks.get(task_id)
            if task is None or task.seq != seq:
                return
            payload = task.payload

            # 历史坑：B 模型 turbo 用 300 秒，A 模型用 600 秒
            timeout = 600 if payload.get("model") == "A" else 300

        try:
            # 历史坑：统一用 urllib 直连，禁止 requests 默认代理
            # 如果必须用 requests，显式 proxies=None
            response = self.api_call_fn(payload, timeout=timeout)

            # 历史坑：Responses API 可能 content 为空
            if not getattr(response, "content", None):
                raise RuntimeError("API response content is empty")

        except Exception as e:
            self._enqueue_failure(task_id, seq, f"api_error: {e}")
            return

        with self.store.lock:
            task = self.store.tasks.get(task_id)
            if task is None or task.seq != seq:
                # 迟到的旧响应，直接丢弃
                return

            task.response = response
            task.status = TaskStatus.COMPLETED
            task.version += 1

            # 入队也持锁，但 Queue 是无界队列，put_nowait 不会阻塞
            self.post_queue.put_nowait((task_id, seq, task.version))

    def _enqueue_failure(self, task_id: str, seq: int, error: str) -> None:
        with self.store.lock:
            task = self.store.tasks.get(task_id)
            if task is None or task.seq != seq:
                return

            task.error = error
            task.status = TaskStatus.FAILED
            task.version += 1

            self.post_queue.put_nowait((task_id, seq, task.version))

    def _post_worker(self) -> None:
        while True:
            try:
                item = self.post_queue.get(timeout=0.2)
            except queue.Empty:
                if self._stop.is_set():
                    return
                continue

            if item is None:
                return

            task_id, seq, version = item

            with self.store.lock:
                task = self.store.tasks.get(task_id)
                if task is None or task.seq != seq or task.version != version:
                    continue  # 过期消息

                if task.status not in (TaskStatus.COMPLETED, TaskStatus.FAILED):
                    continue

                # 乐观锁：如果聚合状态已经变了，说明这次后处理基于过期快照
                if task.base_agg_version != self.store.aggregate_version:
                    task.status = TaskStatus.FAILED
                    task.error = "stale aggregate version"
                    continue

                task.status = TaskStatus.PROCESSING
                task.version += 1
                expected_version = task.version

                response = task.response
                error = task.error

            # 后处理在锁外执行，避免阻塞 API 提交 / 响应
            try:
                # post_process_fn 必须返回 delta，而不是直接改共享状态
                # 例如：{"usage_total": 123}
                delta = self.post_process_fn(
                    task_id,
                    task.payload,
                    response,
                    error,
                )
            except Exception as e:
                with self.store.lock:
                    task = self.store.tasks.get(task_id)
                    if task is not None and task.version == expected_version:
                        task.status = TaskStatus.FAILED
                        task.error = f"post_process_error: {e}"
                        task.version += 1
                continue

            with self.store.lock:
                task = self.store.tasks.get(task_id)
                if task is None or task.version != expected_version:
                    continue

                # 应用 delta，必须原子完成
                for k, v in delta.items():
                    self.store.aggregate[k] = self.store.aggregate.get(k, 0) + v

                self.store.aggregate_version += 1

                # 回读验证：每次同步后必须验证生效
                verify_ok = all(
                    self.store.aggregate.get(k) == v
                    for k, v in delta.items()
                )

                if not verify_ok:
                    task.status = TaskStatus.FAILED
                    task.error = "post_apply verify failed"
                    task.version += 1
                    continue

                task.status = TaskStatus.APPLIED
                task.version += 1
```

## 五、锁获取顺序与死锁规避

1. **锁顺序固定**  
   所有共享状态访问必须先获取 `store.lock`，再操作队列。  
   队列内部锁不会反向获取 `store.lock`，因此不会形成循环等待。

2. **不在锁内做 I/O**  
   API 调用、后处理函数、外部写入都不持锁。

3. **用 `RLock` 防重入死锁**  
   同一个线程可能在状态校验中再次进入临界区，`RLock` 更安全。

4. **队列用无界队列或 `put_nowait`**  
   避免持锁期间因队列满而阻塞。

---

## 六、重试与乱序处理

- 每次重试必须递增 `task.seq`。
- API 响应到达时，只有 `task.seq == response.seq` 才接受。
- 后处理消息携带 `(task_id, seq, version)`，三者全部匹配才处理。
- 超时任务：
  - B 模型 turbo：300 秒
  - A 模型：600 秒

超时后建议进入重试流程，而不是直接标记失败；但重试前必须递增 `seq`，使旧响应失效。

---

## 七、多实例扩展

当前方案是单实例内的完整锁机制。V7.5 高可用要求至少 2 个引擎实例，因此“串行后处理”必须是全局串行：

| 单实例 | 多实例 |
|---|---|
| `threading.RLock` | Redis / etcd / DB 行锁 |
| `queue.Queue` | Redis Stream / Kafka / DB outbox |
| 单后处理线程 | 每个 task_id 分区只有一个消费者 |
| `aggregate_version` | 用 DB `SELECT FOR UPDATE` 或 CAS 实现 |
| 任务表内存字典 | 任务表放 DB / Redis，带版本字段 |

多实例时必须使用 **fencing token**：

- 每次获取分布式锁时获得一个单调递增 token。
- 后处理 apply 前检查 token 是否仍然有效。
- 防止旧 leader 的锁过期后继续写状态。

引擎启动时避免 PID 文件竞态：

- 启动前用 `kill -0` 检查旧 PID。
- 或用 `flock` 文件锁，而不是依赖 PID 文件。

## 八、验证清单

1. **并发压力测试**  
   100 个任务并发 submit，API 响应乱序返回，最终 `APPLIED` 数量必须等于成功任务数。

2. **故障注入**  
   - API 超时
   - API 返回空 content
   - 重复响应
   - 迟到响应
   - 后处理抛异常

3. **配置修改验证**  
   锁超时、后处理线程数、队列容量等配置修改后，必须执行：

   ```bash
   sync --check
   ```

   并立即验证行为变化。

4. **新 API 格式验证**  
   Responses API 格式必须先单测 `content` 非空，再接入主流程，否则 reasoning 会耗尽 token 导致正式回复为空。

---

## 九、最终提醒

这套锁机制的核心不是“加很多锁”，而是：

> **把并发 API 调用与串行状态变更彻底解耦，用版本号和状态机保证一致性。**

网络调用越慢，越不能持锁；状态变更越关键，越要短锁 + 乐观锁 + 回读验证。
