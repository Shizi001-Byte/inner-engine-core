# 任务池动态扩充机制：负熵自进化闭环

基于已有认知锚定：**重复率升高 = 负熵输入不足的外部表现**，会导致引擎功能熵升高。因此设计以下闭环：

> 任务完成 → 重复率检测 → 超阈值触发 → 认知/坑库刷新 → 候选模板生成 → 模型差异化校验 → 灰度注入 → Canary 验证 → 效果确认 → 知识沉淀 → 继续检测

---

## 1. 重复率检测器

用滑动窗口检测任务池执行结果中的“语义重复”，而不是只查模板 ID。

### 定义

- 滑动窗口：最近 `W = 50` 个已执行任务（可配置）
- 任务指纹：对任务目标、输入约束、输出要求做归一化后生成 embedding / SimHash
- 相似度：两两计算余弦相似度
- 重复判定：相似度 > `α = 0.90` 记为一次重复

### 重复率公式

\[
R = \frac{2}{N(N-1)} \sum_{i<j} I(sim(T_i, T_j) > \alpha)
\]

当 `R > β`（默认 `β = 0.30`）时触发自动扩充。

**注意：** Canary 验证任务不计入重复率统计，避免自我触发。

---

## 2. 认知池 / 坑库联动

避免“认知池只进不出”和“认知反哺不生效”。

### 刷新策略

- 每完成 10 个任务，或每轮调度结束，强制刷新认知缓存
- 只拉取 `created_at >= now - 30min` 的新认知
- 缓存有容量上限，新认知必须参与生成，旧认知若长期未命中则降低优先级

### 注入要求

生成新任务模板时，必须至少引用一条“最近 30 分钟内的新认知”作为 `cognitive_anchor`。没有认知锚点的候选模板直接拒绝。

同时从坑库中读取历史失败经验，生成“避坑回归类任务”，例如：

- “验证配置项修改后是否真的改变了执行行为”
- “验证 B 模型高 reasoning 占比是否被误判为废稿”

---

## 3. 候选模板生成器

超阈值后，从高重复任务簇中采样种子模板，并结合新认知和坑库生成候选模板。

### 变异算子

1. **参数变异**：改变输入规模、噪声强度、资源限制
2. **场景迁移**：保留推理结构，迁移到新业务场景
3. **目标反转**：原来是“延迟约束下最大化准确率”，反转为“准确率约束下最小化延迟”
4. **难度阶梯**：在重复任务基础上增加或降低复杂度
5. **认知探针**：用最新认知生成验证任务
6. **失败反推**：从坑库历史失败中生成回归测试任务

每次生成 `M = 3~5` 个候选，不能只生成一个，避免新模板质量不足。

---

## 4. 质量校验器：模型差异化规则

所有候选模板必须通过校验后才能注入。

### 通用校验

- 结构完整：有目标、输入 schema、输出 schema、成功标准
- 可执行性：当前引擎能够运行
- 价值对齐：不违反安全/合规约束
- 新颖性：与现有 active 模板最大相似度 ≤ `0.85`

### 模型差异化校验

| 模型 | 超时 | 校验规则 |
|---|---|---|
| B / turbo | 300s | **跳过 reasoning 占比检测**；只检查指令清晰、输出格式、可完成性 |
| A 模型 | 600s | 保留 reasoning 路径完整性校验，但不以简单占比作为废稿标准 |

这是为了避免历史坑：**B 模型 reasoning 占比 70-82% 是正常特性，不能被判定为废稿。**

---

## 5. 注入与调度

候选模板先进入 `candidate` 状态，不直接全量上线。

### 灰度注入流程

1. 候选模板写入任务池，状态为 `candidate`
2. 立即执行 3~5 次 Canary 任务
3. Canary 通过 → 状态提升为 `active`
4. Canary 失败 → 状态置为 `failed`，记录到坑库

新模板默认权重低，防止淹没在线任务。若后续需要调整并发、权重、冷却，必须走配置中心，并执行“三同步”。

---

## 6. 三同步：配置生效全链路

任何新增可配置参数，包括重复率阈值、生成数量、冷却轮数、模型超时、新模板权重，都必须同步修改三个点：

| 环节 | 要求 |
|---|---|
| 状态写入 | 配置中心写入，并更新运行时版本号 |
| 执行读取 | 检测器、生成器、调度器每周期读取最新版本，禁止使用超过一个周期的本地缓存 |
| 生效验证 | 用探针任务验证行为确实变化，例如修改阈值后重放历史窗口确认触发点变化 |

**三缺一 = 配置未生效。**

若自动扩充过程中需要调整调度权重或冷却时间，也必须用 Canary 验证派单比例确实变化，否则告警并回滚。

---

## 7. 效果验证与回滚

注入新模板后，不是结束，而是下一个闭环的开始。

### 验证指标

- 重复率 `R` 是否在后续 `20` 个任务内下降，例如相对下降 ≥ 20%
- 任务成功率是否稳定，下降不超过 `2pp`
- 平均耗时是否在预算内
- 新模板是否真的被调度执行，而不是只存在于任务池中

### 失败处理

- 如果重复率未下降，自动回滚新模板，并记录坑库
- 如果连续两轮生成的新模板均未通过 Canary，则进入“保守模式”：停止自动注入，输出告警，等待人工介入

## 8. 伪代码

```python
def on_task_completed(task):
    if task.tag == "canary":
        return

    window.push(fingerprint(task))
    R = pairwise_repeat_rate(window)

    if R > cfg.auto_expand.threshold and not cooling():
        expand_task_pool()


def expand_task_pool():
    refresh_cognitive_cache(ttl=30min, force=True)

    seeds = sample_high_repeat_templates()
    cognitions = get_recent_cognitions(age <= 30min)
    pitfalls = get_recent_pitfalls()

    candidates = []
    for op in mutation_ops:
        candidates.append(op.generate(seeds, cognitions, pitfalls))

    validated = [c for c in candidates if validate(c)]

    for c in validated[:cfg.max_new_templates]:
        c.status = "candidate"
        task_pool.add(c)

        if run_canary(c):
            c.status = "active"
            c.effective_at = now()
        else:
            c.status = "failed"
            pitfall_library.log(c, reason="canary_failed")

    wait(cfg.effect_window_tasks)

    if repeat_rate_dropped() and success_rate_stable():
        knowledge_base.record(promoted_templates)
    else:
        rollback(promoted_templates)
        pitfall_library.log(reason="effect_verification_failed")


def validate(c):
    if not schema_valid(c):
        return False
    if not value_alignment(c):
        return False
    if max_similarity(c, active_templates) > 0.85:
        return False

    if c.model_hint == "B":
        # B/turbo：跳过 reasoning 占比检测，允许 70-82% reasoning
        if c.timeout > 300:
            return False
    elif c.model_hint == "A":
        if c.timeout > 600:
            return False
        if not has_valid_reasoning_path(c):
            return False

    return True
```

## 9. 避坑映射

| 历史坑 | 本机制的对策 |
|---|---|
| 配置修改后未生效 | 三同步 + 探针验证 + Canary 验证 |
| API 超时 | B/turbo 300s，A 模型 600s，超时丢弃不阻塞主链路 |
| B 模型被误判废稿 | B 模型跳过 reasoning 占比检测 |
| 认知池只进不出 | 每 10 任务/每轮刷新；30 分钟内新认知必须参与生成；模板必须带 cognitive_anchor |
| 自动调参全链路失效 | 并发/权重/冷却调整也走“写入、读取、验证”三同步 |

---

## 10. 结论

这个机制本质上是引擎的**负熵输入阀**：用重复率作为功能熵升高的报警信号，用认知池和坑库作为变异来源，用质量校验和 Canary 作为选择压力，用效果验证作为反馈闭环。只要该闭环持续运行，任务池就不会退化为静态档案库，而是会随外部信息和内部经验持续自进化。
