## 1. 裸 except 判定标准

以下三类都属于本次治理范围：

| 类型 | 表现 | 风险 |
|---|---|---|
| 裸 `except:` | 捕获所有异常，包括 `KeyboardInterrupt` / `SystemExit` | 极高，可能掩盖严重错误 |
| `except Exception:` 但无处理 | `pass` / 空注释 / 没有日志 | 高，关键路径静默失败 |
| `except Exception:` 但只 `print` | 没有结构化日志，无法定位上下文 | 中高，运维不可观测 |

---

## 2. 分类清单

治理时统一分为三类：

### A 类：合理忽略（需加 DEBUG 日志）

满足以下条件才可忽略：

- 不在关键路径上
- 失败不影响主流程 / 数据一致性
- 失败可自动恢复
- 已有兜底逻辑

典型场景：

- 关闭临时文件失败
- 删除缓存文件失败
- 上报非关键指标失败
- 清理临时目录失败

**处理要求：**

不允许完全裸 `except`，至少改为：

```python
except Exception as e:
    logger.debug("非关键清理失败，忽略: %s", e, exc_info=True)
```

---

### B 类：关键路径需加日志

满足以下条件必须加 ERROR 日志：

- 影响状态保存 / 读取
- 影响文件移动 / 覆盖
- 影响配置加载 / JSON 解析
- 影响 API 调用结果
- 影响主流程继续运行

**处理要求：**

```python
except Exception as e:
    logger.error("关键操作失败，上下文=%s，错误=%s", context, e, exc_info=True)
    raise  # 或执行明确降级策略
```

---

### C 类：必须修复

- 裸 `except:` 出现在任何位置
- `except Exception: pass` 出现在状态保存、文件移动、JSON 解析等关键路径
- 异常被吞掉但上层无法感知

**处理要求：**

必须改为具体异常类型 + 日志 + 处理策略。

## 3. 重点三类专项治理

### 3.1 状态保存失败

**现状检查点：**

- 状态写入是否用 `try / except`？
- 是否捕获 `OSError`、`TypeError`、`json.JSONDecodeError`？
- 是否记录了状态文件路径？
- 保存失败后是否继续运行？

**修改建议：**

```python
try:
    save_state(state_file, state)
except (OSError, TypeError) as e:
    logger.error(
        "状态保存失败 file=%s state_type=%s err=%s",
        state_file,
        type(state).__name__,
        e,
        exc_info=True,
    )
    raise
```

如果希望保存失败不中断主流程，也必须明确降级：

```python
except (OSError, TypeError) as e:
    logger.error("状态保存失败，已降级为不保存 file=%s err=%s", state_file, e, exc_info=True)
    fallback_used = True
```

禁止：

```python
except:
    pass
```

---

### 3.2 文件移动失败

**现状检查点：**

- 是否使用 `os.rename` / `shutil.move`？
- 是否捕获 `OSError`、`shutil.Error`？
- 日志中是否包含 `src` 和 `dst`？
- 跨文件系统移动失败时是否有 fallback？

**修改建议：**

```python
import shutil

try:
    shutil.move(src, dst)
except (OSError, shutil.Error) as e:
    logger.error(
        "文件移动失败 src=%s dst=%s err=%s",
        src,
        dst,
        e,
        exc_info=True,
    )
    raise
```

特别注意：

- `os.rename` 跨文件系统会报 `EXDEV`，如果必须用 `os.rename`，失败后要 fallback 到 `shutil.move`。
- 文件移动失败不能静默继续，否则会导致重复处理或数据缺失。

---

### 3.3 JSON 解析失败

**现状检查点：**

- 解析配置文件、状态文件、API 返回值时是否有 `try / except`？
- 是否捕获 `json.JSONDecodeError`？
- 日志中是否包含解析来源、错误位置、上下文片段？

**修改建议：**

```python
import json

try:
    data = json.loads(text)
except json.JSONDecodeError as e:
    logger.error(
        "JSON解析失败 source=%s pos=%d line=%d col=%d snippet=%r err=%s",
        source_name,
        e.pos,
        e.lineno,
        e.colno,
        text[max(0, e.pos - 20): e.pos + 20],
        e,
        exc_info=True,
    )
    raise
```

如果是配置解析失败，允许使用默认值，则必须记录 WARNING：

```python
except json.JSONDecodeError as e:
    logger.warning("配置解析失败，使用默认配置 source=%s err=%s", source_name, e, exc_info=True)
    config = DEFAULT_CONFIG
```

禁止：

```python
except Exception:
    config = DEFAULT_CONFIG
```
