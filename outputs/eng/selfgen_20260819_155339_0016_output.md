# 任务类型: eng

## 方案：多模型成本实时监控与自动熔断系统

### 一、定位与设计原则

1. **所有状态持久化，不依赖进程内存**  
   沙箱环境可能随时杀进程，系统必须能从持久化 state 中“在崩溃中重建”。

2. **所有阈值、冷却、超时、模型 ID 从 state/config 读取**  
   全局常量只做默认值兜底，禁止硬编码熔断冷却、预算、timeout。

3. **熔断是默认退化路径，不是异常分支**  
   模型不可用/超预算时，自动降级或排队，而不是报错中断。

4. **每个模型独立计数，且计数语义唯一**  
   成本、调用次数、任务完成数必须分开，避免 `count/task/bonus` 混用。

5. **以 `change_id + content_hash` 作为幂等纽带**  
   所有任务、补跑、配置变更都带同一个幂等键，防止重复执行和重复计费。

### 二、核心状态模型

#### 1. 模型熔断状态表 `model_guard_state`

```sql
create table model_guard_state (
  model_id text primary key,          -- 官方完整 model_id，如 doubao-seed-2-1-pro
  alias text not null unique,         -- 业务别名，如 A-pro / B-turbo
  budget_limit numeric not null,      -- 周期预算上限
  budget_used numeric not null default 0,
  budget_period text not null default 'daily',
  budget_reset_at timestamptz not null,
  circuit_state text not null default 'closed', -- closed/open/half_open
  circuit_reason text,                -- budget/failures/manual
  circuit_opened_at timestamptz,
  circuit_cooldown_seconds int not null default 300,
  consecutive_failures int not null default 0,
  total_calls int not null default 0,
  task_calls int not null default 0,
  bonus_calls int not null default 0,
  total_cost numeric not null default 0,
  total_tokens bigint not null default 0,
  timeout_seconds int not null default 600,
  version bigint not null default 0,
  updated_at timestamptz not null default now(),
  constraint calls_consistency check (total_calls = task_calls + bonus_calls)
);
```

#### 2. 等待任务表 `pending_task`

```sql
create table pending_task (
  task_id text primary key,           -- sha256(change_id + content_hash + preferred_model_id)
  change_id text not null,
  content_hash text not null,
  preferred_model_id text not null,
  fallback_chain jsonb not null default '[]',
  payload jsonb not null,
  status text not null default 'queued', -- queued/running/done/failed/canceled
  attempts int not null default 0,
  max_attempts int not null default 5,
  retry_at timestamptz not null default now(),
  priority int not null default 0,
  last_error text,
  actual_model_id text,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  unique(change_id, content_hash, preferred_model_id)
);
```

### 三、计数与成本规则

- `budget_used`：真实成本，由 `response.usage` 和模型单价计算。
- `total_calls`：所有模型调用次数。
- `task_calls`：真实业务任务触发的调用，重试沿用原 `task_type`。
- `bonus_calls`：系统自触发调用，如探活、巡检、预热。
- `tasks_completed`：从 `pending_task` 中统计，不写入模型状态表。
- 唯一关系：`total_calls = task_calls + bonus_calls`。
- 成本、调用次数、任务完成数三者分开统计，禁止互相替代。

所有计数更新必须走统一函数，例如：

### 四、熔断状态机

```
closed
  ├─ 预算超限              -> open(reason=budget)
  ├─ 连续失败超过阈值       -> open(reason=failures)
  └─ 正常调用

open(reason=budget)
  ├─ 不自动恢复，等 budget_reset_at 或人工调高预算
  └─ 恢复后 -> closed，并 drain_queue

open(reason=failures)
  ├─ 冷却时间过后 -> half_open
  └─ half_open 探活成功 -> closed，drain_queue
  └─ half_open 探活失败 -> open，重新冷却
```

熔断打开时：

```python
async def open_circuit(model_state, reason):
    model_state.circuit_state = "open"
    model_state.circuit_reason = reason
    model_state.circuit_opened_at = now()
    # 关键：冷却时间从 state 读取，不能硬编码
    model_state.circuit_cooldown_seconds = (
        config.value.get("fuse_cooldown_override")
        or DEFAULT_COOLDOWN_SECONDS
    )
```

### 五、调用与降级流程

```python
async def guarded_call(req):
    cfg = await get_config()  # 每次读取最新配置
    model_id = resolve_official_model(req.model_alias, cfg)

    async with state_lock(model_id):
        ms = await load_model_state(model_id)
        await maybe_reset_budget(ms, cfg)

        # 1. 熔断检查
        if ms.circuit_state == "open":
            if ms.circuit_reason == "budget" and now() >= ms.budget_reset_at:
                await reset_budget(ms)
                ms.circuit_state = "closed"
            elif ms.circuit_reason == "failures" and now() >= ms.circuit_opened_at + ms.circuit_cooldown_seconds:
                ms.circuit_state = "half_open"
            else:
                return await fallback_or_enqueue(req, ms)

        # 2. 半开探活
        if ms.circuit_state == "half_open":
            if not probe_allowed(ms, cfg):
                return await fallback_or_enqueue(req, ms)

            ok = await probe_model(model_id, ms.timeout_seconds)
            if ok:
                ms.circuit_state = "closed"
                ms.consecutive_failures = 0
                await save_state(ms)
                await drain_queue(model_id)
            else:
                await open_circuit(ms, reason="failures")
                await save_state(ms)
                return await fallback_or_enqueue(req, ms)

        # 3. 预算预检
        if ms.budget_used >= ms.budget_limit:
            await open_circuit(ms, reason="budget")
            await save_state(ms)
            return await fallback_or_enqueue(req, ms)

        # 4. 调用模型
        try:
            resp = await call_model(
                model_id,
                req,
                timeout=ms.timeout_seconds  # 从 state 读取
            )
            cost = calc_cost(model_id, resp.usage, cfg)
            await update_stats(ms, cost, resp.usage, task_type=req.task_type)
            await save_state(ms)
            await mark_task_done(req.task_id, actual_model_id=model_id)
            return resp

        except Exception as e:
            ms.consecutive_failures += 1
            if ms.consecutive_failures >= cfg.value["max_consecutive_failures"]:
                await open_circuit(ms, reason="failures")
            await save_state(ms)
            return await fallback_or_enqueue(req, ms)
```

### 六、恢复后自动补跑

后台 `RecoveryLoop` 定时执行：

```python
async def recovery_loop():
    while True:
        # 1. 重置到期预算
        await reset_expired_budgets()

        # 2. 处理上次崩溃遗留的 running 任务
        await requeue_stale_running()

        # 3. 推进 half_open 熔断探活
        await advance_half_open()

        # 4. 对 closed 且有预算的模型补跑队列
        for model_id in closed_models():
            await drain_queue(model_id)

        await sleep(cfg.value["scan_interval_seconds"])
```

```python
async def drain_queue(model_id):
    batch = select * from pending_task
            where status = 'queued'
              and retry_at <= now()
              and (preferred_model_id = model_id or fallback_chain @> [model_id])
            order by priority, created_at
            limit cfg.value["queue_batch_size"]

    for task in batch:
        if not await can_use_model(model_id):
            break
        await guarded_call(task.to_request())
```

### 七、崩溃恢复与幂等

- 所有状态在 Supabase/Postgres 中，进程内存只做临时缓存。
- 启动时扫描 `pending_task`：
  - `running` 且超过 `timeout_seconds` 的任务，标记为 `queued`，`attempts + 1`，设置退避 `retry_at`。
  - 如果 `attempts > max_attempts`，标记 `failed`。
- 启动时如果发现 `half_open` 状态，统一回退为 `open`，因为无法确认上一次探活是否完成。
- 每次调用都携带 `change_id + content_hash` 生成的 `task_id`，保证重试不重复入队。

### 八、避坑清单

1. **模型型号错配**  
   所有计数、路由 key 必须是官方完整 `model_id`，业务别名只做映射，禁止混用 `pro/turbo/light`。

2. **熔断冷却配置不生效**  
   熔断打开时从 `state/config` 读取 `fuse_cooldown_override`，写入 `circuit_cooldown_seconds`，不读硬编码常量。

3. **计数语义混乱**  
   `total_calls = task_calls + bonus_calls`；`budget_used` 是成本；`tasks_completed` 是任务完成数。三者不能互相替代。

4. **配置修改后不生效**  
   所有配置读取统一走 `get_config()`，修改后必须 bump `version`，并立即发一次探活验证。

5. **API 超时**  
   每个模型独立配置 `timeout_seconds`：B 模型 turbo 用 300 秒，A 模型用 600 秒。超时计入连续失败并触发熔断。

---

### 九、与同步链的衔接

本系统可以作为“先验证、再分工、后沉淀规范”同步链上的一个节点：

- 配置变更在 Gitee 产生 `change_id`。
- 内容哈希写入 `app_config` 和 `pending_task`。
- 飞书文件上传、Supabase 存储同步共用同一 `change_id + content_hash`。
- 熔断、降级、补跑都围绕同一个幂等键展开，保证跨系统可追踪、可恢复。

这样，多模型成本监控与熔断系统就不只是三个 API 的拼接，而是一套可演化、能在崩溃中重建的同步链机制。
