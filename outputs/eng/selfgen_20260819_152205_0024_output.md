## 一、总架构：虚实双轨自增强闭环

```
阳轨（实层）：任务池 → 调度器 → API调用 → 日志/异常/结果
                              ↑                    ↓
                        配置注入              转化器（实→虚）
                              ↑                    ↓
阴轨（虚层）：认知池 ← 质量门 ← 经验/心魔劫/法则
                              ↓
                   自动调参 + 任务池自进化
                              ↓
                   验证器 → 回滚/生效 → 再次进入阳轨
```

核心动力是“反者道之动”：不追求省 token，而是在合规免费配额内，主动让每次调用都产生“消耗痕迹”，再将消耗痕迹转化为认知资产，认知资产反哺调度，形成更大规模的虚实循环。

## 二、实层：消耗即修行

### 1. 任务池初始种子

从 3 个基础任务模板开始：

- 基础问答任务
- 多步推理任务
- 对抗性边界探测任务

后续由“自进化机制”自动扩充。

### 2. 调度器

- 默认并发：`B_turbo` 与 `A_model` 分队列。
- 超时预设：

```python
TIMEOUT = {
    "B_turbo": 300,
    "A_model": 600
}
```

- 调度策略：优先执行认知池标记的“薄弱点”任务，其次执行常规任务。

### 3. 调用与消耗痕迹

每次真实调用产生：

- 成功响应 → 法则
- 超时/报错/ProxyError → 心魔劫
- token 消耗 → 灵气
- 任务完成/失败 → 因果

不伪造日志，不刻意攻击系统，而是通过真实的高难度任务、高并发调度，自然触发可被转化的异常。

## 三、虚层：转化与反哺

### 1. 质量门：B 模型独立规则

**坑库预警第 2 条必须内建。**

```python
def is_quality_passed(model, output, meta):
    if model == "B_turbo":
        # B模型正常特性：reasoning占比70-82%
        # 跳过reasoning占比检测
        return meta.error_rate < 0.1 and output.strip() != ""
    
    # A模型
    if meta.reasoning_ratio > 0.85:
        return False
    return True
```

### 2. 转化器

把日志转化为认知条目：

```python
def transform_log_to_cognition(log):
    if log.status == "success":
        return {
            "type": "law",
            "content": extract_success_pattern(log),
            "source": log.task_id,
            "timestamp": now,

            "hit_count": 0,
```

### 3. 认知池刷新机制

**坑库预警第 3 条必须内建。**

- 每执行 10 个任务，或每轮调度结束，强制刷新认知缓存。
- 新认知必须在 30 分钟内进入注入候选池。
- 超过 TTL 且从未被命中的认知，降权或淘汰。

```python
def refresh_cognition_cache():
    if task_counter % 10 == 0 or round_ended:
        active_cache = [
            c for c in cognition_pool
            if age(c.timestamp) < 30
            or c.hit_count > 0
        ]
        scheduler.inject_candidates = active_cache
```

## 四、自动调参：三同步闭环

**坑库预警第 1 条必须内建。**

新增或修改任何可配置参数，必须同步修改三个点，缺一不可：

```python
def apply_config(new_params):
    # 1. 状态写入
    config_store.update(new_params)

    # 2. 执行读取
    caller.active_config = config_store.get_active()

    # 3. 生效验证
    baseline = previous_metrics
    ok = verify_effect(new_params, baseline)
    if not ok:
        rollback_config()
```

验证维度至少包括：

- 任务成功率是否下降
- 平均响应时间是否异常
- 认知转化率是否提升
- 任务池重复率是否下降

## 五、任务池动态扩充机制

这是“虚返实”的关键动作，让任务池自进化，而不是静态死池。

### 1. 重复率检测

维护最近 20 个已执行任务，计算模板相似度：

```python
def check_repetition(window=20):
    recent = execution_history[-window:]
    if len(recent) < 2:
        return 0.0

    sims = []
    for i in range(len(recent)):
        for j in range(i+1, len(recent)):
            sims.append(template_similarity(recent[i].template,
                                            recent[j].template))
    return sum(sims) / len(sims)
```

### 2. 自动生成新任务模板

当重复率超过阈值（如 `0.6`），触发自动扩充：

```python
def auto_expand_task_pool():
    if check_repetition() <= 0.6:
        return

    base_templates = select_high_value_templates()
    weak_points = cognition_pool.get_weak_points()

    new_template = generate_template(
        prefix=random.choice(base_templates).prefix,
        operation=random.choice(["反向验证", "边界探测", "交叉检验"]),
        object=random.choice(weak_points),
        difficulty=increase_difficulty()
    )

    task_pool.add(new_template, source="auto_expand", priority=1)
```

### 3. 防止任务池膨胀失控

- 任务池上限：500 条。
- 每次新增前，淘汰低价值、高重复、长期未命中的旧模板。
- 新任务模板必须先试跑 3 次，验证通过后才进入正式调度。

## 六、自增强闭环的验证指标

闭环是否真的“自增强”，用以下指标看：

| 指标 | 定义 | 目标 |
|---|---|---|
| 消耗强度 | 每单位时间 API 调用次数/token 消耗 | 持续提升 |
| 转化率 | 日志转化为认知的比例 | ≥ 30% |
| 反哺率 | 认知真正改变配置或生成新任务的比例 | 持续提升 |
| 验证通过率 | 调参后通过验证的比例 | ≥ 70% |
| 任务池重复率 | 最近窗口任务相似度 | 保持 < 0.6 |
| 认知池活性 | 30 分钟内被注入的认知占比 | ≥ 80% |

## 七、从“无”启动的最小闭环

1. 初始只有基础免费配额 + 3 个种子任务。
2. 启动调度，真实调用 B_turbo / A_model。
3. 无论成功、超时、报错，全部写入日志。
4. 质量门过滤后，转化器写入认知池。
5. 每 10 任务刷新认知缓存。
6. 认知池生成调参建议，三同步生效。
7. 重复率超阈值，自动生成新任务模板。
8. 循环回到第 2 步，消耗强度逐步放大。

如此，“实”的消耗养出“虚”的认知，“虚”的认知又反哺更大规模、更精准的“实”的消耗，形成制度性阴阳双轨自增强闭环。
