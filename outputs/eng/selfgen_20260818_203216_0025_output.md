# 任务类型: eng

## 推演结论

V7.5 方舟效能引擎的多线程 API 调用 + 串行后处理，不能靠“一把大锁锁住全部流程”来解决。正确模式是：

> **并行写槽位 + 屏障等待 + 串行提交**

锁只保护状态变更，不保护网络调用。否则任何一个慢 API 都会持锁阻塞整个任务，出现“生命体征暂停”。

---

## 状态模型

### 任务阶段

```
PENDING
  -> API_CALLING
  -> BARRIER
  -> POST_PROCESSING
  -> COMMITTED / DEGRADED / FAILED
```

### 槽位状态

```
EMPTY
  -> IN_FLIGHT
  -> DONE / ERROR / TIMEOUT
```

槽位一旦进入终态，除 barrier 超时外不允许再次写入；迟到写入必须通过 **generation** 丢弃。

---

## 完整锁机制方案

### 锁角色

- `ctx.lock`：保护 `phase`、`remaining`、槽位状态、`generation`。
- `ctx.cv`：Condition Variable，用于屏障等待。
- 网络调用在锁外执行，锁内只做状态写回。
- 后处理提交在锁外执行，锁内只推进任务阶段。

### 核心代码

```python
import threading
import time
import json
from urllib.request import Request, urlopen
from urllib.request import build_opener, ProxyHandler

class Slot:
    def __init__(self, slot_id, request, timeout):
        self.id = slot_id
        self.request = request
        self.timeout = timeout
        self.status = "EMPTY"
        self.result = None
        self.error = None
        self.generation = 0


class BatchContext:
    def __init__(self, cfg):
        self.lock = threading.Lock()
        self.cv = threading.Condition(self.lock)
        self.cfg = cfg
        self.slots = []
        self.remaining = 0
        self.phase = "PENDING"
        self.generation = 0


def api_worker(ctx, slot):
    # 1. 网络调用：绝不持锁
    try:
        # 统一 urllib 直连，避免 requests 全局代理 ProxyError
        opener = build_opener(ProxyHandler({}))
        with opener.open(slot.request, timeout=slot.timeout) as resp:
            data = resp.read()
        err = None
    except Exception as e:
        data = None
        err = e

    # 2. 状态写回：必须持锁
    with ctx.lock:
        # 迟到写入丢弃：generation 不匹配，或槽位已不是 IN_FLIGHT
        if slot.status != "IN_FLIGHT" or slot.generation != ctx.generation:
            return

        slot.result = data
        slot.error = err
        slot.status = "DONE" if err is None else "ERROR"
        ctx.remaining -= 1
        ctx.cv.notify_all()


def start_batch(ctx):
    with ctx.lock:
        ctx.generation += 1
        gen = ctx.generation

        for s in ctx.slots:
            s.generation = gen
            s.status = "IN_FLIGHT"
            s.result = None
            s.error = None

        ctx.remaining = len(ctx.slots)
        ctx.phase = "API_CALLING"

    threads = []
    for s in ctx.slots:
        t = threading.Thread(target=api_worker, args=(ctx, s))
        t.start()
        threads.append(t)

    return threads


def wait_barrier_and_snapshot(ctx):
    with ctx.lock:
        ctx.phase = "BARRIER"
        deadline = time.monotonic() + ctx.cfg["barrier_timeout"]

        while ctx.remaining > 0:
            wait = deadline - time.monotonic()
            if wait <= 0:
                break
            ctx.cv.wait(wait)

        # 超时未返回的槽位置为 TIMEOUT
        if ctx.remaining > 0:
            for s in ctx.slots:
                if s.status == "IN_FLIGHT":
                    s.status = "TIMEOUT"
                    s.error = TimeoutError(f"slot {s.id} timeout after {s.timeout}s")
                    ctx.remaining -= 1

        # 关键：使所有迟到写失效
        ctx.generation += 1
        ctx.phase = "POST_PROCESSING"

        # 复制快照，串行后处理不持锁
        snapshot = [(s.id, s.status, s.result, s.error) for s in ctx.slots]

    return snapshot


def extract_content(raw):
    if raw is None:
        return ""

    try:
        obj = json.loads(raw)
    except Exception:
        return raw.decode("utf-8", "ignore") if isinstance(raw, bytes) else str(raw)

    # 兼容 Responses API / Chat Completions
    return (
        obj.get("output")
        or obj.get("content")
        or (obj.get("choices") or [{}])[0].get("message", {}).get("content")
        or ""
    )


def serial_post_process(ctx, snapshot):
    committed = []

    for slot_id, status, result, error in snapshot:
        if status == "DONE":
            content = extract_content(result)

            # 坑：B 模型 Responses API content 可能为空
            # 不能把空 content 当成功提交
            if not content:
                status = "ERROR"
                error = Exception(f"slot {slot_id} content empty")

        if status != "DONE":
            # 重试必须新建 BatchContext，不能复用旧槽位
            handle_failure(slot_id, status, error)
            continue

        # 串行幂等提交
        commit_with_idempotency(
            key=f"ark_v75:{ctx.generation}:{slot_id}",
            content=content,
        )
        committed.append(slot_id)

    with ctx.lock:
        if len(committed) == len(ctx.slots):
            ctx.phase = "COMMITTED"
        else:
            ctx.phase = "DEGRADED"
        ctx.committed = committed

    return committed
```

## 竞态条件处理对照

| 竞态 | 防护机制 |
|---|---|
| 后处理早于所有 API 返回 | `remaining` + Condition 屏障等待 |
| 多线程同时写槽位 | 槽位预分配 + `ctx.lock` 保护写回 |
| 超时后迟到写覆盖结果 | `generation` 递增，迟到写直接丢弃 |
| 同一槽位重复提交 | 槽位状态检查 + 幂等提交键 |
| 配置修改不生效 | 任务启动时配置快照，新增配置必须同步读取点 |
| API 调用超时导致任务卡死 | 每请求显式 timeout + barrier_timeout |
| ProxyError | 统一 urllib 直连，`ProxyHandler({})` 禁代理 |
| B 模型 content 为空 | 串行后处理中强制 content 非空校验 |

---

## 可直接写入 SOP 的工程铁律

1. **网络调用零持锁**  
   API 调用在锁外执行；锁内只更新槽位状态和推进阶段。

2. **屏障等待必须带超时，并且用 generation 失效迟到写**  
   等待 `remaining == 0`，超时后槽位置为 `TIMEOUT`，然后 `generation += 1`，所有迟到响应自动丢弃。

3. **串行提交必须幂等，且校验 content 非空**  
   提交键必须包含任务代际和槽位 ID；B 模型 content 为空视为失败，不能提交空壳。

这套机制把“多线程并发”和“串行一致性”之间的鸿沟，收敛为：

> **并发只负责填槽，屏障只负责收敛，串行只负责提交。**
