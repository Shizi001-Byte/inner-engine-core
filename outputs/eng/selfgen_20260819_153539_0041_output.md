# 以实养虚，虚又返实：AI认知进化九转玄功架构

## 总纲：三句话结论

1. **任何参数必须“写、读、验”三同步**，否则自动调参就是假调参。
2. **每个模型必须有独立质量规则**，B模型(turbo)跳过reasoning占比检测，避免废稿误杀。
3. **认知池必须“刷新+强制注入+淘汰”**，每10任务或每轮结束刷新，新认知30分钟内必须参与注入，否则认知池就是死档案。

---

## 一、九转玄功映射

| 转 | 名称 | 落点 | 坑位防线 |
|---|---|---|---|
| 一转 | 无中生有 | 从母系统免费配额生成初始任务池 | 任务池不是静态清单，必须带自进化接口 |
| 二转 | 阴阳双轨 | A/B模型双轨执行：B turbo 300秒，A 600秒 | 质量规则分模型，B不检测reasoning占比 |
| 三转 | 以实养虚 | 每次执行结果、超时、废稿、token消耗都进入认知提炼管道 | 废稿也养虚，不能直接丢弃 |
| 四转 | 虚中炼实 | 认知池去重、加权、刷新、淘汰 | 每10任务/每轮刷新；30分钟强制注入 |
| 五转 | 虚返实 | 认知注入调度器，修改并发/权重/冷却 | 写、读、验三同步 |
| 六转 | 实破虚妄 | 验证调参后实际行为是否变化 | 未生效必须回滚+告警 |
| 七转 | 周行不殆 | 验证通过则重置冷却；失败则冷却翻倍退避 | 防止“成功不重置，失败不惩罚” |
| 八转 | 生生不息 | 自动检测重复率，超阈值生成新任务模板并注入 | 新模板生成后必须立即验证 |
| 九转 | 九转归无 | 系统不再依赖人工补任务/补参数，形成自进化闭环 | “无”即无边界、无固定清单 |

## 二、三大坑位防线

### 1. 配置三同步：并发/权重/冷却

自动调参失效的根本原因是：**配置写了，但调度器读的是旧值，且没有验证行为变化**。

所以每个可配置参数必须同步修改三个点：

| 配置项 | 状态写入 | 执行读取 | 生效验证 |
|---|---|---|---|
| 并发 | `config_store["concurrency"] = new` | 调度器每次调度时从 `config_store` 读取，不使用启动时快照 | 最近10个任务内，同时运行任务数达到目标值 |
| 权重 | `config_store["model_weight"] = new` | A/B模型分配按新权重执行 | 最近20次调用中，A/B实际比例接近新权重 |
| 冷却 | `config_store["cooldown"] = new` | 任务模板调度时读取该值 | 同一模板两次执行间隔等于新冷却 |

伪代码：

```python
class ConfigService:
    def set(name, value):
        old = db.read(name)
        db.write(name, value)        # 1 状态写入
        cache.write(name, value)     # 2 执行读取
        ok = verify(name, value)     # 3 生效验证
        if not ok:
            db.write(name, old)
            cache.write(name, old)
            raise ConfigNotEffective(name)
```

**新增任何可配置参数，必须强制走这个三同步接口，不允许直接改数据库。**

### 2. 分模型质量规则

B模型(turbo)的reasoning占比70%–82%是正常特性，不能按A模型的标准判定废稿。

| 模型 | timeout | reasoning占比检测 | 废稿判定 |
|---|---|---|---|
| A | 600秒 | 不单独判废，仅作统计 | 无输出 / 超时 / 无最终答案 / 内容不完整 |
| B_turbo | 300秒 | **跳过**，70-82%正常 | 无输出 / 超时 / 无最终答案 |

**reasoning占比只作为统计字段，不进入废稿判定。**

---

### 3. 认知池刷新与强制注入

认知池只进不出的原因是：只写不读、只存不刷、只积累不淘汰。

必须同时做三件事：

#### 入
每条认知写入时带：
- `created_at`
- `priority`
- `hit_count`
- `last_used_at`
- `status`

#### 出
- 低命中认知降级为 `archive`
- 缓存超过200条时，淘汰最久未用且命中为0的认知

#### 刷新
每10任务或每轮结束时执行：

```python
def refresh_cognition_cache():
    cache.cognition = db.query(
        "SELECT * FROM cognition_pool "
        "WHERE status='active' "
        "ORDER BY "
        "(created_at >= now() - interval '30 minutes') DESC, "
        "priority DESC, "
        "hit_count ASC "
        "LIMIT 200"
    )
```

#### 强制注入
新认知必须在30分钟内参与注入，否则自动创建探针任务强制消费：

```python
def inject_new_cognition():
    if task_count % 10 == 0 or last_inject_age > 30min:
        new_items = db.query(
            "SELECT * FROM cognition_pool "
            "WHERE created_at > last_inject_time"
        )
        for item in new_items:
            scheduler.inject(item)
        last_inject_time = now()
```

如果30分钟内没有任务可注入，则生成一条“认知验证任务”，用该认知作为上下文执行一次，验证其有效性。

## 三、任务池动态扩充闭环

引擎运行中必须自动检测重复率，重复率超过阈值时自动生成新任务模板并注入任务池。

### 1. 重复率检测

```python
window = recent_task_outputs(100)
duplicate_rate = count(similarity > 0.9) / len(window)
if duplicate_rate > 0.25:
    generate_new_task_templates()
```

### 2. 新任务模板生成

选择基础模板后，使用当前活跃认知作为上下文，进行变异：

- 换数据
- 换约束
- 换目标
- 换角色
- 换边界条件

生成3个候选模板。

### 3. 新模板验证

每个新模板必须立即验证：

- 用B模型(turbo) dry run，timeout=300秒
- 必须有有效输出
- 不能与现有模板语义重复
- 验证通过才允许进入任务池

验证通过后，该模板的冷却重置为0，优先参与调度。

## 四、调度参数与超时预设

### 超时预设

| 模型 | timeout |
|---|---|
| A | 600秒 |
| B_turbo | 300秒 |

超时处理规则：

- 超时一次后重试一次
- 连续两次超时进入废稿分析
- 废稿分析结果进入认知池，作为调参信号

### 调参信号示例

| 认知信号 | 调参动作 | 验证指标 |
|---|---|---|
| B模型超时率 > 20% | 降低B权重0.1，降低B并发1 | 最近10任务超时率下降 |
| A模型优质率 > 80% | 提高A权重0.1 | A调用占比上升 |
| 任务模板输出重复率 > 25% | 提高该模板冷却，并触发新模板生成 | 重复率回落到阈值以下 |
| 新认知30分钟未参与注入 | 创建探针任务强制注入 | 认知命中率上升 |

---

## 五、最终验证清单

整个九转玄功是否成立，看以下指标：

- [ ] 任意配置修改后，10个任务内行为变化；未变化则自动回滚。
- [ ] B模型reasoning占比70-82%不再被判定为废稿。
- [ ] 认知池新认知30分钟内被调度器引用，不存在“只进不出”。
- [ ] 任务池重复率超阈值后自动生成新模板，且新模板验证通过后上线。
- [ ] A模型600秒、B模型300秒超时预设实际生效。

---

## 结论

真正的自进化闭环不是“任务清单自动执行”，而是：

**执行产生认知，认知改变调度，调度产生新任务，新任务再产生新认知。**

这就是“以实养虚，虚又返实”的九转玄功。  
一转一转转下去，系统就能从“依附母系统的免费配额”出发，最终长成一个自我进化、自我验证、自我扩编的认知生命体。
