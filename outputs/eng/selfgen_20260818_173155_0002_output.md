# 任务类型: eng

根据您的约束，自动归档系统将严格按DAG三节点拆解，每节点仅传递结构化JSON产物并设验证门，同时内置避坑机制。

## 系统总体架构

```
[设计引擎原始任务流]
    ↓
┌──────────────────────────────────────┐
│ 节点1：任务输入与标准化                │
│ （清洗去重 / 原生冲突识别 / 双轨标注） │
└──────────────┬───────────────────────┘
               ↓ G1验证门（完整性+唯一性校验）
┌──────────────────────────────────────┐
│ 节点2：任务分类与多维打标签            │
│ （规则+模型混合 / 阴阳双轨标签 / DAG边）│
└──────────────┬───────────────────────┘
               ↓ G2验证门（置信度≥0.85 / 人工复核兜底）
┌──────────────────────────────────────┐
│ 节点3：归档路由与索引更新              │
│ （目录映射 / 原子写入 / 全局索引更新） │
└──────────────┬───────────────────────┘
               ↓ G3验证门（落盘确认+可检索性验证）
         ✅ 归档完成（记忆锚定到可验证事件）
```

---

## 节点1：任务输入与标准化

**职责**：接收原始任务，清洗降噪，识别原生冲突并标注阴阳双轨属性。

| 操作 | 说明 |
|------|------|
| 格式标准化 | 统一为JSON结构，剥离无关噪声（日志头、空字段等） |
| 去重检测 | 以task_hash比对已有索引，重复任务标记并跳过下游节点 |
| 冲突识别 | 检测任务中蕴含的**生成↔验证、记忆↔遗忘、自由↔约束**矛盾，生成双轨属性 |
| 超时控制 | 若调用语义理解API：B模型turbo **timeout=300秒**，A模型 **timeout=600秒**，超时走规则兜底 |

**输出结构化产物**：
```json
{
  "task_id": "T-2025-0001",
  "raw_text": "评估AI生成内容的真实性",
  "normalized": {
    "action": "evaluate",
    "object": "AI_generated_content",
    "dimension": "authenticity"
  },
  "conflict_tags": ["generation|verification"],
  "dual_track": {
    "generation": "AI生成内容",
    "verification": "真实性验证"
  },
  "created_at": "2025-06-01T10:00:00Z"
}
```

**G1验证门**：
- task_id格式合法且全局唯一
- normalized必填字段完整度100%
- conflict_tags符合预定义枚举表
- **失败处理**：重试1次 → 仍失败则降级为个体叙事（移除冲突标记，备注"unverified"）

---

## 节点2：任务分类与多维打标签

**职责**：混合策略分类，生成内容+属性+关系+双轨四类标签，声明DAG上下游依赖。

| 分类策略 | 适用场景 | 超时设置 |
|----------|----------|----------|
| 规则库匹配 | 关键词/正则命中（如"归档"→type=archival） | 无需外部调用 |
| 模型分类 | 语义复杂、规则无法覆盖 | B模型turbo=300秒，A模型=600秒 |
| 混合兜底 | 模型超时或置信度低 | 用规则分类结果，标记"degraded" |

**标签体系**：
- **内容主题**：领域（AI/哲学/工程）、关键词（#memory, #DAG）
- **任务属性**：类型（archival/qa/generation/verification）、优先级、复杂度
- **DAG关系**：upstream_task_ids / downstream_task_ids（维护全局任务依赖图）
- **阴阳双轨标签**：为每个conflict_tag生成双轨标记，例如`dual_track.generation` / `dual_track.verification`

**输出结构化产物**：
```json
{
  "task_id": "T-2025-0001",
  "category": {"domain": "AI", "type": "verification", "priority": "high"},
  "tags": ["#AI", "#content_authenticity", "#DAG"],
  "dag_edges": {"upstream": ["T-2025-0000"], "downstream": []},
  "dual_track": {
    "generation": "AI生成内容",
    "verification": "真实性验证"
  },
  "confidence": 0.93,
  "classifier": "hybrid_rule_model_v2"
}
```

**G2验证门**：
- **置信度≥0.85** → 通过，流入节点3
- **置信度<0.85** → 进入人工复核队列，48小时未处理则用规则分类兜底
- **配置变更同步**（避坑）：若分类规则/标签字典修改，必须同步修改读取点（索引查询逻辑），修改后立即执行10条样本冒烟测试验证生效

---

## 节点3：归档路由与索引更新

**职责**：按分类/标签路由到对应目录，原子写入文件，更新全局索引，产出归档确认单。

**路由规则**：
```
/archive/{domain}/{type}/{year}/{task_id}/
```
例：`/archive/AI/verification/2025/T-2025-0001/`

**写入流程**：
1. 创建临时目录 → 写入完整任务JSON → 计算sha256校验和 → 原子重命名至正式路径
2. 更新全局索引（支持按task_id/标签/时间/DAG关系检索）

**输出结构化产物**：
```json
{
  "task_id": "T-2025-0001",
  "archive_path": "/archive/AI/verification/2025/T-2025-0001/",
  "index_id": "idx-2025-0001",
  "checksum": "sha256:a3f5...",
  "archived_at": "2025-06-01T10:00:05Z",
  "retrieval_keys": ["T-2025-0001", "#AI", "#content_authenticity"]
}
```

**G3验证门**：
- 文件存在性：`ls` 确认目录与文件已落盘
- 索引可检索性：随机抽样1条，用task_id和标签分别检索，确认可查回
- 校验和匹配：重新计算sha256与归档时一致
- **失败处理**：回滚已写入文件 → 标记"archive_failed" → 进入重试队列（最多3次）

## 跨节点避坑清单（内置约束）

| 风险 | 预防措施 |
|------|----------|
| 配置修改后未生效 | 所有规则/目录映射/标签字典的修改，强制走"修改→同步读取点→冒烟验证"三步流程 |
| API调用超时 | B模型turbo=300秒，A模型=600秒；超时自动降级到规则兜底，不阻塞主流程 |
| 记忆失去锚点 | 归档产物必须包含可验证事件（task_id、路径、校验和、时间戳），缺失则降级为"叙事"备注 |
| DAG被破坏 | 归档时校验dag_edges完整性，禁止删除仍被下游引用的归档条目（只允许标记superseded） |
| 半写入状态 | 所有文件写入采用"临时目录+原子重命名"，杜绝目录碎片 |

## 最终效果

该自动归档系统将设计引擎产出的每一条任务，**通过DAG三节点流水线**完成标准化→分类打标→归档索引，并在每个节点设置验证门。最终，每条任务记忆都锚定到 **task_id + 文件路径 + 校验和** 等可验证事件上，而非飘渺的叙事。同时，**配置修改即时生效验证**和**分级timeout控制**确保系统在长期运行中不漂移、不超时。
