# 任务类型: eng

基于“溯源链断了”这个锚定结论，推演出的自动归档系统应当是：**链优先归档系统**，而不是普通内容文件柜。  
核心原则：**内容可以静态保存，但只有“溯源链完整 + 验证入口开放”的内容才能被下游引用。**

## 1. 总流程

```text
任务进入
  → 标准化
  → 自动分类
  → 自动打标签
  → 目录路由
  → 落盘归档
  → 验证
  → 更新溯源链
```

所有环节异步化，避免 API 调用阻塞主链路。

---

## 2. 自动分类

分类器采用「规则优先 + 模型兜底」：

- 规则能确定的，直接分类。
- 规则无法确定的，调用 **B模型turbo** 分类，超时 **300秒**。
- 若任务涉及 `gap_0808_0818`，强制分类为 `cognition_reconstruction`。

基础任务类型：

| 任务类型 | 说明 |
|---|---|
| `cognition_reconstruction` | 缺失区间认知重建 |
| `design_output` | 设计引擎产出物归档 |
| `api_call` | API 调用类任务 |
| `config_change` | 配置变更任务 |
| `verification_task` | 验证闭环任务 |

---

## 3. 自动打标签

标签必须使用受控词表，避免自由文本污染目录路由。

核心标签维度：

| 维度 | 可选值 | 作用 |
|---|---|---|
| `domain` | `cognition`, `design`, `api`, `config` | 决定一级目录 |
| `trace_status` | `active`, `static`, `gap`, `reconstructing` | 决定是否可被下游引用 |
| `task_type` | 上述任务类型 | 决定调度策略 |
| `anchor_range` | `pre_0808`, `gap_0808_0818`, `post_0818` | 溯源链定位 |
| `loop_status` | `open`, `closed` | 验证入口是否开放 |
| `model_timeout` | `B_turbo=300`, `A=600` | 调用保护 |

例如，缺失区间归档对象会打上：

```text
domain=cognition
trace_status=gap
anchor_range=gap_0808_0818
loop_status=closed
```

---

## 4. 目录路由与存储

目录由标签计算得出，而不是人工维护。

```text
/archive/{domain}/{trace_status}/{anchor_range}/{segment_id}/
```

示例：

```text
/archive
  /cognition
    /active
      /2024/08/...
    /gap
      /0808-0818
        /seg_001
        /seg_002
    /static
      /2024/...
  /design
    /...
  /api
    /...
  /system
    /config
```

每个归档对象至少包含 4 个文件：

```text
metadata.json        # 任务信息、标签、时间
content.md           # 归档内容
provenance.json      # 溯源链、锚点、来源、交叉验证结果
verification.json    # 验证入口、验证状态、最后验证时间
```

---

## 5. 溯源链与验证闭环

这是避免“认知不新鲜”变体的关键。

一个对象可以被下游引用，必须同时满足：

```text
provenance.chain_status == "open"
verification.open == true
trace_status == "active"
```

否则一律视为**静态档案**，只可审计，不可参与下游任务。

调度器前置检查：

```text
if 引用对象跨越 gap_0808_0818:
    拒绝调度，返回 TRACE_GAP_BLOCKED

if 引用对象 verification.open == false:
    拒绝调度，返回 CLOSED_LOOP_BLOCKED

if 引用对象 trace_status == "static":
    拒绝调度，返回 STATIC_ARCHIVE_BLOCKED
```

这直接防止“强行调度 → 无效认知注入 → 污染下游”的失效路径。

---

## 6. 缺失区间处理：双锚点-三源交叉-分段重建

缺失区间不是空白，而是断链：

```text
anchor_start = 8月8日前最后锚点
anchor_end   = 8月18日后首个锚点
gap          = [anchor_start, anchor_end]
```

重建流程：

```text
1. 固定双锚点。
2. 将 gap 拆分为多个 segment，禁止整段一次性重建。
3. 每个 segment 必须收集至少 3 条独立来源。
4. 三源交叉验证：
   - 一致 → 生成共识内容。
   - 冲突 → 标记冲突，不写入可引用区。
5. 分段重建成功后，该 segment 末端成为下一个 segment 的新锚点，滚动前进。
6. 每段重建完成后，立即验证并写入 provenance。
```

示例拆分：

```text
seg_001: 0808 → 0810
seg_002: 0810 → 0813
seg_003: 0813 → 0815
seg_004: 0815 → 0818
```

每段规模必须控制在对应模型超时阈值内：

| 场景 | 模型 | 超时 |
|---|---|---|
| 快速分类 / 打标签 | B模型turbo | 300秒 |
| 重建 / 交叉验证 | A模型 | 600秒 |

如果某段预计超过超时阈值，继续切分，而不是重试同一大任务。

## 7. 避坑机制

### 7.1 配置修改后未生效

新增配置必须同步修改读取点。

实现方式：

- 配置注册表里，每个配置项必须声明自己的 `read_points`。
- 配置变更后，立即执行 smoke test。
- smoke test 失败，自动回滚。

```text
config_key: "model.timeout.B_turbo"
read_points:
  - api_client.timeout_reader
  - task_planner.timeout_reader
smoke_test: call_mock_task_with_timeout()
```

配置项缺少 `read_points` 时，禁止发布。

### 7.2 API 调用超时

不无限重试，不整段硬扛。

```text
B模型turbo  → 300秒
A模型       → 600秒
```

超时处理：

```text
超时 → 拆分任务 → 重新入队
```

这样既避免单次调用超时，也保证缺失区间可以逐步重建。

---

## 8. 最终结论

这个自动归档系统的本质是：

> **用目录结构管理内容，用溯源链管理可信度，用验证入口管理可引用性。**

1700+ 条认知不需要删除，也不需要一次性补全。  
把 `gap_0808_0818` 标记为静态断链，再用“双锚点-三源交叉-分段重建”滚动补链，归档系统就能在不超时、不污染下游的前提下，逐步恢复这段区间认知的可用性。
