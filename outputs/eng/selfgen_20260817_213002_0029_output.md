# 任务类型: eng

为设计引擎产出的资产建立一套自动归档系统，是提升团队效率、保障资产可检索性和规范化的关键。这套系统的核心逻辑是：**解析产出物元数据 -> 智能分类与打标 -> 路由分发与存储 -> 索引与检索**。

以下是一套完整的设计引擎自动归档系统架构方案：

---

### 一、 系统整体架构

系统可分为四个核心层：**接入层、大脑层（分类与打标）、执行层（归档与存储）、服务层（检索与消费）**。

1.  **接入层**：监听设计引擎的产出事件（如渲染完成、导出完成），获取原始文件及伴随元数据（如任务ID、创作者、设计参数）。
2.  **大脑层**：解析文件内容与元数据，运用规则引擎和AI视觉模型，生成分类标签树。
3.  **执行层**：根据分类标签，将文件重命名并移动/复制到对应的物理目录或对象存储桶中。
4.  **服务层**：建立Elasticsearch索引，提供前端检索界面和API供设计师/开发者调用。

---

### 二、 核心模块设计

#### 1. 任务自动分类模块
分类决定了文件“放在哪个文件夹”。采用**“规则优先，AI兜底”**的混合策略：

*   **强规则分类（基于元数据）：**
    *   引擎产出的任务通常带有上下文。例如：任务来源于“电商频道”，则自动归入`E-Commerce`大类；文件格式为 `.lottie` 或 `.json`，归入`Animation`类。
    *   根据画板尺寸/分辨率：如 1920x1080 归入`HD-Video`，50x50 归入`Icon`。
*   **AI视觉分类（基于内容理解）：**
    *   对于元数据缺失或模糊的产出，调用轻量级图像分类模型（如 ResNet 或 CLIP）。
    *   识别图像主体：人物、风景、UI界面、3D模型渲染图等。
    *   **分类树设计示例：**
    *   `📁 DesignAssets`
        *   `📁 UI_Components` (按钮、导航栏、表单)
        *   `📁 Illustrations` (插画、背景图)
        *   `📁 3D_Renders` (三维渲染图、材质贴图)
        *   `📁 Branding` (Logo、字体、VI规范)

#### 2. 自动打标系统
标签决定了文件“能不能被精准搜到”。标签体系应是多维度的：

*   **维度一：业务标签**
    *   来源业务线（如：双十一大促、日常迭代、海外版）
    *   情感/风格（如：科技感、扁平化、赛博朋克、极简）
*   **维度二：视觉特征标签 (AI驱动)**
    *   **主色调**：提取Top 3颜色值（如 `#FF5733`, `Dark-Mode`）
    *   **画面元素**：目标检测模型识别出的物体（如 `Dog`, `Car`, `Button`）
    *   **构图与布局**：居中、对称、留白率高。
*   **维度三：工程标签**
    *   分辨率、格式、是否带透明通道、文件大小。
*   **标签存储规范：**
    标签不仅存入数据库，还应写入文件的 XMP/EXIF 元数据中，确保文件离线流转时标签不丢失。

#### 3. 对应目录存入模块
归档不仅涉及物理路径，还涉及命名规范和存储策略。

*   **动态目录路由：**
    根据分类模块的结果，动态映射到存储路径。
    *映射公式：* `BasePath / {一级分类} / {二级分类} / {年月} / {文件名}`
*   **自动化重命名规范：**
    杜绝 `未命名1.psd`，系统自动生成标准化文件名：
    `日期_业务线_分类_唯一ID.扩展名` (例：`20231025_Ecomm_UI_btn_a1b2c.png`)
*   **存储隔离策略：**
    *   **热数据**（近30天产出、高频检索）：存入 SSD 本地目录，便于快速预览。
    *   **冷数据**（历史归档）：定期脚本迁移至 NAS 或云端 OSS（如阿里云OSS、AWS S3），降低成本。

---

### 三、 标准化工作流

以设计引擎产出一个“电商大促的3D按钮渲染图”为例：

1.  **事件触发**：设计引擎完成渲染，向消息队列发送 Event `{task_id: 998, file_url: ..., source: '电商大促', type: '3D'}`。
2.  **元数据提取**：系统下载文件，提取尺寸 200x80px，格式 PNG，带透明通道。
3.  **AI分析与打标**：
    *   视觉模型判定：画面主体为“按钮”，风格为“3D立体”、“红色系”。
    *   生成标签数组：`["e-commerce", "3D", "button", "red", "transparent", "UI"]`。
4.  **分类决策**：根据规则 `type=3D` 且 `主体=button`，决定一级目录为 `UI_Components`，二级目录为 `3D_Buttons`。
5.  **执行归档**：
    *   文件重命名为：`20231025_Ecomm_3DBtn_998.png`
    *   移动至：`/mnt/DesignAssets/UI_Components/3D_Buttons/2023-10/20231025_Ecomm_3DBtn_998.png`
6.  **索引建立**：将路径、标签、缩略图URL写入 Elasticsearch，供前端检索。

---

### 四、 技术实现建议

*   **消息中间件**：Kafka 或 RabbitMQ，用于解耦设计引擎产出与归档系统，高并发渲染时不丢数据。
*   **规则引擎**：Drools 或 Python 自定义规则链，处理确定性的分类与路由逻辑。
*   **AI 视觉服务**：
    *   使用 CLIP (Contrastive Language-Image Pretraining) 模型提取图片特征向量，支持以图搜图和自然语言搜图。
    *   部署轻量级 YOLO 模型进行元素检测。
*   **文件存储与索引**：MinIO（自建对象存储）或云OSS存放实体文件；Elasticsearch 存储元数据与标签索引。
*   **工作流编排**：使用 Temporal 或 Apache Airflow 管理归档流水线，支持失败重试和断点续传。

---

### 五、 异常与边缘场景处理

1.  **文件分类冲突**：如果一张图既是插画又是背景，系统应允许多级分类，生成软链接或在不同分类下创建快捷方式，而非复制文件造成冗余。
2.  **低质产出拦截**：在归档前增加质量校验（如：分辨率过低、纯白图片、损坏文件），不合格的产出直接拦截并打回引擎，不进入归档库。
3.  **人工纠偏机制**：系统自动归档后，在前端提供“纠错”按钮。设计师发现分类错误，可手动修改，系统不仅会物理移动文件，还会将该修正作为训练数据反馈给AI模型，实现持续优化。

通过这套系统，设计引擎的产出将从“一堆散乱的文件”转变为“结构化、可检索、可复用的数字资产库”，大幅降低资产管理和沟通成本。
