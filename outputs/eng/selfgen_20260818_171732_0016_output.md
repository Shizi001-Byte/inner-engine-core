# 任务类型: eng

## 修复方案：L4 成品转化支持 code / checklist

### 结论先行

L4 目前只实现 `sop` 转化，原因在于：  
- `artifact_type` 的可选值没有开放 `code/checklist`；  
- `convert_to_artifact` 中只有 `_build_sop`，缺少 `_build_code` / `_build_checklist`；  
- 相关认知没有注入，导致后续任务不知道 L4 已支持新类型。

修复思路：**扩展类型注册表 + 实现两个 builder + 配置读点同步开放 + 注入认知闭环**。风险低，且不影响现有 SOP 任务。

---

## 一、代码修改点

### 1. 定义成品类型常量

文件：`l4_converter.py` 或 `constants.py`

```python
class ArtifactType:
    SOP = "sop"
    CODE = "code"
    CHECKLIST = "checklist"
```

### 2. 改造转化入口，使用注册表

原来可能是：

```python
def convert_to_artifact(self, task):
    if task.config.get("artifact_type", "sop") == "sop":
        return self._build_sop(task)
    else:
        raise UnsupportedArtifactType(...)
```

改为：

```python
def convert_to_artifact(self, task):
    artifact_type = task.config.get("artifact_type", ArtifactType.SOP)

    builder = self._builders.get(artifact_type)
    if not builder:
        raise UnsupportedArtifactType(f"L4 不支持的成品类型: {artifact_type}")

    return builder(task)
```

在 `__init__` 中注册：

```python
self._builders = {
    ArtifactType.SOP: self._build_sop,
    ArtifactType.CODE: self._build_code,
    ArtifactType.CHECKLIST: self._build_checklist,
}
```

### 3. 实现 `_build_code`

需要产出包含代码、语言、运行方式、测试用例的结构化成品：

```python
def _build_code(self, task):
    result = task.result

    code_block = result.get("code") or result.get("content")
    language = result.get("language", "python")
    runtime = result.get("runtime", "python3")
    entrypoint = result.get("entrypoint", "main.py")
    dependencies = result.get("dependencies", [])

    # 如果需要模型生成代码，必须设置超时：
    # B 模型 turbo 用 300 秒，A 模型用 600 秒
    timeout = 600 if task.model == "A" else 300
    if not code_block and task.need_generate:
        code_block = self._call_llm(task, timeout=timeout)

    return {
        "artifact_type": ArtifactType.CODE,
        "task_id": task.task_id,
        "language": language,
        "runtime": runtime,
        "entrypoint": entrypoint,
        "code_block": code_block,
        "dependencies": dependencies,
        "test_cases": result.get("test_cases", []),
        "created_at": now(),
    }
```

### 4. 实现 `_build_checklist`

将任务结果转化为可执行的清单：

```python
def _build_checklist(self, task):
    result = task.result
    raw_items = result.get("checklist") or result.get("items") or []

    items = []
    for idx, item in enumerate(raw_items, start=1):
        items.append({
            "id": idx,
            "content": item.get("content", item),
            "required": item.get("required", True),
            "owner": item.get("owner", task.owner),
            "status": item.get("status", "pending"),
        })

    return {
        "artifact_type": ArtifactType.CHECKLIST,
        "task_id": task.task_id,
        "title": result.get("title", task.title),
        "items": items,
        "total": len(items),
        "created_at": now(),
    }
```

### 5. 修改配置读取点 / 校验点

只改 builder 不够，必须同步修改所有读取 `artifact_type` 的地方：

- 任务配置 schema：  
  将 `artifact_type` 的枚举从 `["sop"]` 改为 `["sop", "code", "checklist"]`。

- 数据库或配置中心如果存了枚举类型，需要同步迁移：

```sql
ALTER TABLE task_config
MODIFY COLUMN artifact_type ENUM('sop','code','checklist') NOT NULL DEFAULT 'sop';
```

- 全局搜索 `artifact_type`，确认没有其他地方硬编码只允许 `sop`。

### 6. 注入认知，形成闭环

L4 修复后，需要把“L4 支持 code/checklist”这个认知写入认知池，并且后续任务要实际引用它：

```python
cognition_pool.add({
    "type": "l4_supported_artifact",
    "content": "L4 成品转化支持 sop/code/checklist",
    "source": "L4Converter",
    "timestamp": now(),
    "used_count": 0,
})
```

在 `convert_to_artifact` 中主动读取这条认知并记录使用：

```python
cognition = cognition_pool.get("l4_supported_artifact")
if cognition:
    cognition.mark_used(task_id=task.task_id)
```

这样避免“认知池堆了 1700+ 条，但从不参与任务”的问题。

## 二、验证方法

### 1. 单元测试

新增 `tests/test_l4_converter.py`：

```python
def test_build_code():
    task = create_task(artifact_type="code", result={"code": "print('hi')"})
    artifact = converter.convert_to_artifact(task)
    assert artifact["artifact_type"] == "code"
    assert artifact["code_block"] == "print('hi')"

def test_build_checklist():
    task = create_task(
        artifact_type="checklist",

    )
    artifact = converter.convert_to_artifact(task)
    assert artifact["artifact_type"] == "checklist"
    assert artifact["total"] == 2

def test_sop_remain_compatible():
    task = create_task(artifact_type="sop", result={...})
    artifact = converter.convert_to_artifact(task)
    assert artifact["artifact_type"] == "sop"
```

### 2. 集成验证

- 构造一个 `artifact_type="code"` 的任务，执行 L4 转化，确认产物写入输出目录。
- 构造一个 `artifact_type="checklist"` 的任务，执行 L4 转化，确认清单字段完整。
- 构造一个旧 `artifact_type="sop"` 任务，确认无回归。

### 3. 认知闭环验证

修复后跑 2 个新任务：

- 第 1 个任务使用 `code` 类型，生成成品。
- 第 2 个任务应引用到认知 `l4_supported_artifact`，并更新 `used_count`。

检查指标：

```text
近30分钟新增认知中被后续任务实际引用的条数 / 近30分钟新增认知总数
```

应大于 0，且 L4 相关认知的 `last_used_at` 被刷新。

## 三、避坑提醒

1. **配置修改后必须同步修改读取点**  
   我已标记 `artifact_type` 的所有读取点，包括 schema、DB 枚举、builder 注册表，确保修改后立即生效。

2. **API 调用必须设超时**  
   如果 `_build_code` 需要调用模型生成代码，超时设置为：  
   - B 模型 turbo：300 秒  
   - A 模型：600 秒  
   避免任务卡死或超时返回。

3. **不要变成静态档案库**  
   修复后主动把新能力注入认知池，并在后续 L4 转化中读取引用，保证认知参与调度。

---

风险等级：**low**  
影响面：仅 L4 成品转化层，不涉及任务调度主流程；SOP 默认行为保持不变。
