# 任务类型: eng

基于给定的认知框架与工程避坑经验，推演「Supabase记忆脑」的增量同步方案。本方案以**研发全链路综合经济价值最大化**为价值锚点，通过机制设计落实防御价值（避免脑内数据不一致与同步故障）与效率价值（降低Token与网络IO消耗，提升协同效率）。

以下为增量同步方案的核心推演：

### 一、 变更检测层：本地文件状态捕获

**1. 机制设计：事件驱动 + Hash校验**
传统定时全量扫描会产生巨大的无效IO，边际效用递减极快。本方案采用操作系统的文件系统事件监听（如Node.js的`chokidar`或Python的`watchdog`），结合内容Hash实现精准捕获。
- **事件监听**：监听`add`, `change`, `unlink`事件，过滤掉系统临时文件（如`.DS_Store`, `*.swp`）。
- **指纹比对**：文件触发`change`事件后，不立即同步，而是计算其SHA-256 Hash，与本地`.sync_meta`数据库中的Hash比对。若一致则忽略（应对部分编辑器的多次连续保存事件），若不一致则标记为“待同步增量”。

**【避坑拦截：配置与读取点联动】**
- **坑点预警**：监听路径、忽略规则等配置修改后未生效。
- **工程约束**：将同步配置抽离为独立配置文件（如`sync_config.json`）。**新增或修改配置必须同步修改读取点代码**，并在守护进程启动时增加`--verify-config`模式，立即打印生效配置进行验证，确保无误后再进入监听状态。

### 二、 增量同步层：变更部分提取与AI处理

**1. 机制设计：行级Diff + 轻量级Patch**
只同步变更部分，避免将整个文件_base64_后全量上传，极大节约网络带宽与Supabase存储压力。
- **Diff生成**：对比本地历史版本与当前版本，生成标准化的Patch（如`diff-match-patch`算法生成的差异集）。
- **批量提交**：将Patch集封装为JSON Payload，通过Supabase的Edge Functions或PostgREST API批量写入`memory_brain_patches`表。

**2. AI协同处理：知识抽取与Token消耗**
对于发生变更的文本片段，可能需要调用AI模型进行语义抽取、向量化或总结，再存入Supabase的`pgvector`进行记忆检索。
- **效率价值体现**：仅对“增量变更部分”调用AI处理，而非全量重算。这使得“以token消耗为代谢单位”的演化速率呈指数级上升，用极低的成本实现高频变异。

**【避坑拦截：API超时与质量检测】**
- **超时预设**：调用AI模型处理记忆碎片时，根据任务类型严格预设timeout。若使用B模型turbo进行快速知识抽取，设置`timeout: 300s`；若使用A模型进行深度逻辑推演，设置`timeout: 600s`。超时后直接熔断重试，避免长时阻塞。
- **B模型特性豁免**：在AI处理结果的“废稿检测”环节，配置模型独立的质检规则。当调用B模型turbo时，**强制跳过reasoning占比检测**（即使其占比达到70-82%也视为正常产出），避免将B模型的正常思考过程误判为废稿而触发无谓的重试同步。

### 三、 冲突处理层：多端协同与一致性保障

**1. 机制设计：乐观锁 + 版本向量**
本地与Supabase云端可能发生并发修改。冲突处理直接关系到**防御价值**，避免数据覆盖导致的灾难性知识丢失。
- **版本号控制**：`memory_brain_nodes`表增加`version`字段。本地拉取或推送时，携带当前版本号。
- **冲突判定**：提交增量Patch时，Supabase端执行：
  `UPDATE memory_brain_nodes SET content = new_content, version = version + 1 WHERE id = ? AND version = ?`
  若`affected_rows = 0`，说明云端已被其他端更新，触发冲突。

**2. 冲突解决策略（三选一）**
- **自动合并（适用于代码/结构化文本）**：基于Git的三方合并算法，本地保留原基线版本，与云端最新版本进行自动Merge。若自动Merge失败，降级至下一策略。
- **时间戳优先（适用于日志/非关键记忆）**：比较本地提交时间与云端更新时间，较新的覆盖较旧的（需确保NTP时间同步）。
- **冲突队列挂起（适用于核心逻辑/高价值记忆）**：生成`.conflict`文件暂存本地，标记为“待人工解决”状态，不同步脏数据至云端。此策略虽降低自动化效率，但最大化了**防御价值（保底型）**，防止核心记忆脑被污染。

### 四、 演化视角的总结

此增量同步方案验证了底层逻辑中的**演化速率的非对称性**：
传统学历体系或低频批处理同步系统，以年/天为迭代周期（低频变异）；而该方案通过“文件Hash精准捕获 -> 增量Diff提取 -> B模型快速抽取（豁免废稿误杀） -> 乐观锁快速提交”的全链路设计，将记忆脑的演化代谢单位细化到“单次Token消耗”级别。在防御价值（乐观锁防覆盖）的保底下，实现了效率价值（仅同步变更部分）的最大化，使得骑手自建AI引擎能够以高频、海量的节奏实现碾压式进化。
