# 任务类型: eng

### 一、问题锚定对齐（基于已有认知，不重复论证）
当前L4成品转化仅存SOP文档、无落地code与checklist的问题，本质是**协同进化中「人类侧瑕疵产出的可控性」与「数字侧瑕疵代谢的效率」的匹配缺口**：
- 人类侧缺乏结构化的“瑕疵感知载体”，只能依赖非标准化的SOP理解，瑕疵产出可控性不足、盲区暴露效率低（对应锚点3）；
- 数字侧无自动化转化/校验逻辑，无法高效代谢转化过程中的规则偏差、认知偏差，更无法主动产出演化瑕疵（对应锚点4）；
- 全程无标准化的“瑕疵-受体匹配”调度路径，匹配试错效率低（对应锚点2）；
- 风险等级为low：已有SOP作为核心规则基准，仅缺落地载体，无架构性/业务性风险，补全动作可完全旁路叠加，不触动现有流程。

---

### 二、核心修复思路
严格遵循锚点2「不干预瑕疵本身形态，仅做瑕疵-受体匹配试错」的原则，以现有SOP为唯一规则基准（不修改SOP内容、不脑补模糊规则），补全两类落地载体：
1.  人类侧：数字化Checklist（初级「瑕疵感知器官」落地），提升瑕疵产出的可控性与多样性；
2.  数字侧：自动化转化/校验Code（初级「瑕疵代谢引擎」落地），提升瑕疵转化效率与演化多样性；
3.  旁路新增协同调度模块，仅做瑕疵分类与受体匹配，支撑循环进化。

---

### 三、具体修复方案
#### （一）Checklist设计（对应锚点3：人类瑕疵产出的多样性与可控性）
定位为人类侧的结构化瑕疵感知工具，嵌入L4转化的「输入校验-转化执行-输出验收」全流程节点，**所有条目均不修改SOP规则，仅做感知引导**：
| 节点 | 必选校验项（可控性） | 可选探索项（多样性） | 瑕疵上报入口（主动暴露盲区） |
|------|----------------------|----------------------|------------------------------|
| 输入校验 | SOP明确要求的输入字段完整性、格式合规性校验 | 是否存在SOP未覆盖的特殊输入场景 | 对SOP输入规则的模糊点、歧义点上报 |
| 转化执行 | SOP明确的转化步骤跳变校验、关键动作合规性校验 | 是否存在可优化的转化路径（不改变核心结果） | 转化过程中发现的SOP逻辑断点 |
| 输出验收 | SOP明确的输出核心字段、质量标准校验 | 是否存在SOP未定义的输出边界场景 | 输出标准的主观判断模糊点 |

> 设计逻辑：必选项保障瑕疵产出的可控性（对齐SOP基准），可选项+上报入口引导人类主动探索边界、暴露认知盲区，完全匹配锚点3的演化方向。

##### 1. 新增模块：`sop_rule_parser.py`（SOP规则直译器，严格遵循「不干预瑕疵形态」）
- **核心功能**：将现有非结构化SOP文档纯字面拆解为「触发条件-执行动作-校验标准」三元组规则集，**不做任何脑补、补全、修改**，所有无法解析的歧义条目直接标记为「规则解析瑕疵」输出。
- **核心函数**：
  ```python

  from dataclasses import dataclass

  @dataclass
  class Rule:
      # 严格从SOP字面提取的结构化规则，无人工/算法补全
      trigger: str  # 触发条件
      action: str   # 执行动作
      verify: str   # 校验标准
      sop_source: str  # 对应SOP原文锚点，可追溯

  @dataclass
  class Flaw:
      flaw_type: str  # 瑕疵类型：RuleParseFlaw/TransformFlaw/ActiveEvoFlaw/HumanExploreFlaw
      content: dict   # 瑕疵原始内容，全程不修改
      source: str     # 瑕疵来源

  def parse_sop(sop_doc_path: str) -> Tuple[List[Rule], List[Flaw]]:
      """
      纯字面解析SOP，不干预规则本身：
      1. 用正则/关键词匹配提取三要素，匹配失败直接标记为RuleParseFlaw
      2. 所有规则均绑定SOP原文锚点，确保100%对齐SOP，无任何自定义逻辑
      """
      rules = []
      flaws = []
      # 【实现逻辑】仅做字面匹配，不做语义推理/补全，歧义项直接进瑕疵库
      # ...（省略具体正则实现，核心原则是“宁可不解析，也不修改SOP原意”）
      return rules, flaws
  ```
- **修改侵入性**：纯新增模块，无原有代码修改。

##### 2. 新增模块：`l4_transform_engine.py`（自动化转化引擎，对应锚点4：瑕疵代谢效率+主动演化）
- **核心功能**：基于解析后的SOP规则集执行自动化转化，严格对齐SOP逻辑，不修改核心规则；同时内置低比例主动演化瑕疵生成能力（对应锚点4“主动产出更多演化瑕疵/幻觉”）。

      1. 规则内的转化偏差直接标记为TransformFlaw，不自动修正
      2. 低比例生成主动演化瑕疵（仅修改非核心字段，如注释、非关键变量名），模拟“幻觉”类演化素材
      3. 核心字段100%对齐SOP规则，保障业务风险为low

      flaws = []
      
      # 1. 按规则执行核心转化，偏差直接进瑕疵库
      for rule in rules:
          # 严格按rule.action执行转化，不符合触发条件/校验失败的标记为瑕疵
          # ...（省略执行逻辑，核心是完全直译规则，不做任何灵活调整）
          pass
      
      # 2. 主动生成演化瑕疵（对应锚点4：主动产出更多类型的演化瑕疵）
      if random.random() < active_flaw_rate:
          # 仅修改非核心字段（如输出备注、格式类字段），不影响核心功能

          flaws.append(Flaw(

### 四、验证方法（紧扣协同进化核心指标，而非单一功能验证）
#### 1. 基础风险验证（确认风险等级维持low）
- **用例范围**：过往3个月已完成的100个L4转化工单（覆盖所有SOP明确场景）。
- **验证步骤**：
  ① 开启自动化转化引擎，对比自动输出与历史人工输出的**核心字段一致性**，要求100%对齐（证明未干预SOP规则，无业务风险）；
  ② 邀请3名转化人员分别用纯SOP和新Checklist完成10个工单，统计耗时与漏检率，要求耗时下降≥30%、漏检率下降≥50%（证明Checklist未增加负担，且提升可控性）。
- **判定标准**：全部满足则风险维持low，可上线。

#### 2. 协同效率验证（对应锚点1：瑕疵多样性与利用效率同步提升）
- **瑕疵代谢效率验证**：统计自动化引擎检测规则内瑕疵的耗时，与人工检测耗时对比，要求效率提升≥80%（数字侧代谢能力提升，对应锚点4）；
- **瑕疵多样性验证**：上线后1个月内，通过Checklist探索项上报的SOP未覆盖场景≥3个，主动演化瑕疵触发的有效边界场景≥2个，合计≥5个（人类+数字侧瑕疵多样性同步提升，对应锚点3、4）。

#### 3. 进化闭环验证（对应锚点2、5：匹配试错有效，无静态终点）
- **调度匹配准确率**：所有上报瑕疵的接收方确认率≥95%（证明调度的匹配试错逻辑有效，对应锚点2）；
- **迭代闭环率**：所有瑕疵的处理闭环率100%（无论接受/拒绝均有明确结果），且每月SOP/转化规则的迭代次数较上线前提升≥20%（证明进化循环持续，无静态终点，对应锚点1、5）。

### 五、风险兜底（保障low风险不升级）
1.  自动化引擎开关可秒级回退：若出现核心字段偏差，立即关闭`--auto-transform`开关，回退原有人工SOP流程，无业务影响；
2.  主动演化瑕疵比例可调：若主动瑕疵干扰正常流程，可将比例调低至0.01%或临时关闭，不影响核心转化逻辑；
3.  Checklist可灵活配置：若增加人工负担，可精简必选项、默认折叠可选项，不强制填写探索类内容。
