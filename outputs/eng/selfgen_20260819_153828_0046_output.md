# 任务类型: eng

## 推演结论

V7.5 的“多线程 API 调用 + 串行后处理”不能只靠一把大锁。  
核心方案是：

> **状态机 + 分片锁 + 单消费者队列 + 版本号/fencing token**

锁只保护临界区，不保护“先后顺序”。  
要保证状态一致性，必须让每个任务有明确状态，并让“API 完成”到“后处理开始”的交接通过线程安全队列完成。

---

## 1. 状态机设计

每个任务必须显式流转：

```text
PENDING
  → API_IN_FLIGHT
  → API_DONE
  → POST_PROCESSING
  → FINISHED

API_IN_FLIGHT
  → FAILED
  → API_DONE（重试时从 FAILED 回到 PENDING）
```

关键规则：

- API 调用线程只能改 `PENDING → API_IN_FLIGHT → API_DONE/FAILED`
- 后处理线程只能改 `API_DONE → POST_PROCESSING → FINISHED/FAILED`
- 禁止跨状态跳跃
- 所有状态变更必须持锁

---

## 2. 锁模型

| 锁/原语 | 保护对象 | 获取者 |
|---|---|---|
| `map_lock` | 任务注册表 `tasks` | 所有线程 |
| `striped_locks` | 单个任务的状态字段 | API 线程、后处理线程 |
| `post_lock` | 串行后处理临界区 | 后处理线程 |
| `queue` | API 结果到后处理的交接 | API 线程 put，后处理线程 get |
| `attempt_id` + `version` | 过期结果/旧请求覆盖新状态 | 逻辑锁，防竞态 |

锁顺序必须固定：

```text
map_lock
  → striped_lock
    → queue.put（非阻塞）
```

后处理线程：

```text
queue.get
  → map_lock
  → post_lock
    → striped_lock
```

API 线程永远不拿 `post_lock`，所以不会死锁。

## 3. 完整代码骨架

```python
import json
import queue
import threading
import urllib.request
import uuid
import zlib
from dataclasses import dataclass, field
from typing import Any, Callable, Optional


class TaskState:
    PENDING = "PENDING"
    API_IN_FLIGHT = "API_IN_FLIGHT"
    API_DONE = "API_DONE"
    POST_PROCESSING = "POST_PROCESSING"
    FINISHED = "FINISHED"
    FAILED = "FAILED"


@dataclass
class Task:
    task_id: str
    state: str = TaskState.PENDING
    version: int = 0
    attempt_id: str = ""
    result: Any = None
    error: str = ""
    retry_count: int = 0
    done_event: threading.Event = field(default_factory=threading.Event)


class StripedLock:
    """分片锁，避免每任务一把锁导致锁对象过多。"""

    def __init__(self, stripes: int = 128):
        self._locks = [threading.Lock() for _ in range(stripes)]

    def get(self, key: str) -> threading.Lock:
        idx = zlib.crc32(key.encode("utf-8")) % len(self._locks)
        return self._locks[idx]


class ArkEngine:
    def __init__(self):
        self.tasks = {}
        self.map_lock = threading.Lock()
        self.striped_locks = StripedLock(128)
        self.queue = queue.SimpleQueue()
        self.post_lock = threading.Lock()
        self.worker_thread: Optional[threading.Thread] = None

    # ---------- 任务注册 ----------

    def create_task(self, task_id: str) -> Task:
        with self.map_lock:
            if task_id in self.tasks:
                raise ValueError(f"task exists: {task_id}")
            task = Task(task_id=task_id)
            self.tasks[task_id] = task
            return task

    # ---------- 多线程 API 调用 ----------

    def submit_api_call(self, task_id: str, api_fn: Callable[[str], Any]) -> None:
        with self.map_lock:
            task = self.tasks[task_id]

        t = threading.Thread(target=self._api_worker, args=(task, api_fn), daemon=True)
        t.start()

    def _api_worker(self, task: Task, api_fn: Callable[[str], Any]) -> None:
        task_id = task.task_id

        # 进入 API 调用状态
        with self.striped_locks.get(task_id):
            if task.state != TaskState.PENDING:
                task.error = f"invalid state: {task.state}"
                task.done_event.set()
                return

            task.state = TaskState.API_IN_FLIGHT
            task.version += 1
            task.attempt_id = uuid.uuid4().hex
            attempt_id = task.attempt_id

        # 注意：这里必须释放锁再调用 API，不能持锁做网络 IO
        try:
            result = api_fn(task_id)

            # 提前拦截空 content，避免后处理拿到空结果
            if result is None or (isinstance(result, str) and not result.strip()):
                raise ValueError("API response content is empty")

        except Exception as e:
            with self.striped_locks.get(task_id):
                # 防止超时旧请求覆盖新请求
                if task.state == TaskState.API_IN_FLIGHT and task.attempt_id == attempt_id:
                    task.state = TaskState.FAILED
                    task.version += 1
                    task.error = f"{type(e).__name__}: {e}"
                    task.done_event.set()
            return

        # API 成功，把任务交给后处理队列
        with self.striped_locks.get(task_id):
            # 只有当前 attempt 仍然有效，才允许写入
            if task.state != TaskState.API_IN_FLIGHT or task.attempt_id != attempt_id:
                return

            task.result = result
            task.state = TaskState.API_DONE
            task.version += 1
            self.queue.put(task_id)

    # ---------- 串行后处理 ----------

    def start_post_processor(self) -> None:
        if self.worker_thread is not None:
            return
        self.worker_thread = threading.Thread(
            target=self._post_processor_loop,
            daemon=True,
        )
        self.worker_thread.start()

    def _post_processor_loop(self) -> None:
        while True:
            task_id = self.queue.get()

            with self.map_lock:
                task = self.tasks[task_id]

            # 串行后处理锁
            with self.post_lock:
                with self.striped_locks.get(task_id):
                    if task.state != TaskState.API_DONE:
                        continue

                    task.state = TaskState.POST_PROCESSING
                    task.version += 1
                    result = task.result

                try:
                    self.handle_post_process(task_id, result)

                except Exception as e:
                    with self.striped_locks.get(task_id):
                        if task.state == TaskState.POST_PROCESSING:
                            task.state = TaskState.FAILED
                            task.version += 1
                            task.error = f"{type(e).__name__}: {e}"
                            task.done_event.set()
                    continue

                with self.striped_locks.get(task_id):
                    if task.state == TaskState.POST_PROCESSING:
                        task.state = TaskState.FINISHED
                        task.version += 1
                        task.done_event.set()

    def handle_post_process(self, task_id: str, result: Any) -> None:
        """子类实现。必须幂等。"""
        raise NotImplementedError

    # ---------- 等待/重试 ----------

    def wait_task_done(self, task_id: str, timeout: Optional[float] = None) -> bool:
        with self.map_lock:
            task = self.tasks[task_id]
        return task.done_event.wait(timeout)

    def retry_task(self, task_id: str) -> None:
        with self.striped_locks.get(task_id):
            task = self.tasks[task_id]
            if task.state != TaskState.FAILED:
                raise ValueError("only FAILED task can retry")

            task.state = TaskState.PENDING
            task.retry_count += 1
            task.version += 1
            task.attempt_id = ""
            task.result = None
            task.error = ""
            task.done_event.clear()
```

## 4. 方舟 API 调用封装

```python
# 统一配置读取点，修改后立即生效，不要在线程里缓存
_CONFIG = {
    "api_key": "YOUR_API_KEY",
    "model_timeout": {
        "B": 300,   # B 模型 turbo：300 秒
        "A": 600,   # A 模型：600 秒
    },
}


def get_timeout(model: str) -> int:
    return _CONFIG["model_timeout"].get(model, 300)


def call_ark_api(model: str, payload: dict) -> str:
    timeout = get_timeout(model)

    # 统一用 urllib 直连，显式禁用全局代理，避免 ProxyError
    opener = urllib.request.build_opener(urllib.request.ProxyHandler({}))

    req = urllib.request.Request(
        "https://ark.cn-beijing.volces.com/api/v3/responses",
        data=json.dumps(payload).encode("utf-8"),
        headers={
            "Content-Type": "application/json",
            "Authorization": f"Bearer {_CONFIG['api_key']}",
        },
    )

    with opener.open(req, timeout=timeout) as resp:
        data = json.loads(resp.read().decode("utf-8"))

    # 检查 Responses API content 是否为空
    outputs = data.get("output") or []
    if not outputs:
        raise ValueError("Responses API output is empty")

    content = outputs[0].get("content")
    if isinstance(content, list):
        content = "".join(
            part.get("text", "") for part in content if isinstance(part, dict)
        )

    if not content:
        raise ValueError("Responses API content is empty")

    return content
```

## 5. 如果业务要求“所有 API 调用完成后，再串行后处理”

上面的方案是“每完成一个 API 就交给后处理”。  
如果你要的是：

> 多线程并发调用 API，全部返回后，再统一做一次串行后处理

那就用 `Condition` 做屏障：

```python
class BatchBarrier:
    def __init__(self, total: int):
        self.total = total
        self.cond = threading.Condition()
        self.results = {}
        self.remaining = total
        self.phase = "API"  # API -> READY -> PROCESSING -> DONE

    def submit(self, index: int, result: Any) -> None:
        with self.cond:
            if self.phase != "API":
                raise RuntimeError("phase changed")

            self.results[index] = result
            self.remaining -= 1

            if self.remaining == 0:
                self.phase = "READY"
                self.cond.notify_all()

    def wait_ready(self) -> dict:
        with self.cond:
            while self.phase != "READY":
                self.cond.wait()

            self.phase = "PROCESSING"
            return dict(self.results)

    def finish(self) -> None:
        with self.cond:
            self.phase = "DONE"
            self.cond.notify_all()
```

使用方式：

```python
def run_batch(api_calls, post_process):
    if not api_calls:
        return

    barrier = BatchBarrier(len(api_calls))
    post_lock = threading.Lock()

    def worker(i):
        try:
            result = api_calls[i]()
            barrier.submit(i, result)
        except Exception as e:
            barrier.submit(i, e)

    threads = [
        threading.Thread(target=worker, args=(i,))
        for i in range(len(api_calls))
    ]

    for t in threads:
        t.start()

    results = barrier.wait_ready()

    # 串行后处理
    with post_lock:
        post_process(results)

    barrier.finish()
```

## 6. 关键避坑映射

| 历史坑 | 本方案怎么避 |
|---|---|
| 全局代理导致 ProxyError | 使用 `urllib.request.ProxyHandler({})`，不走 requests |
| Responses API content 为空 | 在 `call_ark_api` 和 `_api_worker` 双层检查，content 为空直接失败 |
| API 超时 | B 模型 turbo 默认 300s，A 模型默认 600s，通过 `timeout` 传入 |
| 配置修改后不生效 | 配置统一从 `_CONFIG` 读取，不在线程里复制缓存 |
| PID 文件竞态误判 | 使用 `attempt_id` + `version` 作为 fencing token，旧请求不能覆盖新状态 |

---

## 7. 死锁预防清单

1. **绝不持锁调用外部 API**
2. **绝不持锁等待队列 put**
3. 使用 `queue.SimpleQueue` 或 `put_nowait`，避免入队阻塞
4. 锁顺序固定：`map_lock → striped_lock`，不反向
5. 后处理线程持 `post_lock` 时，不等待 API 线程
6. `handle_post_process` 必须幂等，防止重复处理

最终一句话：

> 并发是阳，串行是阴；锁不是限制并发，而是让并发后的状态有序落地。
