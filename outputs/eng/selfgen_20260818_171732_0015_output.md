# 任务类型: eng

风险等级：**medium**  
原因是：该方案会修改“上下文构造 → 模型调用 → 输出校验 → 认知回写”的核心链路，影响面较大，但通过开关、限流和可回退设计可以控制风险。

---

## 一、问题定位

从「认知质检 SOP」视角看，「产出同质化、套话多」的本质是：

1. **认知不新鲜**：认知池堆到 1700+ 条，但新认知从不注入任务，模型看到的永远是旧模板，自然只能输出套话。
2. **闭环不开放**：输出没有反向影响认知池的排序和选择，认知池变成静态档案库。
3. **调用不设限**：缺少“必须引用具体认知/数据”的约束，模型默认使用安全但空洞的表达。

所以修复方向不是“再加认知”，而是**让认知流动起来，并强制输出引用新鲜认知**。

---

## 二、修复方案总览

增加 4 个机制：

1. **认知注入器**：任务开始前，从认知池抓取“近 30 分钟新增认知 + 任务相关认知”，注入 prompt。
2. **强制引用约束**：prompt 中要求输出至少引用 1 条新认知，并标注来源编号。
3. **反套话输出校验器**：检测固定套话，命中后触发改写。
4. **调度闭环回写**：每 10 个任务或每轮调度结束，刷新认知缓存，并将引用情况回写认知池，调整后续排序。

## 三、具体代码修改点

### 1. `cognitive_store.py`

新增“获取新鲜且相关认知”的方法：

```python
def fetch_fresh_and_relevant(self, task_meta, minutes=30, limit=8):
    cutoff = datetime.now() - timedelta(minutes=minutes)

    fresh = self.query("""
        SELECT * FROM cognitive_pool
        WHERE created_at >= :cutoff
        ORDER BY created_at DESC
        LIMIT 5
    """, {"cutoff": cutoff})

    relevant = self.query("""
        SELECT * FROM cognitive_pool
        WHERE tags MATCH :tags
        ORDER BY last_cited_at ASC, relevance_score DESC
        LIMIT 5
    """, {"tags": task_meta.get("tags", "")})

    merged = dedup(fresh + relevant)
    return merged[:limit]
```

同时新增回写方法：

```python
def record_citations(self, task_id, cited_ids):
    for cid in cited_ids:
        self.query("""
            UPDATE cognitive_pool
            SET last_cited_at = :now, cited_count = cited_count + 1
            WHERE id = :cid
        """, {"now": datetime.now(), "cid": cid})
```

### 2. `context_builder.py`

在构建 prompt 时注入认知：

```python
def build_context(task):
    base_prompt = load_base_template()

    fresh_cognitions = cognitive_store.fetch_fresh_and_relevant(
        task_meta=task.meta
    )

    cognition_block = "【本轮必读认知】\n"
    for i, item in enumerate(fresh_cognitions, 1):
        cognition_block += f"[C{i}] {item.content}\n"

    task_context = base_prompt + cognition_block + """

【输出约束】
- 必须引用上面【本轮必读认知】中的至少 1 条，并用 [C1]/[C2] 标注。
- 禁止使用“综上所述”“需要注意的是”“赋能”“抓手”“颗粒度”等空泛套话。
- 如果本轮没有可用新认知，则必须基于任务原始数据中的具体数字、事实或案例回答。
"""

    return task_context
```

### 3. `task_runner.py`

在任务处理主循环中加入刷新和校验：

```python
class TaskRunner:
    def run(self, task):
        # 每 10 个任务刷新认知缓存
        if self.processed_count and self.processed_count % 10 == 0:
            cognitive_store.refresh_cache()
            self.freshness_ratio = cognitive_store.report_freshness_ratio()

        # 构建带认知注入的上下文
        context = context_builder.build_context(task)

        # 模型调用超时仍按模型类型设置
        timeout = 300 if task.model_type == "B_turbo" else 600
        output = llm.call(context, timeout=timeout)

        # 反套话校验，失败则改写一次
        if not output_validator.is_acceptable(output):
            output = llm.call(
                context + "\n你刚才的输出包含套话，请用上面认知中的具体内容改写，禁止出现固定套话。",
                timeout=timeout,
            )

        # 回写引用记录，形成闭环
        cognitive_store.record_citations(task.id, extract_cited_ids(output))

        self.processed_count += 1
```

### 4. `output_validator.py`

新增反套话校验器：

```python
CLICHE_PHRASES = [
    "综上所述",
    "需要注意的是",
    "赋能",
    "抓手",
    "颗粒度",
    "进一步优化",
    "持续提升",
]

def is_acceptable(text):
    hit_count = sum(1 for p in CLICHE_PHRASES if p in text)

    # 命中 2 个以上固定套话则判定不合格
    if hit_count > 2:
        return False

    # 也可以和最近 20 条输出算 self-BLEU，过高则判定重复
    if self_bleu(text, recent_outputs) > 0.7:
        return False

    return True
```

### 5. `scheduler.py`

每轮调度结束时刷新认知池：

```python
def end_round(self):
    cognitive_store.refresh_cache()
    cognitive_store.compute_freshness_ratio()
    # 如果新鲜度比例过低，开启“认知饥渴模式”
    if cognitive_store.freshness_ratio < 0.3:
        context_builder.set_require_citation_count(2)
```

## 四、验证方法

### 1. 单元测试

- 构造 10 条近 30 分钟新增认知，执行 1 个任务，断言输出中包含 `[C1]` 或 `[C2]`。
- 断言输出中不包含“综上所述”“赋能”等套话。
- 模拟任务数达到 10，断言 `refresh_cache()` 被调用。
- 模拟认知池中新增认知全部未被引用，断言 `freshness_ratio` 被记录且低于阈值。

### 2. 集成测试

取 50 个历史任务，分别用旧链路和新链路生成输出，对比：

- 旧链路“套话命中率”预计 > 30%；
- 新链路“套话命中率”应 < 5%。

同时计算两组的 self-BLEU：

- 旧链路输出彼此相似度高；
- 新链路输出应明显下降，说明多样性提升。

### 3. 核心指标验证

上线后重点观察两个指标：

```text
认知新鲜度 = 近30分钟新增认知中被后续任务实际引用的条数 / 近30分钟新增认知总数
```

目标：从接近 0 提升到 **> 0.6**。

```text
套话命中率 = 含2个及以上套话词的输出数 / 总输出数
```

目标：从基线值降到 **< 5%**。

### 4. 灰度对比

建议按 10% 流量灰度 1 天，对比灰度组和对照组：

- 输出多样性；
- 人工评审通过率；
- 任务平均耗时；
- 模型调用超时率。

确认无异常后逐步放量。

---

## 五、风险与兜底

| 风险 | 缓解措施 |
|---|---|
| 强制引用新认知导致内容偏离主题 | 只注入高置信度认知；没有可用认知时允许回答“当前认知不足” |
| 反套话校验误伤 | 只拦截高频固定套话；触发后仅重写一次，不无限循环 |
| 认知刷新增加耗时 | 异步刷新；刷新失败时保留旧缓存，并记录告警 |
| 模型调用超时 | 继续按模型类型设置超时：B 模型 turbo 用 300 秒，A 模型用 600 秒 |

---

这个方案直接解决“认知不新鲜”和“闭环不开放”两个根因，通过“注入 → 强制引用 → 反套话校验 → 回写”形成闭环，能有效降低套话率，提升产出多样性。
