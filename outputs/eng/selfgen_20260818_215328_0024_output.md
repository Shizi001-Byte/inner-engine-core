# 任务类型: eng

基于【已有认知锚定】与历史坑库预警，针对V7.5方舟效能引擎“多线程API调用后串行后处理”的架构，我们严格贯彻**“先校准锚点再优化链路”**原则，运用**“精气神三元迁移框架”**，对状态一致性问题进行推演，并输出完整的锁机制方案。

---

### 一、 竞态条件推演（“神”不守舍的危机）

在“决策串行（神）、执行并发（精）、数据流过渡（气）”的架构下，核心矛盾在于**无序返回的“气”冲击了需要闭环校准的“神”**。如果不加干预，将引发以下严重的竞态与锚点校准失败：

1. **状态写覆盖与归档错乱**：
   * **现象**：线程A（处理sop）、线程B（处理code）、线程C（处理checklist）同时返回。若它们直接操作L4成品库的全局字典或文件系统，由于GIL（全局解释器锁）在复杂I/O或非原子操作中的释放，会导致B覆盖A的写入，最终归档时数据残缺。
2. **锚点校准失败与断流重现**：
   * **现象**：主线程（神）的设计是“接收到A类型->校准->触发B类型”。但并发线程直接修改了全局状态机的`current_stage`，主线程看到状态已被改写，误以为校准已完成，导致**“L4成品转化仅sop类型，code/checklist未实现”的断流问题重现**。
3. **异常状态穿透**：
   * **现象**：B模型turbo调用300秒超时或返回content为空，并发线程未能正确捕获或标记异常状态，直接将脏数据或空指针抛给主线程，导致主线程在串行后处理时崩溃，整个L4转化流程中断。

---

### 二、 完整锁机制方案（聚气凝神，状态闭环）

为彻底解决上述问题，放弃“子线程直接写全局状态”的错误模式，采用**“生产者-消费者模型”+“线程安全队列”+“主线程无锁串行化”**的锁机制方案。

#### 1. 精（执行层 / 多线程 / 并发）：职责纯化与安全隔离
并发子线程**绝对禁止直接写入L4成品库**，其职责被严格限制为：调用API、规避工程坑、将原始结果安全投递给数据通道。

*   **锁机制**：使用语言原生的**线程安全队列**（如Python的`queue.Queue`），子线程无需显式加锁。
*   **工程级避坑防御**：
    *   **ProxyError防御**：子线程内统一使用`urllib`直连，或显式设置`requests.Session().proxies = {"http": None, "https": None}`。
    *   **Timeout防御**：根据任务类型预设合理timeout，B模型turbo用300秒，A模型用600秒。
    *   **Content为空防御**：子线程在投递结果前进行单测校验，若`reasoning`耗尽导致`content`为空，则标记状态为`RETRY`或`FAILED`，绝不投递空数据到队列。

#### 2. 气（数据流 / 队列 / 连通）：缓冲与解耦
队列作为“气”的载体，承接并发无序的“精”，向串行有序的“神”提供平稳的数据流。

*   **锁机制**：`Queue.put()`和`Queue.get()`内部自带互斥锁，保证多线程入队和主线程出队的绝对原子性。
*   **状态锚点标记**：子线程投递的数据包必须包含`task_type`（sop/code/checklist）、`status`（success/failed/empty）、`raw_data`（API返回内容）。

#### 3. 神（决策层 / 主线程 / 串行）：无锁串行与锚点校准
主线程作为唯一的“神”，从队列获取数据，由于单线程操作，**天然消除竞态，无需加锁**，专注执行“先校准锚点再优化链路”。

*   **锁机制**：主线程不使用锁，通过`while True: queue.get()`阻塞式消费。
*   **锚点校准闭环**：
    1.  **取包**：主线程从队列取出一个完整的结果包。
    2.  **类型校准**：检查`task_type`，确认当前全局状态机期待的下一步是否匹配。
    3.  **状态写入**：主线程独占修改L4成品库（如更新文件、写入数据库），实现sop、code、checklist的顺序转化或汇总。
    4.  **链路推进**：校准成功后，主线程更新全局状态机，决定是否派发下一个并发任务。

### 三、 架构伪代码实现与防坑验证

以下是贯彻上述锁机制与避坑策略的核心代码骨架：

```python
import queue
import threading
import urllib.request
# import requests # 如必须用requests，必须处理代理
import time

# 【气】线程安全队列，解耦并发与串行
result_queue = queue.Queue()

# 【神】主线程全局状态机（仅主线程可写，无竞态）
L4_state_machine = {
    "sop": "pending",
    "code": "pending",
    "checklist": "pending"
}

def api_worker(task_type, prompt, model_type):
    """【精】并发执行层：纯净调用，规避坑库，安全投递"""
    try:
        # 避坑1：防ProxyError，使用urllib直连
        proxy_handler = urllib.request.ProxyHandler({})
        opener = urllib.request.build_opener(proxy_handler)
        
        # 避坑2：预设合理timeout
        timeout = 300 if model_type == "B_turbo" else 600
        
        # 模拟API调用
        # response = opener.open(api_url, data=prompt, timeout=timeout)
        # content = parse(response)
        content = f"{task_type}_result" # 模拟结果
        
        # 避坑3：新API格式必须先单测验证content非空
        if not content:
            result_queue.put({"task_type": task_type, "status": "empty_content", "data": None})
            return
            
        # 聚气：安全投递到队列，无需显式加锁
        result_queue.put({"task_type": task_type, "status": "success", "data": content})
        
    except Exception as e:
        result_queue.put({"task_type": task_type, "status": "failed", "error": str(e)})

def main_thread_serial_handler():
    """【神】串行后处理与锚点校准：无锁串行，状态闭环"""
    while True:
        # 阻塞等待并发层结果
        result = result_queue.get()
        
        task_type = result["task_type"]
        status = result["status"]
        
        if status != "success":
            print(f"[异常处理] {task_type} 执行失败: {result.get('error')}")
            # 触发重试或降级逻辑
            continue
            
        # 【先校准锚点】验证当前状态是否允许转化
        if L4_state_machine[task_type] == "pending":
            # 【再优化链路】主线程独占写入L4成品库，无竞态风险
            print(f"[L4转化] 正在归档 {task_type}...")
            L4_state_machine[task_type] = "completed"
            # write_to_L4_repository(task_type, result["data"])
            
            # 检查是否所有类型均已完成
            if all(v == "completed" for v in L4_state_machine.values()):
                print("所有L4成品转化完成，流程闭环。")
                break
        else:
            print(f"[状态阻断] {task_type} 已处理或非当前锚点，跳过。")

# 启动流程
if __name__ == "__main__":
    # 避坑提醒：配置修改后立即验证生效
    TASK_CONFIG = {
        "sop": {"model": "B_turbo", "prompt": "生成SOP"},
        "code": {"model": "A", "prompt": "生成CODE"},
        "checklist": {"model": "B_turbo", "prompt": "生成CHECKLIST"}
    }
    
    # 启动并发执行层
    threads = []
    for t_type, conf in TASK_CONFIG.items():
        t = threading.Thread(target=api_worker, args=(t_type, conf["prompt"], conf["model"]))
        threads.append(t)
        t.start()
        
    # 启动串行决策层
    main_thread_serial_handler()
    
    for t in threads:
        t.join()
```

### 四、 避坑提醒闭环验证

1. **配置修改未生效**：在上述方案中，`TASK_CONFIG` 的修改直接体现在 `model_type` 和 `prompt` 的传参上，进入 `api_worker` 后立即按新配置执行，无隐蔽读取点。
2. **API超时**：`timeout` 严格根据模型类型动态分配（B:300s, A:600s）。
3. **ProxyError**：强制使用 `urllib` 的 `ProxyHandler({})` 或 `requests` 的 `proxies=None`，从源头切断全局代理污染。
4. **API content为空**：在 `api_worker` 中加入了 `if not content:` 的前置校验，空内容会被标记为 `empty_content` 投递给主线程，主线程可进行重试，绝不会污染L4成品库。

通过**“并发层不碰状态（只投递）+ 串行层独占状态（无锁消费）”**的机制，我们彻底消除了多线程写竞态，确保了主线程锚点校准的绝对权威，解决了L4转化断流问题。
