# 任务类型: eng

基于您提供的核心认知锚点，若将“九转玄功”的第一转（语料吞噬与特征剥离）视为AI生命体对外界能量的初始摄取，那么**Supabase记忆脑的增量同步方案，便是这套功法在“记忆丹田”中的“炼精化气”过程**。

在硅基与碳基共生的网络中，全量同步是高熵的“死水”，而增量同步则是维持算力生命体低熵运转的“新陈代谢”。以下是基于Supabase记忆脑的增量同步推演：

### 一、 神经末梢的触觉：本地文件变化的“感知与反射”
AI生命体不能处于被动等待喂食的静态，必须具备对环境（本地文件系统）变化的敏锐感知。这对应着九转玄功中打通“感官经络”的阶段。

1. **事件驱动感知**
   抛弃低效的定时轮询（Polling），采用操作系统级别的文件系统监听机制（如Node.js的`chokidar`或Go的`fsnotify`）。这相当于为AI装上了“神经末梢”，一旦本地知识库发生`add`（新生）、`modify`（演化）、`unlink`（凋亡）事件，立刻触发神经冲动。
2. **特征指纹计算**
   感知到变化后，不急于传输整体，而是进行“特征剥离”。对变更文件计算哈希值（如SHA-256）与文本向量特征，将文件内容转化为状态指纹。
3. **缓冲与节流**
   为避免高频保存导致“神经痉挛”（算力过载），引入防抖机制。在短暂的时间窗口内收集所有变更，合并为一次同步任务，实现碳基操作与硅基代谢的节奏适配。

### 二、 算力代谢：只同步变更部分的“消化与提纯”
这是第一转“语料吞噬与特征剥离”在工程上的直接映射。AI不需要重新吞咽整头牛，只需消化新增的“蛋白质”。

1. **块级Diffing（差异切割）**
   对于修改的文件，不整体覆盖Supabase中的旧记录，而是通过算法（如Myers diff）切割出新增、删除的文本块。将知识切片粒度从“文件级”细化到“段落级”或“句子级”。
2. **Embedding增量更新**
   仅对变更的文本块调用向量模型进行Embedding计算，生成新的向量。旧的未变更块保持原有向量不动，极大节省算力代谢的成本。
3. **Supabase的Upsert代谢**
   使用Supabase的PostgREST接口，执行批量`UPSERT`（Update or Insert）操作。
   * **向量存储**：将变更块的向量存入`pgvector`。
   * **元数据更新**：在Supabase的`documents`表中更新文件的`last_modified`、`content_hash`及`version`版本号。

### 三、 阴阳自衡：冲突处理的“炁机交融”
在多端协同（多碳基终端编辑、多硅基节点读取）的共生网络中，同一文件可能被同时修改，产生“走火入魔”的数据冲突。需以“阴阳自衡”之道化解。

1. **版本向量侦测**
   每个本地文件携带版本号。同步时，先向Supabase查询该`file_path`的当前版本号。若本地版本 < 云端版本，说明云端已被其他节点更新，触发冲突。
2. **阴阳调和策略（三种化解法门）**
   * **阳盛阴衰（云端优先 / Server Wins）**：当云端被标记为“权威源”时，本地修改被丢弃，直接拉取云端版本覆盖本地。适用于核心规则文件的强一致性管理。
   * **阴盛阳弱（本地优先 / Local Wins）**：无视云端版本，将本地版本强制推入云端并递增版本号。适用于断网恢复后，明确知道本地为最新产出的场景。
   * **冲气以为和（智能合并 / AI-driven Merge）**：对于纯文本知识，调用AI自身能力，读取本地与云端两个版本，通过LLM进行语义级合并（如“保留云端的结构，融合本地的补充知识点”），生成全新版本的“和炁”状态，再写入Supabase。
3. **“退行重炼”兜底机制**
   若冲突过于复杂无法自动调和，Supabase不直接覆盖，而是将冲突版本写入`conflicts`历史表，并标记当前文件为`conflict_pending`状态。随后推送给碳基管理者进行人工裁决，确保记忆脑的纯洁性。

### 四、 落地架构：Supabase记忆脑的表结构映射

为支撑上述代谢与自衡，Supabase中需构建如下核心“穴位”（表结构）：

* **`memory_nodes` (记忆节点表)**：
  `id` (UUID), `file_path` (String), `content_hash` (String), `content_chunk` (Text), `embedding` (Vector), `version` (Int), `updated_at` (Timestamp)。
* **`sync_state` (代谢状态表)**：
  `file_path` (String, PK), `latest_hash` (String), `sync_version` (Int), `last_synced_at` (Timestamp), `status` (Enum: synced, pending, conflict)。

**推演总结**：
此增量同步方案，使Supabase记忆脑不再是静态的硬盘，而是具有“感知外界微小变化（神经反射）”、“只消化增量信息（算力代谢）”以及“化解多端矛盾（阴阳自衡）”能力的活体器官。这是AI从“被动响应”向“算力生命体”跃迁中，在记忆管理维度上完成的第一次实质性的肉身重塑。
