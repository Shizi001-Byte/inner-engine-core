# 任务类型: eng

基于【已有认知锚定】与历史坑库预警，针对V7.5方舟效能引擎“多线程API调用后串行后处理”的架构，在推演Supabase记忆脑的增量同步方案时，必须严格贯彻**“先校准锚点再优化链路”**原则，运用**“精气神三元迁移框架”**解决无序返回的“气”对闭环校准的“神”的冲击。

以下为Supabase记忆脑增量同步方案推演：

### 一、 锚点校准（精：资源层 / 数据态 / L4成品库）

在执行并发同步前，必须先确立唯一的最终归档地与基准态，切断数据流的越权侵入。

1. **Supabase作为L4成品库（唯一真源）**：所有本地文件的最终记忆态以Supabase库中的记录为准，本地文件仅为“气”（过渡态）的载体。
2. **配置校验（避坑1落地）**：
   - 新增同步配置（如`watch_path`、`supabase_url`、`冲突解决策略`）必须同步写入读取点。
   - **立即验证**：配置修改后，立即执行一次空跑测试，确认文件监听器已正确读取新路径且Supabase连接通畅，杜绝“配置修改未生效”现象。

### 二、 气流转并发（气：数据流过渡 / 异步监听与差异提取）

执行并发处理无序返回的文件变更，但不能直接写入L4，需经“气”的缓冲与隔离。

1. **本地文件变化检测（异步监听）**：
   - 使用文件系统监听器（如Node.js的`chokidar`或Python的`watchdog`），捕捉`add`/`change`/`unlink`事件。
   - 事件触发后，不立即同步，而是将变更文件路径推入**内存缓冲队列**，并进行防抖处理，避免高频保存导致“气”流溢出。
2. **并发差异提取（只同步变更部分）**：
   - 消费队列中的文件路径，**多线程并发**读取本地文件内容并计算哈希值（如SHA-256）。
   - 并发调用Supabase API查询该文件路径对应的最新哈希值。
   - **避坑2落地（API超时控制）**：若在同步过程中触发AI模型（如调用B模型生成文件摘要或向量化），必须严格预设timeout：**B模型turbo用300秒，A模型用600秒**，防止API调用超时阻塞同步流程。
   - 比对哈希值，若一致则丢弃（无变更），若不一致则提取差异内容（Diff），打上时间戳与版本号。
3. **坑库预警落地（废稿检测误杀防范）**：
   - 若在差异提取阶段调用B模型(turbo)生成记忆摘要或分析，**必须跳过reasoning占比检测**。
   - B模型reasoning占比达到70-82%是其正常特性，不能因为思维链过长将其判定为废稿触发自动重试，否则会导致同步任务无限循环或丢失有效记忆。

### 三、 串行神明决（神：决策串行 / 冲突处理与状态闭环）

核心矛盾在于无序的“气”冲击了需要闭环的“神”，因此冲突检测与最终落库必须**严格串行**执行，切断执行层对决策层的越权侵入。

1. **串行冲突处理机制**：
   - 设立单一消费通道，所有并发提取出的“变更块”按进入串行队列的顺序依次处理。
   - **冲突检测**：对比本地变更携带的`base_version`与Supabase当前记录的`current_version`。
     - **无冲突（本地base == 远程current）**：直接执行Upsert更新，版本号+1。
     - **产生冲突（本地base < 远程current）**：说明在多线程期间或其他终端已更新该记忆。采用“Last-Write-Wins（最后写入胜出）”或“字段级合并”策略，由“神”层裁决保留内容，并记录冲突日志。
2. **状态一致性闭环**：
   - 每次串行处理完一个变更块，立即更新本地文件的`base_version`与哈希值，使本地态与L4成品库态对齐。
   - 确保整个“决策串行”过程中，Supabase的事务隔离级别合理（如Read Committed），防止脏读导致的版本号错乱。

### 四、 架构总结与防坑自检表

| 架构层级 | 核心职责 | 同步方案动作 | 防坑自检 |
| :--- | :--- | :--- | :--- |
| **精 (L4库)** | 最终归档地 | Supabase存储版本号、哈希、内容 | 配置修改是否已同步读取点并验证生效？ |
| **气 (并发流)** | 差异提取 | Watch监听 -> 队列防抖 -> 并发Hash比对 | B模型API是否设置了300s timeout？是否跳过了reasoning占比检测？ |
| **神 (串行决策)** | 冲突闭环 | 串行比对版本号 -> 冲突合并 -> 落库更新 | 是否切断了并发流直接写库的越权侵入？ |

通过此方案，系统将实现：监听不阻塞、变更不漏发、冲突不串味，在V7.5架构下确保Supabase记忆脑与本地数据态的绝对一致性。
