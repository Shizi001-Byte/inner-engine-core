## 二、核心组件设计

### 2.1 重复率检测器

```python
class DupRateDetector:
    """
    在串行后处理阶段运行，不影响并发性能
    基于内容寻址hash，复用已有链路
    """
    def __init__(self):
        self.window_size = 100          # 滑动窗口大小
        self.hash_ring = deque(maxlen=self.window_size)  # hash环
        self.template_dup_map = {}      # {template_id: {hash: count}}
        self.dup_threshold = 0.65       # 全局重复率阈值
        self.per_template_threshold = 0.50  # 单模板重复率阈值
        
    def detect(self, result, template_id):
        content_hash = self._compute_hash(result)
        
        # 全局重复率
        dup_count = self.hash_ring.count(content_hash)
        self.hash_ring.append(content_hash)
        global_dup_rate = dup_count / len(self.hash_ring)
        
        # 单模板重复率
        t_map = self.template_dup_map.setdefault(template_id, defaultdict(int))
        t_map[content_hash] += 1
        template_dup_rate = t_map[content_hash] / sum(t_map.values())
        
        return {
            "global_dup_rate": global_dup_rate,
            "template_dup_rate": template_dup_rate,
            "should_trigger": global_dup_rate > self.dup_threshold 
                           or template_dup_rate > self.per_template_threshold,
            "triggered_template": template_id if template_dup_rate > self.per_template_threshold else None,
            "content_hash": content_hash
        }
```

**关键设计决策**：
- 检测器位于串行后处理队列末端，与已有 `内容寻址去重` 环节复用hash，零额外计算成本
- 滑动窗口而非全量统计，符合"恢复时不遍历所有节点状态"约束——重启后窗口自然为空，从头累积
- 单模板维度统计，精确定位哪个模板需要替换

### 2.2 阈值触发器（防抖+冷却）

```python
class ThresholdTrigger:
    """
    防抖设计：避免短时间内连续触发模板生成
    """
    def __init__(self):
        self.last_trigger_time = 0
        self.cooldown_seconds = 300  # 5分钟冷却
        self.trigger_count = 0      # 触发计数，用于每10任务刷新认知缓存
        
    def should_fire(self, detection_result):
        now = time.time()
        
        # 冷却检查
        if now - self.last_trigger_time < self.cooldown_seconds:
            return False, "cooldown"
        
        # 阈值检查
        if not detection_result["should_trigger"]:
            return False, "below_threshold"
        
        self.last_trigger_time = now
        self.trigger_count += 1
        return True, detection_result["triggered_template"]
```

### 2.3 模板生成器

```python
class TemplateGenerator:
    """
    从认知池提取认知，调用LLM生成差异化模板
    """
    def __init__(self):
        self.llm_config_b = {"model": "turbo", "timeout": 300, "skip_reasoning_check": True}
        self.llm_config_a = {"model": "a_model", "timeout": 600}
        
    def generate(self, triggered_template_id, dup_stats):
        # 1. 认知池提取（30分钟内新认知必须参与）
        recent_cognitions = cognition_pool.fetch_recent(minutes=30)
        related_cognitions = cognition_pool.fetch_related(
            trigger_type="high_dup_rate",
            context={"template_id": triggered_template_id, "dup_rate": dup_stats["template_dup_rate"]}
        )
        
        # 2. 认知缓存刷新（每10任务或每转结束）
        if trigger_counter % 10 == 0:
            cognition_pool.refresh_cache()
        
        # 3. 构造prompt
        prompt = self._build_evolution_prompt(
            triggered_template_id=triggered_template_id,
            dup_stats=dup_stats,
            cognitions=recent_cognitions + related_cognitions,
            existing_templates=template_registry.get_all_ids()  # 避免生成重复模板
        )
        
        # 4. 调用LLM（B模型turbo，300秒超时，跳过reasoning占比检测）
        new_template = llm_call(prompt, config=self.llm_config_b)
        
        # 5. 模型适配的质量检测
        quality_check = self._quality_check(new_template, model_type="turbo")
        # B模型跳过reasoning占比检测，只检查结构完整性
        if not quality_check.passed:
            return None, quality_check.reason
        
        return new_template, "success"
    
    def _quality_check(self, template, model_type):
        """不同模型独立的质量检测规则"""
        checks = {
            "turbo": ["structure", "uniqueness", "field_completeness"],  # 跳过reasoning占比
            "a_model": ["structure", "uniqueness", "field_completeness", "reasoning_ratio"]
        }
        return run_checks(template, checks[model_type])
```

### 2.4 模板注入器（WAL + 三点同步）

```python
class TemplateInjector:
    """
    核心约束：无记忆修改
    - 不持久节点状态/文件树
    - WAL记录事务意图（注入模板的意图）
    - 恢复时重放WAL即可重建TemplateRegistry
    """
    
    def inject(self, new_template):
        # ========== 三点同步：缺一不可 ==========
        
        # ① 状态写入
        wal_entry = WAL.record(
            intent="inject_template",
            payload=new_template.to_dict(),
            timestamp=time.time(),
            txn_id=uuid4()
        )
        # WAL是事务意图，不是节点状态，符合"无记忆修改"约束
        
        template_registry.add(new_template)  # 运行时状态
        
        # ② 执行读取（确保调度器下一轮能读到）
        scheduler.refresh_template_cache()  # 刷新调度器缓存
        
        # ③ 生效验证（立即验证，不留到下次任务）
        verified = self._verify_injection(new_template.id)
        if not verified:
            WAL.record(intent="rollback_template", payload={"template_id": new_template.id})
            template_registry.remove(new_template.id)
            return False, "verification_failed"
        
        return True, wal_entry.txn_id
    
    def _verify_injection(self, template_id):
        """注入后立即验证三个读取点"""
        checks = [
            template_registry.exists(template_id),           # 注册表可读
            scheduler.has_template(template_id),             # 调度器可见
            cognition_pool.is_template_tracked(template_id)  # 认知池可关联
        ]
        return all(checks)
```

### 2.5 闭环验证器

```python
class ClosureValidator:
    """
    验证新模板是否真正降低了重复率
    形成自进化闭环的最后一环
    """
    def __init__(self):
        self.observation_window = 10  # 注入后观察10个任务
        self.pending_validations = {}  # {template_id: {"count": 0, "dup_hashes": set()}}
        
    def observe(self, template_id, content_hash):
        if template_id not in self.pending_validations:
            return
        
        obs = self.pending_validations[template_id]
        obs["count"] += 1
        if content_hash in obs["dup_hashes"] or obs["count"] > 1:
            obs["dup_count"] += 1
        
        if obs["count"] >= self.observation_window:
            dup_rate = obs["dup_count"] / obs["count"]
            if dup_rate < 0.3:  # 新模板重复率低于30%，验证成功
                template_registry.mark_effective(template_id)
                cognition_pool.add_cognition(
                    category="template_evolution",
                    content=f"模板{template_id}有效降低重复率至{dup_rate:.0%}",
                    expiry=3600
                )
            else:
                template_registry.mark_ineffective(template_id)
                # 标记为低效模板，下次触发时优先替换
            del self.pending_validations[template_id]
```

## 三、WAL设计（无记忆修改约束下的持久化）

```
WAL Entry 结构：
┌──────────────────────────────────────────────────────────┐
│ txn_id (UUID)     │ intent            │ payload           │
├───────────────────┼───────────────────┼───────────────────┤
│ a1b2c3d4          │ inject_template   │ {template JSON}   │
│ e5f6g7h8          │ rollback_template │ {template_id}     │
│ i9j0k1l2          │ mark_effective    │ {template_id}     │
│ m3n4o5p6          │ mark_ineffective  │ {template_id}     │
└──────────────────────────────────────────────────────────┘

恢复流程：
1. 读取WAL最后一个checkpoint
2. 重放checkpoint之后的entries（不遍历节点状态）
3. 重建TemplateRegistry运行时状态
4. 滑动窗口自然为空，从头累积
```

**符合约束验证**：
| 约束 | 如何满足 |
|------|---------|
| 无记忆修改 | WAL记录的是"注入模板的事务意图"，不是节点文件树/时间戳 |
| 恢复不遍历所有节点 | 只重放WAL checkpoint后的entries，复杂度 O(Δ) 而非 O(N) |
| 多线程管线 | 检测在串行后处理阶段，不影响并发API调用 |

## 四、配置项与三点同步矩阵

| 配置项 | 状态写入(WAL) | 执行读取 | 生效验证 |
|--------|:---:|:---:|:---:|
| `dup_threshold` (0.65) | WAL.init | DupRateDetector.read | 注入后检查dup_rate是否下降 |
| `per_template_threshold` (0.50) | WAL.init | DupRateDetector.read | 单模板dup_rate < 30% |
| `window_size` (100) | WAL.init | DupRateDetector.read | 窗口满后统计偏差 < 5% |
| `cooldown_seconds` (300) | WAL.init | ThresholdTrigger.read | 5min内不重复触发 |
| `observation_window` (10) | WAL.init | ClosureValidator.read | 10任务内得出结论 |

## 五、避坑对照表

| 历史坑 | 本设计应对 |
|--------|-----------|
| 配置修改后未生效 | 每个配置项三点同步矩阵，注入后立即 `_verify_injection()` |
| API超时 | B模型turbo用300秒，A模型用600秒，硬编码在config中 |
| 自动调参全链路失效 | 三点同步：WAL写入→调度器读取→重复率下降验证 |
| 废稿检测误杀B模型 | `quality_check` 按model_type选择检测规则，turbo跳过reasoning占比 |
| 认知池只进不出 | 触发器计数%10刷新认知缓存；30分钟内新认知强制参与注入；闭环验证成功后回写认知 |
| 认知不参与注入 | `cognition_pool.fetch_recent(30min)` + `fetch_related()` 双通道提取 |

## 六、自进化闭环完整流程

```
正常运行
    │
    ▼
串行后处理 → 内容寻址去重 → 重复率检测
    │
    ├─ dup_rate < 阈值 ──▶ 继续运行
    │
    └─ dup_rate ≥ 阈值
        │
        ▼
    冷却检查(5min) ──No──▶ 跳过
        │ Yes
        ▼
    认知池提取(30min内新认知 + 相关认知)
        │
        ▼
    LLM生成新模板(B:turbo/300s, 跳过reasoning检测)
        │
        ▼
    质量检测(结构+唯一性+完整性)
        │
        ▼
    WAL记录注入意图 ──▶ 三点同步 ──▶ 立即验证
        │                                    │
        │                              验证失败
        │                              WAL回滚
        │
    ▼ 验证成功
    调度器下一轮使用新模板
        │
        ▼
    闭环验证器观察10个任务
        │
        ├─ dup_rate < 30% ──▶ 标记有效, 回写认知池
        │
        └─ dup_rate ≥ 30% ──▶ 标记低效, 下次优先替换
```
