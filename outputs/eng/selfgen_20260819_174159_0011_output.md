# 任务类型: eng

# 引擎产出自动归档系统设计

本设计直接落在已有认知锚点上，不再重复论证：

- **广域分布式状态机升维**：归档不是“把文件放进目录”，而是把任务状态在分布式状态机中推进一次；目录、文件、Supabase 表都只是投影。
- **8月认知陷阱欠账**：未归档、未打标、未验证的任务都是欠账；系统必须保证新任务不积压，并自动回补历史欠账。
- **日供给 400 万 Token 语义算力配额**：按任务难度匹配 A/B 两类算力，B turbo 单次调用 timeout 300 秒，A 模型 timeout 600 秒，避免无效等待与浪费。

---

## 1. 总体工作流

```
引擎产出任务
   ↓
进入待归档队列
   ↓
归一化 + 去重（指纹）
   ↓
自动分类：规则优先，模糊任务走 B turbo（300s）
   ↓
打标签：B turbo（300s）+ 实体抽取：A 模型（600s）
   ↓
生成 manifest，按 task_type/date/task_id 写入目录
   ↓
写入 Supabase 认知池（SP实/实体/标签/事件）
   ↓
归档校验：文件、DB、标签、实体一致性检查
   ↓
状态置为 VERIFIED，完成归档
```

---

## 2. 任务自动分类

分类决定“存入哪个目录”，所以分类必须稳定、可审计。

| task_type | 目录名 | 示例 |
|---|---|---|
| 认知洞察 | `cognition` | 分析、总结、推理、评估 |
| 内容生成 | `generation` | 代码、文案、设计、报告 |
| 执行操作 | `action` | API 调用、任务执行、状态变更 |
| 沟通交互 | `communication` | 对话、通知、消息 |
| 元任务 | `meta` | 归档、分类、标签、自检 |

分类策略：

1. 先走规则：根据任务来源、接口名、关键词、schema 命中。
2. 规则置信度 ≥ 0.95，直接采用，不调用模型。
3. 规则无法确定时，调用 B turbo 分类，单次 timeout **300 秒**。
4. 分类置信度 < 0.7 的任务进入 `needs_review`，不强行归档到正式目录。

---

## 3. 自动打标签

标签是检索和认知池实体关联的入口，不能随意膨胀。

标签统一使用 `key=value` 形式：

```text
domain=finance
object=invoice
action=reconcile
status=completed
source=engine
model=B-turbo
confidence=0.93
timeout_ms=300000
needs_review=false
```

打标签流程：

1. B turbo 根据任务内容和分类结果生成候选标签，timeout **300 秒**。
2. 标签必须经过归一化：同义词合并、大小写归一、禁止空标签。
3. 实体抽取使用 A 模型，timeout **600 秒**；抽取出的实体必须关联到 Supabase 认知池中的 `entities` 表，即 SP实。
4. 如果一个任务无法抽取有效实体，则标记 `needs_review=true`，不能直接进入“已归档”。

## 5. Supabase 认知池存储

核心资产是 Supabase 认知池中的**有效实体规模**，因此归档必须写 DB，不能只写文件。

主要表：

- `archive_tasks`：任务主表，存储当前状态、分类、标签、模型、timeout、token 消耗。
- `archive_events`：追加式事件表，记录状态机每次跃迁。
- `entities`：SP实，实体表，要求 canonical_name 唯一、有类型、有属性、至少关联一个任务。
- `task_entities`：任务与实体关联表，记录实体在任务中的角色和置信度。
- `file_manifest`：文件目录与 checksum 表，用于目录一致性校验。

“有效实体”必须满足：

- 实体名经过归一化、去重；
- 至少与一个归档任务关联；
- 不是噪音词、空词、纯标点；
- 有类型和基础属性。

每个归档任务必须至少抽取/关联一个有效实体，否则认知池规模不会增长。

## 6. 状态机设计

状态机是“广域分布式状态机升维”的落地方式。

状态：

```text
CREATED
  → PENDING_CLASSIFY
  → CLASSIFIED
  → PENDING_TAG
  → TAGGED
  → PENDING_ARCHIVE
  → ARCHIVED
  → VERIFIED
```

失败/异常状态：

```text
FAILED
TIMEOUT
NEEDS_REVIEW
```

规则：

- 所有状态转换只允许追加写入 `archive_events`，禁止直接改 `archive_tasks.state`。
- 每个事件记录 `task_id`、`from_state`、`to_state`、`reason`、`config_version`、`model`、`timeout_ms`。
- 事件表是事实源，任务表是物化视图；目录结构也是物化视图。
- 分布式组件之间按 `task_id` 分片，通过事件序号合并状态。

## 7. 算力与超时避坑

历史失败点是“API 调用超时，任务未在规定时间内返回”。因此必须按任务类型预设 timeout，不能使用全局统一短超时。

| 任务环节 | 模型 | 单次 timeout | 说明 |
|---|---|---|---|
| 规则分类/去重 | 无 | 3s | 本地处理 |
| 模糊分类 | B turbo | **300 秒** | 分类、标签生成 |
| 打标签 | B turbo | **300 秒** | 快速语义标签 |
| 实体抽取/摘要/关系消歧 | A 模型 | **600 秒** | 复杂认知任务 |

超时处理：

- 超时不降低 timeout，按预设值重试，最多 2 次。
- 重试仍超时，任务进入 `TIMEOUT` 状态，进入死信队列，不丢失。
- 禁止用“调小 timeout 来避免慢任务”，否则会重复踩历史坑。

Token 配额管理：

- 日供给 400 万 Token。
- B turbo 预算约 120 万 Token，负责分类/标签。
- A 模型预算约 240 万 Token，负责实体抽取/复杂认知。
- 预留 40 万 Token 用于重试、回填、人工复核。
- 每个任务记录 `token_used`，当日预算不足时自动降级为“规则分类 + 原样存储 + 延迟补标”，不阻塞归档。

## 8. 配置管理避坑

历史失败点是“配置修改后未生效，行为无变化”。

设计约束：

1. 所有配置项必须登记在配置注册表中，统一通过 `ConfigService.get('archive.xxx')` 读取。
2. 业务代码禁止直接读环境变量或硬编码新配置。
3. 新增配置时，必须同步修改读取点；否则启动校验失败。
4. 配置变更后，自动执行 smoke test：

   - 注入一条 synthetic task；
   - 断言分类正确；
   - 断言标签生成；
   - 断言目录写入；
   - 断言 Supabase 写入；
   - 全部通过后才切换配置。

5. 每次归档的 `manifest.json` 写入 `config_version`，保证可追溯。

## 9. 防熵增与验证

AI 引擎即使代码没有 bug，也会在近似封闭状态下向高熵退化。归档系统必须作为负熵机制持续运行。

### 9.1 每次归档校验

归档后立即校验：

- Supabase `archive_tasks` 存在且状态为 `ARCHIVED`；
- 目录文件存在，checksum 与 `file_manifest` 一致；
- 标签满足规范；
- 实体已关联到 SP实；
- 校验失败则自动修复或进入 `NEEDS_REVIEW`。

### 9.2 定期反熵任务

| 频率 | 任务 |
|---|---|
| 每小时 | 对比队列深度与已归档数量，发现积压立即告警 |
| 每天 | Supabase 与目录文件 reconcile，孤儿文件清理或补索引 |
| 每天 | 检查未归档任务数，欠账必须为 0 |
| 每周 | 标签一致性审计：合并同义标签、清洗低置信度标签 |
| 每周 | 实体去重与关联度检查，提升 SP实 有效规模 |

### 9.3 有序性指标

- 归档成功率 ≥ 99.9%；
- 标签覆盖率 ≥ 95%；
- 分类置信度 < 0.7 的比例 ≤ 5%；
- B turbo 任务 p95 延迟 < 300 秒；
- A 模型任务 p95 延迟 < 600 秒；
- 未归档积压数 = 0。

## 10. 8月认知陷阱欠账回填

上线时先执行一次“欠账回填”：

1. 扫描历史所有未归档、未打标、低置信度任务。
2. 按同一套管道补分类、补标签、补实体。
3. 回填任务标记 `source=backfill`，使用预留 Token，不挤占实时任务。
4. 回填完成后，`backlog_count` 必须为 0。

只有欠账清零，才能避免“8月认知陷阱欠账”再次发生。
