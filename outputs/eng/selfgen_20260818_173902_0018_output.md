# 任务类型: eng

# 自动归档系统设计（基于锚定推演）

不再重复论证，直接把锚定作为设计前提：

- 同步粒度：**块**，不是整个文件  
- 归档对象本体：**DAG 顶点**，不是进程实例  
- 流程结构：**三个串联 DAG 节点**，每节点三转，共九转  
- 核心目标：为 AI 输出建立**事实边界 + 校验机制**  
- 认知层级：**基础指令跟随层**，不做自由创作，只做确定性归档  

---

## 1. 总体 DAG

```text
引擎产物
   ↓
块切分器（Block Splitter）
   ↓
Node A：候选生成（自由）
   ↓
Node B：事实验证（约束）
   ↓
Node C：归档落位（记忆/遗忘）
   ↓
归档目录 + manifest
```

三个节点严格串联：

```text
A → B → C
```

不存在反向边。B 校验失败时进入 `needs_review` 终止态，不回跳 A。

---

## 2. 九转玄功 → DAG 映射

| 九转 | DAG 节点 | 动作 | 产出 |
|---|---|---|---|
| 一转 | Node A | 块切分 | `block_id` 列表 |
| 二转 | Node A | 候选分类 | 候选 task_type |
| 三转 | Node A | 候选打标签 | 候选 tags |
| 四转 | Node B | 证据核对 | 校验 evidence |
| 五转 | Node B | 边界判定 | fact_boundary |
| 六转 | Node B | 冲突消解 | verified tags |
| 七转 | Node C | 去重/遗忘 | changed block set |
| 八转 | Node C | 目录映射 | target directory |
| 九转 | Node C | 原子提交 | manifest + index |

对应关系：

- Node A 处理「生成 vs 验证」中的**生成**  
- Node B 处理「自由 vs 约束」中的**约束**  
- Node C 处理「记忆 vs 遗忘」中的**记忆与遗忘**  

---

## 3. 块级增量同步

归档不按文件同步，按块同步。

```text
block_id = sha256(block.content)
```

同步规则：

```text
changed_blocks = new_block_ids - existing_block_ids
```

只有 `changed_blocks` 进入 Node A → B → C。

未变化块不重新分类、不重新打标签、不重新写入。

文件级目录只是一个“视图”，底层块存储是内容寻址的：

```text
block_store/
  {block_id[0:2]}/
    {block_id[2:4]}/
      {block_id}
```

这样避免“整个文件同步”导致的重复归档和配置变更后全量重跑。

---

## 4. 从进程实例到 DAG 顶点的本体论迁移

归档系统不感知进程生命周期，不读取 PID、stdout、临时状态。

它只消费 DAG 顶点输出事件：

```json
{
  "vertex_id": "v-123",
  "input_block_ids": [],
  "output_blocks": [],
  "metadata": {
    "model": "B_turbo",
    "task_type_hint": "code"
  },
  "config_version": "2026.06.01"
}
```

每个归档对象都是一个 DAG 顶点，不是进程实例。

好处：

- 可重放  
- 可增量  
- 可验证  
- 无隐藏状态  
- 配置变更不影响旧顶点  

---

## 5. Node A：候选生成

Node A 负责自由生成候选，不负责判断对错。

### 一转：块切分

把引擎产物切成语义块：

- 代码：函数、类、import 块  
- Markdown：章节、段落  
- JSON：对象、数组元素  
- 日志：按时间戳或事件边界  

### 二转：候选分类

模型输出候选 task_type：

```json
{
  "block_id": "sha256:abc",
  "candidate_task_type": "code",
  "confidence": 0.87,
  "evidence_snippet": "def main():"
}
```

### 三转：候选标签

模型输出候选标签：

```json
{
  "block_id": "sha256:abc",
  "candidate_tags": [
    {
      "tag": "python",
      "namespace": "language",
      "confidence": 0.95,
      "evidence_snippet": "import os"
    }
  ]
}
```

Node A 只生成，不验证。

---

## 6. Node B：事实验证

Node B 是核心校验节点，解决“幻觉生成”和“弱验证”矛盾。

### 四转：证据核对

每个候选分类/标签必须带 `evidence_snippet`。

验证规则：

```text
evidence_snippet 必须能在原始 block 中精确找到
否则拒绝该候选
```

这是硬校验，不是模型自我确认。

### 五转：边界判定

判断 AI 输出是否超出事实边界。

例如：

- block 里只写了 `fix typo`  
- 模型打标签 `bug_fix`  
- 校验失败，因为 `typo` 不等于 `bug_fix`

边界声明示例：

```json
{
  "verified": ["task_type=code", "tag=python"],
  "not_verified": ["code correctness", "security", "business value"]
}
```

超出边界的内容不写入归档事实。

### 六转：冲突消解

- 同 namespace 下重复标签，只保留置信度最高者  
- 不在 taxonomy 中的标签，拒绝  
- 置信度低于阈值，进入 `needs_review`

Node B 通过后，候选才成为可归档事实。

---

## 7. Node C：归档落位

Node C 负责记忆与遗忘。

### 七转：去重/遗忘

- 已存在的 `block_id` 不重复存储  
- 未通过校验的候选被“遗忘”  
- 只保留 verified 内容

### 八转：目录映射

按任务分类和日期生成目录：

```text
archive/
  {task_type}/
    {yyyy}/{mm}/{dd}/
      {vertex_id}/
        manifest.json
        boundary.json
        tags.json
        blocks/
```

如果存在多个候选分类，取最高置信度的 task_type 作为主目录。

Tags 不直接作为目录，而是写入索引：

```text
archive/
  _index/
    tags/
      python/
        v-123.json
```

### 九转：原子提交

先写临时目录，再原子 rename：

```text
tmp/{vertex_id} → archive/{task_type}/{date}/{vertex_id}
```

最后更新索引。

避免归档一半导致目录不完整。

## 8. 避坑落地

### 8.1 配置修改后未生效

统一配置读取点：

```python
def cfg(key):
    return CONFIG_REGISTRY[key]
```

新增配置时，必须同步修改：

- `config_schema.yaml`  
- `cfg()` 的读取点  
- 对应目录映射函数  

修改后立即验证：

```bash
archivectl validate-config --sample block
```

验证输出是否进入了预期目录。

每个 DAG 顶点记录 `config_version`，配置变更后旧顶点不变，新顶点用新配置。

### 8.2 API 调用超时

预设 timeout：

```yaml
model_timeout:
  B_turbo: 300
  A: 600
```

所有模型调用必须传入 timeout：

```python
resp = model.call(
    model="B_turbo",
    timeout=cfg("model_timeout.B_turbo")
)
```

超时后：

- 状态置为 `TIMEOUT`  
- 不写入归档目录  
- 不生成部分 manifest  

---

## 9. 核心目标闭环

```text
幻觉生成
   ↓
Node A 生成候选
   ↓
Node B 证据核对 + 边界判定
   ↓
无证据候选被拒绝
   ↓
弱验证
   ↓
Node B 不依赖模型自问自答
   ↓
依赖 block 原文 + taxonomy + 置信度阈值
   ↓
建立事实边界
```

最终每个归档产物都有：

- `block_id` 溯源  
- `evidence_snippet` 证据  
- `verified` / `not_verified` 边界  
- `config_version` 可复现  
- `model_timeout` 可观测  

这就是“基础指令跟随层”的自动归档系统。
