# 任务类型: eng

## 先校准锚点

多线程 API 调用本身不是问题，问题在 API 返回后：

> 多个线程同时尝试进入“串行后处理”临界区，导致共享状态被交错读写。

锁机制的目标不是“锁住所有代码”，而是：

1. **状态转移必须原子**：一个任务只能从当前状态进入下一个合法状态。
2. **后处理必须串行**：同一时间只能有一个任务在做后处理。
3. **API 调用不持锁**：锁只保护状态机和后处理临界区，不保护网络等待。

这就是“决策串行 → 执行并发”的落地方式。

---

## 状态机定义

状态是唯一真相源，所有线程都通过状态机判断“能不能做下一步”。

| 当前状态 | 事件 | 下一状态 | 持锁 |
|---|---|---|---|
| PENDING | 开始调用 API | CALLING | state_lock |
| CALLING | API 成功 | READY | state_lock |
| CALLING | API 失败 | FAILED | state_lock |
| READY | 后处理线程领取 | PROCESSING | state_lock |
| PROCESSING | 后处理成功 | DONE | state_lock |
| PROCESSING | 后处理失败 | FAILED | state_lock |
| FAILED | 重试 | CALLING / READY | state_lock |

`READY` 表示“已进入后处理队列，等待被串行消费”。

---

## 锁机制全景

| 锁 | 粒度 | 持有时间 | 作用 |
|---|---|---|---|
| `state_lock` | 全局状态库 | 微秒级 | 保护状态字典和后处理队列 |
| `ready_cv` | 条件变量 | 等待时释放 | 后处理线程避免忙等 |
| `post_process_lock` | 后处理临界区 | 整个后处理过程 | 强制串行后处理 |
| `api_semaphore` | 并发 API 调用数 | API 调用期间 | 限制并发量，避免打爆上游 |

核心锁顺序：

> `post_process_lock` → `state_lock`

禁止反向。  
禁止持有 `state_lock` 时去等待 `post_process_lock`。

## 完整代码骨架

```python
import threading
import time
import json
import copy
import urllib.request
from collections import deque
from concurrent.futures import ThreadPoolExecutor, as_completed
from dataclasses import dataclass
from typing import Any, Optional
from enum import Enum


class TaskStatus(str, Enum):
    PENDING = "PENDING"
    CALLING = "CALLING"
    READY = "READY"
    PROCESSING = "PROCESSING"
    DONE = "DONE"
    FAILED = "FAILED"


@dataclass
class Task:
    task_id: str
    status: TaskStatus = TaskStatus.PENDING
    version: int = 0
    result: Optional[Any] = None
    error: Optional[str] = None
    retry_count: int = 0


class StateStore:
    """状态存储 + 后处理队列。所有状态转移必须经过 state_lock。"""

    def __init__(self):
        self._lock = threading.Lock()
        self._cv = threading.Condition(self._lock)
        self._tasks = {}
        self._ready_queue = deque()

    def create(self, task_id):
        with self._lock:
            if task_id in self._tasks:
                return False
            self._tasks[task_id] = Task(task_id=task_id)
            return True

    def start_call(self, task_id):
        with self._lock:
            task = self._tasks.get(task_id)
            if task is None or task.status != TaskStatus.PENDING:
                return False
            task.status = TaskStatus.CALLING
            task.version += 1
            return True

    def complete_call(self, task_id, result):
        with self._lock:
            task = self._tasks.get(task_id)
            if task is None or task.status != TaskStatus.CALLING:
                return False

            task.result = result
            task.status = TaskStatus.READY
            task.version += 1
            self._ready_queue.append(task_id)
            self._cv.notify()
            return True

    def fail_call(self, task_id, error):
        with self._lock:
            task = self._tasks.get(task_id)
            if task is None or task.status != TaskStatus.CALLING:
                return False

            task.status = TaskStatus.FAILED
            task.error = error
            task.version += 1
            self._cv.notify_all()
            return True

    def claim_next(self, timeout=None):
        """从 READY 队列中领取一个任务，并原子地置为 PROCESSING。"""
        with self._lock:
            deadline = None if timeout is None else time.time() + timeout

            while True:
                while not self._ready_queue:
                    if deadline is None:
                        self._cv.wait()
                    else:
                        remaining = deadline - time.time()
                        if remaining <= 0:
                            return None
                        self._cv.wait(remaining)

                task_id = self._ready_queue.popleft()
                task = self._tasks.get(task_id)

                if task is not None and task.status == TaskStatus.READY:
                    task.status = TaskStatus.PROCESSING
                    task.version += 1
                    return task_id

                # 状态不一致，丢弃这条队列项并继续
                continue

    def finish_processing(self, task_id, result=None):
        with self._lock:
            task = self._tasks.get(task_id)
            if task is None or task.status != TaskStatus.PROCESSING:
                return False

            if result is not None:
                task.result = result

            task.status = TaskStatus.DONE
            task.version += 1
            self._cv.notify_all()
            return True

    def fail_processing(self, task_id, error):
        with self._lock:
            task = self._tasks.get(task_id)
            if task is None or task.status != TaskStatus.PROCESSING:
                return False

            task.status = TaskStatus.FAILED
            task.error = error
            task.version += 1
            self._cv.notify_all()
            return True

    def get_task(self, task_id):
        with self._lock:
            return copy.deepcopy(self._tasks[task_id])

    def wait_until_idle(self, timeout=None):
        with self._lock:
            deadline = None if timeout is None else time.time() + timeout

            while True:
                if not self._ready_queue and not any(
                    t.status == TaskStatus.PROCESSING
                    for t in self._tasks.values()
                ):
                    return True

                if deadline is None:
                    self._cv.wait()
                else:
                    remaining = deadline - time.time()
                    if remaining <= 0:
                        return False
                    self._cv.wait(remaining)


# 后处理串行锁。当前单消费者时锁不竞争，但保留作为安全网。
POST_PROCESS_LOCK = threading.Lock()


def choose_timeout(model_type):
    # B 模型 turbo 用 300 秒，A 模型用 600 秒
    if model_type == "B_turbo":
        return 300
    if model_type == "A":
        return 600
    raise ValueError(f"unknown model_type: {model_type}")


def call_api(store, task_id, endpoint):
    """并发执行 API 调用。这里不持锁，只有状态转移时短暂持锁。"""
    if not store.start_call(task_id):
        return

    try:
        # 统一用 urllib 直连，避开 requests 的全局代理 ProxyError
        opener = urllib.request.build_opener(
            urllib.request.ProxyHandler({})
        )

        req = urllib.request.Request(
            endpoint["url"],
            data=json.dumps(endpoint["body"]).encode(),
            headers={"Content-Type": "application/json"},
        )

        timeout = choose_timeout(endpoint["model_type"])

        with opener.open(req, timeout=timeout) as resp:
            data = json.loads(resp.read().decode())

        # 避坑：Responses API 可能把 token 全耗在 reasoning 上，content 为空
        content = extract_content(data)
        if not content:
            raise ValueError("Responses API content empty")

        # 列契约锚点：这里只做契约映射，不允许执行层自行简化
        result = normalize_by_contract(task_id, content)

        store.complete_call(task_id, result)

    except Exception as e:
        store.fail_call(task_id, str(e))


def extract_content(data):
    try:
        return data["output"][0]["content"][0]["text"]
    except (KeyError, IndexError, TypeError):
        return ""


def normalize_by_contract(task_id, content):
    # 伪代码：基于 schema_contract 做严格映射
    return schema_contract.apply(task_id, content)


def run_post_process(store, task_id):
    """真正需要串行的后处理：生成 SQL、写库、发通知等。"""
    task = store.get_task(task_id)

    # 锚点：列映射在决策层已经定死，这里不许自行简化 SQL
    sql = schema_contract.to_sql(task.result)

    # 幂等键防止重试导致重复副作用
    return db.execute_with_idempotency(task_id, sql)


def post_processing_loop(store, stop_event):
    """单消费者线程：串行消费 READY 队列。"""
    while not stop_event.is_set():
        task_id = store.claim_next(timeout=1.0)
        if task_id is None:
            continue

        try:
            with POST_PROCESS_LOCK:
                # 锁顺序：POST_PROCESS_LOCK -> state_lock
                result = run_post_process(store, task_id)
                ok = store.finish_processing(task_id, result)
                if not ok:
                    raise RuntimeError(f"finish_processing failed: {task_id}")

        except Exception as e:
            store.fail_processing(task_id, str(e))


def run_pipeline(tasks):
    store = StateStore()

    for task in tasks:
        store.create(task.id)

    stop_event = threading.Event()
    post_thread = threading.Thread(
        target=post_processing_loop,
        args=(store, stop_event),
        daemon=True,
    )
    post_thread.start()

    # 并发 API 调用
    with ThreadPoolExecutor(max_workers=8) as ex:
        futures = [
            ex.submit(call_api, store, task.id, build_endpoint(task))
            for task in tasks
        ]

        for f in as_completed(futures):
            try:
                f.result()
            except Exception:
                # call_api 内部已经 fail_call
                pass

    # 等待所有 READY/PROCESSING 清空
    store.wait_until_idle(timeout=600)

    stop_event.set()
    post_thread.join(timeout=5)

    # 汇总状态
    return [store.get_task(task.id) for task in tasks]
```

## 为什么这样能避免竞态

### 1. `complete_call` 是原子状态转移

多个 API 线程同时完成时，只有一个线程能把自己的任务从 `CALLING` 改为 `READY` 并入队。  
另一个线程如果看到状态已经不是 `CALLING`，就直接失败返回，不会重复入队。

### 2. `claim_next` 是原子的“领取”

后处理线程从队列里取出任务时，同时把状态从 `READY` 改为 `PROCESSING`。  
这样不会出现：

- 两个线程同时拿到同一个任务
- 任务从队列取出但状态没变，导致重复处理

### 3. `POST_PROCESS_LOCK` 保证后处理真正串行

即使未来为了吞吐启动多个消费者线程，`POST_PROCESS_LOCK` 也会保证同一时间只有一个任务在执行 `run_post_process`。

### 4. 锁顺序固定，避免死锁

所有需要两把锁的路径都是：

> `POST_PROCESS_LOCK` → `state_lock`

API 线程只短暂持 `state_lock`，不持有 `state_lock` 去等 `POST_PROCESS_LOCK`。

## 必须同步处理的三个坑

1. **配置修改后未生效**  
   锁超时、API 超时、并发数等配置必须从配置中心读取，不能硬编码在类变量里。  
   修改后要打印实际生效值，并跑一条 smoke test 验证状态流转。

2. **API 超时**  
   按模型类型设置：
   - B 模型 turbo：300 秒
   - A 模型：600 秒

3. **代理导致 ProxyError**  
   代码里统一用 `urllib.request.ProxyHandler({})` 直连，不引入 `requests`。  
   如果未来必须用 `requests`，所有请求显式传 `proxies=None`。

## 验证 checklist

- [ ] 单测：两个线程同时 `complete_call` 同一个任务，只有一个成功。
- [ ] 单测：后处理失败后状态为 `FAILED`，重试只能从 `FAILED` 进入 `CALLING` 或 `READY`。
- [ ] 压测：100 个任务并发 API，后处理单消费者消费，最终全部 `DONE` 或 `FAILED`，无卡死。
- [ ] 死锁检查：`state_lock` 持有时间不超过毫秒级，API 调用和 DB 写都不在 `state_lock` 内。
- [ ] 幂等验证：后处理用 `task_id` 作为幂等键，重跑不会产生重复数据。

这套方案的本质是：

> 状态机是锁的锚点，锁是状态机的执行器。  
> 先校准状态契约，再谈并发优化。
