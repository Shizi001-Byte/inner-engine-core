# 多模型成本实时监控与自动熔断系统：虚实闭环设计

## 0. 设计立场：熔断不是省钱，而是“反者道之动”

本系统不把“熔断”理解为终止消耗，而是理解为**热区转移 + 蓄能**：

- 成本升高 → 熔断（反）
- 熔断后降级到其他模型（变）
- 任务进入等待队列（虚）
- 冷却后自动补跑（虚返实）

于是形成：

```text
实（API 消耗） --> 虚（指标/熔断/等待任务）
      ^                    |
      |                    v
补跑/恢复（实） <-- 冷却/降级/排队（反）
```

这符合“以实养虚，虚又返实”的自增强闭环：  
**消耗产生指标，指标驱动熔断，熔断产生等待，等待恢复后变成新的消耗。**

---

## 1. 总体架构

```text
                 +-------------------+
                 |   Config/State    |
                 | 唯一事实源         |
                 +---------+---------+
                           |
   Task --> Router --> CircuitBreaker --> Model API
                |              |
                +--> Fallback  +--> PendingQueue
                |              |
                +--> Monitor   +--> Replay/Backfill
```

核心模块：

1. **Config/State**：所有配置、计数、熔断状态、等待任务都从 state 读取。
2. **Router**：根据模型状态选择可用模型；无可用模型则入队。
3. **CircuitBreaker**：每个模型独立状态机：`CLOSED -> OPEN -> HALF_OPEN -> CLOSED`。
4. **Monitor**：实时扫描窗口指标，触发熔断/恢复。
5. **PendingQueue**：记录等待任务，恢复后自动补跑。
6. **API Adapter**：统一封装模型调用、超时、计费、计数。

## 2. 配置中心：避免“配置修改后未生效”

所有配置必须从 `state.config` 读取，全局常量只做默认值兜底。

```python
DEFAULT_FUSE_COOLDOWN_SECONDS = 120  # 仅兜底

def get_cooldown(state):
    # 从 state 读取，禁止硬编码 120
    return state.config.fuse_cooldown_override or DEFAULT_FUSE_COOLDOWN_SECONDS
```

配置热更新后必须立即验证：

```python
def reload_config(state, new_config):
    with state.lock:
        old_config = state.config
        state.config = validate_config(new_config)

    try:
        verify_config_effective(state)   # 发最小探针，确认行为变化
    except Exception:
        with state.lock:
            state.config = old_config     # 验证失败回滚
        raise
```

`verify_config_effective` 会实际调用一次 `max_tokens=1` 的探针，确认新配置生效，而不是“看起来加载了但行为没变”。

## 4. 计数语义：避免“九维计数混乱”

统一规则：

- `task_count`：只统计真实任务调用
- `bonus_count`：只统计系统自触发调用（探针、保活、配置验证）
- `count = task_count + bonus_count`
- 任何计数增加必须走 `incr(kind)`，禁止直接 `count += 1`

```python
class Metrics:
    def __init__(self):
        self.task_count = 0
        self.bonus_count = 0
        self.task_completed_count = 0
        self.bonus_success_count = 0
        self.error_count = 0
        self.timeout_count = 0
        self.degraded_count = 0
        self.recovered_count = 0
        self.pending_count = 0

        self.total_tokens = 0
        self.total_cost = 0.0

        # 滑动窗口，用于熔断判断
        self.window_cost = WindowCounter()
        self.window_tokens = WindowCounter()
        self.window_requests = WindowCounter()
        self.window_errors = WindowCounter()
        self.consecutive_failures = 0

    @property
    def count(self):
        return self.task_count + self.bonus_count

    def incr(self, kind: str, tokens=0, cost=0.0):
        if kind == "task":
            self.task_count += 1
            self.window_requests.add(1)
        elif kind == "bonus":
            self.bonus_count += 1
            self.window_requests.add(1)
        elif kind == "task_success":
            self.task_completed_count += 1
        elif kind == "bonus_success":
            self.bonus_success_count += 1
        elif kind == "error":
            self.error_count += 1
            self.window_errors.add(1)
        elif kind == "timeout":
            self.timeout_count += 1
            self.window_errors.add(1)

        self.total_tokens += tokens
        self.total_cost += cost
        self.window_tokens.add(tokens)
        self.window_cost.add(cost)
```

这样就不会再出现“count=666 但 tasks_completed=79”的失真问题。

## 5. 每个模型独立熔断状态机

每个模型维护独立状态：

```python
class ModelBreaker:
    def __init__(self, model_id, family):
        self.model_id = model_id
        self.family = family
        self.state = "CLOSED"   # CLOSED / OPEN / HALF_OPEN
        self.opened_at = 0.0
        self.metrics = Metrics()
```

状态转换：

```text
CLOSED:
  窗口成本/token/错误率/连续失败 超过阈值
  -> OPEN

OPEN:
  等待 cooldown，冷却时间从 state.config 实时读取
  冷却完成 -> HALF_OPEN

HALF_OPEN:
  发送系统探针（bonus，不计 task）
  探针成功且指标低于阈值 -> CLOSED，触发补跑
  探针失败或指标仍超阈值 -> OPEN，重新计时
```

关键：冷却时间判断必须动态读取配置：

```python
def is_open_expired(state, breaker):
    return time.time() - breaker.opened_at >= get_cooldown(state)
```

这样 `fuse_cooldown_override=300` 就一定会生效，不会再用硬编码 120。

## 6. 熔断阈值判断

每个模型独立判断：

```python
def is_threshold_exceeded(state, breaker):
    m = breaker.metrics

    if m.window_cost.sum() >= get_cost_threshold(state, breaker.model_id):
        return True

    if m.window_tokens.sum() >= get_token_threshold(state, breaker.model_id):
        return True

    total_req = m.window_requests.sum()
    if total_req >= 5:
        error_rate = m.window_errors.sum() / total_req
        if error_rate >= get_error_rate_threshold(state, breaker.model_id):
            return True

    if m.consecutive_failures >= get_consecutive_failure_threshold(state, breaker.model_id):
        return True

    return False
```

## 7. 降级路由

熔断后自动降级到备用模型：

```python
DEGRADE_CHAIN = {
    "doubao-seed-2-1-pro": [
        "doubao-seed-2-1-turbo",
        "doubao-seed-2-1-light",
    ],
    "doubao-seed-2-1-turbo": [
        "doubao-seed-2-1-light",
    ],
    "doubao-seed-2-1-light": [],
}

def choose_model(state, task):
    preferred = task.model_id
    for model_id in [preferred] + DEGRADE_CHAIN.get(preferred, []):
        breaker = state.models[model_id]
        if breaker.state == "CLOSED":
            return model_id
    return None
```

如果所有可用模型都熔断，则任务进入等待队列。

## 8. 等待任务与自动补跑

等待任务记录：

```python
@dataclass
class PendingTask:
    task_id: str
    preferred_model_id: str
    payload: dict
    enqueued_at: float
    attempts: int = 0
```

任务入队：

```python
def enqueue(state, task):
    with state.lock:
        state.pending_queue.append(task)
        state.models[task.preferred_model_id].metrics.pending_count += 1
```

恢复后自动补跑：

```python
def replay_pending(state, model_id):
    while True:
        with state.lock:
            breaker = state.models[model_id]
            if breaker.state != "CLOSED":
                break

            if is_threshold_exceeded(state, breaker):
                open_breaker(state, breaker)
                break

            task = state.pending_queue.pop_for(model_id)
            if task is None:
                break

            state.models[model_id].metrics.pending_count -= 1

        # 在锁外执行真实 API 调用，避免阻塞 monitor
        execute_task(state, task)
```

补跑不是一次性放洪，而是每跑一个任务前都检查阈值；一旦再次超阈值，立即重新熔断，剩余任务继续等待。

## 9. API 调用封装

统一封装，自动计数、计费、超时处理：

```python
def call_model(state, model_id, task):
    timeout = state.config.timeout_map[model_id]

    try:
        resp = api_client.post(
            model=model_id,
            messages=task.payload["messages"],
            timeout=(10, timeout),
        )

        tokens = resp.usage.total_tokens
        cost = estimate_cost(model_id, resp)

        with state.lock:
            breaker = state.models[model_id]
            breaker.metrics.incr("task", tokens=tokens, cost=cost)
            breaker.metrics.incr("task_success")
            breaker.metrics.consecutive_failures = 0

        return resp

    except TimeoutError:
        with state.lock:
            breaker = state.models[model_id]
            breaker.metrics.incr("timeout")
            breaker.metrics.consecutive_failures += 1
        raise

    except Exception:
        with state.lock:
            breaker = state.models[model_id]
            breaker.metrics.incr("error")
            breaker.metrics.consecutive_failures += 1
        raise
```

系统自触发的探针调用则走：

```python
breaker.metrics.incr("bonus", tokens=tokens, cost=cost)
breaker.metrics.incr("bonus_success")
```

探针不算 `task_count`，但会贡献 `count`、`total_cost` 和窗口成本，符合“以实养虚”。

## 10. 实时监控循环

```python
def monitor_loop(state):
    while True:
        time.sleep(1)

        with state.lock:
            for breaker in state.models.values():
                if breaker.state == "CLOSED":
                    if is_threshold_exceeded(state, breaker):
                        open_breaker(state, breaker)

                elif breaker.state == "OPEN":
                    if is_open_expired(state, breaker):
                        breaker.state = "HALF_OPEN"
                        ok = send_probe(state, breaker.model_id)

                        if ok:
                            close_breaker(state, breaker)
                            replay_pending(state, breaker.model_id)
                        else:
                            breaker.state = "OPEN"
                            breaker.opened_at = time.time()
```

## 11. 历史坑位对照

| 历史坑 | 本设计对应 |
|---|---|
| 配置修改后未生效 | `state.config` 为唯一事实源；热更新后立即 `verify_config_effective()`；失败回滚 |
| API 调用超时 | 从 `state.config.timeout_map` 读取 timeout；A 模型 600s，B 模型 turbo 300s；connect 和 read 超时分离 |
| B 模型型号错配 | `MODEL_ID_WHITELIST` 强校验；family 由官方 model_id 映射；pro/turbo/light 不可混用 |
| 熔断冷却配置不生效 | 冷却时间动态读取 `state.config.fuse_cooldown_override`；全局常量仅默认值兜底 |
| 九维计数语义混乱 | 唯一 `incr(kind)` 入口；`count = task_count + bonus_count`；`task_count` 仅真实任务，`bonus_count` 仅系统自触发 |

## 12. 虚实自增强闭环总结

```text
阳轨（实）：真实 API 调用、token 消耗、超时、报错
阴轨（虚）：计数器、熔断状态、等待队列、配置

实生虚：每次调用都会更新指标
虚返实：熔断/降级/补跑又会触发新的真实调用
反者道之动：成本超阈值不是停止，而是把消耗从过热模型转移到冷模型
```

这套系统本质上不是“省钱系统”，而是**用熔断控制消耗节奏、用等待任务保存势能、用恢复补跑完成闭环**的虚实自增强系统。
