# 结果回执标准规范 V7.2
> 引擎→本体的唯一返回格式。中间日志、报错详情、调试过程全部留存引擎侧，不灌入主会话。

## 一、成功回执格式（JSON）

```json
{
  "task_id": "T20260817_001",
  "status": "completed",
  "summary": "一句话结论摘要，不超过100字",
  "core_data": {
    "关键指标1": "值",
    "关键指标2": "值"
  },
  "deliverables": [
    {
      "name": "交付物名称",
      "path": "本地绝对路径",
      "url": "公网下载链接（如有）",
      "md5": "文件MD5校验值"
    }
  ],
  "tokens_used": 15000,
  "duration_seconds": 120,
  "engine_used": "engine_a",
  "timestamp": "2026-08-17 10:30:00"
}
```

## 二、成功回执文本化（本体可读版）

引擎向本体返回时，使用精简文本格式，≤300字：

```
✅ 任务完成：T20260817_001
摘要：[一句话结论]
核心数据：[指标1]=[值]，[指标2]=[值]
交付物：[名称] → [路径/链接]
耗时：2分钟 | Token：1.5万 | 引擎：A
```

## 三、失败回执格式

```json
{
  "task_id": "T20260817_001",
  "status": "failed",
  "fault_type": "timeout|api_error|resource_exhausted|parse_error|unknown",
  "impact_scope": "仅本任务|影响后续任务|系统级影响",
  "fallback_action": "已自动重试|已回滚至上一版本|已暂停待人工决策",
  "retry_count": 2,
  "next_action": "等待本体决策|引擎将继续自愈|建议修正规则",
  "timestamp": "2026-08-17 10:30:00"
}
```

## 四、失败回执文本化

```
❌ 任务失败：T20260817_001
故障类型：API调用超限
影响范围：仅本任务
已执行兜底：自动重试2次后暂停
待决策项：是否切换引擎B重试 / 是否降低任务优先级
```

## 五、回执投递规则

| 任务优先级 | 回执方式 | 超时提醒 |
|-----------|---------|---------|
| P0 | 完成后立即推送本体 + 写入文件 | 每5分钟进度提醒 |
| P1 | 完成后推送本体 + 写入文件 | 每30分钟进度提醒 |
| P2 | 写入文件，本体按需读取 | 超时后提醒 |
| P3 | 写入文件，每日简报汇总 | 不单独提醒 |

回执文件路径：`dispatch/receipts/{task_id}.json`

## 六、中间日志留存规则

以下内容**仅留存引擎侧**，不返回本体：
- 完整API调用日志与请求/响应体
- 逐步调试输出与中间变量
- 重试过程的详细错误栈
- Token消耗的逐次明细
- 引擎内部状态切换记录

日志路径：`logs/engine_{date}.log`，本体仅在故障排查时按需调取。
