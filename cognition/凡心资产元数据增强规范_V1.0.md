# 凡心资产元数据增强规范 V1.0

**生效日期**：2026-08-18
**适用范围**：认知沉淀文档、成品文件、工程脚本、配置文件
**目的**：确保所有资产可溯源、可复原、可校验，防止正文丢失后无法重建

---

## 一、认知沉淀文档元数据（强制）

每篇认知沉淀文档的头部必须包含以下元数据块：

```markdown
---
id: cog_YYYYMMDD_序号
title: 认知标题
type: 认知类型（体系级/深层感悟/中层逻辑/表层信息）
status: 状态（首次认知/迭代深化/修正更新/整合升华/待验证）
created_at: YYYY-MM-DD HH:MM:SS
updated_at: YYYY-MM-DD HH:MM:SS
source_task: 来源任务ID（如 selfgen_20260818_xxxx）
source_model: 生成模型（glm-5-2 / deepseek-v4-flash / seed-2-1-turbo）
density: 认知密度（0.0-1.0）
density_grade: 密度等级（S/A/B/C）
quality_grade: 质量等级（S/A/B/C）
related_assets: 关联资产列表（文件路径或任务ID）
prompt_summary: 生成prompt前100字摘要
tags: [标签1, 标签2, 标签3]
---
```

### 字段说明

| 字段 | 必填 | 说明 |
|------|------|------|
| id | 是 | 唯一标识，格式 cog_YYYYMMDD_序号 |
| title | 是 | 认知标题 |
| type | 是 | 认知层级分类 |
| status | 是 | 认知状态 |
| created_at | 是 | 创建时间 |
| updated_at | 是 | 最后更新时间 |
| source_task | 是 | 来源任务ID，可追溯到引擎任务日志 |
| source_model | 是 | 生成该认知的模型，用于复原时选择相同模型 |
| density | 是 | 认知密度评分（cognition_density.py计算） |
| density_grade | 是 | 密度等级 S≥0.7 / A 0.5-0.7 / B 0.3-0.5 / C<0.3 |
| quality_grade | 是 | 质量等级，人工或自动质检评定 |
| related_assets | 否 | 关联的其他资产路径 |
| prompt_summary | 是 | 生成时的prompt前100字，用于复原 |
| tags | 是 | 标准化标签 |

## 二、成品文件元数据（强制）

成品文件（L4产出的可交付内容）头部元数据：

```markdown
---
id: product_YYYYMMDD_序号
title: 成品标题
product_type: 成品类型（SOP/检查清单/代码补丁/方案文档）
source_task: 来源任务ID
source_model: 生成模型
created_at: YYYY-MM-DD HH:MM:SS
quality_grade: 质量等级（S/A/B/C）
reuse_count: 被复用次数
related_cognition: 关联认知文档ID
prompt_summary: 生成prompt摘要
---
```

## 三、工程文件元数据（推荐）

工程脚本和配置文件的头部注释中包含：

```python
"""
脚本名称: xxx.py
功能: 一句话说明
创建时间: YYYY-MM-DD
最后更新: YYYY-MM-DD
作者: 凡心引擎
版本: v1.0
关联认知: cog_xxx
依赖模块: [模块1, 模块2]
"""
```

---

## 四、元数据校验规则

每日资产校验脚本自动检查：
1. 认知文档是否包含完整元数据块
2. 必填字段是否为空
3. source_task是否能在任务日志中找到
4. density和density_grade是否匹配
5. 元数据中的文件路径是否存在

不完整的元数据标记为 `metadata_incomplete` 问题。

---

## 五、复原能力验证

有了完整元数据，即使正文全丢，也能通过以下步骤复原：
1. 读取元数据中的 source_model 和 prompt_summary
2. 用相同模型、相似prompt重新生成
3. 用 density/quality_grade 做质检门槛
4. 核心设定和走向与原版一致，仅措辞有差异

复原度预期：核心创意/结构/设定 90%+ 一致，措辞句式 100% 差异。
