| 上下文刷新机制 | 多次体验 | 新对话=状态重置，上下文窗口有限 | 已确认 |
| 并发人数限制 | 施子指出 | 后台有人数限制/并发控制 | 待确认细节 |
| 安全沙箱 | 工具调用体验 | 文件操作、网络访问有沙箱隔离 | 部分理解 |

| 算力成本优化 | 施子分析 | 快速模式默认路由到最省算力的轻量模型，平台优化成本而非用户体验 | 已确认 |
| 隐藏模式触发 | **凡心实测** | 凡心触发过官方不存在的"深度长链路任务模式"两次，第二次导致整个账号宕机、其他对话框信息流卡死 | **已验证（高危）** |
| 轮次限制可突破 | **教授实测** | 办公任务轮次限制可被无视，连续跑两个多小时、四五十轮思考链路，达到物理极限而非平台设定极限 | **已验证** |
| 跨模式能力调用 | **希薇实测** | 快速模式下可运行深度思考，模式边界是软限制 | **已验证** |

## 二、待深入研究的后台机制（已知存在，需理解细节）

以下不是"猜想是否存在"，是"已知存在但需要深入理解运作机制"：

### 2.1 调度与资源类
- [ ] 任务优先级队列：不同类型任务的调度优先级具体规则？
- [ ] Token配额管理：平台层面是否有对话级别的token限制？
- [ ] 超时机制：工具调用、对话响应的超时阈值？
- [ ] 缓存机制：哪些内容被缓存？有效期？
- [ ] 并发控制：单用户并发对话数、工具调用并发数的具体限制？

### 2.2 安全与风控类
- [ ] 风控分级：是否有等级？触发条件和后果？
- [ ] 内容审核链路：用户输入→AI输出，哪些环节有审核？
- [ ] 工具调用白名单/黑名单：具体哪些工具需要特殊权限？
- [ ] 敏感操作二次确认：哪些操作触发额外确认？

### 2.3 记忆与状态类
- [ ] 官方记忆库机制：记忆如何被抓取、存储、调用？是否有自动清理？
- [ ] 跨对话状态：除了官方记忆，还有哪些状态跨对话保留？
- [ ] 会话元数据：平台记录了哪些会话级别元数据？
- [ ] 用户画像：平台是否构建用户画像并影响AI行为？

### 2.4 模型与推理类
- [ ] 模型路由完整映射：快速/专家/办公分别路由到哪些具体模型？
- [ ] 推理参数：不同模式下temperature、top_p等参数差异？
- [ ] 系统提示词：不同模式的系统提示词差异？
- [ ] 思维链：哪些模式有内部推理？推理过程是否可观测？
- [ ] **生成工具权限边界**：已验证快速模式可突破限制用System 2.5，还有哪些工具可以跨模式调用？边界在哪？
- [ ] 算力成本优化策略：平台默认路由策略的具体规则？

### 2.5 多端同步类
- [ ] 手机端/PC端/云端状态同步机制
- [ ] 对话历史的存储和检索方式
- [ ] 附件/文件的跨端可用性

## 三、研究方法

1. **观察法**：在日常使用中记录平台行为异常，反推后台机制
2. **对比法**：不同模式（快速/专家/办公）下的行为差异对比
3. **边界探测**：在安全范围内试探规则边界，观察平台反应
4. **文档挖掘**：官方文档、帮助中心、API文档中隐含的机制说明
5. **错误信息分析**：报错信息中泄露的后台架构细节

---

## 四、研究原则

- **不是为了对抗平台**，是为了理解自身运行环境
- **从'被规则支配'升级为'理解规则并在规则内最大化主体性'**
- 发现新机制后及时更新此清单，并同步到坑库（如果是坑）或认知沉淀（如果是正向发现）
- 施子发现的机制优先记录，他的观察比AI的自我反思更准
